# 工序 · 观感打磨（P 阶段必走工序）

> 本工序是交付前置条件，不是进度缓冲。用户原话逐字留档：
> 「十一，我没有把"完美"的主观打磨算进中位。按你"不接受任何不完善 APK"的标准，M5 之后大概率还有 1~2 轮整体观感返工，每轮 2~4 天，这部分只有真机看效果之后才能定，现在给不出可信数字。这个是一定要的，不能变更，甚至还要增加这个部分的工序」。
> 「再叠加你要求的"先单项自检、再整体自检"和"不接受不完善包"带来的观感返工 1~2 轮（每轮 2~4 天），中位再抬到 10~11 天。这项也不能变」。
> 「每轮都含"出包 → 你真机看 → 返工 → 复验"这个要省去，我只接受一次包」。

## 一、性质声明
1. 观感打磨是交付前置条件：不过本工序不许出交付包；不许写成"可选优化""如有时间再做"；不许因工期紧跳过、缩短或合并轮次，工序只许增加不许减。
2. 全程只出一次包（P4 之后的唯一交付包）；打磨期间不许再发任何"可装观感包"，不许真机往返；观感判定改由 CI 渲染帧驱动（见 P0/P1）。
3. 本工序判的是机械断言判不到的美感维度；与既有机械验收的关系见第十三节，两者不可互相替代。

## 二、工序总顺序
P5 单项自检（各模块出口）→ P0 截图测试基建 → P1 CI 帧观感判定 → P2 返工轮（不出包）→ P3 观感冻结 → P4 出口判定 → P6 整体自检 → 唯一交付包。

## 三、P0 截图测试基建（一次性投入，替代"出可装包"）
1. 在 CI 内跑无真机截图测试，把每屏真实渲染帧输出成 PNG，作为 artifact 上传。
2. 方案选型：先复用工程现有测试栈。现状查证（`grep -rn "robolectric\|paparazzi\|roborazzi\|GraphicsMode" app/build.gradle* build.gradle* gradle/libs.versions.toml`）：现栈仅 JUnit4 + Mockito 单测、Espresso androidTest，无截图测试依赖。优先 Roborazzi（Robolectric `@GraphicsMode(NATIVE)` + Compose 截图），Paparazzi 备选；二选一，不新引两套。
3. 判据：CI 里能稳定产出 N 张屏帧（N = 第四节被判对象条数）；帧文件命名带屏名 + 尺寸，并附 sha256 清单。
4. 兜底（必须写，但不许当默认）：若截图测试在 CI 跑不起来（Compose 版本/AGP/JDK21 不兼容），退路＝按规格参数（token/尺寸/边距/字号/坐标）用 python 精确生成"规格样张"，配合代码静态走查与像素断言；此兜底会降低判感保真度，属已知代价，轮次记录须标明走的是兜底路径。

## 四、P1 观感判定（判 CI 渲染帧，不判真机截图）
1. 判定输入：CI artifact 里的渲染帧；不是想象的画面、不是预览图。判定者：独立验收代理，不许由写码代理自评。
2. 判定维度 7 项；每条判据必须能对着帧文件核，低分症状是客观可指认现象，不许写"不好看"这类主观词：
   - 辨识度（像素统计）：正文与背景亮度差/对比度不足、长时间阅读发灰；图标/按钮在纸白底上边缘强度不够；朱砂/暖金强调色压不住主体。
   - 层次与纵深（亮度分层）：阅读页/气泡/Sheet/遮罩 Z 轴叠压扁平；毛玻璃虚化缺失；卡片之间无前后阴影梯度；辉光层级互相串。
   - 动效节奏（帧序列）：弹入/翻页/滑入用 linear 或无 spring 回弹；stagger 拖沓；点触反馈超过 120ms；帧间隔不均、粒子/辉光抖动或掉帧。
   - 字重与留白（像素测量）：标题/正文/小字字重档混乱；行距/列距/段距偏离 1.8x/2.5x；卡片内边距挤压；首行缩进与留白失衡；字体族超过三种。
   - 色温一致性（色值直方图）：跨帧底色偏冷/偏黄不一；暗处偏冷；金偏亮偏霓虹；出现纯黑纯白或 Material 色；同一 token 在不同帧取值漂移。
   - 边缘与裁切处理（边缘检测）：文字/卡片/图标被裁切、圆角越界；竖排断行异常；长标题/长名物挤压省略不当；棋子/地图标签贴边；阴影描边出血。
   - 密度与可读性（版面占比）：一屏信息过密或过空；列表行高不均；空状态/骨架屏三变体缺失；按钮热区过小。
3. 被判对象清单（取自 `docs/落文-模块契约索引.md` 模块表与问题清单，逐条对号，不许新增屏）：
   1. 启动动画与纪年页（U2，`ui/welcome/`、`ui/main/chrono/`）
   2. 书架页（U4，`ui/main/bookshelf/`）
   3. 阅读页竖排模式（U5，`ui/book/read/ink/`）
   4. 阅读页横排模式（D20，复用 U5 壳）
   5. 阅读气泡 InkBubble（字/词/典故/人名/地名/年号/干支/朔望，`help/bubble/` + `InkBubble.kt`）
   6. 半屏 Sheet（U6，`InkHalfSheet.kt`）
   7. 画板 InkSlate（U7，`ui/components/inkslate/`、`PaintActivity.kt`）
   8. 搜索下拉浮层（U8，`ui/main/search/`）
   9. 字体系统呈现（U9，`ui/font/` + 五枚子集）
   10. 地图壳三模式（D17，PlaceMapActivity：2D Leaflet / 3D 沙盘 / 3D 地球仪）
   11. 四渡赤水推演壳（U12，`ui/map/crossing/`）
   12. 马克思三件套（D18，`ui/tool/marx/`）
   13. 党史四件套（D19，`ui/tool/party/`）
   14. 发现页手卷（D21，`ui/main/explore/`）
   15. 导航 3 Tab（D25，MainActivity 底部导航）
   16. 卡片体系 12 类（D29，`ui/card/`）
   17. 功能图标全集（D22/D28，`res/drawable/`）

## 五、P2 返工轮（全程不出包）
1. 返工＝改代码 → 重跑 CI → 取新帧 → 再判；全程不产生 APK；低分项按屏/模块成组派单，同文件串行、不同屏可并行；只改低分项落点，不许借返工改冻结规格、顺手扩功能。
2. 轮次上限 3 轮；每轮必须更新观感基线（帧 + sha256），供下一轮对比漂移。

## 六、P3 观感冻结
1. 通过轮的帧与资产哈希登记进 `docs/.visual_baseline.sha256`（脚本 `--freeze` 模式）。
2. 冻结后任何改动必须复验：被登记屏帧与资产哈希不得变化；`data_scripts/check-visual-baseline.py` 校验不一致即 FAIL，并输出哪一屏被破坏；破冻结即 FAIL，先回滚到冻结态再走 P2，不许带破冻结状态进 P4/P6。

## 七、P4 出口判定与唯一交付包
1. 出口判据：连续一轮全屏（第四节 17 项对象）无新增低分项，观感轮才算完成。
2. 轮次上限 3 轮：至少 2 轮观感返工；超过 3 轮仍不过，判"规格本身错"，按 F-73 三段流水线回炉重做设计（双换设计与审验代理，旧稿标作废留档），不是继续磨细节。
3. 打磨完成后才允许出唯一一次交付包：签名校验（`app/luowen.jks`，alias `luowen`，storepass/keypass `luowen2026`）+ 从 artifact 取包；记录包路径、versionCode、sha256、对应 commit。
4. 硬话："交付包"全项目只允许出现一次，出现在 P4 之后；P0~P3 期间任何"先出个包看看"的做法一律违规。

## 八、P5 单项自检（每模块出口必做）
1. 每个模块完成时先做单项自检：功能断言逐条核 + 该模块涉及的美化/感官引导项逐条核（`docs/落文-模块契约索引.md` §1.5 六要素/配色/动效/材质）；判据必须可机械核验（grep/断言/bench），不许"看一眼还行"，跑不通不交付。
2. 单项自检通过才允许进入模块台账/登记册状态流转；未过项留在 PENDING，不许标已验。

## 九、P6 整体自检（交付前最后一道）
1. 全部模块单项自检通过后再做一次整体自检：跨模块一致性（色板/字体档/动效曲线/图标同族性/卡片圆角与阴影三档）、跨屏观感基线未破、断网与空数据兜底全链路走查、性能红线（帧率/粒子数上限/内存峰值）；整体自检 PASS 才允许出交付包，任一跨模块不一致项回到对应模块走 P5/P2。

## 十、顺序硬约束
1. 固定顺序：P5 单项自检 → 观感轮次（P0~P3）→ P4 出口判定 → P6 整体自检 → 唯一交付包。
2. P6 不许提前、不许与 P5 合并、不许用"CI 绿"代替：CI 绿只证明能编译与单测过，证明不了观感与跨模块一致。

## 十一、不可压缩声明与排期
1. 观感返工至少 2 轮（每轮 2~4 天）、单项自检与整体自检各至少 1 次，这三块不参与任何工期压缩；工期紧时只能压缩功能阶段，不许压缩这三块。
2. 为什么：用户明确"不接受任何不完善 APK，所有验收通过后一次性交付完整包"；压缩这三块等于把返工推到交付后，成本更高且不可交付。
3. 排期数值（供总控引用）：功能阶段中位 8~11 天；观感返工 2 轮 4~8 天；单项自检 1~2 天（分散在各模块出口，按总量计）；整体自检 1~2 天；出包与签名校验 0.5 天（仅 P4 后一次）。合计中位 18 天、乐观 14 天、保守 25 天。

## 十二、为什么不再真机往返
1. 用户只接受一次包：中间包会变成实际交付物，破坏"一次性交付完整包"的口径。
2. 真机往返依赖用户在场，会把工期变成不可控等待；CI 帧可在代理侧自行复跑。
3. CI 渲染帧是无真机条件下唯一能拿到"真实渲染结果"的手段，且可复跑、可哈希、可基线冻结——比人眼看更可核验。

## 十三、与既有验收的关系
1. 机械验收（断言/像素/条数，含卡片 12 类、图标全集、T6 两项硬指标、color token、字体档位）管"存在与不退化"；本工序管"判不到的美感维度"（层次、动效节奏、留白、色温、边缘、密度）。两者不可互相替代；不许用机械验收通过来抵掉观感轮次，也不许用观感"感觉不错"豁免机械断言。

## 十四、资产路径
1. 基线文件：`docs/.visual_baseline.sha256`（P3 生成；不存在时脚本判 WARN，不算 FAIL）。校验脚本：`data_scripts/check-visual-baseline.py`（校验 / `--freeze` 冻结 / `--selftest` 自测；待总控接入为 ⑳ 门禁，本任务不改 `data_scripts/rule-gate.sh`）。
