# 工序 · 观感打磨（P 阶段必走工序）

> 本工序是交付前置条件，不是进度缓冲。用户原话逐字留档：
> 「十一，我没有把"完美"的主观打磨算进中位。按你"不接受任何不完善 APK"的标准，M5 之后大概率还有 1~2 轮整体观感返工，每轮 2~4 天，这部分只有真机看效果之后才能定，现在给不出可信数字。这个是一定要的，不能变更，甚至还要增加这个部分的工序」。
> 「再叠加你要求的"先单项自检、再整体自检"和"不接受不完善包"带来的观感返工 1~2 轮（每轮 2~4 天），中位再抬到 10~11 天。这项也不能变」。
> 「每轮都含"出包 → 你真机看 → 返工 → 复验"这个要省去，我只接受一次包」。

## 一、性质声明
1. 观感打磨是交付前置条件：不过本工序不许出交付包；不许写成"可选优化""如有时间再做"；不许因工期紧跳过、缩短或合并轮次，工序只许增加不许减。
2. 全程只出一次包（P4 之后的唯一交付包）；打磨期间不许再发任何"可装观感包"，不许真机往返；观感判定改由 CI 渲染帧驱动（见 P0/P1）。
3. 本工序判的是机械断言判不到的美感维度；与既有机械验收的关系见第十三节，两者不可互相替代。

## 二、工序总顺序
P5 单项自检（各模块出口）→ P0 截图测试基建 → P1 CI 帧观感判定 → P2 返工轮（不出包）→ P3 观感冻结 → P4 出口判定 → P6 整体自检 → 唯一交付包。

## 三、P0 截图测试基建（一次性投入，替代"出可装包"）
1. 在 CI 内跑无真机截图测试，把每屏真实渲染帧输出成 PNG，作为 artifact 上传。
2. 方案选型：先复用工程现有测试栈。现状查证（`grep -rn "robolectric\|paparazzi\|roborazzi\|GraphicsMode" app/build.gradle* build.gradle* gradle/libs.versions.toml`）：现栈仅 JUnit4 + Mockito 单测、Espresso androidTest，无截图测试依赖。优先 Roborazzi（Robolectric `@GraphicsMode(NATIVE)` + Compose 截图），Paparazzi 备选；二选一，不新引两套。
3. 判据：CI 里能稳定产出 N 张屏帧（N = 第四节被判对象条数）；帧文件命名带屏名 + 尺寸，并附 sha256 清单。
4. 兜底（必须写，但不许当默认）：若截图测试在 CI 跑不起来（Compose 版本/AGP/JDK21 不兼容），退路＝按规格参数（token/尺寸/边距/字号/坐标）用 python 精确生成"规格样张"，配合代码静态走查与像素断言；此兜底会降低判感保真度，属已知代价，轮次记录须标明走的是兜底路径。

## 四、P1 观感判定（判 CI 渲染帧，不判真机截图）
1. 判定输入：CI artifact 里的渲染帧；不是想象的画面、不是预览图。判定者：独立验收代理，不许由写码代理自评。
2. 判定维度 7 项；每条判据必须能对着帧文件核，低分症状是客观可指认现象，不许写"不好看"这类主观词：
   - 辨识度（像素统计）：正文与背景亮度差/对比度不足、长时间阅读发灰；图标/按钮在纸白底上边缘强度不够；朱砂/暖金强调色压不住主体。
   - 层次与纵深（亮度分层）：阅读页/气泡/Sheet/遮罩 Z 轴叠压扁平；毛玻璃虚化缺失；卡片之间无前后阴影梯度；辉光层级互相串。
   - 动效节奏（帧序列）：弹入/翻页/滑入用 linear 或无 spring 回弹；stagger 拖沓；点触反馈超过 120ms；帧间隔不均、粒子/辉光抖动或掉帧。
   - 字重与留白（像素测量）：标题/正文/小字字重档混乱；行距/列距/段距偏离 1.8x/2.5x；卡片内边距挤压；首行缩进与留白失衡；字体族超过三种。
   - 色温一致性（色值直方图）：跨帧底色偏冷/偏黄不一；暗处偏冷；金偏亮偏霓虹；出现纯黑纯白或 Material 色；同一 token 在不同帧取值漂移。
   - 边缘与裁切处理（边缘检测）：文字/卡片/图标被裁切、圆角越界；竖排断行异常；长标题/长名物挤压省略不当；棋子/地图标签贴边；阴影描边出血。
   - 密度与可读性（版面占比）：一屏信息过密或过空；列表行高不均；空状态/骨架屏三变体缺失；按钮热区过小。
3. 被判对象清单（取自 `docs/落文-模块契约索引.md` 模块表与问题清单，逐条对号，不许新增屏）：
   1. 启动动画与纪年页（U2，`ui/welcome/`、`ui/main/chrono/`）
   2. 书架页（U4，`ui/main/bookshelf/`）
   3. 阅读页竖排模式（U5，`ui/book/read/ink/`）
   4. 阅读页横排模式（D20，复用 U5 壳）
   5. 阅读气泡 InkBubble（字/词/典故/人名/地名/年号/干支/朔望，`help/bubble/` + `InkBubble.kt`）
   6. 半屏 Sheet（U6，`InkHalfSheet.kt`）
   7. 画板 InkSlate（U7，`ui/components/inkslate/`、`PaintActivity.kt`）
   8. 搜索下拉浮层（U8，`ui/main/search/`）
   9. 字体系统呈现（U9，`ui/font/` + 五枚子集）
   10. 地图壳三模式（D17，PlaceMapActivity：2D Leaflet / 3D 沙盘 / 3D 地球仪）
   11. 四渡赤水推演壳（U12，`ui/map/crossing/`）
   12. 马克思三件套（D18，`ui/tool/marx/`）
   13. 党史四件套（D19，`ui/tool/party/`）

## 四补、UX 体验维度（美感 + 用户体验双维验收，与第四节七维并行判定）

> 来源：用户原话「美感验收那一轮还要加入优化用户体验的规则」（Q-20，`docs/派单队列.md` L30）。
> 本批九维与第四节美感七维并行：美感七维判"看着好不好"，UX 九维判"用着顺不顺"；两者不可互相替代，不许用美感通过抵掉 UX 违例，也不许用机械断言通过抵掉人眼/真机项。
> 每维固定四件套：低分症状（客观可指认现象，禁"不好用"这类主观词）＋ 可机械核验判据（具体阈值或可 grep/python 判定）＋ 谁来验 ＋ 何时验。判不了的项必须显式登记"需人眼/需真机"，给出替代口径与降级证据，不许静默放过、不许把"没测出"写成通过。违例逐条进 `docs/台账-观感UX.md` 闭环。

### UX-01 可读性（字号 / 行距 / 对比度）
1. 低分症状：正文发灰长时间阅读吃力；字号小到眯眼；行距与字号挤成一坨；暗色下正文贴黑底。
2. 判据：
   - 最小字号 ≥14sp：脚本静态扫 `app/src/main/**/*.kt`，正则兼容 `X.sp` 与辅助写法 `spX()`，数值 <14 即 FAIL（输出 `文件:行` 与数值）；标题/强调档可 ≥16sp，正文不得低于 14sp。谁验：`check-visual-baseline.py --ux` 机械初筛，独立验收代理复核。何时验：P5 模块出口 + P6 整体自检。
   - 行距 ≥1.4 倍字号：静态取同行 `lineHeight` 与 `fontSize` 比值，<1.4 即候选 FAIL；静态配不上对的，转渲染帧像素复核（lineHeight ÷ fontSize）。谁验：脚本初筛 + 验收代理对帧复核。何时验：P1 帧判定 + P6。
   - 正文对比度 ≥4.5:1：对渲染帧取正文前景色与背景色算 WCAG 对比度，<4.5:1 即 FAIL；无帧时登记"需帧/需真机"，不许拿色值猜测冒充通过。谁验：帧像素脚本 + 独立验收代理。何时验：P1 帧判定；P6 复验。
3. 降级口径：截图基建未就绪时（P0 兜底路径，见第三节第 4 条），字号/行距走静态 grep 判，对比度项显式登记"需帧/真机"，台账记走兜底路径。

### UX-02 暖金辉光 / 暗色下正文对比度保底
1. 低分症状：暗色/纯黑主题下暖金辉光把正文淹掉，正文与辉光同亮度发飘；纸白主题金强调色压不住主体。
2. 判据：暗色帧正文前景对背景（含辉光叠加层）对比度仍 ≥4.5:1；辉光透明度不得把正文对比压到 3:1 以下。机械部分＝帧像素取色对比；静态部分只查暗色主题色是否走 token、不硬编码近黑文本。像素取不到帧即 DEFER（需帧/真机），显式登记。谁验：验收代理对帧 + 脚本静态。何时验：P1 暗色帧 + P6。
3. 降级口径：无暗色渲染帧时，登记"暗色对比度未验"并附静态 token 引用证据，禁止判 PASS。

### UX-03 点击目标尺寸与间距
1. 低分症状：按钮/图标/热区手指按不中；相邻可点元素挤在一起误触。
2. 判据：可点元素热区 ≥48dp×48dp（`size`/`minHeight`/`minWidth` 取值 <48.dp 且落在可点 UI 文件——按钮/图标/导航/Tab/气泡/胶囊/动作条——即候选 FAIL，输出 `文件:行` 与数值）；列表/卡片间距 ≥8dp（`Arrangement.spacedBy(N.dp)` 中 N<8 即 FAIL）。谁验：脚本静态初筛 + 验收代理对帧核热区归属。何时验：P5 模块出口 + P6 整体自检。
3. 降级口径：静态只能判数值，热区是否真为可点归属由验收代理对帧/代码复核；复核不通过回写台账违例条目。

### UX-04 点击到视觉反馈 ≤100ms
1. 低分症状：点下去半天没反应，用户以为没点中而连点；反馈与手势脱节。
2. 判据：目标口径＝手势落点到反馈可见（按压态/辉光/音效起）≤100ms。截图帧测不到时间延迟，替代口径三档：①静态查反馈链路不得有 >100ms 的 `delay`/`delayMillis` 前置（限 `ui/**` 交互路径，>100 即候选 FAIL；轮询/限流/清理等待不算交互反馈延迟，按路径豁免）；②帧序列取按下帧与反馈帧序号差，配合帧间隔推算反馈时延；③真机/bench 出延迟样本。谁验：脚本静态 + 验收代理；真机样本后置登记。何时验：P5 出口静态项；P6 整体帧序列；真机项随唯一交付包前复核。
3. 降级证据要求：无真机时必须在台账登记"延迟项＝替代口径 + 降级证据（静态链路 / 帧序列）"；禁止静默放过，禁止把"没测出延迟"写成通过。

### UX-05 加载与空态
1. 低分症状：异步入口白屏转圈或直接空白；没数据时一屏死白；三变体（loading/empty/offline）缺其一。
2. 判据：凡 `collectAsState`/`LaunchedEffect`/异步加载的 UI 入口，代码必须出现骨架屏/占位/loading/空态文案之一（骨架/占位/空/loading/empty/placeholder 关键词）；缺即 FAIL 候选，转人眼复核三变体是否齐全。谁验：脚本静态配对 + 验收代理人眼复核。何时验：P5 模块出口 + P6 整体自检。
3. 降级口径：静态配对只证明"有占位代码"，占位是否真展示、文案是否得体转人眼/帧复核。

### UX-06 错误恢复
1. 低分症状：断网/缺数据直接崩溃、闪退或死页；无重试、无兜底文案，用户只能退出重进。
2. 判据：错误/离线/空数据分支必须有重试动作或兜底文案（retry/重试/兜底/离线/offline/empty 文案之一）；静态在含 error/uiState/网络状态的 UI 文件里查不到即 WARN 转人眼；崩溃类回归以单测/异常捕获证据为准。谁验：脚本静态 + 验收代理全链路走查 + 单测。何时验：P5 模块出口 + P6 断网与空数据全链路。
3. 降级口径：静态查不到兜底词不直接判崩溃；须由验收代理走查错误分支路径，确认无异常逃逸后关闭条目。

### UX-07 手势可发现性
1. 低分症状：可翻页/可缩放区域首屏无任何提示，用户不知道能划、能捏；手势入口藏在长按里无引导。
2. 判据：可翻页/可缩放入口首次可见提示（角标/轻扫动画/文案 hint/引导浮层）；静态查提示关键词或手势引导组件；提示是否首次可见、是否被后续操作顶掉，转人眼/帧复核，DEFER 项显式登记。谁验：脚本静态 + 验收代理人眼/帧。何时验：P1 帧判定 + P6 整体自检。
3. 降级口径：首访提示只在冷启动出现，静态代码查得到引导组件不等于首屏可见，该项必须留帧/人眼证据才能关闭。

### UX-08 返回栈一致性
1. 低分症状：返回后阅读进度丢回开头；地图视角跳回默认；气泡/筛选上下文丢失。
2. 判据：返回后恢复阅读进度与地图视角（相机位置/缩放/选中状态）；静态查 `rememberSaveable`/`onSaveInstanceState`/进度与相机状态的保存-读取是否成对存在；保存恢复是否真生效转真机/集成复核。谁验：脚本静态配对 + 验收代理集成走查。何时验：P5 模块出口 + P6 整体自检。
3. 降级口径：静态成对存在只证明接线在，状态真能跨返回恢复由集成走查确认；未走查前条目状态保持"待验"。

### UX-09 长文性能手感
1. 低分症状：长文连续翻页掉帧、卡顿；粒子/辉光抖动；滚动中新建 Bitmap 拖慢列表。
2. 判据：目标口径＝连续翻页 ≥50 帧无掉帧（帧率 ≥50fps，单帧耗时 ≤16.7ms）。bench 未上真机前替代口径：①静态禁在滚动/列表 item lambda 内新建 Bitmap 或大对象（呼应 F-50）；②帧序列测帧间隔方差与丢帧缺口；③真机 bench 样本后置登记。谁验：脚本静态 + 帧序列分析；真机 bench 后置。何时验：P6 整体自检；真机 bench 随交付前复核。
3. 降级口径：替代口径不得冒充真机帧率结论；台账必须写明"手感项＝静态/帧序列替代证据，真机帧率未验"。

## 五、P2 返工轮（全程不出包）
1. 返工＝改代码 → 重跑 CI → 取新帧 → 再判；全程不产生 APK；低分项按屏/模块成组派单，同文件串行、不同屏可并行；只改低分项落点，不许借返工改冻结规格、顺手扩功能。
2. 轮次上限 3 轮；每轮必须更新观感基线（帧 + sha256），供下一轮对比漂移。

## 六、P3 观感冻结
1. 通过轮的帧与资产哈希登记进 `docs/.visual_baseline.sha256`（脚本 `--freeze` 模式）。
2. 冻结后任何改动必须复验：被登记屏帧与资产哈希不得变化；`data_scripts/check-visual-baseline.py` 校验不一致即 FAIL，并输出哪一屏被破坏；破冻结即 FAIL，先回滚到冻结态再走 P2，不许带破冻结状态进 P4/P6。

## 七、P4 出口判定与唯一交付包
1. 出口判据：连续一轮全屏（第四节 17 项对象）无新增低分项，观感轮才算完成。
2. 轮次上限 3 轮：至少 2 轮观感返工；超过 3 轮仍不过，判"规格本身错"，按 F-73 三段流水线回炉重做设计（双换设计与审验代理，旧稿标作废留档），不是继续磨细节。
3. 打磨完成后才允许出唯一一次交付包：签名校验（`app/luowen.jks`，alias `luowen`，storepass/keypass `luowen2026`）+ 从 artifact 取包；记录包路径、versionCode、sha256、对应 commit。
4. 硬话："交付包"全项目只允许出现一次，出现在 P4 之后；P0~P3 期间任何"先出个包看看"的做法一律违规。

## 八、P5 单项自检（每模块出口必做）
1. 每个模块完成时先做单项自检：功能断言逐条核 + 该模块涉及的美化/感官引导项逐条核（`docs/落文-模块契约索引.md` §1.5 六要素/配色/动效/材质）；判据必须可机械核验（grep/断言/bench），不许"看一眼还行"，跑不通不交付。
2. 单项自检通过才允许进入模块台账/登记册状态流转；未过项留在 PENDING，不许标已验。
3. UX 单项项（四补节九维逐条核）：跑 `data_scripts/check-visual-baseline.py --ux` 出机械初筛；脚本判不了的维（对比度像素、反馈时延、首访提示、真机帧率等）显式登记"需人眼/需真机"与替代口径，不许静默放过；违例逐条进 `docs/台账-观感UX.md`，关闭条件见该台账。本模块涉及的 UX 项未闭环，模块不许流转已验。

## 九、P6 整体自检（交付前最后一道）
1. 全部模块单项自检通过后再做一次整体自检：跨模块一致性（色板/字体档/动效曲线/图标同族性/卡片圆角与阴影三档）、跨屏观感基线未破、断网与空数据兜底全链路走查、性能红线（帧率/粒子数上限/内存峰值）；整体自检 PASS 才允许出交付包，任一跨模块不一致项回到对应模块走 P5/P2。
2. UX 整体项：九维跨屏全走查一遍——对比度/暗色保底对帧复核，点击目标与间距跨屏一致，反馈时延走帧序列或真机样本，加载/空态/错误恢复三变体跨屏齐全，手势首访提示与返回栈恢复在关键链路（阅读页/地图壳/气泡/Sheet）逐一走通，长文手感以帧序列替代口径 + 真机 bench 后置证据闭环；台账 `docs/台账-观感UX.md` 无未关闭 FAIL 项、DEFER 项全部带替代口径与降级证据，整体自检才许判 PASS。

## 十、顺序硬约束
1. 固定顺序：P5 单项自检 → 观感轮次（P0~P3）→ P4 出口判定 → P6 整体自检 → 唯一交付包。
2. P6 不许提前、不许与 P5 合并、不许用"CI 绿"代替：CI 绿只证明能编译与单测过，证明不了观感与跨模块一致。

## 十一、不可压缩声明与排期
1. 观感返工至少 2 轮（每轮 2~4 天）、单项自检与整体自检各至少 1 次，这三块不参与任何工期压缩；工期紧时只能压缩功能阶段，不许压缩这三块。
2. 为什么：用户明确"不接受任何不完善 APK，所有验收通过后一次性交付完整包"；压缩这三块等于把返工推到交付后，成本更高且不可交付。
3. 排期数值（供总控引用）：功能阶段中位 8~11 天；观感返工 2 轮 4~8 天；单项自检 1~2 天（分散在各模块出口，按总量计）；整体自检 1~2 天；出包与签名校验 0.5 天（仅 P4 后一次）。合计中位 18 天、乐观 14 天、保守 25 天。

## 十二、为什么不再真机往返
1. 用户只接受一次包：中间包会变成实际交付物，破坏"一次性交付完整包"的口径。
2. 真机往返依赖用户在场，会把工期变成不可控等待；CI 帧可在代理侧自行复跑。
3. CI 渲染帧是无真机条件下唯一能拿到"真实渲染结果"的手段，且可复跑、可哈希、可基线冻结——比人眼看更可核验。

## 十三、与既有验收的关系
1. 机械验收（断言/像素/条数，含卡片 12 类、图标全集、T6 两项硬指标、color token、字体档位）管"存在与不退化"；本工序管"判不到的美感维度"（层次、动效节奏、留白、色温、边缘、密度）。两者不可互相替代；不许用机械验收通过来抵掉观感轮次，也不许用观感"感觉不错"豁免机械断言。
2. UX 九维（四补节）介于两者之间：可静态/可像素的走机械判据，判不了的显式走人眼/真机特殊通道（F-89 M4）；台账逐条闭环，不许用美感判定结论顶替 UX 项，也不许用机械断言通过顶替人眼/真机项。

## 十四、资产路径
1. 基线文件：`docs/.visual_baseline.sha256`（P3 生成；不存在时脚本判 WARN，不算 FAIL）。校验脚本：`data_scripts/check-visual-baseline.py`（校验 / `--freeze` 冻结 / `--selftest` 自测；`--ux` 跑 UX 九维静态审计，判不了的维显式 DEFER 需人眼/真机；待总控接入为 ⑳ 门禁，本任务不改 `data_scripts/rule-gate.sh`）。UX 违例台账：`docs/台账-观感UX.md`。
