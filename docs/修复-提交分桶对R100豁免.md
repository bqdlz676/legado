## 六、自查反例 / 改坏推演

- 反例 1（豁免被放大到内容改写）：若判据按「路径在 docs/」整体豁免而非 R100 双侧 docs 限定，E-05 事故类混提（结单报告扫进未收口代码）会被放绿，㊵ 形同虚设。夹具 B 正是这条负样本：docs 内容改写 + 代码同提交必须 FAIL，实测命中 docs 桶与 code 桶两侧。状态：已闭环。
- 反例 2（非满格改名被误豁免）：R90 改名（文件搬位置同时改了大段文字）携带真实内容 diff，交付语义已变；若状态前缀 `R` 即豁免，等于给「改名夹带改写」留后门。实现上只认字面 `R100`，R<100 一律落入 docs 内容桶。状态：已闭环。
- 反例 3（跨桶改名漏判）：docs 文件被移动到 `app/src/` 下，属跨桶搬运；`classify()` 按旧新两侧任一在代码前缀即归代码桶，不享受豁免。状态：已闭环（代码路径未在夹具中单独造样，判据分支按两侧前缀判定，留待后续负样本补齐）。
- 反例 4（基线滞留）：脚本补了 selftest 却不把 debt 条目删掉，51 自测覆盖门禁会报「基线滞留」FAIL；已同步从 `selftest-baseline.json` 移除并复跑 PASS。状态：已闭环。
- 反例 5（为消 ㊵ 去放宽路径前缀）：若把代码前缀判据改松（如只认 `app/src/main/`、放过 `app/src/test/`），测试代码混提同样失去防线；本单未动前缀边界，main 与 test 仍同属代码桶。状态：已闭环。
- 反例 6（N-2 直接挪行不补列）：把 5 列活跃行原样搬到主表，㊶ C1 立即报列数 5≠6，C3 对 RUNNING 行报缺起时/文件域/判据锚，反而新增一片红；故本轮只出评估方案，不做物理迁移。状态：已闭环。

### 6.1 为什么纯改名该豁免、但不该放宽到内容改写

- 纯改名（R100）零增删 diff：交付物在语义、行为、回源锚点上都不变，变的只是路径字符串；锚点连续性由锚点卡与报告沿革段维护旧名→新名对应（Q-244 更名已落地）。把它和代码改动捆在同一 commit，不产生「commit 与单号无法一一回源」的 E-05 风险，因为 docs 侧没有可被误归因的内容。
- 内容改写（A/M/D/C 或 R<100）改变交付语义：读者读到的规则、台账结论、验收口径变了，这条 docs 改动必须能独立回源到某个单号；与代码同 commit 时，结单层 `git add -A` 扫入未收口代码的事故路径依然成立。豁免到这一档，等于拆掉 ㊵ 要防的那道闸。
- 一句话边界：豁免的是「搬运」，不是「交付」；搬运零语义，交付必须分桶。
