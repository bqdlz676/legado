## 五、反例推演（必写三条）

### a) 回执块"形式合规、内容空转"的风险与防法

风险：回执块若把"适用条款"写成三句泛话（如"遵守团队纪律、按规范执行、注意质量"），门禁只查块在不在、指纹对不对、引用够不够三条，会把空转文案放成绿。本单的防法：

- 三条逐字引用全部取自守则文件正文连续子串（≥6 字），写入前逐条在对应 `docs/机制-*.md` 里 grep 命中，并标注 `文件:行`；`check-onboarding.py` 回源比对，片段不在守则原文即判红，不接受自造句。
- 适用条款逐条对应本单实际动作：一条缺陷一单（点名了哪些文件）、禁 git 写（本单实际未执行哪些命令）、禁本地编译（沙箱实际跑了什么预检）、grep/行号回证（对应报告哪一节）、未验证项（哪些留给云端 CI）；不写无法回指到本单行为的空话。
- 引用与条款角色对齐：修复单引 `机制-子代理必读.md`，验收单引 `机制-验收代理必读.md`，不交叉套用。

### b) "已入队"与"待裁"的事实边界

风险：问题其实还没派单，却写"已入队"，等于把未立项事项谎报成在飞；反方向把已在册事项写成"待裁"则重复派单。本单判定边界：

- `已入队`：`docs/派单队列.md` / `docs/派单台账.md` 中存在在册条目（Q-xxx，RUNNING/PENDING/DONE），且该条目的改动对象文件与本缺陷对象同名、同脚本。本单仅 D-1/D-2/A-3 挂 Q-272（对象 `check-design-tokens.py` + `契约-设计token.json`）、F-1/F-2/F-3 挂 Q-273（对象 `bisect-suspects.py` + `ci-bisect-片段.yml`），核过队列行后才标已入队。
- `待裁`：报告里识别出问题，但队列/台账查无在册条目，等待裁决派单。A-2、A-4、D-3、D-4、E-1、H-5、H-6、件4 接线、件6 快照等均无在册条目，标待裁，不借邻近在飞单挂靠。
- 其余词表边界：`已修` 必须有本报告内 grep / selftest 实跑回证；`判废` 须写明废弃理由；`已闭环` 指裁决已结束、无后续动作（Q-282 第 5 条 keep 规则保留即此类）。不允许为凑状态词统一填 `待裁`。

### c) 为让门禁变绿而删问题为什么禁止

55 门禁的存在意义是强制每份报告登记"新发现问题"，防止审计在自己手里收口。若把一条问题从报告里删掉换绿：缺陷不会消失，只是失去跟踪入口，后续同类问题无人接；门禁读数变好看但结论失真，正是历史上被打穿过的假绿方式。本单的做法：只追加状态词、追加登记条目，不删任何既有问题——Q-284 原 5 条原样保留；Q-282 原 5 条只改状态词、不改结论与理由；Q-286 / Q-283 新增条目全部来自报告自身边界声明与交叉复核 §三/§四，不虚构问题，也不回填已被 Q-286 收口项的旧状态。
