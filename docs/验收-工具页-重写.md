## 2. 重写结构（四层编排，复用底层）

```
Activity / DialogFragment 壳   ：只做宿主、生命周期、权限、ActivityResult、Manifest 入口
        ↓ setContent { Screen }
Compose Screen 编排层           ：纯声明式 UI，交互回调上抛；颜色只取 ComponentTokens
        ↓ StateFlow collectAsState()
ViewModel 主控层                ：BaseViewModel(application)，execute{}/onSuccess/onError/onStart，viewModelScope
        ↓ 复用既有底层（未重写）
DB / DAO / model / 工具 / 偏好   ：appDb.*Dao、AutoTask、ContentProcessor、ReplacePreview、
                                  AppConfig、OkHttpUtils、FileUtils、ACache、GSON 等
```

- 状态：kotlinx `StateFlow` + `collectAsState()`。工程无 `lifecycle-runtime-compose` 依赖，**未使用** `collectAsStateWithLifecycle`。
- 宿主基类：`androidx.fragment.app.FragmentActivity`（弹窗域需要 `supportFragmentManager`），不继承 appcompat `BaseActivity`。
- 颜色：新代码内联 hex = 0，全部取自 `ComponentTokens`。
- 未复用：旧 XML 布局、ViewBinding、RecyclerAdapter / ViewHolder、旧 Fragment 编排、旧菜单。

## 7. 反例与边界（假设当前方案错误，逐条找反例与兜底）

1. **空数据 / 空目录 / 空搜索结果**：列表 VM 初始 `loading=true`，DAO 返回空列表时 Screen 走 `InkEmptyState` 空态；文件域目录读不到时走错误空态 + 重试（`FileManageScreen.kt` 错误分支调 `onPop` 回根）；词典/替换/自动任务无规则时空态给「新建」动作。未做真机空态渲染验证（见 §9.1）。
2. **网络断开 / 在线导入失败**：在线导入 URL 走 OkHttp 既有调用，异常由 VM `onError` 收口到错误文案；`ImportAutoTaskViewModel` 解析失败落 `state.error`，弹窗展示错误空态而非崩溃；离线时帮助文案、本地规则、本地文件导入路径不依赖网络。
3. **缺字段 / 同名消歧失败**：导入 JSON 字段缺失或类型不符时，`GSON.fromJsonObject/fromJsonArray` 走 `getOrNull()` 兜底为 null，比对结果记为「新增」；`AutoTaskRule` / `ReplaceRule` / `DictRule` 实体缺字段按默认值构造，不抛空指针。同名规则由 DAO `getByName` / `findById` 定位，编辑态按 id 区分。
4. **极端参数**：Cron 表达式非法时 `CronSchedule.parse` 返回 null，编辑保存前拦截并提示，不落库；替换规则 pattern 为空时编辑校验拦截；文件选择扩展名列表为空时不过滤；超时字段非法时预览走 `ReplacePreviewException` 分流提示，不阻塞保存。
5. **权限被拒**：存储 / 图片权限拒绝时走 `PermissionsCompat.Builder.onDenied` 回调，Toast 提示并留在当前页，不强制跳转；系统选择器无可用 Activity 时，`SelectImageContract` 内部已回退 PickVisualMedia。
6. **大列表 / 长文本**：列表用 `LazyColumn` 惰性渲染；长脚本/响应头走全屏 `CodeEditActivity` 文本文件缓存（`TRANSFER_THRESHOLD=4000` 本地阈值），不在 Compose 内联大文本编辑；超大导入 JSON 只读查看，不做内联可编辑合并。
7. **反例自检（方案可能被推翻的点）**：若 `findById` 之外 DAO 还存在旧调用方依赖 `get(id)` 旧名，本次未保留该别名——已核 `ReplaceRuleDao.kt` 仅有 `findById`，旧名不存在；若 Compose 运行时缺少某 `ComponentTokens` 字段，§5.1 已逐个比对引用 token 均有定义，但未经编译器确认，仍属 §9.1 未验证。

## 8. 认知成本（接手人视角）

- **新增概念**：每域三个新角色——`Screen`（纯编排）、`Models`（UI 状态数据类 ↔ 实体映射）、`List/Edit ViewModel`（StateFlow 主控）；外加共享 `ToolScaffold` 骨架组件。接手人需先理解「Screen 不直接碰 DAO、VM 不持有 Compose 状态」这条单向边界。
- **抽象层数**：相比旧「Activity + XML + Adapter + VM」四层，新结构仍是四层，但 XML/Adapter 两层被 Screen/Models 替代；没有新增跨层抽象，复用件仍是既有 DAO / model / 工具。
- **命名澄清**：
  - `XxxUi`（如 `ReplaceRuleUi`、`AutoTaskUi`、`DictRuleUi`）= 界面状态模型，非数据库实体；实体映射在 `Models.kt` 的 `toEntity()` / `toUi()`。
  - `ReplaceFilter` 是密封类（All / Group / NoGroup），不是字符串枚举。
  - `AutoTaskField` 枚举标识全屏代码编辑目标字段，与表单草稿字段一一对应。
  - `HandleFileContract` 常量 0–4 是模式码，不是请求码；`Result.requestCode` 才是 ActivityResult 请求码。
- **可能的困惑点**：四域 Screen 内保留了少量内联中文文案（未抽 `R.string`），与参考 Compose 页一致；多语言收口需后续统一（见 §10.3）。`ReplacePreview.kt`、`HandleFileContract.kt` 是有意保留的旧纯逻辑文件，不算贴皮残留，勿误删。
