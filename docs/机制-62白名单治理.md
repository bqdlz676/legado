- 62 闸（`data_scripts/check-line-anchors.py`）扫描 `docs/**/*.md` 里的 `文件:行` / `文件:行-行` 锚点，指向不存在文件或行号越界即判 DEADFILE / OUTOFRANGE FAIL；白名单 `docs/.line-anchors-allow.txt` 按「引用文档｜锚点串」逐条放行。

- 治理目标：让「仓外样本 / 已删夹具」的证据不再需要白名单——把路径文本本身改成不可被扫描器识别的散文写法，信息不丢；改完一条删一条豁免，白名单收到合理下限（本单收到 0 条）。
- 边界：本单只改 `docs/` 文档与白名单文件；未做任何 git 写操作（add / commit / push / stash / checkout / restore），未跑编译，未改 `data_scripts/` 脚本与基线 JSON。

## 二、治理口径

- 扫描器识别形态：完整锚点 `名称.扩展名:行号[-行号]`；裸锚点 `:行号[-行号]` 归属上文最近一次完整锚点的文件。改写后散文里不出现「扩展名紧跟冒号加数字」的组合，也不出现裸 `:数字` 片段，即不可被命中。
- 保留要素（每条都核对过）：夹具 / 探针文件名、行号（含区间）、成员或类别槽位语义、「仓外镜像仓 / 仓外迷你仓 / 仓外夹具 / 临时探针 / 验毕已删」限定词；FAIL 原文的判定类别、成员名、断言消息逐字未动，只替换定位串。
- 不改的部分：真仓源码、真仓脚本、真仓文档自身的合法锚点；基线冻结的存量老账不在本单追改范围。
- 闸脚本落点：完整锚点正则 `data_scripts/check-line-anchors.py:53`；白名单装载 `data_scripts/check-line-anchors.py:123`；豁免比对 `data_scripts/check-line-anchors.py:150`。
- 改坏推演：若把锚点整段删掉而不保留文件名与行号，证据链会断、回源对不上原红行；若图省事继续往白名单里加条目，闸会被位置型豁免慢慢架空。本单两条都避开：散文保留文件名、行号、槽位与限定词，豁免逐条删净，不靠新增白名单收口。
