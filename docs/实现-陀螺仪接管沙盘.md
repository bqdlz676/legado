## 二、规格九节逐条对账

### §一 技术路径
- 原生 `SensorManager.TYPE_ROTATION_VECTOR`（加速度计 + 陀螺仪 + 磁力计融合）首选；不走 DeviceOrientation API（file:// 不授权）。落点：`GyroBridge.kt` 首选传感器取值段、旋转向量取四元数入队段（均以现行行为准，核对时点 2026-11-27 19:13 CST；Q-447 在飞）。
- 链路 `SensorManager → FIFO 缓存（10 条四元数）→ 每帧取一条 → Three.js slerp 合成`。落点：`GyroBridge.kt` 队列声明段、入队超上限挤掉队首段；`gyro.js` 每帧 `pollNative` 拉一条段、slerp 合成段（均以现行行为准，核对时点同上；Q-446 / Q-447 在飞）。
- 规格原文「500ms 窗口，10 条」：队列上限按 §二锁定 10 条；50Hz 下 10 条约覆盖 200ms 新鲜值，旧值不堆积。

## 三、边界自兜方案（逐条对应实现点）

1. 传感器抖动 / 精度差：JS 侧 0.08 低权 slerp 做平滑；非有限（NaN / Infinity）四元数帧直接丢弃不入合成（`gyro.js` NaN 丢弃段）；FIFO 只留 10 条新鲜值，旧值不回流。原生侧 `onAccuracyChanged` 不抛错，精度问题交给 JS 平滑吸收（`GyroBridge.kt` 精度回调段；均以现行行为准，核对时点 2026-11-27 19:13 CST；在飞）。
2. 快速切前后台：`start()` 入口先 `stop()` 幂等清旧监听与旧队列，重注册不叠监听（`GyroBridge.kt` 申领幂等段）；`onPause` 立即注销、`onResume` 重注册（`PlaceMapActivity.kt`、`BattleActivity.kt` 生命周期段）；回前台走 800ms 过渡，不硬切视角（`gyro.js` 回前台过渡段；均以现行行为准，核对时点同上；在飞）。
3. WebView 销毁后回调：桥方法是纯取数，不持有、不调用 WebView；原生侧无主动 `evaluateJavascript`，销毁后不存在悬空推送（`GyroBridge.kt` 桥注释段、`PlaceMapActivity.kt`、`BattleActivity.kt` 桥持有段）；`onDestroy` 先 `stop()` 再 `destroy()` WebView（两 Activity `onDestroy` 段）；`pull` 空队返回空串，JS 侧 try/catch 兜底（`gyro.js` 拉取 try/catch 段；均以现行行为准，核对时点同上；在飞）。
4. 无磁力计：先回退游戏旋转向量；游戏向量也缺时才进加速度 + 磁力融合；磁力计仍缺则判不可用，不硬算（`GyroBridge.kt` 降级选择段）。兜底分支 `degraded=true`，JS 锁死 0.04 权重档位（`gyro.js` 兜底锁权段与 `setWeight` 段；均以现行行为准，核对时点同上；在飞）。
5. 屏幕旋转 90° / 180° / 270°：融合矩阵路径按 `Display.rotation` 走 `remapCoordinateSystem` 换轴（`GyroBridge.kt` 方向重映射段）；JS 监听 `orientationchange` 清拖动偏移、重置叠加基准、清过渡态（`gyro.js` 方向变更监听段；均以现行行为准，核对时点同上；在飞）。
6. 设备平放（Pitch 90° 万向节奇异）：`getRotationMatrix` 在姿态异常 / 磁力过弱时返回 false，该帧丢弃等下一帧，不把坏矩阵转四元数（`GyroBridge.kt` 融合矩阵判空段）；四元数出库前归一化，零向量除零有 `coerceAtLeast(1e-9)` 保护（`GyroBridge.kt` 归一化保护段）；旋转向量路径不经过矩阵奇异点（均以现行行为准，核对时点同上；在飞）。
7. 跟随模式拖到一半切后台：切后台瞬间复位 `draggingFollow`，不留半按态；回前台重新走 800ms 过渡，拖动偏移在回弹窗口内自然归零（`gyro.js` 前后台复位段，以现行行为准，核对时点同上；Q-446 在飞）。
8. 全无传感器设备：`start()` false → JS `available=false`，dock 不挂载、模式强制关闭，不显示可点的死按钮（`gyro.js` 能力探测段、`setMode` 守卫段、`buildUI` 早返段；以现行行为准，核对时点同上；Q-446 在飞）。
9. 桥未就绪 / file:// 桥注入晚于首帧：`pollNative` 每帧探一次，桥在后续帧到位即自动接上，首帧缺值不报错（`gyro.js` 每帧拉取段，以现行行为准，核对时点同上；Q-446 在飞）。

## 七、新发现问题

1. `battle.html` 手势全量走 `touchstart/touchmove/touchend`，未用 pointer 事件；`gyro.js` 的跟随拖拽监听挂在 pointer 上。现代 WebView 通常合成 pointer 事件，但未在真机内核验证；兜底方案是在 `bindFollowDrag` 再补一组 touchstart/touchmove/touchend 同名处理。
2. `app/src/main/assets/map/three.html` 既有相机是「球面轨道 + lookAt」模型，无独立 `controls` 对象；规格 §九所述「引用现存 camera、controls 对象」中的 controls 在本仓不存在。本单 `Gyro.attach(camera)` 只接 camera；轨道偏航 / 俯仰仍由页面既有变量驱动，未抽象 controls。
3. 跟随模式下相机位置仍按既有球面轨道计算，姿态被陀螺仪四元数覆盖；位置与姿态短期解耦，展示时可能出现视点平移但朝向由手机决定。若验收要求跟随模式视点锁定在目标点纯换朝向，需下一单把位置计算也纳入合成层。
4. 权重金点只有四个，档位表五档（0.04–0.20）；0.20 档在指示器上与 0.16 档同显第四点，属 UI 粒度限制，不影响功能。
