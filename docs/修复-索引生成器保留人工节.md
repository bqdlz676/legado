## 三、sha256 前后对比取证（人工节字节未变）

对比口径：取每次 `--write` 前人工尾段（机制 `## 三、` 起、文档 `## 附：` 起）与写盘后 END 标记之后的区间外正文，trim 首尾空行后取 sha256。

命令（一次跑完，结果落盘后只读一次）：

```
python3 - <<'EOF'
import hashlib, pathlib
GEN_S, GEN_E = '<!-- GEN:START -->', '<!-- GEN:END -->'
def post_body(text):
    lines = text.splitlines(keepends=True)
    e = next(i for i,l in enumerate(lines) if l.strip()==GEN_E)
    return ''.join(lines[e+1:]).strip('\n')
for short in ('索引-机制.md', '索引-文档.md'):
    after = post_body(pathlib.Path(f'docs/{short}').read_text(encoding='utf-8'))
    before = pathlib.Path(f'/tmp/q242/{short}.manual.before').read_text(encoding='utf-8').strip('\n')
    hb, ha = hashlib.sha256(before.encode()).hexdigest(), hashlib.sha256(after.encode()).hexdigest()
    print(f'{short}: before={hb} after={ha} 一致={hb==ha} 字节={len(after.encode())}')
EOF
```

真实输出：

- `索引-机制.md: before=0ea5d652e09e9546968ec23957006767a9622bbf9fb6c8d86afb3a4658d417e3 after=0ea5d652e09e9546968ec23957006767a9622bbf9fb6c8d86afb3a4658d417e3 一致=True 字节=3012` —— PASS。

- 幂等复跑：两个生成器再各跑一次 `--write`，人工节 sha256 仍与上表一致（二次写后一致：机制 `0ea5d652e09e9546`、文档 `15326d13dbcb5c5d`）。

## 五、影响 / 自查反例 / 认知成本

### 5.1 二阶三阶影响

- 直接效果：两个生成器重跑不再冲掉 §三 / 附录人工节；手写门禁表与 M-56 风险行有区间外位置兜底。
- 连带影响：54 接线审计把新检测器计入 49 个门禁并确认已接线；51 自测覆盖计入 48 个门禁；后续任何文档轮次先跑 `--write` 再补人工节的顺序约束松绑——人工节在区间外，顺序不再敏感。
- 维护成本：新增 `GEN:START/END` 两个约定标记；区间内可被机器重写，区间外禁机器覆盖，写文档的人需要知道这条边界。

### 5.2 自查反例（改坏推演）

- 反例 1（现场已踩到）：人工节正文反引号里写了 `<!-- GEN:START -->` 字样，初版用子串 `in text` 判标记，把这句散文误切成真标记，机制索引人工节被腰斩成两段。改法：标记行必须 `strip()` 后整行相等；生成器与 58 检测器同口径。状态：已修。
- 反例 2（人工标题缺失）：若未来人工节不再以 `## 三、` / `## 附：` 开头，首次迁移切不出尾段，post 为空；58 会因关键词缺失判红，不会静默丢节。状态：已闭环（检测器兜底）。
- 反例 3（区间掏空）：生成器 bug 导致 GEN 区间内无正文，58 判「GEN 区间为空」红。状态：已闭环（检测器兜底）。
- 反例 4（人工节被挪进区间）：后人把手写内容贴到 START/END 之间，下次 `--write` 照样冲掉；58 按关键词行号判其落在区间内并点名行号。状态：已闭环（检测器兜底）。
- 反例 5（并发双写）：两个代理同时跑 `--write`，区间外仍各自从落盘文件提取保留，不会因并发把人工节写丢；区间内生成正文以最后一次写为准，属可重生成内容。状态：已闭环。

### 5.3 认知成本

- 新增概念仅两个标记串，无新抽象层；接手人看文件头迁移说明 + 58 检测器判据即可懂。命名上 `GEN` 即 generated，与人工节对照明确。
