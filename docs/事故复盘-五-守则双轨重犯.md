# 事故复盘（五）· 没读既有三份必读就先新造四份守则

> 记录时间：2026-11-26 深夜。等级：机制级事故（重犯事故三）。
> 一句话：仓库早已有 `docs/机制-总控必读.md`、`docs/机制-子代理必读.md`、`docs/机制-验收代理必读.md` 三份成文守则（分别 149 / 67 / 67 行，含铁律编号、槽位口径、CI 五级判读、验收六坑），我却新建了 `docs/开工/` 四份平行件，等于把同一件事做成两套判据。

## 一、事实（可回源）

- 既有件：`docs/机制-总控必读.md`（1–149 行）、`docs/机制-子代理必读.md`、`docs/机制-验收代理必读.md`；`docs/落文-规矩总纲.md:13` 明写「开工第一步两读 + 逐条调用全部铁律自检」并点名这三份；`:14` 还规定了派单第一行的固定前置句。
- 我的动作：新建 `docs/开工/总控-派单必读.md`、`写码子代理-开工守则.md`、`验收子代理-开工守则.md`、`机制-文档子代理-开工守则.md` 四份，并改 `docs/接手/00-入口.md` 新增 §2.5 指向这四份。
- 触发点：用户一句「之前已经有守则了你自己没读也没及时修订」，与事故三（自造七层金字塔）完全同型。

## 二、损失

- 直接：四份文档（约 300 行）与既有三份重复，下一棒会读到两套口径，早晚要合并。合并成本已付出（四份内容已并入三份并删除目录）。
- 间接：我用自己的守则里第一条「先找现成事实源，不许新建平行件」违反了自己——说明"写在文件里"不等于"开工时真会读"。
- 更深一层：三份既有守则本来就是**没及时修订**的状态（今晚新增的语法预检、S4 行数上限、四机检、CI 红停发新功能单、未验入库补账全都不在里面），所以真问题不是"我造了新文件"，而是"既有件停更了两天，没人发现"。

## 三、根因（三层）

1. **开工动作缺一步**：我的流程里"读总纲"有，"grep 是否已有同类守则"没有。开工检查只查了门禁脚本，没查文档事实源。
2. **守则没有变更触发条件**：三份必读没有"何时必须改"的条款，于是新增规则都散在派单里、散在事故复盘里，没有回流成守则条款。
3. **索引与正文分离**：`docs/接手/00-入口.md` 的 §2 只列了"台账与工序"，没列"开工文案在哪"，导致我按任务需要临时找，找到一半就自己写。

## 四、处置（已落地）

1. 四份新件全部并入既有三份（总控 §13/§14、子代理 §7、验收代理 §8），`docs/开工/` 目录删除。
2. `00-入口.md` §2.5 改为指向三份既有件，并把本次事故写成一句警示，防下一棒重犯。
3. 三份必读各加"变更触发条件"（见下），把"何时改"从隐性变显性。

## 五、变更触发条件（写进守则，防止再停更）

- 新门禁/新规则上线 → 当天改对应必读（总控改 §13、执行方改 §7、验收方改 §8）。
- 出一次事故 → 事故清单加一行（总控 §14），并把处置条款落到对应必读。
- 每轮收口前 `grep` 三个必读文件的最后修改日期，落后 HEAD 超过一天的，先补再收口。
