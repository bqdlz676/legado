# 通用战役推演引擎规格
## 零、数据驱动（核心铁律）
**引擎不内置任何一场战役。** 所有战役 = 一个 JSON，引擎 = 吃 JSON + 地形 + 规则，吐出推演过程。验收方式：同一份引擎，喂垓下之战 → 推出来项羽被围、韩信十面埋伏；喂赤壁 → 推出来火攻生效的关键在风向和铁索连船。
```json
// 通用战役 JSON schema
{
  "id": "gaixia",
  "title": "垓下之战",
  "era": "前202",
  "terrainFocus": { "center": [117.2, 33.5], "radius": 80 },
  "heightMap": "gaixia_height.png",
  "duration": 30,           // 推演回合上限
  "victory": {               // 胜利条件：不是"谁活到最后"，是目标
    "type": "annihilate",    // annihilate | capture | defend | escape | reachPoint
    "target": "项羽",
    "side": "汉"
  },
  "armies": [
    {
      "id": "xiangyu",
      "name": "项羽",
      "side": "楚",
      "color": "#C23B2E",
      "initialPos": [117.19, 33.52],
      "strength": 10,           // 单位战斗力，不搞人数，用相对值
      "type": "elite",          // elite | regular | militia | cavalry
      "fatigue": 2,             // 0-5，开局已累
      "morale": "wavering",     // high | steady | wavering | broken
      "intent": "escape"        // 开局意图（被规则引擎按优先级自动覆盖）
    },
    { "id": "hanxin", "name": "韩信", "side": "汉", ... },
    { "id": "pengyue", "name": "彭越", "side": "汉", ... }
  ],
  "events": [                   // 脚本事件：不是硬编码，是按条件的 if-trigger
    {
      "trigger": { "turn": 5 },
      "action": "moraleChange",
      "target": "xiangyu",
      "value": "wavering",
      "reason": "四面楚歌"
    },
    {
      "trigger": { "army": "xiangyu", "strengthBelow": 2 },
      "action": "surrender",
      "target": "xiangyu"
    }
  ]
}
```
**不是硬编码「四面楚歌发生在第 5 回合」**——而是声明了触发条件。改一场仗只改 JSON，不改引擎。
## 二、地形通用算法（不依赖具体区域）
高度图从 PNG 读。地形分析层所有输出都是**相对地形**，不依赖具体坐标：
| 计算 | 解释 |
|---|---|
| `traversable(cell)` | 坡度 ≤ 45° → 步兵可过；坡度 ≤ 30° → 马可过；坡度 ≤ 15° → 辎重车可过 |
| `fords(map)` | 找连续 2 格以上、相邻也为河的窄河段 → 涉渡点 |
| `chokePoints(map)` | 找相邻高坡之间的狭窄通道，宽度 ≤ N 格 |
| `highGround(cell, radius)` | 周围 N 格内相对高差 > 阈值的制高点 |
| `visibility(from, to)` | 两点之间是否有地形遮挡（山脊线遮挡） |
| `AStar(from, to, armyType)` | 代价 = 距离 × 坡度惩罚 × 路况（平地 > 丘陵 > 山地 > 河流） |
| `flankPath(from, to, enemyPos)` | A* 但强制绕开敌方视线的路径 |
**算法 = 地形归地形、军队归军队、互不影响。** 加一场新战役 = 放一张高度图 PNG + 填一份 JSON。不需要调代码。
## 三、推演引擎（跟具体战役无关的纯规则层）
每个回合：
```
for 每一支军队（按速度排序——骑兵先动、步兵后动）:
  1. 情报更新
     - 能看到敌方军队位置 IF 敌军在己方视野内（无山脊遮挡 AND 距离 < 可视半径）
     - 看不到的 → 用敌方上次已知位置 + 模糊半径
     - 地图（地形本身）永远完整可见
  2. 规则意图轮询
     - 检查当前意图是否已完成（到达了、打赢了、逃掉了）
     - 检查是否有更高优先级的意图（遭遇战 > 撤退 > 包抄 > 进军）
     - 需要换意图时，根据优先级 + 战场态势自动切换
  3. 移动（A*，沿地形的实际路径，不是飞）
     - 行军速度 = 基础速度 × 路况系数 × 疲劳惩罚
     - 移动完成后更新位置
  4. 遭遇检测
     - 两军相邻格 → 触发遭遇
     - 一方伏击中 → 伏击方优先判定、伤害 +2x
     - 一方在制高点 → 防御 +1.5x
     - 结算：伤亡 = 兵力平方之比（兰彻斯特简化），败方后撤 1 格 + 士气下降
  5. 状态更新
     - 疲劳 = 当天行军距离 / 日行上限 + 已有疲劳
     - 疲劳 > 4 → 士气降一级
     - 士气 broken → 军队解散（消失）
     - 补给断绝 > 3 回合 → 疲劳加速
```
**规则意图优先级**（从高到低）：
1. 遭遇战中 / 被攻击 → 应战
2. 士气 broken → 溃逃（朝远离所有敌军的方向）
3. 被包围（四周均有敌） → 突围（朝敌最弱的方向）
4. 有可执行的伏击条件（敌军即将进入伏击点） → 设伏
5. 当前有意图 → 执行意图
6. 无意图 → 据守（军队原地不动）
## 四、胜利条件（不是「杀光」一种）
| 类型 | 条件 |
|---|---|
| `annihilate` | 目标军队被消灭或投降 |
| `capture` | 目标点/城被我方占领3回合 |
| `defend` | 目标点/城未失守，撑过所有回合 |
| `escape` | 目标军队移动到逃脱点并存活 |
| `reachPoint` | 我方军队到达目标点 |
| `rout` | 敌方所有军队士气broken |
| `compound` | 以上条件的 AND/OR 组合 |
**胜利判定不是最后一回合才查**——每回合都查。达到即结束。
## 五、推演回放与手动干预
**自动模式**：点「推演」→ 引擎自动跑完全部回合，每个 phase 的箭头/棋子移动/战斗动画自动播放。底部面板实时展示每回合结果。
**手动模式**：每回合暂停，用户可以**拖拽调整军队意图**——把「撤退」拖成「包抄」、把「据守」拖成「急行军」。拖完点「执行本回合」→ 引擎用新意图算这一步的结果。这是「推」的核心——不是看动画，是**你也能当一次韩信**。
**分支保存**：手动改了意图之后，当前状态（所有军队位置/士气/兵力）可以存成一个分支存档。用户可以「如果我在第 3 回合改包抄会怎样」→ 开一个分支 → 跑到底 → 跟原历史线对比。
## 六、验收战役（必须按这个顺序做，难度递增）
| 验收战役 | 验证什么 | 回合数 | 军队数 |
|---|---|---|---|
| 垓下之战 | 包围、突围、士气崩溃、四面楚歌事件 | 30 | 6 |
| 长平之战 | 对峙、切断粮道、包围圈合拢 | 60 | 8 |
| 四渡赤水 | 多次渡河、来回穿插、情报模糊、摆脱追击 | 60 | 6 |
| 淝水之战 | 退兵溃散、心理士气链式传导 | 10 | 4 |
| 赤壁之战 | 风向/火攻/水军（新增 weather/temperature 变量） | 20 | 5 |
第一行跑通就算引擎框架成立，后面全是数据填充。

**一句话给实现 AI**：一份引擎代码，吃 JSON（战役定义）+ PNG（高度图），吐出回合制推演过程。推演 = A* 寻路 × 规则意图轮询 × 兰彻斯特简化结算 × 事件触发器。所有战役数据独立于引擎，加新战役不碰代码。
纯规则引擎（不花钱，离线跑）
Android 本地，手机 Ubuntu 里一个 Node.js 进程，沙盘 WebView 连 ws://127.0.0.1:8765。
运行位置目录结构
```

├── server.js           # WebSocket 入口
├── engine/
│   ├── SimEngine.js    # 回合主循环
```

核心：IntentResolver（规则决策）
```
优先级（从高到低）：
1. 当前正在遭遇中        → FIGHT（应战）
2. 士气 broken           → ROUT（溃逃，朝远离所有敌方的方向）
3. 被包围（四方有敌）     → BREAKOUT（朝敌最弱方向突围）
4. 有伏击条件触发        → AMBUSH（停在关隘不暴露）
5. 补给断绝 > 3 回合     → RETREAT（朝最近补给点退）
6. 当前意图未完成        → CONTINUE（继续执行）
7. 无意图                → HOLD（原地据守）
```
意图切换逻辑：
```
function resolveIntent(army, allies, enemies, terrain, turn):
  1. 先检查硬性生存条件（broken→溃逃，被围→突围，断粮→撤退）
  2. 再检查战术机会（敌在必经关隘→包抄，制高点空→抢占）
  3. 都不触发→维持当前意图
  4. 行军途中遇敌→FIGHT（遭遇战优先级最高）
```
全部规则表：
| 条件 | 意图 | 参数 |
|---|---|---|
| 相邻格有敌军 | FIGHT | 攻击最近敌军 |
| 士气 broken | ROUT | 朝远离所有敌方向 A* |
| 四向有敌 | BREAKOUT | 朝敌兵力最小方向 A* |
| 在关隘 + 敌距 < 5 格 + 己方未暴露 | AMBUSH | 原地不动 |
| 补给 ≤ 0 持续 3 回合 | RETREAT | 朝最近补给点 |
| 持有制高点 + 敌距 < 3 格 | HOLD | 防御加成 |
| 兵力 3× 于最近敌 | ADVANCE | 朝敌进军 |
| 有盟友相邻被攻击 | SUPPORT | 朝盟友位置 A* |
| 未持有关隘但敌距 > 5 格 + 关隘空 | SEIZE | 抢占关隘 |
| 以上均不触发 + 当前有意图 | CONTINUE | 沿原路 |
| 以上均不触发 + 无意图 | HOLD | 原地 |
决策代码量 ~150 行。不调模型，不联网，一回合 < 1ms。
