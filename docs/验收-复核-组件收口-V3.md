## 六、反例与边界（最强反对者视角）

- 反例一：并集写成 offline 覆盖 state，或优先级错置。若闸函数写成 `offline || state.eventsAllowed` 反向逻辑，DISABLED 显式态可能被 offline=false 放行。否证：实测公式为 `state.eventsAllowed && !offline`（`Timeline.kt:90`），契约阻断档 `eventsAllowed=false` 先硬短路，测试 `:28-30` 锁定；offline 只在放行档追加阻断，不覆盖阻断档。
- 反例二：离线布尔误伤压淡。若并集时把 offline=true 也套成 DISABLED 0.30，缓存内容会被错误压淡。否证：契约 OFFLINE `contentAlpha=1f`（`ComponentSystemContract.kt:49`），`timelineContentAlpha` 只读枚举字段，测试 `:103` 锁定 DEFAULT+offline=true 仍 1f，`:105-108` 锁定离线布尔前后透明度相等。
- 反例三：EMPTY 被离线/空态分支误伤成禁用。契约 EMPTY `eventsAllowed=true`、`contentAlpha=1f`（`:46`）；测试 `:36`、`:53`、`:111-112` 双向锁定 EMPTY 放行不压淡。
- 边界一：只传 loading 布尔。`effectiveLoading`（`Timeline.kt:121`）并集后先走三点加载分支（`:126-129`），Body 不渲染，箭头闸不参与；LOADING 禁点由分支缺席与契约 `eventsAllowed=false` 双保险。
- 边界二：单向可用。首节点 `canGoBack=false`、末节点 `canGoForward=false`，箭头闸末位与运算置不可点；`TimelineModel.goBack()/goForward()`（`Timeline.kt:63-65`）边界原地返回，不抛异常。
- 边界三：布尔与显式 state 冲突。显式 `state=DISABLED` 时无论 offline 布尔如何，契约 `eventsAllowed=false` 先短路；显式 `state=OFFLINE` 与 offline=false 一致禁点；state=DEFAULT 且 offline=true 按布尔禁点。
- 边界四：空数据/断网/缺字段。`effectiveEmpty`（`Timeline.kt:123`）兜住空列表进 `InkEmptyState`；Body 内 `model.current() ?: return`（`:151`）二次防空，索引越界不崩、不画越界节点。
- 边界五：低端机 reduce-motion。压淡走静态 `alpha` modifier（`:154-156`），不挂动画时长弹簧；reduce-motion 只归零动画区间，不回退静态透明度。
