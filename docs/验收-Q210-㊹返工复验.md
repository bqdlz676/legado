## 二、反向自检（改坏推演）：这条判据现在还能不能被我钻空子？

改坏推演（二阶/三阶影响）：本次六处修法都在门禁/轮询脚本内部，不触碰 `app/**` 与排版引擎；二阶影响是门禁口径变严后，历史队列里的非标准行可能新暴露为 FAIL（预期内，属盲区显形而非误伤）；三阶影响是若把"状态格子串定位"进一步放宽到任意单元格关键词，会放大 N-2 假阳性，故后续修 D-2 时应先收紧状态格白名单、再谈兜底。下面逐条给出想过的绕过思路及是否成立。

- **D-1**：
  1. 思路 a（**成立，记 N-1**）：把坏样本放进 fixtures 下一个**未跟踪子目录**。`git status --porcelain` 对未跟踪目录折叠为目录名，只输出 `?? data_scripts/fixtures/sub-evil/`，`paths_ok()` 拿 basename `sub-evil` 去匹配 `POLLUTION_RE`，内层 `坏样本.md` 永远不被看到。实测：
     ```
     $ mkdir -p data_scripts/fixtures/sub-evil && printf x > data_scripts/fixtures/sub-evil/坏样本.md
     $ git status --porcelain → ?? data_scripts/fixtures/sub-evil/
     DISPATCH-A: PASS … RC=0   # 静默放行
     ```
     修法缺口：`tracked()`/`paths_ok()` 只逐文件判，未展开未跟踪目录内容。建议：A 判据对 fixtures 下未跟踪目录整体点名，或 `git status --porcelain -uall` 展开内层文件。
  2. 思路 b（不成立）：先 `git add` 把污染文件纳入索引再留着——`tracked()` 确会放行，但该文件进入提交链与 diff，其他门禁/评审可见，不是静默后门；与"未跟踪塞样本"性质不同。

- **D-2**：
  1. 思路 a（**成立，见 2c/2d**）：写成无管道纯文本行，或行首加空格，两个正则（`ROW_RE`、`raw_running`）的 `^\|` 锚定都失败，行从 B/C 视野整体消失。
  2. 思路 b（**成立，记 N-2，假阳性方向**）：状态格按词子串定位，DONE 行的备注/标题里出现"RUNNING"字样即被误判为在飞。实测：
     ```
     | Q-930 | 备注：曾 RUNNING 后收口 | DONE（s_fakeDone） | 域 |
     DISPATCH-B: FAIL … Q-930 s_fakeDone：轨迹不存在 …   # 误报
     ```
     修法缺口：应优先取精确状态格（白名单词独立成格），子串命中仅作兜底。
  3. 思路 c（不成立）：把状态词写进依赖列/锚列——同思路 b 同根因，子串定位都会选中；列漂移场景下按词定位仍是当前折中，假阳性代价低于真盲区。
- **D-3**：
  1. 思路 a（不成立）：再造"已完成红 + 在跑"组合压过判定顺序——合成用例实测 rc=1，先判 `bad` 后判在跑，顺序无法被在跑态翻转。
  2. 思路 b（不成立，口径偏严）：`completed` 但 `conclusion=None`、`cancelled`、`action_required` 均不在 `('success','neutral','skipped')` 白名单内，一律计入非绿；保守方向，不会漏红。
