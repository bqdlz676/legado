## 一、背景与目标

既有 50 余个门禁全部是否定式：查文档有没有状态词、有没有回源、有没有锚点、有没有混桶。它们保证「过程合规、构建可信」，但对「这东西到底好不好用、好不好看」零覆盖。本项目的核心价值恰好在后者——东方暖金美学、圆角与间距、辉光半径、动画时长与弹簧曲线、内存上限、帧率目标，这些数字用户已在规格里定死，却没有任何机检能拦住「某次改动把圆角 16 改成 14、把辉光半径改小、把动画 250ms 改成 500ms、把缓存/内存预算胀破」。

本方案把取证到的冻结常量落成结构化契约，由 `data_scripts/check-design-tokens.py` 逐项比对源码常量，不一致即红并打印「契约值 / 源码实际值 / 出处行」。

## 三、机检分级：哪些能拦住、哪些拦不住

### 3.1 可真机检（源码常量 ↔ 契约，本脚本当前覆盖）

**67 条** `check=source`：color 13 / geometry 18 / motion 21 / perf 15。判据是符号级静态比对：解析锚点声明行的 RHS，按 kind 归一化后与契约值比较；主锚点 + aliases 别名锚点逐一过，不一致即红，输出「契约值 / 源码实际值 / 出处行」。能拦住：色值被改、圆角/间距/半径被改、时长/曲线/弹簧参数被改、帧率与粒子/draw call 上限被改、旧口径常量残留。

### 3.2 只能人工（脚本给不了判据，登记 DEFER 不走假绿）

1. **「看起来高不高级」整体美感**：绢帛质感、暖金辉光的分寸、疏密层级是否克制——无单一数值可判，走人眼 + 独立验收代理复核（M4 人判门禁通道）。
2. **图标造型与线条神韵**：圆角端点、收笔走势属造型判断，线宽 1.5px 可机检，造型好坏不可机检。
3. **宣纸颗粒 / 墨爆粒子的观感**：颗粒透明度、粒子疏密有常量可查，但「像不像宣纸、墨爆是否利落」需帧后人眼判定。
4. **空态 / 三变体（loading/empty/offline）是否真的齐全且不刺眼**：静态只能查关键词，呈现效果需人眼。

### 3.3 需要 CI 像素 / 帧率能力（当前沙箱与本脚本都不具备，列工单不实现）

1. **正文对比度 ≥4.5:1（WCAG）**：需渲染帧像素取色算对比度；无帧不冒充通过。
2. **连续翻页 ≥50 帧无掉帧**：需 Macrobenchmark / 帧序列序号差推算，静态常量只能证明预算值写死，证明不了真机不掉帧。
3. **真机帧率 55fps（手机）/ 120fps（桌面）实测**：需真机或 benchmark 采集，`FPS_FLOOR` / `TARGET_FPS_*` 常量只是预算上限。
4. **内存峰值 PSS 三档实测（≤100 / 100–120 / >120MB）**：需运行时 PSS 采集进 bench；当前源码无 100MB 常量，3 条 memory 项全挂 spec-only。
5. **截图基线像素回归**：冻结屏与基线图做像素 diff（区别于门禁 52 的 sha256 整文件哈希）。
6. **spring 回弹手感**：刚度/阻尼比可机检数值，「回弹是否利落不跳脱」需真机手感判定。

### 3.4 下一步工单（只描述，不在本单实现——无 JDK 环境写不出可编译 Kotlin）

- **W-1 截图像素基线**：接 Compose 截图测试 / 真机截帧，建基线图目录与容差像素 diff 脚本，进 CI；覆盖 3.3 第 5 项。
- **W-2 性能 bench 接线**：Macrobenchmark 采集帧耗时 P50/P90、峰值 PSS、首载时长，把 memory 三档、16ms 帧预算、55/120fps、80ms 气泡热路径写成 bench 断言；覆盖 3.3 第 2/3/4 项。
- **W-3 AST 级字面量识别**：以 Kotlin 编译器插件 / ktlint 规则替代当前正则启发式，识别组件层对 token 的引用而非裸字面量；覆盖 3.2 第 4 项与反例 b。
- **W-4 契约改宽提交级守卫**：commit trailer 增加「设计裁决：<token> <旧值>→<新值> 出处行」强制项，接既有提交认证书尾门禁；覆盖反例 a 的提交环节。

## 四、反例推演：门禁怎么变成「假绿花瓶」，以及对应防御

### 4.1 契约 JSON 被顺手改宽（把 40dp 写成 30dp 就绿了）

**最强反对者视角**：门禁读的是仓库里的 JSON，改门禁数据比改代码容易；如果契约值本身可被随意放宽，机检就是自证清白。

脚本内已有防御：

- 每条 `locked: true` 的项必须同时带 `spec_source`（规格出处 `文件:行`）与 `ruling_ref`（设计裁决说明）；缺任一项，校验直接 FAIL「契约缺裁决锚点，不许无裁决改宽」。
- `--emit` 抽取的初版骨架强制标 `"review": "draft"`，校验时打印 WARN；默认拒绝覆写锁定契约，覆写需 `--force`。
- 契约值与规格出处成对入账，改值必须能指回规格行；规格本身未给数值的工程推定项一律 `locked: false`，不享受冻结保护，也不冒充规格裁决。

残留缺口：同一提交里「改契约值 + 补一行裁决说明」仍可能骗过静态比对；提交级 trailer 守卫属 W-4，本单未实现。

### 4.2 源码把常量拆成局部字面量绕过 grep

**最强反对者视角**：主 token 文件守住了，但某个 Composable 内部写 `Color(0xFFC23B2E)`、`350.dp`、`250f`，常量表里查不到，门禁全绿而页面已经漂了。

脚本内已有防御：

- `--sweep-literals` 模式启发式扫描组件层（豁免清单内的 token 定义文件除外）内联裸色值 `0x........`，输出 WARN 候选清单与出处行；本轮实跑扫出 **22 处**候选（如 `card/TopicMarxCard.kt:40,43`、`main/PersonDetailActivity.kt:169`、`main/explore/ExploreInkFragment.kt` 多处），留待 W-3 AST 级收口。
- 豁免文件清单显式登记在契约 `literal_sweep_exempt_files`，新增 token 副本必须先登记，不许口头豁免。

残留缺口：正则认不出函数调用内的拼接色值、也判不了裸数值语义（哪个 12 是间距、哪个 12 是字号）；故 sweep 只出 WARN 不置 FAIL，AST 级识别在 W-3。

### 4.3 同一语义两个常量名，只检到一个

**最强反对者视角**：`GlowRadiusDp` 与 `glowRadius`、`CARD_RADIUS_DP` 与 `cardRadius` 并存，主源改了、副本没改，门禁只挂主源就漏报。

脚本内已有防御：

- 每条契约的 `aliases` 是显式同名归一化清单：同一语义的全部已知别名锚点（`文件:行`）逐一比对，任一锚点值与契约不符即 FAIL。
- 本轮实证生效：`card-radius-dp` 的别名 `ShelfTokens.kt:84` 被抓出 14 vs 契约 16（见新发现问题 F-1）。

残留缺口：清单只能覆盖已知副本；新复制一份 token 文件而不登记进 `aliases`，脚本不会主动报警。长期收口方向是推进既有 TODO（`InkTokens.kt:22-23` 已记 D23 收口）删掉阅读页/书架/搜索/发现/启动页五份副本，契约只挂 `ComponentPalette` 单源。

## 五、一阶到三阶影响推演

### 5.1 一阶（直接效果）

- 冻结常量漂移在提交后静态校验阶段被拦住，红灯信息直接给出契约值、源码实际值、出处行，不再靠人翻规格对数字。
- 设计改动多一道手续：改常量必须同步改契约（或走裁决行补 `spec_source` / `ruling_ref`）。

### 5.2 二阶（对其他模块与用户行为的连带）

- **成本上升 → 绕过动机**：改一个圆角要同时改源码和 JSON，执行代理可能倾向把值写成局部字面量避开契约（反例 b）；缓解靠 sweep 提示 + W-3 AST 收口 + 派单模板把「token 只引常量」写成硬约束。
- **与门禁 52（视觉基线）的职责边界**：门禁 52（`check-visual-baseline.py`）管冻结截图/资产 sha256 不漂 + UX 九维关键词静态审计，DEFER 帧/人眼/真机项；本门禁管数值常量↔契约符号级比对。两者正交：52 证明「冻结那一屏的像素和资产没动」，本门禁证明「常量数值没动」。重叠面仅在阴影半径/颜色两类，且 52 是整文件哈希、本门禁是单符号取值，不构成重复判定。
- **与既有 12 色自检的关系**：S-03 锚点卡判据 1–2 查裸 hex 与 token 名引用，本门禁 color 类是其数值级补强；不重复造轮子，裸色值扫描归 sweep 模式。

### 5.3 三阶（长期维护成本与复杂度）

- **维护成本随 token 数量近似线性增长**：每条 = 1 主锚点 + N 别名锚点，别名副本越多，漂移面和比对耗时越大。对策：契约只收冻结值与规格明示值，工程推定项 `locked: false` 不进冻结表；推动 D23 删副本后 aliases 清单同步收敛。
- **token 膨胀风险**：若把所有工程常数（含布局微调值）都锁进契约，门禁会从「防漂移」退化成「官僚盖章」，每次微调都要改两份文件。边界建议：入契约的只限于规格明示值 + 跨页面复用的语义 token；页面局部尺寸留组件自决。
- **认知成本**：新工程师接手只需读契约 JSON（70 条，每条带出处与口径）+ 本方案第三节分级；脚本约 300 行，无第三方依赖，纯 python3 可跑。
