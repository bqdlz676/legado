## 五、反例推演（必写三条）

### a) 55 状态词为何不许统一写「待裁」

「待裁」是尚未裁决 / 尚未派发的开放态。若把已修、已入队、已闭环、判废的条目一律标「待裁」，门禁只检查词表命中就放行，整节假绿：已落地工作被记成没落地，真正待裁的条目混在其中无法分流，下一棒无从判断哪些该派单、哪些已在册。历史上即发生过口径漂移导致 3 份报告整节判红。正确选词：已修＝本单落地；已入队＝挂工单或别单登记；判废＝裁决废弃；待裁＝尚未裁决派发；已闭环＝在册保留或本单范围关闭。每条必须能回指事实，不许凑词。

### b) 当日流水抄别单结论的后果

流水是交接事实源，下一棒按流水回源派单、验收、追责。把别单结论抄成本单事实，会造成「谁做的」不可回溯：产物记到本单名下，双源漂移（㊶ 队列↔台账一致性正是抓这一类）；验收方按流水找本单代理要证据时找不到人；别单若返工，名下记录无法联动。区分口径：每条落文必须挂本棒可回源的 commit 哈希 / 报告路径 / Q 号；别单结论只能作背景引用并标明别单号，不得改写成自身动作。

### c) ㊹ 把还在跑的单写成 DONE，什么机制失效

存活检测（B：轨迹 >10 分钟无更新判僵尸）与熔断（C：超 15 分钟且轨迹 >5 分钟无更新判停摆）都以队列 RUNNING 行为输入。提前把在跑单写 DONE：该代理真挂死 / 超时无人告警，槽位被占却不计在飞，5 槽并发上限与熔断补救全部失效，等于把存活检测开关摘掉。反向同样成立：已交付单挂 RUNNING 是僵尸，会高估在飞数并触发误熔断。状态必须与轨迹存活事实一致；交付未验收可以标 `✅ 已交付` + 验收代理 `待派`，但不能把活着的代理提前销户。
