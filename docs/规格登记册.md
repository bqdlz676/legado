# 落文 · 规格登记册（立项与完整性唯一权威）

> 本册登记"每一项规格"并给它一个状态，用来保证整个项目不漏项、每项都有人做、做完都有人验收。立项规则见下；`data_scripts/spec-check.sh` 每轮机械检查本册。

## 立项规则（铁律 E13 落地细则）

### 0. 本规则用到的词，一律先在这里定义（防止子 AI 各读一段时误读）
- **规格**：用户的一条要求（一个功能、一次规则修改、一次治理动作）。
- **立项**：给规格登记唯一编号，并定"由哪个缺陷号来做 + 做到什么算完成"。
- **缺陷号**：`docs/问题清单.md` 里一行一缺陷的编号，格式 = 大写字母分区 + 数字（例如 D14、B1）。它是"这件事交给谁做"的唯一标识。
- **完成定义（DoD，Definition of Done）**：用一句话说清"做到什么 = 这条规格完成"，让验收的人能据此判"过 / 不过"。
- **验收级别（五级，数字越大越严）**：L0=静态（grep/读代码对得上）、L1=接线（符号存在且真被调用）、L2=编译（CI 绿 + 单测全绿）、L3=契约（冻结签名/边界逐字对上）、L4=运行（真机/整包冒烟）。**L4 用户已定"不用真机"，不作强制门禁**。
- **落地物**：治理动作改出来的东西（规则文档、脚本、目录），用它的 commit sha（git 提交哈希，8 位短号）当证据。
- **执行进度**：问题清单缺陷号那行的标记，🔴=未做、🟡=进行中、🟢=已修待验。

### 1. 规格分两类，立项动作不同
- **功能规格**（要写代码 / 做产品功能）：立项 = **在 `docs/问题清单.md` 立一个缺陷号 + 写完成定义 DoD**。
- **治理规格**（改规则 / 文档 / 机制本身）：**不在问题清单立缺陷号**；直接改出落地物，验收 = 落地物 + commit sha。

### 2. 状态机（每项规格只能是这 4 个状态之一）
- `[待立项]`：已登记，但还没立缺陷号、还没写完成定义。
- `[已立项]`：已立缺陷号 + 已写完成定义，可以派单。（此后做到哪一步，看问题清单该缺陷号那行的 🔴/🟡/🟢）
- `[已验收]`：验收代理给出结论，**必须写"级别 L0~L4 + 证据（报告路径或 commit sha）"**，不许只写"已验收"三个字。
- `[已否决]`：这条规格作废，不再做。

### 3. 每轮动作（用户说完一句话后，当轮必做）
1. 用户**新增**要求 → 当轮：① 把用户原话抽成一条规格（照抄措辞，不改写、不压缩）；② 判它是功能规格还是治理规格；③ 给唯一编号（新增规格用 `N-001` 起递增）；④ 登记进本册「四、新增规格」分区；⑤ 功能规格 → 立缺陷号 + 写完成定义，状态改 `[已立项]`；治理规格 → 改出落地物，状态改 `[已验收]`。
2. 用户**修改**既有规格/铁律/契约 → 找到对应那一行，更新描述并标注"变更 + commit sha"，**不新建一行**；改的是铁律/规则（本册没登记过的）→ 当作治理规格新增一条登记（落地物=铁律改动 + sha）。
3. 每轮结束前 + 每次 commit 前跑 `bash data_scripts/spec-check.sh`；只要还有 `[待立项]` 就当场立项或否决，不许留着。

### 4. 完整性判据（spec-check.sh 机械判断，不是人看）
① 切片编号连续、无跳号；② 本册没有 `[待立项]` 遗留；③ 每个 `[已立项]` 的缺陷号都能在问题清单里找到对应行；④ 每个 `[已验收]` 都写了"级别 L0~L4 + 证据"。
