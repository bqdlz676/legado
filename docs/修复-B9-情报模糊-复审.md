## 三、二阶 / 三阶影响

1. **VictoryChecker 是否误用真实坐标**：未误用，也不应改。`VictoryChecker.check` 收到的是运行态 `corps` 真值列表，承担胜负 adjudication（歼灭 / 逃脱 / 抵达 / 据点归属），属地面真值层，不是玩家情报视图；它从不接收 `perceivedEnemies` 拷贝。据点归属由控制器 `buildPointHolders()` 用真值预算后传入。若把判定层也模糊化，会出现"判不到敌人已逃脱"的失真。本单未改 `VictoryChecker.kt`（他人域）。
2. **分支存档（B7 / wip 分支）恢复后情报是否串线**：不串线。`restoreBranch` 先 `intel.clear()` / `reports.clear()`，再按恢复后的军位重新播种决策层情报，视图目睹记录清空需重新侦察；旧版 `BranchSnapshot` 本就不含情报表字段，情报是可由军位重建的派生状态。wip 分支的 `IntelRecordSnapshot` 字段形态仅只读参考，未搬入 main。二阶：回滚后第一回合决策层持有的是"回滚时刻部署报告"，不是另一时间线的超前情报。
3. **寻路是否因模糊位置改变**：会改变，且是预期内雾战代价。FLANK 避敌剪枝用感知位置；敌军脱离报告位置后环线可能偏旧。`Pathfinder` 域未改，避敌半径仍读感知格。三阶：陈旧报告半径越大，侧翼路径越保守（绕大圈）；后续若要按半径做概率搜索，消费方读 `reportRadiusCells` 即可。
4. **视图路线清空的连带影响**：未观测敌军 `route` 不再下发；B10 分支对比只比 strength/morale/lat/lng/status，不比 route；盲区两侧均 NaN，`POSITION_EPSILON` 比较对 NaN 为 false，不会误报位移。
5. **战力 / 士气情报仍为真值**：感知拷贝只模糊位置；规格 F8 只要求位置雾，兵力 / 士气模糊化属另一议题，未扩面。
6. **死亡 / 投降敌军旧报告残留**：`reports` 不清出局敌军旧条目；快照层不再追加目睹，陈旧报告停在最后目睹位。壳层按 `alive/surrendered` 压暗，影响可控；清扫逻辑挂后续。

## 四、反例与边界

| 边界 | 实现兜底 |
|---|---|
| 敌我同格 | 同格 `octile=0`，目睹距离 0，距离项 0；接触交战互刷，半径 0；与侦察路径合一，不产生双写冲突。 |
| 半径 0 | age≤0（刚目睹 / 刚接触 / 回滚边界负龄期）直接返回 0，不进距离项加法。 |
| 时间戳缺失 / 旧档无情报字段 | `restoreBranch` 不读存档情报，按军位重建；`latestReportRecord` 查不到返回 null → 半径 null、盲区文案兜底；`seenTurn` 缺失的旧记录按播种 0 回合处理。 |
| 极端长时间不侦察 | 半径封顶 `MAX_STALE_RADIUS_CELLS=8`，不涨到全图；位置仍停在最后目睹点，不漂移、不回填真值。 |
| 情报表缺条（防御性） | `perceivedEnemies` 剔除该敌军；视图走盲区占位；不抛 NPE。 |
| `victory.side` 为空 | `reportRadiusCells` / `blindZoneLabel` 入口 null 守卫返回 null；快照全体按未观测处理。 |
