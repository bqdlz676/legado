## 1. 缺陷原貌与本单结论

缺陷原貌（锚点卡 §一 四条事实锚点，已逐条复核现役代码）：

- `ReaderSheetOverlay.kt` 旧 :57 / :75 / :93 / :111：四个调用点 `visible` 恒 `true`。
- `ReaderSheetOverlay.kt` 旧 :40：`val request = state.request ?: return`，`request=null` 直接摘除整个子树。
- `InkHalfSheet.kt:110-131`：`LaunchedEffect(visible)` 的 `visible=false` 离场分支（旧 :121-130，遮罩回亮 + Sheet 下降）与 :133 保留帧条件 `progress.value == 0f && !visible`，因子树被立即摘除而永不执行。
- 对照既有正确写法：`InkBubble.kt:305` 保持组合并传 `visible = sheetOpen`，由组件内部动画收束。

本单处置口径：**两段式关闭 + 纯 JVM 离场状态机**。

1. 关闭不直摘：`dismiss` 先把当前请求交离场守卫进入离场段（保留原请求、`visible=false`），状态请求仍按 B20 口径置空；覆盖层按保留请求继续组合，播组件内离场动画。
2. 收束再摘：离场动画收束后（等效延时对齐组件自有遮罩 + Sheet 两段时长），覆盖层回调 `finishExitAnimation()` 清空保留请求，子树摘除。摘除时机有明确依据，不写「立即摘」。
3. 离场段拒收新半屏：离场闸与 B20 连点闸串联，不替代、不改写 B20 判重与快照比对语义。
4. 阶段迁移规则下沉到纯 JVM 守卫 `ReaderSheetExitGate`，普通单测可断言「关闭时子树仍在、visible 已 false」。

编译结论：**未验证，等 CI**。沙箱无 gradle / JDK21 / SDK，本地未跑 `./gradlew` / `kotlinc`；新增 7 条 Gate 断言 + 2 条 State 断言（既有 B20 6 条适配两段式生命周期后保留）是否全绿以云端 CI 为准。
