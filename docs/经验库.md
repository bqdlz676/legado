# 经验库（从实际事故里长出来的，只收"再犯会痛"的）

写法：一条经验 = 症状 / 根因 / 对策 / 机检入口 / 适用条件。没有机检入口的经验不收——靠自觉的条目只会变成口号。

## L1 跨模块漏改（CI 红 ×2）

症状：`app/src/test` 里写 `Sequence.isEmpty()`（Kotlin 只为 Collection 提供）；`screenshot/src/test` 的 `BookshelfScreen` 调用点没跟新增的 10 个搜索回调形参。两次都是"只改一处、另一个编译单元没动"。
根因：改签名的人只看见自己那棵树；沙箱没有 gradle/JDK21/SDK，无法编译发现。
对策：派单固定"编译面清单"（`app/src/test`、`screenshot/src/test`、`modules/**`），改签名后必须 grep 全仓调用点。
机检：`python3 data_scripts/cross-module-guard.py`（F1 删类残留引用 = FAIL，F2/F3 调用点提示）。
适用：任何 `fun`/`class` 签名变更、任何删类。

## L2 测试字面串陈旧（隐性必红）

症状：测试用 `"attach(null, null)"` 这种字面串锁调用形态，`InkShelfFragment` 改成 `attach(key, scope)` 后该断言仍去找旧串，一跑必红。
根因：把"源码文本"当契约，等于让测试和实现共享一个会漂移的副本。
对策：行为锁优先；确要锁静态事实，改用结构锁（枚举全集、注册表条数）。
机检：`cross-module-guard.py` 的 F4（改动函数的名字若出现在 `app/src/test` 的字面串里就提示）。
适用：任何按字面串断言的测试。

## L3 断言空转（返工最大来源）

症状：改掉实现，测试照样绿。典型形态：源码子串回证、缺调用记录桩、只测正向不测反向。
根因：断言对象选错——锁了"代码长什么样"，没锁"跑起来对不对"。
对策：`docs/断言范式.md` 四范式；写单报告必须有「自查反例」节。
机检：验收单判据固定含"改坏会不会红"推演；缺节不进验收槽。
适用：所有写码单。

## L4 写码方自述的分类结论不可信

症状：回放栈那轮把 6 种"有状态位但没接线"误报成"模型无状态位"，验收一读代码就推翻，整轮 FAIL。
根因：分类/穷举属于判断，写码方有动力把"没做完"说成"不需要做"。
对策：穷举类结论必须附反例；验收方独立数一遍，不许照抄报告。
机检：无（属判断项），靠验收单硬判据兜。
适用：凡是"共有 N 种、其中 M 种…"这类结论。

## L5 状态手写必然漂移

症状：3 条单报告与代码都完成，队列里仍写 PENDING；台账状态格与 git 事实不符。
根因：状态是人手写的副本，事实在 git 与文件系统里，两者无同步机制。
对策：状态由脚本派生，人只确认差异。
机检：`python3 data_scripts/queue-sync.py`（报告在盘 → 收口，老化 → 报警）。
适用：队列、台账、交接快照。

## L6 机制吃产能

症状：24h 内 docs 提交 116 次、`app/src/main` 51 次；机制单占走 5 个并发槽里的 3 个。
根因：把"机制完备"当成进度信号，报告/门禁/锚点/交接每一项都要人（或代理）现场生产。
对策：功能槽 4 + 验收槽 2；机制单最多占 1 槽；连续两轮无 main 提交即停发机制单。
机检：`python3 data_scripts/progress-meter.py 24`（main 提交数、PENDING 条数与最老年龄）。
适用：每轮调度开工第一件事。

## L7 串行验收

症状：写单完成 → 等验收结论 → 才派下一张写单；单张平均翻倍，同域吞吐恒为 1。
根因：六条机制叠加（详见 `docs/诊断-机制空转.md` 第六节），核心是把"一对一"误读成"时间轴上独占"。
对策：交付三连（提交→派 V→派下一张 W）；V 单固定被验 commit 只判该区间。
机检：`queue-sync.py` 的 PENDING 老化报警；`progress-meter.py` 的 main 提交数。
适用：所有写单。

## L8 缝合怪只增不减

症状：贴皮残留 151 页；回放栈长出第三份动作注册表；13 处旧搜索入口与新浮层并存。
根因：局部最省事解——"这页还能用先别动""新入口先接上，旧的以后删"，而"以后"永远不来。
对策：债务棘轮（在册数只许减）；写单报告固定回答"是否新增入口/第二份实现"，答是则同时给旧路径删除点。
机检：`python3 data_scripts/debt-ratchet.py`（超基线即 FAIL，上调须显式留痕）。
适用：任何新增入口、注册表、兼容层。

## L9 git 锁争用

症状：多代理并发跑 `git status`/`git log`，0 字节 `index.lock` 反复出现，提交被阻塞十几秒到几分钟。
根因：读命令默认也拿可选锁；并发读者与写者抢同一把。
对策：派单统一写 `GIT_OPTIONAL_LOCKS=0 git status`；提交侧带陈旧锁清理与重试。
机检：`pre-push-check.sh` 第 1 步（0 字节且无 git 进程才删）。
适用：所有并发代理任务。

## L10 快推互相取消

症状：连续快速 push，前一轮 Verify 被 `cancel-in-progress` 取消，等于白跑一轮。
根因：CI 并发组设了取消旧跑。
对策：推送单飞——等上一轮出结论再推；确需打断时先确认旧跑结论已落盘。
机检：CI 查询取 `status/conclusion`，看到 cancelled 即视为该轮无结论。
适用：所有推送。
