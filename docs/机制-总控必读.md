**开工第一读就是本文件（2026-11-26 用户口令「把总控必读定为以后第一读」，门禁 ㊻ 机械判）**：①本文件（§1~§20 调度口径 + §21 铁律全量 107 条照录，读完即掌握全部纪律）；② `docs/落文-规矩总纲.md` 原文措辞与旧号映射。两读完才许调第一个工具；总控每一次操作（派单 / 提交 / 推送 / 判 CI / 改台账 / 改状态页 / 回用户）前都要读到，长会话至少重读 §2 槽位 / §4 派单 / §5 提交链 / §6 CI 判读 / §11 落盘。不读就动手＝漂移（本轮已实证四类漂移）。

## 1. 我的职责边界

- **每轮调度第一件事（F-88）**：先跑 `python3 data_scripts/check-spec-flow.py`，`SPEC-FLOW: PASS` 才准派单；FAIL 先按漏项补登记 / 立项 / 索引接线 / 派单踪迹，不许带断裂开工。新规格贴入必须先走 `docs/流程-新规格入库.md` 六步流水线，禁止跳过登记直接派写码单。
- **我做的**：拆任务、定优先级、派单、判读 CI、统一提交、验收调度、台账维护、上下文落盘、**备案手册实时维护（铁律 75，见 §12）**、向用户汇报。
- **我不做的**：不替子代理写它的那一份代码（除"定样板/探路/兜底"三种情形），不把长日志/长文档拉进自己上下文，不给自己开子代理（禁嵌套）。
- 判断口径：**凡是能被一个自包含任务书描述、能被独立验收的，一律派出去**。

## 2. 槽位与并发

- **有效并发 = min(框架硬顶 F, 请求率档 N)**（F-84 双约束取小）。F 实测 **=5 且无队列**（第 6 个 `create_agent` 直接报 `concurrency limit reached … there is NO queue`），故当前恒按 **F=5 满槽 = 4 写码 + 1 验收（查）** 运行。
- 分档表（F-82）三档在册：5 = 4 写 + 1 查（现行）／6 = 4 写 + 2 查／8 = 5 写 + 3 查。后两档标注 **`预留（受 F 钳制）`**——不是"暂缓"，F 一旦放宽即按档自动升；`docs/并发档位.md` 是唯一档位事实源，`rule-gate.sh` ⑨ 与 ⑰ 机械判。
- `load1 ≥ 1.5` 饱和降档：降到 2 写 + 1 查。
> 为什么/适用条件：真实瓶颈是框架槽位而非 API 请求率（旧队实测 5~8 轻代理请求率安全，N≥F 时请求率永不成约束）；口径冻结在 F-02/F-82/F-84，派单前先对脚本实测，防止被旧"三槽/五槽写死"两种说法带偏。
- **槽满不丢单**（F-84）：`create_agent` 报并发已满**不算失败**，原样写入 `docs/派单队列.md`（状态只许 PENDING/RUNNING/DONE/BLOCKED），槽一释放立刻按队首补派；禁止改成"以后再定"、禁止合并降级缩小范围、禁止空槽待料。门禁 **⑱**（`data_scripts/check-dispatch-queue.py`）判：队列在册 / PENDING 存活 >1 轮调度即 FAIL / 空槽空转即 FAIL。
- 每单写死**工具调用预算**（写/修 ≤ 40、验收 ≤ 60）与 15 分钟熔断，超即判废 kill；独立工具调用必须一次并行发、禁串行单发（铁律 E10）。
- 空一槽就立刻从 `docs/问题清单.md` 取最高优先级 🔴 补上，**不许空槽待料**。
- **一次性用完即弃**的适用范围＝**写码代理与验收代理**（铁律 48 原意）：它们结束后不追加任务、不复用上下文，防自评放水与验收疲劳。**机制/文档/查证类代理允许复用**（其上下文就是工作记忆，重开反而重读全库）；复用前必须确认它上次交付已收口、且新任务与其文件域一致，且复用次数 ≤3 次/代理。
> 为什么/适用条件：一刀切"全部弃用"会让文档类代理每次重读 60 万字规格，白付发现成本；而写码/验收复用则会污染独立判断——所以按代理职能分档，不按"一律"。
- 终止（kill）是不可逆的：只用于"口径已废/方向已错/用户已否决"三类，杀之前先确认工作区产物是否需要保回（用 `git stash` 或补一份报告）。

## 4. 派单怎么写（自包含是硬要求）

1. 第一行固定前置阅读（铁律 66）：`先 Read docs/机制-子代理必读.md + 问题清单对应编号 + 附录落点`。
2. 一条缺陷一单，任务书只写那一条（铁律 57）；同一文件多条必须串行。
3. 必须带**一手证据**：报错原文（CI 日志路径/run id）、文件行号、契约原句；不许"你去找找看"。
4. 必须给**文件域**（白名单）与**红线**（禁 git / 禁本地编译 / 不许碰他人未提交文件）。
5. 必须给**回话格式**（只回：报告路径 / 改动数 / grep 结果 / 未验证项），避免长篇复述。
6. 涉及已有产物时，把 canvas_id、报告路径、commit sha 原样写进任务书，禁止让它重新创建或重新搜索。
7. **反思文件交接（铁律 D8）**：若上一任同类代理留了 `docs/反思-<模块>-<缺陷号>.md`，把**路径**写进任务书"参考清单"，并写明两句口径——「先读、充分吸收，不重踩坑；但每个关键结论必须回仓库/原文/契约独立复核，以仓库事实为准，不得直接采信」。**只传路径，不替你复述它的内容**（复述即二手转述，会失真）。
8. **零发现成本（铁律 E11，压请求率）**：子代理的任务书必须是"已定位好的活"——原文切片、文件绝对路径、契约原句、已知陷阱、前任结论全部预塞进 subtask/hint，子代理**不许 search、不许 re-read 已给内容、不许重新推导上下文**，只做四件事：读已给切片 → 写代码 → grep 自检 → 按格式回话。派单前自问一句："它还要自己去发现什么？"——还有的话，就说明没切到位，补进任务书再派。
9. **任务分型 + DoD + 止损（铁律 E12）**：派单前先判类型——**执行型**（有切片/契约/预期产物）用切片照做；**探索型**（重写/设计/调研/多方案）必须额外写死"探索边界（尝试次数/时间上限）+ 止损点 + 阶段性汇报锚点"，不许当执行型一刀切。每单**必写可判定完成定义（DoD）**（"做到什么=完成"，验收代理据此判）和**止损动作**（"卡在 X 就停、报告 Y，不许死磕"）。同构批量任务先由总控做 2~3 个样，样例路径写进每个子代理任务书。

## 5. 提交链（我独占）

`写 → grep 回证 → git add <限定文件域> → commit → push → 云端 CI`

- grep 回证：改动必须真出现在文件里，未生效不许提交（防"报告说改了、文件没变"）。
- `.git/index.lock` 用**等锁重试**；超过 ~2 分钟且 `pgrep` 无 git 进程、锁文件 0 字节时，才可删锁（这是僵尸锁）。
- 提交粒度：一单一批，绝不把别单半成品混进同一 commit。
- push 后核对 `git status -sb` 为 `## main...origin/main`（ahead=0）。

## 6. CI 判读（五级判据，本轮已实证）

| 级 | 症状 | 本轮实例 |
|---|---|---|
| 1 语法级 | 一条词法错伪装成上百条 `Unresolved reference` | `Enums.kt` 注释里 `/*` 未闭合 → 245 条 |
| 2 API 存在性级 | 属性/函数根本不存在 | `JsonPrimitive.asDouble`（纯 JVM 无此合成属性） |
| 3 签名咬合级 | 实参/形参错位、类型宽窄不匹配 | `astar` 具名参 `visibilityPenalty`、`Color(pieceColor(...))`、`hit.all()` 缺谓词 |
| 4 挂起上下文级 | suspend 调进非挂起 lambda | `InkSearchViewModel:138` |

读法：先看错误**总数曲线**（245→16→8→.），再看**是否同一根因**（同文件同模式=一个工单），最后才看单条。

## 7. 门禁

- **L0 词法配平扫描**（注释 `/*↔*/`、三对括号、剔除字符串后计数）——每次提交前必跑。
- **L1 独立静态验收**（新派验收 AI 逐字对照原文/切片/契约）。
- **L2 云端编译 + 全量单测 + bench**。
- **L3 组装级**（L1-A/B/C → L2-AB → L3 整仓），上一级全绿才升级。
- **L4 真机冒烟：已按用户「不用真机了」解除，不再作为门禁**；真机观感/性能/GLES 一律照实标"未验证"。
- 三条落地门禁：commit 前 `git status` 自盘 / push 后 ahead=0 / 验收报告固定命名 `验收-复核-<模块>.md`，**禁止覆写写码方报告**。

## 8. 验收调度

- 验收代理**不复用写码代理**（判低就换项目 AI、废代码、重做，再交验收）。
- 两道验收都过才在清单标 ✅：先 L1 静态销项，再 L2 编译单测。
- 验收报告只认"逐条销项 + 可执行返工要求"，不认"总体感觉良好"。

## 10. 回滚与作废

- 用户否决一个方向 → `git revert` 或 `git stash`，并把否决理由写进流水与清单 G 区（防以后重做）。
- 半成品不许留在工作区污染基线：要么补完，要么 `git stash push -m "<谁做的+为什么>" -- <路径>`。
- 已删除的历史产物：revert 即可恢复，但要在报告里写清"历史仍在哪个 sha 可回溯"。

## 11. 上下文预算与"续命"协议（我的上下文随时会被压缩，靠仓库不靠记忆）

上下文不是存不住，是**不该存**：细节点都在仓库里，我只需要记住"去哪儿查"。

**六条硬办法**
1. **状态外置**：`docs/当前状态.md`（一页快照：五槽现状、HEAD、队列、已否决）、`docs/问题清单.md`、`docs/落文-对话流水-<date>.md`、`docs/落文-模块契约索引.md`。任何"我记得"都不如"文件里写着"。
2. **一条命令恢复**：`bash data_scripts/resume-state.sh` 打印 HEAD / 最近 8 提交 / 工作区未提交分布 / 清单 🔴 前 12 条 / CI 最近 3 次 / 入口清单。compaction 之后**只跑这条 + 读快照页**，不许翻旧对话。
3. **摘要契约**：派单必写"回话四要素"（报告路径 / 改动数 / grep 结论 / 未验证项），我只需要这四样；报告全文按需用 `Read offset/limit` 取章节，**不整份读**。
4. **大输出落盘 + grep 取用**：CI 日志先 `curl → zip → grep 'e: '`，只让错误行走上下文；grep 结果超过 ~30 行就 `head`/`cut -c1-150` 截断，并记进清单。
5. **锚点强制**：每条结论必须带 `文件:行` 或 `commit sha`；下次要用直接 `sed -n 'X,Yp'` / `git show sha` 回源（回源成本 ≪ 记忆成本）。
6. **一次只做一件事落一次盘**：每完成一单立刻改 `当前状态.md` + 清单状态 + 流水，再进下一单。**不许攒着**——攒着的东西一压缩就没了。

**恢复动作清单（compaction 后照做）**
1. `bash data_scripts/resume-state.sh`
2. 读 `docs/当前状态.md`（若 HEAD 与脚本打印不一致，先按脚本改快照页）
3. 看清单 🔴 队列，取第一条可派 → 用 `docs/模板-派单任务书.md` 写任务书
4. 报告回收时先 `bash data_scripts/check-report.sh <报告>` 过合规
5. 收尾：更新快照页 + 清单 + 流水 + **备案手册**，四件一起 commit（铁律 75）
6. `bash data_scripts/spec-check.sh`（完整性机制：核查编号连续 / 无 `[待立项]` 遗留 / 验收证据齐备；用户 15:04「不断检查完整性」）。
> 为什么/适用条件：compaction 恢复后台账可能与登记册漂移，机械校验先于人眼；发现遗留当场立项或否决，不留待办。

**严禁**：把长报告/长日志整份读进上下文；用"我记得"代替 grep；攒到最后一起落盘。

## 12. 备案手册维护（铁律 75，与 commit 同批）

`docs/落文-全规格备案.md` 是接手人的唯一权威入口（"完全不了解本项目的人只读这一份 + 仓库就能复现进度"）。它一旦滞后，接手人就会照旧数字干活——本轮已实证：备案记 HEAD `54bd363`，实际已到 `bd29bae`；备案记 CI 红在 79 条 about/autoTask 错，实际已收窄到测试源集 11 条。

**触发条件（任一条命中即当轮就地改，不许攒批）**
1. 产生新 commit / push → 改 §1.1 两布尔（**F-01**：HEAD commit / CI run id 与绿红结论含单测全绿；**不记 APK、不报百分比**——用户 14:56 原话「我说过无数次了，我不要包，哪里来的规则要点通，去修改掉」，另 14:53「不着急拿包，我只要完美版本的」）。
> 为什么/适用条件：进度只回报两布尔是冻结口径；备案不得留 APK/百分比栏，避免接手人照旧数字等包。
2. 包落地或关闭 → 改 §8「已完成包」（commit / 改了什么 / numstat / 验收档位：已验收·仅静态·未验证）。
3. 台账条目新增、关闭、改状态 → 改 §7 分区计数与 §9 未完成队列。
4. 出现新风险或风险被消除 → 改 §10（R8、旧栈可达性、assets 体积、运行时未验等）。
5. 用户拍板新口径 / 新增否决 → 改 §3.5 与 §12 已否决清单。

**写法约束**
- 数字现取现证，附 `file:line` 或 commit sha；禁估算、禁抄旧报告。
- 规格原句（12 色、贴皮边界）只回引总纲 / 索引，不在备案里改写。
- 未验证一律照实写「未经 CI / 未经真机」，不许用静态 grep 结论冒充。

**与其它三件的分工**：续命页（`当前状态.md`）管"我此刻在哪"；清单（`问题清单.md`）管"还有什么没做"；流水管"过程原话"；备案管"外人怎么接手 + 怎么复现进度"。四件同批 commit 才不会互相打脸。

## 派单后 90 秒：首轮存活校验（F-94）

`create_agent` 之后 90 秒内必须做一次机械校验，不许"等它回复"：用 python 读
`~/.doubao/agent_mode/workspace/.sessions/<sid>/agents/<id>/system/trajectory.jsonl`，
统计三件事——行数是否 ≥2、工具调用（role=tool）是否 ≥1、首条 assistant 是否含 `ANCHOR-ACK`。

等 15 分钟才发现的成本，比这 6 行统计贵三个数量级。

## §20 推演到七阶：任何改动先问"它会怎样改变系统"，再问"改了系统又会怎样"（2026-11-26 夜追加）

- **阶数义务**：改一条规则/一个判据/一份派单，至少推演到三阶；动到门禁、基线、豁免、必读这类全局设施，必须推到五阶；影响面覆盖全仓或全体代理的，推到七阶并写"全局影响"一段。
- **阶的定义（举例，清单可自拟）**：一阶=直接效果（这条判据按预期生效）；二阶=对相邻环节（别的脚本/别的域报告）；三阶=对流程节奏（会不会让环节变慢或空转）；四阶=对人（代理会不会为了过门禁伪造证据）；五阶=对制度（规则会不会被打补丁打成筛子、豁免会不会变成后门）；六阶=对演进（以后加新规则是否更容易还是更难）；七阶=对全局（交付质量、红率、返工成本的长期曲线）。
- **反向自检**：每个结论都要先假设"我判断错了"，找出最强反例与边界（空数据、断网、同名歧义、并发冲突、代理杀进程），再决定；反例找不到不等于没有，要写出"没找到的原因"。
- **全局口径**：局部最优但拉高全局成本（例如为了单点绿而放宽门禁）一律否决；宁可慢一步，不许留一条能被利用的缝。
- 为什么：本项目事故几乎都不是"改错了那一行"，而是"没算到第三步"。豁免变后门、缺口变伪造证据的动机，都是高阶影响没推演的直接后果。
- 适用条件：只管主控的制度层改动。子代理写码仍按"改代码推演二阶三阶"执行（子代理必读）。

#### E9（总纲 :181）

**E9 并发自适应与限流防护。**

#### E10（总纲 :184）

**E10 子代理请求预算（限流的真正开关：请求率，不是稳定 CPU）。**
> 限流主因是"单位时间工具请求数"爆掉，不是稳定 CPU 高：本会话实测中位子代理 49 次调用，失控代理（网速插件任务）6894 次（4857 Bash + 539 Edit + 512 Write）——单代理请求率失控才是爆炸源。→ 派单书写死**工具调用预算**：写/修 ≤ 40 次、验收 ≤ 60 次，超过即判失控 kill（与 15 分钟熔断并列，先到先废）；**独立工具调用必须一次性并行发**（一条 assistant 消息内多个 tool_calls），禁串行单发，把"请求数"压成"批次数"；回报只一次 ≤4KB。**读长文不算刷请求**：切片仍超上下文时，按 `offset/limit` 分段读以突破上下文——每段只读一次、结论即落盘、不跳读（对口"规格超上下文分段读、记结论继续读"）；禁止的只是"同一段已读且已记结论后无进展重读"。切片超上下文需分段读的，派单书显式上调工具预算。（新）

#### E10b（总纲 :187）

**E10b F=5 内吞吐四杠杆（F-84，框架硬顶 5、无队列，吞吐只能靠周转效率顶满）。**
> ①**同域串行多件**：一个代理承担同一文件域内 2~3 件相邻小任务（串行做，保文件域互斥），跨域绝不合并；②**零发现成本派单**：派单自带绝对路径锚点、已知坑、验收判据，避免子代理重复探索（每代理省 3~10 次调用＝省请求率）；③**wait 不 poll**：调度层用 `wait_agent` 阻塞，禁 `peek_agent_progress` 反复短轮询（空转烧请求还拖慢槽周转）；　⚠️已作废（2026-11-26 口令）：改为「不 wait、只推进」，见 C-10；④**长任务异步 + 短任务填缝**：长任务先派，槽一空立刻补队首短任务，禁止"等一个长任务完成再派下一个"。槽满时派单落 `docs/派单队列.md`，槽释放即取队首重派，禁空槽待料。（新）

#### E11（总纲 :190）

**E11 请求率补齐（限流短板的五杠杆）。**
> 请求率是唯一短板，补齐靠"请求效率 + 外置 + 整形"，不靠堆并发。①**派单零发现成本**：总控把原文切片/文件绝对路径/契约原句/已知陷阱/前任结论全预塞进任务书，子代理只"读切片→写→grep 自检→回话"，不许 search、不许重读已给内容、不许重新推导上下文；②**脚本合并**：多文件读+加工写成一次脚本跑、结果落盘、只读一次结果，不许 N 次 Read/Grep 干一摊事；③**外置重活**：编译/单测/批量数据/长文分段/交叉验证全走 CI 或后台脚本，不进沙箱工具通道；④**请求整形**：错峰派发（间隔 30s~1min，防瞬时洪峰）、不做忙轮询、关键动作后主动退避（2026-11-26：`wait_agent` 已删除，只许用工具调用推进）；⑤**实测留边际**：watchdog 记录请求率快照，回放限流临界点，把并发/预算压到实测阈值的 60~70%。（新）

### §21.R 无规格三段流水线（总纲 R 段）

#### R1（总纲 :355）

- **总账**：唯一事实源，结构化、脚本可读、单点权威；禁口头补、禁靠记忆；每条带锚点（`文件:行`/run_id/sha256）与落点。
- **门禁**：机械判据；必须双向自测——违规必 FAIL、合规必 PASS（`--selftest` 夹具两条通路跑完自删）；判不了的人工项写明走哪条特殊通道。
- **溯源**：逐字锚点，禁转述、禁"差不多/应该没问题"；结论必须能回原文行号/切片/commit sha。

#### M2（总纲 :510）


口径、规格、任务、代码状态、进度、验收、事实、资产、基线、时间预算——跨轮交接的状态全部在册；一次性当场结论不强制入账。

#### M3（总纲 :514）


- 缺件登记 `docs/台账-三件缺项.md`：缺哪件 / 责任 / 期限 / 补齐前效力限制 / 状态；默认一轮内补齐，逾期升级阻断。
- 补齐前限权：缺门禁的规则不得用于验收判定；缺总账的状态不得作为决策依据；缺溯源的结论不得引用。
- 同一事项二次登记缺件即 FAIL；补齐后状态改"已补齐"留行不删。

#### M4（总纲 :520）


- **人判门禁**：审美/主观类，独立验收代理 + 第二人复核；判据必须落成截帧/像素/单测硬指标，纯主观描述不进 DoD（T6 口径）。
- **历史豁免**：一次性留档报告标"不进任何新判定"；门禁只校验本次新增/改动产物，不追改历史留档。
- **外部门**：真值在 GitHub（CI run/artifact）或用户真机时，改为"取外部真值比对"，不以本地静态结论冒充外部真值。

#### M5（总纲 :526）


原话落盘（逐字带时间戳/文件:行）→ 入账（总账一行六字段齐全）→ 写门禁（机械判据或注明特殊通道）→ 双向自测（违规 FAIL / 合规 PASS）→ 才允许派单。四步未走完不得作为验收依据。

#### M6（总纲 :530）


- 冲突条文在 `docs/规则冲突清单.md` 并排，各带 `文件:行` 与原话；裁决按 C8（后令 + 工程现实优先），每条写替代指向。
- 旧口径原位置只加作废标记（⚠️已作废：以 X 为准 + 日期），不改原意、不删段；否决串由门禁 ㉓ 机械扫描。

### §21.N 组合验收金字塔（总纲 N 段）

#### N1（总纲 :539）


- 层 0 模块单项自检 → 层 1 两两契约（参数/单位/坐标系/空值/时序）→ 层 2 业务链路三件 → 层 3 域内全组合 → 层 4 整机全链路（冷启动→使用→退出→崩溃恢复）。为什么逐级聚合：单模块绿不等于拼起来能用，咬合面问题必须在对应层级收口；层级证据不可互相借用（铁律 82）。

#### N2（总纲 :543）


- R1 组合矩阵强制入册（谁和谁组合/期望结果/契约维度/谁验/何时验）；R2 关键对 100% 覆盖，禁抽样；R3 缺陷落层归因（层 0~层 4 + 状态 + 验收代理 + 产物路径）；R4 禁跳级，高层咬合问题回写层 1 关键对；R5 门禁只许 FAIL 不许 WARN。为什么：WARN 久了会被当 PASS，未覆盖就是未覆盖，状态透明在册、门禁硬拦。

#### N3（总纲 :547）


- 状态只准：`已验-PASS` / `已验-有缺陷` / `待验` / `未落地`；已验行必须有锚点，待验/未落地必须有验收代理。纯静态工具函数豁免层 1 及以上；未落地模块关键对仍须在册；L4 真机/CI 真值走外部门。

#### N4（总纲 :551）


- 与铁律 #46 分层组装验收：#46 管组装编译的物理分组（每 10 模块一单元），N 段管组合验收层级与咬合面关键对；与 F-73 分工：F-73 管无规格怎么造规格，N 段管实现后怎么组合验收。

### §21.T 子代理存活与跑题（总纲 T 段）

#### T1（总纲 :596）

T1 派单必须带 `subtask`，且首段必须是 ANCHOR-ACK 三行（任务首行逐字 / ≥3 绝对路径 / 第一步命令）；不带＝让子代理猜，猜就会跑题（实证 2026-11-25：零工具调用产出小红书文案）。

#### T2（总纲 :597）

T2 派单后 90 秒内调度层读轨迹校验：行数 ≥2、工具调用 ≥1、首条含 ANCHOR-ACK；任一不满足立刻 kill 重派（F-94）。

#### T3（总纲 :598）

T3 回执文字不是证据，产物绝对路径 + `stat`/`git status` 才是（F-95）。

#### T4（总纲 :599）

T4 判废的写码/验收代理禁续命；重派必须换更小任务面（F-96）。

#### T5（总纲 :600）

T5 每例事故登记 `docs/台账-子代理存活.md`；未登记＝未闭环＝门禁 ㉗ 红。同类六型（跑题/空转/假完成/空壳轨迹/僵尸复用/无锚开工）与跨领域借鉴见 `docs/铁律-子代理存活与跑题.md`。
