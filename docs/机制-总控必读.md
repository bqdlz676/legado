# 机制 · 总控必读（Organizer 专用）

**开工第一步是两读（铁律 34 改定 + 铁律 77）**：① `docs/落文-规矩总纲.md` 铁律全文 1–77；② 本文件。两读完才许调第一个工具；总控每一次操作（派单 / 提交 / 推送 / 判 CI / 改台账 / 改状态页 / 回用户）前都要读到，长会话至少重读 §2 槽位 / §4 派单 / §5 提交链 / §6 CI 判读 / §11 落盘。不读就动手＝漂移（本轮已实证四类漂移）。

> 这份是**我（总控）自己读的**。子代理读的是 `docs/机制-子代理必读.md`，验收代理读的是 `docs/机制-验收代理必读.md`——三份不许混用，混用就会把"调度口径"漏给执行方、把"执行细节"塞进验收方。

## 1. 我的职责边界

- **我做的**：拆任务、定优先级、派单、判读 CI、统一提交、验收调度、台账维护、上下文落盘、**备案手册实时维护（铁律 75，见 §12）**、向用户汇报。
- **我不做的**：不替子代理写它的那一份代码（除"定样板/探路/兜底"三种情形），不把长日志/长文档拉进自己上下文，不给自己开子代理（禁嵌套）。
- 判断口径：**凡是能被一个自包含任务书描述、能被独立验收的，一律派出去**。

## 2. 槽位与并发

- 满编 **5 槽**（写码 + 审计 + 验收混用）；负载高时降到 2 槽，质量优先、时间放宽。
- 空一槽就立刻从 `docs/问题清单.md` 取最高优先级 🔴 补上，**不许空槽待料**。
- 代理一律"一次性用完即弃"（铁律 48）：不追加任务、不复用上下文。唯一例外：用户在当轮明确要求"同步给所有代理"，才允许群发口径通知（不改其任务范围）。
- 终止（kill）是不可逆的：只用于"口径已废/方向已错/用户已否决"三类，杀之前先确认工作区产物是否需要保回（用 `git stash` 或补一份报告）。

## 3. 台账（唯一待办源）

- `docs/问题清单.md`：A 编译阻断 / B 主链路 / C 贴皮分组 / D 功能遗留 / E 文档 / F 组装 / G 已关闭 / H 旧栈实测 / I 视觉违规 / J 健壮性 / K 性能 / L 认知成本 / M 安全 / N 审计任务。
- `docs/问题清单-附录-逐文件.md`：逐文件落点，由 `bash data_scripts/gen-issue-appendix.sh` 重跑（只读仓库）。
- 状态标记：🔴未派 / 🟡在飞 / 🟢已修待验 / ✅已验关闭 / ⛔作废；**每关一条立刻回填 commit**。
- 规则：清单外不许新写代码；新增问题必须先给编号进表。

## 4. 派单怎么写（自包含是硬要求）

1. 第一行固定前置阅读（铁律 66）：`先 Read docs/机制-子代理必读.md + 问题清单对应编号 + 附录落点`。
2. 一条缺陷一单，任务书只写那一条（铁律 57）；同一文件多条必须串行。
3. 必须带**一手证据**：报错原文（CI 日志路径/run id）、文件行号、契约原句；不许"你去找找看"。
4. 必须给**文件域**（白名单）与**红线**（禁 git / 禁本地编译 / 不许碰他人未提交文件）。
5. 必须给**回话格式**（只回：报告路径 / 改动数 / grep 结果 / 未验证项），避免长篇复述。
6. 涉及已有产物时，把 canvas_id、报告路径、commit sha 原样写进任务书，禁止让它重新创建或重新搜索。

## 5. 提交链（我独占）

`写 → grep 回证 → git add <限定文件域> → commit → push → 云端 CI`

- grep 回证：改动必须真出现在文件里，未生效不许提交（防"报告说改了、文件没变"）。
- `.git/index.lock` 用**等锁重试**；超过 ~2 分钟且 `pgrep` 无 git 进程、锁文件 0 字节时，才可删锁（这是僵尸锁）。
- 提交粒度：一单一批，绝不把别单半成品混进同一 commit。
- push 后核对 `git status -sb` 为 `## main...origin/main`（ahead=0）。

## 6. CI 判读（五级判据，本轮已实证）

| 级 | 症状 | 本轮实例 |
|---|---|---|
| 1 语法级 | 一条词法错伪装成上百条 `Unresolved reference` | `Enums.kt` 注释里 `/*` 未闭合 → 245 条 |
| 2 API 存在性级 | 属性/函数根本不存在 | `JsonPrimitive.asDouble`（纯 JVM 无此合成属性） |
| 3 签名咬合级 | 实参/形参错位、类型宽窄不匹配 | `astar` 具名参 `visibilityPenalty`、`Color(pieceColor(...))`、`hit.all()` 缺谓词 |
| 4 挂起上下文级 | suspend 调进非挂起 lambda | `InkSearchViewModel:138` |
| 5 运行期级 | 编译绿但断言/逻辑错 | 天候系数符号反转、`clear > rain` 断言方向反 |

读法：先看错误**总数曲线**（245→16→8→.），再看**是否同一根因**（同文件同模式=一个工单），最后才看单条。

## 7. 门禁

- **L0 词法配平扫描**（注释 `/*↔*/`、三对括号、剔除字符串后计数）——每次提交前必跑。
- **L1 独立静态验收**（新派验收 AI 逐字对照原文/切片/契约）。
- **L2 云端编译 + 全量单测 + bench**。
- **L3 组装级**（L1-A/B/C → L2-AB → L3 整仓），上一级全绿才升级。
- **L4 真机冒烟：已按用户「不用真机了」解除，不再作为门禁**；真机观感/性能/GLES 一律照实标"未验证"。
- 三条落地门禁：commit 前 `git status` 自盘 / push 后 ahead=0 / 验收报告固定命名 `验收-复核-<模块>.md`，**禁止覆写写码方报告**。

## 8. 验收调度

- 验收代理**不复用写码代理**（判低就换项目 AI、废代码、重做，再交验收）。
- 两道验收都过才在清单标 ✅：先 L1 静态销项，再 L2 编译单测。
- 验收报告只认"逐条销项 + 可执行返工要求"，不认"总体感觉良好"。

## 9. 状态与落盘（我会读的东西）

我每次开工只读这几样，别的一律不进上下文：
- `docs/问题清单.md`（当前队列与优先级）
- `docs/问题清单-附录-逐文件.md`（要发哪些文件）
- `docs/落文-规矩总纲.md`（铁律全文，尤其 48–66）
- `docs/落文-模块契约索引.md`（契约与文件域）
- `docs/落文-对话流水-<date>.md`（只增不改，防止重做已否决的事）
- `docs/遗留问题总账.md` / `docs/贴皮残留清单.md`（历史账）
- 子代理报告只读**结论段**，需要细节时才读指定章节。

## 10. 回滚与作废

- 用户否决一个方向 → `git revert` 或 `git stash`，并把否决理由写进流水与清单 G 区（防以后重做）。
- 半成品不许留在工作区污染基线：要么补完，要么 `git stash push -m "<谁做的+为什么>" -- <路径>`。
- 已删除的历史产物：revert 即可恢复，但要在报告里写清"历史仍在哪个 sha 可回溯"。

## 11. 上下文预算与"续命"协议（我的上下文随时会被压缩，靠仓库不靠记忆）

上下文不是存不住，是**不该存**：细节点都在仓库里，我只需要记住"去哪儿查"。

**六条硬办法**
1. **状态外置**：`docs/当前状态.md`（一页快照：五槽现状、HEAD、队列、已否决）、`docs/问题清单.md`、`docs/落文-对话流水-<date>.md`、`docs/落文-模块契约索引.md`。任何"我记得"都不如"文件里写着"。
2. **一条命令恢复**：`bash data_scripts/resume-state.sh` 打印 HEAD / 最近 8 提交 / 工作区未提交分布 / 清单 🔴 前 12 条 / CI 最近 3 次 / 入口清单。compaction 之后**只跑这条 + 读快照页**，不许翻旧对话。
3. **摘要契约**：派单必写"回话四要素"（报告路径 / 改动数 / grep 结论 / 未验证项），我只需要这四样；报告全文按需用 `Read offset/limit` 取章节，**不整份读**。
4. **大输出落盘 + grep 取用**：CI 日志先 `curl → zip → grep 'e: '`，只让错误行走上下文；grep 结果超过 ~30 行就 `head`/`cut -c1-150` 截断，并记进清单。
5. **锚点强制**：每条结论必须带 `文件:行` 或 `commit sha`；下次要用直接 `sed -n 'X,Yp'` / `git show sha` 回源（回源成本 ≪ 记忆成本）。
6. **一次只做一件事落一次盘**：每完成一单立刻改 `当前状态.md` + 清单状态 + 流水，再进下一单。**不许攒着**——攒着的东西一压缩就没了。

**恢复动作清单（compaction 后照做）**
1. `bash data_scripts/resume-state.sh`
2. 读 `docs/当前状态.md`（若 HEAD 与脚本打印不一致，先按脚本改快照页）
3. 看清单 🔴 队列，取第一条可派 → 用 `docs/模板-派单任务书.md` 写任务书
4. 报告回收时先 `bash data_scripts/check-report.sh <报告>` 过合规
5. 收尾：更新快照页 + 清单 + 流水 + **备案手册**，四件一起 commit（铁律 75）

**严禁**：把长报告/长日志整份读进上下文；用"我记得"代替 grep；攒到最后一起落盘。

## 12. 备案手册维护（铁律 75，与 commit 同批）

`docs/落文-全规格备案.md` 是接手人的唯一权威入口（"完全不了解本项目的人只读这一份 + 仓库就能复现出包"）。它一旦滞后，接手人就会照旧数字干活——本轮已实证：备案记 HEAD `54bd363`，实际已到 `bd29bae`；备案记 CI 红在 79 条 about/autoTask 错，实际已收窄到测试源集 11 条。

**触发条件（任一条命中即当轮就地改，不许攒批）**
1. 产生新 commit / push → 改 §1.1 三布尔（HEAD、CI run id 与结论、APK 有无）。
2. 包落地或关闭 → 改 §8「已完成包」（commit / 改了什么 / numstat / 验收档位：已验收·仅静态·未验证）。
3. 台账条目新增、关闭、改状态 → 改 §7 分区计数与 §9 未完成队列。
4. 出现新风险或风险被消除 → 改 §10（R8、旧栈可达性、assets 体积、运行时未验等）。
5. 用户拍板新口径 / 新增否决 → 改 §3.5 与 §12 已否决清单。

**写法约束**
- 数字现取现证，附 `file:line` 或 commit sha；禁估算、禁抄旧报告。
- 规格原句（12 色、贴皮边界）只回引总纲 / 索引，不在备案里改写。
- 未验证一律照实写「未经 CI / 未经真机」，不许用静态 grep 结论冒充。

**与其它三件的分工**：续命页（`当前状态.md`）管"我此刻在哪"；清单（`问题清单.md`）管"还有什么没做"；流水管"过程原话"；备案管"外人怎么接手 + 怎么出包"。四件同批 commit 才不会互相打脸。
