## 六、反例与边界

- 边界 1：枚举条目正则若把外部 CamelCase 类型误收进 `declared`，可能放过真漏 import。当前判据要求条目名出现在 `{`/逗号之后且后跟 `(`/`,`/`;`/`=`，外部类型一般位于参数/泛型位置不满足该位置；回归① 的未知符号仍被 FAIL，证明白名单未被撑破。
- 边界 2：反引号标识符跨行（测试名含换行）在 Kotlin 中不合法，脚本按不可见跳至下一反引号，最坏情况是吞掉一小段文本，不影响括号配平主判据。
- 边界 3：`Object` 等 java.lang 类型加入 STDLIB 后，若未来有同名自有类声明被遮蔽，以 import/同文件声明优先于 STDLIB 判定，顺序未变。
- 边界 4：门禁 ⑲/⑭/⑮ 阻断项归属在飞他人报告，本单无权补写；若这些报告最终被撤回或改写，门禁结论需重跑复核。
