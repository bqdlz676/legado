# 开工守则 · 写码子代理（每单必读，逐条执行）

> 用途：任何写码子代理开工前先读本文件，再读任务单。任务单只写"这一单做什么"，共性纪律全在这里，派单不再重复长文。
> 为什么单独成文：2026-11-26 夜实测，凡是把共性纪律抄在每份派单里的，抄漏一条就返工一轮（B1 按文件名判死 5 件、B2 十页无承接目标白跑、B10 接线未验即入库）；纪律沉淀成文件，派单只写差异。

## 一、开工前（顺序固定，跳一步就会做错方向）

1. 读仓库绝对路径：`/home/user/Doubao/chats/38454122521460994/legado`，先 `git log --oneline -3` 确认 HEAD 与任务单一致；不一致就以磁盘为准并在报告头写明区间。
2. 读 `docs/接手/00-入口.md` 拿到最新机制索引位置，再按任务单指向读原文（规格原文一律逐字读，长则分段读，记结论继续读，**禁跳读、禁摘要替代原文**）。
3. 读任务单给的锚点卡 `docs/锚点/<缺陷号>-<主题>.md`。没有锚点卡就先建卡（逐字引原文 + 落点表 + 判据），再动代码——没有卡等于没有验收口径。
4. 读同域既有实现，只作参考，**不复用既有实现**（用户明令：已有实现绝不复用，同样的事重写一遍）。
5. 先 `GIT_OPTIONAL_LOCKS=0 git status --porcelain` 认脸在飞改动面；报告里写明"谁的在飞文件我不碰"。

## 二、动代码前（两件事，缺一件必返工）

1. **删/改/改道前先做活引用 sweep**：`grep -rn` 覆盖 `app/src`（含 test/androidTest）、`screenshot/src`、`modules/`、`res/layout`、`AndroidManifest.xml`、proguard、assets 字符串。命中分三类——代码引用 / 测试编译锁（`readText()` 一类契约锁也算锁）/ 注释文档提及；只有"零代码引用且零编译锁"才可删。为什么：B1 按文件名判死 5 件，实测 4 件有活引用（`ExploreFragment` 的 helper 被同包单测编译调用，删即 unresolved reference）。
2. **新逻辑先接好再删旧**：改道必须先有真实可达的新入口（Compose 自绘形态），再接旧入口，最后才删旧文件；只加开关不加可达链路＝死装饰（B10 就是这么来的）。删旧前 grep 0 命中 + CI 绿。

## 三、写代码时（会被机检和 CI 双重抓的点）

1. 禁本地编译（沙箱无 Android 链），但 **Python/Kotlin 语法级检查必须真跑**：`python3 data_scripts/kotlin-syntax-lint.py <你的文件>` 必须 PASS。已知三类硬错会被它抓：括号不配平、`if(...),)` 条件尾逗号、`BasicText/Text` 直传 `fontFamily`（应写进 `TextStyle`）。
2. 测试函数名反引号内不许出现 `/` 等 JVM 非法字符（门禁⑬/㉘ 会红）。
3. 断言必须"改坏会红"：报告里逐条写改坏推演（删判定、改阈值、颠顺序、去兜底），并说明对应哪条断言会红。
4. 不许静默降级、不许砍功能、不许留空白态：查不到/无网/数据损坏/空集合，每种给可读兜底，写进报告"边界清单"。
5. 每条规则代码注释写一句"为什么 / 适用条件"（用户要求，缺注释的判定会被验收按 D 级记）。
6. 不做跨域夹带：只改任务单划定的目录与其测试；发现跨模块问题不许顺手改，写进报告"跨模块交接"段。

## 四、收尾（不做到这四步不算完成）

1. `grep` 回证每处改动真的写入（接线点存在、删除文件不存在、断言真在文件里），报告附命令与输出。
2. 跑本域门禁：`python3 data_scripts/check-frankenstein.py`、`python3 data_scripts/debt-ratchet.py`（只许减不许增）、`python3 data_scripts/kotlin-syntax-lint.py`，三者 PASS 才写报告。
3. 报告放 `docs/修复-<单号>-<主题>.md`（或 `docs/实现-…`），首行锚点卡路径；含：机器头（被改文件数/新增断言数/真跑门禁结论/未验证项数）、改动清单带 `文件:行`、二阶三阶推演（对其他模块、用户路径、性能、维护成本的影响）、边界清单、改坏推演、跨模块交接、未验证项（编译/单测/真机一律标"未验证，等 CI"）。
4. 禁 `git add/commit/push`（落地由调度层做）；禁唤醒续跑——本单结束后不再复用你。
