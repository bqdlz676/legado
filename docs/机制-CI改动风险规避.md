# 机制 · CI 改动风险规避

> 为什么有这份：改 CI 拓扑（删分片、换 job 结构）是风险动作，一旦撞上时限或丢断言，红的是整个流水线。所以本仓对 CI 改动只有一条路：**先用影子路径证明等价，再切默认；证不出来就不切**。

## 一、风险清单（先说清坏在哪）

- 单 job 全量单测可能撞 `timeout-minutes`：3185 个测试在 2 核 runner 上的耗时没有实测数，靠猜就是赌。
- 删分片会失去"分片并集=全集、两两不重叠"的交叉核对，只剩"总条数 ≥ 3185"这一道弱断言。
- 缓存键收窄后若命中旧产物，可能掩盖本该重编的改动（靠 `--build-cache` 的输出摘要兜底）。
- `cancel-in-progress` 下连续快推会互相取消，白烧一轮且看不到结论。

## 二、规避办法（已落地的）

1. **影子对照 workflow**（`.github/workflows/verify-shadow-single.yml`）：只在手动触发，单 job 跑全量，输出 XML 级统计（total/failures/errors/skipped/classes 与类名集合哈希），与现役 4 分片的 aggregate 输出逐项比对。它不挂 push、不进绿红判定、不与现役共享并发组——零风险。
2. **切换判据写死**：连续 N 个 commit 差异为 0 才允许切默认；任一 diff 非 0 则永不切。判据落在 workflow 的 STEP_SUMMARY 里，可回读。
3. **现役结构不动**：分片、discover、aggregate 原样保留，只在其上加"零语义"提速（SDK 已装则跳过、`--build-cache`、缓存键收窄）。这三条都不改变"跑哪些测试、怎么断言"。
4. **可切回**：任何 CI 改动按单独 commit 落盘，回滚只需 revert 那一笔，不影响代码桶。
5. **时限兜底**：影子 job 故意给 60 分钟宽限并记录 `WALL` 秒数——超时本身就是"不可切"的证据，不用等结论吵架。

## 三、串行链的零风险提速（不碰 CI 拓扑）

- 门禁并行：各机检步骤互不依赖，并发跑，退出码逐段收集（门禁自诊断单在修）。
- 增量机检：只对本轮改动文件跑 S1~S8 与只读 setter，全仓扫描只在日检跑一次。
- 派单流水线：写码单 N 个并行；验收用证据包（`acceptance-evidence.py`）并发判；CI 在飞时继续开下一单，只有"红"才停新单。
- 报告瘦身：报告只保留结论 + 证据 + 回执，长过程描述一律不写；验收看证据包，不看长文。

## 四、不许做的事

- 不许为了快而减少测试、跳过断言、放宽 `skipped>0` 判死、把 baseline 调低。
- 不许在没跑影子对照的情况下把默认切到单 job。
- 不许把"CI 拓扑改动"和"业务代码"混进同一个 commit（回滚会连坐）。
