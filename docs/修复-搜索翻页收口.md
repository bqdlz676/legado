### D1-R1（阻断项）多批次误路由 / 收口标记丢失

- 验收原文判据（验收报告 :184）：首批 `LoadMoreAppend` 且 `hasMore=true` 时归约器即把 `paging` 置回 `Idle`；二批 `onSearchSuccess` 判 `paging !is LoadingMore` 误入首屏回填；随后 `LoadMoreFinish` 被 `paging !is LoadingMore` 守卫拒收，远端 `hasMore=false` 收口标记丢失，状态停在 `Idle / hasMore=true`。
- 改到：`SearchReducer.kt:179-193`（`LoadMoreAppend` 分支）；路由判定仍在 `InkSearchViewModel.kt:251-253`。
- 修法一句话：同一页请求内多批 `onSearchSuccess` 都保留 `LoadingMore` 在途身份，追加只合并条目并 OR 累积 `hasMore`，终态一律等 `LoadMoreFinish` 落定，二批不再被误判成首屏。

### D1-R2 跨词竞态：翻页协程体未复核命令序号 / 分页态

- 验收原文判据（:185）：`loadMore` 协程体只复核模型空 / 关键词空 / 网络，未复核命令序号与当前分页态；挂起期间新检索覆盖 `searchID / searchKey`，旧翻页体随后用新字段再调 `model.search`；`SearchCommandGate` 只罩 `runSearch`。
- 改到：`SearchPagingOrchestrator.kt:83`（`gate.next()` 占翻页命令令牌）、`:97-102`（`bodyStillEligible` 闸门 + 在途态双重复核）；`InkSearchViewModel.kt:170-187`（`launchPageSearch` 协程体先复核再取字段快照再调模型）、`:216`（新检索 `onNewSearch`）。
- 修法一句话：翻页触发同样领取命令闸门令牌，协程体在调模型前复核「令牌仍有效且状态仍在途」，作废命令或被打断的旧体直接退出，不用新检索字段再发请求。
