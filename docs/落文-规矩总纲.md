# 落文 · 规矩总纲（做任务前必读）

> 唯一重读入口。上下文被压缩后，先读本文件再动手。
> 翻轨迹铁律：要同时理解「用户说过的话」+「我(agent)说过、用户未否决的话」——二者都是约定，未否决=默认接受。

## 一、目的 vs 手段（最高优先级）
- 灵魂闭环只是冒烟用例，**验收是手段、不是目的**：打开书→竖排读→点字出气泡→点「晋」命中春秋晋国→点「鲁隐公元年」出前722干支辛酉。
- 真正目的是：把整套规格做对、做好看、好用、所有边界兜底，不降级、不砍功能、不允许空白态或崩溃。

## 二、四条硬规则（读对话/派单/验收的根本纪律）
1. 锚点强制可回源：每条结论必须能回到原文行号/切片/文件。
2. 规格、契约、验收三类**禁止压缩**，只压缩已完结过程。
3. 子 AI 禁止自行摘要——只读小段原文照做，靠索引+完整覆盖核对。
4. 三层分离：
   - 导航层：可有损，只答"在哪"。
   - 执行层：无损，原文切片逐字。
   - 验收层：逐字对照原文全文。

## 三、铁律（来自用户长期偏好）
1. 落文只保留 Legado 排版引擎，界面全部原生自绘重写。
2. 编译通过只代表语法过，不代表功能可用，未验证必须明说未验证。
3. 交付前必须自我模拟跑一遍关键路径并逐项自查，再报完成。
4. 每个项目先做单项自检，再做一次整体自检，才可交付。
5. 目标真机是荣耀 WIN，12GB 内存，安卓手机（用户语境"win"指手机，与电脑无关）。
6. 规格未覆盖的边界情况自行判断并兜底，不允许空白态或崩溃，不降级不砍功能。
7. 每完成一个模块必须自测验收，跑不通不交付。
8. 规格超上下文时分段读、记结论继续读，不许跳读。
9. 改代码要推演二阶三阶影响，不只考虑改动直接效果。
10. 做方案先假设自己方案错误，找反例边界重新评估再定。
11. 改动后必须先 grep 确认代码真的写入，未生效不许编译更不许报完成。
12. 分析代码库历史和遗留包袱，识别可安全移除的历史代码。
13. 以新人工程师视角评估代码认知成本，简化命名与职责不清的代码。
14. 复盘 Bug 返工回滚的共同根因，沉淀为项目规则或自动化。
15. 质量优先，交付前自检，不好全部返工；已有实现绝不复用只做参考。
16. 每个模块配可跑的单测和 bench，性能指标跑过才算数，只过编译没真机验证的显式写进交付说明。
17. 固定签名 keystore 收口，签名不一致会导致覆盖安装失败。
18. 负载高时并发降到 2 个，质量优先，时间放宽。
19. 用户原文规格必须逐字保留、不蒸馏不改写；子 AI 读全靠索引+完整覆盖核对，不靠压缩浓缩。
20. 派单任务尽量划小范围，每个子 AI 只读小段原文照做，减少其自行编造或摘要。
21. 每次出 APK 必须 JDK17 先 clean 再 assemble 全量重编，禁止增量编译。（见下方「已定决策」：工程 toolchain 钉 21 已让位于实际，改 JDK21）
22. 排查问题用穷举法：列全部嫌疑点后一次性全改，不逐点试。
23. 用户提出修改意见时先读相关源代码再动手，不许凭感觉改。
24. 改动前先对比旧版 APK 借鉴好用实现，再自己重新研究重写。
25. 新逻辑先接好再删旧，不留旧格式兼容层，及时清理废旧代码。
26. 每次交付 APK 前必须把整个 APK 完整模拟跑一遍再报完成。
27. **验收 AI 独立把关**：每模块/派单完工后交独立验收 AI（非写码的项目 AI）逐字对照规格原文+验收标准判质量；判质量低 → 换掉项目 AI、废弃其代码、重新派单重做，做完再交验收 AI，直到通过；项目 AI 禁止自评代替验收 AI。
28. **翻轨迹双向理解**：读对话历史要同时理解用户的话 + 我(agent)说过、用户未否决的话，二者都算约定。

## 四、我已定的决策（用户未否决=约定，改动前先回查这里）
- **JDK 定案 JDK21**：app/build.gradle jvmToolchain 钉死 21、AGP 8.13.2 / Kotlin 2.4.20 / Gradle 8.14.4；JDK17 产不出 21 字节码，故「JDK17」这条让位于工程实际，云端用 temurin-21；「clean+assemble 全量、禁增量」仍保留。
- **前722干支=己未**（史料正确值）；规格冒烟里写的「辛酉」实为前720·鲁隐公三年。保留规格原文不改，引擎按史料输出己未，交付时写清这一处。
- **锚点总线**：气泡/Provider/阅读页继续用 `help.chrono.ContextAnchor`（已接线、功能更全）作权威；`core.chronology`（C1新写）暂并存、不重接、不删，统一合并由「时空锚统一」任务单独做。
- **本地只写码、绝不本地 gradle**：本地 gradle 会卡死共享沙箱触发限流，是硬红线；编译一律走 GitHub Actions 云端。
- **三引擎冻结 API（不许改签名）**：
  - 竖排 `ui/book/read/vertical`：`VerticalLayoutEngine.layout(text,viewWidthPx,viewHeightPx)` / `hitTest(x,y):CharHit?` / `invalidateCache()`；`VerticalPage(columns,pageIndex,progress)`、`Column(cells,left,top)`、`CharCell(char,offset,x,y,width,height)`、`CharHit(char,offset,paragraphText,pos)`。
  - 气泡 `help/bubble`：`BubbleResolver.resolve(paragraph,pos,anchor):BubbleContent?`；`sealed Action` 四子类 OpenMap/OpenPerson/OpenTimeline/OpenRelation（不许增删）；`BubbleContent(kind,token,phonetic,headline,body,detail,actions,candidates,source)`。
  - 时空 `core/chronology`：`Chronology` / `ContextAnchor`（resolve 全 app 唯一消歧入口）。
- **12 色 token**：bg-page `#F7F1E6`、bg-surface `#EFE8D8`、bg-overlay `rgba(26,20,16,.45)`、text-primary `#1A1410`、text-secondary `#5C4F3A`、text-tertiary `#9B9687`、text-accent `#C23B2E`、brand-gold `#D4A54A`、brand-copper `#8B6914`、color-link `#C23B2E`、color-divider `rgba(26,20,16,.08)`、color-glow `rgba(212,165,74,.3)`。
- **三源置信度**：3/3=high 默认命中；2/3=medium 标「待校」；≤1/3=low 标「待考·来源冲突」不进默认命中；今址参考层恒 low。
- **零 copyleft**：Wikipedia/OSM/CC-CEDICT 不直接灌文案；Wikipedia 只做交叉验证。
- **性能红线**：翻页≤16ms/帧、气泡冷≤300ms/热≤80ms、字典≤15MB、启动→书架≤1.8s、内存≤180MB、字体子集≤200KB、地图≤2s、纪年换算≤8ms、球面 LOD 2-3帧、球面 55fps 手机/120fps 桌面、首次加载≤800ms。
- **灵魂闭环＝冒烟验收手段，非目的**；真正验收是整套规格做对+好看+好用+边界全兜底。
