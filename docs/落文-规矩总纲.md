## 一、目的 vs 手段（最高优先级）

- 灵魂闭环只是冒烟用例，**验收是手段、不是目的**：打开书→竖排读→点字出气泡→点「晋」命中春秋晋国→点「鲁隐公元年」出前722干支。
- 真正目的是：把整套规格做对、做好看、好用、所有边界兜底，不降级、不砍功能、不允许空白态或崩溃。
- **【最高优先级】开工第一步两读 + 逐条调用全部铁律自检**：任何任务/派单/提交/推送/判 CI/改台账/回用户前，先 Read 本总纲 + `docs/机制-总控必读.md`（子代理读各自机制文件），再逐条过一遍铁律确认满足/已覆盖，未覆盖即补齐。只写不执行=未遵守。
- **派单任务书第一行固定写前置**：`【开工前必读】按角色读对应机制文件：写码/审计读 docs/机制-子代理必读.md；验收读 docs/机制-验收代理必读.md；总控读 docs/机制-总控必读.md。再读 docs/问题清单.md 对应编号 + docs/问题清单-附录-逐文件.md 落点，然后动手。报告必须含"二阶三阶影响""反例/边界""认知成本"三节。` 缺这三节或缺前置阅读的交付一律打回。

## 二、四条硬规则（读对话/派单/验收的根本纪律）

1. 锚点强制可回源：每条结论必须能回到原文行号/切片/文件。
2. 规格、契约、验收三类**禁止压缩**，只压缩已完结过程。
3. 子 AI 禁止自行摘要——只读小段原文照做，靠索引+完整覆盖核对。
4. 三层分离：导航层可有损（只答"在哪"）；执行层无损（原文切片逐字）；验收层逐字对照原文全文。

## 三、铁律全集（分主题整合）

### A 边界与红线（改什么、不能改什么）

**A1 落文只保留 Legado 排版引擎，界面全部原生自绘重写。**
> 改动边界只动 UI，不碰 legado 排版引擎。**保留不动（legado 横排引擎）**：`page/provider/*`、`page/entities/*`、`page/api/*`、`page/delegate/*` 一行不许动。**落文自有竖排引擎 `vertical/*`**：这是落文自己写、自己维护的核心资产，只冻结公开 API 签名（`VerticalLayoutEngine.layout/hitTest/invalidateCache`、`BubbleResolver.resolve`、`ContextAnchor`），内部实现可维护、可改，不得当"legado 保留不动"锁死。（旧铁律 1；2026-11-24 修正走偏：vertical 非 legado 保留、text 为幽灵路径、补 delegate）

**A2 禁止"只换 UI 壳"式派单（贴皮禁令）。**
> 禁止复用旧 XML、`*Binding`、旧 Adapter/ViewHolder/Fragment 界面编排；禁止把旧 XML 逐条翻译成 Compose。允许复用底层能力（DB/DAO、网络、规则解析、偏好、model）。每包必须带"功能项 100% 对照表（旧功能→新落点行号）"。（旧 56）

**A3 新逻辑先接好再删旧，不留旧格式兼容层，及时清废旧代码。**
> 接新再删旧，避免旧包袱继续背。（旧 25）

**A4 清缝合怪必须双口径扫描，禁止只看 `R.layout`。**
> 删资源前扫三遍：`R.layout.<名>`/`@layout/<名>` 文本引用 + ViewBinding 类名 `<驼峰>Binding`。实证 194 个 layout 里单口径 100 个"零引用"、复扫 ViewBinding 后 97 个是活引用、真死仅 3 个。（旧 81）

**A5 冻结契约不许改签名（三引擎 + 图标 + 包名/签名）。**
> `VerticalLayoutEngine.layout/hitTest/invalidateCache`、`BubbleResolver.resolve`（sealed Action 四子类不许增删）、`ContextAnchor`（全 app 唯一消歧入口）；包名 `com.legado.app`/`io.legado.app`、应用名「落文」、keystore `app/luowen.jks`（alias `luowen`，口令 `luowen2026`，SHA-256 `B6:2D:…:E4`）——签名不一致会导致覆盖安装失败。（旧 17）

**A6 图标定案 = 玻璃金星 3D 版，冻结。**
> 任何代理不得改图标；要改必须用户明示 + `apply_icon.py` 重生成 + 出图预览确认后才许提交。（旧 79）

**A7 数据分层按需加载，不堆进安装包。**
> APK 只内置核心小数据；书/图层/战役/大词典按需下载 + 预缓存 + 断网兜底。（已定决策）

**A8 性能红线（可度量的硬指标）。**
> 翻页≤16ms/帧、气泡冷≤300ms/热≤80ms、字典≤15MB、启动→书架≤1.8s、内存≤180MB、字体子集≤200KB、地图≤2s、纪年换算≤8ms、球面 55fps 手机/120fps 桌面、首载≤800ms。每个模块配可跑单测+bench，性能跑过才算数；只过编译没真机验证的显式写进交付说明。（旧 16）

### B 质量与自检（怎么写才算对）

**B1 编译通过≠功能可用；未验证必须明说未验证。**
> 防"假绿"。真机验证后置（用户已定"不用真机了"），真机观感/性能/GLES 一律照实写"未验证"。（旧 2、55）

**B2 改动后先 grep 确认代码真写入，未生效不许编译更不许报完成。**
> 落盘验证。（旧 11）

**B3 改代码推演二阶三阶影响，不只考虑直接效果。**
> 报告必须带"影响推演"：直接效果 → 对其他模块/调用方连带影响（列文件与接口）→ 对用户行为/复杂度/维护成本的二阶三阶后果。（旧 9、59）

**B4 做方案先假设自己错，找反例边界再定。**
> 写"最强反对者"节：能推翻方案的证据/反例/边界（空数据/断网/年份缺失/同名消歧失败/帧率掉线/超大文件/极端字号），并给否证后是否成立。没有反例清单不许进实现。（旧 10、61）

**B5 跨领域对照求解。**
> 先找 2+ 外域同类最优解（竖排分页↔断行盒模型、地图粒子↔GPU instancing、离线缓存↔CDN 预取），写清采纳/不采纳理由，禁拍脑袋。（旧 60）

**B6 排查用穷举法：一次列全部嫌疑点，一次性全改，不逐点试。**
> 穷举防反复试错。（旧 22）

**B7 改动前先读源码、对比旧 APK 借鉴，再自己重新研究重写。**
> 先读源码再改；先借鉴旧版好用实现再重写。**已有实现绝不复用、只做参考**（防带病续命）。（旧 23、24、15）

**B8 质量优先、交付前自检，不好全部返工。**
> 先做单项自检，再做一次整体自检，才可交付；质量>速度。（旧 4、15）

**B9 交付前自模拟跑一遍关键路径并逐项自查；不出包、不报 APK（用户已定：只要完美版，不要包）。**
> 防空口交付。（旧 3、26，已按最新口令改）

**B10 分级验证五级门禁，每级判据不同、结论不可越级借用。**
> L0 写码自检（不算验收）→ L1 独立静态验收（强制词法配平扫描：`/*`↔`*/`、括号三对、剔字符串计数）→ L2 云端编译单测 bench → L3 组装级（上一级全绿才升）→ L4 灵魂闭环（已不设门禁）。顶门禁=L3+CI 全绿+全量单测 0 failed+静态/轨迹复核。落地三条：commit 前 `git status` 自盘；push 后 `git status -sb` 为 `## main...origin/main`；验收报告命名 `验收-复核-<模块>.md`、禁改写写码代理报告。（旧 55）

**B11 自检必须自报级别，低级别结论不得当验收。**
> 任何"已通过"必须带 `L0/L0.5/L1/L2/L3` 标签；禁止拿 L0 grep 说"功能验证过"、拿 L2"CI 绿"说"功能可用"。（旧 82）

**B12 历史包袱审计与安全移除 + 新人认知成本 + 返工复盘。**
> 动模块前用 `git log --follow/-S` 分三类（有意为之/历史遗留/为已不存在问题引入）；每个交付附"认知成本"评估并**自行执行最优简化**（拆>1000行文件、收拢同职责双实现）；每轮收尾复盘返工根因，聚簇（编译遮蔽/口径错/契约漂移/贴皮/验收放水/历史包袱/边界缺失）并沉淀为规则或自动化。（旧 12、13、62、63、65）

**B13 最慢环节分析。**
> 按 CI 历史找慢点（编译/单测/体积/启动阻塞），给"慢在哪/为什么/怎么优化"，可自动化部分写脚本；禁把慢归因"机器不行"。（旧 64）

### C 规格与上下文（原文怎么保真）

**C1 用户原文规格逐字保留、不蒸馏不改写；子 AI 只读小段原文照做，靠索引+完整覆盖核对。**
> 原文无损，防自行编造/摘要。（旧 19、20）

**C2 规格超上下文时分段读、记结论继续读，不许跳读。**
> 长规格必须全读完。（旧 8）

**C3 规格未覆盖的边界自行判断兜底，不降级、不砍、不允许空白态或崩溃。**
> 每种边界必须有迂回方案（地图没网就预缓存、粒子多就优化算法不砍粒子）。（旧 6）

**C4 数据字段 schema 先行、示例数字是下限非上限；数据拉满与闭环解耦并行。**
> 先抽 schema 再按规则拉满；示例数字（8/120/2000）是模式不是配额；批量灌数脚本与最小闭环互不阻塞。（旧 35、36）

**C5 派单前冻结三层地基契约，不冻结不派单；细节唯一事实源落磁盘。**
> 设计系统/消歧接口/数据 schema 先落盘冻结再并行；子代理开工从磁盘重读契约与原文，不靠主控口述。（旧 37、38）

**C6 落盘原文/资产逐字符比对自检，UTF-8 无乱码无截断，磁盘+云链接双备份。**
> 落盘无损双保险。（旧 41）

**C7 翻轨迹双向理解：用户的话 + 我(agent)说过、用户未否决的话，都算约定。**
> 未否决=默认接受。（旧 28）

**C8 指令前后冲突时，以后面（最新）指令与实际（工程现实/史实）为准。**
> 后令+事实优先。例：JDK 按工程实际 21、干支按史实己未、距今按后说 1950。（旧 29）

**C9 上下文抢救只做逐字抽取，禁止转述。**
> 按时间锚抽原文落 docs，保留原始行号可回源；不得让子 AI"读完再概述"。（旧 52）

**C10 状态判断以仓库事实为准。**
> 判"待派/已完成"先 `git log`+`grep` 复核，索引与仓库冲突以仓库为准并回写。（旧 53）

### D 派单与代理（怎么拆、怎么用代理）

**D1 一个问题一个子代理。**
> 不许打包多缺陷"一次全清"，任务书只写一个问题（报错原文/判据+落点行号+只许改哪个文件）。（旧 57）

**D2 写码/验收代理一次性用完即弃，禁止唤醒复用（最严口径）。**
> 一次派单=一条命；organizer 对子代理的 `send_message` 目标数恒等于 0（唯一例外是叫停/终止）；补活先终止在飞代理再派全新代理，上一代理的未提交半成品作为事实交底（产物可继承、代理不可继承）。（旧 45、48）

**D3 验收 AI 独立把关，禁自评代验收。**
> 每模块完工交独立验收 AI 逐字对照规格判质量；判低 → 换掉项目 AI、废弃代码、重派重做；项目 AI 禁止自评代验收。（旧 27、70）

**D4 验收代理一缺陷一条，禁一代理验多条。**
> 四条改动同批提交也要拆四个验收代理；台账"独立验收代理"列逐行不同 id。（旧 85）

**D5 子代理资源预算 + 输出体积双重熔断。**
> 派单书固定：禁编译/重 IO/死循环，只允许 grep/git show/python 短脚本；单条回报文本 ≤ 约 4KB，一旦变长/重复立即只回"结论+产物路径+未验证项"；超 15 分钟无产物或无报告即判废 kill（小模块写/修应 5–10 分钟内交付，大模块派单书写死更长超时并显式声明）。（旧 71、87）

**D6 跨模块问题交接，不漏交不甩锅。**
> 子 AI 发现非自己域的问题，记录（问题/归属/发现者/证据）交总控转给对应子 AI；不属任何切片进待派清单。（旧 32）

**D7 同文件多缺陷必须串行，不同文件可并行。**
> 两个代理不许同写一个文件；修缺陷先修遮蔽性最强的（语法/API 存在性>签名咬合>挂起上下文>功能逻辑>观感）。（旧 66 附则）

**D8 反思文件交接：充分利用，但不完全依赖。**
> 每个写码/验收子代理收工时写 `docs/反思-<模块>-<缺陷号>.md`，至少含：① 做了什么（一句话）② 踩的坑/教训 ③ 我可能判断错的地方/存疑点 ④ 遗留未决项 ⑤ 给下任的一句话提醒。总控把该文件路径写进**下一个需要它的代理**的任务书"参考清单"，要求：**先读、充分吸收**（不重踩坑、复用已确认结论）；但**每个关键结论必须回仓库/原文/契约独立复核，以仓库事实为准**——反思文件是人写的、会漂/会错/会过时，不得直接采信当事实。（呼应 C10/F3；交接不抄内容、只传路径）

### E 流水线与并发（怎么推进、怎么收口）

**E1 写→验→push→编译→编译后再验，两道验收都过才算完成；不攒批。**
> 写完一个验一个编一个；写完先存仓库，边写边推边编，不干等编译。（旧 33）

**E2 push 不阻塞验收：验收未过也先推云端，只做区分标记。**
> 代码写完 commit 即 push 存档；PASS/FAIL 只做区分标记；FAIL 有空位即调新代理重写，不留本地藏码空窗。（旧 47、50）

**E3 代码槽永不空（满编 5 槽：4 写 + 1 独立验收），写完即送审。**
> 4 个写码槽任何时刻不许空，完成一个立即补派；写码完成立即送验收槽（不攒批）；验收报错派新代理重写，不退回原代理、不让 organizer 下场修 bug。（旧 45、50）

**E4 分层组装验收（金字塔）。**
> 每 10 小模块聚合成 1 大组装编译验收（clean 编译+测试，专验接口咬合）；每 2 大组装再聚合成更大组装，直到整仓全量；契约索引登记"模块→所属组装单元→更大组装"层级归属。（旧 46）

**E5 P0 红灯优先。**
> CI 红或没包时，停发新功能派单，全队先修红；修复最小改动立刻 push（CI 即验收）；已在飞的允许收尾，不许再开新功能单。（旧 69）

**E6 出包链路暂冻结（用户已定：不要包）。**
> `data_scripts/release.sh` / `bump-versioncode.sh` 脚本保留但不再作为目标；versionCode 唯一权威=根 `.versioncode`（当前 38000，禁改小），仅在用户以后明确要包时再启用。（旧 58、73，已按最新口令改）

**E7 只交完美版：所有验收（L1+L2+L3）过完才算完成，一次性交付；不出包、不交半成品。**
> L1+L2+L3 全过之前不报完成；最终以 CI 绿 + 单测全绿 + L2 运行级验收过为准。（旧 78，已按最新口令改）

**E8 JDK21 + clean 全量重编，禁增量。**
> 云端 temurin-21，`clean` + `assemble` 全量；沙箱内禁一切编译（gradle+kotlinc），编译/单测/bench 真跑全走 CI。（旧 21、30 及已定决策）

**E9 并发自适应与限流防护。**
> 本机实测 2 vCPU / 3.9G 无 swap（见 `docs/资源清查与利用方案.md`）→ **落文在飞代理并发硬上限 5 = 4 写码 + 1 验收（查）**，验收代理独立、不与写码代理复用；按 1 分钟负载动态下调：`load1 < 1.5` 允许满 5，`≥1.5` 饱和降到 2（下限 2 永不突破）；`rule-gate.sh` 第⑨项机械判。只并发文件域互不重叠的任务。限流根因先查孤儿进程/垃圾输出（不是平台锅）；触发限流标准动作：停发→终止在飞代理→`ps` 清孤儿进程+`df/du` 查盘清 `/tmp`→低频恢复→重建基线；调度层禁高频轮询（<5 分钟间隔），实时轮询只用 `wait_agent` 阻塞等待。（旧 18、74、86、88、89）

**E10 子代理请求预算（限流的真正开关：请求率，不是稳定 CPU）。**
> 限流主因是"单位时间工具请求数"爆掉，不是稳定 CPU 高：本会话实测中位子代理 49 次调用，失控代理（网速插件任务）6894 次（4857 Bash + 539 Edit + 512 Write）——单代理请求率失控才是爆炸源。→ 派单书写死**工具调用预算**：写/修 ≤ 40 次、验收 ≤ 60 次，超过即判失控 kill（与 15 分钟熔断并列，先到先废）；**独立工具调用必须一次性并行发**（一条 assistant 消息内多个 tool_calls），禁串行单发，把"请求数"压成"批次数"；回报只一次 ≤4KB。**读长文不算刷请求**：切片仍超上下文时，按 `offset/limit` 分段读以突破上下文——每段只读一次、结论即落盘、不跳读（对口"规格超上下文分段读、记结论继续读"）；禁止的只是"同一段已读且已记结论后无进展重读"。切片超上下文需分段读的，派单书显式上调工具预算。（新）

**E11 请求率补齐（限流短板的五杠杆）。**
> 请求率是唯一短板，补齐靠"请求效率 + 外置 + 整形"，不靠堆并发。①**派单零发现成本**：总控把原文切片/文件绝对路径/契约原句/已知陷阱/前任结论全预塞进任务书，子代理只"读切片→写→grep 自检→回话"，不许 search、不许重读已给内容、不许重新推导上下文；②**脚本合并**：多文件读+加工写成一次脚本跑、结果落盘、只读一次结果，不许 N 次 Read/Grep 干一摊事；③**外置重活**：编译/单测/批量数据/长文分段/交叉验证全走 CI 或后台脚本，不进沙箱工具通道；④**请求整形**：错峰派发（间隔 30s~1min，防瞬时洪峰）、`wait_agent` 阻塞不忙轮询、关键动作后主动退避；⑤**实测留边际**：watchdog 记录请求率快照，回放限流临界点，把并发/预算压到实测阈值的 60~70%。（新）

**E12 派单分型 + 完成定义 + 止损（复盘代理失控的补漏）。**
> 派单前先判任务类型：**执行型**（有明确切片/契约/预期产物）用"切片照做 + 工具预算 + DoD"；**探索型**（重写/设计/调研/多方案）必须额外给"探索边界（尝试次数/时间上限）+ 止损点 + 阶段性汇报锚点"，不许当执行型一刀切——历史所有失控（C4A 重写六包、netboost 做插件）都是"把探索型当执行型派、又不给探索边界"。**每单必带可判定完成定义（DoD）**——"做到什么 = 完成"，验收代理据此判；**必带止损动作**——"卡在 X 就停、报告 Y，不许死磕"。同构批量任务先由总控做 2~3 个样，把样例路径写进每个子代理任务书（few-shot，防自猜格式跑飞）。（新）

**E13 规格登记 + 持续完整性闭环（立项规则唯一权威见 `docs/规格登记册.md`）。**
> 每一项规格登记唯一编号 + 立项缺陷号 + 状态 + 完成定义/验收证据；用户每轮新增/修改要求当轮登记立项，改既有规格则更新对应行、不重复登记。**立项的术语定义、两类规格（功能/治理）、状态机、每轮动作、完整性判据，全部以 `docs/规格登记册.md` 为唯一权威，此处不复制**（防止两处各写一套、一处漂移让子 AI 误读）。`data_scripts/spec-check.sh` 每轮结束前 + commit 前机械检查。（新）
