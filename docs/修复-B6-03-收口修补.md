## 三、D1 裁决：删除 `DiscoverRegion` 枚举（含理由、二阶影响、为何不选消费）

### 裁决结论

选删除，不做快照层消费。

### 理由

1. 全仓零消费：删除前 `rg -n 'DiscoverRegion' app/src --glob '*.kt'` 仅定义处一处命中；无 `when` 分支、无访问器、无测试引用（验收 D1 同口径，本单 grep 复核一致）。
2. 五区身份已有强类型表达：五个状态位（`battleState` / `classicState` / `topicState` / `heroState` / `notebookState`，DiscoverViewModel.kt:108-112）、五个端口（:54-76）、五个单区刷新方法（:124-181）、五个快照访问器（:184-196）、聚合快照五个字段（:81-87）。枚举是第二条平行身份轴，不承载任何行为。
3. 无既有穷尽消费方：仓内不存在对该枚举的 `when` 表达式，删除不会留下未穷尽分支；也没有扩展函数或序列化路径依赖它。

### 二阶影响

- 生产 main 侧：零引用，无符号悬空；符号存在性门禁可反查。
- 测试侧：`DiscoverViewModelTest.kt` 未引用该枚举；`DiscoverModelsTest.kt` / `DiscoverMotionTest.kt` 未引用。
- 契约面：未新增、未改名任何公共数据类；删除的是一个未被使用的装饰枚举，不影响 `DiscoverPageState` 五字段强类型结构。
- 文档面：旧验收报告 `docs/验收-复核-B6-03发现页VM编排.md` 与旧锚点卡中对 :29 的描述属历史留档，不在本单文件域内回改；本单新报告与新卡不再引用该枚举。
- 未来成本：若 B6-05 分区壳或 B6-12 挂载单确实需要按区遍历（例如 stagger 顺序表、分区可见性清单），届时在有真实消费方的位置再引入枚举或有序表；现在保留一个无消费方的抽象属于投机性设计，后续还要维护它与五字段集合不漂移。

### 为什么不选「页面快照层真实消费」

1. 类型不可压平：`DiscoverPageState` 五字段泛型实参各不相同（`BattleCardData` / `ClassicBook` / `TopicCardData` / `HeroCardDraft` / `NotebookEntryCard`），键式聚合只能退化成 `Map<DiscoverRegion, RegionState<*>>`，把已有强类型抹成星号类型，形成第二份平行契约——与验收 X1 / N5 已登记的双轨争议同向加重。
2. 无现存调用方：仓内当前没有遍历五区的代码路径；为保留枚举而造一个聚合键，是让实现迁就未被使用的抽象。
3. 边界约束：本单白名单只含 VM 与其单测；改快照数据结构（新增聚合键 / 遍历入口）超出收口修补边界，且会牵动 B6-04 动效读取快照的既有路径。

## 四、D5 / D2 生字本对称性收口与坏条目口径

### 错误隔离（与四区同构）

- 包裹形态对齐：`runCatching { notebookSource.load() }.mapCatching { … }`，端口读抛异常、过滤抛异常、映射抛异常三类都被收进 `Result`，不向上逃逸到页面层。
- 失败兜底复用 `offlineCopy`：保留上一轮 items；`offline=true`；`errorMessage = failure.message ?: "数据源不可达"`；无旧内容 `OFFLINE`，有旧内容 `ERROR`。与 `applyRegion` 四区失败分支同一套代码，不再各拷一份口径。

### 坏条目口径（自洽定义，测试已钉住）

- 判坏规则：`token` 经 `trim()` 后为空视为坏条目；`bookName` / `chapterTitle` 空白按空串兜底（类比四区 era / context / preview 缺源留空，不计坏）；`timestamp` 非正不预判新列，不计坏。
- 坏条目表现在哪里：
  - 表现在 `count` 上：入口卡 `count` 只计有效条目数，坏条目不计入；
  - 表现在 `dropped` 上：坏条目逐条计入 `RegionState.dropped`，与四区 `MapOutcome.dropped` 同口径上报；
  - 不表现在 `status` 上：`status` 只由「有效条目数是否为 0」决定；端口可达且过滤完成时，即使全坏也落 `EMPTY`（恒带一卡、count=0、dropped=N），不单独置 ERROR / OFFLINE；只有读源或映射抛异常才进失败分支。
- 恒带一卡口径不破：本区 `items` 恒为 `listOf(一张 NotebookEntryCard)`，空态由 `count==0` + `EMPTY` 表达，不返回空列表；壳层不得再叠空态卡（沿用 B6-05 装配注意事项）。

### 边界推演

- 空列表：有效 0 条 → EMPTY、count=0、dropped=0、恒带一卡（既有用例 `notebook refresh maps entry count and empty count yields empty` 守住）。
- 混合好坏：好条目入场计数，坏条目进 dropped，CONTENT。
- 全坏：EMPTY 而非空列表，卡仍在，count=0，dropped=坏条目数。
- 二次刷新失败：保留上一轮卡与 count，置 ERROR + offline；首轮即失败：OFFLINE、items 空。

## 八、自查反例（改坏推演）

- 反例一：若为保留枚举而做键式聚合，强类型被抹成 `RegionState<*>`，下游分区壳取卡片字段要二次强转，类型不安全且形成双轨。本单处置：删除枚举，保留五字段强类型结构。
- 反例二：若生字本映射仍留在 `mapCatching` 之外，后续映射层加字段校验抛异常时异常会逃出刷新路径，首屏崩溃且无离线兜底。本单处置：映射与过滤整体包进 `mapCatching`，失败进共用 `offlineCopy`。
- 反例三：若坏条目从 count 与 dropped 两边都漏算，页面入口卡计数虚高、坏条目不可见，与四区坏条目口径不一致。本单处置：count 只计有效条目，dropped 逐条上报，测试双向钉住。
- 反例四：若失败分支把上一轮 items 清空，断网回退后页面空白，违反「离线保留上一轮内容」口径。本单处置：失败分支只 `copy` 状态位与摘要，items 沿用旧值，ERROR 用例守住旧卡。
- 反例五：若把恒带一卡改成空列表表达空态，B6-05 壳层会叠出双层空态。本单处置：成功路径恒 `listOf(card)`，全坏用例断言 `items.size==1`。
