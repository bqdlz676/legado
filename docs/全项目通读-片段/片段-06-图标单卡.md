# 片段 06 · docs/图标单卡/（77 个 md，一图标一卡）

## 这个目录有什么
- 77 张卡对应切片-24 的 77 个 VectorDrawable：导航/阅读工具栏/气泡菜单/画板/六色/地图沙盘/地球仪/名物 17 类/专题/状态/音效三态/书架/文件类型。
- 每卡结构：切片规格逐字行 → 三段 pathData 坐标 → 规范（24dp、strokeWidth 1.5、round 端点、暗铜 #8B6914）→ 自检（minidom 良构、grep 命中、坐标 0..24）→ 未验证项声明（未编译未真机）。

## 发现的问题
- ic_launcher_small.md 虽标注 F-46 作废不制作，但仍作为一张卡留在 77 文件目录内，计数与"77 个有效图标"口径需要靠卡片内文字排除，容易被后续统计误算。
- 自检停留在 XML 良构与坐标区间，未含视觉一致性/缩略图比对；"未编译未真机"是常态声明。

## 值得肯定
- 每卡把抽象规格落成确定 pathData 与边界校验（半宽/越界/圆角），坐标可直接照抄生成 drawable，减少实现代理自行发挥空间。
- 作废卡也留了反证 grep（工程内零引用、禁词扫描无残留），区分"有意缺席"与"漏做"。
