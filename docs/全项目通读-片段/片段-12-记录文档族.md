# 片段 12 · 过程记录族（CI归因 16 / 修复 64 / 验收 54 / 反思 19 / 台账 11）

## 这个目录有什么
- `CI归因-45xxxx.md` 16 份：每份一张表（conclusion/commit/标题/时间）+ 错误归并 + 根因 + 处置；与事故清单 K 族一一对应，门禁 ㉛ 机械核对 failure run 必须在册。
- `修复-*.md` 64 份：任务范围、基线 HEAD、白名单文件、改动、grep 自检；多份标题带"复审/返工/容差返工"，说明同一缺陷经多轮。
- `验收-*.md` 54 份：分首轮验收与`验收-复核-*`独立复核；结论带 L0~L4 级别与"未验证"标注；选型类（T6/启动图标）记选中与判低理由。
- `反思-*.md` 19 份统一五段：做了什么 / 踩坑教训 / 我可能判断错的地方 / 遗留未决 / 给下任提醒。`台账-*` 11 本：存活代理、空转盘点、缝合怪、验收分层 DEF-01~09、熔断、三件缺项、前置设计费、本地编译违规、CI 转绿、作废冻结标记、观感 UX。

## 发现的问题
- 验收结论普遍停在低级别：抽样 54 份中大量同时含 FAIL/部分 PASS/未验证；多条仅 L0/L1 静态过关，L2 编译/L3 契约/L4 运行未取得；`验收-U10/U11/U6/书源域/工具页/设置关于/接线包C` 等几乎只标"未验证"。
- 修复文档历史回证缺档：F10 记录 46 修复 + 22 验收共 68 份形态为"有结论无 grep 与 文件:行"，只看报告无法回源；新报告才由 check-evidence.py 强制 E1/E2/E3。
- 同一缺陷多份返工文档并存（B10 三份、高亮三件三份、B2~B15 各一复核），文档数量随轮次膨胀，最新结论需回看问题清单状态列才知道哪份生效。

## 值得肯定
- 反思段强制写"我可能判断错的地方"与未上机验证项，把静态推断与运行期结论分开，避免把推断当事实；并给下任一条复跑命令（如先跑 scan-orphan-strings.py 复扫）。
- 验收分层台账 DEF-01~09 把缺陷归到金字塔层，矩阵层 1 关键对 27（已验 PASS 0 / 有缺陷 1 / 待验 18 / 未落地 8），覆盖缺口可见。
- CI 归因与事故清单双向挂钩，判废代理 id 也强制在册，证据链闭合到 run 与 commit 短号。
