# 片段 05 · docs/T6候选预览 + 图标规格候选（2 对比表 md + 14 张 PNG）

## 这个目录有什么
- T6候选预览：4 候选（高光 A/B、剪影 A/B）各 1024 与 72px 预览图 + 对比表.md，按视觉辨识度/复杂度/性能/兜底/token 一致性/可测性六维对照，结论高光 A、剪影 A 选中，B 两案判低。
- 图标规格候选：启动图标 A/B/C 三候选预览图 + 对比表.md，结论 A·绢帛墨山选中。

## 发现的问题
- 对比表只做维度对照、选型结论交独立验收代理，但表内「选中/判低」理由已直接写入总表右列，流水线职责边界在文档里有轻微重叠。
- 预览图体积大：4 张 1024 PNG 各约 1.4MB 入库，属文档目录里的二进制资产，会撑大仓库。

## 值得肯定
- 判低理由落到可核验事实：B 高光依赖尚不存在的片元渲染层（RenderPipeline/SoftwareRasterizer 现状查证）；B 剪影无场景身份锚点、mask IoU 不可验；72px 坍缩逐案目检记录。
- 每条候选都列了四边界兜底（断网/离线/低端机/掉线）与 token 回挂情况，选型同时评估可落地性而非只看美观。
