# 片段 14 · data_scripts/（61 项，50 可执行：39 py + 11 sh）与 .github/workflows/

## 这个目录有什么
- 门禁层：`rule-gate.sh` 串起 38 道机械闸（①~㊴），每道对应一个 `check-*.py`：台账新鲜度/档位/队列/锚点卡/本地禁编译/规格完整性/扩展 import/测试源码陷阱/回执证据/三段锚点/缝合怪/接手链/规则总账/缺项台账/组合验收/子代理存活/测试函数名/停工/队首推进/事故在册/Float-Double 混算/禁本地编译/Groovy 语法/推送窗口/锚点防洗白/验收字样/熔断/认证书尾。
- 运营层：`pre-push.sh`（30 分钟节拍攒批，防连环 push 取消在飞 run）、`release.sh`（CI 绿→取 artifact→aapt2 校验 versionCode→交付）、`watchdog.sh`（失控熔断，防吃满 2 核 4G）、`resume-state.sh`（一键恢复上下文）、`update-handover.py`（快照段自动重写）、`fetch-ci-log.sh`（日志归因抓取）、`queue_stats.py`（在飞/待派唯一计数源）。
- 数据/资产层：`build_dict.py` 722 行、`build_geo.py` 1611 行、`build_people.py` 1263 行（字典/地理/人物构建），`gen-launcher-icon.py` 625 行，`scan-orphan-strings.py`/`scan-orphan-res.py`/`delete-orphan-strings.py` 孤儿清理，`frame-manifest.py` 截图清单，`bump-versioncode.sh`/`build-delete-manifest.py`。
- 虚拟自检三层：`selfcheck-data.py`（数据级）、`selfcheck-path.sh`（接线级 22 环）、`selfcheck-flow.py`（流程级），不跑 Android 也能过关键路径。
- CI：`build.yml` discover 枚举测试类 round-robin 切 4 片 → 4 分片 fail-fast:false → aggregate 求和 JUnit 硬断言基线 3185、禁 failures/errors/skipped、跨片去重、清单交叉核对 → `build-apks` composite 双包构建 + 二进制 versionCode 断言；另有 baseline 单 job 对照模式。`screenshot.yml` 独立并发组跑 :screenshot Paparazzi 出帧 + frames.json。

## 发现的问题
- `pre-push.sh` 第 1 步仍用 `git add -A` 整体提交，与 F-112/E-05「禁 -A、逐路径 add」直接冲突；脚本本意是守纪律，自身却保留最容易裹入他人改动的写法。
- `rule-gate.sh` ② 与 `release.sh` 从 `~/.git-credentials` 抓 `ghp_` token 拼进 remote URL / Authorization header，token 出现在命令行与日志面；脚本内还硬编码期望索引版本 v2.36（门禁④），文档一升级不改脚本就会误红。
- 截图链路在 CI 从未成功出帧（待接 README 实证），`screenshot.yml` 指向的 `:screenshot` 模块与 `screenshot/` 源码需在 settings/目录核实是否真已落地；frame-manifest 当前可能无 workflow 实跑。
- 38 道闸里若干是 WARN/提示型（⑦级别自报、㊴认证书尾、㉟推送窗口），不阻断；体检 O 项亦指出⑨/⑰只判总数、写查未分列。

## 值得肯定
- 每道闸都回溯到具体事故编号与 run 号（如⑫来自两次 Compose 扩展函数漏 import 连红、㉞来自 Groovy 行首 # 假注释、㉘来自反引号测试函数名非法字符），不是凭空设卡。
- CI 分片机制有双重防漏：discover 校验并集=全集、片间零重叠；aggregate 再做 XML 类与 manifest 交叉核对、重复执行即报错；基线 3185 写死断言，新增测试需台账登记，防止分片悄悄漏测。
- 出包链脚本化：versionCode 单一权威 `.versioncode` + 地板 38000 + aapt2 从 APK 二进制读号比对，不靠记忆；release.sh 找不到该提交 run / CI 不绿 / 无 artifact / 无 apk 都有独立退出码。
- 缓存 key 绑定 wrapper distributionUrl 指纹 + build.gradle/版本目录 hash，换 Gradle 版本必然换 key；全程不用 continue-on-error、if:always()、exclude 测试类。
