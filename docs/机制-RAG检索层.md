# 机制 · RAG 检索层（切片—召回—回源）

锚点卡：docs/锚点/RAG检索层.md

> 立项来源：用户 2026-11-27 口令「弄一下这个进机制里面」，附抖音科普视频（RAG 知识库原理：切片、重叠、元数据、混合检索）。本文件把该套思路落成机制层的一层检索，**不改写既有铁律**，只补「找不到东西时怎么找」这一环。

## 一、先说清楚为什么不是「加个向量库」

前一轮用户已问过「这套机制建向量数据库没有」，当时答的是全仓无 faiss/milvus/chroma/qdrant/pinecone/sqlite-vec，机制层是纯文本索引 + rg + `文件:行` 锚点。这条结论继续有效，原因写死在这里，避免下一棒重新发明：

- 机制层的第一性要求是**锚点强制可回源**：任何结论必须能指到 `文件:行` 的原文。向量相似度只回答「意思像不像」，不回答「原文在哪」，拿它当唯一入口会把「疑似相关」当「已核实」，与铁律冲突。
- 切片一旦打散，章节、前提、引用关系会丢（这正是视频里说的「上下文失真」）。机制文档是判据文书，前提条件丢了就是另一种造假。
- 证据锚的漂移机检已经成体系：`data_scripts/check-line-anchors.py:261` 是主入口，`data_scripts/check-line-anchors.py:48` 指向棘轮基线 `data_scripts/line-anchors-baseline.json`，`data_scripts/check-line-anchors.py:239` 读基线、`:252` 算新增键；失联与漂移的四判口径写在 `docs/机制-证据锚规范.md:20`。
- 全仓已有一份不依赖任何模型的符号索引 `data_scripts/dep-symbols.json`（134 包 / 2932 类 / 7543 声明），再加一个需要下载模型、需要联网、需要几 GB 显存的向量库，维护成本与收益完全不成比例。

所以本层的口径是：**用 RAG 的「检索范式」，不用 RAG 的「向量底座」**。召回靠词法 + 结构，回源靠锚点，语义近似只作为补充信号，且永不单独成结论。

## 二、三件事按视频口径落地

视频讲的知识库存储三步，机制层对应如下：

- 切片：不按字数硬切，按 Markdown 标题层级切（`#`/`##`/`###` 小节即天然语义块）；单节超过 **500 字**再二次切分，相邻块保留 **50 字**重叠，防一句判据被剪成两半。
- 元数据（原文叫「原数据」）：每块带 `路径`、`小节标题`、`行号区间`、`文档类型`（修复/验收/机制/规格/源码/清单）、`域`（app 包名或 docs 主题）、`状态`（DONE / 在飞 / 作废 / 待裁）、`首现提交时间`。元数据的作用是**先缩范围再召回**（对应视频里「只查 2026 年的合同就先按标签缩范围」）。
- 召回：两路并行——词法路（FTS5 BM25 倒排，权重高）与结构路（小节标题/文件名/符号名精确匹配，权重最高），合并去重后按「结构命中 > 词法命中 > 长度惩罚」排序。**语义路暂缺**，用「同义词表 + 符号表」近似替代，落地在 `data_scripts/rag-synonyms.json`，只允许人工增补，不许自动学习。

## 三、八条口径（R1–R8）

- R1 **回源先于摘要**：查询结果每条必须带 `文件:行` 与原文片段（截断时给原文起止偏移），禁止只返回「摘要 + 相关度」。摘要是给人看的，锚点是给判据用的。
- R2 **切片不切判据**：一个小节内含多条件判据时整节保留，宁可超 500 字也不许在条件之间断开；重叠 50 字是下限不是上限。
- R3 **元数据先缩范围**：查询可带 `--type` / `--domain` / `--status` / `--since` 过滤，先缩范围再召回，禁止全库裸查后靠截断。
- R4 **增量索引**：按 mtime + 路径长度建索引，未变文件不重建；索引落 `data_scripts/_cache/rag-index.sqlite`（FTS5），可整库删除重建，不许成为事实源。
- R5 **不联网、不加载模型**：本层只用 Python 标准库（`sqlite3` 的 FTS5、`re`、`json`）。任何需要下载模型或调外部 API 的方案，一律驳回并写明理由。
- R6 **索引可复核**：给出 `--stats`（文档数、块数、平均块长、元数据分布）与 `--verify`（抽样 20 块回读原文，逐字比对哈希），索引坏了要能自己证明坏了。
- R7 **检索结果不进判据**：RAG 命中只能作为「去哪儿找」的线索，写进报告时必须回到原文重读并给锚点；直接引用检索摘要当证据＝造假，与既有语料断言闸冲突。
- R8 **三层兜底**：第一层索引召回 → 第二层 `rg`/`Glob` 精确落点 → 第三层人工/外部检索。任一层给出明确「未命中」信号，不许把「没找到」静默当「不存在」。

## 四、产物与入口

- 建库：`python3 data_scripts/rag-index.py [--rebuild] [--stats] [--verify]`
- 查询：`python3 data_scripts/rag-query.py "问题或关键词" [--type 修复] [--domain 陀螺仪] [--status 在飞] [--since 2026-11-20] [--top 20]`
- 表结构（FTS5）：`chunks(path, heading, line_start, line_end, body, type, domain, status, mtime)` + 外部内容表与倒排索引；同义词 `data_scripts/rag-synonyms.json`。
- 与既有机制的关系：`docs/索引-机制.md:4` 起的 `GEN` 区间仍是**导航层**（人工可读的全景），本层是**执行层**（机器召回的入口）。两者同源不同用，禁止把本层结果反写成索引正文。

## 五、验收判据（六条，缺一不通过）

0. 规格自身可回源：本文件引用的既有机制锚点必须在现行树上站得住（`data_scripts/check-line-anchors.py:261` 主入口回查；`docs/机制-证据锚规范.md:20` 是四判口径出处）。
1. 对一个已知答案的问题能召回正确小节，且返回锚点的 `文件:行` 与原文逐字一致（抽 5 条人工核对）。
2. 增量索引：改一份文档后重跑，只有该文档的块被重建（给块级 `mtime` 对照）。
3. 元数据过滤真的缩范围（同一关键词在带 `--type` 与不带时结果集大小差异给数字）。
4. `--verify` 在正常索引上 PASS；人为改坏一行后能 FAIL 并点名。
5. 500/50 切片规则由一个夹具文档验证：含跨段判据的长小节不被切断。
6. 全程零网络请求、零模型加载（给 `strace`/`socket` 级的替代证据：代码内无网络库引用 + 运行时无外部进程）。

## 六、与美感无关的一句

本层不出现在任何用户可见界面。它是给「下一棒的工程师」用的：明天换一个完全不懂项目的人接手，他问「这套机制里某条判据在哪」，应当一条命令拿到 `文件:行` 与原文，而不是翻 800 份报告。
