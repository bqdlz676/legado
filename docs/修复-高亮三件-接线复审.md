## 一、方案选择：B（Sheet 回 Dialog 形态，宿主不动）

宿主与半成品 Sheet 的语义不符共 4 处（> 止损阈值 3）：

1. 宿主走静态 `Companion.show(fragmentManager, model)`；wip 仅有裸 `@Composable ShadowEditSheet(visible, initial, onConfirm, onDismiss)`，无 Fragment 入口；
2. 宿主 `implements XxxEditDialog.Callback` + `override` 回调；wip 已删 Callback 接口，回调只是 Composable 形参；
3. 宿主是 XML `BottomSheetDialogFragment` 行式编排，自身无 Compose 树；wip Sheet 依赖 `visible` 状态提升由 Compose 树托管；
4. 下划线同上（show 入口 + Callback 接口两处断链）。

故按止损口径选 **B**：保留 Fragment 壳、`Callback` 接口、`companion.show` 与宿主既有调用签名逐字一致；内部承载换成 Compose 令牌体系。**未新增 `*Sheet.kt` 文件**；wip 裸 Sheet 函数收编为各文件 `private @Composable` 内容槽，对外只有一套 API，无两套并存。

## 五、二阶 / 三阶影响

- **宿主 409-415 一带调用方**：两个 override 现在解析到本单恢复的接口；`apply(style)` → `styleHost?.onHighlightStyleChanged(style)` → `refresh()` 重建行 UI。`styleHost` 为空时 `apply` 内空转不崩（宿主 `:57-60` 已有 dismiss 兜底）。回调链路上无第二实现方（全仓 `onShadowChanged/onUnderlineChanged` 仅宿主两处 override + 两弹窗声明/调用）。
- **主题色 / 夜读纯度**：本单不写死任何颜色，全部令牌取值，跟随组件主题解析；F-15 纯黑禁令只约束装饰 UI，阅读主题暗色/纯黑档属冻结配置项，本单未触碰阅读页背景。
- **编辑后重渲染路径**：阴影/下划线确认 → `apply(copy(...))` → `refresh()` 逐行回填开关/色样/extra 文案；备注确认 → `ReadBook.updateHighlight(highlight)` 走既有模型刷新路径，删除 → `removeHighlight`。弹窗在单次提交后 dismiss，重渲染由既有路径承担，本单不新增观察者。

## 六、反例与边界（假设判断错误时的兜底）

- **空笔记**：章节名空白不渲染空行；两字段空串允许提交（对齐旧版 `orEmpty()` 行为），不强制非空。
- **超长输入**：粘贴 5000+/1000+ 字符 → 输入侧即截断，计数封顶；提交前再截断一道；按 UTF-16 code unit 截取，代理对边界在中文备注场景极少出现，已在注释标注适用条件。
- **连点**：确定与删除互斥共用同一 `submitted`；取消同样置位；配置变更重建后状态随视图重建，不跨弹窗残留。
- **滑杆 0 与最大**：端点含在 `coerceIn` 区间内（width 0、distance 0 合法）；`normalized()` 对越界/非有限值回落默认；拖动区域宽度为 0 时手势回调直接 return，不除零。
- **宿主不可达**：`parentFragment` 与 `activity` 都不是 `Callback` 时 `?.` 空安全跳过回调，弹窗照常 dismiss，不抛 `ClassCastException`。
- **arguments 丢失**：进程重建后 parcel 缺失 → 空参 dismiss，不渲染半成品表单。
