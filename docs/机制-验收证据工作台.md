# 机制 · 验收证据工作台（acceptance-evidence.py）

## 1. 背景：为什么造这个工作台

- 113 份验收报告里 99 份写着"未本地编译"，其中 96 份照样判了 PASS——验收判据里从来没有编译面，验收代理只能看文档口径，形同摆设。
- 2026-11-26 夜两路 CI 红 24 条，全是编译错：拆文件漏 import、public 暴露 internal、私有 setter 直写；这些在验收环节事先一条都没被看见。
- 本工作台把"改动面 + 既有门禁机检 + 编译面风险清单 + 三值建议"压成一份可回源的机器输出，验收代理第一步跑脚本、贴证据块，不再靠嘴验。
- 脚本路径：`data_scripts/acceptance-evidence.py`；纯 Python 标准库，不联网、不编译、不做任何 git 写操作。

## 2. 用法

常规（本单改动文件显式指定，便于验收代理只看本单）：

```
python3 data_scripts/acceptance-evidence.py --paths <改动.kt ...> [--report docs/验收-xxx.md]
```

历史单回归（从指定提交取快照，与其父提交做 diff，快照落临时目录，不碰工作区）：

```
python3 data_scripts/acceptance-evidence.py --rev 88e62bc --paths <改动.kt ...>
```

机器可读：追加 `--json`；默认输出可直接贴进验收报告的 Markdown 证据块。退出码：`1` = 机检 FAIL；`0` = PASS 或有条件通过。

改动面来源：不给 `--paths` 时取 `git -c core.quotepath=false status --porcelain` 下本轮改动文件。

机检汇总（subprocess 调既有门禁，原样收回退出码与输出，不做二次解释）：

- 对每个改动 `.kt` 跑 `kotlin-syntax-lint.py`，PASS/FAIL 与 FAIL 条目原样收录；
- 给了 `--report` 时跑 `check-anchor-card.py --strict <报告>`；
- 跑 `check-onboarding.py`（按其自有口径扫本轮改动报告）；
- `--rev` 快照模式跳过报告门禁（快照上下文没有本单报告）。

## 3. 三值判据

- `FAIL`：任一机检 rc ≠ 0（lint / 锚点卡 / 回执任一 FAIL），直接判 FAIL，不得写成有条件通过或 PASS。
- `有条件通过（编译面待 CI）`：无机检 FAIL，但命中以下任一类编译面敏感改动——新增文件、import 改动、签名/可见性改动、搬迁候选、public 暴露 internal、行数超限（≥600）、疑似漏 import。
- `PASS`：无新增文件、无 import 改动、无签名/可见性改动，且机检全绿。
- 证据包给 `有条件通过（编译面待 CI）` 时，验收总结论**不得写成 PASS**；编译面以云端 clean 编译 + 单测全绿为准（接 `docs/机制-验收代理必读.md` §9、§10 硬规）。

## 4. 编译面风险清单推导口径

- **新增文件**：base（HEAD 或 `--rev^`）中不存在同名路径。
- **import 改动**：与 base 逐行比对，新增 / 移除的 import 原样列出。
- **跨包引用**：import 包名 ≠ 本文件包名，逐条列出供验收核对符号归属（androidx / kotlinx 等外部依赖均在此列）。
- **public 暴露 internal**：工作树扫描 `internal/private class/object/interface/typealias` 登记表；非 internal/private 的函数，其参数或返回类型命中登记表即报风险（含跨包 internal 类型）。
- **行数超限**：文件行数 ≥ 600（与 `kotlin-syntax-lint.py` LINE_WARN、`check-frankenstein.py` 同口径）。
- **搬迁候选**：本轮新文件里出现的符号，在 base 的别文件里存在、而在该别文件当前版本中消失，提示核对 import 是否随迁。
- **疑似漏 import**：大写符号在仓库他包有声明、本文件既未导入也未本地声明；另含 Compose 特例——源码使用 `.dp` 扩展属性却未导入 `androidx.compose.ui.unit.dp`（小写扩展属性，大写标识符扫不到）。
- **可见性漂移**：同一函数在 base 与当前版本之间可见性变化（如 public → internal），归入签名/可见性改动。
