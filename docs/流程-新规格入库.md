# 流程 · 新规格入库（F-88 唯一流水线）

> 用途：用户每贴入一条新要求 / 新规格，必须走本流水线接住，不许直接派写码单。
> 上游：用户消息；下游：`docs/规格登记册.md` → `docs/派单队列.md` → 门禁 ㉒。
> 巡检脚本：`data_scripts/check-spec-flow.py`（四向双向对齐，判据见脚本头注释）。

## 六步流水线

### 1. 接收（原样落盘）
- 输入：用户消息中的规格文本；附件路径一并记下。
- 动作：不改字、不摘要、不压缩，原样落 `docs/落文-原始/<日期>-<来源>.md`；文末记行数与来源（消息时间 / 附件名）。
- 产出：原始落盘文件 + 行数。
- 判据：落盘文本与用户原话逐字一致，可按日期/来源 grep 回源；本步禁止改写规格。

### 2. 切片（自包含切段）
- 输入：第 1 步原始文件。
- 动作：按功能域切段，每段独立成文，命名 `切片-<序号>-<主题>.md` 落 `docs/落文-规格切片/`；段内带 `文件:行` 锚点、逐字引文、本段自己要做什么的说明，边界与兜底写进段内。
- 产出：自包含切片文件。
- 判据：切片能单独发给一个不了解项目的代理而不产生误读（用户原话「排除掉所有可能让 ai 误读的风险，而各做一段」）；不依赖前后文；引文逐字、锚点可回源。

### 3. 登记（连续编号）
- 输入：第 2 步切片。
- 动作：在 `docs/规格登记册.md` 对应分区新增一行，编号连续不跳号；跳号必须在册内写明「跳号预留 + 原因」。
- 产出：登记册行（编号 / 规格一句话 / 来源锚点）。
- 判据：巡检 ①向无「切片无登记行」断裂；切片序号与登记编号一一对应。

### 4. 立项（档位 + 缺陷号 + DoD）
- 输入：登记册行 + `docs/立项规则.md`。
- 动作：按立项规则定 A/B/C 档与验收级别；缺陷号能复用既有号就复用，不能才新立；新号前 grep `docs/问题清单.md` 防撞号；写一句可验收 DoD。
- 产出：缺陷号 + 档位 + DoD 落册；功能规格进问题清单，治理规格不立缺陷号。
- 判据：缺陷号在清单找得到（巡检 ②向）；档位 / DoD 非空；新号 0 撞号。

### 5. 入队（派单排队 + 文件域互斥）
- 输入：已立项规格。
- 动作：写入 `docs/派单队列.md`（PENDING），注明文件域互斥范围与依赖；槽满原样保留，不缩范围、不合并降级。
- 产出：队列行。
- 判据：已立项项在问题清单 / 台账 / 队列三处至少留一处踪迹（巡检 ④向，无悬空立项）；文件域与在飞单互斥。

### 6. 巡检（入库门禁）
- 输入：前 5 步全部产物。
- 动作：跑 `python3 data_scripts/check-spec-flow.py`（门禁 ㉒ 同脚本）。
- 产出：`SPEC-FLOW: PASS` 或逐条漏项清单。
- 判据：必须 PASS 才算「已入库」；FAIL 回到对应步骤补齐，不许带断裂派单。

## 触发规则

1. 用户消息里出现规格文本（新功能 / 新规则 / 新口径 / 附件规格）→ 必须先走本流水线再派单；禁止直接派写码单（防贴皮，F-73 / F-85 / F-88 同口径）。
2. 每轮调度开始时跑一次巡检（`docs/机制-总控必读.md` §1 第一条动作）；commit / push / 派单前随 `rule-gate.sh` ㉒ 再跑一遍。
3. 治理类规格（改规则 / 文档 / 机制本身）同样走 1→3→6；第 4 步不立缺陷号，落地物 = 文件 + commit sha。
