## 一、项目是什么

**判断：这是一个在 Legado 阅读器旧仓之上、用 Jetpack Compose 重写全部界面、只保留其排版/解析内核的中文古籍阅读与推演 App；新栈数据层与规则治理体系已成形，但大量 UI 与 3D 模块仍停在"已提交待验收"或"已立项未开工"，旧栈十一万九千行代码仍在生产链路可达。**

### 1.1 技术栈

- 语言/构建：Kotlin 2.4 + JDK 21 工具链，AGP/Gradle，Groovy `settings.gradle`/`build.gradle`；版本收口在 `gradle/libs.versions.toml`（root `build.gradle` 全用 `alias libs.plugins.*`）。
- UI：Jetpack Compose（ui/foundation/animation/runtime/activity-compose），外围界面自绘，**不引入 material/material3 Compose 主题、不取 Material colorScheme**（`ui/components/ComponentTokens.kt:1-20`；`app/build.gradle` 依赖注释明示）。
- 保留内核：Room + DAO + AppDatabase、jsoup/json-path/xpath 规则解析、modules:rhino（18 kt，JS 引擎）、modules:book（Java epublib）、OkHttp/Cronet、media3/ExoPlayer/GSY/弹幕、Glide、libarchive、zxing。
- 测试：JUnit4 + Mockito（mockitoAgent javaagent），CI 4 分片并行 + 汇总硬断言；另有 Paparazzi 截图独立模块 `:screenshot`（5 kt）。
- 数据资产：`app/src/main/assets` 116M，含字典/说文/用例/拼音、人物、地名、典故、地图 DEM 与 `three.html` 等。

### 1.2 模块划分（编号口径见 `docs/落文-模块契约索引.md` §3）

- **C 契约层**：`C2 气泡解析`（`help/bubble/`，BubbleContent/BubbleResolver）；`C1 时空锚定+纪年`（`help/chrono/`，Chronology/ContextAnchor）。

## 二、优点（每条附证据与"好在哪"）

1. **新栈数据层边界干净、可单测、来源强制**。D1~D4/C1/C2 全部纯 Kotlin/JVM、不依赖 `android.content.Context`、不碰 UI，对外签名冻结（如 `help/chrono/Chronology.kt:238-14` 声明"只做纯计算，不碰 UI/Compose/Android 资源"；`help/person/PersonDirectory.kt:10-9`、`help/place/PlaceDirectory.kt:8-8` 同口径，无出处记录注册即拒）。好在业务规则与 Android 生命周期解耦，宿主单测可直接跑，是整套体系里最可维护的一层。

2. **规格→锚点→判据→反例形成可回源链条**。`docs/锚点/` 13 张卡每张含逐字引文（文件:行）、参数表、机械可判据、已知冲突去向；`check-anchor-card.py`（门禁⑲）与 `check-anchor-integrity.py`（门禁㊱）机械校验锚点存在与防洗白。好在写码代理被禁止凭记忆转述规格，返工根因（BookCard/TopicCard 凭记忆返工）被前置卡住。

3. **CI 分片有双重防漏测机制**。`.github/workflows/build.yml` discover 枚举编译产物测试类 round-robin 切 4 片，先校验"并集=全集、片间零重叠"；aggregate 再把 JUnit XML 类与 manifest 交叉核对、重复执行即报错，并硬断言 `tests ≥ 3185`、禁 failures/errors/skipped。好在分片并行不会悄悄漏类，基线数被锁死，新增测试须台账登记。

4. **出包链脚本化、不靠记忆**。`data_scripts/release.sh` 固定走"找该提交 run → 轮询到终态 → CI 不绿即中止 → 取 artifact → aapt2 从 APK 二进制读 versionCode 比对"，每步有独立退出码；`.versioncode` 是 versionCode 唯一权威，地板 38000，`build-apks` composite 双包共用避免两份出包步骤漂移。好在历史上"漏 bump versionCode/漏 aapt 断言/漏取 artifact"三类失误被固化成必执行步骤。

5. **规则逐条回溯到事故血缘**。`docs/规则形成史.md` 把 35 条 F 规则 + 21 道门禁血亲编号到具体事故，并单列 10 条"有事故没规则"缺口（K-17 排序口径、A-06/A-08 退化、S-07 远端 500 等）；`规则总账.md` 是 F-89 唯一事实源，门禁㉓机械判账在册、冲突已裁、旧口径不裸奔。好在规则不是拍脑袋堆出来的，每条能回答"防的是哪次事故"。

6. **事故台账化、可机械完整性校验**。50 条事故分 K/A/S/D/E 五族，每条带时间/run 号/证据文档/根因/处置/状态；`check-incident-register.py`（门禁㉛）核对散落在复盘/CI 归因/存活台账里的事故是否在册。好在"发生过什么"不再靠人翻记忆，新事故必须登记否则门禁 FAIL。

7. **保留范围克制、复用边界明确**。审计-历史包袱把旧代码分 A 有意保留（data/76 文件、analyzeRule、modules:book、modules:rhino、DAO、网络、朗读服务）/ B 历史遗留 / C 已不存在问题三类；规格 §3.4 明确允许复用 DB/DAO、网络、规则解析、偏好、model，丢弃旧 XML 界面与编排。好在没有把解析内核一起丢掉，也没有无差别保留旧 UI。

8. **虚拟运行自检补了"无运行时"的盲区**。`selfcheck-data.py`（数据级）、`selfcheck-path.sh`（接线级 22 环）、`selfcheck-flow.py`（流程级）三层不跑 Android 也能验证"喂给引擎的数据对不对、每环接上没有、流程通不通"。好在沙箱无 JDK21/无设备的前提下，仍有一层接线证据，而不是全靠肉眼。

9. **候选选型留了可核验的判低理由**。`T6候选预览/对比表.md`、`图标规格候选/对比表.md` 按视觉辨识度/复杂度/性能/兜底/token 一致性/可测性六维对照，判低理由落到具体事实（B 高光依赖尚不存在的渲染层；B 剪影无场景身份锚点、mask IoU 不可验），并覆盖断网/离线/低端机/掉线四边界。好在选型不是纯审美投票，能回溯为什么淘汰。

10. **性能与兜底有量化红线**。如高程采样 `ui/map/sandbox/DemTerrainElevation.kt:1-16` 对空栅格/尺寸不符/包围盒退化/NaN 全兜底返回 0.0，不抛异常不出 NaN；地球仪 `GlobeConfig.kt:1-12` 把散落四处的几何半径/LOD/性能红线收口单源；架构层 D24 定内存三档 100/120MB、内置包体 ≤25MB。好在关键路径有明确退化行为和数值上限。

## 三、缺点（分类列证据与影响）

### 3.1 账目不清：同一问题数出不同数字

1. **事故条数自相矛盾**。`docs/事故清单.md` 实测编号 50 条（K20+A11+S7+D7+E5，`grep -oE '\*\*[KASDE]-[0-9]+\*\*' | sort -u | wc -l` = 50），但文末"统计"段写"合计 37 条（K19/A9/S6/D7）"；`规则形成史.md` 自检已指出该漂移但清单未回填。影响：报告引用事故规模时无法确定该信哪个数，门禁㉛若按 37 校验会漏判。
2. **旧栈残留三套计数并存**。贴皮清单：160 非 Ink 页 / 141 Binding / 81 Material；问题清单 H 区：215 layout / 66 menu / 47 Activity / 128 DialogFragment / 69 ViewBinding / 96 appcompat / 19 Material；审计-历史包袱 HEAD 实测：221 layout / 69 menu / 66 Activity / 129 DialogFragment / 72 ViewBinding / 99 appcompat / 21 Material。影响：清理派单无法基于同一底数估算工作量，容易重复清或漏清。
3. **测试数多口径**。源码 `@Test` 计数 3370（`grep -rn '@Test' app/src/test --include=*.kt | wc -l`）；CI 基线断言 3185（`build.yml` BASELINE）；审计 d8cbf06 实测 3030；98ee6d0 台账记 2736。影响：到底"现在有多少条测试"在不同文档里答案不同，新增测试是否"达标"缺乏唯一对照。
4. **在飞计数三源打架**。机制体检 C1：台账记 4、队列记 0、子串扫到 7；虽已用 `queue_stats.py` 做单源，但旧文档与旧门禁注释仍残留旧口径。影响：并发超限时到底派不派单，历史上一度无可信答案。
5. **文档状态页 HEAD 普遍滞后**。`当前状态.md` HEAD 记 `7b1bd1b`、备案三布尔记 `5ac8874`/CI 红/无 APK、接手快照记 `2b65e6d`，而仓库实际 HEAD 已是 `a2e3b84`。影响：新接手者按状态页判断现场会误判 CI 与在飞情况。

### 3.2 规则冲突

6. **"攒批等终态"与"代码槽永不空、先推保槽"互斥**。机制体检列出现行冲突：F-109 要求门禁全绿才攒批 push，而保槽铁律要求未验收也先 push；门禁①在待提交态必红，曾导致"全绿才 push"等价于永不 push（事故 E-04）。影响：推送策略两条规则都对，执行时取决于调度层临场解释。
7. **独立验收占槽与并发硬顶 5 互锁**。E3/E9 满编 5=4 写+1 验，硬顶来自框架实测第 6 个 create_agent 直接报错；但验收单与写码单同槽竞争时，高峰期验收排不进。影响：L1 独立验收容易被写码槽挤掉（自检已记近三轮只有 L0/L2、缺独立验收代理）。
8. **脚本自身违反规则**。`data_scripts/pre-push.sh` 第 1 步仍 `git add -A` 整体提交，与 F-112/E-05"禁 -A、逐路径 add"直接冲突；而 E-05 正是 `git add -A` 裹入在飞代理 welcome 层代码进结单 commit 的事故。影响：守纪律的推送入口自身保留了最容易裹入他人改动的写法，规则在工具层未闭环。
9. **规格旧假设未回写**。切片-03/04/08/12 头部挂⚠️保留 WebView/React/桌面/七色等旧口径，冲突以 `立项-冲突裁决.md`（18 条）为准；如 C-02 设计规格仍写墨卡托，代码 `DemTerrainElevation.kt:13` 已是等经纬度线性归一化。影响：写码代理若只看切片不看裁决，会复活被推翻的旧假设。

### 3.3 文档过载

10. **471 个 docs 文件、447 份 md 形成高认知负担**（`find docs -type f ! -path '*/全项目通读-片段/*' ! -name '项目总结报告.md' | wc -l` = 471）。同一内容三处重复：启动动画/四层框架/沙盘氛围在原文、历史附件、规格切片各存一份；规则在总纲、总账、逻辑链、形成史、全集五处互引。影响：改一个参数要同步多处，新人在 400+ 文档里定位权威口径成本极高；本次通读即需 15 份片段才勉强覆盖。

### 3.4 抽象过度 / 命名混乱

13. **三层契约/卡体系层数多、字段重**。W 卡七项（模块/独占文件域/行数预算/前置卡/锚点/配对 V/状态）、V 卡配对，再加锚点卡、规格登记册、组合验收矩阵、缺陷台账；36 张 W 卡仅 8 张锚点齐备或已交活，28 张挂"缺锚点"，W-036 跨域拆不出独占文件域。影响：流水线主体尚未具备开工条件，抽象先于落地，维护卡本身成为负担。

## 四、失败点：50 条事故的共性根因归类

### 根因 1：派单判据过载，代理"讲过程不讲结论"、空壳退化（10 条：A-01~A-09、A-11）

- 现行防护：门禁㉗子代理存活（零工具/首轮无 ANCHOR-ACK 即 FAIL）、门禁⑭回执证据 E1/E2/E3 三件套、锚点 ACK；存活台账白名单在册；重派上限 2 次，第 3 次调度层自做；A-11 重派把判据压到 3 条、回执限 5 行后一次通过。

- 表现：3 分钟内连推 3 次/连推 6+ 次，把旧 commit 的 run 打成 cancelled，四次红推上云。

- **还防不防得住：基本防住，但有残留**。窗口是防抖兜底，理想时机是上一批终态事件到达时顺手推；`pre-push.sh` 自身仍 `git add -A`（见缺点 8），节拍内若工作区不干净仍可能裹入改动。

### 根因 3：验收缺位，L0 自盘顶替独立验收，未验收先推（含 E-01、D-01、D-02 及自检近三轮缺 L1）

### 根因 7：调度规则未自跑通 / 台账未接线 / 空转停工（S-01、S-02、S-03、S-04、S-06、E-04）

### 根因 8：通配符裹入他人代码（E-05，1 条但性质严重）
- 表现：调度层 `git add -A` 把在飞代理未提交的 welcome 层代码扫进结单 Q-62 commit，单号与改动无法一一回源。
- 现行防护：F-112 台账类 commit 逐路径 add；门禁㊵扫"docs+代码同 commit"。
- **还防不防得住：工具层未闭环**。如缺点 8 所述，`pre-push.sh` 仍用 `git add -A`，规则只在提交约定层、未在推送脚本层强制执行。

### 根因 9：基建/类路径污染（K-05、K-07，2 条）
- 表现：Paparazzi 2.0.0-alpha05 + `includeAndroidResources=true` 触发 htmlunit-core-js `NoClassDefFoundError`，11 个测试类/11 个 JS/Rhino 测试族全红。

- **还防不防得住：未闭环**。G-09 期限 2026-11-27 前择一重接线；当前截图链路在 CI 从未成功出帧，无冻结 golden 帧。

### 根因 10：外部不可控与并发碰撞（S-05、S-07，2 条）
- 表现：多代理并发 commit 撞 `.git/index.lock`；GitHub 远端 500 拒绝 push。
- 现行防护：F-102 锁冲突 sleep 重试、禁删锁；push 500 不重写历史、不 force，指数退避重试 3 次。
- **还防不防得住：基本防住**，属外部抖动，重试即可恢复。
