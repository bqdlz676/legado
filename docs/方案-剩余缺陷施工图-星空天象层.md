### 1.1 现状原文（逐字贴出，带 文件:行；未转述）

```kotlin
class OfflineFallback(private val cache: TextureCache = TextureCache()) {

    /** 当前网络是否在线；由 Android 网络观察层写入，纯逻辑层不感知实现。 */
    var online: Boolean = true

    val textureCache: TextureCache get() = cache

    /** 单个素材的解析结果。 */
    data class Resolution(
        val kind: TextureKind,
        val status: AssetStatus,
        val fallback: FallbackKind,
    ) {
        /** 渲染层是否应走程序化 / 种子兜底。 */
        val useFallback: Boolean get() = !status.hasRealTexture
    }

    /**
     * 解析某类素材的就位状态。任何分支都返回非空 Resolution：
     * - 缓存命中 → 真实纹理；
     * - 在线未缓存 → 先 PENDING_DOWNLOAD，渲染用兜底，下载完成后回填缓存；
     * - 离线未缓存 → READY_FALLBACK，直接走降级源。
     */
    fun resolve(kind: TextureKind): Resolution {
        val cached = cache.status(kind)
        if (cached != null && cached.hasRealTexture) {
            return Resolution(kind, cached, kind.fallback)
        }
        val status = if (online) AssetStatus.PENDING_DOWNLOAD else AssetStatus.READY_FALLBACK
        return Resolution(kind, status, kind.fallback)
    }

    /** 全量素材解析（场景装配 / 自检用）。 */
    fun resolveAll(): List<Resolution> = TextureKind.entries.map { resolve(it) }

    /** 整体退化档位。 */
    fun degradation(): DegradationLevel {
        val resolutions = resolveAll()
        val realCount = resolutions.count { it.status.hasRealTexture }
        return when {
            realCount == resolutions.size -> DegradationLevel.FULL_TEXTURES
            realCount > 0 -> DegradationLevel.CACHED_MIX
            else -> DegradationLevel.PROCEDURAL_ONLY
        }
    }

    /** 真实纹理种类数（性能 / 自检报告用）。 */
    fun realTextureCount(): Int = resolveAll().count { it.status.hasRealTexture }

    /** 兜底种类数。 */
    fun fallbackCount(): Int = resolveAll().count { it.useFallback }
}
```

### 1.3 边界行为（失败 / 极端情形各自返回什么）

1. **州域命中式同类情形：星空域全缺、地球域全缓存** → `degradation(EARTH)=FULL_TEXTURES`，`degradation(SKY)=PROCEDURAL_ONLY`；地球不被星空缺档拉进 `CACHED_MIX/PROCEDURAL_ONLY`（旧 bug 本体，`docs/星空天象层-实施规格-合并定稿.md:304` 明示易漏点）。
2. **离线档位计算拿不到地球 / 星空权重**：`OfflineFallback` 不接收外部权重入参，档位只由 `TextureCache` 内 `AssetStatus` 派生；缓存槽位缺某种类记录 → `status(null)` 分支按 `online` 落 `PENDING_DOWNLOAD/READY_FALLBACK`（`OfflineFallback.kt:37-44` 既有口径不变）。域内种类列表由枚举静态标注，不存在「拿不到权重」的运行时分支；若枚举漏标 domain（编译期构造缺参），Kotlin 构造即报错，不靠运行时兜。
3. **某域种类集为空**（未来裁剪枚举导致）→ `degradation(domain)` 返回 `PROCEDURAL_ONLY`（宁可降层出兜底，不返回 `FULL_TEXTURES` 空真）；该口径由单测固定，见 1.4 用例 4。
4. **在线未缓存**：域内单种类 `PENDING_DOWNLOAD` 不计真实纹理；域内全部 PENDING → 该域 `PROCEDURAL_ONLY`（先画兜底，下载回填后下帧升档），与既有 `resolve` 语义一致。
5. **异说 / 缺失分野条目**与本缺陷无关，不串入离线域判定。

### 2.3 边界行为（失败 / 极端情形各自返回什么）

1. **州域命中但分野表无对应条目**：`focusRegion` 返回空列表；`fieldLayer.selectedRegion` 不被写入（不清空旧值）；`asterismLayer.select` 不调用；门面不转向。地球侧不画空脉冲环（规避 `docs/验收-星空天象层.md:227` 记的「成员星为空时脉冲环落屏心」风险）。
2. **分野表残缺 / 锚点表为空**：`RegionHitResolver(emptyList()).resolve(...)` 恒返回 null；`focusRegion` 对空表返回空列表；整条反向链静默不动作，不抛异常、不崩。
3. **点在所有锚点半径外**（海洋、域外、对跖点）：`resolve` 返回 null；地球 tap 不产生任何星空写回。
4. **未入星空时触发反向聚焦**：`focusFieldRegion` 先 `enterSky(SKY_HEAVEN)` 走既有 800ms spring（`GlobeController.kt:160-168`）；`target=null` 时只切视角不改姿态；已在星空时不重复 `enterSky`（`enterSky` 内部同态早退，`:162`）。
5. **同名 / 多宿同域消歧**：一州多宿（雍州=井 `jing`+鬼 `gui`；扬州=牛 `niu`+女 `nv`）codes 全量返回；高亮取 `codes.firstOrNull()`，成员凸包由 `memberIdsForRegion` flatMap 并集（`FieldAllocationLayer.kt:74-75` 既有口径）；异说（`isVariant=true`）不参与反查。
6. **重复点按同一州域**：`focusRegion` 重起脉冲时刻；`asterismLayer.select` 幂等；不叠加第二路过场。

## 4. 二阶三阶影响

### 4.1 D43 分域算档

- **一阶**：地球 / 星空各自三档算档，星空瓦片缺失不再把地球纹理误判成程序化档（规格 §十三.8 易漏点闭合）。
- **二阶**：
  - `SkyCanvasRenderer.lowPower` 改读 `skyDegradation`：地球离线兜底不再压低星空 `magLimit` 与银河 / 尘粒 / 流星开关（既有 `:66` `min(magLimit, MAG_BRIGHT_ENTITY)` 口径改由空域档位驱动）。
  - `loadingProgress` PENDING 扫描限 SKY 种类：地球纹理待下载不再顶星空顶部金线进度条。
  - 三条既有测试类断言从「混合档位」口径迁到「分域档位」；`fallbackSummary` 全量 real/total 计数保留作自检报告，不拆成两份文案。
- **三阶**：
  - 未来新增 `TextureKind` 必须标 `domain`，否则完备性测试（1.4 用例 4）红；这是把分域约束机检化，不靠 reviewer 记忆。
  - **双轨确认**：`SKY_DENSITY_L9` / `SKY_DENSITY_L11` 仍是 `SKY` 域内两个独立种类，分域不合并它们；与 `STAR_SKY` 三项并存，回退 `FallbackKind.PROCEDURAL_STAR_FIELD` 不变。
  - 对用户行为：地球仪态离线时横幅文案只反映地球域；星空低配提示由空域档位独立决定，两态不再互相掩盖。
- **反向自检（假设本方案错了）**：若分域后地球域档位在「星空为背景、地球悬中央」的天外视角下失去参考意义——反例成立一半：天外视角地球已缩成 40px 锚，地球域档位确实只影响地球仪态 pass；但快照装配与横幅仍是地球仪态语义，分域后语义更清晰，不构成回退理由。未找到的反例：若未来出现「地球纹理与星空纹理共用同一缓存槽句柄」的资源复用，分域计数会重复计入——当前 `TextureCache` 按 kind 分槽（`TextureCache.kt:21`），无此耦合，列为后续观察项。

### 4.2 D39 反查会不会把地球命中逻辑耦合进星空层

- **一阶**：地球点按经纬度 → 州域名 → 反查 codes → 进天外视角 + 高亮星官。
- **二阶**：
  - 耦合方向控制：`RegionHitResolver` 输入 `lat/lng` 标量、输出州域名字符串，放在 `astro/pick/` 但不引用星空渲染类型；`FieldAllocationLayer` 只认 code / region 字符串，不持有地球几何。地球命中逻辑**不反向侵入** `astro/layer`。
  - `asterismLayer.select(code)` 被反向接通；与 N1 正向链共享同一选中口，但正向下游 starId→code 反查仍缺，两条链不同时闭合。
  - `FieldGlowOverlay` 地球侧脉冲复用既有 `fieldRegion()` 桥接，不新增 overlay 组件。
- **三阶**：
  - 若后续把 resolver 锚点表换成真实州界多边形，命中算法从最近邻升级为多边形包含，接口签名（`resolve(lat,lng): String?`）不变，调用方无感。
  - 维护成本：分野词表两份消费（正向 `regionForAsterism`、反向 `asterismCodesForRegion/regionForCodes`）同出 `entries` 单一事实源，不建第二张映射表。
- **反向自检**：最强反例是「州域命中本应走地球渲染层的区域拾取，而不是纯 JVM 最近邻」。当前仓内无州界多边形数据（§十一.4 tier3 示意），地球渲染层也无区域命中入口；一期用锚点最近邻是数据现实下的迂回方案，接口预留升级位。若验收要求真实多边形命中，须另立数据缺陷，不在本单凑。

## 5. 反例边界（穷举）

1. **同名州域消歧**：一州多宿（雍州=井+鬼）、异说并存（`isVariant=true`）。口径：主表反查剔除异说；多宿 codes 全量返回、高亮取首个、成员凸包并集；州域名重复出现于多行时不合并仲裁（§十一.5）。
2. **分野表残缺**：CSV 缺列 / 空行 / 解析异常（`StarStoreProvider.kt:58-82` 既有回落空列表口径）→ layer 空表，反向反查恒空列表，resolver 锚点表独立于 CSV，仍可命中州域但无 codes 可高亮，链路静默不崩。
3. **锚点半径外 / 对跖点 / 海洋**：`resolve` 返回 null，不触发转向；不凭空造最近州域。
4. **拆分后行数反弹**：新文件超 400 行继续内拆私有子组件；宿主基线 604 不许上调；禁止以删战役控制台 / 图例功能换行数。
5. **离线域权重缺失**：缓存槽位无记录走既有 `online` 分支；分域枚举标注是编译期约束，无运行时「权重拿不到」分支。
6. **并发 / 重入**：反向聚焦重复点按幂等；`enterSky` 同态早退；弹簧打断续接沿用既有 `poseValue/poseVel` 口径（`GlobeController.kt:163-166`）。
7. **数据占位态**：`StarStore.isPlaceholder` 时空表不进 layer；反向链在占位态下 `focusRegion` 返空，不抛 NPE。
