# 铁律 · 组合验收金字塔（模块的组合验收，非测试分层）

> 口径来源：用户 2026-11-25 原话「金子塔结构的验收机制你再去找找，是模块的组合验收」（`docs/派单队列.md` Q-17 行）；口径冻结 F-92。
> **口径更正**：本金字塔**不是**"单元 / 集成 / E2E"的测试分层金字塔，而是**模块的组合验收**——从单个模块自检，逐级向上验模块之间的咬合，直到整机全链路。
> 为什么要单独立铁律：单模块自测全绿，不等于拼在一起能用；历史返工多发生在"接口参数对不上、单位/坐标系不一致、空值未兜、时序错位"这类咬合面上。组合验收把咬合面变成强制入册的关键对，逐层往上验，不许拿单模块结论冒充组装结论。
> 适用条件：所有有对外接口的模块（数据域 / 阅读域 / 地图域 / 音频域 / 导航域 / 专题域）；纯静态工具函数无跨模块输入输出的，只走层 0。

## 1. 五层定义（层 0 → 层 4，逐级聚合，禁跳级）

| 层 | 名称 | 验什么 | 通过判据 | 证据形态 |
|---|---|---|---|---|
| 层 0 | 模块单项自检 | 模块自身：内部逻辑、边界空值、单测/bench、观感六要素 | 模块内单测绿 + bench 指标写死跑过 + 观感项在册 | 模块 commit / 单测 run / bench 输出 |
| 层 1 | 两两契约 | 两个模块之间的咬合面：接口参数、单位、坐标系、空值、时序 | 关键对双方签名/单位/坐标系/空值兜底/调用时序逐条对齐，无未归因差异 | 矩阵关键对行 + 契约锚点 `文件:行` |
| 层 2 | 业务链路三件 | 一条真实业务串起 3 个以上模块：① 打开书→分章→排版→翻页；② 地图→地形→图层→交互；③ 点字→解析→消歧→跳转；④ 发现页→专题卡→Canvas/地球 | 链路每一跳输入输出接得上，断跳有归因 | 链路矩阵行 + 链路证据（CI run / 截图 / 单测） |
| 层 3 | 域内全组合 | 同一域内模块两两与成组组合（阅读域 / 数据域 / 地图域 / 音频域 / 导航域） | 域内关键对 100% 在册且状态明确；域内组装编译 + 单测过 | 域矩阵行 + 组装单元 CI 记录 |
| 层 4 | 整机全链路 | 冷启动→使用→退出，含崩溃恢复；跨域串联 | 整机链路走通，崩溃有恢复路径；沙箱无 Android 运行时的部分走外部门（真机 / CI 真值） | 整机矩阵行 + 外部真值锚点 |

> 为什么是五级而不是三级：层 1 只验一对咬合，层 2 验一条业务串，层 3 验一个域内全部组合，层 4 验整机——层级不同，证据不可互相借用（铁律 82：低级别不得当验收；索引 §3.5 五级门禁 L0~L4 同口径）。

## 2. 五条硬判据（F-92 正文，门禁 ㉑ 机械判）

- **R1 组合矩阵强制入册**：谁和谁组合、期望结果、契约维度、由谁验、何时验，必须写进 `docs/组合验收矩阵.md`；矩阵外的组合不算验收过。
  > 为什么：咬合面靠记忆必然漏；入册后门禁能机械数关键对覆盖率，不靠人翻。
- **R2 关键对 100% 覆盖，不允许抽样过**：层 1 关键对清单内每一对都必须有矩阵行；缺一行即 FAIL，不许"先抽几对验、其余以后补"当通过。
  > 为什么：抽样过 = 未验的咬合面裸奔；历史 CI 连红多为漏掉的那一对签名错配。
- **R3 缺陷必须落层归因**：每条缺陷/未决项登记 `docs/台账-验收分层.md`，写明落哪一层（层 0~层 4）、状态、验收代理、产物路径；未写层别的缺陷视为未归因，FAIL。
  > 为什么：不归层就不知道退回哪一级重验；混在"待优化"里的缺陷会长期无人收口。
- **R4 禁跳级**：低一层未过，不许拿高一层结论放行；反过来高层发现咬合问题，必须回写到对应层 1 关键对，不许只在高层打补丁。
  > 为什么：跳级验收会把根因留在低层，高层越补越乱；回写关键对才能让缺陷在咬合面上收口。
- **R5 门禁机械判，只许 FAIL 不许 WARN**：矩阵缺失 / 关键对未覆盖 / 有未归因缺陷 → 门禁 ㉑ FAIL；本项不设 WARN 档。"待验""未落地"是矩阵内的明确状态，必须带验收代理与期限/锚点，不是门禁放行的借口。
  > 为什么：WARN 久了会被当成 PASS；未覆盖就是未覆盖，状态要透明在册，门禁要硬。

## 3. 状态词表（矩阵与台账只准用这几组，禁自造）

- `已验-PASS`：该对/链路有可回查证据（CI run / commit sha / 产物路径），当前无未归因缺陷。
- `已验-有缺陷`：验过但挂着缺陷；缺陷必须在台账有 DEF 行并落层。
- `待验`：模块已落地、组合尚未验；必须填验收代理（或"待派独立验收代理"）与期限锚点。
- `未落地`：对端模块尚在立项、代码未进 `app/src/main/java`；组合不具备验收条件，矩阵仍须在册跟踪，不得空表。

> 为什么固定词表：门禁按词表机械判；自造同义词（"基本通过""待优化""差不多"）会让状态不可解析，视同未归因。

## 4. 失配症状（出现即按对应层归因，对号入座）

| 症状 | 首归层 | 典型表现 |
|---|---|---|
| 模块内部空指针 / 单测挂 / bench 不达标 | 层 0 | 模块自己跑就错，与他模块无关 |
| 参数个数/类型/命名对不上、单位错位（px/dp、米/世界单位）、坐标系错位（经纬度/栅格/世界坐标）、空值未兜、调用时序颠倒 | 层 1 | 单模块都对，拼一起崩或显示错 |
| 链路中途断跳、上一跳产物下一跳读不到、跳转意图落空 | 层 2 | 单对都通，串起来走不通 |
| 域内某组合未验即放行、域内组装编译红 | 层 3 | 链路能走，域内其他组合出问题 |
| 冷启动崩、退出泄漏、崩溃后无法恢复、跨域串联丢状态 | 层 4 | 域内都通，整机起不来或恢复不了 |

## 5. 归因格式（台账逐行照此写）

`DEF-xx | 标题 | 落层(层0~层4) | 涉及模块(矩阵 ID) | 状态(已验-有缺陷/待验/未落地/已修) | 验收代理 id（或"待派独立验收代理"）| 产物路径 / 证据锚点(文件:行 或 run id / commit sha) | 退回层级与下一步`

> 为什么：七列缺一不可；验收代理缺位时必须显式写"待派"，不许留空——留空就是 R3 未归因。

## 6. 豁免条件

- **纯静态工具函数**（无跨模块输入输出）豁免层 1 及以上，只走层 0；豁免须在矩阵备注写明"无跨模块接口"。
- **未落地模块**（立项 🔴，目录尚未进 `app/src/main/java`）相关关键对状态记 `未落地`，不要求层 1 证据；但行必须在册，模块落地后首轮验收即补验。
- **外部门**：真值在 GitHub CI 或用户真机（如 L4 崩溃恢复、导出让真机看），本地静态结论不得冒充外部真值；改取外部真值比对，锚点记 run id / 真机回执（F-89 §4 特殊通道）。
- **历史留档**：一次性复盘/旧验收报告标"不进任何新判定"，门禁只校验本次新增/改动的矩阵与台账行（同 ⑭/⑮ 边界口径）。

## 7. 与既有机制的分工（不重叠、不双轨）

- 与铁律 #46 分层组装验收（索引 §3.5）：#46 管"每 10 模块聚合一次组装编译"的物理分组；本金字塔管"模块组合验收的层级与咬合面关键对"。组装单元是层 3/层 4 的验收载体，关键对是层 1 的登记颗粒。
- 与 F-89 三件套：本机制三件齐备——总账＝`docs/组合验收矩阵.md` + `docs/台账-验收分层.md`；门禁＝㉑ `data_scripts/check-combo-coverage.py`；溯源＝矩阵行锚点 `文件:行` / run id / commit sha。
- 与 F-73 三段流水线：本金字塔管"实现后怎么组合验收"，不管"无规格怎么造规格"；新功能仍先走三段流水线到层 0，再进本金字塔层 1 往上。
