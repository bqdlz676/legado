## 二、判据 2：双轨排除 —— 人物 / 地名 / 典故不在名物槽二次出气泡 —— PASS

### 2.1 排除机制是清单级结构性短路，不是「查不到自然重叠」

- 登记表把三类标为 `EXISTING_SLOT`（`ArtifactSlots.kt:60` PERSON→`person` 槽、`:68` PLACE→`place` 槽、`:180` ALLUSION→`allusion` 槽），其 `schemaType = null`（:62 / :70 / :182）。
- 适配层查询清单由 `entitySlots` 过滤产出（`ArtifactSlots.kt:200`），`ArtifactBubbleProvider.kt:38` 只遍历这 14 类；循环体内 :40 传给 `entity.query` 的 `slot.schemaType` 只可能是 14 个实体 type，三类既有槽根本不进入 `entity.query` 调用。
- 关键区别（对照判据要求）：双轨排除不依赖 `EntityProvider` 对人名 / 地名「查不到返回兜底壳」；即便后续真实数据表把 person / place 表接入通用入口，适配层的遍历清单里也没有这三类，不会二次出泡。短路证据行号：`ArtifactSlots.kt:200`（清单过滤）、`ArtifactBubbleProvider.kt:38-41`（仅遍历 entitySlots 并逐类调 query）。

### 2.2 测试断言回证

- `ArtifactSlotsTest.kt:70-75`：实体链 wire 集合不含「人物 / 地名 / 典故」。
- `ArtifactBubbleProviderTest.kt:203-215`（`人物地名典故类别不在实体查询类型清单`）：桩件记录全部入参 type，断言每条都落在 `entitySlots` 允许集合内，且不含 `person` / `place` / `allusion`；调用次数 = 14 类 × 3 词 = 42 次（:214 `assertEquals(ArtifactSlots.entitySlots.size * 3, recorded.size)`）。

## 三、判据 3：链序推演 —— artifact 在地名之后、多字词之前；first-hit-wins，无两泡并存 —— PASS（附条件观察项 O1）

### 3.1 两条链的实际顺序（代码证据）

段落命中链 `BubbleResolver.kt:98-108` `dispatch`：

105  safe { word.matchWord(...) }        ?.let { return it }

```

整词链 `BubbleResolver.kt:79-89` `queryToken`：

```
82  ?: safe { date.query(clean, anchor) }
83  ?: safe { allusion.query(clean, anchor) }
84  ?: safe { person.query(clean, anchor) }
85  ?: safe { place.query(clean, anchor) }

87  ?: safe { word.query(clean, anchor) }

```

两链同序：date → allusion → person → place → **artifact** → word → char。测试 `ArtifactBubbleProviderTest.kt:110-127` 用桩件记录调用顺序，断言恰为 `listOf("date", "allusion", "person", "place", "artifact", "word", "char")`（:124）。

### 3.2 同一段落同时命中 artifact 与 word 的推演

- 机制：`dispatch` 命中即 `return`（:100-106 的 `?.let { return it }`），`queryToken` 为 `?:` 短路链（:82-88）；均为 first-hit-wins。一次点击只产出一张气泡，artifact 与 word 不会两泡并存。
- 实际结果分两种情形：
  1. 当前空数据实现：`ArtifactBubbleProvider.query` 对任何名物名都拿到 `source=未命中` 兜底壳并判未命中（:45 `if (result.source == MISSING_SOURCE) continue`），最终 :48 返回 null；artifact 槽不出泡，落到 word 槽，与装配前行为一致。
  2. 真实数据表落地后：若某词同时被名物 Provider 与词表命中，artifact 位次在 word 之前，**名物气泡胜出，word 气泡被抑制**——不会双出，但存在普通多字词被名物槽抢占的方向性风险。
- 前端点击链路单泡口径回证：`app/src/main/java/io/legado/app/ui/book/read/ink/InkReadController.kt:225-229`，`BubbleResolver.resolve(...)` 结果赋给单一 `bubbleContent` 字段，无批量并出；`:279` 候选切换走 `queryToken` 单回包。

### 3.3 与 B18 / B25 气泡数量口径对照

- 全仓 main 侧未发现「一段最多几个气泡」的数量上限常量：

```

- 段落级批量气泡（全页地名 / 名物列表）的数量上限与排版容量属 `ui/**` 域，自述 §5.3 / §九-4 已登记另单，本单未核未改，不构成本单超量风险。

### 3.4 条件与观察项

- 条件（O1）：真实名物 Provider 接入时必须守「查不到返回 null / 兜底壳不冒充真实命中」口径，且匹配精度不得宽到把普通词表词条截胡；否则 artifact 前置位次会抢占 word 槽气泡。该风险在数据组装单落地时以 `BubbleBenchmarkTest` 同口径复测（冷启 ≤300ms / 热路径 ≤80ms）并补「artifact 命中抑制 word」方向的断言。
