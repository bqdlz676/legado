## 5. 反例与边界

### 5.1 三类必兜边界（任务书点名）

| 边界 | 现象 | 本实现兜底 |
|---|---|---|
| URL 是相对路径 | `<img src="../img/a.png">`，词条规则 `urlRule` 为远程地址 | 解析期 `NetworkUtils.getAbsoluteURL(activeRule.urlRule, src)` 收口；base 为空 / 非法 URL 时工具函数原样返回相对串（`NetworkUtils.kt:161-190`），透传给 Glide；仍失败则进失败块展示原文 URL + `AppLog` 落档，不崩、不留空白 |
| 图超大 | 原图分辨率远超半屏宽度，整图解码有 OOM 风险 | 列表图 `RequestOptions().override(availableWidthPx)` 把解码宽度下压到条目可用宽度；大图查看器 `override(屏幕宽)`；高度按原生宽高比等比缩放，超宽在半屏内横滑、超高走半屏竖滑；位图 `copy(config, true)` 脱离 Glide 位图池 |
| 无网 / 断网 | 请求超时或失败 | `onLoadFailed` → `failed = true`，渲染「图片未能载入」+ 原文 URL；`AppLog.put` 记录；不弹异常、不白屏；词条文本释义照常显示 |

### 5.2 其它反例与极端参数（自查补充）

- `width` 非法值（非数字、非百分比）：回退原生宽度；百分比缺省按 80% 收口（同 `GlideImageGetter.kt:119`）。
- `src` 缺失 / 空串：该 token 不生成图片块，按文本段处理，不渲染空骨架。
- `data:` 内联图（base64 / data-uri SVG）：`data:` 原样透传给 Glide；注意 `as(Bitmap)` 链对 SVG 的解码
  依赖 Glide SVG 插件注册情况，未覆盖时进失败块（旧链 `SvgUtils` 的 data-uri SVG 分支本次未迁移，见 §6 交接）。
- GIF：`loadBitmap` 取静态首帧，不播放动图（旧链 `GlideImageGetter` 支持 `GifDrawable` 动画，本次未迁移）。
- Markdown 图片 URL 含括号 / 空格：当前正则 `[^)\s]+` 不匹配，会退化为文本段；词典规则少见该写法。
- `<img>` 属性值内含 `>` 或转义引号：正则截断可能偏差；属罕见畸形 HTML，失败时进失败块兜底。
- 切换词典标签：`remember(block.src)` / `DisposableEffect(block.src)` 按图地址重建加载；
  切换规则时 `viewerSrc` 不自动清空，关闭半屏即复位。
- 解析期异常（GSON 选项串损坏）：`fromJsonObject(...).getOrNull()` 取 null，按无选项处理，不抛到 UI。

### 5.3 站在最强反对者角度的复核

- 反对意见：「直接复用旧 `GlideImageGetter` 包进 Compose 不更省？」——它产出的是 `Drawable` + `TextView`
  回调，依赖 `WeakReference<TextView>` 与 `invalidateDrawable`，硬绑旧 View 体系；塞进 Compose 等于
  变相 `AndroidView` 贴皮，违反本单红线。故只对齐其宽度 / 百分比口径，不复用其 Drawable 载体。
- 反对意见：「解析为什么不用 Jsoup？」Jsoup 虽已是既有依赖，但 `<md>` 包裹的 Markdown 图片不是 HTML 节点；
  单条正则双匹配 + 属性收口更轻量，且不改变原文文本段内容；代价是畸形 HTML 覆盖度低于完整 DOM 解析（见 5.2）。
- 反对意见：「大图为什么不做手势缩放（双指 / 拖动）？」任务书只要求「查看大图」，统一半屏槽自带竖滑、
  本层补横滑；双指缩放属新交互，未在本单范围，记入交接。

## 6. 认知成本

- 新增概念 4 个，均在 `ui/dict/DictRichContent.kt` 单文件内聚：
  `DictRichBlock`（块模型）、`DictRichParser`（切块器）、`DictRichImage`（列表图状态机）、`DictImageViewer`（大图槽）。
  接手者先读密封接口定义（`:59-80`）即可理解数据流，无需翻 Glide 旧链。
- 命名：`Image` 块字段 `widthAttr / align / click / alt` 与旧 HTML 属性 / 选项键同名，便于从旧链对照；
  未新造抽象层（无中间 ViewModel、无 mapper 接口），解析结果直接喂 Compose。
- 保留的既有概念：`ImageLoader.loadBitmap`、`InkHalfSheet`、`ComponentTokens`、`AppLog` 全部复用既有口径，
  不另立颜色 / 尺寸 / 日志约定。
- 可能的理解负担：宽度百分比与 `override` 下压两处都涉及 px/dp 换算，代码内注释标明了对齐出处
  （`GlideImageGetter.getDrawableRect`）；后续若调骨架高度 / 保底百分比，集中在 `DictRichImage` 一处。

## 8. 交接（发现但未改的跨模块问题）

1. **Markdown / HTML 其余富文本仍为纯文本**：表格、加粗、斜体、超链接、`<br>` 换行等在当前 Compose 正文区
   仍按原始字符串透传（本单只补图片）。若属 C2 工具页重写缺口，建议另立单子评估 Markwon 等价 Compose 渲染或
   轻量行内样式解析；落点同样在 `ui/dict/**`。
2. **data-uri SVG 分支未迁移**：旧链 `GlideImageGetter.kt:78-82` 用 `SvgUtils.createDrawable` 解码内联 SVG；
   本 Bitmap 链未复用，SVG 可能进失败块。建议后续在 `DictRichImage` 加载前补 SVG 解码适配（`help/SvgUtils` 可复用）。
3. **GIF 动画未迁移**：本链只取首帧；如需动图，需另走 `CustomTarget<Drawable>` + `GifDrawable` 播放管理。
4. **大图双指缩放**未实现；如阅读期图片查看有缩放诉求，建议在 `InkHalfSheet` 内容槽层面做统一缩放手势，
   不要在词典单文件另造。
5. 解析正则对畸形 HTML / 含括号 URL 的覆盖度有限（见 5.2）；若后续规则源出现此类写法，再评估换 Jsoup DOM 切块。
