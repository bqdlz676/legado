### 锁三 · `attach` 重开分支的作用域保留 + resume 恢复（本单未补行为锁：阻塞原因 + 可观测量 / 解阻规格）

- 生产位置 `InkSearchViewModel.kt:67-75`：`hotBinder == null` 时 `observeHistory()` 重建收集；`searchModel?.resume()`；`initialScope` 非空白才 `searchScope.update(...)`，`null` / 空白保留上次作用域。
- 仍未锁住的部分：重开必调 resume；空白 / null 新作用域不得覆盖旧作用域；binder 已存在时不重复重建收集。
- 不可纯 JVM 测的原因同锁二（AndroidViewModel 构造、`appDb` Room 懒构建、`private` 字段无注入缝、仓内无 ViewModel 测试先例）。
- 解阻后的锁定规格：
  - 构造输入：是否已初始化、binder 是否为空、新作用域（`null` / 空白 / 非空串）、旧作用域串；model 桩、scope 桩。
  - 调用入口：协作器 `reopen(binder, model, newScope, currentScope)`。
  - 断言对象：binder 为空 → 重建记录一次；binder 非空 → 不重建；`model.resume` 必调一次；新作用域非空 → `scope.update` 被调用且入参为新串；`null` / 空白 → 不调 update、旧作用域原样保留。

## 二、去掉 `delay(200)`（验收 N4）

- 改前（`SearchHotBinderTest.kt`，改动前快照）：`:5` `import kotlinx.coroutines.delay`；`:203` 注释「留出余量：若收集协程未被取消，Unconfined 会同步回放空快照回填状态。」；`:204` `delay(200)`；冻结断言在 `:205`。
- 改后：`delay` import 已删除；`:197-206` 关闭 binder 后直接发两路空快照，`:206` 同步 `assertEquals("关闭后流更新不得再回填 UI 状态", closedSnapshot, state.value)`；正向收敛路径仍统一 `withTimeout(5_000) { state.first { 谓词 } }`（如 `:194`、`:218`）。
- 确定性依据：测试注入 `Dispatchers.Unconfined`，收集协程在调用线程内联执行；`close()` 取消句柄后，若 Job 未被取消，流重发会在 setter 线程同步回放空快照并回填状态，下面的相等断言立即变红；若已取消，状态冻结为关闭前快照，无需任何等待余量。
- 范式对齐：符合 `docs/断言范式.md` 硬约束「禁用 `Thread.sleep` 等时序等待，统一 `withTimeout(5_000)` + 流式 `first`」；冻结类断言走同步状态相等，不使用负向等待窗口。
