## 2. 两条路线估算与选型

### 2.1 路线 A：构建期/入库前切片，两级金字塔随包进 `assets/astro/`

**体积估算（可复算，实数基准来自现有 L0 表）**

- 实测全字段（13 列）行均字节：635,052 数据字节 / 8,920 行 = **71.19 B/行**。
- 实测金字塔瘦表（`id,raDeg,decDeg,magVt,colorBv,constellation` 6 列）行均字节：
  376,156 数据字节 / 8,920 行 = **42.17 B/行**（用真实 L0 行投影，非拍脑袋）。
- Tycho-2 全表 2,539,913 行（规格 §二.5 / §四.118）。全量瘦表上界 =
  2,539,913 × 42.17 B ≈ 107.11 MB = **102.15 MiB**；全字段上界 ≈ 180.82 MB = **172.44 MiB**。
- 对照红线：规格 §四.138「金字塔按需 <60MB 可删可重建」；总纲 P-04「APK 内置 ≤25MB 硬上限」。
  路线 A 即使只带瘦表，上界 102.15 MiB 同时顶破 60MB 按需预算与 25MB 内置红线。

**首帧耗时**：L1+L2 随包则冷启动必须读两级切片（上百 MB 级 IO），与 §十二.2「一帧 700 颗
零分配、防 GC 抖动」的口径冲突；实测真机帧耗本单未验证（§3.3）。

**合规冲突（硬门禁，不是偏好）**

- `docs/构建说明-派生素材不入库.md` 规则一：mag > 6.5 金字塔切片、原始行星表**不进 APK
  `assets/`、不进 CI artifact、不入 git**；规则二：APK 内置只允许 mag ≤ 6.5 层。
- 规格 §四.3（:120）：「NC 数据随构建产物分发会把"非商用"粘到 APK 上」；§三.10（:95）：
  「`assets/astro/**`——内置矢量与分野表；Tycho 金字塔不入库」。
- 台账 S-01 入库范围：「mag > 6.5 金字塔层级与原始行星表走按需下载链路，不入库」。

**离线可执行性**：沙箱实测 CDS 不可达（`cdsarc.cds.unistra.fr` http_code=000）；
HYG v44 LFS 对象 404（代理回 404，11 字节）；仓库与 `data_scripts/_cache/` 内无更深星表落盘。
路线 A 在本环境无法用真实观测数据切表；补造 RA/Dec/mag 属假数据，按 B1 与子代理禁令不许做。

### 2.2 路线 B：按需下载 → 设备本地缓存 → 缺网降级（三段式）

**分段职责**

1. **下载段**：首启许可确认页之后可选下载（规格 §四.3、§七.4 加载态）；复用既有
   `AssetStatus / TextureCache / DegradationLevel` 体系，**不新建下载器**（§十二.8）。
   源 = 台账 S-01（CDS I/259，署名串逐字：`Source: ESA Hipparcos mission; Tycho-2 Catalogue
   (Høg et al. 2000), CDS I/259`）。
2. **缓存段**：切片落设备 `filesDir/astro/pyramid/`，逐片带 sha256 旁证；可删可重建（§四.138）。
3. **降级段**：缺文件 / 校验失败 / 低内存一律回落 L0 内置亮星层；缺失天区由低层密度底图覆盖，
   不出空白洞（§七.4、§十三.2）；L0 自身才缺失时才走 `StarField` 种子 9173 程序化兜底（§七.6）。

**体积与首帧估算**

- APK 增量：**0 字节**（不带任何 mag > 6.5 行；本单入库的只有脚本与 JSON 契约，无星表行）。
- 设备缓存上界：60 MiB（62,914,560 字节，规格 §四.138），用户可清。
- 冷启动 IO：不读缓存目录，只读既有 `astro/stars.csv`（635,151 B，既有路径未变）；
  暗星切片在双指捏合进局部星图时懒加载，不占首帧。

**离线可验证部分（本单已在沙箱跑通）**：层级契约、L0 真数据逐行校验、构建器离线退出码、
校验器好/坏双样本自测（§3.2）。运行时下载与合并属下一单 + 真机/CI 验证范围。

### 2.3 选型：路线 B；否决路线 A 的四条理由

1. **门禁硬冲突**：构建说明规则一/二、规格 §三.10/§四.3、台账 S-01 四处一致禁止 mag > 6.5
   切片入库；路线 A 一落地即违反出包门禁。
2. **NC 分发口径**：Tycho-2 为 CC-BY-NC-3.0 IGO；派生素材随 APK 分发等于把非商用约束
   粘到安装包上，商业化换源成本不可控（§十三.6 同源同换）。
3. **沙箱无源、不可真做**：实测 CDS 000、HYG LFS 404、本地无更深落盘；路线 A 在此环境
   只能交占位/造假，被 B1 与「不许造假数据」禁令禁止。
4. **包体红线**：瘦表全量上界 102.15 MiB > 60MB 按需预算、> 25MB 内置上限；即使合规允许，
   体积也不成立。

> 反向自检（§20）：路线 B 最强反对意见是「离线用户永远看不到 9–11.5 等暗星，拍板的
> 11.5 深度项对他不成立」。否证后是否成立：成立但有兜底——离线/未下载时 L0 亮星 + 线框
> 全在，画面不空白不崩（§七.6/§十三.2）；深度层在联网后按需补齐，与 A7「核心小数据内置、
> 大数据按需下载 + 预缓存 + 断网兜底」一致。该反对意见改变的是「首启可见深度」，不改变
> 路线选择；真正要防的是缓存段设计成必须联网才能亮星，施工图 §4.3 已把降级写成硬分支。

## 4. 施工图（下一单写码代理照此接线）

### 4.1 签名与返回类型

替换 `StarCatalog.kt:72-74` 现有 `fun loadPyramid(level: Int)`（Unit 空实现）为：

```kotlin
sealed interface PyramidResult {
    /** 成功合并：[level] 级新增 [added] 颗。 */
    data class Loaded(val level: Int, val added: Int) : PyramidResult
    /** 缓存缺文件 / 未下载 / level 越界：保留当前层，不抛异常。 */
    object Missing : PyramidResult
    /** 校验和不符 / 零有效行 / 解析损坏：隔离坏片，回落内置层。 */
    object Corrupt : PyramidResult
    /** 合并前内存评估不足：拒绝合并，保持当前已加载层。 */
    object LowMemory : PyramidResult
}

fun loadPyramid(level: Int, cacheDir: File?): PyramidResult
```

- 可见性：与既有 `fromAssets` / `parseRows` 同域；`PyramidResult` 放 `data` 包内，
  不向渲染层暴露原始数组（维持 §十二.2 零分配口径）。
- `level` 语义：1 = L1（6.5, 9.0]，2 = L2（9.0, 11.5]；`0` 与 `> PYRAMID_LEVELS` 一律 `Missing`。

### 4.2 读路径与缓存布局

- 缓存根：`File(context.filesDir, "astro/pyramid")`；`cacheDir` 由宿主注入（便于单测传临时目录）。
- 文件名（与 `astro_pyramid_manifest.json` `levels[].cacheFile` 单源一致）：

```
<cacheDir>/level_1.csv            # L1 瘦表
<cacheDir>/level_1.csv.sha256     # 逐片 sha256（"<hex>  level_1.csv"）
<cacheDir>/level_2.csv
<cacheDir>/level_2.csv.sha256
<cacheDir>/bundle_manifest.json    # 下载段写入：源、行数、校验和、署名串
```

- 内置层路径不变：`astro/stars.csv`（`StarCatalog.kt:78` `ASSET_PATH`）。
- 校验顺序：文件存在 → 读旁证 sha256 → 对切片字节重算 sha256 比对 → 解析；任一步失败走
  `Corrupt`，不进入合并。
- 缓存淘汰：切片可整目录删除重建；下载段续传/重下覆盖同名文件；坏片改名
  `level_N.csv.corrupt-<epoch>` 隔离，不覆盖好片。

### 4.3 三种边界的返回与行为

| 边界 | 判定条件 | 返回 | 上层行为 |
| --- | --- | --- | --- |
| 缺文件 | `cacheDir` 为 null；切片/旁证不存在；`level` 越界 | `Missing` | 保留 L0；缺失天区低层密度底图覆盖（§七.4）；不弹错误态 |
| 损坏 | sha256 不符；解析零有效行；越界坐标/非有限星等占满片 | `Corrupt` | 隔离坏片；回落 L0；Sheet 顶部一次性 `textAccent` 提示（§七.7）；异常计数进 `importReport`/`importAnomalies` |
| 低内存 | 合并前内存评估：新增行数 × 每行扁平数组增量超出可用阈值 | `LowMemory` | 不追加数组、不抛 OOM；保持当前层；降层顺序沿用 §十三.4（关流星→尘粒→magLimit 9→银河） |

补充硬口径：

- 解析坏行跳过并计数，不整片回退；有效行为 0 才判 `Corrupt`（沿用 `parseRows` :115-155 口径）。
- 跨层 id 互斥：与 L0 / 已加载层重复的 id 不计入 `added`，计入重复计数留痕，不覆盖既有索引。
- 下载中状态：由渲染层进度线（§七.4，1px `brandGold`）表达；`loadPyramid` 只负责缓存校验与合并，
  不持有网络回调。

### 4.4 解析与留痕口径

- 复用既有 `parseRows` 的校验规则：`ra ∈ [0,360)`、`dec ∈ [-90,90]`、星等有限、主键唯一；
  坏行分类计数（badCoord / nanMag / dupId）并入目录级 `importReport` 文本与 `importAnomalies` 计数。
- 增量存储：金字塔层追加为独立扁平数组（`DoubleArray`/`FloatArray`/`LongArray`），查询期按索引
  原始类型访问，不 new 实体列表（§十二.2）；`queryRect`/`nearest` 扫描顺序 L0 → 已加载 L1 → L2。
- 署名串：`bundle_manifest.json` 落 S-01 署名串逐字值；Sheet 出处行只在源表注录时显示，缺字段不编。

### 4.5 单测断言清单（≥6 条；每条附「改坏会红」推演）

测试类建议放 `app/src/test/.../data/StarCatalogPyramidTest.kt`，纯 JVM 夹具构造，不碰
`AssetManager`/Android（沿用 `StarCatalogBvTest` 风格）。

1. **L0 星等带全量**：夹具行混入一颗 mag 7.0；断言有效行只收 ≤6.5，7.0 行计入 `nanMag`/越带计数。
   改坏推演：若解析器丢掉星等过滤，7.0 行进目录，本断言失败变红。
2. **缺目录返回 Missing**：`loadPyramid(1, null)` 与 `loadPyramid(1, 临时空目录)` 均 `Missing`；
   `catalog.size` 不变、无异常抛出。改坏推演：缺文件路径若抛 NPE 或返回 `Loaded(0)`，断言变红。
3. **校验和不符返回 Corrupt**：写入切片后篡改一字节、旁证不改；断言 `Corrupt`，且 L0 行仍可查。
   改坏推演：若合并前不校验 sha256，坏片被解析合并，本断言变红。
4. **零有效行返回 Corrupt**：夹具全为越界坐标；断言 `Corrupt`、异常计数 > 0、目录尺寸不变。
   改坏推演：若空片被当成功合并，`Loaded.added=0` 与空目录被误判健康，断言变红。
5. **level 越界返回 Missing**：`level=0`、`level=3` 均 `Missing`，不触发 IO。
   改坏推演：若越界 level 被当成 L2 读文件，路径拼错会抛异常或误 `Loaded`，断言变红。
6. **低内存拒绝合并**：注入内存评估器返回不足；断言 `LowMemory`，增量数组长度为 0。
   改坏推演：若跳过内存评估直接合并，低内存机 OOM，本断言在注入路径变红。
7. **成功合并计数**：合法 L1 夹具 N 行；断言 `Loaded(1, N)`，`queryRect` 能扫到新增星。
   改坏推演：若合并只追加部分行或索引未建，`added` 与查询命中数对不上，断言变红。
8. **跨层重复 id 拒绝**：L1 夹具含一颗与 L0 同 id 的星；断言该颗不计入 `added`、重复计数 > 0。
   改坏推演：若重复 id 覆盖 `idToIndex`，拾取会错指旧星，断言变红。
9. **坏片隔离不毁好片**：L1 `Corrupt` 后再放合法 L2；断言 L2 仍 `Loaded`，L1 坏片被改名隔离。
   改坏推演：若损坏处理清空整个缓存目录，L2 一并丢失，断言变红。
10. **累积单调与星等带**（脚本侧已机检，测试侧镜像）：夹具 L1 行 mag ∈ (6.5, 9.0]、
    L2 ∈ (9.0, 11.5]；断言越带行被拒。改坏推演：带边界写反（如 L1 收到 9.5），断言变红。

### 4.6 接线点与复用边界

- 门面：`StarStore`（`StarStore.kt:23`）暴露目录规模时计入已加载金字塔层；关系查询仍走 DAO。
- 触发：`SkyInputHandler.kt:74-76` 局部星图请求 → 宿主按当前 `magLimit` 调 `loadPyramid`；
  在途请求按 level 去重，防双指连点重复加载（§6 并发边界）。
- 复用：下载/缓存状态接既有 `AssetStatus/TextureCache/DegradationLevel`；降级域必须拆
  「地球域 / 星空域」两套算档（§十三.8），星空瓦片缺失不得误判地球纹理降级。
- 禁新建：不新建 StarProvider（§十二.4，归 D16 `astronomy` 类）；不新建下载器；不改冻结签名
  （`GlobeController` 只增方法不改参）。

## 5. 二阶三阶影响

**一阶（直接效果）**：联网且缓存就绪时，局部放大能长出 6.5→9.0→11.5 暗星；离线/未下载时
亮星层与线框照常。

**二阶（相邻环节）**

- **内存与 GC**：金字塔增量走扁平数组，查询期零装箱（§十二.2）；L2 全量十万级行并入后，
  常驻内存随层增长，低内存分支（§4.3）是硬约束而非可选。
- **渲染扫描成本**：`queryRect`/`nearest` 由单层扫变为 L0→L1→L2 顺序扫；既有 700 颗投影
  bench（`SkyBenchTest`）需在增量并入后回归，防止帧预算被扫描层顶破（§八 15 draw call 预算）。
- **冷启动 IO**：缓存目录不在启动读取路径；首帧只读既有 `stars.csv`，启动→书架 ≤1.8s 红线
  （A8）不受金字塔影响。
- **与 8,920 颗基础表的关系**：L0 是唯一实体锚点（拾取、星名、星官成员、分野联动都回 L0 id）；
  金字塔层只增暗星渲染点，不回写 L0、不改 L0 主键；清缓存/卸载不影响内置亮星与连线。

**三阶（流程与演进）**

- **后续 LOD 分层会不会被这套结构绑架**：契约只绑「星等带 + 瘦表字段 + 缓存文件名」，
  **不绑 CSV 格式**。将来换二进制打包/坐标量化/按天区分片，上层查询接口不变；
  9.0 界值若调整，只改 manifest 与 `SkyParams` 单一常量（见 §8 交接 3），不动渲染层。
- **数据工程成本**：切片、校验和、行数留痕是发布工序的一部分；构建器必须可重跑幂等，
  源表更换（NC 商业化换源，§十三.6）时 L0/L1/L2 同源同换，脚本按同一 schema 出片。
- **门禁联动**：构建说明规则三的文件名扫描模式需在切片格式落地时补齐（`*pyramid*`/`*tile*`/
  `*lod*`）；本单产物在 `data_scripts/_cache/` 与脚本目录，不进构建中间产物，不触发该扫描。

## 6. 反例边界（最强反对者清单）

1. **断网首启**：下载请求不可达 → 对应层 `Missing`；L0 亮星 + 全部线框显示，暗星区走低层
   密度底图；不空白、不崩（§七.6、§十三.2）。
2. **缓存被系统清理**：Android 回收 `filesDir` 后切片消失，路径同缺文件 → `Missing`；
   下次联网再下载重建；清理动作不影响 L0。
3. **资产被裁剪的极简包**：`stars.csv` 缺失/损坏 → 既有占位态（`StarCatalog.kt:87,105,173-185`）
   → `StarField` 种子 9173 程序化兜底 + 「星表未载，当前为示意星空」（§七.6）。
4. **星等越界请求**：请求 11.5 以上深度无对应层 → `Missing`；`magLimitFromBlend` 已在
   `SkyParams.kt:263-266` 钳制到 [6.5, 11.5]，上层不应发出界 level。
5. **半截/损坏下载**：校验和先于解析拦截；半截文件不产生部分合并；坏片隔离不覆盖好片。
6. **低内存设备**：`LowMemory` 拒绝当前层合并，先走 §十三.4 降层序列；不杀进程、不留半合并态。
7. **并发连点**：双指 ≥2× 反复触发；在途下载/加载按 level 去重，回调幂等；重复 `loadPyramid`
   不得重复追加数组。
8. **同名消歧 / 重复星**：跨层同 id 计入重复留痕，不覆盖索引；源表双条目（双证）以构建器
   去重口径为准，坏行不进产物。
9. **没找到反例的面**：时区/恒星时与金字塔层无关（坐标 J2000 静态，时间变换在投影层）；
   行星/彗星属二期，不进本切片。

## 7. 认知成本（新人接手需要知道的概念）

1. **两级金字塔星等带**：L0 ≤6.5 内置；L1 (6.5, 9.0]；L2 (9.0, 11.5]；层级数 `PYRAMID_LEVELS=2`，
   不是「三张地图」而是同一星表按星等切的增量层。
2. **NC 许可边界**：S-01 Tycho-2 非商用可用，商业化整体换源；派生素材不进 APK/CI artifact/git；
   入库前先查 `docs/台账-数据源许可.md`。
3. **缓存布局与校验链**：`filesDir/astro/pyramid/`，sha256 旁证先于解析；缺/坏/低内存三分支
   各有返回类型，不许吞异常。
4. **零分配数据层**：目录存扁平原始类型数组，查询期不 new 实体列表；新增层沿用同一存储口径。
5. **降级域隔离**：星空与地球是两个独立 fallback 域，星空缺瓦片不得把地球纹理误判成程序化档。
6. **瘦表 schema**：六层字段与 L0 表头子集对齐；缺色/缺距离留空不编（§四.5/6）。
7. **离线验证口径**：沙箱无外网，运行时下载不可在此验证；可验证的是契约、L0 真数据、构建器
   离线退出码与校验器双样本；未上机项必须显式标未验证。
