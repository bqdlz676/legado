### 时间线


**0ms · 黑底**
纯黑 `#0A0C14`。


**0–400ms · 墨滴坠落**
屏幕正中央上方，一滴浓墨从画面外坠入。墨滴不是正圆——边缘有细微撕裂，像毛笔饱蘸后自然垂落的一滴。下落速度先慢后快（重力加速感）。


**400–700ms · 炸裂**
墨滴触底。不是碰到屏幕边缘——是在画面正中心**凭空触到一张看不见的纸面**。炸开 40–50 粒墨色碎屑，大小不一，形态各异：有圆粒、有飞白细丝、有大块溅墨。粒子飞散半径最大 60dp。


**700–1000ms · 回聚**
所有粒子悬停半空 0.3s。然后被一股看不见的力往回吸——不是匀速回收，是加速吸入。粒子在回聚过程中互相碰撞、旋转、融合。最终汇聚成两个字：


```
落
文
```


竖排。字不是 fade in 出现的，是**从墨迹里渗出来的**——先淡得像水渍，0.4s 内凝成浓墨。笔顺一笔一笔在空中画出来——"落"的草字头先出、"文"的捺最后收。


**1000–1200ms · 金粉爆**
字成型后顿一下（0.2s）。然后字面上**向外炸开一次金粉**——60–80 粒暖金色微粒从字面飞出，铺满屏幕 1/3。金粉在空中飘 0.5s，亮度衰减到 0。像锤子砸在烧红的铁上溅出来的火星。


**1200–1600ms · 远山浮现**
画面底部缓缓亮起一座水墨远山。只勾轮廓线不填色。山脊线淡入 400ms，山腰有雾气横亘——雾气是半透明白色，缓慢左右飘动。山的存在感很低（opacity 最高 0.25），不抢字的注意力。


**1400–1800ms · 暖金线扫过**
山与文字之间，一条细暖金线从左到右划过。不是平滑移动——有轻微的顿挫，像毛笔在纸上走。扫过时字面轮廓发光，背后投出 40dp 金色辉光。线到"文"字最后一捺的末端停住，变成一粒金点（像句号收束）。


**1800ms · 标语**
底部浮现一行小字：


```
读其文，知其人，通其时。
```


12sp，云灰色（`#9B9687`），不加粗不加斜。不是 slogan——是这幅画的落款。淡入 400ms。


**2200–2800ms · 淡出**
全部画面（字、山、金点、标语）同时缓慢淡出 600ms。淡出过程中字最后消失的是"文"字那一捺，山最先消失。进入书架页。

## Three.js 层增补：落文专用约束


你列的粒子场、3D orb、floating geometry 是通用科技风。落文用 Three.js 的地方必须换语义——**不要科技感，要东方感**。


| 落文场景 | Three.js 内容 | 粒子上限 | 帧率底线 |
|---|---|---|---|
| 启动页 | 墨滴坠落 + 金粉粒子 | 60 | 55fps |
| 阅读页背景 | 水墨氛围粒子（极淡，不高于 #000 8%） | 40 | 保持 60fps，否则降级到静态 |
| 地图 3D 地形 | 高程地形 + 光柱 + 粒子上升 + 冲击环 | 200 | 45fps |
| 纪年金环 | 环形粒子 + 流动数字粒子 | 80 | 55fps |


**关键约束**：
- 离开可见区域必须 `dispose()`（地图页是最重灾区——离开即销毁 geometry/material/texture，不然 3 秒内存泄漏）

指标上限测量点启动 → 看到书架≤ 1.8sperformance.now() 首帧首触气泡≤ 300ms（冷）/ ≤ 80ms（热）touchstart → 气泡 visible翻页≤ 16ms/frame（不掉帧）requestAnimationFrame 间距地图页进≤ 2s 地形渲染完成WebView onPageFinished → 首帧内存峰值≤ 180MB（含 WebView）performance.memory字体子集大小≤ 200KB 首屏Network 面板字典加载内存≤ 15MB（4 表总和）加载前后 usedJSHeapSize 差值竹林鸟青鸾 z4（平板振膜）加听羽 f1（USB 解码耳放）——这套组合值得一个好解析。你要的一是解码能力（格式全、不压缩），二是输出路径（绕过 Android 重采样，直通 DAC），三是跟落文不冲突。

## 6. 古籍朗读

**引擎**：Android 系统 TTS（TextToSpeech） + 自定义断句层。不用自己训练模型。

**断句层（核心）**：
```
原文："郑伯克段于鄢"
没有断句 → TTS 直读："郑伯克段于鄢"（一口气，听不出意思）

落文断句：
1. 查典故词表 → 没命中
2. 查人名表 → "郑伯"命中 → 在"郑伯"后加 200ms 停顿
3. 查地名表 → "鄢"命中 → 在"于鄢"前加 150ms 停顿
4. 查虚词表 → "于"是介词 → 加 100ms 停顿
5. 最终："郑伯 ⏸ 克 ⏸ 段 ⏸ 于鄢"
```

**断句规则优先级**：
1. 典故词 → 词前后各加 200ms 停顿（第一优先级，不能把"四面楚歌"读成"四面/楚歌"）
2. 人名 → 人名后加 200ms
3. 地名 → 地名前后各加 150ms
4. 虚词（于/之/而/以/则/者/也/乎/哉/焉/矣）→ 虚词前加 100ms
5. 标点 → 句号/问号/感叹号 400ms，逗号 200ms

**TTS 引擎选择**：
- Android 自带 Pico TTS → 中文语音一般，能听
- 推荐用户装 **Google 文字转语音**（Play Store 免费）→ 中文语音自然很多
- 设置页加一行「推荐安装 Google TTS 引擎以获得更好的朗读体验」+ 跳转 Google Play 链接

**UI**：阅读页右上角一个喇叭图标。点一下开始朗读，再点停止。朗读时当前句子用朱砂色底高亮。底部浮出极简控制条：「⏸ 暂停」「← 上一句」「→ 下一句」「1.0× 速度」。3 秒后控制条自动半透明化。

## 1. 生字本
### 数据模型
```sql
CREATE TABLE vocab_log (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    char      TEXT NOT NULL,         -- 单字或词
    type      TEXT DEFAULT 'char',   -- 'char' | 'word' | 'allusion'
    book_id   TEXT,
    chapter   TEXT,
    context   TEXT,                  -- 原文句子（含该字）
    clicked_at INTEGER,              -- 首次点击时间戳
    review_count INTEGER DEFAULT 0,
    last_reviewed INTEGER,
    mastered  INTEGER DEFAULT 0     -- 0=需复习 1=已掌握
);
```
### 写入逻辑
气泡弹开 → 同时 `INSERT OR IGNORE` 写入 `vocab_log`。同一个字在同一本书同一章里不重复计。同一个字在不同书/不同章里各算一条（出处不同，语境不同）。
### 复习提醒
- WorkManager `PeriodicWorkRequest`，每 6 小时轮询一次
- 查询 `last_reviewed < now - 7天 AND mastered = 0 AND review_count < 5` → 如果有 ≥ 3 条 → 推通知"《左传·隐公元年》里有 3 个字需要复习"
- 点击通知 → 直接进复习列表
### UI
发现页多一个入口卡片：「生字本 · N 字待复习」。点进去 → 竖排字列表。每行：字（墨色 18sp）+ 拼音（石青 10sp）+ 原文出处句子（云灰 12sp，该字用朱砂高亮）。点一行 → 半屏 Sheet 显示完整字义 + 说文 + 用例。底部两个按钮：「已掌握」（加 mastered=1）、「再看一次」。
### 复习列表排序
按遗忘曲线加权 = `距今天数 × (5 - review_count)`，越久没复习排越前。复习一次 `review_count++`，5 次后自动 `mastered=1`。

## 6. 字源演变
### 数据模型
```sql
CREATE TABLE char_etymology (
    char          TEXT PRIMARY KEY,
    oracle        TEXT,         -- 甲骨文 SVG path
    bronze        TEXT,         -- 金文 SVG
    seal          TEXT,         -- 小篆 SVG
    clerical      TEXT,         -- 隶书 SVG
    regular       TEXT          -- 楷书 SVG
);
```
每个字形存为 SVG path 字符串（`<path d="M..." />`），不是图片——一张图片 0。一个字的 5 个字形加起来约 4KB，2 万汉字 = 80MB。只覆盖常用 6000 字（24MB），其余冷僻字按需下载。
### 来源
- **Chinese Etymology（字源网，Richard Sears）**——公版免费。几万汉字从甲骨文到楷书的全部字形，每字形 SVG 或高清 PNG。直接爬他们的开放 API
- **小篆/隶书**——《说文解字》收录的字形，从 ctext 的《说文》数字化版里自动截字形图
- 楷书 → 就是现在用的 Noto Serif SC，不需要单独存
### UI
字详情 Sheet 底部加一栏「字源」。点 → 全屏 Canvas 竖排显示五个字形从上到下：
```
甲  (甲骨文，底部标注"甲骨文·商")
金  (金文，标注"金文·西周")
篆  (小篆，标注"小篆·《说文》")
隶  (隶书，标注"隶书·汉")
楷  (楷书，标注"楷书")
```
进入时自动播放：甲骨文出现 → 停顿 600ms → 金文淡入并变形成一个过渡态 → 停顿 → 小篆淡入 → 隶书 → 楷书。不是硬切，是用 `PathMorph` 做形状过渡（两个 SVG path 之间插值）。每个形变段 400ms。

## 7. 异体字/避讳字标注
### 数据模型
```sql
CREATE TABLE variant_char (
    variant   TEXT NOT NULL,    -- 异体字字形
    standard  TEXT NOT NULL,    -- 标准字形
    reason    TEXT,             -- '避讳·唐太宗李世民' / '异体' / '俗字' / '简化'
    PRIMARY KEY (variant, standard)
);
```
### 生成方式
- Unihan 数据库 → `kTraditionalVariant` + `kSimplifiedVariant` + `kSemanticVariant` 三个字段直接导
- 避讳字表——手写一份 JSON，含历代帝王名讳（李世民→"民"缺笔、"世"缺笔；康熙→"玄"缺笔）、圣人讳（孔子→"丘"缺笔）、家讳（手写不完，只收最常见的）
约 2 万条异体 + 200 条避讳规则。
### 排版层改动
阅读页排版时（分页阶段），逐字扫描正文：
- 查 `variant_char` 表 → 命中 → 在该字右上方标注正字
- 标注格式：石青色 `#3C5C6E`、6sp、半透明 0.6、float 在该字右上方 4dp
标注不是覆盖在原字上，是偏右上的极小字——不影响阅读，像眉批一样的存在感。
### 交互
点异体字 → 气泡多一行："避唐太宗讳"（石青色 10sp）+ 气泡正文仍是正常释义。点气泡 → 半屏 Sheet 正常字详情，底部多一栏「字形说明」：这段话在清代刻本中是 XXX 字形，避 YYY 讳。

pinyinOfWord 多音字一律取首音，像「长」「乐」「行」「朝」会标错——好在人名有 PersonPinyin 兜底，但正文词组注音还是错。地名建时空本体——把一个地名拆成三层：实体（点/面）+ 名字（随时间变）+ 时间区间。这是历史 GIS 的标准答案，哈佛 CHGIS（中国历史地理信息系统）就是这么建模的。你给人物做的「本名 × 别名 × 生卒」，思路完全对，搬过来就行，只是地名多一个坑：点和面不是一回事。先拆你点名的「长安/咸阳/京兆」——它们三个根本不是一类：


长安 = 点（一座城），西汉都城，渭河南岸。
咸阳 = 点（另一座城），秦都，渭河北岸。和长安隔河相望约 20 公里，不是同一个地方，靠时间区分（秦→咸阳，汉→长安）。
京兆 = 面（行政区划，京兆尹/京兆府），它的治所是长安。所以「京兆」不是拿来画点的，是画辖区的，中心落在长安上。json复制{

## 3D 沙盘 · 氛围渲染


### 一、势力范围（画在地表上）


不是浮在空中的线框。把 `powers_poly.js` 的每个多边形**贴在地形表面**——用 `THREE.ShapeGeometry` 按多边形顶点采样地形高度，生成一张贴合地表起伏的半透明色块。


- 己方势力：暖金色半透明（opacity 0.12），边界用金色虚线 1px
- 敌方势力：灰青色半透明（opacity 0.10），边界暗铜色虚线
- 盟友势力：铜色半透明（opacity 0.08）
- 中立区域：无填充，只画边界
- 势力交界处：两条色块交叠的地方自动叠加一层微弱的渐变（shader 做，2fps 流动）


### 二、古城池（你来问氛围感就给你氛围感）


当前只有 `place_entity.txt` 的坐标和 22 个 `CanvasTexture` 文字标签。不够。


**三级城池渲染**：


| 级别 | 视觉 | 示例 |
|---|---|---|
| 都城 | 金色光柱从地面升 12 单位 + 柱顶一个旋转的微型篆印章 + 柱旁金粉粒子上升消散 | 长安、洛阳、临淄、郢、咸阳 |

**城池光柱细节**：
- 光柱是一根竖直的 `CylinderGeometry`，半透明，底部粗顶细，像灯柱
- 光柱内有金粉粒子缓慢上升（`Points` + `BufferGeometry`，每柱 8-12 粒）
- 柱底在地表上方浮 1 单位，不陷进地形
- 同一时刻最多画 8 根都城光柱（其余降级为亮点），控制 draw call
- 被敌军占领的城池 → 光柱颜色从暖金变朱砂红，粒子从上升变下落


**城池标签**：
- 竖排小字浮在光柱中段偏右，墨色 serif 字体，8sp
- 不是 CanvasTexture 一个一个画——合并到一张 atlas 纹理，所有标签一次 draw call

# 3D 战役回放 · 完整视觉规格


---


## 全局气质：不是游戏，不是地图 App，是将帅沙盘


暗底、暖金、地形是主角、UI 是侍从。整个画面只有两个光源——头顶一盏看不见的烛灯（暖金色光照亮地形山脊），和战场上那些移动的光点（军队棋子自己发微光）。


进入方式：从阅读页点地名 → 底部浮出「2D 地图 / 3D 沙盘」选项 → 选 3D → 2D 地图从中间撕开、3D 地形从裂口隆起来。不是跳转，是**地面抬升**。


---


## 第一帧加载：地形出生


不是白屏→地形突然出现。是：
- 0-400ms：黑底上浮出金色网格线（经纬网），线从暗到亮，像蚕丝被光照透
- 400-800ms：地形从网格下方**缓缓隆起**——平面 → 丘陵 → 山脊 → 河谷——像大地在呼吸
- 800-1000ms：贴地雾气沉入河谷，山顶露出来
- 1000-1200ms：军队棋子一颗一颗从天而降，落在起始位置，落地时地面轻微震颤（涟漪扩散一圈 80dp 的金色波纹）
- 1200ms：顶部标题淡入，底部面板从下方滑入


加载完成。全程没有转圈、没有进度条、没有「请等待」。

## 顶栏（存在感为零，需要时才在）


```
┌──────────────────────────────────┐
│ ← 长平之战 前260年 │
└──────────────────────────────────┘
```


- 背景：**没有背景**。字浮在画面上方，半透明墨色（`rgba(26,20,16,0.7)`）
- 字号：战役名 16sp · 年代 12sp
- 左侧「←」箭头：点一下回到 2D 地图——返回动画不是 fade，是**地形下降**，3D 沉回平面、2D 地图从下方升上来
- 顶栏在用户 3 秒不碰屏幕后**自动淡出**，点一下画面再淡入

## 底部控制栏（战斗仪表盘）


```
┌──────────────────────────────────┐
│ ◆ 回合 7/30 进度 ▂▂▂▂▂▂▂░░░ │
│ ◀◀ ◀ ▶ ▶▶ ▏一渡 ▏二渡 ▏三渡 ▏四渡 │
│ ▸ 自动 ▸ 分支 ▸ 对比 ▸ 导出 │
└──────────────────────────────────┘
```


- 背景：**深茶色毛玻璃**，背透地形色但看不穿。底部有极细的金线（1px）跟控制区隔开
- 下拉控制栏可展开为**全宽战术面板**（显示当前回合的军队状态），收起后只留最上一行
- 控制栏 3 秒无操作 → 底部收缩成一条 4dp 高的金线。再点金线 → 展开


**播放按钮不是图标，是质感**：
- ▶（播放）——暖金色三角形，悬浮发光
- ⏸（暂停）——两条竖线，压下时颜色从暖金变为朱砂
- 自动播放时 ▶ 周围有一圈**旋转的金色虚线光轨**（细金线 240° 弧，不是满圈，6s 转一圈），暗示「正在推演中」
- 按钮之间用云灰色竖线分隔


**进度条不是条**：是一根**拉直的蚕丝金线**，线的一端到另一端代表回合 1 到 N。当前回合位置有一颗**悬浮的朱砂小圆点**，不是嵌在线上，是**浮在线上方 2dp**，点按住左右拖可以手动跳回合——拖动时金线轻微振动。


**阶段标签**（一渡/二渡/三渡/四渡）：金线下方有对应的阶段标记——不是 tab 按钮，是**线上一颗一颗的小铜点**。当前 phase 的铜点亮暖金、其余暗。点铜点 → 跳转到该 phase 的第一回合，同时地图上的箭头瞬切。

## 地形渲染风格


不是卫星图、不是卡通、不是等高线地图。


**「绢帛军图」风格**：
- 地形主色：深沉的绢帛底色（`#1C1A14` 偏暖黑），山顶受光面偏米褐（`#B8A88A`），谷底阴影面偏青灰（`#3A4048`）
- 光照：一束暖光从左上方打下来（模拟烛灯或军帐里的油灯），光不是均匀的——光源处偏暖、远处偏冷，光在陡坡上投射出清晰的明暗面
- 翻越山脊的一侧被照亮，背光面暗到几乎看不清——制造**地形悬念**：「山那边有什么？」
- 河流：不是四渡赤水那种细管，是**一条缓缓流动的液态金线**，宽度根据地形的河谷宽窄变化。河面有微弱反光——不是物理 PBR，是沿河中线画一条半透明的金色反光带，缓慢流动（shader 做的，2fps 就够）
- 等高线：不显示线，只在地形较缓处有**极淡的纹理叠加**——像帛布本身的纹理，不是地图标记
- 颗粒噪点：画面整体覆盖一张 2px 的 noise overlay（CSS `background-image` 或 shader），模拟绢帛的织物纹理


---


## 军队棋子


```
红军（金朱） 蓝军（灰青）


 ▲ ▲
 /│\ /│\
/ │ \ / │ \
──●── ──●──
```


不是模型、不是图标、不是写实。每个棋子 = **一组浮在空中的几何体**：


- 底部：一个发光的**圆环**（金色或蓝色，1px 粗，浮在地表上方 3 单位），圆环在地面投下淡淡的圆形阴影
- 主体：一个**三角棱锥**（四面体），立在地面上方，尖顶朝上。金色（己方/红军）或灰青（敌方/蓝军），材质 = 半透明自发光，内部有微弱的光在流动
- 顶部：一根**竖直的细光线**从棱锥顶端向上延伸 8 单位，忽明忽暗（呼吸效果，1200ms 周期）
- 棋子尺寸跟兵力成正比——项羽主力部队的棋子比一支偏师大 1.5 倍


**选中态**：点一个棋子 → 棋子周围浮起一个**旋转的金色虚线圆环**（2 圈，慢转），同时棋子顶部的光线变亮、呼吸加快（400ms 周期）。底部浮出信息卡（不遮地形，是悬浮的）。


**麾下状态可视化**：
- 士气高昂：棋子发光稳定，顶光向上直射
- 士气动摇：棋子在微颤（0.5° 随机抖动），顶光长短不定
- 溃散：棋子原地碎成 6-8 片光屑 → 飘散 → 消失（800ms），原位置留下一圈暗红色的残影圆圈


---


## 箭头（不再是线，是兵锋）


行军路线不是一条线，是**一支带箭头的金色锋芒**：


- 箭身：一根渐粗渐细的金色光带，根部（起点）细、锋部（终点）粗，像毛笔写的一撇
- 箭身内部有**缓慢流动的金色光粒子**（2-3 粒，沿箭头方向流动，不是整条线闪），像军队在行进
- 箭头末端：一个三角形的**金色尖锋**，不是几何三角形，是带撕裂边缘的墨迹飞白效果
- 箭头贴地走：不是浮在空中，是**紧贴着地形表面**，上坡时抬头、下坡时低头


**多军同时动**：红军金箭头和蓝军灰蓝箭头**同时在地形上出现**。相遇点的箭头碰到一起时 → 炸一圈朱砂红的光环（300ms），这是遭遇/交战标记。


**箭头状态对应军队意图**：
- 进军 → 实线金箭头
- 急行军 → 虚线金箭头（间距短、闪得快）
- 包抄 → 弧线金箭头（不是 A→B 最短，是绕山走的曲线）
- 撤退 → 箭头末端散开的虚线（像人在溃散）
- 设伏 → 棋子虚化半透明（0.3 opacity） + 地面一个微弱的脉冲红点


---


## 交战场面


两军箭头相交、两军棋子相邻 → 触发交战动画（全屏最炸的部分）：


- 第一阶段（0-200ms）：冲突点炸出一个**朱砂红的冲击环**（跟启动页墨爆是一个调性），环从冲突点扩散到半径 120dp，暗红色、半透明
- 第二阶段（200-600ms）：冲击环消散过程中，冲突点上方浮起**两个棋子在快速互冲**——金三角和蓝三角各向对方冲一次、弹回、再冲一次，每次冲撞都有微弱的金色火花（3-4 粒）
- 第三阶段（600-800ms）：胜负定。胜方棋子猛然变大 1.5 倍、发光增亮，败方棋子褪色、缩小、向后位移。底部浮出一行战报文字（竖排、毛笔字风格）：「韩信破项羽前军 斩首三千」
- 结束后交战标记留在原地 → 一颗朱砂色的小方钉扎在地面上（不是一个点，是一枚**墨色篆印**的视觉效果，实际是 canvas 画的）


---


## 时间轴 / 阶段切


当前 phase 的节点在时间轴上不是圆点，是**一枚竖排的微型金色篆章**，章上面三个小字是该 phase 名称（小篆风格，实际上是渲染的小号 serif 字体）。


手指在时间轴上左右划 → 篆章依次被点亮（不是滑过去，是**点亮下一个、熄灭上一个**，节奏像点灯笼）。亮起时发出一圈暖金色光晕（160ms）。


---


## 信息卡（点棋子/箭头/渡口弹出的）


不是半屏 Sheet——那个留给字词/人物。沙盘上的信息卡是一张**悬浮的竹简**：


- 形状：竖向长条矩形，上下两端有**浅色木纹边**（2dp），像一片竹简
- 底色：半透明深褐色（`rgba(22,18,10,0.92)`），有细密竖纹（竹子纹理）
- 文字：竖排。棋子信息卡 =「韩信 · 汉军 · 兵力 8 万 · 士气高昂 · 意图：进军（目标：垓下）」；箭头信息卡 =「行军 62 里 · 预计 2 日 · 途经 3 个渡口」
- 出现：从棋子顶部光柱中**滑出来**（200ms ease-out），不是弹窗
- 消失：原路缩回棋子光柱中（150ms）


---


## 自动推演模式（最出片的模式）


点「自动推演」→ 进入**战争剧场模式**：


- 顶栏和底部控制栏完全消失，**全屏只剩战场**
- 回合自动推进，每回合 1.2s（可调），回合之间 0.3s 淡黑过渡
- 棋子按服务器计算结果移动，箭头随动
- 交战自动播放近景——镜头自动向前推 40%（0.6s），聚焦交战区域，交战动画结束 → 镜头拉回全景（0.6s）
- 模式左下角一个极小的「退出剧场」按钮，透明度 0.3，点一下回到手动操控
- 剧场模式下，地形边缘有**暗角效果**（vignette），像老式望远镜视野——告诉用户「这是回放，不是实时」


**剧场模式结束**：最后一回合结束 → 镜头缓缓拉远（1.5s，dist 从 300 拉到 560）→ 整个战场缩小成一个发光的金色沙盘 → 军队棋子变成微型光点 → 最后画面定格 2s → 底部浮现战役总结：「垓下之战 · 前 202 年 · 汉军胜 · 项羽自刎乌江」。


这个定格画面，就是落文的截图屏保。每一场战役都该能出这么一张。

**一句话**：当前代码 = `drop → connect → display`。推演引擎 = `heightMap → A* → decide → move → encounter → display`，前面五步都是新增的，最后一步复用当前渲染。先做 Day0 → 一渡赤水的单回合推演跑通（红军两个方向动、川军堵截、自动画箭头），再往多回合扩。# 3D 沙盘优化


## 一、地形是假的（标注自己都说了「示意地形，非实测高程」）


当前是 fbm 噪声生成的山——好看的沙盘玩具，但不是地图。改法：


**接真实高程数据**。不用全球 DEM，太重型。方案：预生成一个 256×256 的 PNG 灰度高度图，R 通道 = 高程（0-255 映射 0-3000m），放进 `assets/map/china_height.png`。加载时读像素做顶点 Y 值，替换掉现在的 `fbm(x,z)` 计算。


首版只覆盖关中/中原（104°E-122°E, 24°N-42°N），一幅 512×512 PNG 大概 200KB，精度够高。经纬度映射当前坐标系——`cityAt` 里那些 `1度≈5.4/6.4单位` 的常量，替换成真实投影（墨卡托或等距圆柱）。


> 验收：长安城在渭河谷地里、洛阳在伊洛盆地、太行山真的隆起——肉眼能认出来这是中国地形，而不是随机山。


## 二、行军路线（有数据模型，体验没跟上）


当前是自由点地落点，连直线算里程。算的是对的，但**没有跟书对应**——


加**预设行军路线**。每个路线就是一组 `[(地名, 经纬度)]`，从 `assets/map/routes.json` 读。首批 8 条经典路线：


| 路线 | 出处 |
|---|---|
| 明修栈道 → 暗度陈仓 | 《史记·淮阴侯列传》 |
| 项羽垓下之战行迹 | 《史记·项羽本纪》 |
| 秦灭六国顺序 | 《史记·秦始皇本纪》 |
| 长平之战进军线 | 《史记·白起王翦列传》 |
| 三家分晋疆域边界 | 《左传》 |
| 诸葛亮北伐路线 | 《三国志》 |


点路线名 → 地形上画出**金色箭头序列**（不是直线，是沿地形的曲线，每个箭头随地形起伏）、显示总里程、按日行 30 里/50 里两档估算日程。行军线所在年代匹配的疆域多边形也叠上。


这才是「读《史记》打开 3D 地图」该看到的——不是沙盘，是**一场战争在我眼前铺开**。


## 三、地形纹理太素


当前纯 vertex color（青灰/赭石/浅米）。加两层叠加：
1. **卫星底图**：256×256 的 JPEG（可选下载，不是内置），半透明叠在地形上
2. **等高线**：当前有 grid helper，但等高线更有地理感——按每 200 米一条，画在地表上方 0.5 单位。山峰处密、平原疏，一眼看出地势


## 四、点地名→3D 地图的入口是断的


`PlaceMapActivity` 进的是 2D 地图，点「二维图」按钮才到 3D。应该反过来：**2D 地图右下角一个 3D 切换按钮**，或者点地名直接问「查看平面图 / 3D 地形」。3D 地图里保留一个「二维图」返回通道——你现在的做法是有的，只是入口权重不对。


## 五、性能（手机上的 3D 必须算清楚每一毫秒）


当前：
- `antialias: true`、`pixelRatio ≤ 2`——对的，保留
- 地形 128×128 段、16,641 顶点——手机没问题
- 纹理用 `CanvasTexture`——OK 但每个 label 一个 Canvas，22 个城市标签 = 22 个 Canvas。合并到一个 CanvasTexture atlas，一片纹理画完所有城市名，一次 draw call


| 指标 | 上限 |
|---|---|
| 帧率 | 保持 50fps |
| 顶点 | 2 万（当前 1.6 万，加等高线后可到 2 万） |
| draw call | ≤ 15 |
| 内存 | ≤ 40MB |
| canvas 纹理 | 1 个 atlas，不是 N 个 |


---


**优先级**：
1. 真实高程（一张 PNG 替掉 fbm）——从「玩具」变成「地图」
2. 预设路线（JSON 配置 + 金色曲线箭头）——从「沙盘」变成「读史工具」
3. 地名到 3D 的入口打通——从「藏起来的彩蛋」变成「一级入口」

## 3D 沙盘 · 氛围渲染


### 一、势力范围（画在地表上）


不是浮在空中的线框。把 `powers_poly.js` 的每个多边形**贴在地形表面**——用 `THREE.ShapeGeometry` 按多边形顶点采样地形高度，生成一张贴合地表起伏的半透明色块。


- 己方势力：暖金色半透明（opacity 0.12），边界用金色虚线 1px
- 敌方势力：灰青色半透明（opacity 0.10），边界暗铜色虚线
- 盟友势力：铜色半透明（opacity 0.08）
- 中立区域：无填充，只画边界
- 势力交界处：两条色块交叠的地方自动叠加一层微弱的渐变（shader 做，2fps 流动）


### 二、古城池（你来问氛围感就给你氛围感）


当前只有 `place_entity.txt` 的坐标和 22 个 `CanvasTexture` 文字标签。不够。


**三级城池渲染**：


| 级别 | 视觉 | 示例 |
|---|---|---|
| 都城 | 金色光柱从地面升 12 单位 + 柱顶一个旋转的微型篆印章 + 柱旁金粉粒子上升消散 | 长安、洛阳、临淄、郢、咸阳 |
| 郡邑 | 铜色光柱 6 单位 + 柱顶静止光点 | 汉中、陈留、南阳、江陵 |
| 关隘/渡口 | 地面一个发光圆点（暖金脉冲，1200ms 呼吸），不打柱 | 函谷关、武关、孟津、茅津 |


**城池光柱细节**：
- 光柱是一根竖直的 `CylinderGeometry`，半透明，底部粗顶细，像灯柱
- 光柱内有金粉粒子缓慢上升（`Points` + `BufferGeometry`，每柱 8-12 粒）
- 柱底在地表上方浮 1 单位，不陷进地形
- 同一时刻最多画 8 根都城光柱（其余降级为亮点），控制 draw call
- 被敌军占领的城池 → 光柱颜色从暖金变朱砂红，粒子从上升变下落


**城池标签**：
- 竖排小字浮在光柱中段偏右，墨色 serif 字体，8sp
- 不是 CanvasTexture 一个一个画——合并到一张 atlas 纹理，所有标签一次 draw call


### 三、河流（真河道路径）


当前的程序化 fbm 曲线换成真实水系数据。`rivers.js` 格式：


```js
window.RIVERS = [
 { name: "黄河", era: "all", path: [[104.1,34.8], [104.5,35.0], ...] },
 { name: "渭水", era: "all", path: [[104.5,34.6], [106.8,34.3], ...] },

 { name: "汉水", era: "all", path: [[106.0,33.1], [110.0,32.5], ...] },
 { name: "淮河", era: "all", path: [[113.0,32.4], [117.0,33.0], ...] },
```

### 四、叠加效果（氛围就靠这个）

## 零、数据驱动（核心铁律）
**引擎不内置任何一场战役。** 所有战役 = 一个 JSON，引擎 = 吃 JSON + 地形 + 规则，吐出推演过程。验收方式：同一份引擎，喂垓下之战 → 推出来项羽被围、韩信十面埋伏；喂赤壁 → 推出来火攻生效的关键在风向和铁索连船。
```json
// 通用战役 JSON schema
{
  "id": "gaixia",
  "title": "垓下之战",
  "era": "前202",
  "terrainFocus": { "center": [117.2, 33.5], "radius": 80 },
  "heightMap": "gaixia_height.png",
  "duration": 30,           // 推演回合上限
  "victory": {               // 胜利条件：不是"谁活到最后"，是目标
    "type": "annihilate",    // annihilate | capture | defend | escape | reachPoint
    "target": "项羽",
    "side": "汉"
  },
  "armies": [
    {
      "id": "xiangyu",
      "name": "项羽",
      "side": "楚",
      "color": "#C23B2E",
      "initialPos": [117.19, 33.52],
      "strength": 10,           // 单位战斗力，不搞人数，用相对值
      "type": "elite",          // elite | regular | militia | cavalry
      "fatigue": 2,             // 0-5，开局已累
      "morale": "wavering",     // high | steady | wavering | broken
      "intent": "escape"        // 开局意图（被规则引擎按优先级自动覆盖）
    },
    { "id": "hanxin", "name": "韩信", "side": "汉", ... },
    { "id": "pengyue", "name": "彭越", "side": "汉", ... }
  ],
  "events": [                   // 脚本事件：不是硬编码，是按条件的 if-trigger
    {
      "trigger": { "turn": 5 },
      "action": "moraleChange",
      "target": "xiangyu",
      "value": "wavering",
      "reason": "四面楚歌"
    },
    {
      "trigger": { "army": "xiangyu", "strengthBelow": 2 },
      "action": "surrender",
      "target": "xiangyu"
    }
  ]
}
```
**不是硬编码「四面楚歌发生在第 5 回合」**——而是声明了触发条件。改一场仗只改 JSON，不改引擎。

## 二、地形通用算法（不依赖具体区域）
高度图从 PNG 读。地形分析层所有输出都是**相对地形**，不依赖具体坐标：
| 计算 | 解释 |
|---|---|
| `traversable(cell)` | 坡度 ≤ 45° → 步兵可过；坡度 ≤ 30° → 马可过；坡度 ≤ 15° → 辎重车可过 |
| `fords(map)` | 找连续 2 格以上、相邻也为河的窄河段 → 涉渡点 |
| `chokePoints(map)` | 找相邻高坡之间的狭窄通道，宽度 ≤ N 格 |
| `highGround(cell, radius)` | 周围 N 格内相对高差 > 阈值的制高点 |
| `visibility(from, to)` | 两点之间是否有地形遮挡（山脊线遮挡） |
| `AStar(from, to, armyType)` | 代价 = 距离 × 坡度惩罚 × 路况（平地 > 丘陵 > 山地 > 河流） |
| `flankPath(from, to, enemyPos)` | A* 但强制绕开敌方视线的路径 |
**算法 = 地形归地形、军队归军队、互不影响。** 加一场新战役 = 放一张高度图 PNG + 填一份 JSON。不需要调代码。

## 三、推演引擎（跟具体战役无关的纯规则层）
每个回合：
```
for 每一支军队（按速度排序——骑兵先动、步兵后动）:
  1. 情报更新
     - 能看到敌方军队位置 IF 敌军在己方视野内（无山脊遮挡 AND 距离 < 可视半径）
     - 看不到的 → 用敌方上次已知位置 + 模糊半径
     - 地图（地形本身）永远完整可见
  2. 规则意图轮询
     - 检查当前意图是否已完成（到达了、打赢了、逃掉了）
     - 检查是否有更高优先级的意图（遭遇战 > 撤退 > 包抄 > 进军）
     - 需要换意图时，根据优先级 + 战场态势自动切换
  3. 移动（A*，沿地形的实际路径，不是飞）
     - 行军速度 = 基础速度 × 路况系数 × 疲劳惩罚
     - 移动完成后更新位置
  4. 遭遇检测
     - 两军相邻格 → 触发遭遇
     - 一方伏击中 → 伏击方优先判定、伤害 +2x
     - 一方在制高点 → 防御 +1.5x
     - 结算：伤亡 = 兵力平方之比（兰彻斯特简化），败方后撤 1 格 + 士气下降
  5. 状态更新
     - 疲劳 = 当天行军距离 / 日行上限 + 已有疲劳
     - 疲劳 > 4 → 士气降一级
     - 士气 broken → 军队解散（消失）
     - 补给断绝 > 3 回合 → 疲劳加速
```
**规则意图优先级**（从高到低）：
1. 遭遇战中 / 被攻击 → 应战
2. 士气 broken → 溃逃（朝远离所有敌军的方向）
3. 被包围（四周均有敌） → 突围（朝敌最弱的方向）
4. 有可执行的伏击条件（敌军即将进入伏击点） → 设伏
5. 当前有意图 → 执行意图
6. 无意图 → 据守（军队原地不动）

## 四、胜利条件（不是「杀光」一种）
| 类型 | 条件 |
|---|---|
| `annihilate` | 目标军队被消灭或投降 |
| `capture` | 目标点/城被我方占领3回合 |
| `defend` | 目标点/城未失守，撑过所有回合 |
| `escape` | 目标军队移动到逃脱点并存活 |
| `reachPoint` | 我方军队到达目标点 |
| `rout` | 敌方所有军队士气broken |
| `compound` | 以上条件的 AND/OR 组合 |
**胜利判定不是最后一回合才查**——每回合都查。达到即结束。

## 五、推演回放与手动干预
**自动模式**：点「推演」→ 引擎自动跑完全部回合，每个 phase 的箭头/棋子移动/战斗动画自动播放。底部面板实时展示每回合结果。
**手动模式**：每回合暂停，用户可以**拖拽调整军队意图**——把「撤退」拖成「包抄」、把「据守」拖成「急行军」。拖完点「执行本回合」→ 引擎用新意图算这一步的结果。这是「推」的核心——不是看动画，是**你也能当一次韩信**。
**分支保存**：手动改了意图之后，当前状态（所有军队位置/士气/兵力）可以存成一个分支存档。用户可以「如果我在第 3 回合改包抄会怎样」→ 开一个分支 → 跑到底 → 跟原历史线对比。

核心：IntentResolver（规则决策）
```
优先级（从高到低）：
1. 当前正在遭遇中        → FIGHT（应战）
2. 士气 broken           → ROUT（溃逃，朝远离所有敌方的方向）
3. 被包围（四方有敌）     → BREAKOUT（朝敌最弱方向突围）
4. 有伏击条件触发        → AMBUSH（停在关隘不暴露）
5. 补给断绝 > 3 回合     → RETREAT（朝最近补给点退）
6. 当前意图未完成        → CONTINUE（继续执行）
7. 无意图                → HOLD（原地据守）
```
意图切换逻辑：
```
function resolveIntent(army, allies, enemies, terrain, turn):
  1. 先检查硬性生存条件（broken→溃逃，被围→突围，断粮→撤退）
  2. 再检查战术机会（敌在必经关隘→包抄，制高点空→抢占）
  3. 都不触发→维持当前意图
  4. 行军途中遇敌→FIGHT（遭遇战优先级最高）
```
全部规则表：
| 条件 | 意图 | 参数 |
|---|---|---|
| 相邻格有敌军 | FIGHT | 攻击最近敌军 |
| 士气 broken | ROUT | 朝远离所有敌方向 A* |
| 四向有敌 | BREAKOUT | 朝敌兵力最小方向 A* |
| 在关隘 + 敌距 < 5 格 + 己方未暴露 | AMBUSH | 原地不动 |
| 补给 ≤ 0 持续 3 回合 | RETREAT | 朝最近补给点 |
| 持有制高点 + 敌距 < 3 格 | HOLD | 防御加成 |
| 兵力 3× 于最近敌 | ADVANCE | 朝敌进军 |
| 有盟友相邻被攻击 | SUPPORT | 朝盟友位置 A* |
| 未持有关隘但敌距 > 5 格 + 关隘空 | SEIZE | 抢占关隘 |
| 以上均不触发 + 当前有意图 | CONTINUE | 沿原路 |
| 以上均不触发 + 无意图 | HOLD | 原地 |
决策代码量 ~150 行。不调模型，不联网，一回合 < 1ms。

```
 slope[r][c] // 每格坡度（0-90°），决定能不能走、走多快
 traversable[r][c] // 人行/马/车哪个能过
 riverMask[r][c] // 哪些格是河流（不可直穿，必须找渡口）
 chokePoints[] // 关隘/峡谷：相邻两格坡度 > 40° 且之间只有 ≤ 3 格平地的窄口
 highGround[] // 周围 10 格内相对高差 > 300m 的制高点
 fords[] // 河流格中相邻格也为河流、且河宽 < 2 格的可涉渡点
 paths(from, to) // A* 寻路，代价 = 基础距离 × (1 + slope/45) × 路况系数
}
```


推演的每一步，军队不走直线——走 A*。路线是地形逼出来的，不是人画的。


## 二、推演引擎（核心）


**每回合 tick() 做三件事**：


```
for each day/turn:
 1. 情报：每支军队能看到敌方最后已知位置，不是真位置
 2. 决策：每支军队执行当前战术意图
 3. 结算：移动、遭遇、战斗、伤亡、推进/后撤
```


**战术意图（一个军队一次只持有一个）**：


| 意图 | 行为 |
|---|---|
| 进军（目标点） | A* 寻路行军，沿路走，日行 30-50 里 |
| 急行军（目标点） | A* 寻路但取最短路径，日行 80-100 里，到达后疲劳+2 |
| 包抄（目标点，侧翼） | 不是直接走向目标，而是绕到侧面，避开敌方视野 |
| 设伏（当前位置） | 停在峡谷/密林里不暴露，敌方进入范围自动触发遭遇 |
| 据守（当前位置） | 停在制高点/城邑，防御加成 1.5x |
| 撤退（方向） | 朝远离最近敌方的方向移动，每日判定是否甩掉追兵 |


**遭遇结算（两军相邻时触发）**：


```
遭遇 = 两军距离 < 2格时
优势方 = 制高点方（防御+1.5x）|| 兵力多的一方 || 伏击方（首击+2x）
结果 = 交换比（双方伤亡） + 攻势方是否被击退 + 防御方是否被冲垮
```


不做逐人计算，做**兰彻斯特平方律简化版**——双方兵力平方比决定结果。够推演级别，不搞兵棋细节。


## 三、推演 UI（这是你看到的）


**推演沙盘不只一张静态地形**。进入推演模式后：


左侧：地形不变，军队是**发光棋子**站在地上——红军金色梭形、蓝军灰蓝梭形，棋子底部在地表上方浮 2 单位，有投在地面的圆形暗影。


右侧：底部推演面板（比时间轴更丰富）：
```

──────────────────────────────────────────
中央红军：土城 → 古蔺（行军 58里，疲劳 1）
国民党军：遵义 → 土城（追击，距红军 22里）
──────────────────────────────────────────
提示：川军叙永方向南下，红军左翼即将接敌
```


**推演面板可折叠**。折叠后只留一行 `回合 3 · ▸▸ · 红军距土城 8里`，不挡地形。

## 四、推演数据（谁来做？）


这不是代码问题，是内容问题。四渡赤水的推演需要：


1. **地形**：赤水河谷高精度高度图（SRTM 30m，免费可商用，预处理成局部图放进 assets）
2. **初始状态**：一个 JSON，给出 Day0 所有军队的位置、兵力、意图
3. **脚本验证**：推演引擎跑完，对比真实历史四渡的时间线——推准了说明引擎对，推歪了说明地形/策略参数要调


给内容团队的第一批任务：**四渡赤水 Day0 JSON + 真实时间线对照表**。引擎代码可以先拿它当验收用例——代码写完，喂 Day0，看自动推演能还原历史多少。


## 五、与当前代码的接轨


当前 `three.html` 有地形生成、标签、行军路线画线、落点。推演引擎接到它身上的方式：


- `terrainHeight(x,z)` 从高度图查，替换 `fbm`
- `routePts` 的 `dropPoint` 变成「给这个军队设定意图=进军（目标点）」
- `tick()` 每回合调用一次，返回 `[{army, from, to, action}]` 的数组
- 渲染层拿到数组后在地形上画箭头 + 移动棋子 + 标注
- `routeLine` 那段画金线的逻辑可以复用，只是线不再是手动连的，是 tick 产出

# 通用战役推演引擎规格


## 零、数据驱动（核心铁律）


**引擎不内置任何一场战役。** 所有战役 = 一个 JSON，引擎 = 吃 JSON + 地形 + 规则，吐出推演过程。验收方式：同一份引擎，喂垓下之战 → 推出来项羽被围、韩信十面埋伏；喂赤壁 → 推出来火攻生效的关键在风向和铁索连船。

## 二、地形通用算法（不依赖具体区域）


高度图从 PNG 读。地形分析层所有输出都是**相对地形**，不依赖具体坐标：


| 计算 | 解释 |
|---|---|
| `traversable(cell)` | 坡度 ≤ 45° → 步兵可过；坡度 ≤ 30° → 马可过；坡度 ≤ 15° → 辎重车可过 |
| `fords(map)` | 找连续 2 格以上、相邻也为河的窄河段 → 涉渡点 |
| `chokePoints(map)` | 找相邻高坡之间的狭窄通道，宽度 ≤ N 格 |
| `highGround(cell, radius)` | 周围 N 格内相对高差 > 阈值的制高点 |
| `visibility(from, to)` | 两点之间是否有地形遮挡（山脊线遮挡） |
| `AStar(from, to, armyType)` | 代价 = 距离 × 坡度惩罚 × 路况（平地 > 丘陵 > 山地 > 河流） |
| `flankPath(from, to, enemyPos)` | A* 但强制绕开敌方视线的路径 |


**算法 = 地形归地形、军队归军队、互不影响。** 加一场新战役 = 放一张高度图 PNG + 填一份 JSON。不需要调代码。


## 三、推演引擎（跟具体战役无关的纯规则层）


每个回合：


```
for 每一支军队（按速度排序——骑兵先动、步兵后动）:
 1. 情报更新
 - 能看到敌方军队位置 IF 敌军在己方视野内（无山脊遮挡 AND 距离 < 可视半径）
 - 看不到的 → 用敌方上次已知位置 + 模糊半径
 - 地图（地形本身）永远完整可见
 2. 规则意图轮询
 - 检查当前意图是否已完成（到达了、打赢了、逃掉了）
 - 检查是否有更高优先级的意图（遭遇战 > 撤退 > 包抄 > 进军）
 - 需要换意图时，根据优先级 + 战场态势自动切换
 3. 移动（A*，沿地形的实际路径，不是飞）
 - 行军速度 = 基础速度 × 路况系数 × 疲劳惩罚
 - 移动完成后更新位置
 4. 遭遇检测
 - 两军相邻格 → 触发遭遇
 - 一方伏击中 → 伏击方优先判定、伤害 +2x
 - 一方在制高点 → 防御 +1.5x
 - 结算：伤亡 = 兵力平方之比（兰彻斯特简化），败方后撤 1 格 + 士气下降
 5. 状态更新
 - 疲劳 = 当天行军距离 / 日行上限 + 已有疲劳
 - 疲劳 > 4 → 士气降一级
 - 士气 broken → 军队解散（消失）
 - 补给断绝 > 3 回合 → 疲劳加速
```


**规则意图优先级**（从高到低）：
1. 遭遇战中 / 被攻击 → 应战
2. 士气 broken → 溃逃（朝远离所有敌军的方向）
3. 被包围（四周均有敌） → 突围（朝敌最弱的方向）
4. 有可执行的伏击条件（敌军即将进入伏击点） → 设伏
5. 当前有意图 → 执行意图
6. 无意图 → 据守（军队原地不动）


## 四、胜利条件（不是「杀光」一种）


| 类型 | 条件 |
|---|---|
| `annihilate` | 目标军队被消灭或投降 |
| `capture` | 目标点/城被我方占领3回合 |
| `defend` | 目标点/城未失守，撑过所有回合 |
| `escape` | 目标军队移动到逃脱点并存活 |
| `reachPoint` | 我方军队到达目标点 |
| `rout` | 敌方所有军队士气broken |
| `compound` | 以上条件的 AND/OR 组合 |


**胜利判定不是最后一回合才查**——每回合都查。达到即结束。


## 五、推演回放与手动干预


**自动模式**：点「推演」→ 引擎自动跑完全部回合，每个 phase 的箭头/棋子移动/战斗动画自动播放。底部面板实时展示每回合结果。


**手动模式**：每回合暂停，用户可以**拖拽调整军队意图**——把「撤退」拖成「包抄」、把「据守」拖成「急行军」。拖完点「执行本回合」→ 引擎用新意图算这一步的结果。这是「推」的核心——不是看动画，是**你也能当一次韩信**。


**分支保存**：手动改了意图之后，当前状态（所有军队位置/士气/兵力）可以存成一个分支存档。用户可以「如果我在第 3 回合改包抄会怎样」→ 开一个分支 → 跑到底 → 跟原历史线对比。


## 六、验收战役（必须按这个顺序做，难度递增）


| 验收战役 | 验证什么 | 回合数 | 军队数 |
|---|---|---|---|
| 垓下之战 | 包围、突围、士气崩溃、四面楚歌事件 | 30 | 6 |
| 长平之战 | 对峙、切断粮道、包围圈合拢 | 60 | 8 |
| 四渡赤水 | 多次渡河、来回穿插、情报模糊、摆脱追击 | 60 | 6 |
| 淝水之战 | 退兵溃散、心理士气链式传导 | 10 | 4 |
| 赤壁之战 | 风向/火攻/水军（新增 weather/temperature 变量） | 20 | 5 |


第一行跑通就算引擎框架成立，后面全是数据填充。

核心：IntentResolver（规则决策）


```
优先级（从高到低）：


1. 当前正在遭遇中 → FIGHT（应战）
2. 士气 broken → ROUT（溃逃，朝远离所有敌方的方向）

7. 无意图 → HOLD（原地据守）
```


意图切换逻辑：


```
function resolveIntent(army, allies, enemies, terrain, turn):
 1. 先检查硬性生存条件（broken→溃逃，被围→突围，断粮→撤退）
 2. 再检查战术机会（敌在必经关隘→包抄，制高点空→抢占）
 3. 都不触发→维持当前意图
 4. 行军途中遇敌→FIGHT（遭遇战优先级最高）
```


全部规则表：


| 条件 | 意图 | 参数 |
|---|---|---|
| 相邻格有敌军 | FIGHT | 攻击最近敌军 |
| 士气 broken | ROUT | 朝远离所有敌方向 A* |
| 四向有敌 | BREAKOUT | 朝敌兵力最小方向 A* |
| 在关隘 + 敌距 < 5 格 + 己方未暴露 | AMBUSH | 原地不动 |
| 补给 ≤ 0 持续 3 回合 | RETREAT | 朝最近补给点 |
| 持有制高点 + 敌距 < 3 格 | HOLD | 防御加成 |
| 兵力 3× 于最近敌 | ADVANCE | 朝敌进军 |
| 有盟友相邻被攻击 | SUPPORT | 朝盟友位置 A* |
| 未持有关隘但敌距 > 5 格 + 关隘空 | SEIZE | 抢占关隘 |
| 以上均不触发 + 当前有意图 | CONTINUE | 沿原路 |
| 以上均不触发 + 无意图 | HOLD | 原地 |

不是硬编码「四面楚歌发生在第 5 回合」——而是声明了触发条件。改一场仗只改 JSON，不改引擎。
二、地形通用算法（不依赖具体区域）
高度图从 PNG 读。地形分析层所有输出都是相对地形，不依赖具体坐标：
| 计算 | 解释 |
| traversable(cell) | 坡度 ≤ 45° → 步兵可过；坡度 ≤ 30° → 马可过；坡度 ≤ 15° → 辎重车可过 |
| fords(map) | 找连续 2 格以上、相邻也为河的窄河段 → 涉渡点 |
| chokePoints(map) | 找相邻高坡之间的狭窄通道，宽度 ≤ N 格 |
| highGround(cell, radius) | 周围 N 格内相对高差 > 阈值的制高点 |
| visibility(from, to) | 两点之间是否有地形遮挡（山脊线遮挡） |
| AStar(from, to, armyType) | 代价 = 距离 × 坡度惩罚 × 路况（平地 > 丘陵 > 山地 > 河流） |
| flankPath(from, to, enemyPos) | A* 但强制绕开敌方视线的路径 |



算法 = 地形归地形、军队归军队、互不影响。 加一场新战役 = 放一张高度图 PNG + 填一份 JSON。不需要调代码。
三、推演引擎（跟具体战役无关的纯规则层）
每个回合：
for 每一支军队（按速度排序——骑兵先动、步兵后动）:
 1. 情报更新
 - 能看到敌方军队位置 IF 敌军在己方视野内（无山脊遮挡 AND 距离 < 可视半径）
 - 看不到的 → 用敌方上次已知位置 + 模糊半径
 - 地图（地形本身）永远完整可见
 2. 规则意图轮询
 - 检查当前意图是否已完成（到达了、打赢了、逃掉了）
 - 检查是否有更高优先级的意图（遭遇战 > 撤退 > 包抄 > 进军）
 - 需要换意图时，根据优先级 + 战场态势自动切换
 3. 移动（A*，沿地形的实际路径，不是飞）
 - 行军速度 = 基础速度 × 路况系数 × 疲劳惩罚
 - 移动完成后更新位置
 4. 遭遇检测
 - 两军相邻格 → 触发遭遇
 - 一方伏击中 → 伏击方优先判定、伤害 +2x
 - 一方在制高点 → 防御 +1.5x
 - 结算：伤亡 = 兵力平方之比（兰彻斯特简化），败方后撤 1 格 + 士气下降
 5. 状态更新
 - 疲劳 = 当天行军距离 / 日行上限 + 已有疲劳
 - 疲劳 > 4 → 士气降一级
 - 士气 broken → 军队解散（消失）
 - 补给断绝 > 3 回合 → 疲劳加速


规则意图优先级（从高到低）：
遭遇战中 / 被攻击 → 应战
士气 broken → 溃逃（朝远离所有敌军的方向）
被包围（四周均有敌） → 突围（朝敌最弱的方向）
有可执行的伏击条件（敌军即将进入伏击点） → 设伏
当前有意图 → 执行意图
无意图 → 据守（军队原地不动）
四、胜利条件（不是「杀光」一种）
| 类型 | 条件 |
| annihilate | 目标军队被消灭或投降 |
| capture | 目标点/城被我方占领3回合 |
| defend | 目标点/城未失守，撑过所有回合 |
| escape | 目标军队移动到逃脱点并存活 |
| reachPoint | 我方军队到达目标点 |
| rout | 敌方所有军队士气broken |
| compound | 以上条件的 AND/OR 组合 |



胜利判定不是最后一回合才查——每回合都查。达到即结束。
五、推演回放与手动干预
自动模式：点「推演」→ 引擎自动跑完全部回合，每个 phase 的箭头/棋子移动/战斗动画自动播放。底部面板实时展示每回合结果。
手动模式：每回合暂停，用户可以拖拽调整军队意图——把「撤退」拖成「包抄」、把「据守」拖成「急行军」。拖完点「执行本回合」→ 引擎用新意图算这一步的结果。这是「推」的核心——不是看动画，是你也能当一次韩信。
分支保存：手动改了意图之后，当前状态（所有军队位置/士气/兵力）可以存成一个分支存档。用户可以「如果我在第 3 回合改包抄会怎样」→ 开一个分支 → 跑到底 → 跟原历史线对比。
六、验收战役（必须按这个顺序做，难度递增）
| 验收战役 | 验证什么 | 回合数 | 军队数 |
| 垓下之战 | 包围、突围、士气崩溃、四面楚歌事件 | 30 | 6 |
| 长平之战 | 对峙、切断粮道、包围圈合拢 | 60 | 8 |
| 四渡赤水 | 多次渡河、来回穿插、情报模糊、摆脱追击 | 60 | 6 |
| 淝水之战 | 退兵溃散、心理士气链式传导 | 10 | 4 |
| 赤壁之战 | 风向/火攻/水军（新增 weather/temperature 变量） | 20 | 5 |



第一行跑通就算引擎框架成立，后面全是数据填充。

核心：IntentResolver（规则决策）
优先级（从高到低）：


1. 当前正在遭遇中 → FIGHT（应战）
2. 士气 broken → ROUT（溃逃，朝远离所有敌方的方向）
3. 被包围（四方有敌） → BREAKOUT（朝敌最弱方向突围）
4. 有伏击条件触发 → AMBUSH（停在关隘不暴露）
5. 补给断绝 > 3 回合 → RETREAT（朝最近补给点退）
6. 当前意图未完成 → CONTINUE（继续执行）
7. 无意图 → HOLD（原地据守）


意图切换逻辑：
function resolveIntent(army, allies, enemies, terrain, turn):
 1. 先检查硬性生存条件（broken→溃逃，被围→突围，断粮→撤退）
 2. 再检查战术机会（敌在必经关隘→包抄，制高点空→抢占）
 3. 都不触发→维持当前意图
 4. 行军途中遇敌→FIGHT（遭遇战优先级最高）


全部规则表：
| 条件 | 意图 | 参数 |
| 相邻格有敌军 | FIGHT | 攻击最近敌军 |
| 士气 broken | ROUT | 朝远离所有敌方向 A* |
| 四向有敌 | BREAKOUT | 朝敌兵力最小方向 A* |
| 在关隘 + 敌距 < 5 格 + 己方未暴露 | AMBUSH | 原地不动 |
| 补给 ≤ 0 持续 3 回合 | RETREAT | 朝最近补给点 |
| 持有制高点 + 敌距 < 3 格 | HOLD | 防御加成 |
| 兵力 3× 于最近敌 | ADVANCE | 朝敌进军 |
| 有盟友相邻被攻击 | SUPPORT | 朝盟友位置 A* |
| 未持有关隘但敌距 > 5 格 + 关隘空 | SEIZE | 抢占关隘 |
| 以上均不触发 + 当前有意图 | CONTINUE | 沿原路 |
| 以上均不触发 + 无意图 | HOLD | 原地 |

| 顶点色 | 3 阶分带（青灰/赭石/米褐） | **连续渐变**——高程 1m 一个颜色过渡，山脚到山顶丝滑变色 |

### 二、材质系统（从 Google Earth 学）
不只是顶点色。6 层材质叠加：
| 层 | 来源 | 效果 |
|---|---|---|
| 1. 卫星底图 | Mapbox/OpenStreetMap 2560×2560 纹理 | 耕田是黄色、森林是深绿、城市是灰色 |
| 2. 法线贴图 | 从高度图自动生成 normal map | 山脊的每一个褶皱都有光照细节 |
| 3. 粗糙度贴图 | 坡度→粗糙度映射（陡 = 粗糙、缓 = 光滑） | 岩石面哑光、平原微反光 |
| 4. 雪线 | 海拔 > 3500m → 自动叠加白色 + 微反光 | 贡嘎山/四姑娘山终年积雪 |
| 5. 河流 | 管状水体 → **平面反射水体**（`THREE.Water` shader） | 河面反射天空和山影，不是金色是真实水 |
| 6. 云影 | 一个半透明云层 Plane 浮在 200 单位高空，慢移 | 云投下的影子在地形上滑过 |

### 三、光照（PBR）
| 光源 | 手机版 | Windows 旗舰版 |
|---|---|---|
| 太阳光 | `DirectionalLight` 单光源 | **`DirectionalLight` + 环境贴图**（HDR 天空球） |
| 阴影 | 无 | **Shadow Map 2048×2048**，山脊在对面山坡投下阴影 |
| 环境光遮蔽 | 无 | **SSAO**（屏幕空间环境光遮蔽），峡谷/裂缝自动变暗 |
| 大气散射 | `scene.fog` 混合雾 | **Rayleigh + Mie 散射 shader**——远山偏蓝、近景偏暖 |
| 辉光 | 无 | **Bloom 后处理**——都城光柱和渡口发光有真正的 bloom 溢出 |

### 四、古城池 3D 模型
手机上是光柱 + 标签。旗舰版用真实 3D 模型：
| 级别 | 模型 | 细节 |
|---|---|---|
| 都城 | 简模城墙（方形围合 + 四面城门 + 角楼） | 墙高 6 单位，暖金瓦顶，城内有极淡暖光透出 |
| 郡邑 | 简模寨墙（方形低围 + 两面门） | 墙高 3 单位，铜色木顶 |
| 关隘 | 两座敌楼夹峡谷，中间一道关门 | 墨灰石质，门前插一杆旗 |
所有城池用 **InstancedMesh**——30 座城 = 1 次 draw call。LOD 三级：近距离 3D 模型、中距离简模、远距离光柱。
