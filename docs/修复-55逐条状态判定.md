## 二、漏洞根因（Q-256 实测漏洞 a）

## 四、逐条判定切分口径

- 条目起始行（`ITEM_START`，`check-problem-finding.py:125`）：`- `、`* `、`+ `、`1. `、`1- `、`B1- `/`Q257- ` 这类字母族+数字前缀、`| ` 表格行。现仓真实条目前缀只有 `数字.` 与 `-`；`*`/`+`/`|` 为兼容保留，现仓无实例。
- 续行并入（`:155-156`）：条目后续的缩进行或非空前缀行并入当前条目正文，不另算新条目；状态词在并入后的整条正文内查找。
- 状态词表（`:40 STATE_WORDS`）：已修、已入队、判废、待裁、已闭环、已处置。空旷豁免（`:42 EMPTY_OK`）：写明「穷举面」/「已穷举」且列出面清单即 PASS，禁「未发现问题」一句话了事。
- 三条判据顺序：① 节存在；② 节内 ≥1 条；③ 逐条含状态词。三条任一不成立即红，判词分别为「缺小节」「节内 0 条」「N/M 条缺处置状态」。

## 十、自查反例 / 改坏推演

- 反例 1（续行被错拆成新条目）：条目正文第二行是缩进行或非前缀续行，`_split_items` 必须并入当前条目（`:155-156`）。若误把续行当新条目，会多算一条缺状态 → 误红；夹具未直接覆盖续行，后续补续行夹具时应回归此点。
- 反例 2（节标题引用误判）：`### 样本 a：「新发现问题」…` 词在引号句中，不算节；`_find_section:140-141` 只认标题前部为该词。若回归到整句 `in` 匹配，引用样例整段会被吞进问题节。
- 反例 3（缺陷号前缀条目）：`Q257-xxx`、`B1-xxx` 这类条目前缀须被 `ITEM_START:125` 识别；只认 `- `/`数字.` 会把缺陷号前缀条目漏切、并入上一条。
- 反例 4（基线洗白改坏）：在册文件内容被改坏后指纹必须不符、重判（`:291-295`）；豁免不能只按路径命中，否则改坏的存量报告会被永久放行。
- 反例 5（空集被当合规）：无报告可判时主流程 `:277` 打 `EMPTY` rc=2，不许判 PASS；trailer 空集同口径降 INFO，git 异常 FAIL。
- 改坏推演：若将来条目出现新前缀（如 `▪`、`– `、`· `），`_split_items` 会把整节并入一条，状态词在整条内查找反而漏判缺状态条目；届时须在 `ITEM_START` 补前缀并加对应夹具。状态词表是封闭集，新处置措辞（如「驳回」「挂起」）不命中会误红，扩词表需同步补夹具。

## 十一、二三阶影响

- 一阶（直接效果）：逐条判定收紧，空条目不再被一条状态词兜底；trailer 空集不再假绿，git 异常不再被空输出掩盖。
- 二阶·误红面：切分口径依赖列表前缀，散文式编号条目、表格内问题、缩进续行存在被错并/错拆的可能；本轮全量实测新判据仅误伤 3 份存量（已豁免），现仓在飞报告写作成本上升——每条问题都要自带在册状态词。
- 二阶·基线膨胀风险：每收紧一次判据就首登一批豁免，基线只许缩小但在册条目存量只增不减；长期若不逐份补状态后剔除，基线会沉淀成永久白名单，逐条判定的收紧意图被豁免架空。棘轮约束：在册文件内容一改坏指纹即失效重判，这是防膨胀的机械闸门。
- 三阶·状态词封闭性：处置措辞超出词表即误红，词表维护需跟报告用语同步；否则报告换个同义词就被拦，值班代理会向词表内挤措辞、掩盖真实处置状态。
- 三阶·trailer 收紧副作用：非 git 目录/沙箱误调脚本会从旧假绿变 FAIL rc=1；CI 环境是完整 git 仓不受影响，本地在非仓目录调用属预期变红。
- 跨模块观察：evidence 门禁另有 118 份历史三件套欠账（Q-256 已记，背景存量，非本单引入，不扩基线洗白）；`check-commit-split.py`、`selftest-baseline.json` 为其他代理在飞改动，本单未触碰。
