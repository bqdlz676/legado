## 1. 方法（四口径，双口径以上交叉证明）

基准 = `res/values/` 全部字符串类键。对每个 name 搜索：
1. `R.string.<n>` / `R.array.<n>` / `R.plurals.<n>`（kt/java/xml，含 main/test/androidTest/debug 全部 source set）；
2. `@string/<n>` / `@array/<n>` / `@plurals/<n>`（XML/Manifest/主题）；
3. `getString(R.string.` 拼接（并入口径1）+ `getIdentifier(` 反射闸：逐调用提取名字面量/类型/包，包为 `android` 的框架资源不触发；
4. `tools:` 与 `?attr` 间接：values* 内 `tools:` 3 处、`?attr/` 0 处，均不指向字符串键。独立复核：反向提取全仓被引用符号与待删清单求差集，零交集；B 类独立口径复核为 0。

## 8. 反例与边界

- 同名不同大小写/前缀子串：扫描用 `\b` 词边界 + 精确 `name=` 匹配，`black` 不会误伤 `c_blacklist`、`bottom` 不会误伤 `padding_bottom`（已人工抽验）。
- 带格式符 `%1$s/%2$d` 的键：删除前同样走四口径；死键中的格式符串随条目整体移除，存活键的格式符未改动。
- 动态拼接/反射：本仓 `R.string.` 无 `${}` 插值；反射仅 dimen/id/integer/mipmap + 一个 android 包 string 查询。若后续出现 app 侧 `getIdentifier(x,"string",pkg)` 动态取键，静态扫描无法排除，脚本会置全局存疑而非判删。
- 测试/debug 源集：已纳入扫描语料，避免只在单测或 debug 资源引用的键被误判。
