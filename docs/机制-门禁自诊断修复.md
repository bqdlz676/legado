# 机制 · 门禁自诊断修复（"所有子检查 PASS，收尾却 GATE: FAIL" 说不出原因）

> 一句话：门禁终结行只会翻一个二进制 FAILED 状态，子检查的退出码和失败明细被 `tail -1` / 二次 `grep` / 空 `FAIL` 分支层层吃掉，导致"全 PASS 却 GATE: FAIL"且没有一行说明是哪一步、哪一条、为什么；本单把判码改成"先落日志、显式取子进程退出码"，并在终结行逐条回列失败清单。

## 一、现象与复现

实跑 `bash data_scripts/pre-push-check.sh > /tmp/g.log 2>&1`，日志逐行出现：

- `REPORT-FIELDS: PASS`、`KOTLIN-LINT: PASS`、`ONBOARD: PASS`、`READONLY-SETTER: PASS`、`GUARD: PASS（含 WARN，需人工核）`、`RATCHET: PASS`；
- 最后一行 `GATE: FAIL（按上面 FAIL 项先补齐）`；
- **没有任何一行 FAIL 说明原因**。

复现确认：门禁退出码为 1，但控制台看不到失败步骤与条目，自诊断失败。

## 二、根因（哪个管道 / 哪个变量吃掉了退出码与明细）

1. **整段门禁输出被 `tail -1` 截断**：旧 `pre-push-check.sh` ⑥ 段先跑 `bash data_scripts/rule-gate.sh 2>&1 | tail -1`，rule-gate 里每个 `bad()` 打出的逐条 `FAIL ⑲锚点卡 …` 明细全部在第一次调用中被 tail 丢掉，控制台只剩终结行。
2. **门禁被跑两遍，原因行排在终结行之后**：旧 ⑥ 紧接着把 rule-gate 第二次跑落 `/tmp/pre-push-gate.log`，再 `grep -E "FAIL" | head -5` 取原因。问题：`head -5` 截断失败清单；多行 FAIL 块（每个条目带若干 `── docs/…` 续行）占满 5 行预算；原因在 `GATE: FAIL` 终结行之后才打印，阅读顺序看起来就是"无原因"；雷达 / 缝合怪 / 锚点全量扫被白白跑两遍。
3. **三个失败分支只翻二进制 `FAILED=1`，不打步骤名**：旧步骤 3（回执证据）、3.5（报告字段）、5（债务棘轮）失败时 `FAILED=1` 后没有任何 `echo FAIL …`；子检查自身输出又被 `| tail -N` 截走，失败后控制台无主可寻。
4. **管道判码口径脆弱**：`if ! cmd | tail -N` 判的是整条管道。实测 `set -o pipefail` 开启时管道能透传子进程非零退出码（`false | tail -3` 管道 rc=1 成立），但该口径依赖隐式 pipefail，且 tail 自身恒退出 0；仓内既有写法（`check-report.sh` 的 `EV/EV_RC`）是先落变量再显式取 `$?`，门禁脚本没沿用。
5. **rule-gate 终结行不汇总清单**：旧终结行只输出 `GATE: FAIL（按上面 FAIL 项先补齐）`，不逐条回列失败步骤；`bad()` 消息内嵌换行时，续行脱离步骤号，tail 截断后变成无主信息；`CUR_FAIL` 变量算出来后从未被读取（死代码）。
6. **退出码语义审计结论**：对 pre-push 各步与 rule-gate 项下全部 python / bash 子检查逐个读源码并实跑核对——真 FAIL 一律 exit 1，WARN / INFO 一律 exit 0；两个刻意 WARN-only 项（㊴ 认证书尾、㉟ 推送窗口）恒 exit 0 不阻断。**语义不一致只出现在 shell 调度层（上面 1–3），子检查本体没有"FAIL 也 exit 0"的情况。**

## 三、修法

### 3.1 `data_scripts/pre-push-check.sh`

- 新增 `run_step <步骤名> <日志尾行数> <命令…>`：子检查输出先落 `/tmp/pre-push-<步骤>.log`，退出码显式取子进程 `$?`，**不经过 tail / 管道判码**；tail 只负责把结论尾行回显到控制台。
- 失败时把 `步骤名｜原因` 追加进 `FAIL_STEPS` 清单：原因从日志里抓 `FAIL / ✗ / ERROR=[1-9]` 行（最多 3 条，换行压平）；抓不到就回写"子检查退出码 N（完整输出见日志）"。
- 门禁 ⑥ 只跑一次，全量输出落 `/tmp/pre-push-rule-gate.log`；失败项从 rule-gate 写出的机读清单 `/tmp/.gate_failures` 读入 `FAIL_STEPS`。
- 终结行：`PRE-PUSH: FAIL —— 失败步骤清单（N 项）` 逐条 `✗ 步骤｜原因`；全绿才 `PRE-PUSH: PASS（可 push）`。WARN 不进失败清单。

### 3.2 `data_scripts/rule-gate.sh`

- `bad()` 同时登记 `FAIL_ITEMS` 数组并写 `/tmp/.gate_failures`（一行一条，`步骤｜原因`）；消息内嵌换行压成空格，续行不再脱离步骤号。
- 终结行：`GATE: FAIL —— 失败步骤清单（N 项）` 逐条 `✗ 步骤｜原因`；`GATE: PASS` 行附带存量留痕跳过计数。
- 删除从未使用的 `CUR_FAIL` 死变量。

### 3.3 回归夹具隔离（测试资产不进真报告命名空间）

- 样本统一放 `data_scripts/fixtures/`，后缀 `.fixture`；`check-onboarding.py`、`check-report-fields.py`、`rule-gate.sh` 三处均加 `is_fixture` 跳过（目录或后缀命中即豁免），门禁常量里不为单个样本开特例。
- 代码夹具只有在被显式传入对应 lint 时才判死；仓内全量扫描只认 `app/src/**/*.kt`，夹具不会被误扫。
