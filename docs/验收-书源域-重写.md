## 6. 二阶三阶影响（连带影响与后果）

1. **外部入口仅靠类名 + Intent extra 耦合**：四个宿主类名保留，10 个外部启动方无需改动即可编译链接；但 extra 键名（`sourceUrl` / `key` / `origin`）属于跨模块隐式契约，一旦后续改名会静默断链。建议后续把这些键名收口到常量（本域未做，避免扩大战场）。
2. **共享资源仍被 RSS 包依赖**：`item_source_edit.xml`、`source_edit` 菜单、`group_manage` 菜单、`item_log.xml` 保留后，`ui/rss` 三包仍走旧 XML 编排；本域删除清单刻意排除这些文件，避免连带打断 RSS 页面。二阶后果：书源域与 RSS 源域短期内架构不一致（一个 Compose、一个旧 XML），维护者需知道两套并存。
3. **状态单向流改造的连带面**：VM 不再持有 View / Adapter 引用，列表刷新全部经 `StateFlow<UiState>`；DAO flow 组合（`SourceManageViewModel.kt:79-121`）在预设 / 关键词 / 排序任一变化时重订阅，过滤与排序在 IO 线程执行。三阶影响：若后续在列表行内引入重计算（如实时校验徽章），需注意 `LazyColumn` 重组频率，当前行卡片为纯渲染。
4. **删除旧 Adapter 后，旧的拖拽排序能力未在 Compose 层接回手势**（详见 §8 未验证项 / 交接）；`vm.move` 方法与 `State.canDrag` 保留，但 UI 未挂长按拖拽。置顶 / 置底 / 手动排序仍可用，条目间自由拖动重排是已知缺口。
5. **对话框复用带来的主题依赖**：`TextDialog` / `VariableDialog` / `ImportBookSourceDialog` 等仍是旧 `DialogFragment`，宿主以 `FragmentActivity` + `supportFragmentManager` 承载；这些对话框内部仍可能读旧主题色，Compose 自绘页面与旧对话框之间存在观感过渡，后续统一对话框域（C7）时需再核对配色。

## 7. 反例与边界（≥3 条，含实现兜底）

1. **空库 / 无匹配 / 无分组**：列表为空时按状态分支呈现——加载中 `InkLoadingDots`；有错误文案走 `InkEmptyState` 错误态；关键词无结果显示 `source_empty_filter`；全空库显示 `source_empty_all` 并给「添加书源」入口。分组被删空后，旧分组筛选回落「全部」（`SourceManageViewModel.kt:131-135`）。
2. **断网 / 在线导入失败 / 源无响应**：在线导入 `okHttpClient.newCallStrResponse` 取空体抛 `NoStackTraceException("在线源无响应")`；导入解析非 JSON / 非 URL 抛「格式不对」；全部经 `onError` 转 Toast 与日志，不静默吞掉。`SourceDebugViewModel.kt:58-60` 抓取异常写入 `error` 横幅并保留重试按钮（`SourceDebugScreen.kt:112-103`）。
3. **字段缺失 / 规则实体为空**：`ruleReview` 可空，装配时 `source.ruleReview?.copy() ?: ReviewRule()`（`SourceEditViewModel.kt:148`）；段评规则整组仅在原有段评非空 / 开关开启 / 有填写内容时才回写（`SourceEditViewModel.kt:261-264`），避免给纯文本源写入空段评块。`maxBatchSize` 非数字时 `toIntOrNull()` 回落 null。
4. **调试通道占用 / 并发冲突**：`Debug.tryAcquireCallback` 失败抛「调试通道占用中」（`SourceDebugViewModel.kt:94-96`）；启动异常时 `Debug.cancelDebug` 释放通道；`onCleared` 兜底释放（`SourceDebugViewModel.kt:130-133`）。校验会话占用时 `Debug.tryStartCheckSession()` 返回 null，Toast「校验正在进行」（`BookSourceActivity.kt:214-218`）。
5. **同名消歧 / 分组名冲突**：分组重命名走 `renameGroupExact(oldGroup, newGroup)` 精确匹配，避免把包含旧名子串的其他分组误改；导出文件名经 `normalizeFileName()` 清洗非法字符。

## 7.1 认知成本（接手视角）

- **新增概念与分层**：本域把旧的「Activity + Adapter + VM + Dialog」四层拆成 `State（纯数据）/ ViewModel（数据变换 + DAO）/ Screen（纯渲染）/ Actions（宿主回调接口）/ Sheets（半屏弹窗）` 五层。新人接手需先认 `SourceManageActions` / `SourceEditActions` / `SourceDebugActions` 三个接口——宿主 Activity 实现接口，Screen 只依赖接口，不直接碰契约与 Fragment。
- **命名澄清**：状态模型内 `selected: Set<String>`（按 url 去重集合）与派生属性 `selection: List<BookSourcePart>`（集合在当前可见 items 中的实体列表）并存，命名相近但用途不同；`preset`（预设枚举）与 `groupName`（分组名）成对出现，读代码时需一起看。`BookSourceSort` 七个枚举值与旧排序菜单一一对应，未另造译名。
- **保留 vs 重写的边界**：`JsSourceEditFlow.kt` 是唯一保留的旧执行层（阶段机），新人容易误以为整包都已 Compose 化；报告 §2.1 已标注其「保留」状态。阶段枚举 `READY/EDITOR_OPEN/SAVING_FOR_DEBUG/SAVING_FOR_LOGIN/DEBUG_READY/DEBUG_OPEN/LOGIN_READY/LOGIN_OPEN` 的跳转链路集中在 `JsSourceEditActivity.kt`，需配合 `restoreAction()` / `afterSuccessfulSave()` 一起读。
- **复杂度变化**：旧 Adapter 内联的行点击、拖拽、角标逻辑被拆进 `SourceManageRow.kt` + `SourceManageSheets.kt`，单文件行数上升（Sheets 604 行），但单组件职责单一；弹窗从 AlertDialog / PopupMenu 统一收口为 `ManageSheet` 密封类 + `InkHalfSheet`，新增弹窗只需在密封类加一个数据类型并在 `ManageSheets` `when` 分支补一处。
- **潜在认知负担点**：域内仍调用一批旧执行层对话框（`TextDialog` / `VariableDialog` 等），新人会看到 Compose 与旧 Fragment 混用；这是过渡期现状，统一归 C7 批次（见 §9）。
