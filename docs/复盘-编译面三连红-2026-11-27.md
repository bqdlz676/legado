## 一、逐次红复盘（原文 / 触发条件 / 根因）

### ① ShellBottomBar.kt：BoxScope 成员扩展被写成顶层 import

CI 日志行（hint 取证，工作树已修复）：

```
e: file:///.../ui/main/shell/ShellBottomBar.kt:14:43 Unresolved reference 'matchParentSize'.
```

- 触发条件：手写 import 段时把 `matchParentSize` 当成普通顶层扩展函数补了一行 `import androidx.compose.foundation.layout.matchParentSize`。
- 根因：`matchParentSize` 是 `BoxScope` 成员扩展，包内不存在可导入的顶层声明；它只在 Box 内容 lambda 内由隐式 BoxScope 接收者解析，本来就不需要 import。写 import 反而让编译器按顶层符号解析，报 Unresolved reference。
- 当前回源：`app/src/main/java/io/legado/app/ui/main/shell/ShellBottomBar.kt:146` 调用点 `.matchParentSize()` 裸写在 Box 内容 lambda 内；import 段（3–35 行）已无该符号。

### ② B3SettingGroups.kt：非 Composable lambda 内调 stringResource（11 处）

CI 日志行（hint 取证，工作树已修复）：

```
e: file:///.../ui/config/b3/B3SettingGroups.kt:78:41 @Composable invocations can only happen from the context of a @Composable function
```

同文件 94/169/171/189/191/210/212/264/280/296 共 11 处同类报错。

- 触发条件：`onClick = { ... }` 事件 lambda 体内直接调 `stringResource(R.string.…)` 取标题/提示文案。
- 根因：`stringResource` 是 @Composable 函数，只能在 @Composable 上下文调用；事件 lambda 形参类型是普通 `() -> Unit`，运行在非 Composable 上下文，编译器按上下文约束判红。修法是把标题/提示提到 composable 作用域先取成 val，事件 lambda 内只引用 val。
- 当前回源：`app/src/main/java/io/legado/app/ui/config/b3/B3SettingGroups.kt:68` 起 `themeModeTitle` 等 11 个 val 在 composable 作用域取值；`onClick` 体（:88/:104/:126/:178/:198/:219/:274/:290）只引用 val 与动作回调。

### ③ MainShell.kt：tween 裸类型参数，声明处无使用点推 T

CI 日志行（hint 取证，工作树已修复）：

```
e: file:///.../ui/main/shell/MainShell.kt:93:20 Cannot infer type for type parameter 'T'. Specify it explicitly.
```

- 触发条件：`val fadeSpec = tween(durationMillis=…, easing=…)` 把动画 spec 工厂调用放在 val 声明 RHS，工厂泛型 `<T>` 没有任何使用点可以推型。
- 根因：`tween`/`spring`/`snap` 等工厂签名是泛型 `AnimationSpec<T>`；作为外层调用实参时 T 由外层形参类型推断，而独立声明 RHS 上既无显式 `<T>`、val 又无类型注解，编译器找不到推型来源。修法 `tween<Float>(…)`。
- 当前回源：`app/src/main/java/io/legado/app/ui/main/shell/MainShell.kt:94` 现为 `val fadeSpec = tween<Float>(durationMillis = duration, easing = ComponentTokens.pageTurnEasing)`。

## 二、共同根因：为什么 kotlin-syntax-lint.py 全 PASS 仍会红

1. **既有 lint 的判据面是文本层形态**：`data_scripts/kotlin-syntax-lint.py:477` 聚合的 S1 括号配平、S2 条件尾逗号、S3 fontFamily 直传、S4 新文件行数、S5 错包、S8 符号出处、S8b 扩展属性、S7 可见性，全部只看字符与声明文本。
2. **三类红发生在编译器的另外三张表上**：接收者作用域解析表（①）、Composable 上下文约束（②）、泛型推型来源（③）。这三处错误语法树合法、符号拼写合法、括号配平，纯文本 lint 没有这三张表可比对，故全 PASS 仍会红。
3. **结构性缺口是「本地无编译链 + 静态 lint 假绿」**：本仓沙箱禁本地编译，本地唯一信号是静态 lint；而 lint 判据与编译器判据不重合，lint PASS 被误当成编译承诺，假绿一路带到 CI 才炸。
4. **既有闸为什么没兜住**：⑫ `check-ext-imports.py` 查的是「扩展函数漏 import」，方向与①相反——① 是「import 了根本不存在的顶层符号」；⑬ `check-test-source.py` 的 R5 泛型推型只在 test 目录提示 `springFor`；② 的 Composable 上下文校验此前无在册闸。三类各有盲区，合起来就是本轮缺口。

## 四、反例与边界（改坏推演：新闸会不会误报合法形态）

1. **BoxScope 内合法调用 `Modifier.matchParentSize()`**：规则 A 只查 import 行、不查调用点；调用点在 Box 内容 lambda 内由 BoxScope 隐式接收者直接解析，裸写合法。
2. **`stringResource`/`remember` 在 @Composable 帮助函数内或 composable 作用域 val 初值里**：规则 B 只进事件 lambda 花括号体判定；`B3SettingGroups.kt:68` 的 `val themeModeTitle = stringResource(...)` 属合法作用域取值，放行。
3. **泛型可推时无需显式类型参**：作为外层调用实参（如 `animationSpec = tween(...)`）T 由外层形参类型推断；声明带类型注解（如 `: AnimationSpec<Float>`）也可推。规则 C 只抓「val/var RHS、无类型注解、工厂调用又无 `<T>`」的裸声明形态。
4. **撞名本地辅助函数**：纯 JVM 测试里的 `private fun snap(...)`/`spring()` 与 Compose 工厂同名，文件未 import `androidx.compose.animation.core` 时规则 C 整文件跳过，本地 fun 声明名再剔除一遍；selftest 边界样本已覆盖。

已知边界（保守放过方向，不做过度判定）：

- 事件 lambda 形参本身被声明为 @Composable 类型（本仓未现）：脚本不解析形参类型注解，按漏报方向放过，不误杀。

## 五、认知成本

- 新人接手最大的坑不是代码复杂度，而是把「lint PASS」等同于「编译能过」：两者判据不重合，编译器的接收者作用域表、Composable 上下文约束、泛型推型来源在纯文本层不可见。
- 一句话可记：scope 成员不 import、事件 lambda 不调 Composable、裸声明动画 spec 要显式类型参。
- 新增这类闸的前提是宁漏勿误报：一旦出现假报，闸门会被绕过，可信度归零；故名单与触发形参名全部可配、表注写明判定依据。
