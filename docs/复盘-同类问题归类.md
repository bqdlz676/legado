## 使用方式（开工自检顺序）

1. 先看 A 族：今天要改的代码有没有"本地验不了"的（测试名、路径前缀、陌生 API、结构约束、双源）——四条静态检查先跑。
2. 再看 C 族：今天有几个代理并发 git、今天是不是又连续 push（→ 攒批）。
3. 派单按 B 族模板写（三条 ANCHOR-ACK + 单一交付物）。
4. 收口按 D 族三件套（E1/E2/E3）+ 锚点卡路径 + 现跑行号。
5. 口径冲突按 E 族：先查裁决文件，没有裁决就按 C8（最新指令 + 工程现实/史实）。
