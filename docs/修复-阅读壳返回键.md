## 4. 二阶三阶影响推演（铁律 59）

### 4.1 直接效果

- 阅读页按返回键 / 系统手势导航滑动返回时，先消化页内覆盖层（气泡 → 朗读暂停 → 禁返键），
  无可消化覆盖层才 `finish()` 回书架；行为与旧壳一致。
- 时间轴页返回显式收口到 `finish()`。

### 4.2 连带影响（被影响的文件 / 接口 / 调用方）

- **`ReaderShellHost` 接口 +1 抽象方法**：全仓具体实现仅 `InkReadController`；
  `InkReaderShell.kt:71` 的 `object : ReaderShellHost by host` 委托自动转发，无需手写；
  测试假实现 `GestureRouterTest.FakeHost` 已补 override（§2.7）。已 grep 确认无第三处实现者。
- **`InkReadController` 新增依赖**：`getPrefBoolean`（SharedPreferences 内存读取，无新 I/O）；
  朗读仍走既有 `onReadAloudToggle` 回调，不直接碰 Service 生命周期。
- **`InkReaderShell` 状态镜像**：新增一条 `bubbleContent → state` 同步 effect；
  既有 `pageTick/scrollTick` 关气泡逻辑不变。
- **`GestureRouter` 新增 `onBack` 槽位**：当前无屏内右滑手势触发它；系统手势返回走分发器。
  该槽位是后续屏内返回手势的唯一接入点。

### 4.3 二阶 / 三阶后果

- **二阶**：后续新增页内覆盖层（章内搜索、阅读设置半屏、选词典藏面板）时，必须在
  `InkBackResult` 枚举里插一个层级并在 `handleBack()` 按栈顶顺序裁决；不能在 Activity 或
  手势层另写 `if (overlayVisible) ...`。否则会重现旧壳回调 if 链随覆盖层增多而漂移的问题。
- **二阶**：气泡关闭路径从「仅点空白 / 翻页 / 跳转」扩到「返回键」；壳侧镜像同步 effect
  保证 `bubbleState` 不留锚点，气泡墨爆 / 尖角定位不会在下次出气泡时复用旧坐标。
- **三阶（维护成本）**：裁决层级集中在控制器一处，新增覆盖层只改一个函数 + 一个枚举值；
  代价是接手者必须知道 `InkBackResult` 四态与栈序（§8 认知成本已评估，约 60 行可读上下文）。
- **三阶（用户行为）**：朗读播放中按返回不再直接退书，而是先暂停——与旧壳一致，
  避免用户误触返回把朗读服务晾在后台；气泡浮着时按返回先收气泡，不丢阅读位置。

## 5. 反例与边界（铁律 61，最强反对者视角）

### 5.1 边界逐条行为（13 条，≥ 任务要求 8 条）

1. **半屏详情 Sheet 开着**：Sheet 是 `InkHalfSheet` 的 `Dialog` 窗口
   （`InkHalfSheet.kt:153–159`，`DialogProperties(usePlatformDefaultWidth = false)`，
   `dismissOnBackPress` 取 Compose 默认 true）。系统 BACK 先分发到 Dialog 窗口的
   `onDismissRequest`（`InkBubble.kt:306` `{ sheetOpen = false }`），Activity 回调不可见；
   Sheet 关掉后气泡仍在，第二次返回再走层级 1 关气泡。
2. **气泡开着**：`bubbleContent != null` → `dismissBubble()` → `BubbleDismissed`，
   页内消化，不退出；壳侧镜像由 §2.4 effect 同步清空。
3. **章节加载中**：`chapterBody` 空串、`engine == null`。`handleBack()` 不触碰引擎与正文，
   气泡必为 null，直接落朗读 / 偏好 / 退出分支；`finish()` 不崩。
4. **目录抽屉开着**：目录经 `tocLauncher` 拉起独立 `TocActivity`（旧壳 Activity），
   返回由该 Activity 自己消费；阅读壳回调在 TocActivity 处于 resumed 时不触发。
   新壳内不存在 Activity 内目录抽屉。
5. **通知 / 外部 Intent 冷启动**：`singleTask` 启动，`onCreate` → `viewModel.initData(intent)`；
   缺 `bookUrl` 时 `refreshFromReadBook()` 已按 `?: intent.getStringExtra(...).orEmpty()` 兜底；
   返回走 `ExitToShelf → finish()`，不崩。`onNewIntent` 二次 Intent 重接缺口见交接 #2。
6. **书未打开（空数据）**：`ReadBook.book == null`；`handleBack()` 不读 `book` 字段，
   各判空既有兜底；`finish()` 安全。
7. **朗读播放中**：`BaseReadAloudService.isPlay()` 为 true → `onReadAloudToggle`
   （实现内 `isRun` 时 `ReadAloud.pause`）→ `ReadAloudPaused` + toast `read_aloud_pause`，不退出。
8. **「禁用返回键」偏好开启**：`getPrefBoolean("disableReturnKey")` 为 true 且无气泡时
   → `ReturnKeyLocked`，消费返回、不退出（对齐旧壳 631–633；旧分支「菜单不可见」条件在新壳无对应物，不搬）。
9. **半屏 + 气泡同时开**：两次返回依次消化——先 Dialog 关 Sheet，再层级 1 关气泡。
10. **朗读中 + 气泡开**：先关气泡（层级 1 优先），再按一次返回暂停朗读；栈顶先消化。
11. **翻页动画进行中按返回**：`handleBack()` 不查翻页动画位；关气泡 / 退出不被掀角动画屏蔽
    （旧壳返回同样不被翻页动画拦截）。动画期间的翻页 / 气泡屏蔽仍由 `PageTurnGate` / `isPageAnimating()` 管。
12. **快速连按两次返回**：第一次按当前状态裁决并消化覆盖层；第二次按更新后的状态重新裁决，
    不存在「一次回调连跳两级」。
13. **时间轴页冷启动 / 缺 year extra**：`InkTimelineActivity` extra 缺省回退锚点年 / 基准 1950
    （`InkTimelinePresenter.shiftYear` 既有兜底）；返回 `finish()` 回阅读壳，不出空白态。

### 5.2 最强反对者：可能推翻本方案的反例与否证结论

- **反例 A：半屏 Dialog 的返回真的到不了 Activity 回调吗？**
  依据：Dialog 是独立窗口，BACK 先经 Dialog 窗口 `OnCancelListener`；Compose `Dialog`
  默认 `dismissOnBackPress = true`。**残余风险**：若 Compose 升级改默认值或组件显式传 false，
  Sheet 会漏到 Activity 回调；当前 `InkHalfSheet.kt:156` 未传该参数。结论：静态依据成立，
  运行时行为列入 §9 未验证项。
- **反例 B：会不会挂上两套返回处理器双消费？**
  本单只在 Activity 分发器挂一个回调；Compose 壳内**未**挂 `BackHandler`；
  `GestureRouter.onBack` 只是同一函数的委托入口，不注册独立回调。结论：无双注册。
- **反例 C：接口加方法会不会漏掉其它实现者导致编译断裂？**
  已 grep 全仓：main 具体实现仅 `InkReadController`；shell 用 `by host` 委托；
  test 仅 `GestureRouterTest.FakeHost`，已补 override。结论：无第三处遗漏。
- **反例 D：朗读分支复用 toggle 回调，会不会在暂停态误触发播放？**
  进入该分支前已判 `isPlay()`（= `isRun && !pause`）；Activity toggle 实现内
  `isRun` 时走 `ReadAloud.pause`，不会反向 `play`。检查与 invoke 之间的状态翻转属极小竞态，
  旧壳同构（判 `isPlay()` 后直接 pause）。结论：不成立。
- **反例 E：偏好键名漂移，读了个没人写的死键？**
  旧壳 `ReadBookActivity.kt:689` 与 `pref_config_read.xml:285` 同键 `disableReturnKey`；
  常量收口在控制器 companion。结论：键名同源。
- **反例 F：空数据退出会不会丢阅读进度？**
  新壳 `onPause/onStop` 未调 `ReadBook.saveRead()`（旧壳 `onPause:771` 有），这是既有进度
  持久化缺口，非本单返回链路引入；按 R57 不扩修，记入交接 #3。

### 11.1 跨领域对照（铁律 60）

- **Android 导航返回栈（OnBackPressedDispatcher 回调链，LIFO 顶优先）**：本实现同构——
  覆盖层栈顶（气泡）先消化，消化完才退到下一层，最后出栈 finish。采纳：单一裁决函数按栈序判。
- **桌面 / Web 模态弹窗栈（ESC 先关最上层 modal）**：半屏 Dialog 自消费返回同构；
  采纳：Dialog 层不进 Activity 裁决，避免双层判重。
- **不采纳的方案**：Compose `BackHandler` 与 Activity 回调并行注册两套——两套回调在
  dispatcher 链上的先后顺序难推理，覆盖层状态容易各判一份漂移（正是铁律 63 要避免的）；
  本单只保留分发器一套，Compose 侧不挂第二处理器。
