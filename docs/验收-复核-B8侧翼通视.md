## 六、认知成本

- 接手者需新理解 3 个概念：`FlankRoute`（路径 + 降级标志 + 原因，`:275-279`）、`strictView` 双模式 A*（`:102 / :130`）、`watchedBy` 两段式视野口径（`:148-151`）。命名自解释；`reason` 字符串只作调试 / 断言，不参与分支。
- 两层入口职责清晰：`flankPath`（List，兼容旧调用方）委托 `flankRoute`（带标志）；旧调用方只看到一个带默认值的新增形参，阅读成本低。
- 历史包袱排查：旧 `stepCost` 内联视线判定已上移为纯函数，未保留「只加价」兼容分支；`VISIBILITY_PENALTY` 保留是退化模式代价诱导所需，不是兼容层残留（`grep` 全仓仅 `:166` 一处消费）。
- 潜在混淆点：`CampaignController.octile` 名实不符（曼哈顿）；新接手者容易把它当真八向口径复用，建议别单正名或修正实现（R3）。
- 遗留双表：半径表在两处各持一份，认知上需要记住「两处同步」，收敛到 model 层单一来源后成本最低（R1）。
