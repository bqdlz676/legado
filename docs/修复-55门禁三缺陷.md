### 2.1 缺陷①：传相对路径参数时 `relative_to` 抛 ValueError 崩溃

- 现象：`python3 data_scripts/check-problem-finding.py docs/修复-xxx.md` 直接崩在 `p.relative_to(ROOT)`，报 `ValueError: 'docs/...' is not in the subpath of '.../legado'`；外部绝对路径同理。
- 根因：命令行参数只包了 `pathlib.Path(a)` 未 resolve，随后在失败消息与豁免比对里反复 `relative_to(ROOT)`；不在 ROOT 子树时该方法必然抛错，脚本没有兜底。
- 改法：
  - `:37-39` `_resolve_target`：参数先 `pathlib.Path(arg).resolve()` 成绝对路径，read_text 不再依赖相对 cwd。
  - `:42-46` `_rel`：先尝试 `relative_to(ROOT)`，捕获 `ValueError` 后原样返回字符串，落盘打印不崩。
  - `:158` targets 解析改用 `_resolve_target`；`:172` 不可读消息、`:175` 豁免比对、`:179` 命中消息全部改用 `_rel`。

### 2.2 缺陷②：`git status` 重命名行按 `line[3:]` 取到旧路径

- 现象：porcelain 重命名行形如 `R  docs/old.md -> docs/new.md`；原解析 `line[3:].strip()` 得到 `old.md -> new.md`，`NAME_RE` 不匹配，改名后的新报告漏出扫描。
- 根因：第 1~2 列是状态码、第 3 列是空格，普通新增/修改行取第 3 列后内容成立；重命名行第 3 列后是 `old -> new` 整串，必须取箭头右侧。
- 改法：
  - `:50-55` `_status_path`：先取 `line[3:]`，含 ` -> ` 时 `split(' -> ', 1)[1]` 取新路径；最后剥掉 porcelain 给特殊字符路径加的成对 `"` / `'`。
  - `:81` 工作区扫描循环由原 `line[3:].strip()` 切换为 `_status_path(line)`。
- grep 回证：

### 2.3 缺陷③：基线幽灵路径不剔除、无提示

- 现象：`problem-finding-baseline.json` 里若登记了已被删除/改名的历史报告，该路径仍留在豁免集；既不判红也不提示，基线只能靠人工记得缩。
- 根因：主流程直接 `set(json.loads(...))`，没有做存在性核对；豁免集与磁盘现状脱钩。
- 改法：
  - `:59-63` `_prune_baseline`：以 `root / e` 是否实存分桶，`ghosts` 为幽灵列表、`kept` 为现存列表，均排序返回。

## 六、二阶三阶影响与边界

- 二阶：`_resolve_target` 统一 resolve 后，相对 cwd 的软链/别名路径也能正确定位；`_rel` 兜底只影响消息打印，不改变豁免比对口径（比对仍用规范化后的相对路径）。
- 二阶：R 行取新路径后，改名报告若缺「新发现问题」节会被正常判红；旧路径不再残留进候选集。
- 三阶：基线剔除只缩不扩，幽灵条目不会被新一轮判定"洗白"；但 json 不自动回写，跨轮次仍可能堆积幽灵名，需配合问题 2 的持久清理。
- 边界：未接 rule-gate.sh 改动、未跑云端 CI；脚本仅本机 python3 实跑与 /tmp 夹具自测；NAME_RE 覆盖的报告前缀族未变。
