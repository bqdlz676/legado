# 铁律 · 缝合怪清理（F-86，门禁 ⑳）

> 用户原话：「把清理缝合怪的工作也要写进铁律机制」。
> 什么是缝合怪：同一能力上拼了两套或多套实现/技术栈，新旧同时活着，或规格要 A 而代码是 B。它不是形容词，下面六种形态均可 grep 机械判定。
> 为什么立这条：缝合怪是 CI 红灯、口径漂移、返工的三重源头；它还让"规格逐字对照"失效——代码里根本没有规格那套实现，验收无从回源。
> 适用条件：`app/src/main/java`、`app/src/main/res` 全部源码与资源；文档/脚本域不在本铁律扫描范围。

## 一、六种可机械判定的形态

### 形态 1 · 双轨并存（同能力两套实现都活着，主链路同时可达）
- 判定命令：`grep -rln "<旧栈关键词>" app/src/main/java` 与 `grep -rln "<新栈关键词>" app/src/main/java`，两边均非空，且旧侧有外部调用点（`grep -rn "import .*<旧包>" app/src/main/java`）。
- 为什么算：同一能力两套代码并行维护，改一处漏另一处，行为口径分裂；典型旧 `help/sim/` 与新 `ui/map/crossing/engine/` 同名解析器并存。
- 适用条件：新旧两侧都在编译进包、且至少一侧能从主链路到达；纯死代码（零引用）归形态 3/6 处置。
- 豁免条件：为兼容旧版本数据必须保留的解析层可留，但必须在 `docs/台账-缝合怪.md` 写明理由与下线条件；无台账条目不豁免。

### 形态 2 · 规格一套代码另一套（切片要求 A 技术栈，代码是 B）
- 判定命令：先读规格切片原文取技术词（如 `Canvas`、`排序数组+二分`、`CardTokens`），再 `grep -rn "<B 侧关键词>" app/src/main/java app/src/main/res` 命中实现侧；两侧技术词不一致即成立。
- 为什么算：规格逐字对照在代码侧找不到对应物，验收代理只能"按记忆验收"，返工与漂移必然发生；典型 D14 规格要自绘 Canvas 环形长卷，代码是 cytoscape+WebView 力导向。
- 适用条件：切片原文有明确技术栈/数据结构要求，而实现命中的是另一套；规格本身允许的备选实现不算。
- 豁免条件：切片标注"候选/待选型"尚未拍板的，登记台账标"待规格化"，不算本形态违规。

### 形态 3 · 兼容层残留（Compat/Legacy/Old/V2 仍在主链路被调用，迁移已完成）
- 判定命令：`find app/src/main/java -name "*Compat.kt" -o -name "*Legacy.kt" -o -name "*Old.kt" -o -name "*V2.kt" -o -name "*_old*"`，再对每个类名 `grep -rn "<类名>" app/src/main/java` 找自身文件之外的调用点。
- 为什么算：新实现已可用而旧壳还挂在调用链上，等于永久保留两套入口；名字带 V2/Legacy 却无人退役，是历史包袱堆积口。
- 适用条件：新实现可运行且已被主链路调用；若新栈尚未接管，属过渡态，登记台账留档。
- 豁免条件：外部生态依赖（如书源 JS 桥接接口）短期无法迁移的，留档并写下线条件；纯内部过渡壳不许豁免。

### 形态 4 · 职责混装（单文件跨 3 个以上域，或行数超阈值）
- 判定命令：`find app/src/main/java -name "*.kt" -exec wc -l {} +`；阈值依据：本轮普查 1368 个 kt 文件，p50=100 行、p90=430、p95=565、p99=1196；≥600 行（≈p95）列候选，≥1200 行（≈p99）列重点。
- 为什么算：大文件是双轨与贴皮的藏身地——域边界消失后，旧逻辑改不动只能往里贴新皮肤；行数是弱信号，须结合"跨域数"人工定级。
- 适用条件：行数超阈仅作门禁提示（不单独 FAIL）；混装定性还要看文件内是否跨 3 个以上域（数据/引擎/UI/资源等）。
- 豁免条件：框架生成门面、协议解析器等天然大单文件，留档注明域边界，不拆。

### 形态 5 · 贴皮实现（只改外观不改结构，旧逻辑+新皮肤靠 flag 切换）
- 判定命令：同一文件内同时出现新皮肤调用（新 token/新 Compose 组件）与旧逻辑分支，且存在 flag/版本判断 `grep -nE "if.*[Ff]lag|BuildConfig|isNew|legacy"` 分隔两套路径。
- 为什么算：贴皮让外观验收通过而结构未换，下一轮改结构时新旧互相牵制；flag 一旦长期存在就变成永久双轨（归入形态 1）。
- 适用条件：新皮与旧逻辑同处一条调用链；纯一次性 A/B 实验且有下线日期的不算。
- 豁免条件：无（贴皮不许留档）；只能按四步工序换成单一实现。

### 形态 6 · 半成品分支/文件残留（wip 分支、标 FAIL 未收口产物、@Deprecated 仍被调用）
- 判定命令：`git branch --list 'wip/*'`；`grep -rn "@Deprecated" app/src/main/java` 后逐个查调用点；台账无登记的 FAIL 标记产物。
- 为什么算：半成品不冻结不清理，会被误 cherry-pick 回 main；废弃符号仍被调用等于旧实现没退役。
- 适用条件：分支未合 main 且无验收结论；Deprecated 符号在主源码仍有外部调用点。框架 API 自带的 `Deprecated in Java/Drawable` 弃用注解不算本形态。
- 豁免条件：存档备查分支（如 WIP 存档 commit）可留档，登记分支名/commit 与收口下线条件；已无调用点的 Deprecated 符号随清理工序物理删除。

## 二、清理工序（四步，写死不许跳）

1. **普查建档**：每处一条入 `docs/台账-缝合怪.md`，字段固定——位置（`文件:行`）/ 形态（六种之一）/ 成分（哪几套东西拼的）/ 风险（会导致什么故障）/ 处置（拆 / 合 / 迁 / 删 / 留+理由）/ 状态（待处理 / 处理中 / 已清 / 留档）。
2. **定序**：阻断交付 > 影响性能 > 影响观感 > 仅整洁；同序内按影响面排序。
3. **清理执行（顺序硬约束）**：先接新实现（可运行、被调用）→ 切所有调用点 → 组合验收与单测过 → 再物理删旧。禁止先删后接；禁止留"旧格式兼容层"当兜底；禁止加 `@Suppress` 掩盖。
4. **回填证据**：每处清完，台账标"已清 + 证据三件"：`grep -rn "<旧符号>"` 0 命中、CI run 绿、受影响的组合验收/单测通过。

## 三、机械门禁 ⑳

- 脚本：`data_scripts/check-frankenstein.py`，扫 `app/src/main/java` 与 `app/src/main/res`，自动判形态 1/3/4/6 中可机械判定的部分；形态 2/5 由台账人工定级，门禁反查台账是否在册。
- 输出：五类命中计数 + 逐条 `文件:行` + `FRANKENSTEIN: PASS/FAIL`。
- 豁免反查：任何"留档/已清"必须能在台账找到对应条目；代码或台账自报豁免而台账无条目者，仍判 FAIL（防自己给自己豁免）。
- 与铁律 57 分工：57 防"一个代理做多件"（横向打包），本条防"一件里拼多套"（纵向双轨）。
