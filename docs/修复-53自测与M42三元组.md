## 五、M-42 三元组豁免键口径

- 键三槽：相对路径（`data_scripts/<文件名>`）+ 变量名（空集条件里的待检集合名，如 `files` / `commits`）+ 分支块指纹。

- 夹具 5（全等豁免）`:329`：用夹具实扫得到的 `(file, var, hash)` 构 `exact_map`，重扫命中 `allow=True`，不入 FAIL 桶。

## 八、自查反例 / 改坏推演

- 反例 1（夹具污染真仓）：若 selftest 直接写 `WF_DIR` / `TEST_DIR`，临时 yml/kt 会混进真仓目录，后续门禁结论不可复现。实现：三判据函数全部目录参数化，夹具只在 `tempfile.mkdtemp` 下读写，`finally` 自删；跑完 `git status --porcelain .github app/src/test` 为空，`/tmp` 无残留目录。
- 反例 2（豁免被放宽成前缀匹配）：若查表退回"路径在豁免名单里"或 `startswith`，同名文件另一处坏分支、甚至改名新文件都能蒙过。实现：`:188` 字典整键 `(rel, var, digest)` 相等；夹具 7 证明同路径不同变量名不豁免；代码注释明令禁前缀 / 目录级匹配。
- 反例 3（正文漂移仍被豁免）：若指纹只锚路径或行号，上下增删行 / 改一个标点都会错配。实现：指纹取条件行 + 分支体正文拼接；夹具 6 仅加一个句号即失配判红。
- 反例 4（夹具绿样本被红样本连带误判）：混合临时目录里同时有红、绿夹具，若判据按目录整体放行或整体判红，绿样本结论不可信。实现：夹具 c 在混合目录内先排除 `deploy.yml` / `Deploy Unit` 出现在问题清单，再用第二个独立临时目录复跑全绿通路。
- 反例 5（空目录 / 缺目录）：`workflow_names` / `check_contract_paths` 入口均先判 `is_dir()`，缺目录返回空清单而非异常；夹具目录结构由 `mkdir(parents=True)` 保证。
