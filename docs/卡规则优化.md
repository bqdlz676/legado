# 卡规则优化（依据三份报告的硬证据）

> 依据：`docs/规则全集.md`（269 条规则 + 事故血缘）、`docs/规则形成史.md`（50 条事故 → 规则映射）、`docs/项目总结报告.md`（通读 471 份文档后的判断）。每条优化都标了它由哪个数字推出，不凭空加。
> 原则：只改新规则（W/V 卡这套），不改旧代码、不改历史台账；有冲突的按"后面（最新）指令与工程现实为准"。

## 二、卡字段层（4 项）

**O-01 加"不做边界"字段（P0）**
证据：缝合怪台账 9 条、D23 现状修复整项、报告 §3.5 指出双轨与贴皮并存。
改法：W 卡增加一列`不做边界`，必须写"本卡不碰哪些文件、不做哪类顺手重构"，空着不许冻结。
落地：`docs/写码卡.md` 表头 + 卡冻结判据。

**O-02 加"规格出处"字段（P0）**
证据：`台账-前置设计费.md` 两条返工（BookCard / TopicCard）根因都是凭记忆转述规格，分享卡三背景 lerp `0.35/0.12/0.10` 记岔。
改法：`判据锚点`之外再要`规格出处`（切片文件名 + 行号），锚点管"怎么验"，出处管"照哪段写"。
落地：W 卡表头。

**O-03 把"边界兜底四条"做成卡字段（P0）**
证据：项目规则第 2 条明确"空数据、断网、缺年份、消歧失败必须给迂回方案，不允许空白态"，现有 36 张卡里没有任何一张写了这四条。
改法：W 卡增加`边界兜底`，四条逐条写一句，缺一条不许冻结；纯数据层卡可写"不适用 + 理由"。
落地：W 卡表头 + 验收卡核对项。

**O-04 加"来源标注"：每条新规则必须写它是口令、事故、拍板还是推理（P1）**
证据：备案线 30 条追不到上游、形成史 30 条无事故支撑。
改法：卡上新立的任何约束，在说明里带`来源：口令/事故/拍板/推理`；`推理`档只作提示，不许当阻断门禁。
影响：直接压低"拍脑袋规则"的权重，与下文 O-13 配套。
落地：卡说明区 + 规则总账新增条目。

## 三、判据与验收层（4 项）

**O-05 判据上限从 4 降到 3，且一句一判（P0）**
证据：A 族 11 例判废，根因是判据条数与跨度过多导致代理"讲过程不讲结论"；本轮重派时把判据压到 3~4 条、回执限 5 行后一次通过。
改法：`判据条数`列上限 3；一条判据只许覆盖一个可 grep/可跑的点，禁"并且/同时"这种复合句。
落地：`docs/验收卡.md` + 判废链规则。

**O-06 验收卡加"回执行数上限"与"结论前置"（P0）**
证据：同上 A 族；退化案例是回执几百行无意义噪声。
改法：V 卡写明`回执 ≤N 行，第一行必须是结论（过/不过 + 一句原因）`；超行数直接判废，不看内容。
落地：V 卡表头。

**O-07 新增"退化检测"门禁（P1）**
证据：报告明确指出"存活门禁能拦零工具调用，但退化重复串无机械识别，只能人工兜底"。
改法：新增门禁项，判三条：输出体积超阈值、同一句重复 ≥5 次、回执行数超 V 卡上限 → 自动判废并记 A 族事故。
落地：`data_scripts/check-agent-degeneration.py` + 门禁表。

**O-08 判据分级：机械可判阻断，观感只提示（P1）**
证据：观感验收靠真机，机械判不了；报告 §3 指出美学项没有机械锚就只能人眼。
改法：判据分两类，`机械`类不过即 FAIL；`观感`类写进 V 卡的"机械+真机"方式，结论记`过（待真机）`或`不过`，不进 CI 阻断。
落地：V 卡`验收方式`列口径。

## 四、流程层（4 项）

**O-09 补一类"删旧卡"（P0，最重要）**
证据：旧 UI 610 文件 / 119,421 行仍可达生产链路；现有 36 张卡里一张删旧卡都没有——铁律 A3 说"先接好再删旧"，但卡表只切了"接"，没切"删"。
改法：按 Compose 页面落地进度逐域加删旧卡（每域一张，判据用"该域旧 XML/Binding/Activity 引用数 = 0"），形成"接一张→删一张"的配对节奏。
落地：`docs/写码卡.md` 追加 W-037 起若干张（先按 ui/ 一级域切：read、bookshelf、explore、setting、card、tool）。

**O-10 三写两验要一起改三处读数，不许只改档位（P0）**
证据：规则逻辑链点出四个断裂点：⑨档位 4 写 1 查、⑱队列寿命、㉚队首推进、E2 未验收先推。
改法：一次性改完四件事，否则 3 写 2 验跑不起来：档位改 3+2、⑱ 删寿命判、㉚ 废、E2 废（改为批次全过才推）。
落地：`并发档位.md`、`check-dispatch-queue.py`、`check-queue-running.py`、`pre-push.sh`。

**O-11 计数改读卡表，旧源缺数据必须报红（P0）**
证据：报告 §3.4 记"旧栈三套计数并存"，同一次问能得出 160 / 141 / 81 三个数；机制体检 C1 也记过"一次门禁吐 4/6/0/7"。
改法：⑥在飞计数、⑯台账新鲜度、`queue_stats.py` 改读卡表；旧源读不到时 FAIL 而非静默 0——静默 0 比报红更危险。
落地：三个脚本。

**O-12 待取长期不报红，但要写"阻塞原因"（P1）**
证据：⑱ 与卡模型的正面对撞点——卡上"前置未做"是合法等待。
改法：卡待取超过 3 轮不报红，但必须填`阻塞原因`（等哪张卡、等哪个锚点、等哪个拍板）；空着才报红。
落地：W 卡加`阻塞原因`（可空）。

## 五、制度层（3 项）

**O-13 一条新规进门四步，缺来源只算建议（P1）**
证据：269 条规则、39 项门禁里，30 条无事故支撑、30 条追不到上游。
改法：新规进门固定四步：①写来源（口令/事故/拍板/推理）→ ②写证据（文件:行 或事故号）→ ③写机械判据 → ④接门禁。只到③没到④的，标`提示`不标`阻断`。
落地：规矩总纲 M5 节 + 规则总账新增`强度`列（阻断/提示）。

**O-14 文档分"在役 / 归档"两区，卡只引用在役（P1）**
证据：471 份文档的认知成本；报告建议"过程记录在缺陷关闭后归档，权威台账只留最新结论"。
改法：`docs/` 下分 `docs/在役/` 与 `docs/归档/`，卡只许引用在役文档；归档区只读、不参与任何门禁计数。
落地：目录迁移（高风险，先出映射表再动，不许批量 mv）。

**O-15 指标口径：只记不推（P2）**
证据：报告 §5 明确"判废率/一次通过率无全周期底数，不外推为比率"。
改法：卡上记`实际行数`、`返工次数`，但对外只报两个布尔（HEAD commit、CI 绿红），不报百分比——与既有 F1 一致。
落地：卡后填区。

## 六、优化后的卡字段终版

**写码卡（10 项固定 + 4 项后填）**
固定：①卡ID ②所属模块 ③写什么 ④文件域（独占，穷举）⑤判据锚点 ⑥规格出处 ⑦前置卡 ⑧配对验收卡 ⑨不做边界 ⑩状态。
说明区（不占列但冻结时必填）：边界兜底四条、来源标注、阻塞原因。
后填：承办代理、commit、实际行数、返工次数。

**验收卡（8 项固定 + 3 项后填）**
固定：①卡ID ②配对写码卡 ③所属模块 ④只读文件域 ⑤判据条数（≤3）⑥判据锚点 ⑦验收方式（机械 / 机械+真机）⑧状态。
说明区：回执行数上限、结论前置、边界兜底四条核对。
后填：验收代理、证据（文件:行 / run id）、结论日期。

**删掉的字段**：行数预算（估算出来的数一旦进事前计划就变成假指标，已定不估算）。

## 七、门禁清单变化

| 动作 | 项 | 说明 |
|---|---|---|
| 新增 | 退化检测 | 体积/重复句/超行数三条，自动判废 |

| 废除 | ⑱ 寿命判、㉚ 队首、E2 未验收先推 | 与卡模型相反 |
| 合并 | ⑮ 三段锚点、㊲ 验收字样 | 并入 V 卡证据要求 |
| 改档位 | ⑨ | 4 写 1 查 → 3 写 2 验 |
| 降级为提示 | 无事故支撑的 30 条 | 依据 O-04 / O-13 |

## 八、落地顺序（每步都最小可回滚）

1. 改卡表头（O-01/02/03/06）——只动两份卡文件，不动脚本。
2. 补删旧卡（O-09）——写码卡加行，先按 ui/ 六个一级域各一张。
3. 四处读数一次改完（O-10/O-11）——档位、⑱、㉚、三个脚本。
4. 新增三项门禁（O-07/O-04 配套、自报数核对）。
5. 目录分区（O-14）——先出映射表，不动文件。

## 九、明确不做

- 不重写 269 条规则，只按动作标签处置（保留 237 / 改指向 16 / 降级 7 / 废除 4 / 合并 2）。
- 不给卡加行数预算（已定不估算）。
- 不把组装与出包塞进写码卡（它们是验收层与交付链，由多张 V 卡结论汇总触发）。
- 不动 `app/src`、`data_scripts` 现有逻辑以外的任何代码；不改历史台账事实。
