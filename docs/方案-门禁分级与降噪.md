# 方案-门禁分级与降噪（Q-271）

> 对象：`data_scripts/rule-gate.sh` 全量门禁的阻断/审计分级，新增 `--blocking-only` 开关与分级台账 `data_scripts/gate-levels.json`。锚点卡：`docs/锚点/Q271-门禁分级.md`。
> 边界：本单只新建 `data_scripts/gate-levels.json`、只给 `data_scripts/rule-gate.sh` 加开关与过滤层；不改任何 `check-*.py` 判定逻辑；不碰 `app/src/**`、`.github/workflows/**`；不 git 写；沙箱无 JDK，未编译。

## 一、问题实测（不是猜测）

- 全量门禁一次稳定出现 3~6 项红，其中绝大多数与本次代码改动无关：历史文档欠账、别单在飞的队列抖动、历史混合提交 `e8ce4a8`、evidence 历史存量、selftest 历史欠账。
- 每次提交前都要人工分辨「哪些红是本单造成、哪些是历史噪声」，分辨成本高于门禁收益；长期后果是报警疲劳——人开始忽略红，门禁退化成装饰。
- 本单目标：把门禁分成两档。`blocking` 只拦「代码能不能编译/能不能跑/改动能不能回源/清单与 CI 能不能执行/门禁机制自身会不会假绿」；`audit` 不拦 push，进夜间/收口审计，每条必须写明事后补偿渠道，没有补偿不许降级。

## 二、逐行核对结论（59 步，编号与脚本调用原样保留）

核对方式：通读 `data_scripts/rule-gate.sh` 全文 678 行，逐步登记编号、名称、调用脚本、判定性质（`bad` 判红 / `info` 仅提示 / `warn` 型）。完整逐条台账在 `data_scripts/gate-levels.json`（59 条，id `g01`~`g59`）。

判定性质分组：

- 判红型（命中即 `bad` 计入失败清单）：除 ①/⑥/⑦/㉟/㊴ 外的绝大多数步骤。
- 仅提示型（脚本内只 `say`，不进 `FAIL`）：①工作区自盘、⑥在飞计数、⑦级别自报、㉟推送窗口（退出码恒 0）、㊴认证书尾（WARN 型）。
- 改动件限定型（判据只扫本轮 git status / origin/main..HEAD ∪ 工作区的新增修改报告，历史留档不追改）：⑲锚点卡、⑭回执证据、⑮三段锚点、㊽未推送报告回执、55永远找问题（按分界提交豁免规则前存量）。
- 全仓/运行态扫描型：代码静态闸（⑫⑬㉘㉜㉞⑳）、队列台账闸（⑯⑱㊶㊷㊸㊹㉗㊳㉙㉚57⑨⑤）、规则文档闸（㉓㉔㉑㉖㉛㊱㊲㊺㊻㊿5658⑪㉒⑰④）、环境闸（⑩㉝）、机制闸（㊼㊾5354）、提交史闸（㊵59②⑧）。

## 三、分级结果：blocking 19 个 / audit 40 个

### 3.1 blocking（阻断 push，19 个）

- `g02` ②远端同步：远端已有外来提交或分叉时强推会覆盖他人历史，属 push 动作本身的安全性，必须拦在 push 前。
- `g09` ⑧图标冻结：出厂图标资产哈希被改是交付物回归，CI 不比对冻结哈希，push 前必须拦住误改。
- `g14` ⑲锚点卡：本单新增/修改的写码验收报告必须能按编号反查到锚点卡，否则改动不可回源；孤儿卡扫描本就仅 WARN。
- `g18` ⑫扩展import：Compose 扩展函数漏 import 语法合法、IDE 无感，只有 CI 编译才红，沙箱无法本地复现，靠静态闸 push 前拦。
- `g19` ⑬测试源码陷阱：R1/R2 类 ERROR（非法字符名、静态调实例方法）直接造成编译红，属代码能不能编译的硬判据。
- `g20` ⑭回执证据：本单报告缺 E1 命令证据/E2 文件:行定位/E3 实测结论即空回执，改动不可核验；判据只限本轮改动件，不追历史。
- `g21` ⑮三段锚点：本单实现/交付报告缺规格/选型/验收三锚点即流水线断链，回不到设计与选型依据；只限本轮改动件。
- `g22` ⑳缝合怪：`app/src` 双轨实现/兼容层/wip 半成品即使能编译也污染运行时行为，CI 编译期不报这类结构问题，push 前拦。
- `g28` ㉘测试函数名合法性：反引号函数名含非法字符会让 `compileAppDebugUnitTestKotlin` 直接 FAIL，属测试代码编译硬判据。
- `g32` ㉜FloatDouble混算：float*double 推成 Double 而返回 Float 缺 `toFloat()` 即编译红，属类型编译硬判据。
- `g34` ㉞Gradle语法：Groovy 构建脚本行首 `#` 非法注释会让 Gradle 连 Task 都进不去，属构建脚本可执行硬判据。
- `g40` ㊵提交路径分离：同一 commit 混 docs 与 `app/src/` 会让目录级 add 把未验收在飞代码扫进提交（E-05 事故），commit 与单号无法回源，必须阻断。
- `g47` ㊼豁免身份化：位置型豁免改名即可蒙过，会架空其余所有门禁的豁免边界；豁免必须绑 git 跟踪/内容哈希身份，属门禁机制可信度。
- `g48` ㊽未推送报告回执：已提交未推送的报告同样必须过回执，堵住「先提交就永不进判据」的缺口（Q-209 事故）。
- `g49` ㊾空集不判PASS：检查器空集 `return 0` 把「没有检查对象」表述成「合规」，删报告/漏传参数即可假绿；门禁机制自身不许带这种结构上线。
- `g53` 53workflow契约：workflow_run 引用名与契约测试路径必须真实存在，否则 CI 矩阵永不触发或整组误红，属 CI 清单可执行硬判据。
- `g54` 54门禁接线：判据写了不跑等于清单不可执行；新门禁当轮未接线必须拦，孤儿基线只许缩小。
- `g55` 55永远找问题：现行报告缺「新发现问题」节或缺状态词即核心假绿，审计停在自己手里；判据已按分界提交豁免规则前存量，只判现行报告。
- `g59` 59提交来源：源码文件进提交必须有 docs 报告文件级回源，否则目录级 add 把未验收在飞产物扫进提交并导致 CI 编译真红（`5ec4ada`/`ImportSourceGroup.kt` 事故），必须阻断。

- 接线自检：`python3 data_scripts/check-gate-wiring.py` 仍 PASS（51 个门禁均接线；历史孤儿基线 0 个）。开关只包过滤层，`check-*.py` 字面调用行全部保留，不产生孤儿门禁。

## 六、反例推演与降级补偿（每个 audit 项的事后发现渠道）

降级总原则：降到 audit 不等于放弃判据，只是不挡 push；每条必须在事后（夜间 job / 收口单 / CI 侧等价检查）被重新发现。无补偿的条目在 JSON 里不许标 audit。

- 反例一（混合提交放开）：若把 ㊵/59 降到 audit，目录级 `git add` 会把未验收在飞代码扫进提交，commit 与单号无法回源，CI 编译真红——今晚踩过的 `ImportSourceGroup.kt:40:26 Unresolved reference 'lastPathSegment' on receiver of type 'URI'` 就是这条路径。因此 ㊵、59 保留 blocking，不降级。
- 反例二（队列僵尸行放开后无人清）：㊹/㊶/⑱ 若只靠 push 闸拦，僵尸 RUNNING 会让调度计数失真、后续派单误判满槽；补偿是调度层当轮清理 + 夜间队列↔台账双源对账 job，残留负样本与超时单入判废/回炉单。
- 反例三（台账新鲜度欠账累积）：⑯ 新鲜度红多为 mtime 口径的历史轮次欠账；补偿是收口单回写台账 + 夜间新鲜度 job 扫超期条目并升级。在飞超硬上限部分仍是硬 FAIL，不豁免。
- 反例四（规则文档漂移无人知）：㊺/㊻/㊿/56/㉓/㉔ 这类规则文本与总账闸，漏判会让主控读到旧口径；补偿是夜间规则总账/铁律双文件/阅读顺序/等待条款/锁口径反向扫描，规则改版单回执逐条核对。
- 反例五（报告空口自称验收）：㊲ 全量扫到无锚「验收通过」；本轮新报告的 claim 已由 ⑭/㊽ 证据闸兜底，存量件补偿为独立验收代理复核 + 夜间全量 claim 扫描，无锚字样回退重验。
- 反例六（历史欠账假装销账）：51 selftest 欠账若进 push 闸，每次提交都被 24 条历史红拖住；补偿是夜间欠账台账销账，新增门禁 PR 当轮必须自带 `--selftest`，基线只许缩小。
- 反例七（人工节被生成器吞掉）：58 人工节若被整文件重写覆盖，知识丢失要到下一次索引刷新才暴露；补偿是索引生成器改写后人工节复核 + 夜间 GEN 区间巡检，人工行被吞即回滚生成器输出。
- 反例八（本地构建纪律失守）：⑩/㉝ 降级后，本地跑 gradle 留下的 daemon/假绿假红痕迹不在 push 闸暴露；补偿是会话开场环境快照核查 + CI 唯一编译契约 + 夜间本地构建痕迹扫描，违规入纪律台账。
