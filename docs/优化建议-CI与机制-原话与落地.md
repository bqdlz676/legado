## 第一部分 · 建议原文（逐字落盘）

### 总判断
新机制最该做的不是加新规则，而是补闭环缺口——263 条已在饱和边缘，重复覆盖三簇就是证明。以下每条都带为什么、适用条件、反例边界。

### CI 优化（六条）

**1. 修红"三同时"升"四同时"**：BUILD SUCCESSFUL + e:0 + tests 0 failed 之外，加一条"上次失败测试族逐项转绿比对"。
为什么：三同时只证全绿，不证"这次红的族真绿了"，K 族同类回归反复出现。适用条件：只在修复 run 要求，新功能批次不要求。反例：新增测试不在上次失败清单里，比对范围必须限定为"上次失败族"，否则新增测试未绿会被误伤。

**2. CI 失败自动回写卡状态**：push 时在批次登记文件里写明"本批次含 W-0xx~W-0yy"，CI 红后按该文件把对应卡置"不过"并挂事故号指针。
为什么：现在 CI 红之后卡状态如何流转没有机械规定，全靠调度层人判，C13"事故挂卡"机制形同虚设。适用条件：批次 >1 卡时需要登记文件归因，单卡批次天然归因可豁免。反例：基建型失败（K-05 截图基建、K-07 复跑绿）不该判卡不过——要留"基建缺件在册/复跑绿"豁免口，否则把基建红误判成代码责任。

**3. 静态门禁拆两级**：只读级在 CI 里也跑一份作唯一真值，提交态级（工作区自盘等本地语义）只留本地。
为什么：F-109 的 ① 豁免口是补丁，且"本地能跑的检查 CI 也应有"防调度层漏跑。适用条件：先盘点 38 项门禁哪些依赖提交态。反例：双份结果不一致会制造新困惑——规定 CI 结果为准；清单脚本生成，避免 D-06 双源漂移重演。

**4. push 触发改"批次闭环即推 + 30 分钟上限兜底"双触发**，替代固定 30 分钟节拍。
为什么：批次全过了干等节拍浪费吞吐；反过来为赶节拍会把没验完的卡混进批次。适用条件：与 C11 兼容，保留"CI 在飞不推"硬闸。反例：立即推可能走回 K-20 连环 push——加最小批次间隔（如 5 分钟）保护，远端 500 按 S-07 退避惯例不 force。

**5. CI 终态结构化落盘**：run id + 失败测试族 + 批次卡片号 + 时间戳写进一个收口文件，调度层只消费文件。
为什么：内部归因需要机器可读，对外两布尔口径不动（F1 只约束对用户的说法）。适用条件：文件带 run id 和时间戳，读取前校验与当前批次一致。反例：落盘文件会陈旧（K-18 教训）——新鲜度校验必须内置，否则就是第二个台账坑。

**6. Paparazzi L2 帧比对结果直接写进 V 卡证据列。**
为什么：观感验收的"美感"维度现在主要靠代理文字描述，帧比对是现成的机器证据，真机 L3 只做最终拍板。适用条件：只覆盖已接 Paparazzi 的组件，未接的（G-09 缺件在册）禁伪造帧证据。反例：帧比对红了先分"基线陈旧"还是"真回归"，不能自动判卡不过。

### 比 CI 更急的三条机制优化

**1. 23 张"缺锚点"卡批量补**：切片在册的直接从切片逐字生成，无规格的走 F-73 三段流水线；批量不豁免——每张仍过 ⑲ 门禁。

**2. 三个悬空号（㉕/㊵/F-110）切卡前一次清**，因为 CI 归因的基建（㊵）本身就悬空着。

**3. A-06/A-08 补回执语义守卫**：90 秒校验加"回执与派单原文相关度/行数下限"，识别长耗时 + 重复串/空壳。

### 与上一轮口径的正面冲突（一处，需裁决）

**CI-4 里出现了两个墙钟**："30 分钟上限兜底"与"最小批次间隔（如 5 分钟）"。这与上一轮已定的"墙钟不进规则、控制改用状态量"直接相反。

按"以后面（最新）指令与工程现实为准"，两种做法都能落地，但必须选一个：

- 口径 A（保留墙钟）：承认报送是例外，允许两个时间兜底，代价是每次调整都要重新掐表，且会诱发"贴边塞单"。
- 口径 B（换状态量，推荐）：把两条都改成可数事实——
  - "批次闭环即推"保留（本身就是状态触发）；
  - "30 分钟上限兜底" → 改为**待推批次数 ≥ 2 即强制推**（有货积压就必须投递，不看钟）；
  - "最小间隔 5 分钟" → 改为**上次 push 的 run 已不是 `queued` 状态，才允许下一次 push**（等价保护，不用秒表）。

其余八条与无墙钟口径不冲突。
