### 4.3 定性结论

**这条修法是“补窗口”，不是“降覆盖”。**

- 正常窗口（未推送提交 + 工作树）的取集逻辑本笔一行未改；非空时判定范围与修前完全一致，不存在把已纳入判定的报告移出集的改动。
- 空集状态：修前 `report_paths()` 返回空 → `main()` 走 `:418-421` 返回 RC=2，判 0 份且恒红；修后回退最近一棒、判那一棒的报告。空集下判定文件数由 0 变为 N，覆盖面只增不减。
- 中文路径修复：`rev-list`/`status`/`log`/`show` 四处路径产出型 git 调用统一带 `-c core.quotepath=false`（`:136`/`:158`/`:198`/`:208`/`:218`/`:221`）；`:120` 的 `git show -s --format=%ct` 只取数字时间、不产出路径，不带该参数无影响。修前中文报告路径被转八进制串、`NAME_RE` 一条匹配不上，回退窗口必然命中 0 份——这是真缺陷修复，不是放宽判据。

残留盲区（本笔未解决，也非本笔引入，列另单）：

1. 回退只取“最新一笔动报告的提交”，`break` 之后更早批次的报告在全推送状态下不会被复判；若某份旧报告在入队后又被改写，改写版不一定再进判定集（本表 `shard1挂死隔离bench`、`分组显示名断言口径` 即近 30 笔内被二次改动件）。

## 七、验收 6：反例推演三条

### 7.a `.gitignore` 忽略 `dist/` 会不会让“195M APK 不再入库”变成“连交付物也不留痕”

现状核对：`.gitignore` 增补 `/dist/` 与 `docs/契约-设计token.emit.json`（`6167a95`）。交付物留痕不由 git 二进制承接，而由两条链承接：

- CI 侧：Package run id、head sha、event 记录在 `docs/交付-APK-98ee6d0-静态自检.md`（run `45160352436`、commit `98ee6d0`、双 artifact id、包体字节数、sha256、签名三件）；`data_scripts/check-package-trigger.py:187-193` 做同 sha 同事件对账，`fetch-apk.py` 按 run 当下取 artifact。
- 产物侧：apk 落本地未跟踪的 `dist/`，报告里记大小与哈希，可对回下载件。

二阶风险：GitHub artifact 有留存期（默认有限天数），过期后报告里的哈希无法再对回可下载原件；`dist/` 又不入库，时间久远后只剩哈希与 run id，无法复验包体。建议（另单，不在本静态验收范围）：交付报告固定记 artifact id + 哈希 + 签名指纹，过期前需要留档的包另存受控介质；当前链在留存期内闭环。

### 7.b 若后来人把 `report_paths()` 回退改成“永远回退”，真状态“本轮无报告”还判得出吗

判不出，且这是本修法最需要守住的护栏。现状回退只在 `if not out:`（`:216`）触发，正常窗口优先；`main()` 仍保留 `targets` 空 → `EMPTY` RC=2 的真值出口（`:418-421`）。若被改成无条件走回退：

- 本轮确实无新增/改动报告时，门禁会拿最近一棒的旧报告凑数判 PASS，“本轮无报告”这一真状态被永久掩盖，㊾空集不判 PASS 的语义被架空。
- 旧报告正文后来被改坏，也可能因回退集只取文件名、不复核改动时间而漏抓。
- 护栏建议：回退分支必须保留“正常窗口优先、空集才回退”的分支条件；补一条夹具固定“非空集不得进入回退”；回退命中的报告在输出里显式标注“回退窗口件，非本轮新增”，避免被读成本轮判定。
