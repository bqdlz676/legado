## 四、二阶三阶影响

### 4.1 事件触发与引擎是否重复计算

- crossing 侧：`TriggerEngine` 只做条件匹配（回合 / 兵力 / 士气 / 点位），不碰兵力与士气；唯一结算口是 `CampaignController.applyEvent`。fireAttack 在匹配后只结算一次，**无重复计算**。
- `help/sim` 侧：`EventTrigger.kt:126` 另有独立 `fireAttack` 分支（固定折损 + 士气降级），属另一套栈。两栈当前口径不一致（crossing 已三态化，help/sim 仍是固定三成五），**双栈合并待 D24**，本单按止损不动 help/sim。

### 4.2 B2 天候系数与风的叠加是否重复

- B2 `TerrainCost.weatherModifier(condition)` 吃的是**天候标签**（clear/fog/wind/rain/snow 五档定性折减，恒 ≤1）；本单 `windMarchFactor` 吃的是**标量风速连续值**，`tempMarchFactor` 吃极端气温。
- 两层在 `dailyMaxCells` 内相乘：标签档 + 标量档。已知重叠面：JSON 同时写 `"condition": "wind"` 且 `wind` 数值偏大时，行军折减会被压两层。本单刻意不删 B2 口径（B2 已验收锁定）；标量档只在风速 > 静风阈值后才开始折减，静风 / 常温不产生额外系数。**是否合并为单一连续天候模型，挂账架构项，不在本单扩战场。**

### 4.3 壳层展示

- `TurnSnapshot` / `CorpsView` 未加新字段：三态结论走既有 `events` 事件日志文本（`outcome.rule.label` + 风温 note），壳层现有日志通道即可展示，无需改壳。
- `weatherDiagnostics()` 为 internal 测试出口；若壳层将来要显示「风温异常已归一」标识，需 model 快照扩字段（同 B9 半径字段同类挂账）。
- 二阶：火攻折损倍率变了，既有战役回放的兵力曲线会与旧线不同；分支对比（B10）按快照实值 diff，不受影响。
- 三阶：系数全部集中在 companion 常量区，后续用户校参只改一处；测试精确值断言需同批改（注释已写明）。

## 五、反例与边界（假设本方案判断错误时的兜底）

1. **缺天气块**：`definition.weather == null` → 归一为静风 0.0 + 常温 15.0，不抛、不记告警；单测 `缺天气块` 覆盖。
2. **NaN / 无穷 / 非数**：归一函数判 `isNaN()` / `isInfinite()`，回落到静风 / 常温；parser 解析失败本就回落默认值，双保险。
3. **超出物理区间**：风夹到 `[0, 40]` m/s，温夹到 `[-60, 60]` ℃；越界原值进 `weatherNotes` 留痕。
4. **风 0 / 静风**：`windMarchFactor(0)=1.0`，行军不折减；火攻走受控或干热加成，不会因无风判蔓延。
5. **强风 + 严寒同时出现**：裁决顺序风优先 → BACKFIRE，不被寒冷分支改写；单测 `大风叠加严寒` 锁定。
6. **目标已阵亡 / 出局**：沿用既有 `applyEvent` 出口守卫（L266），本单分支不绕过；BACKFIRE 下士气不降，但兵力折损仍经 `applyLoss` 钳到 ≥0。
7. **event.value 非法 / 越界**：`fireFrac` 回落默认 0.35，钳 0..1，与既有 `fracOf` 口径一致。
8. **风向方位缺失**：`WeatherDef` 无方位角字段、`EventDef` 无攻方字段；顺 / 逆 / 侧以风速区间近似，注释显式声明不得臆造相对方位；方位建模挂账。
