## 二、CI-4 走 B：两条边界定义（新增硬判据，可被脚本读状态实现）

### 边界 1 · "待推批次"计数口径

- **可执行判据**：计入"强制推"计数的批次，必须同时满足两个状态量——① 批次内全部 V 卡状态为"过"；② 该批次对应的静态门禁全绿（按 F-109 口径，除 ① 待提交态必红豁免口外全绿）。未闭环批次一律不计入强制推计数。
- **未闭环批次的排除清单**：状态为"待取 / 在写 / 已交活（验收未结）/ 不过 / 缺锚点 / 待拆卡"的批次，以及静态门禁存在红项的批次，均不计入。
- **为什么必须卡死**：B 口径把"30 分钟上限兜底"改为"待推批次数 ≥ 2 即强制推"；若把未闭环批次也算作积压货，计数虚高会触发强制推，等于给 C11"全过才推"开旁门——没验完的卡被混进推送批次。
- **脚本落点**：计数解析只读卡状态列与门禁结果文件，不读时长、不看备注文字；批次闭环事实以仓库在册状态为准（C10）。

### 边界 2 · "run 不再处于 queued"改判为"run 已进入终态（success 或 failure）"

- **可执行判据**：允许下一次 push 的条件 = 上次 push 触发的 run 已进入终态；终态集合只含 `success` 与 `failure` 两种。`queued`、`in_progress` 不满足；`cancelled` 不计入终态，不视为满足。
- **为什么必须卡死**：按字面"不在 queued"判定，会把 `cancelled` 也算作满足条件，连环推照样能打掉在飞 run，K-20 同型事故复发。
- **脚本落点**：读 run 状态字段做白名单匹配（终态 ∉ {success, failure} 即不满足），禁止用"状态字符串 ≠ queued"的反向排除写法。

## 三、归因规则草案（F-113 / F-114 / F-115）

### F-113 · 归因判定禁止人工出现在链条上

- **规则一句话**：归因判定链条上禁止出现人工环节；能机械判的一律机械判，判断依据只能是文件逐行 diff。
- **为什么**：G1 要求绝不违规必须机械化；人工判读不可回源、不可复跑，口径随人漂移，不满足 F-89 溯源要求（逐字锚点、脚本可重复执行）。归因结果要进批次登记与卡状态回写，必须由脚本产出、可双向复测。
- **适用条件**：CI 红归因、卡状态回写、批次归因等一切归因判定；归因脚本的 dry-run 回放与正式批次回放走同一条 diff 判据，不另设人工通道。
- **反例边界**：纯规格层面需拍板的取舍（如数值选型、档位取舍）不属于机械归因范围，走 F-73 三段流水线另路处理；本规则只约束归因判定链，不禁止调度层按 F-115 一次性写定期望归因文件。

### F-114 · 归因脚本必须带 dry-run 模式，双批回放逐行 diff

- **规则一句话**：归因脚本必须带 dry-run 模式，用两个已结批次回放——单卡批次作对照、多卡批次作样本；产物与预落盘期望归因文件逐行 diff；"两轮验证"= 跑两次 diff，使用两个不同批次样本，不是同一样本跑两遍。
- **为什么**：先回放已结批次证明脚本归因口径正确，再接 CI 自动回写；双批分别覆盖单卡、多卡两种归因形态，单卡对照批隔离变量，多卡样本批验证复合归因。
- **适用条件**：归因脚本上线前，以及每次归因口径改动后；两个被回放批次均须已结（终态已知、事实在册），未结批次不得进回放样本。
- **反例边界**：同一样本跑两遍只证脚本幂等，不证泛化能力，第二轮的样本必须换批次；期望文件本身错误时，diff 只证"脚本与期望一致"，不证"期望正确"（见 F-115 反例边界）。

### F-115 · 期望归因文件由调度层一次性写定落盘，此后只 diff 不人眼

- **规则一句话**：期望归因文件由调度层一次性写定并落盘，带批次号与时间戳；此后只 diff 不人眼，版本随批次事实更新。
- **为什么**：期望文件是 diff 的真值基线；逐轮人眼复看会临场改判，基线漂移后 diff 失去判定意义；批次号与时间戳保证回放对象可回源、可对档。
- **适用条件**：dry-run 双批回放与正式批次归因比对；每个被回放批次对应一份期望归因文件，文件头必须带批次号、run id 与时间戳，读取前校验与当前批次一致。
- **反例边界**：期望文件正确性不自证——diff 通过只说明脚本产物与期望一致，期望内容必须由同批次已知事实（已结 run 终态、V 卡在册状态、在册归因记录）生成；批次事实更新后，期望文件随事实更新，禁止为让 diff 变绿而事后改期望。

## 四、执行顺序与现状

### 4.1 执行顺序（相应改为）

㉕/㊵ → 27 锚点 → 卡表三列 → 归因 dry-run 双批 diff → 拆 workflow。

- ㉕/㊵：先清两个纯悬空门禁号（`data_scripts/rule-gate.sh` 补实现或标作废）。
- 27 锚点：补 27 张缺锚点卡，每张仍过 ⑲ 门禁；无规格的先走 F-73 三段流水线。
- 卡表三列：`docs/写码卡.md` 补批次 / 车道 / 失败归因三列，先不上 CI 自动回写。
- 归因 dry-run 双批 diff：按 F-113 / F-114 / F-115 跑两轮不同批次样本的逐行 diff。
- 拆 workflow：CI 配置最后拆，新旧并行对照后再切换。

### 4.4 反例边界汇总（两条，闭环留档）

1. **期望文件正确性不自证**：期望文件本身错误时，diff 只证"脚本与期望一致"，不证"期望正确"；故期望文件必须由同批次已知事实生成，禁止事后为让 diff 变绿改期望（F-115）。
2. **同批两遍只证幂等**：同一样本跑两遍只证脚本幂等，不证泛化；第二轮验证必须换批次样本（单卡对照批、多卡样本批为两个不同批次）（F-114）。
