# 工作模式 · 门禁 + 总账 + 溯源（F-89 通用模式，非规则专用）

> 来源：用户 2026-11-25 原话「我不再靠记忆补规则，改成总账加门禁两条腿，这个也弄成一个工作模式的规则」「我说的是工作模式，是门禁加总账的核对，可以应用到任何场景」「不是当他不存在，是要你特殊处理」。
> 为什么：靠记忆维持的状态必然漏——今晚已证三次（三档配比只落最低档、台账冻结 8h45m 在飞计数恒 0、切片 21~25 漏登记长期无人发现）。

## 1. 三件套定义

- **总账**＝唯一事实源：结构化、脚本可读、单点权威；禁口头补、禁靠记忆维持；一切条目带锚点与落点。
- **门禁**＝机械判据：必须双向自测——违规必 FAIL、合规必 PASS（`--selftest` 造夹具跑通两条通路后自删）；判不了的人工项写明走哪条特殊通道。
- **溯源**＝逐字锚点：`文件:行` / run_id / commit sha / sha256；禁转述、禁"差不多/应该没问题"。

## 2. 适用范围

任何需长期维持的状态都套三件套：口径、规格、任务、代码状态、进度、验收、事实、资产、基线、时间预算。一次性当场结论不强制入账，但跨轮交接的状态必须在册。

## 3. 缺件特殊处理（不是当它不存在）

- 缺哪件登记 `docs/台账-三件缺项.md`：缺哪件 / 责任 / 期限 / 补齐前效力限制 / 状态；默认一轮内补齐，逾期升级阻断。
- 补齐前限权：缺门禁的规则不得用于验收判定；缺总账的状态不得作为决策依据；缺溯源的结论不得引用。
- 同一事项二次登记缺件即 FAIL（防把缺件台账当常驻豁免层）。

## 4. 三条特殊通道（写清适用条件）

- **人判门禁**：审美类、主观观感项，独立验收代理 + 第二人复核；判据必须落成可截帧/可量像素/可单测的硬指标（T6 口径），纯主观描述不进 DoD。
- **历史豁免**：一次性留档报告（复盘/流水/旧验收/被否稿）标"不进任何新判定"；门禁只校验本次新增/改动产物，不追改历史留档。
- **外部门**：真值在 GitHub（CI run/artifact）或用户真机时，门禁改为"取外部真值比对"，不以本地静态结论冒充外部真值。

## 5. 防滥用

- 总账单点权威：同一规则两处写必漂移，第二处只准指向第一处。
- 门禁不接受自报豁免：任何"留档/已清/豁免"必须能回查到对应台账条目，自报无条目仍判 FAIL。
- 缺件台账不是兼容层：补齐后状态改"已补齐"并保留行，不删除留痕。

## 7. 落地节奏（新规则进门四步）

原话落盘（逐字带时间戳/文件:行）→ 入账（本总账一行，六字段齐全）→ 写门禁（机械判据或注明特殊通道）→ 双向自测（违规 FAIL / 合规 PASS）→ 才允许派单。四步未走完的规则不得作为验收依据。
