## 四、二阶三阶影响与改坏推演

- 直接效果：push 前多一道离线符号核对，"抄到不存在的 Compose 符号"在本地即可被拦，不必等云端 CI 两路同红。
- 连带影响：`pre-push-check.sh` 3.61 步只跑本轮改动 kt（脚本自行取 git 改动），不全仓扫，单轮耗时与改动文件数成正比；索引 JSON 约 328KB 随仓入库，`data_scripts/` 体积增加可控。
- 三阶影响：后续升级 Compose 版本时，索引必须随版本重建，否则新版新增符号会被误判不存在；重建方法见第六节交接。
- 改坏推演（如果本判断是错的）：
  1. **索引漏收某个常用构件** → 该构件的大写类名会被误判 FAIL。兜底：未命中的小写符号只 WARN；全仓回归 0 FAIL 证明当前仓内用法全部命中；新构件接入时先补索引再开 FAIL。
  2. **sources 解析启发式漏掉声明**（多行签名、注解跨行）→ 类名仍由 `classes.jar` 精确兜底，包级函数退化为 WARN，不会误杀。
  3. **通配符 import（`….*`）** 不展开核对，属已知盲区：通配符带入的符号本脚本不判，由编译器与 S5 种子表兜底。

## 五、反例与边界

- **空数据/索引缺失**：`dep-symbols.json` 不存在时脚本直接 FAIL 并提示重建，不静默放行（`data_scripts/check-dependency-symbols.py:98`）。
- **断网**：索引是离线 JSON，检查阶段不联网；联网只发生在建索引时下载构件，与 push 门禁解耦。
- **同名消歧**：索引按"包路径 + 符号名"精确匹配，不做跨包猜测；同符号不同包各记各的。
- **未收录依赖**：`androidx.core`、`kotlinx.coroutines`、`okhttp3`、仓内 `io.legado.*` 等全部 SKIP，不计 FAIL 也不计 WARN。
- **枚举条目/嵌套类 import**：如 `Lifecycle.State` 形态的嵌套引用不在本脚本解析模型内，且其包多在未收录域，按 SKIP 处理。
