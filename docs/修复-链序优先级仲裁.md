# B35 修复：消掉「名物槽前置于多字词槽」的抢词风险

> 日期：2026-11-26 ｜ 范围：`help/bubble/**` 与其测试；未触碰 `ui/**`、`engine/**`、`data/**`、`res/**`、`data_scripts/**`。
> 约束遵守：未 git add / commit / push；沙箱无 gradle / JDK21 / SDK，未本地编译跑测，红绿以云端 CI `:app:testAppDebugUnitTest` 为唯一终验。
> 上游观察项：`docs/验收-名物槽装配.md` O1（artifact 前置位次在真实数据表落地后可能截胡普通多字词）、O2（缺「artifact 命中抑制 word」反方向断言）。

## 一、风险来源（逐字回源）

- O1 原文口径：`BubbleResolver` 链序为 `place → artifact → word`，命中即 return（first-hit-wins）。当前 `artifact` 槽背后是 `EmptyEntityProvider`（查不到东西、返回 null），暂时不触发；一旦真实名物数据表落地，`artifact` 可能截胡本该由 `word` 槽命中的普通多字词（例如「白马」既是名马也是普通词），造成读页气泡选错类。
- O2 原文口径：现有链序断言只记录调用先后；先命中抑制断言只覆盖 person 抑制 artifact 一个方向，未覆盖 artifact 命中时抑制 word 的反方向。
- 代码核实（本单开工首读）：段落链 `dispatch` 原 `BubbleResolver.kt:104-105` 为 `artifact.hitAt` 命中即 return、再问 `word.matchWord`；整词链 `queryToken` 原 `:86-87` 为 `?: artifact.query` 短路到 `?: word.query`。两链同序，均 first-hit-wins。
- 多字词命中口径（`WordProvider.kt:39-48`）：`matchWord` 走 `ChineseDict.wordAt(paragraph, pos)`，内部 5→2 字最长词优先；非汉字直接返回 null。名物适配层（`ArtifactBubbleProvider.kt:51-59`）词窗同为 2~5 字长词优先，逐窗 `query` 十四类实体 type，兜底壳（`source=未命中`）判未命中返回 null。

## 二、三方案取舍与反例压力测试

### 2.1 候选方案

- 方案 A：长词优先仲裁。artifact 与 word 两侧候选都取回，先按候选 token 长度比较，长者胜；等长时按既有领域优先（名物 > 普通词）；null 不参与。
- 方案 B：artifact 后置到 word 之后。word 命中即不再问 artifact。
- 方案 C：同一 span 只允许一个槽产出的集中仲裁器，两槽都返回候选后再裁决。

### 2.2 选定：方案 A（长词优先 + 等长领域优先），仲裁规则单源落在 `SlotArbitrator`

一句话理由：长度是规格已冻结的次级排序键（`BubbleResolver` 类注释「同位置多命中取更高优先级；同优先级取更长词」），A 只是把这条键从槽内窗口提到 artifact/word 两邻接槽之间，不动冻结链序、不降级名物槽、不凭空造证据模型。

### 2.3 方案 B 被否决的理由与反例

- B 把 artifact 后置，反转了冻结规格链序（规格切片-02 §2：名物第 5 层、多字词第 6 层；验收报告判据 3 记录两链同序），属于为消风险改优先级骨架，二阶影响外溢到候选切换、搜索重查两条入口。
- 反例（假设 B 上线后的真实出错文本）：「赤兔」若被 zh_ci 词表收为普通名马词条，读《三国演义》点「赤兔马」时 word 槽先命中，名物气泡（带 OpenMap / OpenRelation 等结构化动作）永不展示；「龙泉」作为剑名 vs 泉水普通词、「铜雀」台名 vs 普通词同理。B 让专名与普通词同形时永久让位词义气泡，错类方向与 O1 相反，并未真正消风险。
- B 是单向让位：更长的专名被套进更短普通词时，B 依然救不回来；它只解决了一类碰撞，把另一类碰撞固化。

### 2.4 方案 C 被否决的理由与反例

- C 要求两槽全量产出候选再集中裁决：段落链上 `artifact.hitAt` 与 `word.matchWord` 都要跑满 2~5 字窗口，热路径 ≤80ms 预算下双倍查表；且两槽窗口切分口径不同（artifact 五窗遍历十四类，wordAt 内部 5→2 扫词表），跨槽对齐 span 起止又是一套新复杂度。
- C 的裁决依据（证据强度 / 置信度 / tier）当前气泡协议没有字段支撑：遗留 `BubbleContent` 无 confidence/tier；契约 `Candidate` 有 tier 但气泡链未接。现在上 C 等于凭空缺一套证据模型，违反「不许凭记忆开发、规格覆盖不到处给合理实现但不造未接线字段」。
- 反例（C 假设有置信度字段但数据未接时）：各 Provider 置信度全为默认值，集中裁决退化成谁先注册谁赢，等价于把 first-hit-wins 换个位置保留；复杂调度结构留着，收益为零。
- 演进保留：等名物候选 tier / 消歧置信接入后，裁决规则只在 `SlotArbitrator` 内部升级为证据裁决，Resolver 与 Provider 调用方不动；C 作为后续演进方向登记，不在本单实现。

### 2.5 方案 A 的反例压力测试（先假设 A 错了，找真实文本出错面）

1. 等长 2 字同形碰撞，A 解决不了（残留风险，如实登记）。文本「白马非马」，点「马」。若名马库收「白马」为专名（祭祀 / 封号之马），zh_ci 词表也收「白马」为普通名词「白色的马」。等长 2 字，A 按领域优先判 artifact 胜；但《公孙龙子》语境里「白马」是泛指类名，词义气泡更贴切。A 没有上下文义项消歧能力，此情形仍可能错类。缓解挂账：等锚点年代 + 名物候选 tier 接入后，在仲裁器内补证据裁决（C 方向）；当前以单测把「等长名物优先」固化为显式口径，不靠隐式链序。
2. 名物短词被套进更长普通词组的反向边界。段落「铜驼巷陌」，点「铜」：artifact 命中短名物「铜驼」2 字，word 词表若收更长词组「铜驼巷」3 字，A 判 word 胜，专名「铜驼」可能被普通词组盖住。两槽窗口都以点击位为中心，span 覆盖关系需真实词表落地后按 `BubbleBenchmarkTest` 同口径复测；长度启发式在此边界可能漏名物气泡，登记为已知边界而非空白态。
3. 「赤壁」既地名又典故又名楼：地名槽 place、典故槽 allusion 在 artifact 之前已先命中，仲裁对只接管 place/allusion 都未中的残余碰撞，不影响人物 / 地名 / 典故三类既有优先级，双轨排除机制（`ArtifactSlots.entitySlots` 清单级短路）未改动。
4. token 长度失真边界：artifact 气泡 token 经 `cleanToken` 去标点，word token 来自词表原形；若两侧 token 存在繁简 / 异体差异，长度比较可能失准。当前两槽输入同为段落汉字窗，繁简一致；登记为数据组装单复核项。
5. 拉丁 / 数字词：`matchWord` 对非汉字返回 null（`WordProvider.kt:41`），artifact 窗口同样只查汉字；仲裁时 null 侧自然下钻，不误伤英文词气泡路径。

## 三、落地内容

### 3.1 仲裁单源位置

- 唯一裁决点：`app/src/main/java/io/legado/app/help/bubble/SlotArbitrator.kt`，`internal object SlotArbitrator.chooseArtifactOrWord(artifactHit, wordHit)`。
- 规则逐条：任一侧 null 不参与，取另一侧；两侧皆命中，token 更长者胜；等长保持名物领域优先（artifact 胜）。
- Resolver 两条链只负责把两侧候选取回并交回本器，不在 Resolver 或 Provider 内写第二份长度 / 类别判断。`ArtifactBubbleProvider.kt`、`WordProvider.kt` 内的「长词优先」注释均为槽内窗口扫描口径，不是跨槽仲裁规则；跨槽比较全仓 main 侧只此一处。
- 未改 `help/artifact/ArtifactSlots.kt`：双轨排除的登记表结构保持原样，本单只动 artifact 与 word 之间的邻接仲裁。

### 3.2 两条链接入

- 段落链 `dispatch`（`BubbleResolver.kt:111-113`）：先取 `artifactHit = artifact.hitAt(...)`，再取 `wordHit = word.matchWord(...)`，交 `SlotArbitrator` 裁决，胜者 return；败者不冒第二张泡。
- 整词链 `queryToken`（`BubbleResolver.kt:90-93`）：同口径取 `artifactHit = artifact.query(...)`、`wordHit = word.query(...)`，仲裁结果为空再下钻 `char`。
- date / allusion / person / place 四槽仍保持原 first-hit 短链，未纳入仲裁对；char 仍在仲裁对之后兜底。
- 构造器签名未变：`artifact` 仍为带默认值的可选参数，既有七参位置调用（`BubbleResolverTest`、`BubbleBenchmarkTest`）源码兼容。

### 3.3 O2 反向断言补齐

- 段落链：`名物等长命中抑制同长词槽只出一张名物气泡`——artifact 与 word 同长各命中，返回实例为 artifact 命中件，`assertNotSame` 排除 word 命中件；调用记录证明两侧都被查询，但只产出胜出一张泡。
- 整词链：`整词链名物等长命中同样抑制词槽`——`queryToken` 同口径断言 artifact 胜出、word 件不回传。

## 四、断言清单（新增 12 条，全部纯 JVM）

仲裁器纯函数 6 条：

1. `等长候选名物槽按领域优先胜出`：两侧等长，artifact 件胜出。
2. `名物候选更长时胜出词槽短词让位`：artifact 3 字 vs word 2 字，artifact 胜。
3. `词槽候选更长时名物短词让位词槽`：artifact 2 字 vs word 4 字，word 胜。
4. `名物返回null不参与裁决直接取词槽`：artifact null，word 件正常返回。
5. `词槽返回null不参与裁决直接取名物槽`：word null，artifact 件正常返回。
6. `两侧皆空返回null交链尾兜底`：两侧 null，返回 null。

段落链接线 4 条：

7. `名物等长命中抑制同长词槽只出一张名物气泡`（O2 反向断言，dispatch 路径）。
8. `段落链词槽更长时名物短词让位词槽`：2 字 artifact 让位 4 字 word。
9. `段落链名物更长时词槽短词让位名物槽`：3 字 artifact 胜 2 字 word。
10. `段落链名物为空时词槽候选正常出泡`：artifact 不参与时 word 照常出泡。

整词链接线 2 条：

11. `整词链名物等长命中同样抑制词槽`（O2 反向断言，queryToken 路径）。
12. `整词链两侧皆空返回null不抛异常`：整词链无 Missing 兜底槽，皆空返回 null 属既有契约。

既有断言未删：`ArtifactSlotsTest` 7 条、`ArtifactBubbleProviderTest` 10 条、`BubbleResolverTest`、`BubbleBenchmarkTest` 原样保留；其中链序记录断言（date→allusion→person→place→artifact→word→char）在新接线下调用先后不变，仍应通过。

## 五、二阶影响推演

- 性能：空数据当前状态下 artifact 恒为 null，word 槽原本就会被查询，热路径调用次数不变。真实数据落地后，artifact 命中的分支会多跑一次 `word` 查询（内存索引 / 二分查表，Provider 契约不整表线性扫）；`queryToken` 同口径多一次 word 查询。增量为一次槽内索引查找，量级远小于冷启词典加载；冷启 ≤300ms / 热路径 ≤80ms 是否守住，以 `BubbleBenchmarkTest` 云端 CI 复测为准，本沙箱未实测。
- 命中率：更长的普通多字词不再被短名物截胡，word 槽长词命中率回升；等长同形碰撞仍归名物（方案 A 已知残留，见 §2.5-1）。专名侧不受影响：artifact 候选更长时依旧胜出。
- UI 气泡数：仲裁对仍只回传一张 `BubbleContent`，Resolver 返回签名未变，阅读页单一 `bubbleContent` 字段口径不变；不存在两泡并存。候选切换走 `queryToken` 单回包，亦不变。
- 缓存：`resolve` 仍按「段落 + 位置 + 锚点年」LRU 缓存最终胜出件，缓存键与失效逻辑未动；仲裁结果随两侧候选稳定，不产生缓存抖动。
- 兼容面：构造器默认参保留，外部只经 `BubbleResolver.resolve / queryToken / preload / clearCache` 单例入口调用，签名变更不外溢；契约层 `BubbleContractResolver` 是候选列表消歧骨架，不参与本气泡链序，未改动。
- 遗留包袱排查：未发现第二份跨槽类别 / 长度对照；`EmptyEntityProvider.categoryForType` 是 type→category 反查表（O4 已登记），方向相反、不决定槽位，本单不并入仲裁器。
