## ① 任务范围

**只修一条（R1）**：`fromDecoder` 拿到解码器返回的非 null 但尺寸 0 / data 长度不符的畸形
`HeightRaster` 时，不经 `HeightRaster.create` 守卫直接进 `resample`：0 维源在
`coerceIn(0, sh-1)=coerceIn(0,-1)` 抛 `IllegalArgumentException`，长度不符在像素索引处
AIOOBE，异常穿出桥接层。

**本单改动**：`fromDecoder` 在 `resample` 前对解码结果做尺寸/长度校验；宽高 ≤0 或
`data.size != width*height` 时回落 `syntheticFallback(gridN)` 并置 `degraded=true`，不抛任何
异常；补 2 条单测（0×0 栅格、长度不符栅格），断言不抛异常 + `degraded=true` + 边长为正。

**明确不做**：
- 不用 try/catch 掩盖异常而不做校验（本单是显式谓词校验，不是兜底吞异常）；
- 不改 `RasterDecoder` 纯 JVM 契约签名；
- 不留旧格式兼容层；

  `ShadowEditDialog.kt` / `UnderlineEditDialog.kt` / `CampaignBranchSnapshotTest.kt`

## ④ 三节 + 铁律逐条结论

### 4.1 二阶三阶影响（R59）

- **直接效果**：decoder 返回非 null 畸形栅格（0 维 / 长度不符）时，`fromDecoder` 在进
  `resample` 前收口到合成兜底场，`degraded=true`；`coerceIn(0,-1)` 的 IAE 与索引 AIOOBE
  不再可能穿出桥接层。
- **连带影响（受影响文件/接口/调用方）**：
  - `CrossingRasterBridge.resample`：输入契约被收紧为「宽高 >0 且 data 长度相符」；其内部
    `:78` 的 `source.degraded` 检查保持不变，两条防线互不替代。
  - `RasterDecoder` 接口：签名与契约未改；实现方仍按既有契约在解码失败时返 null，但即便
    实现方违规返回畸形非 null 栅格，桥接层也不再被击穿。
  - 生产调用方：验收 §2.5 已核实桥接方法在 `app/src/main/` 内暂无生产调用点（grep 仅命中
    定义与 import），故本次收紧不改变任何现存装配行为；后续 controller 接线时拿到的兜底
    口径与既有 null/异常/空白路径一致。
  - `HeightRaster.create`：未改动；其守卫仍只服务 `fromInlinePixels`。
- **二阶/三阶后果**：
  - 用户行为：畸形高程图不再导致推演/渲染崩溃，地图以合成缓丘谷地降级呈现并带降级标志，
    与既有无图口径一致，用户可感知「图没加载出来」而非闪退。
  - 系统复杂度：新增 1 个局部布尔谓词 `malformed`，未新增抽象层、未新增状态；两条入口
    （decoder / inline）的兜底口径现在语义一致。
  - 维护成本：谓词公式与 `HeightRaster.create:62` 平行存在，存在两处口径漂移的理论风险
    （见 4.3 与交接 #1）；除此之外无长期负债。

### 4.2 反例与边界（R61，先假设本方案错误）

最强反对者立场：「在桥接层再抄一遍 `create` 的校验谓词是重复逻辑，不如直接把 decoder
结果喂回 `HeightRaster.create` 收口；现在这版校验漏了边界怎么办？」逐条反证：

1. **0×0 + 空数组**：`width<=0` 命中 → 回落。已由新测试 `:111` 覆盖。
2. **64×64 声明但 data 仅 100 像素（长度偏短）**：`data.size != width*height` 命中 →
   回落。已由新测试 `:123` 覆盖。
3. **长度偏长**（如 64×64 但 data 有 5000 像素）：长度不等同样命中 → 回落；`resample`
   只按 `y0*sw+x0` 取前 `sw*sh` 个像素，偏长数组本就是畸形，收口方向正确。
4. **单边为 0**（如 64×0、0×64）：`height<=0` / `width<=0` 命中 → 回落。
5. **负宽高**：`<=0` 命中 → 回落；负尺寸在 `create` 口径下同样非法。
6. **Int 溢出**：极端宽高相乘在 Kotlin Int 内溢出为负值，与 `data.size` 几乎必然不等 →
   落入畸形分支回落（安全方向：宁兜底不索引）。
7. **`degraded=true` 但尺寸合法的栅格**：不走本守卫；由 `resample:78` 既有退化分支处理，
   两条防线职责不重叠。
8. **data 为 null（JVM 层违反 Kotlin 非空类型）**：本侧未加 null 判断，与 `resample` 既有
   假定一致；若解码器实现以反射/异语言构造出 data=null 的实例，`raster.data.size` 仍可能
   NPE。属残留边界，列入交接 #2；在纯 Kotlin 实现 + `HeightRaster` 构造器非空类型约束下
   不可达。
9. **为何不复用 `HeightRaster.create` 收口**：`create` 收到畸形输入时用 `minOf(width,height)`
   派生种子与边长生成合成场，而桥接层既有兜底统一走 `syntheticFallback(gridN)`（种子
   `RASTER_SEED=1207L`、边长对齐推演网格 `gridN`）；若改走 `create`，兜底场种子/边长口径
   会与同函数内其他回落路径分叉。故本侧保留桥接自己的兜底出口，谓词只做形状校验。

否证结论：除 #8 残留边界外，所列反例均被谓词覆盖；方案在「显式校验 + 统一兜底出口」上
成立，未用 try/catch 吞异常。

### 4.7 R65（返工复盘沉淀）结论

**触发，根因归类：边界缺失 + 契约漂移（守卫只挂一条入口）。**

- **共同根因**：`HeightRaster.create` 的形状守卫只接在 `fromInlinePixels` 入口，
  `fromDecoder` 入口凭「解码器会返合法栅格」的假定裸放；同一份合法性口径没有被两条入口
  共享，导致验收 §2.1 缺口。这与本轮既往「API 存在性/签名咬合」类返工同属「入口防线未
  全覆盖」根因簇。
- **预防手段（沉淀建议）**：① 同一实体的合法性校验应下沉到实体自身（`HeightRaster`
  暴露形状判定），所有装配入口共用，禁止各入口手抄谓词；② 桥接/适配层单测必须对每个
  入口各补一组「畸形非 null 输入」用例，不只测 null 与异常。
- **落地状态**：本单因文件域限制未做谓词下沉（见交接 #1）；上述两条建议交总控纳入后续
  单子或规则条目。
