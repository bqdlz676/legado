### 3.3 退出路径与子树摘除阶段

1. 任一离开路径（确认 / 删除 / 取消 / 下滑 / 遮罩点击 / 返回键）收敛到单点出口 `HighlightNoteDialog.kt:217` `dismissOnce`：`submitted` 置位防二次触发；提交类副作用先写库。

3. 第二段（收束摘除）：`第 107–113 行` `LaunchedEffect(exitingState.value)` 按 `MASK_DURATION_MS + RISE_DURATION_MS` 等效延时（常量引自组件锚点，本单未改数值）→ `第 110 行` `exitGate.finishExit()` EXITING → REMOVED，负载清空 → `第 112 行` `isAdded` 时 `dismissAllowingStateLoss()` 摘 Fragment。

5. 摘除阶段结论：子树只在 REMOVED 段（`finishExit` 收束后）摘除；EXITING 段全程保留组合，不提前拆树。

三态判闸表（两道闸合取，等价旧 `tryOpen` 单道）：

- OPEN：`canOpen=true`（在场段判重不归本闸），`tryOpen()=false` → 拒收，不叠第二节点。
- EXITING：`canOpen=false`，`tryOpen()=false` → 拒收，离场动画中不叠新弹窗。
- REMOVED：`canOpen=true`，`tryOpen()=true` → 放行并登记新会话。

## 四、判定点 3：回归边界 —— `ReadBookActivity.kt:546` 镜像判断等价性

既有判断（本单未改行体，合并后保持）：

```kotlin
if (f is HighlightNoteDialog && !noteEntryGate.isComposed) {
    noteEntryGate.open()
}
```

等价性论证：

- 基类定义 `isComposed = phase != REMOVED`（`SheetExitPhaseGate.kt:148-149`），故 `!noteEntryGate.isComposed` 逻辑等价于 `noteEntryGate.phase == ReaderSheetExitPhase.REMOVED`。
- 镜像职责：Fragment 恢复在场、而宿主闸处于摘除段（REMOVED）时，回同步到 OPEN，覆盖配置重建后 Fragment 被系统保留、宿主闸复位的场景。OPEN / EXITING 段 `isComposed=true`，条件不成立，不回写闸态。
- 不把判断内联成 `phase == REMOVED`：那会在宿主侧再造一份阶段比较口径，违反「禁留第二份口径」；保留 `isComposed` 委托读法，事实源仍在基类。
- 三态取值与旧 B26 口径逐态一致：REMOVED `isComposed=false`（条件成立，回同步）；OPEN / EXITING `isComposed=true`（条件不成立）。语义不变。

## 六、二阶三阶影响推演

### 6.1 直接改动与连带面

- `ReaderSheetState` 新增 `isComposed` 委托属性：纯增量公开只读属性，不改既有 `isOpen / isExiting / exitRequest / exitVisible` 签名；既有 `ReaderSheetStateTest`、`ReaderSheetStateRestoreTest` 断言面不受影响，本单在两条 B21 用例补 `isComposed` 断言锁口径。

## 七、自查反例（先假设本方案错误，逐条找边界）

- 反例 1：组合判据回到负载槽会怎样？若 `finishExit` 提前清负载而阶段仍 EXITING，旧 B21 口径会误判子树可摘，离场动画播到一半树被拆。兜底：基类不变量把清负载挂在 `onFinishedExit`，与 REMOVED 迁移同一动作（`SheetExitPhaseGate.kt:127-128`）；覆盖层保留 `exitRequest ?: return` 仅作内容槽空值防御，不派生阶段。
- 反例 2：`canOpen` 若误按「REMOVED 也拒收」实现会怎样？弹窗收束后永远无法再打开，只能外部重置阶段。兜底：保留既有 B21/B26 语义 `canOpen = phase != EXITING`（`第 152–153 行`），REMOVED 段放行；在场段叠节点由 `tryOpen` 承担。
- 反例 3：配置重建 / 旋转时 Fragment 被系统保留而宿主闸复位。兜底：`onFragmentResumed` 镜像 `app/src/main/java/io/legado/app/ui/book/read/ReadBookActivity.kt:546-548` 见 `!isComposed` 即 `open()` 回同步 OPEN；Fragment 一并销毁则无回调，闸保持 REMOVED，不留幽灵节点。旋转走 `configChanges`，Activity 不重建（既有机型配置，本单未改）。
- 反例 4：`exitingState` 镜像与闸阶段漂移。兜底：镜像只写不判，可见 / 组合 / 可开全部读闸字段；镜像唯一读取点是 `LaunchedEffect` 键与重组触发，不参与任何谓词推导。
- 反例 5：空数据 / 断网路径。弹窗缺参数（进程重建后 arguments 丢失）走 `HighlightNoteDialog.kt:89-91` 既有防御直退 ComposeView，本单未改该路径；无空白表单态、无崩溃路径。
