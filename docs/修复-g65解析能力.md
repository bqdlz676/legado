# 修复-g65 消费方反查闸解析能力补丁

## 总结论

g65 消费方反查闸（`data_scripts/check-member-consumers.py`）三面判据在验收实测中暴露五条解析能力缺口：子类主构造参数含函数类型 / 嵌套括号时参数列表被惰性正则在第一个 `)` 截断，父类型识别落空；sealed 头与子类同一行声明时漏登记；归属提及匹配未剥注释 / 字符串，注释与串里的同名提及被当成消费方；同名局部变量裸标识符命中即进 blocking，可能误报；计数报表把 INFO 与 WARN 混列，改名配对按旧 × 新笛卡尔积不核语义。本单只改这一个脚本与两份 docs 产物，五条缺口逐条补成括号配平扫描、行内建表、等长掩码、局部遮蔽降级、分类分行与同父语义配对；每条修复都带必失败样本与放行样本，各自独立临时目录单文件单断言，断言类别 + 文件 + 行名，不只比退出码。

`--selftest` 十三例双向自测 rc=0；`--changed` 改动面 PASS；`--audit` 全仓只登记不判红，密封子类由 529 补登到 533，净增 4 条已逐类解释；接线闸、shell 语法机检通过。未改 `app/src` 产品代码，未碰 `data_scripts/rule-gate.sh` 与 `data_scripts/gate-levels.json`，未做 git add / commit / push。

## 一、五条缺口与改法（逐条对应验收实测）

1. 构造参数函数类型 / 嵌套括号截断（修复一）。旧版子类头正则 `(?:\([^)]*\))?` 按首个 `)` 收口，主构造参数含 `() -> Unit`、`(String) -> Unit` 或默认值 `emptyList()` 这类嵌套括号时，参数列表提前截断，冒号后的父类型读不到，子类不进集合。改为 `_balanced_paren`（data_scripts/check-member-consumers.py:62）做括号 / 字符串 / 字符字面量 / 三引号感知配平，泛型尖括号同样配平（:118 `_read_parent`）；父类型读取只取名字与泛型，不吞构造实参。真仓实例 app/src/main/java/io/legado/app/ui/components/InkBottomSheet.kt:91 的 `data class Wired(val onAction: () -> Unit) : SheetOfflineAction` 修复后已入集合（同文件 :94 `data object HintOnly` 旧版在册）。
2. 密封头与子类同行声明漏登记（修复二）。旧版 `SUB_HEAD` 只从行首锚定匹配，`sealed interface A { object X : A; object Y : A }` 这类内联花括号 / 分号同行排布的子类扫不到。改为 `_iter_sub_heads`（data_scripts/check-member-consumers.py:133）逐行扫描全部 `object` / `class` 出现位，根修饰符（sealed / enum / abstract / open / interface 等）前置的声明判为类型根本身跳过，避免把根错并进子类表。
3. 归属提及未剥注释 / 字符串（修复三）。新增面归属判定旧版直接在原始文本上搜父类型短名，行注释、块注释、字符串字面量里写到父类型名也会把文件纳入 when 覆盖候选。新增 `_mask_code`（data_scripts/check-member-consumers.py:271）等长掩码：注释面与字符串 / 字符 / 三引号内容替换成空格、换行保留，写法思路同仓内 check-member-override.py 的 `_mask`；`check_added_members`（:718）归属提及改在掩码文本上匹配。删除面残留 grep 仍保留字符串（handler 字符串映射算真残留），两条口径不混。
4. 同名局部变量 blocking 误报（修复四）。旧版残留 grep 命中裸标识符即判红，函数体内 `val OldFoo = …` 这类同名局部变量会被当成成员残留。本单选最小符号表路线（取舍见下）：`_local_bindings`（:586）收集本文件局部 `val` / `var` / `fun` 绑定与形参名（:582 `LOCAL_BIND`、:583 `LOCAL_PARAM`），`_strong_position`（:595）判定命中是否落在 `.Name` 限定位、import、is / as、类型标注 `: Name` 等强位；`grep_name`（:612）命中带 `strong` / `local` 标记。删除面只有强位或非局部绑定命中才进 blocking；仅局部支持的裸标识符命中降 `LOCAL-SHADOW` INFO 提示（:819），不判红。
5. 计数混列与改名笛卡尔积（修复五）。旧版 INFO（找不到归属 when）混进 warns 列表一起打；改名面对同文件同类的旧名集合与新名集合做笛卡尔积，两两都出 RENAME 配对记录，不核语义。新版 `evaluate`（:788）分 `fails` / `warns` / `infos` / `records` 四段，主流程（:899）WARN、INFO、FAIL 分段打印、计数分列；改名只在同类且同父类型短名（`_parent_short` 归一）内 1:1 配对（:843），跨父类型不落 RENAME，改落 `RENAME-SKIP` INFO（:850）。

修复四取舍说明：本单没有上完整类型解析符号表（静态闸拿不到接收者类型与跨函数作用域，硬建全量表代价高且易漂移），改为「局部绑定收集 + 位置强弱判定」的最小符号表。代价是：跨函数捕获的同名遮蔽、上层局部同名变量识别不到；局部表把成员属性名也纳入了绑定集合，可能把个别成员位命中保守降级。缓解是强位（限定 / 类型 / import / is / as）命中始终 blocking，不因局部表降级。完整作用域解析留作后续待裁项。

## 五、自查反例（改坏推演）

- 反例一：若配平扫描不感知字符串 / 字符字面量，串内括号（如 `"a)b"`、`'('`）会被计入深度，参数列表在串内 `)` 处错收口，父类型再次落空；实现里 `_balanced_paren` 先判三引号 / 双引号 / 字符状态，串内括号不计深度。
- 反例二：若同行扫描把 `sealed class Foo : Bar` 这类根声明也并进子类表，会把类型根本身当成自己的子类，删除 / 改名面误判；实现用根修饰符前置标记跳过 sealed / enum / abstract / open / interface 等根声明。
- 反例三：若归属提及把字符串也剥掉，`"VerticalPageView"` 这类 handler 字符串映射会被放走；本单只在归属判定用 `_mask_code` 抹串，删除面残留 grep 仍走 `strip_comments` 保留字符串，两条口径分开。
- 反例四：若局部遮蔽把强位命中也降级，`Bar.OldFoo` 限定残留、`is OldFoo` 类型判定这类真残留会被放过；实现要求强位命中始终 blocking，只有非强位且有局部绑定支持的裸标识符才降提示。
- 反例五：若改名配对不核父类型，跨类一删一增也会被记成改名对，掩盖真残留；实现要求同类且同父类型短名才 1:1 配对，跨父落 `RENAME-SKIP` 提示留痕。
- 反例六：若新增面一上来硬红，全仓 420 处无 else 的 when 会把闸压成红墙；本单未改新增面 WARN 口径，存量仍走 audit 不挡 push。

## 六、新发现问题

- 问题 1 · 待裁（归属：g65 闸脚本维护单）：最小符号表不做跨函数作用域解析。局部绑定只认本文件 `val` / `var` / `fun` 与形参，跨函数捕获、上层局部同名变量识别不到；这类同名遮蔽仍可能出现 blocking 误报，需后续扩到作用域回溯再收口。
- 问题 2 · 待裁（归属：g65 闸脚本维护单）：归属提及仍拿不到接收者类型。链上调用、扩展函数接收者这类静态推断不出父类型的 when，沿用旧边界跳过并留 INFO，不硬判；掩码只解决注释 / 串噪声，不解决类型归属推断。
- 问题 3 · 待裁（归属：g65 闸脚本维护单）：父类型只按短名归属，未核对泛型实参。同父不同泛型实参的 sealed 子类可能被归到同一父类型名下，when 覆盖判定偏宽；当前静态闸不解析泛型实参，留待后续。
- 问题 4 · 已入队（归属：g65 存量口径复核单，audit 补偿通道）：本单把可配平构造参数的子类补登进 audit 表，subs 由 529 增至 533；若后续把 subs 表从登记口径收紧为 blocking 判定，需先对这 4 条及全量 533 条做逐条语义复核，本单不改动 blocking 口径。
