## 三、七类聚簇汇总与对策草稿

### 3.1 边界缺失（线索 ①、⑦）

- 共性：门禁脚本只建模主路径形态，非理想输入（行形、路径形态、状态行格式、条目生命周期）既不命中也不失败，盲区被差值 / 异常掩盖。
- 规则 / 机检草稿：
  - 判据 A（夹具形态覆盖）：凡解析命令行路径参数、`git status` 行、队列表格行的门禁函数，`--selftest` 必须备对应形态双向夹具；机检扫描 `data_scripts/check-*.py`：路径解析函数存在但 selftest 无相对路径 / 子树外样本 → WARN；porcelain 解析函数存在但无 `R ` 重命名样本 → WARN。
  - 判据 B（非理想行不得静默）：队列 / 台账扫描中，含状态词（`RUNNING` / `在飞` / `DONE`）但解析不出表格结构的行，必须进 `malformed` 集合并 FAIL；不允许"两个集合都不计入、差值恒 0"。扫描正则须同时接受纯文本行与前导空格行作为失败候选。
  - 判据 C（异常形态兜底）：所有 `relative_to(ROOT)` / 路径 join 调用前先 `resolve()`；子树外路径走兜底返回原串并打结构化 FAIL，禁止 traceback 退出。

### 3.2 口径错（线索 ②）

- 共性：判据锚了可观察现象，没锚本质事件；成因不同的两类样本在现象层重合，合法样本被误红。
- 规则 / 机检草稿：
  - 判据 D（本质事件优先）：合法性判据必须锚解码器 / 断言 / 命中规则本身的异常事件（`UnicodeDecodeError`、断言失败、规则串命中），禁止用文本现象计数（替换字符数、关键词出现次数）单独作为 FAIL 条件。
  - 机检扫描：脚本中凡以 `count('\ufffd')` 或关键词计数作为唯一 FAIL 分支，同文件必须存在对应本质异常捕获分支（`except UnicodeDecodeError` 等）；缺失则 WARN，提示"现象代本质"。
  - 正反例：正例 = strict 解码 + 异常偏移 `e.start` 入 FAIL 文案；反例 = replace 读入后数字形符即 FAIL。

### 3.3 验收放水（线索 ③）

- 共性：收口陈述先于逐条回源；写码方自评、验收方未逐条比对磁盘现状，假绿过关。
- 规则 / 机检草稿：
  - 判据 E（收口陈述必带逐条锚点）：报告 / 分析文档中出现「已统一改 / 已收口 / 全部对齐 / 均已修订」等收口词，同节必须逐条附 `文件:行` 现状引用；机检扫描 docs：收口词所在小节无任何 `路径:行` 锚点 → WARN，标"无证据收口"。
  - 判据 F（独立验收逐条比对）：验收代理对"已收口"清单必须逐条打开磁盘现状核对，命中旧口径行按 FAIL 列清单；禁止采信写码方报告里的计数陈述（对应子代理必读"行数、计数、字节、sha 不许估"）。

### 3.4 契约漂移（线索 ④、⑤、⑥）

- 共性：派单 / 验收链路里的锚点（根因假设、动作落点、缺陷归属）与代码现实或单据现实脱节，且落盘前没有机械校验。
- 规则 / 机检草稿：
  - 判据 G（动作-域交集校验）：派单落盘前，动作清单里点名的目标文件必须落在声明文件域内；机检解析队列行：动作含「改 / 修 / 补」且目标文件 ∉ 域清单 → WARN，退回派单方补域或拆单。
  - 判据 H（根因假设先取证后锁域）：派单若写明疑似根因（如"比较器缺键"），执行单第一步必须先回源该假设是否成立；假设被取证否定时，修复域允许跨出原域，但须在报告偏离说明节登记（参照 Q-216 `:50` 写法）。
  - 判据 I（验收 FAIL 必须挂单号）：验收报告点名的每条缺陷行，台账 / 队列须有对应在飞或已收口单号；无主 FAIL 项门禁 WARN，防止并发代理顺手改完无人对账。

### 3.5 历史包袱（线索 ⑧；⑦③ 附带）

- 共性：豁免 / 基线把一次性留档做成永久通行证，锚键不绑内容，劣化与删除不可见。
- 规则 / 机检草稿：
  - 判据 J（基线锚内容指纹）：基线豁免键必须 = 路径 + 内容 sha256 前 12 位；内容改写后哈希失效、升级重审。机检扫基线 json：条目只有路径无 `sha` 字段 → WARN。
  - 判据 K（生命周期剔除）：基线条目载入时核对磁盘存在性，幽灵路径自动剔出本轮判定集合并打 INFO；基线文件持久缩小留维护环节登记待裁项（参照 Q-223 `:59-63`）。
