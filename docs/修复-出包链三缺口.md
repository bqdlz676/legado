## 四、缺口 2：APK Signing Block 只读探测与签名三态

## 七、反例推演（必写三条）

1. **续传在 artifact 过期（404）时会不会死循环重试？** 不会。404 在每轮请求返回后首先判定，直接抛 `ARTIFACT_EXPIRED=404`，不进入续传计数、不写残片；续传循环只处理 200/206 的字节不足。另有两道刹车：本轮已收字节与上一轮相同（连接空转）即跳出；服务端回 200（不支持 Range）整包重下一次后仍不足即跳出，不再循环。「资源不存在」（404/401/403/5xx）与「字节不足」在代码上分属不同分支，前者立即 InfraError 退出码 2，后者走续传上限后 `SIZE_MISMATCH` 退出码 2。
2. **Sig Block 探测在 zip 有注释 / 有 zip64 时会算错偏移吗？** 有注释不会：EOCD 不靠固定尾偏移，先在尾段 `22+65535` 字节内找 `PK\x05\x06`，再读 EOCD+20 的 uint16 注释长度，并校验 `eocd+22+comment_len == 文件大小`，不一致即判备注异常返回，不猜偏移。zip64 不硬算：中央目录偏移读 EOCD+16 的 uint32，若为 `0xFFFFFFFF` 置 `zip64=True`，真实偏移在 zip64 extra record / zip64 EOCD locator，本只读探测不解析、不猜，返回 unknown 备注。魔数与尾随长度字段的位置固定为 CD 偏移 -16 / -24，不依赖条目顺序。
3. **对账会不会把「Package 还在跑」误判成 MISSING？** 不会。`classify` 先看 `status`：非 `completed`（queued / in_progress / waiting / pending / requested / waiting_for_approval）单列 `IN_PROGRESS`，原因写明「仍在跑；下一轮对账再闭合，不计 MISSING」；只有完全查不到同 sha 的 workflow_run Package run 才记 `MISSING`。selftest 夹具 104 覆盖 in_progress 分支并断言不落 MISSING。
