## 三、核查 2：「永不 throw」覆盖面 —— PASS（带保留）

### 3.1 语法错误：顶层有兜底【L1-铁证】

`parse()` 入口 `:37-46`：

```kotlin
val root = try {
    JsonParser.parseString(json)
} catch (t: Throwable) {
    return fallback("JSON 解析失败：${t.javaClass.simpleName}", warnings)
}
```

- 非法 JSON（`JsonSyntaxException`）、读取异常（`JsonIOException`）均被 `catch(Throwable)` 兜住，走 `fallback` 返回最小中立定义，**语法错误在覆盖范围内**。
- 空 / 空白串在 `:39-41` 早退 fallback；根节点非对象在 `:47-49` 早退 fallback。

### 3.2 类型错位：字段级守卫收口（见第二节表）【L1-铁证】

### 3.3 保留项（残留 throw 面，L1 静态不能完全排除）

1. **`parse()` 主体 `:50-90` 没有一把顶层大 try**：类型错位的安全性依赖各子解析器字段守卫逐条成立；除 `parseTerrain`（`:250-295` 整块 `catch(Throwable)`）外，`parseFocus` / `parseWeather` / `parseVictory` / `parseVictoryDef` / `parseSides` / `parseDiplomacy` / `parseArmies` / `parseEvents` 自身未包 try。本次逐行核对其内部取值器均有守卫，未发现裸调用；但守卫若被后续改动绕过，没有顶层第二道网。【L1-推断】

## 八、最不确定的一条

**测试 #9（`:121`）四类畸形坐标是否各自走对了回落分支（【L1-推断】，实跑【L2 待验】）。**

5. **证明不了壳层降级表现**：`degraded` 标识、warnings 文案在 Compose 壳层的展示未上真机验证。
6. 字符级配平扫描不能替代类型系统与编译器；字符串 / 注释剔除为启发式处理，极端字面量写法可能造成计数偏差。
