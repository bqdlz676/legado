### 4.1 反向推演（先假设本方案错误，找反例与边界）

- 反例 A：浮层与旧 Activity 各持一个 VM 实例，是否会双写历史 / 双订阅？——不会。两个实例作用域独立（Fragment 作用域 vs Activity 作用域），历史写入走同一 DAO 单表，去重由 DAO 与 `SearchHistory` 清洗收口；订阅流各自独立，互不串扰。
- 反例 B：重复打开浮层是否重建检索模型、重复订阅热门 / 历史流？——不会。`attach` 首建分支只在 `searchModel == null` 时进入；二次打开走幂等分支，`initialScope` 为 null 不覆盖作用域，空词不触发提交（`InkSearchViewModel.kt:56-70`）。
- 反例 C：第二批是否可能覆盖首批？——归约单源 `SearchReducer.LoadMoreAppend` 做追加 + 按 id 去重；断言 4 锁定首批保留。浮层未另写合并。
- 反例 D：双空时热门面板是否留白？——`SearchHotResolver` 必落 SEED 精选档，`SearchHistoryPanel` 双空还有 `HINT_GUIDE` 兜底文案；断言 3 锁定来源标记与非空。
- 反例 E：离线书架态（`ShelfState.OFFLINE`）打开浮层是否崩？——检索栈离线分支走本地缓存 + `Offline` 态，浮层 `OverlayFallbackWithCache` 渲染缓存列表与离线文案；书架本身离线态入口 `BookshelfScreen.kt:240` 同样可打开浮层。
- 反例 F：结果列表在面板内是否仍被裁切？——面板只限最大高度，列表 LazyColumn 内部滚动；`weight(1f, fill = false)` 给列表剩余空间，脚注随滚动可达。
- 反例 G：清空输入是否只清画面词、分页态残留？——清空走 `ClearQuery` 归约，关键词、分页态、结果一并复位回 Idle（`SearchReducer` 既有口径），状态机 query 同步清空。

## 六、二阶 / 三阶影响推演

- 二阶 1：Fragment 作用域 VM 在底部 Tab 切换时保留，热门 / 历史流持续订阅；Fragment `onDestroyView` 时 `viewModelScope` 取消，无泄漏。`onPause / onResume` 透传 `pause() / resume()`（`InkShelfFragment.kt:194-202`），后台不跑书源轮询，口径同旧 Activity。
