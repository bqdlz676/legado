# 规则 · 推送口径双轨（F-116）

> 生效：2026-11-25。锚点：`docs/拍板-2026-11-25.md:11`（用户原话「就按你的建议办」）。总账行：`docs/规则总账.md:129`。
> 本文是 F-116 的完整规则；总账只留一句话，细节以本文为准。

## 一、为什么要分轨

同一套 push 口径套不住两种改动，因为两条相反的事实同时成立：

- **文档改动先推的代价**：这类 commit 在 CI 里只跑验证、不产任何编译产物，先推等于把"还没验收过的历史"留在远端；还会把 F-109 的攒批纪律打散成零散推送。
- **代码改动后推的代价**：沙箱没有 JDK21/SDK（F-107），本地编译只能给假绿；如果坚持"本地验收过才推"，代码改动就永远等不到唯一可信的编译验证。

所以口径一劈两半：文档轨等验收再推，代码轨推了让 CI 验收。

## 二、A 轨（文档轨）

- **定义**：一个 commit 触及的路径全部落在 `docs/`、`data_scripts/`、或仓库根级文档（`*.md` / `*.txt` / 图片 / html）。
- **流程**：逐路径 `git add`（F-112，禁 `-A`）→ commit（带 `Verified-by: <验收代理id>`，纯文档可用 `Docs-only: 1`，F-111）→ 自检或独立验收结论为"过" → push。
- **判定依据**：验收结论为过；攒批一次推（F-109）。
- **适用条件**：规则文档、卡表、锚点、归因台账、data_scripts 里的校验脚本。

## 三、B 轨（代码轨）

- **定义**：一个 commit 触及 `app/`、`.github/`、`gradle/` 或构建配置（`*.gradle` / `*.kts` / `gradle.properties` 等）。
- **流程**：逐路径 `git add` → commit（`Verified-by: pending` 允许，由 CI 结果后补）→ **立即 push** → CI 判绿红（CI 即验收）→ 红则在下一轮做最小改动再推。
- **判定依据**：`verify.yml` 全绿（含 3185 条单测断言与 aggregate 硬校验）；打包车道由 `workflow_run` 只在验证绿后放行（R-CI-1）。
- **适用条件**：任何影响编译、单测、CI 定义或出包链的改动。

## 四、机械判别（不靠人眼）

```bash
python3 data_scripts/check-push-track.py                      # 判 origin/main..HEAD 全部待推提交
python3 data_scripts/check-push-track.py --sha <sha>          # 单条复核
python3 data_scripts/check-push-track.py --range HEAD~3..HEAD # 指定范围
```

- 输出每条 commit 的 `A` / `B` / `MIX` 与理由。
- `MIX` = 文档与代码混在同一 commit，违反 F-112，必须先拆分再推。
- 退出码：`0` 无混合；`1` 存在混合或 git 不可用。
- **保守规则**：认不出的路径一律算代码轨（B）——宁可多跑一次 CI，也不让未编译的改动留在远端当"已验收"。

## 五、与既有纪律的关系

- **F-109 攒批**：两轨都遵守"一次 push 一批"。A 轨攒到验收通过，B 轨攒到一轮改完。
- **F-111 trailer**：A 轨必须带 `Verified-by` 或 `Docs-only`；B 轨允许 `Verified-by: pending`，CI 绿后用下一条 commit 补。
- **F-112 逐路径**：两轨都不许 `git add -A`；出现 `MIX` 即视为违反 F-112。
- **F-107 禁本地编译**：这正是 B 轨存在的理由，不是偷懒。

## 六、边界与例外

- **紧急回滚**：允许先推后补 trailer（沿用 F-109 的豁免口），但必须在紧接着的一条 commit 里补 `Verified-by`。
- **单文件热修**（一个文件同时含文档与代码，例如 README 内嵌代码片段）：允许混合，但 commit message 必须写明 `F-112 例外` 与理由。
- **空提交**：归 A 轨，无路径、无害。
- **`pre-push.sh` 的历史包袱**：该脚本"给 message 就 `git add -A && git commit`"的分支与 F-112 直接冲突，已在本批改为拒绝并提示逐路径提交；这样推送入口不再能绕过逐路径纪律。
