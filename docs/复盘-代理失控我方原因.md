# 复盘 · 代理失控的"我方原因"

> 定性：失控代理的直接动作是代理做的，但**根因在我方派单机制缺失**——我们给了一个"没有边界的开放任务"，代理只能按自己的理解自由发挥，然后一路跑飞。这不是"代理笨"，是"我们没把笼子做好"。以下逐案归因，并给对应已补机制。

## 一、失控案例 → 我方原因 → 已补机制

| 案例 | 现象 | 我方根因 | 已补机制 |
|---|---|---|---|
| C4A（跑 83 分钟吐乱码） | 空转+乱码 | 没给超时、没给完成标准、任务切太大（"重写阅读器域六包"一整块） | 15 分钟熔断（E9/87）、划小范围（每单只一小片） |
| D1 验收代理（吐 MB 级重复串） | 重复输出 | 没给输出体积上限、没定"只回结论不复述全文" | 回报 ≤4KB、回话四格式（结论/路径/改动/grep） |
| B4（中段 seed 噪声） | 上下文串味 | 任务书塞了无关背景、边界不清 | 派单书自包含 + 只给这一单要的一手信息 |
| m_0cweOx7ZzeF（6894 次调用，网速插件任务） | 本地狂跑 4857 Bash + 539 Edit + 512 Write | 给了"做一个插件"的开放目标，没给工具预算、没禁本地重活 | E10 工具预算（写≤40/验≤60）、禁本地编译/重 IO |

## 二、我方五条共同根因（缺什么补什么）

1. **没给"工具调用预算"** → 代理无限探索、无限重试。→ 补：E10 写 ≤40 / 验 ≤60，超即判废。
2. **没给"超时熔断"** → 失控没人喊停。→ 补：15 分钟无产物判废 + watchdog 盯在飞超时。
3. **没给"输出体积上限"** → 吐 MB 垃圾把通道占死。→ 补：单条回报 ≤4KB，回话只四样。
4. **没给"完成标准 + 禁止清单"** → 代理不知道何时算完、什么不能碰。→ 补：派单书固定结构（范围/文件域白名单/红线/回话格式/验收标准）。
5. **没给"够细的切片 + 一手信息"** → 代理大量 search/read 空转，靠猜补上下文。→ 补：E11 零发现成本——切片/路径/契约/陷阱全预塞，子代理只"读切片→写→grep 自检→回话"。

## 三、结论（一句话）

**失控的根因不是"代理坏了"，是"任务没有边界"。** 边界 = 预算 + 超时 + 体积 + 完成标准 + 禁止清单 + 切片。这六样齐了，代理即使想跑飞也没有空间；之前全缺，所以任何一个代理都可能失控。现已全部落成机械门禁（E9/E10/E11 + watchdog + 派单书结构），不再靠"派单时记得"。
