## 四、被否决方案与反例

1. 否决：为 14 个未接类各建独立 Provider 槽。反例：09:30 拍板「其余类别走通用 EntityProvider，不加新 Provider」；七槽构造器与既有六 Provider 冻结；槽位膨胀会让匹配逻辑散落多处，违背「加新类别只加数据表不改 Provider/UI」。
2. 否决：让 EntityProvider 复用 PersonProvider / WordProvider 的匹配结果再二次出泡。反例：09:31 冻结不双轨；同一段落同一称谓会出两张气泡；本单对人物 / 地名 / 典故只登记为已覆盖（`EXISTING_SLOT`），适配层查询清单不含这三类。
3. 否决：把 D16 兜底壳直接作为气泡返回链上。反例：兜底壳 body / detail 为空串，直接上链即空白态，违反「不许空白态」；既有链契约靠 null 触发优先级下钻。收敛方式：兜底壳经结果壳回读状态与文案，链上未命中返回 null，最终由 MissingProvider 兜完整气泡。
4. 否决：把「类 → Provider」映射分别写在 Resolver 与 UI 两处。反例：单源要求；两处映射日后漂移会导致同名不同槽。映射只在 `ArtifactSlots` 一处定义，Resolver / 适配层 / 后续 UI 同读一张表。
5. 否决：扩展冻结 `BubbleContent` 九字段承载兜底状态。反例：B25 已立 `ArtifactFallbackResult(state, content)` 为唯一状态载体；契约字段不可扩，状态不能塞进 body / detail / source。
6. 否决：本单顺手落地草木 / 鸟兽 / 药名 / 山川真实数据表。反例：本单范围只做装配；真实数据量级与数据源归数据组装单；空实现占位不造假条目。

## 五、二阶 / 三阶影响推演

### 5.1 性能：每段每类查询量与缓存 / 短路

- 当前空实现路径：单次点击 `hitAt` 走 2~5 字词窗（长词优先），每窗遍历 14 个实体类调用 `EmptyEntityProvider.query`；空实现仅做 type 反查 + 兜底壳构造，无表扫描。既有人物 / 地名槽同为词窗循环口径，名物槽未引入新的线性扫表。
- 既有热路径缓存：`resolve` 结果按「段落 hash + 长度 + 位置 + 锚点年 + 锚点态」进 LRU（`cacheSize=64`），同段同位重复点击命中缓存，不重复走链。
- 风险前置：真实数据表接入后，每类 Provider 内部必须走索引 / 二分查表，禁止整表线性扫；14 类 × 词窗的调用次数在大库场景下需以 `BubbleBenchmarkTest` 同口径复测冷启 ≤300ms / 热路径 ≤80ms。段落级结果缓存、按首字 / 词长短路等优化列入另单观察，本单不预判实现。
- 三阶影响：名物槽位于地名之后、多字词之前；若真实名物 Provider 命中偏宽，会抢占普通多字词气泡。数据组装单须守「查不到返回 null」口径，兜底壳不得冒充真实命中。

### 5.2 与 D16「17 类剔除典故」裁决的关系

- P04 已把典故接进 allusion 槽（`WordProvider.matchAllusion` + `AllusionAnchorProvider` 总线重绑）；本单 `ALLUSION` 登记为 `EXISTING_SLOT/allusion`，不进实体查询链，未改动典故槽任何一行代码。
- 09:11 列入十七类 vs F-07 剔除典故的冲突仍属待裁；裁决回填前 `ALLUSION.schemaTable=null`，不挂 D16 数据表。若后续裁决剔除典故，登记表把该类移出清点即可，适配层无需改逻辑。

### 5.3 气泡 UI 容量限制

- 点击链路为 first-hit-wins：一次点击只产出一张气泡，名物槽接入不增加单次点击的气泡数量；既有 `ui/book/read/ink/` 侧未发现「一段最多几个气泡」的数量上限常量（仅见气泡宽占比 `BUBBLE_MAX_WIDTH_RATIO` 等样式参数）。
- 段落级批量气泡（如底栏列出全页地名 / 名物）的数量上限与排版容量属 `ui/**` 域，本单未核未改；需 UI 在飞单 / 后续接线单复核，列为另单。

### 5.4 依赖方向与包结构

- 依赖方向：`help.bubble`（Resolver / 适配层）→ `help.artifact`（登记表 / 接口 / 兜底）→ `help.bubble.contract`（冻结契约）；artifact 包不反向 import bubble 既有 Provider 实现。

- 既有七槽 Provider、D1 字典 / D2 人物 / D3 地名 / D4 典故代码结构未合并、未重构（09:31）。

### 5.5 既有测试兼容性

- `BubbleResolverTest` / `BubbleBenchmarkTest` 以 7 个位置参构造 `BubbleResolverImpl`；新槽带默认值，旧调用源码兼容。默认装配的空实体适配层不向 Stub 记录表写条，既有「链序 / 缓存 / 兜底」断言口径不变。
