# 卡片基座·噪点平铺改造报告

## 缺陷原由
`CardBase.kt` 原私有 `cardNoise()` 用 `drawBehind` 在 2dp 网格逐格 `drawCircle`：书架 20 张卡同屏滚动约十几万次 drawCircle/帧，必掉帧；且每帧走 while 循环掷点。

## 规格判据原文（切片-25 第 70 行，判据 8）
> 8. 颗粒 noise 走 1 张 ≤64KB 平铺 png（不逐卡生成），滚动时无新 Bitmap 创建（grep 证明）；

## 改动点（仅 `CardBase.kt` + 新增 1 张 png；未动 CardTokens / 其他卡片 / icon）
- 新增 `app/src/main/res/drawable-nodpi/paper_noise_tile.png`：64×64 RGBA，墨色 `#1A1410`，alpha 峰值 8/255，其余全透明，固定种子 4102517，227 粒。
- 删除逐格 `drawCircle` 旧实现；新增文件级进程缓存表 `noiseTileCache`(L195–196) 与取图函数 `noiseTile`(L202–211)；`cardNoise()`(L217–240) 两层 `remember`，`drawBehind` 内只 `drawRect`。
- import：删 `kotlin.random.Random`、`imageResource`、`BitmapPainter`、`painterResource`；增 `Resources`(L3)、`BitmapDrawable`(L4)、`asImageBitmap`(L32)、`LocalContext`(L33)、`Collections`(L36)；`Log`(L5)。
- 关键行号：L195–196 缓存表；L202 `synchronized(noiseTileCache)`；L203 命中返回；L205 `getDrawable`；L206 `BitmapDrawable`；L208 `asImageBitmap`；L209 成功入表；L221 `LocalContext.current.resources`；L225 `remember(res)`；L227 `Log.w`（位于 remember lambda 内，仅失败那次组合打一条）；L232 `remember(noiseBitmap)`；L233 `ShaderBrush`；L234 `ImageShader`；L236/L237 `TileMode.Repeated`；L241 `drawRect`。
- 对外签名 `CardSurface(state, modifier, content)` 与五态行为不变。

- `noiseTileCache`：L195、L196、L203、L209；`synchronized`：L202；`asImageBitmap`：L208；`Log.w`：L227（唯一调用点，在 L225 `remember(res)` lambda 内）。

## PNG 校验（python3 / PIL + numpy）
- 64×64、mode RGBA、**638 B**（≤65536）；max alpha 8；227 粒；透明像素 RGB 全 0；可正常解码。

## 判据 8 证据（可判定结论：进程内解码 1 次）
- 缓存表：`private val noiseTileCache`（L195–196，`Collections.synchronizedMap`，key = 资源 id，value = 解码后 `ImageBitmap`），文件级单例，不进 `CardTokens`，不随组合销毁。
- 取图链路 `noiseTile`(L202–211)：`synchronized(noiseTileCache)` 段内先查表（L203）→ 未命中才 `getDrawable` → `BitmapDrawable.bitmap` → `asImageBitmap`（L205–208）→ `onSuccess` 入表（L209）；`runCatching` 全包，异常返回 null。
- 论证链：进程级缓存表按 resId 共享解码位图（跨槽位、跨密度）→ `remember(res)` 挡重组重复取表（L223）→ `remember(noiseBitmap)` 每槽位建一次 Brush（L230）→ `drawBehind` lambda 仅 `drawRect`（L239），帧内零新建对象、零解码。
- 结论：书架 `LazyColumn` 20 卡滚动，无论新进屏多少槽位，`paper_noise_tile` 在**进程内只解码 1 次**；滚动过程无新 Bitmap 创建。跨槽位共享风险已由我方缓存表消除，不依赖 Compose 内部缓存行为。

## 兜底与降级
- `runCatching` + `getOrNull`：资源缺失 / 非位图 / 解码失败均返回 null；`Log.w`(L227) 置于 `remember(res)` lambda 内，仅失败那次组合打一条，后续重组不刷屏；判空后 `return this`，不画噪点层，纸白底与交互照常。
- 允许静默降级的原因：噪点只是材质装饰，缺它不影响可读性与交互；故不抛异常、不阻塞卡片渲染。

## 二阶影响
- `CardTokens.noiseSeed/noiseGrid/noiseProbability/noiseAlpha` 基座内已无引用（仅定义处留存）；按约束未改 `CardTokens.kt`，留待后续清理。
- 缓存表进程生命周期内持有一张 64×64 位图（≈16KB 量级），无逐卡累积；无内存泄漏路径（单例 + 单条条目）。

- 平铺接缝为单像素点，未做跨边缘包裹；视觉效果待真机复核。
