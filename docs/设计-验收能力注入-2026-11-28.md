## 2. 两条门禁的判据口径

### 2.1 g77 文件域互斥（audit）

- 解析台账中状态为 ACTIVE / RUNNING / 在飞 的行，取 `文件域` 列；多域以 `、` / `；` / `，` / `+` 分隔。
- 任一两条在飞行的文件域 token 完全相同，或成父子目录重叠（`ui/card/**` ↔ `ui/card/BookCard.kt`）→ 报红并给两行行号。
- 豁免：域列为 `—` / `-` / `待拆` / `待定` / `待派` / `无` / 空，或纯散文 token（无路径、无扩展名）；
  同一行内部多域是单内正常切分，不与自身比对；终态行（✅ / 已交付 / 已收口 / 已完成 / 已提交 / DONE /
  作废 / 已裁决 / 已判定 / 判不通过 / 待裁）不参与互斥。
- 退出码：0 PASS / 1 FAIL / 3 UNVERIFIED（台账不存在或在飞行空集；空集不判 PASS，假绿结构兜底）。

### 2.2 g78 判据证据对齐（audit）

对状态为 DONE / 已验收 的行，四条判据：

1. **分人（F-108）**：`独立验收代理` 非空，且其 `s_` 代理 id 与 `写码代理` 不同；占位词
   （待派 / 无 / — / 待定 / 待产出 / 不另设验收 / 待回执…）视为缺位；两侧 id 相同判 SAME-AGENT。
2. **产物存在**：`验收产物` 指向的仓内文件真实存在；占位产物（待产出 / 预定 / 待定 / —）判
   PRODUCT-MISSING；抽到的路径解析不到文件判 PRODUCT-DEAD。
3. **判据 ↔ 证据一一对齐**：产物报告里每条判据都带可回源证据（`文件:行` / CI `run id` /
   `文件:行号` 三者之一）；判据条数与证据条数对齐，一条证据服务多条判据（多对一）不算对齐。
   报告解析不出判据标记时跳过本项（不逼人造格式）。
4. **锚点真实**：每条 `文件:行` 锚点的文件存在，行号不超过该文件总行数；死文件 / 越界判红。

退出码同 g77：0 / 1 / 3（空集 UNVERIFIED，不判假 PASS）。

### 2.3 白名单与身份绑定（㊼ 形态，照 g76 已验证形态）

- 存量豁免落 `data_scripts/verdict-gate-allow.txt`，四列制表符：脚本名 ｜ 行号或缺陷号 ｜
  内容 sha256 前 12 ｜ 豁免理由。
- 身份绑台账行原文哈希：行被改名或换内容，哈希即变，自动失去豁免（已做篡改夹具实测：原样命中、
  尾部加空格后不再命中）。白名单只许删不许加；存量条目随收口逐条补齐后删除对应行。
- 空集（无待检对象）判 UNVERIFIED rc=3，不判 PASS。

## 5. 砍掉第三条：判据可测性前置为什么不立

原拟第三条能力：判据可测性前置，落 `最高级别` 列 L0..L4 语义（DONE 至少 L0、L1 以上须有层级
证据小节、已验收缺层判 FAIL）。本单取消，理由：

1. **根因在规格侧，不在验收侧**：星空 268 行一次验收里 23 条判据不可验、33 FAIL，根因是判据
   本身没有观测方式（不可观测、不可实测），而不是验收时没查出来。这种缺陷必须在派单前的锚点卡
   「判据条数 / 观测方式」字段里前置治住；验收门禁事后只能读到台账上的声明，判到的是「写法」，
   不是「事实」。
2. **层别完整性在 audit 下同样只能判声明**：L0..L4 小节 / 锚点是否存在是书写结构，判不出该层
   证据是否充分；在没有规格侧观测方式字段配套前先立这条，误报面大，且会诱导为过门禁而补层级
   小标题（与 g78 要防的凑锚点假证据同类）。
3. **处置位置**：判据可测性留待锚点卡 / 派单模板补「观测方式」字段后，再评估是否需要门禁；
   本单不建 `check-verdict-level.py`、不登记 g79、不接 `rule-gate.sh`。

  误报率口径：误报条数 / 门禁命中总条数，按单记，不合并成百分比粉饰。
- **转 blocking 条件**：连续 3~5 单误报率降到可接受区间（目标误报 0 条/单），且白名单存量逐条
  补齐删除后，才在 `gate-levels.json` 把对应门禁改 `blocking`；在此之前 audit 只入报告、不拦单。
  转 blocking 前不扩判据、不加新门禁列。

## 7. 最强反对者：能推翻这两条门禁的证据

按「先假设当前方案错误」逐条列出反证与边界，验收时优先找这些证据：

1. **门禁增量导致 CI 红停发**：两条 audit 门禁若被误接成 blocking，存量 35 条 g78 违规会让
   每次 push 红、新单发不出去。反证信号：rule-gate 全量跑出现 FAIL 且归因到 g77 / g78；
   对策：保持 audit 分级，`--blocking-only` 下跳过。
2. **g78 诱导凑锚点假证据**：为过「判据 ↔ 证据对齐」，写码 / 验收方可能补一堆格式合规但不指向
   真实落点的 `文件:行` 锚点。本闸只验锚点存在与行号不越界，验不了落点是否真支撑该判据；
   这部分仍归验收代理 L1 逐条销项与真机 / CI 证据，不能把 g78 当成证据充分性结论。
3. **g77 看不到归属，只看到声明**：文件域是台账自报字段，单把域写窄（只写目录不写文件）或漏报
   文件，g77 拦不住；真实归属仍靠提交前 `git diff --cached --name-only` 人判与 g75 / g40 /
   g59 兜底。若实跑发现两单声明域不重叠却发生索引带走，说明声明口径失真，需要回到调度层登记
   准确性，而不是加厚本闸。
4. **正则识别的误报面**：判据标记、路径 token 都靠文本正则；散文式销项报告、中文散文粘连路径、
   仓外文档基名都是已知误报边界（见 §2.2 与脚本 docstring）。试跑期若误报集中在某类格式，应
   收窄正则或补解析，而不是放宽判据。
5. **白名单膨胀**：若存量条目只增不减、新违规也进白名单，门禁等于失效。反证信号：白名单条数
   随试跑上升；对策：白名单只许删不许加，收口单逐条销项并删行。

## 8. 回滚方式

两条门禁均为独立静态脚本，回滚按最小改动：

1. 接线层：从 `data_scripts/rule-gate.sh` 移除 g77 / g78 两个调用块（本单新增，未触碰既有块）。
2. 分级层：从 `data_scripts/gate-levels.json` 删除 g77 / g78 两个条目。
3. 脚本与白名单：删除 `data_scripts/check-file-domain-conflict.py`、
   `data_scripts/check-verdict-evidence.py`、`data_scripts/verdict-gate-allow.txt`；
   不影响其他门禁（g76 孤儿闸等既有脚本与白名单独立）。
4. 文档层：本设计文档可整体留档或撤下；台账既有行语义未被本单改动，无需回写台账。
