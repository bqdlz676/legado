# 铁律 · 测试函数名合法性（F-100）

## 一、问题（同一根因连炸两次）

- run `45453607335`：`DesignTokenGuardTest.kt:25` 反引号函数名 `anchor contract: ...` 含 **冒号** → `compileAppDebugUnitTestKotlin` FAIL。
- run `45465010171`：`VerticalReaderParamsTest.kt:17/23` 反引号函数名含 **小数点**（`栏宽 = 885.6`、`行距 = 32.4sp`）→ 同一任务 FAIL。
- 共同根因：Kotlin 反引号名在 JVM 目标下禁止 `. : [ ] / ; < >`；本地无 JDK21 无法编译，只能等 CI 15 分钟才得知 → 一次失误=一整轮空转。

## 二、规则

1. **测试函数名（反引号内）禁含 `. : [ ] / ; < >`**；小数写成"885点6"这类中文表述，或改用下划线。
2. 新增/改动测试文件后，**push 前必须跑** `python3 data_scripts/check-test-fun-names.py`（已进门禁 ㉘）。
3. 违反者一次即返工；不许"先推上去等 CI 告诉我"。
4. 同类"本地无法验证、只能等 CI"的检查，一律先落本地机械脚本（本条就是先例），不许靠记忆。

## 三、为什么是铁律而不是建议

- 成本对比：本地脚本 0.1 秒 vs CI 15 分钟；一轮 CI 红还会连带取消后续 push 的 run（`concurrency.cancel-in-progress`），实际损失被放大。
- 可机械判定：字符集是封闭集合，不存在"看情况"，因此禁止留给人工判断。

## 四、反例边界（什么时候不适用）

- 非测试代码的函数名不受此限（普通标识符本来就不允许这些字符，编译器会直接拦）。
- 字符串字面量、注释里的 `.` 与 `:` 完全合法，脚本只扫 `fun \`...\`(` 形态，不误伤。
