## 六、自查反例 / 改坏推演：已交付行误迁的后果与避免方式

- 反例 1（已交付行迁进主表虚高在飞）：若把 Q-236～Q-252 这类 DONE 行也搬进主表，⑯ 台账在飞计数与 ⑱ RUNNING 统计虽按状态格判定不直接虚高，但主表混入大量旧行会稀释 C3 四要素巡检面，且 ㊶ 主表行数虚增、结构漂移回潮。避免：迁前逐条对台账状态格与收口报告，状态非 DONE 且无 ✅ 才迁；§2.2 留档清单逐条留历史小节。
- 反例 2（只挪行不补列）：5 列原样进主表，㊶ C1 立即报列数 5≠6，RUNNING 行再缺起时/文件域/判据锚被 C3 连串打红；本单每行都补齐创建时间、状态格要素、依赖锚点与文件域，抽查 3 行回证 6 列齐全。
- 反例 3（合并号首格带斜杠）：`Q-231/232/233` 不匹配 ㊹ 行首正则 `^\|\s*(Q-\d+)\s*\|`，整行变成 B/C 永久盲区（㊹ 实测报「1 行含 RUNNING 但无法解析」）；规整为首格单 Q 号、余号入标题后解析恢复。
- 反例 4（批量 sed 全表重排）：一次性把历史小节全部行搬到主表，会把 4 列留档行、作废行、DUP 行一并卷入，破坏 commit/断言行号回源；本单一次一行，迁一行删一行旧位。
- 反例 5（迁移时改并发在飞行的范围/状态）：Q-253/Q-258/Q-261 迁移后由并发代理收口，本单只规整列位，不改其标题范围与收口结论。
