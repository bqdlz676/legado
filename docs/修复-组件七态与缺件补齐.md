## 六、自查反例与边界（最强反对者自查）

- **反例 1：空数据不是禁用。** 契约 `EMPTY.eventsAllowed=true`、`contentAlpha=1f`，旧模型曾把 empty 归入不可交互（`isInteractive=false`）是错的。本单保留 EMPTY 可点、不压淡；空态重试按钮仍按 B17 分闸独立放行。
- **反例 2：离线不压淡但禁点。** `OFFLINE.contentAlpha=1f`、`eventsAllowed=false`；不得套用禁用档 0.30 压淡，也不得让离线容器本体可点。重试入口作为独立入口分闸放行，不改变容器本体闸。
- **反例 3：显式 state 与布尔输入冲突。** 若宿主传 `state=DISABLED` 但 `enabled=true`，外观闸与手势闸会不一致；本单在 `InkButton.kt:104-107` 取并集（`effectiveDisabled = !enabled || state == DISABLED`，加载/离线/空同理），双保险拦点击。
- **边界 1：排除域未迁移不能删桥。** 旧枚举定义虽已删，但 `InkCard.kt:86/:98`、`BookshelfScreen.kt:59/:815` 仍经别名/身份扩展引用；此时物理删除别名或扩展会直接编译红。故保留并写明唯一用途，属 A3「新链路接好再物理删旧」的未完成侧。
- **边界 2：无宿主的组件不造假接线。** `InkTimeline` 当前生产调用点为 0；`InkToastHost` 宿主在 book 域、`InkBottomSheet` 宿主在 config 域，均属排除域。三件组件已接受 `state` 并渲染对应分支，但本单不为凑 grep 给它们安插假调用点；非默认态宿主接线登记入队。
- **边界 3：进度值越界。** `InkProgress` 的 `progress` 入参 `coerceIn(0f, 1f)`，负值/超 1 不绘制越界段；Divider 厚度默认 1dp，由调用方按需加重。
- **否证后结论成立**：上述反例逐条在实现与断言中闭合；未闭合项均为排除域或无宿主场景，已转入新发现问题节，不留空白态。

## 八、旧号结论（60 / 62 / 64 / 65）

- **旧 60（B5 跨领域对照）**：对照 Web 前端组件库状态机（档位枚举 + disabled/loading/empty/offline 事件与透明度分离）与 Compose `MutableInteractionSource` 手势源。采纳：枚举档位携带 `contentAlpha/eventsAllowed` 两字段的契约写法；不采纳：Material ripple（落文明确禁 ripple，切片-04:6），不采纳 `MutableInteractionSource` 作为第二套状态源（手势只做指针跟踪，不持有状态规则）。
- **旧 62（B12 历史包袱审计）**：旧七态枚举属**历史遗留**——与契约包重复声明档位与可点口径；旧 `isInteractive` 属**为已不存在问题引入**——契约已有 `eventsAllowed` 等价字段。可安全移除：旧枚举定义、旧映射跳跃、`isInteractive` 口径。暂留：类型别名与身份扩展，编译锁在排除域未迁移调用点上，不满足零引用删除条件（见 `ComponentState.kt:14-18`）。
- **旧 64（B13 最慢环节）**：本单为状态接线与补件，不涉及编译/单测/体积/启动路径，未引入新的慢点。仓内既有慢点观察：ToolScaffold 开关与长按行绕过墨触闸（N1），手势层若补长按能力后可一并收口；状态解析为纯函数，无热路径分配放大。
- **旧 65（B12 返工复盘）**：B18 六态双源前科的共同根因是「状态规则在两处各写一份 + 映射层滞留不回收」。本单对策：枚举规则单源化、快照只做输入记录、过渡桥 KDoc 标注回收条件与唯一用途；沉淀规则：**新组件状态只接契约枚举，禁止再包一层自声明枚举或第二套可点/压淡系数**。
