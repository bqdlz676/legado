# 构建说明 · Tycho 派生素材不入库

> 用途：写明 Tycho 派生素材在 APK、CI artifact、git 三处的入库边界，以及 CI 校验口径，作为出包门禁依据。
> 落地依据：`docs/星空天象层-实施规格-合并定稿.md:72`（§二 第 4 条「合规三条」第三分句：「Tycho 派生素材不进 APK/CI artifact 的规则写进构建说明」）。

## 规则一：派生素材不进 APK、不进 CI artifact、不入 git

- 对象：Tycho 派生素材，包括 mag > 6.5 的金字塔层级切片、原始 2,539,913 行星表（含原始抓取件与中间派生表）。
- 边界：上述素材**不进 APK `assets/`**、**不进 CI artifact**、**不入 git**；只允许出现在按需下载链路，落用户设备本地缓存。
- 为什么：派生素材可由原始星表按需重建，随包分发会同时违反包体上限与 NC 分发口径；规格一页纸速览第 3 条已明确「Tycho 派生素材不进 APK/CI 产物」。
- 适用条件：所有 mag > 6.5 的分层切片、原始星表抓取件、行星表中间产物；无论提交进仓库、打进 assets 目录，还是随构建产物打包上传，均在禁止范围。

## 规则二：APK 内只允许内置层

- 对象：APK 内置数据只允许 mag ≤ 6.5 的内置层，约 9,100 行，总体积 < 2MB；更深星等一律走按需下载。
- 为什么：内置层是离线可用下限，包体必须压在 < 2MB 内；更深星等在金字塔链路按需取得，不随包携带。
- 适用条件：`assets/astro/**` 内置矢量、分野表与内置星表层；超出 mag ≤ 6.5 的星表数据不得写入该目录。

## 规则三：CI 校验口径（违者判红）

- 判据：构建产物目录与 CI artifact 中不得出现金字塔切片与原始星表文件名模式；以下任一命令输出非空，构建判红。
- 为什么：入库边界不能靠约定，必须由可执行命令在出包前与打包后各扫一次，扫描结果进 CI 门禁。
- 适用条件：CI 出包前的构建中间产物目录、打包上传前的 artifact 目录；本地出包自查复用同一组命令。路径以实际构建目录为准，文件名模式随数据目录命名落地时补齐。

可执行判据示例：

```sh
# 1. APK 构建中间产物：按文件名模式找金字塔切片与原始星表件
find app/build/intermediates/assets -type f \
  \( -iname '*pyramid*' -o -iname '*tile*' -o -iname '*lod*' \
     -o -iname '*tycho*raw*' -o -iname '*hip_main*' \)

# 2. 产物目录内递归检索原始星表行数标记与原始表字段名
grep -RInE 'tycho2?_?(raw|full)|hip_main|2,539,913' app/build/intermediates/assets

# 3. CI artifact 目录（打包上传前再扫同一组模式）
find "$ARTIFACT_DIR" -type f \
  \( -iname '*pyramid*' -o -iname '*tile*' -o -iname '*lod*' \
     -o -iname '*tycho*raw*' -o -iname '*hip_main*' \)
```
