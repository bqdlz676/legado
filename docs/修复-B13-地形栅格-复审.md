### 1. 新增 `terrain/HeightMapDecoder.kt`（445 行）

- `SourceKind` 枚举（L20）：`ASSET / LOCAL_PATH / BASE64 / SYNTHETIC / NONE`。
- `HeightMapRaster` 数据类（L29-48）：`width / height / data: FloatArray(0..1) / degraded / source`；行优先、行 0=北缘、列 0=西缘，与 `HeightRaster`/`TerrainMap` 同方向。
- `classify(raw)`（L91）：空白→NONE；`data:` 前缀→BASE64；`/` 或 `file://`→LOCAL_PATH；无路径分隔且像 base64（长度 ≥32、字符集合法）→BASE64；其余→ASSET。

- 护栏（L67-79）：`MAX_DIMENSION=2048`、`MAX_PIXELS=4_000_000`、`HARD_DIMENSION=8192`、`HARD_PIXEL_CAP=8_000_000`、`DEFAULT_GRID_N=32`（对齐 `CampaignController.GRID_N`）。
- `downsample(...)`（L331/337）：超护栏等比最近邻降采样；抽成独立纯函数便于单测喂小栅格验证比例。
- `synthesize(seed, width, height)`（L376）：FNV-1a 字符串哈希播种 + 三倍频值噪声（类柏林噪声）+ 中央低洼带；同字符串两次逐格相同；不用 `Random`。

## 四、二阶三阶影响

### 4.1 连带消费方（点名文件 / 接口）

- `terrain/TerrainMap.kt`：现有消费口径是 `HeightRaster`（0..255 `IntArray`）；本单新增的 `HeightMapRaster` 是 0..1 `FloatArray`，两套栅格暂并存。**转换点未在本单落地**：controller/桥接装配时需 `0..1 × 255` 转 `IntArray` 再喂 `HeightRaster.create`；在此之前新解码器不改变 `TerrainMap` 既有行为。
- `shell/CrossingRasterBridge.kt`：既有 `RasterDecoder` 接口 + `fromDecoder/fromInlinePixels/resample` 通路保留不动；本单解码器是该接口背后可复用的纯 JVM「字节→栅格」实现，平台侧 `RasterDecoder` 包装时可直接调 `decodeBytes`，不必再写 PNG 解析。
- `engine/CampaignController.kt`（B7 在飞，未碰）：现有兜底 `HeightRaster.synthetic(...)` 通路不变；后续接线建议在装配 raster 处改调 `CampaignJsonParser.decodeHeightMap(def.heightMap, assetReader)`。
- 体积：不新增 assets / 第三方库；解码器源码约 445 行，编译后体积增量可忽略（F-05 不承压）。

### 4.2 内存（F-04 ≤100MB 三档口径）

- 正常路径：1024² 灰度 → raw 1MB + 灰度 IntArray 4MB + FloatArray 4MB，瞬态约 9MB。
- 护栏路径：超 2048 见方或 4MP 先降采样；IHDR 声明超 8MP / 8192 单维直接拒绝回落合成，不分配像素缓冲。8MP 上限下三态峰值估算 ≤96MB（raw ≤32MB + IntArray ≤32MB + FloatArray ≤32MB），贴线但不越 100MB；常规战役图远低于此。
- 推演网格侧仍由桥接重采样到 32×32（`GRID_N`），常驻栅格仅 1KB 级。

### 4.3 反例与边界（至少 3 条，均有兜底）

1. **空数据 / 断网 / 资产缺失**：reader 返回 null 或抛异常 → `decode` 回落 `synthesize(heightMap 串哈希)`，`degraded=true`，不空白、不崩。
2. **非 PNG / 损坏字节 / 截断 IDAT / 非法 filter 码 / 畸形 chunk 长度**：`decodeBytes` 逐级返回 null → 合成场；不把异常抛到 UI。
3. **超大图 / 恶意头声明天文尺寸**：硬上限先拦（8MP、8192），软上限降采样（2048、4MP）；最近邻采样确定性可复算。
4. **字段类型错位**（对象 / 数组 / JsonNull）：仍走原 `strOrNull` 守卫回落 null，本单未改该口径。
5. **同名消歧 / 同名资产**：本层不做同名消歧，按字符串原样交 reader；查不到即合成兜底，不假装解码成功。
6. **16-bit 深 / Adam7 隔行 / 非支持色彩类型**：显式回落合成（能力边界，非崩溃路径）。

### 4.4 认知成本

- 新增概念两层：`SourceKind`（来源分类）+ `HeightMapRaster`（0..1 FloatArray 栅格）。与既有 `HeightRaster`（0..255 IntArray）并存，命名与值域在类注释里互相指明换算关系，避免接手人混用。
- 解码器把「字节→栅格」抽成零依赖纯函数，BitmapFactory 不进引擎层；单测可在普通 JVM 跑，无需 Android 环境。
- 遗留易混点：parser 暴露的 `decodeHeightMap` 与桥接 `RasterDecoder.decode` 是上下游关系（前者纯 JVM 装配入口，后者平台接口），报告交接节已注明；建议下一单在 controller 接线时把两条路径合并表述。
