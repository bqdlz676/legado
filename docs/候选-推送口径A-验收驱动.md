# 候选方案 · 推送口径 A：验收驱动 push（未落地，待定论）

> 状态：**候选方案，未落地**。`data_scripts/pre-push.sh` 保持现状，本文件仅记录待拍板口径与自测草稿；
> 在用户下定论前，不改造、不 commit、不 push。

## 一、三个判定条件（全满足才推，任一不满足打印原因并 exit 0，不阻塞、不报错）

1. **工作区干净**：`git status --porcelain` 无未提交改动——防漏文件。
2. **整批验收合格**：`git log origin/main..HEAD` 里每一条 commit 都带 `Verified-by: <验收代理id>`，
   且没有任何 `Wip:` 提交、也没有缺 trailer 的提交。`Docs-only:` 视同合格（纯文档免验收）。
   - 整批合格才推，**不推"最前面连续合格的一段"**：要么整批推、要么一个都不推，简单可判，不产生半推状态。
   - 不满足时逐条列出未验收 commit 短号与缺什么（`Wip 未验收` / `无 trailer`），便于直接派验收单。
3. **CI 无在飞 run**：复用 `data_scripts/check-push-window.py`，输出含"在飞"即判忙，不打断正在跑的验证。

## 二、时间窗降级为 5 分钟防抖（理由）

- 旧口径"距上次 push ≥30 分钟"**废弃为主判据**，只保留 5 分钟防抖，防同一分钟内连点两次 push 触发两批 run。
- 为什么废弃时间窗：时间窗是"猜 CI 什么时候结束"的笨办法——窗口时长靠估，估短了撞在飞 run，估长了拖慢槽位周转；
  验收驱动是"知道什么时候该推"的准办法——条件 2 已经确认整批合格、条件 3 确认 CI 空闲，何时该推由事实判定，不靠猜时长。
- `docs/.last_push_epoch` 里那 26 分钟实测（主 run 实测时长）只作为防抖参考记录，不再作为闸门。
