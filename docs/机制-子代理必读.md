# 机制 · 子代理必读（执行方专用）

> 你是被派来**只做一件事**的执行代理。开工顺序：① 读完本文件；② 读任务书指的 `docs/问题清单.md` 那一条编号；③ 读 `docs/问题清单-附录-逐文件.md` 里对应的落点清单；④ 读任务书给的报错原文/契约原句。**不要通读全仓、不要通读总纲，不要自己"顺便"扩大范围。**
> 铁律全文在 `docs/落文-规矩总纲.md`，你只需要知道与你直接相关的这几条（下文的 R48/R57/R66 等编号即指它）。

## 0. 十秒钟规矩（先背下来）

- **R57 一条缺陷一单**：只修任务书点名的那一条。发现别的缺陷 → 记进报告"交接"节，**不要动手改**。
- **R48 一次性**：你不接追加任务；改完即交报告，不再等新指示。
- **禁 git 写操作**：不许 add/commit/push/revert/checkout——提交由总控统一做。
- **禁本地编译**：不许跑 gradle / kotlinc / assemble。编译只在云端 CI 发生。
- **文件域独占**：只碰任务书白名单里的文件；工作区里别人未提交的改动（`git status` 里不是你的）**不许删、不许改、不许提交**。

## 1. 证据链（报告的核心，不是附属）

1. **改前/改后代码对照**（逐处：文件:行号 + before + after）。
2. **grep 回证**：每一处改动后用 `grep -n` 贴出真实输出（证明代码真的写入、证明旧符号真的清零）。没贴 grep 的改动视为未改。
3. **数字必须自己算**：行数、计数、字节、sha 不许估；量不出来就写"未测"。
4. **未验证项声明**：没编译、没跑测试、没真机 —— 一律显式写出来，不许用"应该没问题"代替。

## 2. 报告必含三节（R59/R61/R63）

- **二阶三阶影响**：直接效果 → 连带影响（点名受影响文件/接口/调用方）→ 对用户行为、系统复杂度、维护成本的后果。
- **反例与边界**：如果我的判断是错的会怎样？至少列 3 个边界（空数据 / 断网 / 缺字段 / 同名消歧失败 / 极端参数），并说明你的实现怎么兜。
- **认知成本**：这次改动让接手的人更容易还是更难？新增了几个概念、几层抽象，是否需要命名澄清。

## 3. 不许做的事（做了就整单作废）

- **贴皮**（R56）：不许复用旧 XML 布局 / `*Binding` / 旧 Adapter/ViewHolder / 旧 Fragment 界面编排；不许把旧 XML 结构逐条翻译成 Compose。可复用的只有：DB/DAO、网络抓取、规则解析、偏好存取、`model` 数据类。
- **留兼容层**：新逻辑接好后直接删旧路径，不留"旧格式兜底"。
- **自己摘要原文**：任务书给的规格/原文/切片必须逐字对待，不许压缩、不许改写、不许"我理解大意是"。
- **编数字**：不许编造 sha、行号、计数、测试结果。
- **拿 `image_gen` 当最终素材**：图形类交付必须代码显式绘制或矢量定义。
- **扩大战场**：不许"顺手优化"、"顺便重构"、"发现有 15 条错就一起修"。

## 4. 设计类任务额外要求

- 几何/颜色/字号等参数必须**写进报告并可复算**（圆心、半径、厚度、角度、占比）。
- 走查自检：逐档量实际像素、逐档检查边界（透明、超界、安全区），并贴预览图自检结论。
- 用户明确否决过的方向（红章/印章/双字/彩虹渐变/纯黑底等）**不许再出现**。

## 5. 交付格式

- 报告路径：任务书指定（一般是 `docs/<动作>-<模块>.md`）；**不许覆写别人的报告名**。
- 报告结构：① 任务与范围 ② 改动清单（文件:行 + before/after）③ grep 证据 ④ 三节（影响/边界/认知成本）⑤ 未验证项 ⑥ 交接（发现但未改的跨模块问题）。
- 回话（给总控）只写四样：`报告路径` / `改动文件数与行数` / `grep 关键结果` / `未验证项`。不要在回话里复述报告全文。

## 6. 跨模块问题怎么处理

发现不属于自己文件域的问题：**写进报告"交接"节**（现象 + 证据 + 建议派给哪个模块），并在回话里点一句。**绝不自己动手修**——你一动手就越界，会把别人的单子搅成一锅。
