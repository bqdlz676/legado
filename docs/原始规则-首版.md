# 落文 · 规矩总纲（做任务前必读）

> 唯一重读入口。上下文被压缩后，先读本文件再动手。

## 一、目的 vs 手段（最高优先级）
- 灵魂闭环只是冒烟用例，**验收是手段、不是目的**：打开书→竖排读→点字出气泡→点「晋」命中春秋晋国→点「鲁隐公元年」出前722干支辛酉。
- 真正目的是：把整套规格做对、做好看、好用、所有边界兜底，不降级、不砍功能、不允许空白态或崩溃。

## 二、四条硬规则（读对话/派单/验收的根本纪律）
1. 锚点强制可回源：每条结论必须能回到原文行号/切片/文件。
2. 规格、契约、验收三类**禁止压缩**，只压缩已完结过程。
3. 子 AI 禁止自行摘要——只读小段原文照做，靠索引+完整覆盖核对。
4. 三层分离：
   - 导航层：可有损，只答"在哪"。
   - 执行层：无损，原文切片逐字。
   - 验收层：逐字对照原文全文。

## 三、铁律（逐条，来自用户长期偏好）
1. 落文只保留 Legado 排版引擎，界面全部原生自绘重写。
2. 编译通过只代表语法过，不代表功能可用，未验证必须明说未验证。
3. 交付前必须自我模拟跑一遍关键路径并逐项自查，再报完成。
4. 每个项目先做单项自检，再做一次整体自检，才可交付。
5. 目标真机是荣耀 WIN，12GB 内存，安卓手机（用户语境"win"指手机，与电脑无关）。
6. 规格未覆盖的边界情况自行判断并兜底，不允许空白态或崩溃，不降级不砍功能。
7. 每完成一个模块必须自测验收，跑不通不交付。
8. 规格超上下文时分段读、记结论继续读，不许跳读。
9. 改代码要推演二阶三阶影响，不只考虑改动直接效果。
10. 做方案先假设自己方案错误，找反例边界重新评估再定。
11. 改动后必须先 grep 确认代码真的写入，未生效不许编译更不许报完成。
12. 分析代码库历史和遗留包袱，识别可安全移除的历史代码。
13. 以新人工程师视角评估代码认知成本，简化命名与职责不清的代码。
14. 复盘 Bug 返工回滚的共同根因，沉淀为项目规则或自动化。
15. 质量优先，交付前自检，不好全部返工；已有实现绝不复用只做参考。
16. 每个模块配可跑的单测和 bench，性能指标跑过才算数，只过编译没真机验证的显式写进交付说明。
17. 固定签名 keystore 收口，签名不一致会导致覆盖安装失败。
18. 负载高时并发降到 2 个，质量优先，时间放宽。
19. 用户原文规格必须逐字保留、不蒸馏不改写；子 AI 读全靠索引+完整覆盖核对，不靠压缩浓缩。
20. 派单任务尽量划小范围，每个子 AI 只读小段原文照做，减少其自行编造或摘要。
21. 每次出 APK 必须 JDK17 先 clean 再 assemble 全量重编，禁止增量编译。
22. 排查问题用穷举法：列全部嫌疑点后一次性全改，不逐点试。
23. 用户提出修改意见时先读相关源代码再动手，不许凭感觉改。
24. 改动前先对比旧版 APK 借鉴好用实现，再自己重新研究重写。
25. 新逻辑先接好再删旧，不留旧格式兼容层，及时清理废旧代码。
26. 每次交付 APK 前必须把整个 APK 完整模拟跑一遍再报完成。
