# 卷一 · 体系地基（为什么这样设计）

## 一、继承 v1 的总判断（不改）

1. 国学宇宙观是一张「月令式」一体网：同一个时节，天象（日在何宿）、五行（盛德在某）、干支（其日某某）、音律（律中某律）、物候（某物候现象）、方位、服色、食物全部联动。v1 卷一 §一 总判断原样继承，本稿不重推。
2. 五张网全部有出处：网一五行全谱（《礼记·月令》/《吕氏春秋·十二纪》）；网二十二消息卦（孟喜卦气说，楚竹书首尾符爻位）；网三卦气网（四正卦主节气、六十卦配候、六日七分）；网四律历网（《淮南子·天文训》十二律配月、节气音比、律数三分损益）；网五十干五行（《月令》十日 + 通例地支五行）。v1 卷一 §二 五节逐条继承，出处 URL 不复制、不删改。
3. 推演原生形态是月令「行令」：拨到某节气展示该月「行他令」的原文后果对照；不接用户命理输入，不占验。v1 卷一 §三 界线原样继承（红线不占验不变）。
4. 三处自造象裁决不改：废日晷影，用十二消息卦；废五件孤立小像，用月令全谱卡；候牌升级为「物候 + 卦气 + 音律」三连。v1 卷一 §四 三条继承。
5. 六种读法与废除清单不改：节气=直射点刻度；阴阳=晨昏线+直射点纬度；五行=直射点季节段；律=节气音；月令星象=天地一条线；月令全谱走卡。废除项：日晷、五方物象田、候牌球面件、三环悬浮罗盘。v1 卷二 §六 继承。
6. 总体原则五条不改：状态是时间的纯函数 `CosmoState=f(t)`；一层一象、象必须可算；全部象共用同一个时钟；观察与推演共用一套实现只换时钟源；国学层是刻度层不是道具层。v1 卷三 §七 五条继承。

## 二、本稿相对 v1 只做变更的三处地基判断

1. 天球不是球壳，是跟随相机的 2D 投影背景。为什么：N-019 §〇.9 已裁决「固定球在相机推到 9R 时会站到球外，看到球壳外表面，模型本身不成立」；v1 沿用旧切片-19 的「太阳圆盘距离 400 单位」球壳口径，与该裁决冲突。本稿按 C8 后令优先，以 N-019 2D 投影口径重写焊点（见卷一·补 冲突 1）。
2. 国学层代码与数据全部未落地，不是「只差刻度」。为什么：资产核查实测 `astro/cosmo/` 包与 `assets/cosmo/` 目录均不存在，五张历法表缺失（底账条目 11）；v1 卷二 §五「物理本体已在实机里，只差刻度」只对太阳方向向量、晨昏线、既有星表成立，历法/卦气/律历/月令数据与 UI 均为新建。本稿据实区分「复用资产」与「本期新建」（卷四）。
3. 本层挂 D17 扩项，编号 N-020，不新立模块、不加顶层入口。为什么：N-019 已立 D17 第四视图口径（登记册 N-019 行、契约索引 D17 行）；国学层作为同一 3D 壳内的主题模式叠加，沿用同壳纪律（卷八登记条）。

## 三、二十条硬冲突裁决（逐条：结论 / 理由 / 证据）

### 冲突 1 · 天球日轮焊点（v1 §六/§9.5.12 vs N-019 §七.9、§八.4）

- 结论：**不挂 400 单位球壳圆盘**。同一个太阳在 2D 投影下的实现为：地球侧直射点与天球侧日轮，都取同一个 `Sun.direction(utcMillis)` 单位向量；天球侧日轮是该向量在 2D 投影背景上按既有 `StarProjector` 同一投影函数算出的屏幕落点，不新建固定半径太阳体，不读 `Sun.position` 的 400 距离分量做几何排布。
- 理由：N-019 §〇.9「天球不是世界里的固定球，是跟随相机的 2D 投影背景」；§八.4「星点方向由 RA/Dec + 恒星时 + 相机姿态算出屏幕坐标」。`Sun.position`（`Sun.kt:58`）保留为既有地球仪太阳圆盘的取位函数，国学层不复用其距离 400 口径。
- 证据：`app/src/main/java/io/legado/app/ui/map/globe/astro/Sun.kt:42` `fun direction(utcMillis: Long): Vec3`；`:58` `fun position(utcMillis: Long): Vec3 = direction(utcMillis) * GlobeConfig.SUN_DISTANCE`；`GlobeConfig.kt:64` `const val SUN_DISTANCE: Float = 400f`；`GlobeScene.kt:81` `sunDir = Sun.direction(utcMillis)`；`astro/proj/StarProjector.kt:23` 类注释「SkyViewMode.SKY_EARTH 先用观测点纬度 + 地方恒星时转地平坐标」。
- 验收改法：判据「天地一条线」只断言两侧读同一个 `sunDir` 向量（逐位相等），不断言 400 距离、不断言球壳交点。

### 冲突 2 · 控件会计（v1 §十八.1 天控签两 chip 并一签 vs N-019 §九.4；主控×挂件缺矩阵）

- 结论：天相沿用 N-019 既有两控件——顶部竖排「星官 / 星座」体系签、右上「天外 / 地上」视角签，**不合并为一签**；v1「两 chip 并一签」作废。道相主控=节气盘（右下拇指区），挂件=左缘消息卦条 + 历法牌（屏幕 UI）+ 月令卡（Sheet）。phase×mode 矩阵见卷六 §一，逐格给主控与挂件。
- 理由：N-019 §九.4「顶部竖排『星官』『星座』400ms 交叉淡入…右上『天外』『地上』800ms 过场」是两个不同维度（体系 / 视角），合并会把两套手势挤入同一热区；既有实现已按两控件落地（`SkyInputHandler.kt:293` 视角切换入口）。
- 证据：`app/src/main/java/io/legado/app/ui/map/globe/host/SkyInputHandler.kt:293` `ZONE_EARTH -> controller.enterSky(SkyViewMode.SKY_EARTH)`；`N-019 §九.4`（前置规格 :251）；`ReplayConsole.kt:37` `internal fun ReplayConsole(` 地相既有主控挂件。
- 理由二：v1 §十八.1「两 chip 并一签」与 N-019 双控件口径正面冲突，按 C8 后令优先取 N-019。

### 冲突 3 · 绘制预算（v1 §六/§十四.8「球面新增 ≤4 件」漏算五方锚点 5 个）

- 结论：图元清点为四类——回归线 2 条、直射点 1 件、五方锚点 5 个、天球日轮 1 件；但**独立 draw call ≤1**：两条回归线并入既有经纬网格同一条 Path 一次描边；直射点与五方锚点并入既有标记 sprite 批绘；天球日轮并入星空星点/辉光批绘。总 draw call 守 `≤15`、LOD0 `≤10` 红线，不靠砍图元守预算。
- 理由：v1 把「图元件数」当「draw call 数」记账，漏算 5 个锚点；`DrawBudget` 的红线是 draw call 数不是图元数。合并手法先例：N-019 §八.2「线框 pass（1 条 Path）：星座线 + 星官线 + 分野边 + 选中光环，单条 Path 一次描边」。
- 证据：`render/DrawBudget.kt:9` 注释「手机端 ≤15 draw call；LOD0 ≤10，LOD1 ≤14，LOD2（战场高精）≤18」；`GlobeConfig.kt:132` `const val MAX_DRAW_CALLS: Int = 15`；`DrawBudget.kt:17` `fun add(passCount: Int = 1)`、`:26` `fun exceeded(): Boolean`。
- 账目不齐时的处置：契约单先出 `CosmoBudget` 纯函数清点表（既有 pass 基线由渲染单实测回填），超支先合并同材质 pass，不砍功能、不留空白 pass（沿用 `DrawBudget.kt:11` 注释「超预算时降级策略是合并同材质 pass，而不是砍功能或留白」）。

### 冲突 4 · 岁差：月令「日在营室」不能当今天太阳所在宿（v1 §9.5.11-12 vs 判据 4 同向量 / 判据 5 原文逐字）

- 结论：**文献宿与今测宿分两列并存，不互替**。月令卡星象行第一列为「文献宿」：逐字照录《礼记·月令》「日在营室，昏参中，旦尾中」，不换算、不改正；第二列为「今测宿」：由当前太阳黄经对照二十八宿距度推算，卡内标注「今测」。判据 4「同向量」只约束直射点方向；判据 5「原文逐字」只约束文献列。
- 理由：岁差约 30°、差约一宿，先秦至西汉观测的日所在宿与今天同一节气的太阳宿次已错位；把文献宿当今测宿，既违天文事实，也违「原文逐字」判据。两列并存即同时满足「同向量」与「逐字」，不必二选一。
- 证据：库内原文 `app/src/main/assets/books/礼记.txt:875`「孟春之月，日在营室，昏参中，旦尾中……」；今测换算所需星官距度复用 `assets/astro/asterisms.csv`（32 行）与 `star_names.csv`（556 行），不另建星宿表。
- 边界：今测宿一期可只给「二十八宿区间」定性归属，距度插值精度不足时标「今测待核」，不编宿名。

### 冲突 5 · 节气算法（v1 §8.4「黄经 15° 等分、定义不是近似」vs 真太阳黄经不等速）

- 结论：节气按**定气**定义——太阳视黄经每 15° 一气（立春 315° 起）；实现用低精度太阳黄经公式（基于既有 `Sun.direction` 赤纬/经度反解或历表插值），**明示为近似**，时刻容差 ±1 天；废除 v1「定义不是近似」表述。2026 年二十四节气校验表由契约单生成（二至二分先锚），交数据代理对《中国天文年历》核对，未核前标 🟢黄。
- 理由：真太阳黄经不等速（地球轨道椭圆 + 章动），均分平气与定气有 1–2 天差；v1 把「黄经 15° 等分」说成定义不是近似，会让验收拿平气公式去套定气时刻，必红。低精度公式满足「节气刻度 + 六读法同帧」的视觉与知识呈现需求，历算精度归历表核对。
- 证据：`Sun.kt:47-49` 现实现为简化赤纬 `GlobeConfig.AXIAL_TILT_DEG * sin(2π(dayOfYear-81)/365.25)`，无黄经分量；`GlobeConfig.kt:24` `AXIAL_TILT_DEG=23.5`（历算 23.44 与视觉 23.5 双轨口径沿用 v1 §八.3 校正）。
- 校验锚点（待核，🟢黄）：2026 春分 03-20、夏至 06-21、秋分 09-23、冬至 12-21；交节时刻以年历为准，单测只断言节气区间与黄经锚角对应，不断言钟点。

### 冲突 6 · 时区与换日边界（v1 未定 utcMillis 与北京时间混用）

- 结论：**历法换算（年干支 / 月建 / 日干支 / 节气交节）一律用北京时间（UTC+8）本地日历**；`utcMillis` 只作物理光照与相机时钟输入，不直接推干支。换日边界：日干支以**子时 23:00（北京时间）**换日；月干支以**节气（立春换寅月）**为界；年干支以**立春**为界（仅历法牌展示，不做命理语义）。单测锚点：1984 甲子、2026 丙午、立春换寅月、子时 23:00 换日。
- 理由：utcMillis 是 UTC 瞬间，干支/月建是本地历法概念；混用会错日错月（23 点后 UTC 仍在前一日）。既有 `Chronology.yearGanzhi` 按公历年推算，未涉时区与时辰边界，本层新增纯函数时必须先转北京时间。
- 证据：`Chronology.kt:449` `fun yearGanzhi(year: Int): String`、`:456` `fun dayGanzhi(date: LocalDate): String`、`:463` `fun ganzhiIndex(gz: String): Int?`；`Chronology.kt:29-30` `GAN = "甲乙丙丁戊己庚辛壬癸"`、`ZHI = "子丑寅卯辰巳午未申酉戌亥"`；`Sun.kt:42` `direction(utcMillis: Long)`。
- 未验证：`monthGanzhi`（月建）与 `hourGanzhi`（时干支）在 `Chronology.kt` 无对应公开函数（grep 仅见 `yearGanzhi/dayGanzhi/ganzhiIndex/anchorFromText/timelineReport`），属契约单新增纯函数，不假装已有。

### 冲突 7 · 数据落点（v1 §15 注「唯一新增数据文件是五帝五神 10 行」与 §16.2「assets/cosmo/ 六张表 + 掩码」自相矛盾）

- 结论：五张历法/卦气/律历表**本期新建，一律落 Kotlin 常量对象**（纯 JVM、无 Android 依赖，与 `SkyParams` 同体例），不建 `assets/cosmo/` 目录、不新增 CSV/JSON 数据文件；干支六十甲子不建表，复用 `Chronology.kt:29-30` 两串常量按索引推算。既有星表四表 + 分野表 + 星官成员表只读复用。掩码位图一期裁掉（见冲突 11）。
- 理由：纯 JVM 常量可直接被 JVM 单测逐字断言（回源到古籍原文行号），CSV 反而要写解析与格式断言；`assets/cosmo/` 在实机不存在（底账条目 11、13），新建目录会同时引入打包体积与解析双轨。v1 两处口径打架，按「最小侵入 + 可测」取 Kotlin 常量方案。
- 证据：底账条目 11——节气表/候表/消息卦表/律表/黄经表/甲子表均不存在；`app/src/main/assets/astro/` 现有 `stars.csv` 8921、`asterisms.csv` 32、`star_names.csv` 556、`constellation_lines.csv` 87、`field_allocations.csv` 29（表头 1 + 数据 28）、`asterism_members.csv` 11、`SOURCES.md`。
- 单测逐字对照出处：每条常量字段在测试里挂古籍行号锚点（卷四逐表列）。

### 冲突 8 · 单字五行词进全局词典会误命中（v1 §24.2/§23.5）

- 结论：**不把「水/火/木/金/土」单字加进 `DictSeedData` 全局词典**。五行命中走三道门：①多字词白名单（「五行」「润下」「炎上」「曲直」「从革」「稼穑」「盛德在木」等，词表落契约常量）；②语境门（洪范 / 月令段落上下文才出「观」入口）；③命中后只在名物卡内出「观」按钮，单字在正文不高亮、不出气泡。
- 理由：五单字在汉语里是高频常用字，全局词典加词条会在任意文本误高亮（河水、火灾、木材、金属、土地全中招）。实测 `DictSeedData.kt:36/37/38/42/44` 五单字已作为普通词典词条存在（水/火/木/金/土），v1「加五行词条」既重复又扩面。
- 证据：`app/src/main/java/io/legado/app/help/dict/DictSeedData.kt:36`「水 shui …」、`:37`「火 huo …」、`:38`「木 mu …」、`:42`「金 jin …」、`:44`「土 tu …」；动作契约 `OpenArtifact(artifactId, type)`（`BubbleContractModels.kt:52`）。
- 兜底：白名单词库为空或语境门判定失败时，该词不进气泡链，保持现状词典行为，不假命中。

## 一、phase × mode 矩阵（冲突 2 / 13 落地，逐格给主控与挂件）

### 枚举口径

1. mode（模式签）：`MAP`（地图模式，既有）/ `GUOXUE`（国学模式，本层新增）。
2. phase（相位）：`EARTH`（地相，既有）/ `SKY`（天相，既有，`SkyViewMode.SKY_HEAVEN / SKY_EARTH`）/ `COSMO`（道相，本层新增）/ `SHI`（史相，壳层识别，一期不交付）。
3. 矩阵只登记合法格与回退格；非法格进入时先摘残留再回退默认合法格，不报错弹窗。

### 逐格裁决

1. **EARTH × MAP（合法，默认基线）**：地球仪现状零感知；主控无；挂件 `ReplayConsole`（既有，`ReplayConsole.kt:37`）。回归基线：无 extra、无国学态时即此格。
2. **EARTH × GUOXUE（非法，回退）**：国学签已选但道相未就绪 / 被降级摘除时，回退 EARTH × MAP，顶栏签保持选中态但画面不挂半成品叠加。
3. **SKY × MAP（合法）**：相机推远连续旅程远端；主控无；挂件=顶部竖排「星官 / 星座」体系签（N-019 §九.4 既有）+ 右上「天外 / 地上」视角签（既有，`SkyInputHandler.kt:293`）+ `SkyAttribution` 署名（既有，`SkyAttribution.kt:35`）。不合并两签（冲突 2）。
4. **SKY × GUOXUE（非法）**：从国学签切入天相路径时，先 `exitSky()`（`GlobeController.kt:197`）摘天相，再入道相；道相内推远不进天相星空。
5. **COSMO × MAP（非法）**：道相只能挂 GUOXUE；地图签选中时道相图元全部摘除。
6. **COSMO × GUOXUE（合法，本层主格）**：主控=节气盘（右下拇指区）；挂件=左缘消息卦条、底部历法牌；月令卡为底部 Sheet，不计挂件数；五方锚点 / 回归线 / 直射点 / 物候线为背景刻度件，不计挂件。

### 控件会计硬规

1. 主控 ≤1、挂件 ≤2（v1 §十八.1 沿用，落到本矩阵逐格）；挂件指可点独立控件，背景刻度件与 Sheet 不计。

3. 道相三枚速度点（既有回放控制台先例）不占主控名额，复用既有减速档位口径。

## 二、拨盘语义（冲突 14 落地）

1. **节气盘（操作件，离散落点）**：拖拽过程指针连续（纬度轴 φ 连续）；松手吸附最近节气刻度；中央轻点回实时；上端 = 夏至、下端 = 冬至、中横线 = 二分。吸附动画 250ms spring（`ComponentPalette.kt:85`）。

## 三、字段（预研 §4.2/§4.3）

1. 复用 `ArtifactEntry` 既有字段：`id / name / type / headline / body / detail / aliases / source / relatedArtifactIds`；`longitude / latitude` 神祇不可考置 null，不猜值。
2. 神祇新增字段：
   1. `system: DeitySystem`（枚举 `STATE_CULT 国家祀典 / MYTH 上古神话 / TAOIST 道教神谱 / FOLK 民间神祇`）——四体系为首要分组维度，不用自由字符串防同类异写。

   3. `originCitation: String`——出处篇卷（公版书名 + 篇名，如《礼记·月令·孟春》），只写公版口径，不引现代点校本版权表述。

   9. `disambiguation: String?`——同名消歧注记。

   13. `yueLingMonth: String?`——月令月次（孟春 / 仲春 / 季春 … 孟冬 / 中央土），节气盘筛神键；与 T3 月令表月次同值。
   14. `guardianStar: String?`——所司星宿名，回链既有 astronomy 星宿条目（只挂边，不新建星宿条目）；无对应星宿者置 null。
