## 二、改动清单（逐处，改后行号以工作区为准）

### 2.1 新增双情报表 + 情报记录结构（`CampaignController.kt:63-90`）

- `intel`（决策层情报表）：观察军 id → 目标军 id → `IntelRecord`。开局按部署情报播种（§2.2），此后每回合更新；意图裁决 / 侧翼寻路只准读这张表。
- `reports`（视图层情报表）：仅记录本方 / 盟友观察者**真正目睹**过的敌军；快照未观测敌军据此回显上次已知位置。与 `intel` 分开：部署情报只供决策推演，不向玩家透视开局部署。
- `IntelRecord(geo, cell, seenTurn, radiusCells)`：上次已知经纬度 / 上次已知格 / 最近目睹回合号 / 当前模糊半径（格）。

> 为什么拆两张表：决策层可以知道「敌方开局部署在哪」（战争开局双方编制与集结地属于公开情报），玩家视图层则必须等到侦察目睹；同一张表会把开局部署透传给壳层，重蹈 F8 透视问题。

### 2.2 开局部署情报播种 `seedIntel()`（`:142-153`）

- 所有军队实例化后，逐支观察者对其敌军播种一条 `IntelRecord`：位置 = 开局报告坐标，`seenTurn = 0`，半径 = 目标兵种视野半径。
- 为什么播种：规格要求「看不到的 → 上次已知位置」，而首回合之前没有任何目睹记录；不播种则决策层对从未目睹的敌军无位置可用，只能回退真实坐标（正是 #1 泄漏点）。播种内容是**开局静态报告**，不含任何开局后的实时机动。

### 2.3 视野半径单一来源 + 模糊半径策略（companion `:756-783`）

- `visionRadiusFor(type)`：骑兵 6 / 精锐 5 / 常规 4 / 民兵 3，引擎内唯一口径；实例方法 `visionRadius(def)` / `visionRadius(type)` 均委派到这里。`Pathfinder.radiusFor` 为侧翼寻路侧同表镜像（B8R1 已登记收敛项，本单不改 Pathfinder 域，注释中标注两处须同步）。
- `fuzzyRadiusCells(type, ageTurns)`：**半径随未观测龄期单调放大，封顶 `MAX_STALE_RADIUS_CELLS = 8`**；龄期 0（刚目睹）半径 0；每回合外扩 `STALE_DRIFT_CELLS_PER_TURN = 1` 格，基准取目标兵种视野半径。
- **策略选择：放大（非常数）**。理由：恒定半径意味着十回合前的旧报告与刚目睹同样精确，违背情报随时间贬值的常识；每回合 1 格约等于一日行军造成的位置不确定性；封顶防止半径膨胀到全图后失去意义。
- 常量：`STALE_DRIFT_CELLS_PER_TURN = 1`、`MAX_STALE_RADIUS_CELLS = 8`。

### 2.4 情报更新重写 `updateIntelligence()`（`:368-392`）

- 目睹（视野半径内 + `map.visible` 通视）：记录刷新为敌军实时真值，`seenTurn = turn`，半径 0；同时写入视图情报表 `reports`。

- **删除改前 #1 的 `?: enemy.latLng` 回退**：`lastKnown` 只回填情报表内已有位置，不再写入实时坐标。

### 2.5 决策层感知拷贝 `perceivedEnemies()`（`:399-406`）

## 五、二阶 / 三阶推演

1. **陈旧情报导致决策偏差（预期内的雾战代价）**：意图裁决与侧翼寻路改用上次已知位置后，敌军机动脱离报告位置时，追击方向 / 避敌环线会偏旧。这是情报模糊的固有代价，不是缺陷；半径扩圈正是给上层「报告不可全信」的量化依据。若后续要按半径做概率搜索，消费方读 `reportRadiusCells` 即可。
2. **播种情报的边界**：开局播种假设双方初始部署可知。若后续战役 JSON 标注「隐蔽开进」（开局位置保密），需在 `ArmyDef` / 定义层加标记跳过播种——当前模型无此标记，列为后续项。
3. **遭遇接触仍用真实坐标**：`resolveEncounters()`（`:456-458`）按物理相邻判定接战，未走感知视图。理由：两军撞到一起是物理事实，不依赖侦察报告；若改为感知触发，会出现「贴脸却不接战」的失真。此点与决策层模糊化口径不同，特此标注。
4. **战力 / 士气情报未模糊化**：感知拷贝只替换位置，`strength` / `morale` / `fatigue` 仍为真值。规格 F8 只要求位置情报雾；兵力情报模糊化属另一议题，未在本单扩面。
5. **死亡 / 投降敌军的陈旧报告残留**：`reports` 中已出局敌军的旧条目不会主动清除；快照层 `observedIds` 对出局军不再追加目睹，陈旧报告最多停留在最后一次目睹位置。壳层渲染本就按 `alive/surrendered` 压暗，影响可控；清理逻辑可在后续回合统一清扫。
6. **分支存档**：`BranchSnapshot`（model 只读）不存情报表；回滚后按军位重新播种，与 B7「快照回滚全部可变量」口径一致——情报是可由军位重建的派生状态，不作为独立存档字段。
7. **半径表双份风险**：`Pathfinder.radiusFor` 仍镜像本单 `visionRadiusFor`（B8R1 登记项）；本单未改 Pathfinder 域，两处数值目前一致，收敛到 model 单一来源需 B8 代理或总控批准后落地。
8. **壳层渲染仍读 `lat/lng` 实时字段**：`shell/CrossingShell.kt:261` 画棋子用 `corps.lat/lng`，未按 `observed` / `reportLat/Lng` 门控；`shell/` 属禁碰域，本单不改。未观测棋子在壳层仍可能被画在实时位置——**泄漏收口的最后一环在壳层**，交接见 §六。
