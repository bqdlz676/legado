## 三、门禁 59 设计（`data_scripts/check-commit-provenance.py`）

- 扫描对象：最近 N 条 commit（默认 10，`--count` 可调）窗口内 A/M/R 状态的源码文件——`app/src/**/*.kt`、`data_scripts/*.py`、`.github/workflows/*.yml`；删除(D)不计。
- 回源判据：每个源码文件必须在 `docs/**/*.md` 现存报告中被文件级提及——全相对路径命中，或带后缀文件名作为独立 token 命中；**只提到所在目录名（如 `bookshelf/`）不算回源**。
- 判红输出：列出首次出现 commit 短哈希 + 路径 + 原因；窗口内同一文件只取首次出现。
- 边界：纯标准库，只读本地 git 历史与 docs 工作树；git 不可用按 FAIL（无法核验即未通过）；本门禁不读报告结论放水。
- `--selftest` 三条夹具（临时 git 仓库，跑完自删）：
  1. 有报告（docs 先落盘写明全路径）→ PASS；
  2. 无报告 → FAIL，点名 `Bar.kt`；
  3. docs 仅写目录名 `bookshelf/` → FAIL，点名 `Baz.kt`；并直接断言目录名串不构成文件级回源。

## 五、二三阶影响与噪声分析

### 5.1 历史提交会不会被这条门禁大规模误判

- 当前实现的 docs 语料取**当前工作树**，不是各提交时点的 docs 快照。事后补写报告会让历史被扫文件回绿，因此门禁**只防未来再扫，不追溯旧账**；要判"提交当时有无报告"，须按本单取证口径逐提交 `git grep <文件> <commit> -- docs/`，成本更高，未纳入 59 默认判据。
- 真仓实跑：6 条与 10 条窗口均 PASS；`5ec4ada` 当时无报告的 3 个文件（`ImportSourceGroup.kt`、`ImportSourceGroupTest.kt`、`HeightMapRasterCache.kt`）现已被现行 docs 提及，故当前窗口不判红——这是口径取舍，不是漏判。
- 误判面：basename 兜底匹配可能把不同包下的同名类认作已回源；全路径优先、basename 仅兜底，收紧建议见问题 3。

### 5.2 窗口取多大才不噪声

- 窗口过大：较早提交的老文件被反复纳入，docs 未提及即噪声红；窗口过小：跨多单链内文件（对话框→Activity→工具类）可能漏网。
- 当前默认 10 条，与一轮并发 5 单的结单节奏（每单若干 docs/src 提交）对齐；真仓 6/10 两档均 PASS。超窗历史问题走基线豁免思路（参照 wiring/selftest 基线只许缩小），不靠放宽判据放水。

### 5.3 与既有门禁的分工

- ㊵ commit-split：判同一 commit 是否混合 docs 与代码；59 判源码文件是否有报告回源。两者互补：㊵ 管"结单与代码分离"，59 管"代码有单有报告"。
- F-123 未推送口径：59 当前只扫已提交历史；工作区未提交的在飞文件不进本门禁判据，其归属仍由 F5 复核文件域归属。

## 六、新发现问题

1. 59 语料取当前 docs 工作树，无法判定"提交当时报告是否已落盘"（待裁：是否增加逐提交时点快照比对口径；实现成本与误判噪声需另单权衡）。
2. 资源文件不在 59 后缀范围：8 份 `strings.xml`、`AndroidManifest.xml`、`app/build.gradle` 被目录级 add 扫入不被本门禁抓（已入队：后缀表是否扩到 `res/**` 与 `*.gradle`，需另单裁定，避免把配置漂移误判成来源缺失）。
3. basename 兜底存在同名类误豁免面（待裁：收紧为全路径优先，basename 命中须再带包名片段；当前仅作兜底，真仓未见同名冲突实例）。
4. `e66325a` 源码与 `a49c136` 报告同分钟先后落盘，"先提交后补报告"在工作树口径下回绿，时点顺序漏洞未被抓（已入队：与 F-123 未推送口径合并考虑，是否纳入提交时点 docs 快照校验）。
5. `HeightMapRasterCache.kt` 当时树内无 docs 提及，属链内半成品；本单判定**判废**翻旧账追溯——59 只防未来，历史误扫不要求逐条回补基线，避免门禁为历史欠账长期挂红。
6. 验收状态不在 59 判据内：`ManifestExportedContractTest.kt` 报告在案但验收状态待核，门禁不会替验收代理下"已验收"结论（已记录：报告回源与验收通过两层结论必须分开写）。
