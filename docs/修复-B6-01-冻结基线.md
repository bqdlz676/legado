## 一、改了什么（问题三问）

### 1. 改了什么

- 把 B6 发现页序列开工前的冻结面固化成可回证基线：八条冻结面逐路径跑 git diff --name-only HEAD 与 git status --porcelain 双通道回证；卡片族五入口以符号为准抽声明行与参数块，留逐行哈希、参数块哈希与整文件哈希；两个 explore 目录逐件登记路径、行数、文件哈希与目录指纹。
- 给出后续每单回执引用本基线的一行模板，以及基线失配时由谁重冻、重冻留什么痕、越界改动怎么回滚的处置口径。
- 本单不写业务代码、不改既有文件、不做 git 写操作；所有数字与哈希均由实跑命令产出，不凭记忆填写。

### 2. 为什么这么改

- docs/拆分-B6发现页小单.md:80 把四类冻结面 diff 空集留痕、五入口符号快照在册、11 文件 2740 行基线清单留痕、后续每单回执引用本基线列为 B6-01 放行条件；基线先冻下来，后续 B6-02 ~ B6-16 每单回执才有可比对象，签名漂移与冻结区越界才能被静态 diff 与哈希抓到。
- 目录级指纹用逐文件 sha256 后整体再取哈希，而不是只记文件名：文件内容被改坏时指纹必变，文件名清单锁不住内容漂移。
- 行号只作辅助定位，符号为准：采集时先 grep 函数名定位真实行号，再 sed 抽原文，避免规格里记的行号随历史提交漂移导致快照错位。

### 3. 怎么验的

- 八条冻结面逐路径跑 git diff --name-only HEAD 与 git status --porcelain 双通道回证；复扫时点八条双通道均为空集；采集时点 read 面在飞改动逐条点名并标注归属在飞单。

### 3. 失配处置（谁重冻、留什么痕、越界怎么回滚）

- 越界回滚：越界改动按文件粒度回滚到 HEAD 基线状态（git 层面由总控统一执行 revert 或 checkout，子代理不做 git 写操作）；回滚前先备份越界件 diff 留痕，回滚后重跑双通道与目录指纹比对，确认回到基线值。
- 重冻留痕：重冻单独成单或单独一笔提交，记录失配条目清单、旧指纹、新指纹、归因、重冻命令、重冻后 HEAD；报告内新增「基线重冻留痕」节，锚点卡同步更新指纹；重冻后四份机检复跑。
