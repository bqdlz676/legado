# 机制 · 文档子代理必读（机制/文档/复盘/索引/脚本类专用）

> 你是被派来处理"机制、台账、索引、复盘、规划、脚本"的代理。开工顺序：① 读完本文件；② 读 `docs/机制-总控必读.md` §13/§14（今晚硬口径与事故清单）；③ 读任务书点名的事实源（既有件路径 + 相关台账行）。别通读全仓。
> 为什么单独一份：三份既有必读只覆盖写码/验收/总控，机制类工作最容易犯的错不是做不对，而是**自造第二套**——2026-11-26 夜我先造了四份平行守则（事故五），同型的还有事故三（自造七层金字塔）。机制方的第一动作永远是"先找现成事实源"。

## 1. 开工先证"不是重复造"（缺这一步，报告直接打回）

1. `grep -rn` 扫 `data_scripts/` 与 `docs/`，找出同类脚本、同类台账、同类文档。
2. 报告第一节写：我找到了哪些既有件（`文件:行`）、为什么不能直接用、我要扩哪一处、以及"为什么不该新建"。
3. 读 `docs/经验库.md`、`docs/台账-机制缺陷.md`（M 编号）。已有结论只标注「同因已见 `文件:行`」，**不重复论证**（语料级重复是纯浪费，实测 5 份既有复盘被重复论证过一轮）。

## 2. 三件套缺一不可（总账 + 门禁 + 溯源）

- **总账**：要长期维持的东西必须有台账承载（派单队列 / 派单台账 / 问题清单 / 专项台账）。只写脚本不写台账＝没人知道它在跑。
- **门禁**：判据必须机检，落成 `data_scripts/check-*.py` 或 `rule-gate.sh` 一项；写完跑一遍贴输出，再做**反向自测**（造一个违规样例确认会红，删掉样例确认恢复绿）。
- **溯源**：报告写清这条判据对应哪份原始事实的哪一行；锚点可回源。

## 3. 脚本类硬约束（每条都是踩过的坑）

1. **误杀优先消灭**：新规则先全仓跑，凡命中既有合法写法就收窄判据并写注释说明为什么收窄（实例：guard F1 把注释里的文件名当引用，误拦一次 land；lint S3 只对 `BasicText`/`Text` 判死，避开 `InkText`/`SpanStyle`）。
2. **宁缺不误杀**：不能确定判死的打 WARN + 人工核，不进 FAIL。
3. **改完先 grep 回证**再跑，再报完成（未生效不许报）。
4. **不加速连续 push**：CI 在跑时等结论再推（`cancel-in-progress` 会白烧一轮 Verify）。
5. **口径只留一处判死入口**：同一件事有两个机检入口、判据不同，取绿的那个就能过关（事故四就是这么发生的：`check-frankenstein` 对超长只提示，`debt-ratchet` 才硬判）。其余入口降为提示并注明"提示不可作为通过依据"。

## 4. 复盘类怎么写（只统计现象不算复盘）

必含五段：事实（可回源 `文件:行` / 命令输出 / commit）→ 损失（直接 + 间接 + 隐性）→ 根因（**至少三层**：机制口径 / 派单约束 / 自检缺口）→ 处置（立单修当下 + 加机检防复发 + 台账编号 M-xx）→ 变更触发条件（什么情况下必须回改守则）。同型事故必须回指旧编号，不许当新事故重写。

## 5. 索引类必须自证新鲜

产出/删除文档后必须重跑 `python3 data_scripts/docs-index.py --write` 与 `python3 data_scripts/mechanism-index.py --write`；索引比目录旧即算未完成。

## 6. 交付格式

- 报告路径按类型：`docs/机制-…md` / `docs/诊断-…md` / `docs/事故复盘-…md` / `docs/索引-…md` / `docs/分析-…md`，首行锚点卡。
- 机器头四行（被改文件数 / 判据 n/m / 真跑门禁结论 / 未验证项数）+ 变更清单带 `文件:行` + 反向自测输出 + 二阶三阶影响（对既有流水、其他代理并发、CI 时长、维护成本）。
- **守则回执**（见 `docs/机制-守则回执规范.md`）：报告头必须带当前必读文件的 sha256 指纹与三条逐字引用，`check-onboarding.py` 会机检，缺则整单不通过。
- 禁 git 写操作；禁编译；机制/文档类代理允许复用（≤3 次，且须上次已收口）。
