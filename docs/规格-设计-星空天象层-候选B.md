# 落文 · 规格设计 · 星空天象层 · 候选 B（程序化公版保守档 · 视觉约 9 等）

段位：F-73 第①段「规格设计」产出。两份候选之一，供**未参与设计的独立选型代理**审验。
选型结论须由该代理另落 `docs/验收-选型-星空天象层.md`，本文件不含结论、不自评。
版本：候选 B · v2（对齐 F-77 八项、与 A 同规格收口）· 2026-11-27

**与候选 A 的差异一句话**：零外部星表、零下载层、零许可风险；代价是**不满足用户已拍板的 11.5 等深度**，视觉顶到约 9 等。

这条必须先摊开：用户 2026-11-27 明确选了"11.5 等推荐档"。因此本候选在"深度"这一项上是**已知不满足**，它的正当用途是 A 的风险回退（Tycho 链路不可达 / NC 边界不允许时整链切换），不是与 A 平权的优选。选型代理若按"用户已拍板项一票否决"处理本候选、判其淘汰，是合理结论；本文件不为此辩护。

## 一、① 目的与用户可感效果

动作序列与 A 同（长安→地球仪→星空→点星→分野→地上观→拖时间轴），差别只在三处可感：

1. 放大到局部天区时，暗星是**程序化长出来的**，密度可观但"越放大越像画"，不会像 A 那样真的多出十万颗实测星。
2. 点开任意一颗星，Sheet 里**没有星等、距离、光谱、西名**——只有古名、星官、宿序、分野、古籍原文一句、精度档标注。
3. 星官位置与真实天球**可能有 1–2° 偏差**，UI 必须显式写"位置示意"，不冒充实测。

可感效果五条：连续（同 A）；密度可观但非实测（诚实）；可读（每条有古籍出处）；有根（分野联动同 A）；美（同 A，暖墨沉金纸白）。

## 三、数据源与许可（本候选的卖点：全公版）

1. 星官成员星位置：由古籍推算——《步天歌》星官成员序 + 距星入宿度/去极度（《晋书·天文志》《旧唐书·天文志》等公版文献的度数记载），按古代 365.25 度制换算到现代赤经赤纬。
2. 换算公式与每条出处入表；精度只承诺"宿内相对位置正确，绝对坐标与真天球偏差可能达 1–2°"——诚实标注，不冒充科学级。
3. 星官与分野：同 A（《史记·天官书》《晋书·天文志》，公版，逐条出处）。
4. 星座 88 个：名称与边界属 IAU 事实；连线自绘，署名"参考 IAU/Sky & Telescope"。
5. 程序化暗星：种子确定性生成（沿用 `StarField.kt` 的 hash 思路），星点数量随密度场分布，无版权。
6. 无西名 / HIP / HD / 星等 / 距离 / 光谱任何外国星表字段——Sheet 里这些行不出现。
7. 无按需下载：全量内置，断网天然可用。
8. 许可结论：本候选**零外部许可依赖**，可进 APK、可进 CI artifact、可商用（古籍与 IAU 事实数据均无 NC 约束）。

## 四、数据 schema

star 表（只含星官成员星，约 1,700 行）：

1. id；nameZh（如"井宿一"）；xingguan（如"井"）；su（28 宿之一，可空，理由：三垣星不属 28 宿）；memberIndex；raDeg / decDeg（古籍度数换算，精度声明入 note）；source（古籍原文）；precisionTier（tier 1 有距星实测锚点 / tier 2 纯度数换算）。
2. `precisionTier` 是诚实性的核心——换算坐标不是实测，验收必须看它，不能当 Tycho 坐标用。

asterism / asterism_member / constellation_line / field_allocation 四表：同 A 第 4 节（第 10–13 条）。

体积：全部 <300KB 内置，无下载层。

## 五、② 尺寸 / 间距 / 圆角 / 字号

与 A 同规格（理由同 A：`audit_ux()` 最小字号 14sp 硬门槛），逐条：

1. 星点直径（屏幕 px）：mag ≤ −1.5 → 9px；0 → 5px；2 → 3px；4.5 → 1.5px；6.5 → 1px。本候选无 6.5 以下实体星，故最小 1px。
2. 连线：星座 0.8px alpha 0.45；星官 1.0px alpha 0.55；分野边 1.5px 虚线 dash 6/gap 4。
3. 网格：赤经/赤纬 0.8px；黄道 1.0px；天赤道 1.0px。
4. 字号：星官名 14sp 竖排；宿名 14sp 竖排；星座名 14sp 横排；Sheet 标题 16sp / 正文 14sp / 出处 14sp。
5. 间距：标签距星点 8dp；热区 ≥48dp×48dp；顶部切换条视觉 28dp、热区 48dp；Sheet 圆角 20dp；星名印框 2dp；列表 `spacedBy` 8dp。
6. Sheet 三段 30/60/90%，关闭阈值 0.12。
7. `SkyCanvasRenderer` 拆文件同 A（宿主 603 行已超阈值）。

## 六、③ 色值（只引既有 token）

与 A 第 6 节同构，逐条给值：

1. **UI 层**：夜空底 = `textPrimary` 压暗 40%（`GlobeTokens.skyNightBase`）；地平暖辉 = `brandCopper` 0.10；星官线 = `brandGold` 0.55；星座线 = `textTertiary` 0.45；分野填充 = `colorGlow`、边 = `brandGold` 虚线；网格 = `textTertiary` 0.12；黄道 = `brandGold` 0.30；天赤道 = `stoneBlue` 0.30（基准线专用，切片-26 声明）；禁用 = `textTertiary` 0.30。
2. **内容色 `SkySpecColor`**（数据色，非 UI，先例同 `GlobeSpecSurface`）：星色四锚 `#D8E4F0` → `#FFFDF6` → `#FFEED8` → `#FFB37A`；银河暖白核心 + 暖灰外围；尘粒 `textTertiary` 0.15；流星 `#FFFDF6` 头部。
3. 本候选星官星无 B-V，全部落"纸白→暖白"段，**不出现早型月白**——这是与 A 的可感差异之一，需在验收里承认。
4. 派生色集中 `GlobeTokens` 三个出口（`skyNightBase` / `skyHorizonGlow` / `skyStarWarm`），单测断言可复现。
5. 硬禁：`#000000`、`#FFFFFF`、Material 默认色、第 14 基础色；`grep` 判据同 A 第 6.4。

## 七、④ 全部状态（八态）

1. **默认**：密度场按可见天区面积连续计算，星点数随缩放平滑增减；判据：无整层突现。
2. **悬停**：压住星点外扩 1.3×，120ms。
3. **按下**：60ms 放大 1.6× → 1200ms 呼吸。
4. **加载**：本候选**无网络加载**，此态仅为"密度场首次生成"（进程内一次性，<30ms），期间显示上帧缓存；判据：不闪白、不空白。
5. **禁用（低端机）**：密度场降采样、关流星、关尘粒；星官线保留。
6. **空（数据缺失）**：古籍度数残缺的星官只显示成员名与连线示意、不落坐标，并在 UI 标"位置示意"；判据：不空白、不崩。
7. **错误（换算表校验失败）**：回退到内置星官表（编译期常量），Sheet 一行朱砂提示"星官位置表校验未过，已回退内置"。
8. **离线**：全功能等价在线（全内置），此态无差异；判据：飞行模式截图与在线一致。
9. 跨态约束：Sheet 关闭后选中态与视角一字不差（同 A）。

## 八、渲染规格

1. 三 pass 同 A（星空底 / 线框 / 星点 sprite 批绘），几何模型同为"跟随相机的 2D 投影"，不做球壳网格。理由同 A 第 8.4–8.7。
2. 差异：星空底 pass 的密度层换 `ProceduralDensityField`——按银纬带分布 + 星官区分布加权，种子固定可复现；视觉密度顶到"约 9 等"观感，不分层（本来无层）。
3. 实体星只有星官成员星（约 1,700）+ 程序化亮星点缀；A 的直径/光晕/四芒/闪烁规则照用，但四芒/闪烁改按"星官距星 + 程序化亮星种子"判定。
4. 银河：无星表可统计，纯程序化（银道坐标带 + fbm 噪声），opacity 0.25。
5. 双视角、过渡、尘粒、流星、选中动效：与 A 第 8 节逐字同规格。
6. 视觉差异须在验收承认：本候选夜空"颗粒感"更均匀、缺少真实星团的疏密对比；这是程序化的固有代价，不冒充。

## 十一、⑤ 边界与降级

1. 星官坐标换算精度不足或古籍度数残缺 → 只显示成员名与连线示意（不落坐标），UI 标"位置示意"；**禁止用现代星表补坐标**（补了就不再是本候选的许可模型）。
2. 用户要求"真实星等/距离" → 本候选不满足，整候选作废，转候选 A。
3. morph 超预算 → 交叉淡化 + 明说。
4. 命中难 → 磁吸 + 局部星图。
5. 流星/闪烁拖帧 → 固定周期 / 降阈值（同 A）。
6. 密度场观感不足 9 等 → 调 `PROCEDURAL_DENSITY_MAG_LOOK` 一个常量，不散改渲染层。
7. 超长文本 / 低帧率 / 无权限（定位）：同 A 第 11.3–11.5。
8. 降级域隔离：同 A 第 11.8。

## 十五、风险、派单与自检

风险 6 条：坐标精度（第 11.1）；用户要真实深度 → 作废转 A；morph 超预算；命中难；拖帧；密度观感不足。

派单（4 写 + 1 验）：

1. 契约单：同 A（`astro/contract/**`）。
2. 接线单：同 A，但不改 `TextureKind`。
3. 数据单：古籍度数提取换算 + 四表落库（无下载管线）；文件域 `data/entities`、`dao/`、`assets/astro/**`。
4. 渲染交互单：同 A。
5. 验收单：独立代理，特别掌握"星官坐标非实测"与"9 等 ≠ 11.5 等"两条口径。

自检：

6. 单项：八项逐项有节可指。
7. 整体：与机制总控、模块索引、规格登记册交叉核对，无自相矛盾。
8. 本版相对上一稿改了什么：① 补 ②尺寸 / ④八态 / ⑧一致性三节；② 色值全部收口为 token + `SkySpecColor`；③ 天球模型改 2D 投影、进入机制改 10R + `skyBlend`；④ 连续 LOD 改三档常驻 + 连续权重并写明边界；⑤ 显式登记"9 等不满足 11.5 拍板项"。
9. 未验证：古籍度数换算的完整覆盖率（多少星官有可靠度数、多少只能示意）、程序化密度场在真实设备上的观感、连续权重帧耗。
