## 三、瓶颈定位（代码走读，改造前 `e0b0688` 版 `SkyCanvasRenderer.kt`，389 行）

逐颗热路径在旧 `private class SkyStarSpriteRenderer.render`（旧 renderer 第 301–367 行；commit `5ab61f9`（2026-11-28）该类下沉为 `host/SkyStarSpritePainter.kt`，现行以 `SkyStarSpritePainter` 为准：类在第 28 行、render 第 35-46 行），8920 颗投影后逐颗进入同一循环：

1. **逐颗新建 `PorterDuffColorFilter`**（旧 renderer 第 323 行；现行 `host/SkyStarSpritePainter.kt:98` `filterFor` 内新建）：每颗星 `new PorterDuffColorFilter((0xFF shl 24) or rgb, SRC_IN)`，8920 颗 = 每帧 8920 个滤镜对象分配；layoutlib 软渲染帧循环里这是直接的 GC 抖动源。滤镜内容只由 rgb 决定，同色星跨帧完全可复用，原实现没有缓存。
2. **屏外星照样进着色与光栅路径**：投影行星源只剔背半球（`astro/proj/StarProjectionSource.kt:118` 背半球判定），不剔屏幕边界；前半球落在 562×1000 视锥之外的星，仍逐颗算颜色、设滤镜、`drawBitmap`（旧 renderer 第 326 行；现行 `host/SkyStarSpritePainter.kt:78`），由 Canvas 自己裁剪。视锥外整段应在进光栅前跳过。
3. **逐颗绘制状态翻动**：`paint.colorFilter` / `paint.alpha` / `rect` 每颗重设；`RectF` 与 `Paint` 原已复用，但滤镜对象未复用（见第 1 条）。
4. 已排除的非瓶颈项（本单不动）：投影遍历与拾取重建在 Q-502 在飞域（`StarProjectionSource.kt` / `StarPicker.kt`，只读）；线框 pass2 的 `findPos` 为线段数级、非逐星；atlas 四档纹理原本就是首用一次预烘焙（旧 renderer 第 197–209 行；现行 `host/SkyCanvasRenderer.kt:251-263` `ensureAtlas`），不存在逐帧重烘焙。

## 四、优化项与逐项机制、收益口径

| # | 优化项 | 机制（代码落点） | 收益口径（可测） | 像素等价性 |
|---|---|---|---|---|
| O1 | colorFilter 跨帧缓存复用 | 新建 `SparseArray<PorterDuffColorFilter>`，键=24-bit rgb；`filterFor(rgb)` 命中取回、未命中才建并入缓存（`host/SkyStarSpritePainter.kt:33`、`host/SkyStarSpritePainter.kt:96-101`） | 消除每帧逐颗滤镜对象分配；首帧按 distinct rgb 建一次，后续帧零滤镜 new。GC 抖动下降；收益以 CI 帧耗中位 / P99 差值为准 | 同 rgb → 同滤镜对象，颜色 / 模式 / alpha 逐位一致 |

| O5 | 投影 / 拾取帧一致性缓存 | 投影坐标只随 视角 / 姿态 / 观测点 / 恒星时 / 画幅 / 星等上限 / 目录规模 变化；输入不变时复用上一帧 `ProjectedStars` 与拾取分桶，跳过逐颗三角投影与分桶重建（`host/SkyCanvasRenderer.kt:57-70` 缓存字段、`projectionCacheMatches`、`saveProjectionCache`） | 稳态静止帧（bench 同快照连绘 100 次、真机悬停重绘）免投影遍历与 picker 重建；相机动帧缓存全失效，行为不变 | 缓存只跳过重复计算，投影结果与逐帧重算逐位一致；目录增层由 `size` / `pyramidSize` 双保险判失效 |

**未采用方向及理由**：
- 按星等分段重排批量（先亮后暗 / 同档合批）：同档同色合批需要每帧分桶数组，本身引入帧内分配，与 O3 零分配口径冲突；软渲染下 blit 数量不变，合批收益有限，本单不做。
- 预烘焙着色 atlas（色×档位图替滤镜）：要把连续 BV 插值色量化成色板，会引入可感知的颜色量化偏差，且八态截图基线是白 atlas+SRC_IN 滤镜口径；为保像素等价不采用。
- 暗星降级 / 减颗：任务书明令禁止回退，不做。

## 八、二阶 / 三阶影响

- **受影响文件 / 接口**：renderer 与 painter 同包内部协作；对外公开签名（`SkyCanvasRenderer.draw` / `pickStar` / 状态面字段）一字未动，宿主 `GlobeScreenHost` / `GlobeActivity` / 测试视图 `SkyRenderView` 无感知。
- **内存**：`filterCache` 以 distinct rgb 为上限常驻 renderer 单例；每颗滤镜仅持 color int + mode，量级为可见星去色数，不随帧增长。缓存不跨 store 清空——星表色值来自目录 BV / 星等映射，目录不变色值不变，无脏值风险。
- **行为面**：屏外裁剪只移除原本就被 Canvas 裁掉的绘制；选中 / 悬停 / 按下拾取走 `StarPicker`（投影缓冲），不依赖绘制循环，裁剪不影响命中。
- **缓存面（O5）**：投影缓存只判输入标量与 store 引用 / 目录规模；相机动、观测点 / 恒星时 / 画幅 / 星等上限变化、目录增层任一发生即失效重算。缓存不持有像素拷贝，`ProjectedStars` 缓冲仍由 renderer 自持；picker 在缓存命中帧跳过重建，但桶内引用的就是同一份投影数组，命中结果不变。
- **维护成本**：sprite 绘制独立成文件后，renderer 行数预算留出余地；新增绘制特效应落在 painter 或同层新文件，不再回塞 renderer。
- **三阶推演**：若后续接入真机 GPU 纹理批绘，滤镜缓存与屏外裁剪仍是有效前置（减少提交给 GPU 的图元数），不构成返工包袱。

## 十一、最强反对者（假设本方案是错的）

1. **软件渲染下 `drawBitmap` 本身有下限，砍滤镜分配与屏外跳过不够**：layoutlib 是纯 CPU 软栅格，8920 颗即便零分配，逐颗 blit 的像素填充仍是主成本；若屏外占比不高，中位 / P99 可能仍超 16ms / 24ms。反驳依据：投影只剔背半球，90° 视锥在 562×1000 竖屏上覆盖的立体角小于前半球，屏外跳过应砍掉可观比例；但占比未在沙箱实测，这是本方案最大不确定点。若 CI 仍红，下一步：把同档同色星按 1px 点合并进一张离屏星位图（离屏一次栅格、整帧一次 blit），或按 atlas 档分桶二次遍历。
2. **layoutlib 与真机差异：软渲染帧耗不能代表真机**。本单 bench 口径本就是代理段（测试类注释 `:19-23` 已声明不含 GPU 栅格 / vsync）；即便 CI 转绿，也只证明 CPU 编排 + layoutlib 路径不退化，不背书真机整帧。本方案未、也不能消除这条差异，Y-05/Y-06 黄因继续保留。
3. **滤镜缓存可能反而拖慢**：`SparseArray.get` 带二分查找，若 distinct rgb 极多，查找成本可能超过新建一个轻量滤镜。反驳：`SparseArray` 键为密集小整数表，查找 O(log n)；旧实现每颗都走对象构造 + 写入路径，缓存命中路径更短。若 CI 显示缓存未带来收益，可退回「每颗新建」但保留屏外裁剪。
4. **屏外余量取 `d*1.4` 可能误裁紧贴边缘的四芒**：四芒线长 `r=d*1.4`，余量同值；线端恰好落在 `±margin` 边界上时可能被跳过一像素。影响仅限贴边最亮星的芒线端点，主体光点与屏内线段不受影响；可复算余量到 `d*1.4 + 1px` 留安全边，本单按同值对齐旧芒线半径，未额外加边。
5. **O5 缓存可能是「给 bench 刷绿」而非真优化，或缓存键漏字段导致星点滞留旧位置**：bench 同快照连绘 100 次，缓存全命中，测量值被压低；真机拖动时每帧失效，拿不到同样收益。另若漏判某个影响投影的帧字段（如未纳入的观测点 / 恒星时分支），会出现星点位置不随姿态更新的视觉 bug。反驳依据：缓存键覆盖 `fromFrame` 读取的全部输入（mode / yaw / pitch / lat / lon / lst / 画幅 / magLimit / density）+ store 引用 + `size` / `pyramidSize` 规模双保险；键内不含 nowMs / hover / press（这些不影响投影坐标）。真机静态停留帧复用投影结果本就是合法省算，不是改测量口径。风险兜底：若 CI 转绿后八态截图基线出现位置错位，第一时间回退 O5 缓存、保留 O1–O4。
