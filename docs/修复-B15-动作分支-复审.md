## 4. 二阶三阶影响

### 4.1 直接效果

13 种脚本事件从「无分支空转」变为有可观察结果：兵力 / 士气 / 存活 / 投降 / 意图之一发生变化，且每条事件无论是否作用于目标军都登记进 `FiredEvent` 列表。

### 4.2 连带消费点（help/sim 栈，已核）

- `SimEngine.tick()`（`SimEngine.kt:403`）：事件在移动与意图裁决之后派发；`fired` 进入 `TurnResult.events` 与 `notes`（404、407 行），供回放时间轴与回合面板展示。
- 胜利判定 `evaluateVictory()`（`SimEngine.kt:433–494`）：只读军队 `alive / morale / target / strength` 状态，**不读 FiredEvent 列表**。事件改写状态后同回合结算胜利，不存在「事件记录再计一次胜利」的重复计数路径。
- 意图消费：意图型分支写入的 `intent` 由下回合 `IntentResolver.resolve` 规则 4 / 14 / 15 与 `SimEngine.applyIntent:313`（flank 走 `flankPath`）读取；`intentActive` 驱动日行里程与动画分支。

### 4.3 crossing 侧重复计数评估（他人域，未读码，据上一轮报告与栈结构推断）

- 仓内双栈并行：`help/sim`（纯 JVM 并行引擎）与 `ui/map/crossing`（在线 Compose 壳，`CampaignController.applyEvent` + 自有 `EventAction` 枚举）。两栈事件对象类型不同，crossing 不消费 help/sim 的 `FiredEvent`。
- 本单在 help/sim 新增/加固的分支不会向 crossing 事件面板写任何条目，**当前不存在跨栈重复计数**。
- 二阶风险：若未来架桥把 `TurnResult.events` 接入 crossing 面板，需按「回合号 + 事件 id + 目标军」去重，避免同一脚本事件在两栈各显示一条；该桥当前不存在，仅作挂账。
- 回放一致性：事件现在真实改状态，回放切片必须与当时快照的兵力 / 士气 / 意图一致；旧版空转录像需重跑生成（本单不动回放种子）。

### 4.4 长期复杂度

动作契约跨三处（help/sim when / crossing 枚举表 / crossing when），新增动作须三处同改，已有两个 selfcheck 脚本做静态门禁。本单未合并双栈；双栈语义漂移风险沿用交接挂账。

## 5. 反例与边界（先自我否证）

**最强反对者论点**：「这些标签本是意图 / 胜利条件名，填进 action 位是数据错误，应改 JSON 而不是补代码。」
**否证**：任务红线禁改 JSON 资产；70 个 JSON 中这些标签携带明确史实语义（火攻、破城、被俘、覆没、佯退……），事件位落点合理；且规格切片 §三 规则表与 §四 胜利表均承认 rout / ambush / retreat / escape / capture / annihilate 为引擎一等概念。故维持代码侧落地，数据原样保留。

穷举边界与兜底：

| 边界 | 实现兜底 | 对应用例 |
|---|---|---|
| 未知 action 字符串 | `else` 记 warnings + FiredEvent 照常登记；军队状态不变，不静默 continue | 243 |
| 空事件列表 / null 列表 | `fire` 开头返回 emptyList，不抛异常 | 294 |
| 同回合 / 跨回合重复触发 | `EventSpec.done` 一次性标记；第二次 fire 返回空，不二次扣兵 | 282 |
| target 不存在（id 拼错 / 同名消歧失败） | 记告警，军队状态不变 | 259 |
| target 已阵亡 / 已投降 | 守卫跳过结算并告警；`moraleChange` 复振路径例外放行 | 269 |
| 全局事件（target=null） | 显式 no-op：不改任何军队，事件仍登记展示 | 232 |
| value 为空 / 非法数字 | `toDoubleOrNull() ?: 默认比例`，不抛异常 | 303、311 |
| value 越界（如 5.0） | `coerceIn(0.0, 1.0)` 钳制，不超扣 | 318 |
| 同回合多事件冲突 | 按 JSON 数组顺序顺序结算，后者覆盖前者；出局目标后续事件被守卫跳过并告警 | 代码路径 74–81，未单列用例 |
| 极小兵力被比例折损 | `roundToInt` 可能扣 0，不死不崩；打空才出局 | 既有逻辑 |

**规格占位核查**：逐条比对切片 06，fireAttack（§六 赤壁火攻，L7/L122）、rout/ambush/retreat/escape（§三 规则 2/4/5/14–15，L95/L156/L174/L146）、capture/annihilate（§四 胜利表 L103–104）均有出处；siegeEngine / breakthrough / navalRout / defendFall / feignedRetreat / flank 为战役史实补充动作，原文未写「暂不实现」。按止损口径，不硬造 no-op，也不强行降级。

## 6. 认知成本

- **收敛位置**：动作分发唯一入口 `EventTrigger.kt:95` 一个 `when`；事件型 / 意图型 / 混合型三段分区注释 + KDoc 分类表，新人按表归类即可，不必翻 JSON 反推语义。
- **抽象增量**：本单未新增抽象层、未引入枚举注册表；`Snap` 仅为测试内快照，不进主代码。
- **命名**：分支字面量与 JSON camelCase 原样对齐；注释标明意图型分支的可观察结果是意图改写而非兵力结算，避免接手人误判「意图型分支没改状态 = 空转」。
- **遗留认知债**：双栈动作表需三处同改，是最大的认知负担；彻底解法是合并双栈（交接 1），本单不做。
