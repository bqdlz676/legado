# 修复-g64 RAWSOURCE 判据括号 / 字符串状态机配平

## 总结论

g64 单测判据真值闸（`data_scripts/check-test-assert-truth.py`）的 RAWSOURCE 判据，旧版用正则按「首个 `}`」截断 lazy 块体，被验收实测出双向失真：嵌套 lambda 里的 readText 漏判，合法 filterNot 写法被假红，字符串内的 `}` 提前截断截面。本次把块体提取整体改成括号 / 字符串状态机配平，字符串（双引号串、字符字面量、三引号串、反斜杠转义）内的括号不计深度，readText 在语句块内任意深度都能识别；白名单判断在整个配平块内生效。

四个验收反例已逐条打成夹具，各自在独立临时目录单文件跑：lazy 基线坏样本仍必红，嵌套 lambda 内 readText 由旧版 0 命中改为必红，字符串含 `}` 的坏样本仍必红，两条合法剥注释面写法由旧版假红改为必放行。探针编号与 `docs/验收-复核-B6-03修补与g64加固.md` 判据 4 逐条对应，原始探针编号以该验收报告为准。`--selftest` 双向自测 rc=0；改动面 `--changed` 闸门 PASS；接线闸与 Compose pitfalls 闸全绿。

改动文件域仅限 `data_scripts/check-test-assert-truth.py` 与本报告、对应锚点卡；未改 `app/src` 业务代码，未做 git add / commit / push。

## 一、旧版根因（验收实测三条失真路径）

- 漏判路径（夹具二）：lazy 块体旧正则 `LAZY_READTEXT_PAT` 用 `\{(?P<expr>.*?)\}` 非贪婪截断到首个 `}`。readText 写在首个内层 lambda 闭括号之后的嵌套 lambda 里时，截面上没有 readText，绑定名不登记，后续 contains 断言漏判。旧版实测夹具二 0 命中。
- 假红路径（夹具四、夹具五）：白名单关键词 filterNot / filter / strip_comments 落在首个 `}` 之后时，旧截面看不见，已剥注释面的合法写法被打成 RAWSOURCE 假红。旧版实测夹具四、夹具五各 1 处假红。
- 字符串干扰路径（夹具三）：截面不感知字符串状态，字符串字面量里的 `}` 被当成代码闭括号，截面在串内 `}` 处提前截断。旧版夹具三虽仍判红，但截面已被截断，块体后半段的关键词与 readText 都可能丢。
- 同源局限（赋值形态）：普通赋值 RHS 旧正则同样按声明行边界截断，深层嵌套 lambda 内的 readText 无括号配平能力，与 lazy 形态同一根因。

## 二、改法（状态机配平替换正则截断）

- 声明头识别改为 `DECL_HEAD_PAT`（`data_scripts/check-test-assert-truth.py:42`），只认 `val` / `var` 绑定；旧版正则会把函数签名 `: String = ...` 里的类型名误抓成绑定名，本次一并清掉。
- 字符串区间预扫 `_scan_string_ranges`（:142）：先扫出双引号串、字符字面量、三引号串的区间，供声明头匹配点回查，避免测试串里写着 `val x =` 被当成真实声明。
- 块体配平 `_balanced_block`（:197）：从 lazy 块开括号起做括号 / 字符串感知配平，双引号串与字符字面量内的反斜杠转义跳过下一字符；字符串内的 `{` `}` `(` `)` 不计深度；配平失败兜底取到末尾，不抛异常。
- 赋值 RHS 收口 `_rhs_until_boundary`（:257）：括号 / 字符串感知地取到本语句结束。深度 0 的换行处判断收口：行首出现下一条声明边界词（val / var / fun / private / import / @）收口；下一行以 `.` 开头、当前行尾是未闭合括号或续行运算符、或当前行为空行（RHS 换行起步）视为续行，否则收口。续行链式调用与嵌套 lambda 都留在截面上。
- 断言实参截面 `_assert_arg_body`（:328）：同样改为字符串感知配平，字符串内的括号不再把实参截面带偏；截面仍限 400 字符，够覆盖单条断言。
- 绑定收集 `extract_readtext_bindings`（:380）：两种形态统一收集——普通赋值 `val src = ...` 与 lazy 委托 `val src by lazy { ... }`。块体内出现 readText 才登记；块体内出现白名单标记（`filterNot`、`filter {`、`strip_comments`，:59）即放行，判断覆盖整个配平块，含续行与嵌套 lambda，不只看首行。
- 旧版两条正则（赋值形态、lazy 形态）已整体删除，不留旧格式兼容层。

## 三、夹具矩阵（逐样本独立临时目录单文件跑，不靠聚合结果凑）

坏样本（必红，退出码 1）：

- 夹具一（lazy 基线）：`val src by lazy { java.io.File("x.kt").readText() }` 接 `assertFalse(..., src.contains("mastered"))`。旧版已红，新版仍必红，绑定行回指 lazy 声明行。

- 夹具三（字符串含 `}` 坏样本）：`val src by lazy { java.io.File("x.kt").readText().replace("}", "") }` 接同名 contains 断言。旧版判红但截面被串内 `}` 截断，新版配平后仍必红。
