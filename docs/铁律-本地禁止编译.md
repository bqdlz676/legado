# 铁律 · 本地禁止编译（F-107）

## 一、用户原话（2026-11-25，逐字）
> 本地禁止编译

## 二、为什么（不是洁癖，是事故驱动）
1. 沙箱没有 JDK21 toolchain、没有 Android SDK，本地跑 gradle 一定不是"真编译"，只会产出**假绿/假红**：某个子代理用 JDK17 跑定向 test task，编译不过就写"未验证"，编译过了就以为验过 —— 两种都是伪证据。
2. 本地跑 gradle 会留下 Gradle daemon 常驻进程，直接撞门禁 ⑩（资源占用），我一个子代理为此还停下来 kill 了 daemon，白烧一段上下文。
3. 唯一可信编译验证是 CI（云端 JDK21 + 完整 SDK）。本地任何"我试了一下能编译"都不算证据，反而污染回执。
4. 双份编译=双份口径：本地缓存出的 class 与 CI 产物不一致时，排查成本翻倍（历史 K 族红里已有先例）。

## 三、规矩（写进每张派单的硬约束）
- **禁止执行**任何 `gradle` / `./gradlew` / `gradlew.bat` 命令，包括但不限于 `compileAppDebugKotlin`、`testAppDebugUnitTest`、`--dry-run`、`tasks`、`help`、`--version`。
- **禁止**为了"试一下"去找 JDK、改 toolchain、拉 Android SDK、装 gradle wrapper。
- 允许的静态自检：`grep`、`ls`、`find`、`python3 data_scripts/*.py`、`bash data_scripts/rule-gate.sh`、`bash data_scripts/spec-check.sh`。
- 回执里"未验证项"必须写"按 F-107 未本地编译，等 CI"，**不许**写"我试跑了 XX task 但失败"。
- 若确实需要编译信号：推一次 commit，等 CI 终态，看 run id 与 conclusion；拿不到就标"CI 未拿到"，不许自造结论。

## 四、机械守卫
- 门禁 ㉝ `data_scripts/check-no-local-build.py`：①发现 `GradleDaemon` 进程 → FAIL；②`~/.gradle/daemon/*/daemon-*.out.log` 在近 120 分钟内被写过 → FAIL；③仓库内 `app/build/` 或 `build/` 目录存在且近 120 分钟内被写过 → FAIL。
- 判据是"近 120 分钟"而不是"永久"，因为历史构建残留不该永久卡门禁；超过窗口的残留只告警不拦。

## 五、违反后果
- 单子直接判废（登记 `docs/台账-子代理存活.md` + `docs/事故清单.md` A 族），不采信其"验证"部分；需要时换人重派。
