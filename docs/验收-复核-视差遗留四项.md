### 判据 1 · 引用计数正确性（N5：同宿主重入不重复上牌 / 未上牌 release 幂等 / 最后一张牌才 teardown） —— PASS（静态层）

实现落点（逐字）：

- `app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:53` `private val holders = HashSet<String>()`
- `app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:85-92`：
  ```

      val fresh: Boolean
      synchronized(holders) {
          fresh = holders.add(host)

      return level > 0
  }
  ```
- `app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:98-104`：
  ```

      val empty: Boolean
      synchronized(holders) {
          empty = holders.remove(host) && holders.isEmpty()
      }
      if (empty) teardown()
  }
  ```
- `app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:107-108` `ensureStarted` 复用判断 `if (listener != null && sensorManager != null) return`；`GyroBridge.kt:172-184` `teardown()` 注销监听、清 FIFO、清兜底缓存、`level = 0`。

三条静态性质核对：

- 同宿主重复 acquire 不重复 registerListener：`holders.add(host)` 对集合内已有元素返回 false，`fresh=false`，跳过 `ensureStarted`，不会第二次 `registerListener`（`GyroBridge.kt:88-90`）。
- 未上牌宿主 release 为幂等空操作：`holders.remove(host)` 对不存在元素返回 false，`false && holders.isEmpty()` 短路为 false，`empty=false`，不触发 `teardown()`（`GyroBridge.kt:101`）。
- 只有最后一张牌摘掉才真正注销并清队复位：`remove` 成功且集合为空才 `empty=true` → `teardown()`；`teardown` 内 `unregisterListener`、`queue.clear()`、`haveAccel/haveMag=false`、`level=0`（`GyroBridge.kt:176-183`）。

四段交错时序推演（H 为持牌集合；监听存活条件 H 非空）：

1. 序列一 · 书架先还 / 地图后还：`PlaceMapActivity.onResume` → `acquire("place-map")`，H={map}，注册监听；书架 Fragment `onHiddenChanged(true)` → `release("shelf")`，`shelf` 不在 H，`remove` 返回 false，H={map} 非空，**不 teardown**，地图监听与 FIFO 原样保留；地图后续 `pull()` 仍可取流；直到地图 `onPause/onDestroy` → `release("place-map")`，H=∅，才注销清队。
2. 序列二 · 地图先还 / 书架后还：书架 `acquire("shelf")` → H={shelf}；地图 `acquire("place-map")` → H={shelf, map}，监听复用不重复注册；地图 `release("place-map")` → H={shelf}，监听保留，书架姿态流不断；书架 `release("shelf")` → H=∅ → teardown。与序列一互为镜像，摘牌只摘自己的。
3. 序列三 · 双持牌后各自生命周期结束：双宿主持牌期间任一方 `onPause/onDestroy` 只移自己的标识，另一方的监听、队列、`level`、兜底缓存均不动；后结束的一方摘牌后 H=∅ 才整体复位。顺序无关：书架先还或地图先还结论同上，不存在「B 在用被 A 拆」的交叉。
4. 序列四 · 宿主 onPause 与 onDestroy 连续两次 release：地图 `onPause` → `release("place-map")`，H=∅ → teardown；随后 `onDestroy` → 第二次 `release("place-map")`，`remove` 返回 false，`empty=false`，**第二次不重复 teardown**，幂等成立。沙盘 `BattleActivity.kt:74`/`BattleActivity.kt:79`、地图 `PlaceMapActivity.kt:210`/`PlaceMapActivity.kt:215` 同此口径。

并发护栏：`holders` 增删在 `synchronized(holders)` 内（`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:87`/`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:100`）；`queue` 既有 `synchronized(queue)`（`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:169`/`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:180`/`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:187`）；`level` 标 `@Volatile`（`app/src/main/java/io/legado/app/help/sensor/GyroBridge.kt:41`），JS 线程 `drainLatest` 与主线程申领/交还不竞态（静态推断，真机线程时序未上机）。

## 八、自查反例 / 改坏推演

- 反例 1：若引用计数用单个 `Int` 而非身份集合。书架 onResume→onPause→onResume 快速重入时 +1/-1 后计数归零会误拆地图正在持有的桥；现集合按宿主身份去重，重入 `add` 不增量、未知宿主 `remove` 不扣减他人（判据 1 序列一/二可证）。
- 反例 2：若关闭态把轮询彻底取消、不刷 `available`。设备本无传感器时开关来回切换后按钮置灰态无法回显；现保留 2Hz 标量读取覆盖该边界（判据 4、O2）。
- 反例 3：若非活跃态 `shadowColor` 仍按残留 `roll` 算透明度。上次倾斜到 |roll|≈1 后关开关，残影阴影仍偏浓偏虚；现守卫直接回缓存基础色（判据 3 `ShelfParallax.kt:223`）。
- 反例 4：若 `ensureStarted` 复用监听时只判 `listener != null`。listener 残留而 SensorManager 已空的脏态会导致注册状态不一致；现双非空（`GyroBridge.kt:108`）才复用，否则 teardown 重建。
- 反例 5：若开关打开时 Fragment 处于隐藏槽也直接申领。不可见宿主白抢传感器，回可见路径还会重复注册；现按 `RESUMED && !shelfHidden` 闸门（`InkShelfFragment.kt:256`）。
- 反例 6：若 D2 守卫把 `touchPaused` 排除在 active 之外。手指拖动期间阴影会跟残留倾斜偏移，与位移回中口径打架；现沿用既有三因子 `active`（`ShelfParallax.kt:176-177`）。
- 反例 7（二阶）：若 `release` 摘牌后不清 FIFO，旧姿态会留在队首被新宿主首帧 drain 到造成视角跳变；现 teardown 清队口径保留（`GyroBridge.kt:180`），新宿主首帧空队，JS 端本帧不更新姿态。
- 反例 8：若验收把「未编译」写成「编译通过」即越级替 CI 背书；本单按 §9 封顶「有条件通过（编译面待 CI）」。
