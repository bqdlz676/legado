# 归并 · 旧项目「落文」(com.gain.luowen) 经验与功能对照

> 背景：落文当前仓库（`io.legado.app` / `com.legado.app`，fork 自 bqdlz676/legado）的前身，是 `Luowen/`（`com.gain.luowen`）——一个纯 Java + 传统 View 的古籍阅读原型，8 个文件约 1350 行，自带 `ReadEngine`，定位"古籍通读 · 字字有据"。
> 本文件是"归并"的落点：把旧项目可复用的经验、数据资产、缺口一并沉淀，避免从头再踩坑；旧项目目录随后归档、清理编译垃圾。

---

## 一、旧项目是什么（已通读全部源码）

| 文件 | 职责 | 可复用点 |
|---|---|---|
| `ReadEngine.java` | 零推理通读：切章→逐字取词典首义→落库 | 内存 HashMap 命中、只收汉字区、同章去重、MIN_PRIORITY 线程、`running` 可中断 |
| `ReaderActivity.java` | 阅读器（分页/点字/气泡/样式） | 点字先取字再判翻页；气泡贴字底 2dp 水平居中、越界上翻 |
| `CharActivity.java` | 字详情：拼音→注家→字典义项→库内判义 | 义项按 `；。;` 切分、去编号、30 字截断、去重 |
| `StudyActivity.java` | 考点库 + 五题制自测（规则判分，不调模型） | **当前落文无此功能** |
| `Books.java` | 书库 16 部古籍、固定段长切章 | 单章压 3000 字防 OOM |
| `Db.java` | 三库分离：主库/字典库/典故库 | `char_mean(ch,book,chap,keep,src)` + 索引 |

## 二、经验提炼（跨到当前落文要照做的）

1. **点字交互顺序**：点击先做逐字命中（`getLineForVertical` + `getPrimaryHorizontal` 取最近字），命中汉字就弹字义气泡；**落空才判左右 1/5 边缘翻页**。→ 这正对应当前冻结契约 `VerticalLayoutEngine.hitTest` / `BubbleResolver.resolve`，顺序不能反（先字后页）。
2. **气泡几何**：贴字底 2dp、以字中心水平居中、越界自动上翻。→ 对应当前 `help/bubble` 域与半屏 `ui/components/InkHalfSheet` 的锚点规则。
3. **长文防 OOM**：单章上限压 3000 字、StaticLayout 分页时 1.2 万字截断；当前 legado 排版层有真分页，但"超长章节兜底截断"的防线仍要保留（铁律 A 边界红线）。
4. **零推理落库**：6373 条简义一次进内存 HashMap，逐字查询变内存命中，避免 N 次 SQL；通读线程 MIN_PRIORITY + `volatile running` 可随时停。→ 当前落文名物库/全书字表若做离线建库，照此"内存命中 + 可中断 + 不调模型"三原则。
5. **三库分离**：主库（落库结果/笔记）+ 字典库（只读）+ 典故库（只读），字典/典故从 assets 首次拷贝到 filesDir。→ 只读库与写入库物理分离，防误写、省事务开销。
6. **义项归一**：多义项用 `；。;` 切首义、去编号前缀、单条 30 字截断、去重；注家取毛传/朱熹原话。→ 对应当前 `help/person` 的注家/义项口径。

## 三、功能对照（旧 → 新）

| 旧项目功能 | 当前落文现状 | 结论 |
|---|---|---|
| 书库 16 部古籍简本 | `assets/books/` 已有 30+ 部（多带集注/故训传/补注） | **已被更全版本取代，旧文本不迁** |
| 字典库 dict.db / 典故库 allu.db | `help/ChineseDict.kt`、`help/CompactDict.kt`、`help/AllusionDict.kt` + `assets/allusion.txt` | **已有对应实现，旧 db 不迁** |
| 点字出义气泡 | `help/bubble` 域 + `BubbleResolver` | 已有，仅对照交互顺序 |
| 字详情（注家/义项/库内判义） | `help/person` 域 | 已有，仅对照口径 |
| 阅读样式 4 字号/3 行距/4 底色 | 阅读氛围域（bg 12 色 + 主题） | 已被设计系统取代 |
| **考点库 + 五题制自测**（StudyActivity） | **无** | **缺口 → 立为新缺陷** |

## 四、缺口（归并结论）

**新缺陷 GAP-KB：考点库 + 五题制自测（规则判分，不调模型）。**
- 来源：旧项目 `StudyActivity.java`（307 条考点 `kb_courses.json`、按课程分组、出题"2 名词解释 + 1 填空 + 1 选择 + 1 简答"、答案取自 `【一句话】` 小节）。
- 为什么保留：用户是汉语言文学专业学生，这是学习刚需；且"规则判分不调模型"天然符合当前落文"离线、零推理、不崩"的红线。
- 待办：在新架构下重做为 Compose 原生页 + 离线考点数据（旧 `kb_courses.json` 未在旧项目 assets 中找到，需另取或重建），列入派单队列。
