## 二、判据设计（每条为什么 / 适用条件）

### ㊶ `check-queue-ledger.py` —— 队列↔台账结构与状态一致

- **C1 列数一致**：主表每个派单行单元格数必须等于表头 6 列。
  - 为什么：M-01 实测 4/6/7/8 列四种混排，按列解析必然取错列；列数不齐是后续一切状态误判的根因。
  - 适用条件：只解析主表；遇到「历史追加账」标题即停止读取，留档 4 列行不参与本判据。
- **C2 状态白名单**：归一化后只许 `PENDING / RUNNING / DONE / BLOCKED / 作废`；`BLOCKED` 必须同时含阻塞原因与解除条件。
  - 为什么：自由状态词（「差不多好了」「已转移」）无法机械分类，僵尸单无法被发现；BLOCKED 不写解除条件就会永久挂起。
  - 适用条件：状态括号内的证据/commit/代理 id 不参与白名单判定，只判前缀族。
- **C3 RUNNING 四要素**：agent id（`s_xxx` 或「调度层」）、起始时间、文件域、判据锚，缺任一 FAIL。
  - 为什么：M-02 僵尸 RUNNING（Q-44/Q-54/Q-61）曾长期挂在飞、实际已 DONE/作废；四要素齐全才能机械判断「真有人在跑、跑的是哪块、锚在哪」。
  - 适用条件：起始时间取创建时间列或状态列内时间；判据锚取依赖列或文件域列中的 `docs/`/锚点/矩阵/拍板/`M-xx` 引用。
- **C4 双事实源一致**：队列与台账同 Q-xx 状态不得互相矛盾（RUNNING↔已收口/作废、DONE↔作废、作废↔在飞、PENDING↔已收口 均 FAIL）。
  - 为什么：M-04 同一事实两处手写必漂（Q-44 队列 RUNNING / 台账 DONE）；须定队列主、台账从，机械对账。
  - 适用条件：台账未登记该 Q-xx 时跳过本条（不反向要求补登，新鲜度归 ⑯ 职责）；台账状态词归一化到五态后再比。

### ㊷ `check-ledger-status.py` —— 清单状态↔报告一致 + 状态词白名单

- **S1 报告脱钩**：编号命中 `docs/修复-<ID>-*.md`、`docs/修复-<ID>R*-*.md`、`docs/验收-*<ID>*.md` 任一报告，而清单状态仍是 🔴 未开工族 → FAIL，列出「编号 → 报告文件」。
  - 为什么：M-03 九个 B 缺陷报告落盘后没人回写清单，103 个 🔴 无法区分真未派与脱钩僵尸。
  - 适用条件：编号按 token 边界匹配（B2 不误命中 B12）；带横线编号（B-2）归一化去横线比对；仅 🔴 族判脱钩，🟢/✅/⛔ 不算。
- **S2 状态词白名单**：状态单元格 emoji 必须属于 🔴🟡🟢✅⛔，关键词落在该族白名单；空状态、✅ 只挂哈希无结论词、自由写法 → FAIL。
  - 为什么：M-07 四套词表四分，不同词同义不同态，门禁无法分类；F-117 已冻结唯一映射。
  - 适用条件：裸 emoji 按族默认态接受（🔴=未派 / 🟡=在飞 / 🟢=已修·待验证 / ⛔=作废）；✅ 例外——关闭态必须有结论词，仅 commit 哈希/代理 id 判 FAIL；反引号、哈希、代理 id、括号证据在判词前剥离。

### F-117 状态词表唯一映射（口径冻结行 266–291）

- 六行映射：未开工 / 在飞 / 已修待验 / 已验关闭 / 阻塞 / 作废，逐行给出队列四态 ↔ 清单五态 ↔ 矩阵四词 ↔ 报告用词。
- 特别排除：「已拍板」是决策态不是验收态，禁止记入 ✅已验·关闭；矩阵「未落地」不等于清单作废。
- 指针：机制缺陷总账 `docs/台账-机制缺陷.md`（M-01~M-10），本单落实其门禁部分；总账由调度层维护，门禁只读不改。

### rule-gate.sh 输出可读性（M-10）

- ⑯/⑱ 结论行只保留一处 ok/FAIL 与最终 PASS 判据串，不再回显脚本内部 ok；WARN 单独成行并写「（不影响 GATE 结论）」，不与 ok 混排。
- 为什么：旧输出 `⑯台账新鲜度 ok ok …` 一行两遍结论，WARN 夹在 ok 里，人眼扫不到真 FAIL。
