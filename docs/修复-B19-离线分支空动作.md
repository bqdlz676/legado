## 1. 缺陷与本单结论

- 缺陷原文（`docs/验收-B17-离线重试分闸.md` §四.1）：`InkBottomSheet.kt:213-217` 与 `InkHalfSheet.kt:326-318` 的 OFFLINE 分支渲染 `InkEmptyState(offline = true, ...)`，均未传 `onAction`，回落默认 `{}`（`InkEmptyState.kt:38`）。B17 分闸后该重试按钮视觉可点，但点击不发起任何重载 / 拉缓存动作，错误恢复链路断在最后一跳。
- 排查结论（判据 1/2/3 逐条核对，证据见 §4 E1-3b）：
  1. 两支浮层是通用容器组件，自身不持有数据与网络请求；其现有动作形参仅有 `onDismiss`（关闭），不存在可直接接入离线重试的刷新 / 重载函数。
  2. 全仓 main 业务调用点 grep 零命中：没有任何调用点向 `InkBottomSheet` / `InkHalfSheet` 传 `state = ComponentVisualState.*`，也没有调用点传重试回调；两支浮层的 OFFLINE / EMPTY / LOADING 分支当前在生产路径上处于休眠态，但组件内「可点空动作」的缺陷形态成立，仍须按锚点卡收口。
- 本单处置口径：**接接缝，不挂空 lambda；缺省回落纯提示**。
  - 两支浮层各新增可选形参 `onRetry: (() -> Unit)? = null`：宿主将来把真实重试 / 刷新函数传入时，离线「重试」按钮接到该回调（判据 1/2 的 Wired 路径）。
  - 宿主未传（null）时，组件内没有可接的重试入口，按判据 3 回落纯提示文案：动作标签置空、不渲染可点按钮，不抛异常、不静默挂空 lambda。
  - 契约 OFFLINE 容器本体禁点语义保持不变（判据 4），本单不放宽容器闸。
