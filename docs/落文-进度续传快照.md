### 6.2 上下文爆掉的根因与对策（本次故障的直接教训）

**根因**：全局单点调度。一个调度 Agent 同时持有 20+ 子任务的往返消息 + 验收报告（7 份、每份 18–22KB）+ 代码片段，再叠加常驻规格（规矩总纲 20KB + 契约索引 23KB + 设计规格 29KB + 路线图 4KB ≈ 76KB）。任务量不是主因，**单点承载全局才是主因**。任何"让一个 Agent 记住全部"的设计都会周期性崩。

**对策（与铁律"三层分离"同构）**：

1. **调度层只持索引**：只读本快照 + 契约索引 §3，不读设计规格全文、不贴代码、不回灌过程。
2. **按批拆组**：每批 3–5 个模块，一个调度；做完即结、另起一批，绝不把已完成批次的过程带进下一批。
3. **子 AI 只读一段**：一个切片 + 自己文件域，禁整仓通读。
4. **验收独立成组**：验收 AI 只读"原文切片 + 该模块代码 + 判据"，不与执行 AI 共享上下文。
5. **状态落盘优先**：阶段结论先写 `docs/`，再对外报——落盘是唯一能跨 Agent 存活的记忆。
6. **并发按负载收敛**：默认并行，负载高降到 2 个。
7. **对话记忆不可救**：Agent 重启即清空，**任何"找回上下文"只能靠仓库落盘**，不要试图扩容旧会话。
