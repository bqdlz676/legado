1. **Bubble（气泡）**：撕边纸片 + 金边 + 注入动画（spring）+ 义项切换点。四种变体——字/词/人名/地名，结构不同但容器统一。
2. **BottomSheet（半屏 Sheet）**：毛玻璃底 + 金杠拖拽指示器 + 三段高度（30%/60%/90%）+ 跟手下拉关闭 + 背后遮罩联动。Radix Dialog 改不动这个，需要从 Radix Drawer 或手写。
3. **Timeline（时间轴）**：竖线 + 节点 + 政权对照行。纪年页和历史人物 Sheet 共用同一个组件，只换数据。
4. **InkButton（墨触按钮）**：落文全站不用 Material ripple。所有可点元素用一个统一交互：touchstart → 元素短暂泛朱砂色（背景从 0 到 8% `--text-accent`），120ms 后回落。不是动画层管，是**组件系统的基类**——所有 Button/ListItem/Tab 继承它。


**组件状态覆盖（你列的 6 态，补一个）**：
默认 / 悬浮 / 点击 / 禁用 / 加载 / 空状态 / **离线状态**——地图页没有网络时降级到缓存瓦片 + toast 提示。

## 漏掉的关键层：性能预算（没这层，上面四层全崩）


落文有几个其他 App 没有的性能天敌：WebView 里跑 Three.js + 竖排文字渲染 + 大字表加载。必须定死上限：


| 指标 | 上限 | 测量点 |
|---|---|---|
| 启动 → 看到书架 | ≤ 1.8s | `performance.now()` 首帧 |
| 首触气泡 | ≤ 300ms（冷）/ ≤ 80ms（热） | touchstart → 气泡 visible |
| 翻页 | ≤ 16ms/frame（不掉帧） | `requestAnimationFrame` 间距 |
| 地图页进 | ≤ 2s 地形渲染完成 | WebView `onPageFinished` → 首帧 |
| 内存峰值 | ≤ 180MB（含 WebView） | `performance.memory` |
| 字体子集大小 | ≤ 200KB 首屏 | Network 面板 |
| 字典加载内存 | ≤ 15MB（4 表总和） | 加载前后 `usedJSHeapSize` 差值 |
Kotlin 原生壳 + 地图/详情走内嵌 WebView，其他保留原生。半屏 Sheet 用 `BottomSheetDialogFragment` 手写磨砂背景「大词典的内存与首触卡顿」这一个点上，其次是几个算法层面的小账。按优先级排：① 内存 / 首触卡顿（最重要）
所有词典都是「第一次点才把整个文件读进 HashMap」——好处是懒加载不拖启动，坏处是每个功能第一次点会卡一下：


EnDict：40 万词 → HashMap(420000)
ChineseDict.ensureWord：28 万词 → HashMap(280000)，再加字/说文/用例三个 map
PersonProfile cbdb：person.txt 用 readText() 整读 8.8 万条（先把整个文件读成一个几 MB 的大 String，再切行），这比别处多用一份瞬时大字符串改法：


person.txt 改成 bufferedReader().useLines {}（你其他文件已经是这么写的），去掉瞬时大 String；
大词表从「文本行解析进 HashMap<String,String>」换成紧凑二进制 + 有序二分（或 SQLite/MMKV）。40 万词装箱成对象，低内存机能直接 OOM；排序后二分查找内存能降到 1/3 以下；
