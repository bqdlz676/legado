## 二、改法：正交分页态 + 三道守卫 + 底部三态脚注

### 2.1 状态模型：分页态与整页态正交（`SearchModels.kt`）

新增 `SearchPagingState` 四态（第 86-99 行）：

| 分页态 | 语义 | UI 表现 |
| --- | --- | --- |
| `Idle` | 空闲，可接受下一次到底触发 | 不渲染脚注 |
| `LoadingMore` | 下一页在途；并发保护，重复到底不重复请求 | 三点加载 +「正在加载更多…」 |
| `LoadMoreError(message)` | 上一页失败，保留现有列表 | 朱砂提示 +「重试」入口 |

### 2.2 归约器：四个翻页 Intent + 守卫 + 首屏重置（`SearchReducer.kt`）

## 五、二阶 / 三阶推演

### 5.1 二阶（直接连带影响）

- **翻页不再切走列表**：`onSearchStart` 识别在途分页态后跳过整页 `Loading`，第二页加载时首屏列表保持可见，不会被三点全屏态替换；失败也只在脚注给重试，不把已有结果顶成整页错态。
- **并发三重保险**：UI 连发 → 归约器 `canLoadMore` 守卫 → ViewModel 去抖窗口 → 底层 `SearchModel` 的 `SearchPageOwner.isRunning()` 二次拦阻；任一层都能挡住同页重复请求。
- **跨词不串页**：新 `Submit` / `PickHistory` / `Retry` / 清空都会 `resetPaging` 并清零去抖时间戳；上一词的在途回调落到非 Content 态时被归约器拒收，不会把旧书灌进新词结果。
- **离线兜底一致**：翻页途中断网走 `LoadMoreFailure(OFFLINE_MESSAGE)`，保留现有列表可重试；与首屏离线态的文案 / 缓存口径一致，不新增网络权限。
- **缓存列表不可翻**：Error / Offline 的缓存列表显式 `hasMore=false` + 空回调，避免在不可点击的缓存上再挂到底请求。

### 5.2 三阶（长期演进与维护成本）

- **合并去重留待 D5**：本单追加只做 id / 同名同作者轻量去重；本地书架前置、命中档位排序等口径仍归 D5，`SearchMerger` 单一收口，后续 D5 改排序不必动分页接线。
- **状态可扩展**：分页四态与整页六态正交，后续若加「预取阈值」「页脚字数统计」「远端总条数」，只需在 `SearchPagingState` 增档、归约器插分支，UI 骨架不动。
- **认知成本**：触发策略（去抖）收在纯 JVM 的 `SearchPagingPolicy`，守卫条件收在 `canLoadMore` 派生属性，归约器只做状态翻转；接手者读 Models + Reducer 即可看清翻页闭环，不必翻 Compose 层。
- **历史包袱排查**：改前 `onSearchFinish` 的 `hasMore` 形参为零引用（仅空态分支用 `isEmpty`），本次激活；未发现可一并移除的废旧兼容层。
