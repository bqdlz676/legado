## 五、新发现问题

1. 55 基线只锚路径不锚内容（待裁）：`check-problem-finding.py:176-177` 按 `rel in base` 整份跳过，在册基线报告被改写成无节空话仍 PASS（探针 4.2-c）。建议总控评估基线键补内容指纹（对照 56 `:61-67` 行哈希做法），或要求基线报告定期重审销账。
2. 55 条目计数不认 `*` 星号列表（待裁）：`:96` 正则 `(?:-|\d+\.|\|)` 不含 `*`，星号条目被算成 0 条误判 FAIL（探针 2.6）。建议条目正则补 `\*`。
3. 56 白名单按整份文件名前缀豁免，前缀文档内旧串不审（待裁）：`check-lock-rule.py:41-58`，`验收-`/`修复-`/`锚点` 等前缀整份跳过；本验收报告自身即落在 `验收-` 前缀豁免内。建议总控评估白名单是否应收窄为"同行留档标记"豁免，与 55 的行内豁免口径对齐。
4. 56 旧口径正则以句号/换行截断，跨句号或跨行旧句存在漏配风险（待裁）：`:36` `禁[^。\n]{0,16}rm[^。\n]{0,20}index\.lock`，短语 `禁删锁` 无此问题；`rm` 与路径若被句号/换行隔开即不匹配。建议补跨句边界探针夹具。
5. 55 仓库级扫描漏抓未跟踪中文路径（待裁）：`:79` 调 `git status --porcelain -uall` 未带 `-c core.quotepath=false`，中文文件名按八进制转义包在引号内；`:50-56` `_status_path` 只剥引号、不解转义，`:82` `NAME_RE` 匹配失败，未跟踪中文报告不进判定集合，仓库级返回 EMPTY（RC=2）。实测本单两份 Q222 文档均未被 `report_paths()` 捕获；显式传文件参数可正常判。建议 git 调用加 `core.quotepath=false` 或对路径做 `unicode_escape` 还原。
6. 55 相对路径参数崩溃（已修）：旧版 `relative_to(ROOT)` 抛 ValueError；当前 Q-223 版 `_resolve_target` + `_rel` 兜底已收口，复测 RC=1 结构化判红、不崩（见 4.1）。
7. 56 基线行哈希锚内容有效（已闭环）：改一字哈希即变、豁免失效升级命中（见 4.3），棘轮基线设计验收通过。
