## 三、EntityProvider 结构

- 接口沿用契约层定稿：`EntityProvider.query(name: String, type: String, anchor: Any?): BubbleContent`（`help/artifact/EntityProvider.kt:29`），本片未改签名、未新增第二个 Provider 接口。
- 新实现 `RegistryEntityProvider`（`provider/RegistryEntityProvider.kt:37`），构造注入 `ArtifactSeedSource`（默认内存种子源）与可选 `ArtifactLoadStrategy`；为什么可注入：全量数据片替换数据源 / 策略时不动 Provider 路由代码（09:13 加新类别只加数据表）。
- 条目模型 `ArtifactEntry`（`entry/ArtifactEntry.kt:28`）：id、name、type、headline、body、detail、aliases、source、relatedPlaceId、relatedArtifactIds、longitude、latitude。为什么 detail 与 body 分层：09:73 最小共同气泡字段——壳内只放名称 + 一句话，完整释义进半屏 Sheet。
- 读取抽象 `ArtifactSeedSource`（`provider/ArtifactSeedSource.kt:16`）：`entriesFor(registrationId): List<ArtifactEntry>`；为什么独立接口：内存种子、资产文件、按需下载三种源后续可互换，Provider 不感知实现。

## 四、路由与懒加载实现位置

- 注册表路由：`RegistryEntityProvider.query` 先经 `ArtifactRegistry.byType(type)` 反查登记（`RegistryEntityProvider.kt:49`）；`byType` 先匹配代表 type / 子类型，再按机器 id 兜底（`ArtifactRegistry.kt:260`）。为什么 type 与 id 双入口：适配层透传 schema type，索引页 / 搜索按类别 id 直查，两个入口共用同一张表，路由判断不散落两处。
- 双轨隔离：登记路由为 EXISTING_SLOT 时只回兜底壳（`RegistryEntityProvider.kt:53`），人物 / 地名交 D2 / D3 原 Provider，本实现不对其二次出气泡（09:31）。
- 懒加载：`registration.category` 非空且策略存在时，未驻留则 `loadIfNeeded(category)`（`RegistryEntityProvider.kt:57-63`）；策略为 null 视为种子已驻留；加载异常 runCatching 兜住，不阻断查询。为什么策略可空：本片种子是纯内存表，无下载动作；大库按需下载 / 预缓存实现归数据片（09:72）。
- 分组查询：`ArtifactRegistry.entityRegistrations`（`ArtifactRegistry.kt:267`）与 `existingRegistrations`（`ArtifactRegistry.kt:271`）供适配层 / 索引页遍历，实体链与既有槽不重叠。

## 六、兜底与消歧

- 类别表缺失 / 未登记 type：`byType` 返回 null → `ArtifactFallback.notFound` 结构完整未收录气泡（`RegistryEntityProvider.kt:50-51`），不抛异常、不返回 null。
- 资产损坏 / 解析异常：`entriesFor` 外包 runCatching，异常退化为空列表 → 未收录气泡（`RegistryEntityProvider.kt:67-70`）；`ArtifactSeedSource` 实现侧同口径（`ArtifactSeedSource.kt:29-31`）。
- 条目查不到：名称与别名均不匹配 → 未收录气泡（`RegistryEntityProvider.kt:74-76`）。
- 同名消歧：多条同名取首条进气泡，候选裸串进 `candidates`，body 追加「同名多条，取首条，疑似待核」标记（`RegistryEntityProvider.kt:79-81`、`:114-117`）。为什么取首条而不是猜年代：本片 anchor 仅透传，年代锚消歧链归后续片；首条 + 疑似标记保证不空白、不冒充定论。
- 空名称：trim 后为空串直接回兜底壳（`RegistryEntityProvider.kt:44-46`），不猜名。
- 兜底气泡口径沿用契约层 `ArtifactFallback`：source=`未命中`，actions / candidates 空列表，phonetic=null，body / detail 为空串；五态（NO_DATA / CACHE_MISS_OFFLINE / YEAR_MISSING / AMBIGUOUS / TIMEOUT）状态壳不在本片扩字段。

## 七、跳转挂点（只挂接口与 Action，不接 UI）

- 一级跳转：命中条目挂 `Action.OpenArtifact(artifactId, type)`（`RegistryEntityProvider.kt:108`），供后续「相关名物 → 名物详情 Sheet」展开。
- 二级跳转：`relatedPlaceId` 非空时挂 `Action.OpenMap(placeId)`（`RegistryEntityProvider.kt:110-112`）；无关联地名不造占位地图按钮。为什么先挂数据点：问题清单 D16 行⑤要求「相关名物 → OpenArtifact → 详情 Sheet → 有地名再 OpenMap」两级跳转，本片 UI 渲染归后续片，本片只保证动作与地名挂点就位可回读。
- `relatedArtifactIds` 留在条目模型上（`ArtifactEntry.kt` 相关名物主键列表），供详情 Sheet 展开相关名物链；本片不解析、不跳转。
- 冻结契约 Action 五子类（OpenMap / OpenPerson / OpenTimeline / OpenRelation / OpenArtifact）本片未扩、未改；OpenArtifact 在既有适配层 `ArtifactBubbleProvider.toLegacy` 暂置空丢弃的现状未动，接线归后续 UI 片。

## 八、断言与改坏推演（18 条纯 JVM 单测）

注册表侧 `ArtifactRegistryTest.kt` 7 条：

1. `十七类登记清点为十七项且显示名逐字一致`：断言 17 条登记与 F-07 名单逐字相等；删一条 / 改一个类别名即红。
2. `每条登记表名资产路径来源许可非空且实体链带代表type`：逐字段非空断言；漏填来源 / 许可即红。
3. `既有槽两类实体链十五类分流防双轨`：既有槽＝person/place，实体链 15 类，两组不相交；把人物或地名错挂进实体链即红。
4. `实体链每类种子三至五条既有槽不重复种子`：15 类种子数 3~5，person/place 种子为 0；种子超量 / 缺类即红。
5. `type反查登记唯一且不串到别的类`：代表 type、子类型（constellation / calendar_term / river / lake / pavilion）路由到正确类别，未知 type 返回 null；type 串类即红。
6. `山川独立landscape表不混入artifact表`：landscape 表名为 landscape，artifact 组内无 landscape。
7. `注册表机器id唯一无重复键`：id 去重计数相等；重复登记即红。

8. `注册表缺类查询返回未收录气泡不抛异常`：未知 type 查询 source=未命中、actions/candidates 空；缺类走异常或空白态即红。
9. `路由type错不串到别的类`：赤兔用 sword 查未命中、用 horse 查命中；龙泉用 horse 查未命中；跨类串结果即红。

12. `空名称查询返回兜底气泡不抛异常`：空白名不猜名、不崩。
