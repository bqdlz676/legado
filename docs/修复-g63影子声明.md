## 四、自查反例与改坏推演

- 反例一（只数大括号深度、不分类帧会误杀类体成员）：顶层函数体与类体都在 depth=1，若按「深度等于类体层」单条件放行，fun 体局部声明与类体成员无法区分；本单按开括号头部分类成 `decl` / `block` 两类帧，栈内出现任一 `block` 帧即排除，类/接口/object/伴生对象/抽象类体帧仍为 `decl`，放行样本八至十一锁这四类不误伤。
- 反例二（回看兜底把上一行关键字带到本行）：类头/fun 头跨多行时开括号落在 `) {` 或裸 `{` 行，若合并本行与回看行后直接搜声明关键字，上一行 `class` 会把本行 fun 体帧错分成声明帧。现归类两步走：先认本行文本，命中 fun 等控制流关键字即判 block，回看仅在本行无关键字时启用。
- 反例三（串/注释内花括号带偏配平）：字符串、三引号串、字符字面量、块注释里的 `{` `}` 若进帧栈，深度会被文案带乱，真实类体帧被多压/多弹。状态机在串与注释状态下跳过一切括号字符，探针覆盖双引号串花括号、三引号串花括号、字符字面量 `'{'`、块注释花括号四组形态，局部影子声明均未被误判为声明位。
- 二阶影响：`_declares_name` 生产唯一调用点是 PACKAGE 层声明位兜底（`data_scripts/check-symbol-existence.py:750`），NODEF/ARITY 配平链路不经此扫描器；帧栈判定只收窄「算声明位」的行集，不改索引建表、不改调用计数与退出码口径。
- 三阶影响：新增夹具全部仓外 tempfile 自删，仓内 `data_scripts/fixtures/` 未新增持久夹具；分级表 g63 仍 blocking、compensation null，本单未把存量债降级成 audit 红墙，也未放宽任何既有白名单。
