# 审计 · 编译风险穷举（Q-255，只读核查）

> 审计背景：本轮 `HeightMapRaster` 把公开字段 `data: FloatArray` 改成 `private val pixels` + `valueAt(Int)` + `toFloatArray()`，`HeightMapRasterCache` 的 `CacheKey` 取值口径也改过；两类改动都可能留下远端编译才暴露的 `unresolved reference` 残留。
> 方法：对全仓 `app/src/main`、`app/src/test`、`app/src/androidTest`、`modules/**`、所有 `*.kts` / gradle 脚本做五类穷举——① `HeightMapRaster` 引用点；② `rasterCache`/`CacheKey`/`CacheSlot` 键类型；③ `HeightRaster.data`（IntArray，另一类）；④ 反扫已删/改名符号；⑤ Kotlin 语法级隐患。每条给「文件:行 + 原文片段 + 判定（安全 / 需改 / 存疑）」。
> 边界：只读审计，未改任何被判代码、未跑本地编译与单测、未执行 git 写操作；本环境禁 kotlinc/gradle，编译真值以云端 CI 为准，证据不足处标「存疑 / 待 CI 复核」，不猜。
> 锚点卡：docs/锚点/Q255-编译风险.md。

## 一、类型基线（先固定两套栅格，再谈引用）

### 1.1 `HeightMapRaster`（新解码侧，FloatArray，0..1）

- 声明：`terrain/HeightMapDecoder.kt:29`，`data class HeightMapRaster(width: Int, height: Int, private val pixels: FloatArray, degraded: Boolean, source: SourceKind)`。

- 旧公开 `data: FloatArray` 已删除；`pixels` 私有，外部不得取句柄。

### 1.2 `HeightRaster`（旧地形侧，IntArray，0..255，与本轮改动无关）

- 声明：`terrain/HeightRaster.kt:15`，`data class HeightRaster(width: Int, height: Int, val data: IntArray, degraded: Boolean)`。

### 1.3 `HeightMapRasterCache`（缓存侧）

- 声明：`terrain/HeightMapRasterCache.kt:16`，`internal object HeightMapRasterCache`。
- `private data class CacheKey(val contentHash: String, val width: Int, val height: Int)`（:31）；`private data class CacheSlot(val key: CacheKey, val raster: HeightMapRaster, val lastUsed: Long)`（:33）；`private val rasterCache = LinkedHashMap<String, CacheSlot>()`（:36）。

### 1.4 接口契约

- `terrain/RasterDecoder.kt:17` 是 `fun interface`，`decode(assetName: String): HeightRaster?`（:25）——注意返回 `HeightRaster`，不是 `HeightMapRaster`。

## 六、⑤ Kotlin 语法级隐患扫描

### 6.1 `runCatching` 返回类型

- 栅格域（terrain / shell / crossing engine）与 globe 渲染包内 **零** `runCatching`；栅格解码的异常收口走 `try { ... } catch (_: Throwable) { null }`（如 `HeightMapDecoder.kt:222`、:226、:242；`HeightMapRasterCache.kt:73`；`CrossingRasterBridge.kt:50-55`），返回类型可推断为可空栅格，与上层 `?: synthesize(...)` 回落链闭合。
- 全仓 main 的 `runCatching` 分布在 `App.kt:97`、:119、:122、:126，`api/controller/BookController.kt:313`、:320，`BookSourceController.kt:208`，`ReviewController.kt:55`，`base/BaseDialogFragment.kt:98`，`model/AudioCacheKey.kt:26` 等非栅格域；本单范围外，不逐条核。

### 6.2 `?.let {}` 链类型推断（栅格域逐条）

### 6.3 data class `private val` 构造参数与 `copy()` 可见性（本单重点存疑项）

- 存疑行：`terrain/HeightMapDecoder.kt:472` `return raster.copy(width = nw, height = nh, pixels = out)`。
- 事实：`HeightMapRaster.pixels` 是主构造里的 `private val`（`HeightMapDecoder.kt:39`）；`copy(...)` 调用点在外部 `HeightMapDecoder` object，与数据类不同声明体；调用以命名参数 `pixels = out` 绑定。
- 风险机理：Kotlin 为 data class 生成 `copy()` 时，各形参与主构造属性对应；私有构造属性在 `copy` 形参上的可见性口径，随 Kotlin 版本与 `ExposedCopyVisibility` / `-Xconsistent-data-class-copy-visibility` 迁移阶段不同而有差异。本环境禁本地编译（不得跑 kotlinc / gradle），无法在此实测命名参数 `pixels =` 能否从外部类通过可见性检查；仓库 Kotlin 版本为 2.4.20（`gradle/libs.versions.toml` `kotlin = "2.4.20"`）。
- 判定：**存疑（倾向需改）**。若远端 CI 报 `Cannot access 'pixels': it is private in 'HeightMapRaster'` 或 unresolved named argument，即此行为红点；在 CI 真值回来之前不擅自改代码。
- 备选返工口径（仅列清单，未动手）：
  1. 在 `HeightMapRaster` 类内补一个同体工厂，如 `fun resized(nw: Int, nh: Int, pixels: FloatArray): HeightMapRaster`，类内可直访私有 `pixels`，:472 改调该工厂；或
  2. :472 直接走公开主构造 `HeightMapRaster(nw, nh, out, degraded = raster.degraded, source = raster.source)`，绕开 `copy()` 私有形参可见性问题。
- 另两处 `copy()` 命名参数核对：`HeightMapDecoder.kt:230` `copy(source = SourceKind.NONE)`（`source` 公开 `val`）安全；`HeightMapRasterCache.kt:69` `slot.copy(lastUsed = System.nanoTime())`（`lastUsed` 槽位公开 `val`）安全。
- `HeightRaster` 侧：全部构造参数公开（`data: IntArray` 也是公开 `val`），且仓内无 `HeightRaster.copy(...)` 调用点（仅主构造 / companion 工厂），不存在同类隐患。

## 九、接手认知成本评估（若明日甲工程师接手这套双栅格类型）

### 9.1 必须先建立的心智模型

- 两套栅格并存，不是新旧替换关系：
  - `HeightRaster`：旧地形消费侧，IntArray 0..255 灰度，米制换算 `metersFor = value/255*7000`；`TerrainMap`、通视、坡度、路径规划全走这一侧；构造有 `create` 守卫与 `synthetic` 回落。
  - `HeightMapRaster`：新解码侧，FloatArray 0..1 归一化高程；PNG/Base64/本地路径解码产物落在这一侧；backing 数组私有，对外只有标量读 `at`/`valueAt` 与防御副本 `toFloatArray`。
- 唯一装配转换点：`CampaignController.kt:1308` `toHeightRaster`，把 0..1 乘 255 四舍五入夹紧到 0..255 生成 `HeightRaster`；除此之外两侧不互转。
- 缓存只服务新解码侧：`HeightMapRasterCache` 按源内容哈希 String 做索引键，`CacheKey` 只在槽内记录哈希 + 宽高与逐出台账；坏数据 / 合成回落场不入缓存。
- 解码回落铁律：任何解码失败、资产缺失、畸形栅格、超大图都回落确定性合成场并置 `degraded = true`，不抛异常、不留空白态。

### 9.2 认知成本与易踩坑

- 成本偏高：两个 data class 字段名相近（`data` vs `pixels`）、同名成员 `size`/`inBounds`/`degraded`，但数组元素类型与值域不同；接手人若只看字段名 grep，极易把 `HeightRaster.data`（IntArray，公开）误当成本轮私有化对象去改，或反过来给 `HeightMapRaster` 找 `.data`。
- 第二个坑：缓存键双轨——索引是 String、身份是 CacheKey；改命中逻辑时若误把 `CacheKey` 当索引键，会与 `LinkedHashMap<String, CacheSlot>` 泛型冲突，编译期才暴露。
- 第三个坑：`pixels` 私有意味着外部不能保存栅格数组句柄；需要批量采样只能 `toFloatArray()` 拿副本，副本改写不回写源栅格（缓存隔离口径，`HeightMapRasterCacheTest.kt:48-63` 有反向锁定用例）。
- 建议接手顺序：先读 `HeightRaster.kt` 全文件 → `HeightMapDecoder.kt` 类声明与 `synthesize`/`decodeBytes`/`downsample` → `HeightMapRasterCache.kt` → 最后读 `CampaignController.toHeightRaster` 装配点；不要从 globe 渲染侧反向理解地形栅格（globe 有独立 `RasterResult`/FbmNoise 体系，不共用这两个类）。
