# 落文 · 设计规格（v2 · 完整版）

> 本文件是实现的唯一准绳。旧版实测参数保留为「已实现基线」，与新规格冲突处以新规格为准。
> 一句话：四模块一条总线，一张地图分朝代，一套引擎吃 JSON，一块画板两层墨。

---

## 零、总纲

四个模块不是四个独立功能，是一条流水线：

```
纪年点年号/王公纪年 → 公元年 → 写入 ContextAnchor
字词扫到「鲁隐公 / 三家分晋」→ 也写入 ContextAnchor
地名查询读 ContextAnchor → 按年份选朝代图层
人物查询读 ContextAnchor → 同名者按年份消歧
```

**ContextAnchor 是四模块之间唯一的共享状态，不是可选件。** 四模块互不调用，只读写这一个锚点。少了纪年，地图是死的；少了地图，纪年换出来的公元年没有出口。

## 一、ContextAnchor（全局单例）

```kotlin
object ContextAnchor {
    var bookId: String = ""
    var chapterId: String = ""
    var title: String = ""                        // 「隐公元年」
    var candidateYears: List<IntRange> = emptyList()

    fun setYear(year: Int)
    fun setYearRange(range: IntRange)
    fun getYear(): Int?
    fun getDynasty(): String?
    fun hasAnchor(): Boolean
    fun reset()
}
```

锚定优先级：

| 级 | 来源 | 写法 |
|---|---|---|
| 1 | 用户点年号气泡 | `setYear(公元年)`（用户主动确认，最高） |
| 2 | 正文王公纪年「鲁隐公元年」 | `setYear(-722)` |
| 3 | 干支 + 朔望 | `setYearRange(出生..卒年)`（最弱，只兜底） |

朝代切片（`eraOf`）：春秋 -770~-477 / 战国 -476~-222 / 秦 -221~-207 / 西汉 -206~8 / 新 9~23 / 东汉 24~220 / 三国 221~280 / 两晋 281~420 / 南北朝 421~589 / 隋 590~617 / 唐 618~907 / 五代 908~959 / 北宋 960~1127 / 南宋 1128~1279 / 元 1280~1367 / 明 1368~1644 / 清 1645~1911 / 近现代 ≥1912。

## 二、数据契约

### 2.1 person（人物主表）

`assets/person_core.txt`，14 列，对应 SQL：

```
id  canonical  dynasty  birth  death  identity  feat  state  source  confidence  proofread  zi  hao  fief
```

| 层 | 来源 | 数量 | 质量 | 用途 |
|---|---|---|---|---|
| L1 | 手校核心库 + 王公纪年 | 245（目标 200+） | 生卒/在位已核 | 主力体验，默认展示 |
| L2 | CBDB 多源核验 | ~5000 | 可信 | 补充展示 |
| L3 | CBDB 孤证 | ~8.4 万 | 存疑 | 只进候选池，不默认展示 |

`confidence`：high / medium / low。`proofread`：0 未校 / 1 已校。**生年史书不载的一律留空，不编。**

### 2.2 person_alias（别名表）

`assets/person_alias.txt`：`别名 \t 归属 \t 类型 \t 国 \t 起年 \t 止年`

类型枚举：本名 / 字 / 号 / 谥称 / 爵称 / 封号 / 排行 / 省称 / 俗称。
爵称用 `@国` 占位（`楚子→@楚`、`齐侯→@齐`），运行时映射到该国当年在位君主。

### 2.3 person_chapter_event（逐章出场表）

```
person_id  book_id  chapter_id  paragraph  event_time  relations(JSON)
```

数据来源两条，都要落地：

1. **自动粗稿**：`RelationExtractor` 段内共现，判定同段人物与关系（君臣/父子/盟友/敌国），写入本表。
2. **手录格式**（JSON，人工补）：

```json
{"book":"左传","chapter":"隐公元年","person":"郑庄公",
 "paragraph":"初，郑武公娶于申，曰武姜……",
 "event_time":"前722","relations":[{"person":"共叔段","relation":"兄弟"}]}
```

### 2.4 字词五表

| 表 | 文件 | 列 |
|---|---|---|
| char_dict | char_dict.txt | 字 / 拼音 / 部首 / 笔画 / 义项 |
| char_shuowen | char_shuowen.txt | 字 / 说文释文 / 反切 / 部首 |
| char_usage | char_usage.txt | 字 / 出处 / 例句 |
| ci | zh_ci.bin（LDIC） | 词 / 释义 |
| allusion | allusion.txt | 典故词 / 拼音 / 释义 / 出处原文 / 出处书篇 |

解析器容错：列数不足时按空缺处理，不抛异常；释义里的 `1. 2.` 编号由切分器剥离（见 §六 义项切分）。

### 2.5 place / place_name（地名时空本体，对齐 CHGIS）

```
place:      id  type(point|area)  lat  lng  geometry(GeoJSON)  tier  tier_source
place_name: place_id  name  type(国名|都邑|郡县|关隘|山川|别名)  dynasty
            year_start  year_end  superior  source
```

- 点（城/关隘/渡口）画坐标；面（政区/诸侯国/郡县）画辖区，中心落治所。
- `tier`：1 遗址实测（必填 `tier_source`）/ 2 考证坐标（谭其骧、CHGIS）/ 3 文献推定。
- **tier 3 只画色块，绝不画点**，避免把「大概在某县」伪装成「精确到百米」。

长安 / 咸阳 / 京兆 是「对齐」，不是「答案」：

```
长安 = 点，西汉都城，渭河南岸（汉长安城遗址，tier1）
咸阳 = 点，秦都，渭河北岸（秦咸阳城遗址，tier1），与长安隔河约 20km
京兆 = 面，京兆尹/京兆府，治所长安（tier2，谭其骧·西汉·京兆尹）
```

### 2.6 era / princes

`era.json` 519 条年号（西汉建元→清末宣统）；`princes.txt` 213 位王公（国 / 称号 / 即位年 / 在位年数 / 末年）。

## 三、引擎契约

### 3.1 人物双引擎

```kotlin
findPersonHits(context, sentence, year)      // 引擎一：全名正则（国号+称号、姓+名）
findPersonAliasHits(context, sentence, year) // 引擎二：无姓称谓（谥称/爵称/排行/省称）
resolvePerson(name, anchor): PersonProfile?  // 别名→本名→同名按生卒过滤→候选
```

- 《左传》高频「桓公 / 楚子 / 郑伯 / 叔向 / 季氏」全靠引擎二。
- 「楚子」不是固定一人：查锚点年份 → `Chronology.timelineFor(year)` → 当年楚王。
- `year == null && anchorState == null` 时**不猜**，只给候选。

人物接口：

```kotlin
profileOf(name): P?
canonical(name): String
lifeSpan(p): String            // 「前551-前479」
ageAt(p, year): String?        // 「72岁（已卒）」/「未生」，带 confidence
relationsInChapter(bookId, chapterId, personId): List<Relation>
eventsInChapter(bookId, chapterId, personId): List<Event>
```

`ageAt` 返回值带置信：

| 置信 | 条件 |
|---|---|
| EXACT | L1 有明确生年 |
| YEAR_ONLY | 只有在位年 / 只有卒年（跨年全年模糊） |
| UNKNOWN | 无生卒 |
| NOT_BORN / DECEASED | 边界明确 |

### 3.2 字词

```kotlin
ChineseDict.preload(ctx); getChar(ctx,ch); getShuowen(ctx,ch); getUsage(ctx,ch)
ChineseDict.wordAt(ctx,text,pos); wordsStartingWith(ctx,ch,limit=14); pinyinOfWord(ctx,word)
AllusionDict.preload(ctx); match(ctx,text): List<Hit>; hitAt(ctx,text,pos): Hit?
```

加载：启动后后台协程预热，四表并行；词表走紧凑二进制（有序数组 + 二分），不建 28 万 Entry 的 HashMap；典故走**首两字**索引（桶缩 10-30 倍）。加载不占主线程。

验收：冷启首次点字 ≤ 300ms，之后 ≤ 80ms。

气泡优先级（同位置多命中）：**典故（已下划线） > 多字词（长度降序 2-5 字） > 单字**。

### 3.3 纪年

保留：`eraOf / eraCandidates / toGregorianYear / princeYear / yearGanzhi / dayGanzhi / ganzhiIndex / resolveDays / phaseDay / yearLabel`。

新增：

```kotlin
anchorFromText(text, knownState): AnchorGuess?      // 扫一段，回候选年代
timelineFor(year): String                            // 同年多政权横向对照
dynastyOf(year): String?
yearsAgo(year): Int                                  // 基准 1950
```

输出样例：

```
前722年 干支辛酉 · 周平王49年 · 鲁隐公元年 · 郑庄公22年 · 齐僖公9年
```

### 3.4 地名消歧

```kotlin
PlaceTimeDict.resolve(name, year): Resolve(hit, others, anchored)
```

规则：按名字拉全部候选 → `year` 过滤（时间区间）→ tier 高优先 → 区间更窄优先 → 点优先于面。
锚点为空：`hit = null, others = 全部`（不猜），Sheet 里列「还有 N 个同名」。
命中后 `detail` 必含：沿革 span + 出处 + 「另有同名 N 处」+ tier3 提示。

## 四、交互契约

### 4.1 半屏 Sheet（所有详情，原文永远在场）

容器：纸白 `#F7F1E6` + 金色 1px 边 + 顶部 4dp 金杠（两端各一粒金点）；最大高 = 屏高 60%；弹起 250ms ease-out，背后茶玻遮罩 40%，阅读页下沉 8dp。

人物 Sheet 顺序（阅读优先，查阅靠后）：

```
① 本段即时信息：本段行为（一句加粗）+ 同场人物（纯文本，可点切）+ 锚定年下年龄/在世
────────────────
② 本书迷你时间轴：首次出场 → 关键事迹 → 末次
────────────────
③ 基础档案：本名/字/号/封号 + 生卒/身份/谱系 + 来源标注
────────────────
④ 还有 N 个同名的 XX ›
```

字词 Sheet：

```
① 拼音 + 部首 + 笔画 + 全义项
② 说文释文 + 反切
③ 古籍用例（≤3 条）
④ 以该字开头的常见词（≤14）
```

纪年 Sheet：`← 前723 ｜ 前722（大号 28sp）｜ 前721 →`，中心干支 + 距今；下列同年各政权纪年；左右滑切年。

**关闭后阅读位置、滚动位置、下划线状态一字不差。这是验收铁律。**

### 4.2 气泡

墨爆：0-100ms 墨色冲击环（半径 60dp）→ 100-200ms 字面亮金 120ms → 200-300ms 纸片 spring 浮现（scale 0.3→1.05→1.0）。

内容：注音 10sp 石青 / 一行释义 14sp 墨色 / 分隔线 / 「共 N 个义项 ›」。
最大宽 = 屏宽 70%；四边不规则撕痕（SVG path）；尖角对准字心；上方越界翻下方；滚动、点空白、翻页立刻消失（0ms）。

### 4.3 空状态 / 错误状态（每类都要有兜底）

| 场景 | 行为 |
|---|---|
| 点了未收录的字 | 气泡显示「此字未收，仅按字形显示」；Sheet 只给部首笔画 |
| 查不到年份 | 气泡「未能定位公元年」；Sheet 提示「请左右滑动选年」 |
| 空地图 / 无该年图层 | 地图保留今址参考层 + 顶部一行「此年暂无疆域图层」 |
| 章节无人物数据 | Sheet 显示「本章未提取到人物，可整本扫描」+ 扫描按钮 |
| 人物未收录 | 气泡「未收录」，不弹空 Sheet |
| 网络/离线（地图瓦片） | 降级缓存瓦片 + 一行提示，不弹错误对话框 |

## 五、地图与 3D 沙盘

### 5.1 2D 地图

Leaflet + 六套朝代基准图层（polygons 带 `year_start/year_end`）：**春秋 / 战国 / 西汉 / 三国 / 唐 / 北宋**。
当前图层由 `ContextAnchor.getYear()` 自动选；同名地名靠锚点年份消歧（春秋的晋 ≠ 战国的晋 ≠ 汉晋）。右下角 3D 切换按钮。

**一张死图 = 错图。这是地图版的人名消歧。**

### 5.2 3D 沙盘 · 绢帛军图

| 项 | 值 |
|---|---|
| 地形底色 | `#1C1A14` 偏暖黑 |
| 山顶受光 | `#B8A88A` 米褐 |
| 谷底阴影 | `#3A4048` 青灰 |
| 光照 | 左上暖烛光，陡坡明暗清晰，背光面极暗 |
| 河流 | 液态金线，宽度随河谷，反光带 2fps 流动 |
| 纹理 | 2px noise overlay（绢帛织物） |
| 顶点 | ≤ 2 万；draw call ≤ 15；内存 ≤ 40MB；帧率 ≥ 50fps |
| 标签 | 所有城市名合并 1 个 CanvasTexture atlas，一次 draw call |

进入动画：0-400ms 金色经纬网浮出 → 400-800ms 地形隆起 → 800-1000ms 雾沉河谷 → 1000-1200ms 棋子落地（80dp 金色涟漪）→ 1200ms 标题/面板淡入。**无转圈、无进度条、无「请等待」。**

顶栏：无背景，半透明墨字 `rgba(26,20,16,0.7)`，3s 无操作淡出；返回 = 地形下降回 2D。
底栏：深茶色毛玻璃，3s 无操作缩成 4dp 金线；▶ 暖金三角，自动推演时 240° 虚线光轨 6s 一圈；进度 = 蚕丝金线 + 朱砂圆点浮线上 2dp 可拖；阶段 = 金线下铜点/篆章。

棋子：底部发光圆环（地表上方 3 单位）+ 四面体主体（半透明自发光）+ 顶部光柱（呼吸 1200ms）+ 地面圆形暗影；尺寸 ∝ 兵力；士气动摇微颤 0.5°，溃散碎 6-8 片光屑 800ms。
颜色按外交：己方金 / 盟友铜 / 敌方灰青 / 中立白。

箭头（兵锋）：渐粗渐细金色光带 + 内部 2-3 粒流动金粒子 + 墨迹飞白尖锋，贴地起伏。
意图样式：进军实线 / 急行军虚线快闪 / 包抄弧线 / 撤退末端散开 / 设伏棋子 0.3 透明 + 地面脉冲红点。

交战：0-200ms 朱砂冲击环（120dp）→ 200-600ms 两棋子互冲火花 → 600-800ms 胜方 1.5× 增亮、败方褪色后撤 + 竖排毛笔战报 → 留墨色方钉。

剧场模式：全屏无 UI，每回合 1.2s + 0.3s 淡黑，交战自动推近 40%（0.6s），vignette；结束镜头拉远（1.5s，dist 300→560）→ 金色沙盘定格 2s → 战报。

### 5.3 高程数据

首版只覆盖关中/中原（104°E-122°E, 24°N-42°N），512×512 灰度 PNG，R 通道 0-255 → 0-3000m，约 200KB。
经纬度→地形坐标用墨卡托，废弃 `1度≈5.4/6.4单位` 的线性常量。
验收：长安在渭河谷地、洛阳在伊洛盆地、太行山肉眼可辨。

## 六、通用战役推演引擎

**数据驱动铁律：引擎不内置任何一场战役。** 战役 = JSON + 高度图 PNG；换仗只换数据，不换代码。

### 6.1 战役 JSON

```json
{
  "id": "gaixia", "title": "垓下之战", "era": "前202",
  "context": "……",
  "terrainFocus": { "center": [117.2, 33.5], "radius": 80 },
  "heightMap": "gaixia.png",
  "duration": 30,
  "victory": { "type": "annihilate", "target": "xiangyu", "side": "han" },
  "sides": [ {"id":"chu","name":"楚","color":"#C23B2E"}, {"id":"han","name":"汉","color":"#3C5C6E"} ],
  "diplomacy": [ {"a":"chu","b":"han","relation":"hostile"} ],
  "armies": [ { "id":"xiangyu","name":"项羽","side":"chu","initialPos":[117.19,33.52],
               "strength":10,"type":"elite","fatigue":2,"morale":"wavering",
               "intent":"escape","target":[117.5,33.8] } ],
  "events": [ {"trigger":{"turn":5},"action":"moraleChange","target":"xiangyu",
               "value":"wavering","reason":"四面楚歌"} ],
  "phases": []
}
```

`diplomacy.relation`：hostile / allied / neutral。`victory.type`：annihilate / capture / defend / escape / reachPoint / rout / compound。
`phases` 填了 = 预设路线回放；不填 = 纯推演。

### 6.2 地形分析（加载时预计算一次）

`heightMap / slope / traversable / riverMask / fords / chokePoints / highGround / visibility / aStar / elevationProfile`

可通行：坡度 ≤45° 步兵，≤30° 马，≤15° 辎重；河流不可直穿，必须走渡口。
关隘：相邻两格坡度 >40° 且之间平地块 ≤3。
渡口：河流连续段中河宽 <2 格、两侧可通行平地。

### 6.3 寻路 A*

128×128 网格，二叉堆 + 欧几里得启发。
`代价 = 基础距离 × (1 + slope/45) × 路况系数`（平地 1.0 / 丘陵 1.3 / 山地 1.8）。
单次上限 8000 节点，目标 < 8ms。`flankPath(from,to,enemyPos)` 绕开敌方视线。

### 6.4 意图（15 条，命中即返回）

| # | 条件 | 意图 |
|---|---|---|
| 1 | 相邻格有敌 | fight 应战 |
| 2 | morale = broken | rout 溃逃（远离所有敌） |
| 3 | 四向有敌 | breakout 突围（敌最弱方向） |
| 4 | 在关隘 + 敌距<5 + 未暴露 | ambush 设伏（首击 2×） |
| 5 | 补给≤0 连续 3 回合 | retreat 撤退 |
| 6 | 制高点 + 敌距<3 | hold 据守（防 1.3×） |
| 7 | 兵力 3× 最近敌 + 敌距<10 | advance 进军 |
| 8 | 盟友相邻且被攻击 | support 支援 |
| 9 | 关隘空 + 敌距>5 | seize 抢占 |
| 10 | 目标已到达 | hold |
| 11 | 目标被敌占 | advance |
| 12 | escape + 出口 ≤3 格 | rush 急行军 |
| 13 | 渡口在 3 格内且路径需渡河 | cross 渡河 |
| 14 | 当前意图未完成 | continue |
| 15 | 均不触发 | hold |

输出：`{intent, target, path, reason, animation:{type: solid|dashed|curved|scatter}}`。

### 6.5 战斗 / 士气 / 回合

```
攻方攻击力 = strength × (伏击?2:1) × (骑vs步?1.3:1)
守方防御力 = strength × (制高?1.5:1) × (据守?1.3:1)
伤亡比 = 守² / (攻² + 守²)         // 兰彻斯特平方律简化
败方后撤 1 格 + 士气降一级，单次 ≤300ms
```

士气链：high → steady → wavering → broken（broken 即消失）。
疲劳 0-5：每日 + 行军距离/日行上限；≥4 有 0.7 概率降士气；补给断 3 回合加速。
首战胜/灭敌升一级；盟友相邻恢复 +50%。

每回合顺序：按速度排序 → 情报（视野 + 模糊半径）→ 意图 → A* 移动 → 遭遇 → 状态 → 脚本事件 → 胜利判定（每回合查）。
一回合 8 军 < 50ms。

### 6.6 验收战役（难度递增）

| 战役 | 验证 | 回合 | 军队 |
|---|---|---|---|
| 垓下 | 包围、突围、士气崩溃、四面楚歌 | 30 | 6 |
| 长平 | 对峙、断粮、包围合拢 | 60 | 8 |
| 三家分晋 | 三方混战 + 疆域边界 | 20 | 3 |

## 七、画板（墨板 InkSlate）

### 7.1 范围

保留：画笔 · 直线 · 箭头 · 矩形 · 圆 · 文字 · 橡皮 · 撤销/重做 · 图层（底图 + 墨迹）· PNG/SVG 导出。
砍掉：抓手 · 菱形 · 插图片 · 激光笔 · 协作 · 填充色 · 透明度 · 粗糙度 · 字体选择器 · 字号多档 · 元素锁定。

工具栏（全露出，无「⋯更多」）：
顶部 `✏️ 画笔 | 📏 直线 | ➡️ 箭头 | ⬜ 矩形 | ⭕ 圆 | 🔤 文字 | 🧹 橡皮`
底部 `六色圆点 | 线宽 | ↩ 撤销 | ↪ 重做 | 图层 | 导出`
六色：朱砂 `#C23B2E` · 墨灰 `#1A1410` · 花青 `#3A5C6C` · 藤黄 `#D4A54A` · 暖金 `#8B6914` · 石青 `#4E7E6E`。

### 7.2 onDraw（性能第一铁律）

笔画完成即「硬化」为 `Path` + `Paint` 缓存，`onDraw` 只遍历 `drawPath`，**不在 onDraw 里 new 任何东西**。

```kotlin
bakedPaths.forEach { (path, paint) -> canvas.drawPath(path, paint) }
```

### 7.3 橡皮

- 空间索引：画布 64×64 网格，每格存经过的笔画 id；橡皮只查覆盖格，命中再精算。
- 命中不是整笔删，是**截断成两笔**，保留未擦两端。
- 单次擦除 ≤ 50ms。

### 7.4 笔锋

- 有笔：`线宽 = base × (0.3 + pressure × 0.7)`。
- 无笔：按速度反推，快扫飞白、缓行顿笔：
  `w = base × (0.5 + 0.5 / (1 + speed × 0.3))`。
- 压感从 `MotionEvent.getPressure()` 经 Bridge 传前端。

### 7.5 撤销 / 落盘

- 撤销 = 倒放：最后一笔 180ms 从末端向起点收缩到零，不是瞬间消失。
- 双击画布 = 撤销（肌肉记忆）。
- 撤销栈 300 笔；`ACTION_UP` 后 2s 防抖落盘，防 IO 暴击。
- 存储：`InkPage(bookId, chapterIndex, pageIndex, strokesJson, savedAt)`，按页绑定；翻页自动存旧页、载新页。

### 7.6 WebView

- Application 启动后台预热一个 WebView 单例；`PaintActivity` 先 `take()`，拿不到再 new。
- 首帧只加载空白画布壳（≤50KB），Excalidraw 主库异步 `import()`。
- 退出 `removeView` 而非 `destroy`，全局复用同一实例。
- 验收：第二次打开画板 ≤ 800ms 可见。

### 7.7 与阅读打通

Annotation 模式传：`bgImage` 截图 + 章节名 + 当前页正文纯文本。
导出底部自动附注：`《左传·隐公元年》第 3 页批注`。
前端加落文主题：画布 `#F7F1E6`，默认笔色朱砂/墨灰/花青/藤黄，工具栏暖金+古铜。
导出支持 `saveSvg(svgString)`（矢量，放大不糊）。

## 九、边界与解法（每一条都必须落地，不能悬空）

| # | 边界 | 解法 |
|---|---|---|
| 1 | 手机上不可能跑 Node.js + Ubuntu 容器 | **纯 JS 引擎内嵌 WebView**：`engine/*.js` 写成无 import 的 UMD，挂 `window.LWEngine`，手机零进程、零 WebSocket。`server.js` 只作桌面调试可选入口。离线优先，断网不降级也不影响。 |
| 2 | SRTM/30m DEM 无法随包内置 | Mapzen Terrarium 公开瓦片离线切片成局部 512×512 PNG（约 200KB/场）；拿不到时用「控制点 + 双线性插值」，并在 `tier_source` 标 `推定`，绝不假称实测。 |
| 3 | 半屏 Sheet 嵌 Leaflet 反复开关会内存抖动 | 单例 WebView + 懒加载 + `removeView` 复用；离开可见区即 `dispose()` geometry/material/texture。 |
| 4 | 字词/典故在数据层没有 schema | §2.4 补齐五表定义与解析器容错（列数不足按空缺，不抛异常）。 |
| 5 | person_chapter_event 没数据来源 | 双来源：RelationExtractor 段内共现灌粗稿 + §2.3 手录 JSON；两者同一张表。 |
| 6 | 点不认识的字 / 查不到年 / 空地图 / 无人物章节 | §4.3 逐类兜底文案与行为，全部实现。 |
| 7 | CBDB 8.9 万条脏数据 | 运行时按生卒/来源判 L1/L2/L3；L3 只进候选池、不默认命中；卡片底部标来源；同名列 `(canonical,dynasty,state,identity)` 四维分组。 |
| 8 | 爵称（楚子/齐侯）无锚点时查不到人 | 章标题能猜出年份 → 当年君主；完全无锚点 → 取该国首位君主兜底，并标「未锚定」。 |
| 9 | 多音词 CEDICT 首选读音与文言不符（朝阳 cháo/zhāo） | 加语境修正表（词 + 邻字/书名语境 → 读音），只覆盖已知偏差，不全局改。 |
| 10 | 关系图缓存 key 会随阅读位置变 | key 改成 `书 + 章节 id`（不是正文首尾散列），整本/本章各一份。 |
| 11 | 5-10MB 中文字体不能进包 | 只打包首屏 2500 字子集（≤200KB woff2），其余回落系统 serif；不做 FOIT。 |
| 12 | 包体已 91MB（45 部书 32MB + 词表 41MB） | 高程图按场切片（200KB×N）；词表只留 LDIC bin；书按需增量导入，不再塞全本。 |
| 13 | 本机 2 核 4G 编译 OOM | GitHub Actions 唯一编译路径；每次 clean + JDK17 全量重编。 |
| 14 | 编译通过 ≠ 功能可用 | 每轮交付前：先单项自检、再整体自检；未真机验证的必须明说「未验证」。 |
