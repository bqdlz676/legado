- 既有 `onPause() → searchViewModel.pause()`、`onResume() → searchViewModel.resume()`（`InkShelfFragment.kt:210-217`）只切 `SearchModel.workingState` 布尔位；`detachOverlay()` 复用同一 `pause()` 出口暂停模型，不新建第二套暂停语义。

## 五、二阶 / 三阶影响推演

### 5.1 释放收集对热路径的影响

- 关闭浮层取消两路 Room DAO 流观察者：历史 / 热门词表数据量为搜索日志小表，重开时重新订阅 Room 流并回放当前快照，单次订阅 IO 开销可忽略；重开首帧可能短暂沿用上一次 `_uiState` 内缓存的 history / hot，待新 binder 首帧回放后收敛，与既有冷启 Warm Start 口径一致，B 级未上机测量帧率。
- 重开幂等：`attach()` 仅在 `hotBinder == null` 时重建收集；若未走过 detach 就再次打开，不会起第二路重复订阅。
- 在途检索：关闭浮层只 `pause()` 模型、不取消在途协程，与既有 `onPause` 口径一致；若关闭时正处翻页在途（`LoadingMore`），分页态保留在 `_uiState`，重开 `resume()` 后继续收口。未做「关闭即取消在途请求」的更强语义，避免改变既有 `pause/resume` 约定。
- 作用域隔离：detach 不碰 `viewModelScope`，书架书籍流 `flowJob`（`InkShelfFragment.kt:142-167`）、其它 Tab 的 VM 与 Fragment 不受影响；VM 存活期内缓存态保留，`onCleared()`（`InkSearchViewModel.kt:184-187`）仍按既有路径取消作用域并 `close()` 模型。

### 5.2 删死代码对外部引用的影响

- 引用穷举：删除符号在 `app/src` 内的命中仅三处——`ShelfSearch.kt` 自身死链、`ShelfSearchOutcomeTest.kt`、`bookshelf/search/ShelfSearchContractTest.kt`，外加 `ShelfSearchD25Test.kt` 的 filter 用例；清剿后 grep 零残留（仅 `ShelfSearch.kt:15-16` 文件头留档注释提及旧符号名）。
- 同名异物已排除：`ui.main.search.SearchField`（`BOOK_TITLE/AUTHOR/CONTENT`）与已删 bookshelf 包私有 `SearchField` 同名但分属两包，search 包测试 `SearchModelsTest` / `SearchMatcherTest` 引用的是前者，不受影响；仓内其它 `searchBooks` 命中均为别处局部变量 / Room 实体 / web 前端资产，与已删纯函数无关。
- 三阶：旧契约文件删除后，`bookshelf/search/` 目录仅余 `SearchOverlayParams.kt`（外观参数单源）与其测试；后续若再立书架本地检索需求，应直接复用 search 栈，不要在本目录重建第二套投影。
