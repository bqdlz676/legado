## 二、缺陷原文与根因

- 补丁前换行分支原文（`data_scripts/check-symbol-existence.py` 旧版 :612-617）：

```
if c == '\n':
    if state in ('code', 'line'):
        new_line()
    else:
        eligible.append(_decl_stack_ok(stack))
    i += 1; continue
```

- 根因：line 态在换行时只调了 `new_line()` 记行首快照，没有把 `state` 从 `line` 复位回 `code`。下一行真实代码逐字符进入 `if state == 'line': i += 1; continue` 分支被整段吞掉，`{` `}` 既不压栈也不弹栈；函数体开帧留在栈上，行注释之后的顶层声明行 eligibility 被误判为 False，被当成函数体局部影子声明。
- 二阶推演：该缺陷只收窄「算声明位」的行集，不改索引建表、不改 NODEF/ARITY 调用计数与退出码口径；帧栈错配方向是「真顶层被误判局部」，即 PACKAGE 层假红，不会把局部影子声明放成包级（那是相反方向，由既有 t13/t14 通路锁着）。
- 三阶推演：行注释换行后若不复位，同一行内后续的 `//` 二次进入、块注释开括号 `/` 等字符也全被 line 态吞掉；复位回 code 后这些字符回到正常分派，行为与无注释源码一致。

## 三、状态机穷举清单（逐态核对漏退出 / 早退）

- line 行注释：漏退出，本单主修。换行后必须显式 `state = 'code'`；旧版留在 line 态吞后续代码行。证据 `data_scripts/check-symbol-existence.py:613-624`。

- dq 双引号串：转义 `\` 跳两字符，退出认 `"`；模板插值 `${...}` 内嵌的嵌套引号 / 花括号未做模板层解析（见「新发现问题」第 1 条，待裁低概率边界）。证据 `data_scripts/check-symbol-existence.py:639-644`。
- char 字符字面量：转义 `\` 跳两字符，退出认 `'`；字符字面量不含换行，无跨态泄漏。证据 `data_scripts/check-symbol-existence.py:649-654`。

## 七、自查反例与改坏推演

- 反例一（复位时机错过换行）：若只在进入 line 态后下次见 `//` 或见代码字符时复位，函数体开帧在整段注释行内仍悬空；本单把复位挂在换行分支，行注释结束的边界就是换行字符，边界最确定。
- 反例二（把局部 fun 一起放成顶层，修反方向）：例 b 锁的就是这条——行注释后真局部影子 fun 仍在 `block` 帧内，`_decl_stack_ok` 判 False，PACKAGE 保持红；若补丁把栈上局部帧误清，例 b 会转绿，自测即断。
- 反例三（块注释深度计数误减到负）：未闭合块注释到 EOF 时 `block_depth` 不归零也不影响退出码；计数只在注释态内增减，code 态开注释时强制重置为 1，不会把上一段注释的深度带进下一段。
- 反例四（三引号串被单个 `"` 提前闭合）：tq 态只认 `"""`，例 d 串内的 `//` 与 `{` 均不参与分派；旧版口径本就如此，本单未动 tq 分支，避免改出回归。
- 二阶影响：`_declares_name` 生产唯一调用点是 PACKAGE 层声明位兜底（`data_scripts/check-symbol-existence.py:765`），NODEF/ARITY 配平链路不经此扫描器；帧栈判定只收窄「算声明位」的行集，不改索引建表与调用计数。
- 三阶影响：新增夹具全部仓外 tempfile 自删，仓内 `data_scripts/fixtures/` 未新增持久夹具；分级表 g63 仍 blocking、compensation null，本单未把存量债降级成 audit 红墙，也未放宽任何既有白名单。
