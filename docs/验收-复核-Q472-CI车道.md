## 三、改坏推演（本单改动可能把什么改坏）

- 若白名单漏收某产品子路径：docs-only 误判 → `build-shard` 跳过、`lane-summary` success，云端表现为 Verify 绿但本轮无 APK 产物，对账侧可能 MISSING；反方向把 docs 误判码变只会白跑长构建，不红。回放 16 条正反例未发现漏收。
- 若 classify 内嵌 Python 在云端抛异常：`classify-paths` job 红，`build-shard` / `lane-summary` 随 needs 失败传播，不产出放行结论；不会出现「classify 崩了却默认出包」。
- 若 `--changed` 解析器在 git 异常时返回非空错误面：可能把存量文件拉进改动面判红；实测异常路径返回 `[]`，空集中性放行，该风险被兜底。
- 若未来把 `--changed` 接入门禁而 git 不可用：EMPTY 中性 rc=0 可能掩盖存量回归——这是中性分支的固有取舍，接入时需在闸口注明 EMPTY 不算全仓 PASS（沿用脚本 `:885` 口径）。
- 二阶影响：package 侧 lane-summary 不挂 static-gate，若上游 verify 闸门被绕过（直接手动 dispatch 到 package），静态报告闸不在 package 复跑；当前 `workflow_run` 只认 verify success，路径封闭。
