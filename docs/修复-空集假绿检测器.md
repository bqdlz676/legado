# 修复-空集假绿检测器

主对象：P32 空集假绿检测器。锚点卡：docs/锚点/P32-空集假绿检测器.md

## 一、任务与产物

本单只做一件事：新建检测器 `data_scripts/check-vacuous-pass.py`，专找"空集即 PASS"的假绿结构——
门禁拿到的待检目标集合为空（没传报告 / 没检出改动 / 队列无行），空集分支却直接 `return 0`
甚至打印 PASS，一个对象都没验，结论却是绿的。

- 产物：`data_scripts/check-vacuous-pass.py`（纯标准库，无第三方依赖）
- 退出码：`0` = 无未豁免命中（PASS）；`1` = 有空集假绿（FAIL）；`2` = 用法错（argparse 未识别参数）
- 扫描范围：`data_scripts/check-*.py`，不含本脚本自身
- 未接线 `rule-gate.sh`：按任务要求，接线由总控统一做，本单不碰总控门禁清单

## 二、判据（窄，防假红）

命中须同时满足：

1. 条件是空集合 / 空列表判断之一：`if not <变量>:`、`if len(<变量>) == 0:`、`if len(<变量>) < 1:`；
2. 该分支之后 3 行内（同缩进体内）出现裸 `return 0`（排除 `return 0 if ... else 1` 三态表达式）；
3. 文案分流：分支体出现 `PASS` / `无待检` / `干净` 字样 → 判"空集即 PASS"候选；只出现 `WARN` / `INFO`
   → 空集即 WARN，没有把空集说成合规，不入 FAIL，只登记豁免；
4. 排除存在性 / 字符串 / 正则谓词：`p.exists()`、`os.path.isfile/isdir`、`line.startswith/endswith/strip`、
   `re.search/match` 等——它们判的是文件在不在、文本长什么样，不是空集合；
5. 排除结论累加器（`bad`/`problems`/`fails`/`warns`/`missing` 等）：其为空表示"零违规"，是验过的真绿，
   与 `files`/`commits`/`shas` 这种"待检目标"性质相反。

豁免表 `ALLOWLIST` 键 = `(文件相对路径, 变量名, 分支代码块 sha256 前 12 位)`：代码块 = if 条件行 +
分支体行，代码不变则哈希稳定，代码一改哈希即变、豁免自动失效重回审查。不允许按文件名前缀整段豁免
（前缀可被改名伪造，沿用 ㊼ 豁免身份化教训）。

豁免分类：

- diff 型门禁（onboarding:184 / report-fields:97 / dependency-symbols:104）：待检集合来自 git 改动面，
  本轮无改动 = 没有需要核验的对象，空集是真实干净状态，不是接线漏传。
- 区间 / 历史型门禁（commit-trailer:74 / push-track:71 / commit-split:83）：区间内无提交 = 干净树或
  零提交边缘；判的是待推 commit 合规性，空区间不报红属真实状态，上游故障已在各自分支 `return 1` 兜底。

  下游另有时间窗判定或冻结侧 `return 1` 兜底，未把空集表述为合规通过。

## 六、二阶三阶影响与边界

- 二阶影响：本检测器一旦由总控接入 `rule-gate.sh`，未豁免的空集 PASS 分支会让门禁 FAIL；
  修法方向是"空集时 `return 1` 或 `return 2` 明示无可检对象"，不应靠把命中加进豁免表蒙混。
- 三阶影响：豁免按分支块哈希锚定，被豁免分支改一行代码哈希即变，豁免自动失效、重回 FAIL/WARN 桶——
  这是有意设计，防止豁免随代码漂移悄悄复活；代价是改注释也会让豁免失配，重审时重算哈希登记即可。
- 边界兜底：二进制 / 乱码文件按 `errors='ignore'` 读入；三态 `return 0 if ... else 1` 不算裸 `return 0`；
  分支体以缩进回退判定结束，跨行函数体不误抓；夹具目录不与真报告混命名空间。
- 已知盲区：静态文本扫描不执行代码，无法识别"集合在别处被填成空"的间接形态；
  谓词排除表按方法名 / 标量名匹配，新造标量名若漏进 `SCALAR_NAMES` 可能误判，
  误判时优先补排除词，不要放宽空集判据。
- 认知成本：新增 1 个脚本、1 张哈希锚定豁免表、2 套判词词表；模式与排除理由都写在脚本 docstring 与注释里，
  接手人无需跨文件上下文即可改判据。
