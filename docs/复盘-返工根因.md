## 1. 编译遮蔽（一条根因错，被成片派生错淹没）

### 1.1 实例（4 条）

- **C-1** `548e8ba` — `app/src/main/java/io/legado/app/ui/map/crossing/model/Enums.kt:7`：KDoc 行内写 `` `assets/map/campaigns/*.json` ``，`*.json` 的 `/*` 触发嵌套块注释未闭合，commit message 记为「245 条级联编译错根因」；修复仅 +1/-1（改写成「`campaigns/` 目录下既有 JSON」）。
- **C-2** `e7002d1`（窗口外旁证，当前文件在库）— `app/src/test/java/io/legado/app/help/bubble/PersonProfileWiringTest.kt:190-191`：`assertNotNull(bubble)` 是普通函数调用、不触发 Kotlin 智能转换，对可空 `BubbleContent?` 直接取成员报可空接收者；单条错使测试源集整体编不过，8 次 CI run 全 failure、出包步骤 skipped（`docs/落文-进度续传快照.md:77,115`）。当前 `:191` 为 `bubble!!.candidates.size` 并带说明注释。
- **C-3** 修红波次接力：`docs/CI日志-da571c9-错误清单.txt` 273 行 → `6e92306`（其余包 13 文件 64 错）→ `docs/CI日志-54bd363-错误清单.txt` 79 行 → `54bd363`（config 包）→ `8e15c72`/`2ac3bde`（二轮）→ `f956cdf`（三轮 29 文件 54 错）→ `f78bec8`（末 5 条）。每波只能看见当前包报错，前一波根因被同形态 Unresolved/上下文错盖住。
- **C-4** `74508c5` — `app/src/test/java/io/legado/app/ui/map/replay/ReplayTerrainTest.kt:212`：裸 `null` 同时匹配 `IntArray?` / `ByteArray?` 两个重载，编译器报「重载歧义」而非「null 缺类型」，根因被候选列表淹没；修法是显式 `val emptyData: IntArray? = null`。

### 1.2 为什么会反复付账（机制层）

1. **本地禁编译**（红线：沙箱无 kotlinc/gradle），错误只能等云端 CI 全量 clean 编译一次性吐回；Kotlin 在词法/注释未配平时，会对同文件下游产生成片 Unresolved、Composable 上下文错，单条根因淹没在噪声里。
2. **修红按"包"切单**：铁律 57「一条缺陷一单」落地成了一包一单，跨包级联错在单包里看不见，只能 push → 等 CI → 再分波，每波一个 CI 周期。
3. **主源集与测试源集同任务编译**：主源集错会把测试错一并带出，日志不区分根因错与派生错，派单按文件平推而非按根因归并。

### 1.3 预防手段（可执行，附失效条件）

- **建议新铁律 78**（规则条目）：CI 报错归并到唯一根因行——每个修红单必须先把报错按「词法/语法 → API 存在性 → 签名咬合 → 挂起上下文 → 运行期」光谱分级归并，报告贴归并表，禁止按文件逐条平推。
  - 失效条件：同一行同时报 Unresolved + 上下文错等跨类型耦合时，分级只能聚类不能定根因；Kotlin 版本升级后错误文本格式漂移，既有匹配词条会失配。
- **脚本/CI 门禁**：新增 `data_scripts/triage-compile-errors.sh`，吃 CI 错误清单 txt，按文件聚簇 + 按错误类型聚类，输出「根因行候选 ≤3」；CI 日志落档后、派单前强制先过该脚本。
  - 失效条件：脚本只能做字符串聚类，跨文件级联（A 文件缺导入导致 B 文件 Unresolved）仍需人判；错误清单被 CI 截断时聚类样本不全。
- **派单模板字段**：任务书新增「根因行（文件:行）／同形态错条数／已排除的派生错」三字段，缺根因行不许派。
  - 失效条件：执行代理为填表把派生错判成根因；需验收代理独立复核归并表，不能只看字段填没填。

## 2. 口径错（实现语义与规格 / 数据资产口径不符，编译过也会错）

### 2.1 实例（4 条）

- **M-1** `da571c9` — `app/src/main/java/io/legado/app/ui/map/crossing/engine/VictoryChecker.kt:108-118`（ROUT 分支）：旧实现 `corps.filter { it.sideId != def.side && it.combatReady() }`，把盟友计入敌军，且以「无可战」代替「士气全 BROKEN」；规格 §四 rout 口径修正为「非胜利方、非盟友、仍可作战，且 `enemies.all { it.morale == Morale.BROKEN }`」。
- **M-2** `ea70156` — `VictoryChecker.kt:106`：COMPOUND 分支 `hit.all()` 无参重载不存在，AND 谓词悬空；修为 `hit.all { it }`，注释写明「`{ it }` 即每项均为 true，与 AND 语义一致」。
- **M-3** `7e6b491` / `841c78c` — `app/src/main/java/io/legado/app/help/sim/EventTrigger.kt` `when (ev.action)`：清单 B15 实证 13 种 JSON `action` 仅 5 种有分支，6 种零消费（`fireAttack`/`siegeEngine`/`breakthrough`/`navalRout`/`defendFall`/`feignedRetreat`），7 种事件/意图语义混用（`ambush`/`flank`/`rout`/`capture`/`annihilate`/`retreat`/`escape`）；`841c78c` 用三自检脚本实证「13 动作仅 5 有分支」，`7e6b491` 补 17 种映射但仅静态通过。
- **M-4** 清单 B2（open，未修）— `app/src/main/java/io/legado/app/ui/map/crossing/terrain/TerrainCost.kt:30-36,57-60`：天候系数符号反转（坏天气提速），路况系数未进速度预算，且自有测试 `TerrainCostTest.kt:55-59` 断言方向反。

### 2.2 为什么会反复付账（机制层）

1. **口径三处各写一遍**：规格切片、JSON 数据资产、测试断言各自表述，实现侧没有唯一口径出口；子代理只读本单切片，看不到规格 §四全表与枚举全集。
2. **枚举状态理解不一致**：盟友 / 投降 / 被歼 / BROKEN 等状态没有状态机对照表，测试按规格写、实现按直觉写，两边对"谁算敌军"理解不同。
3. **字符串位无注册表**：`action` / `VictoryType` 这类字符串位没有 sealed 枚举或注册表，JSON 串与代码 `when` 分支靠 grep 对，新增动作必然空转。

### 2.3 预防手段（可执行，附失效条件）

- **建议新铁律 79**（规则条目）：枚举 / 动作 / 胜利条件等口径必须有单一注册表（sealed enum 或顶层常量对象），JSON 字符串位与代码分支双向可枚举核对；禁止在 `when` 里散落裸字符串。
  - 失效条件：动作由外部规则 / 组合句式动态生成时，注册表列不全；别名、同义词归一缺失会造成静态差集误报。
- **脚本/CI 门禁**：扩展 `data_scripts/selfcheck-flow.py`：登记 JSON 出现的 `action` / `VictoryType` 集合 vs 代码 `when` 分支集合，差集非空即 FAIL（现脚本只查 `HalfSheetKind` 两态，未覆盖 action 位）。
  - 失效条件：字符串多段拼接、运行时查表的动作抓不到；脚本读的是源码快照，数据资产后补而代码未跟时差集会滞后。
- **派单模板字段**：口径类单子附「规格原句行号 + 枚举状态对照表 + 三态用例（正向达成 / 未达成续推 / 清空或投降边界）」。
  - 失效条件：规格原句本身含糊（未列盟友态、未定义投降与被歼区别），对照表只能补出实现方理解，仍需验收方回原文复核。

### 9.2 最重要的一条机制结论

> **在「本地禁编译、CI 是唯一编译器」的流水线里，测试源集是一道比主源集更脆弱的闸门：任何一条测试侧错（可空接收者 / 缺位函数 / 签名写法）都会阻断整轮测试编译，并级联跳过出包；而「测试先行」若不与「实现同批」绑定，缺位函数会持续把 CI 钉红，红又反过来阻断实现单派单——形成自锁。**

解开自锁的关键不是加快逐条修红，而是两层结构性动作：① 派单层把「测试断言 ↔ 实现签名」绑成同一交付单元（铁律 80 / 85 建议）；② CI 错误归并时把测试源集错单独成组，优先于主源集编译错处理（铁律 78 建议）。本轮 8 连红证明：一条测试侧小错的机会成本是 8 个 CI 周期 + 零出包，远高于主源集同类错。

## 10. 二阶三阶影响（整体推演）

- **直接效果**：八类根因各自修掉对应错；本轮修红把错误从 273 条收窄到 11 条测试源集错，主源集错清零（A1–A12 记录在案），测试源集能否编译转绿仍待云端 CI 实证。
- **二阶连带**：
  - 修红按包切单导致同一文件跨三轮返修（0.2 节 17 个文件 ≥2 次），每次返修都带一份独立修复文档，文档与代码双份维护；
  - 静态自检脚本数量增长（`selfcheck-data.py` / `selfcheck-path.sh` / `selfcheck-flow.py` / `check-report.sh`），脚本口径与编译器口径并存，调度层需要同时维护「脚本绿」和「CI 绿」两套事实；
  - 测试先行单挂 A8/A9/A10/A11/A12 编号在清单跟踪，编号体系膨胀，清单本身成为需要回填维护的契约（D-4 漂移风险）。
- **三阶后果**：
  - 若不把测试与实现绑成交付单元，后续每开一个新域都会重演「测试红 → 锁死派单 → 总控兜底补函数」的循环，CI 周期成本随域数线性增长；
  - 旧栈 11.9 万行留存期内，新代理持续面临「读旧代码当参考」的诱惑，贴皮与历史包袱两类会反复付账，直到对应 Compose 页成批落地；
  - 验收级别若不冻结，低级别 PASS 会被下游当成就绪依据，批次排期建立在虚高结论上，返工从编码阶段后移到组装阶段，成本更高。

## 11. 反例与边界（本报告自身的否证）

- **分类边界**：一条实例可能同时命中两类（如 `7e6b491` 既是口径错 M-3，又是边界加固 B-2；`75fd638` 既是契约漂移 D-1，又是测试先行 T-1）。本报告按主根因归一类，旁注另一类；换一个复盘者可能聚类口径不同。
- **窗口边界**：60 窗口外的 `819ce86`、`8af78bc` 仅作旁证，改动面未逐一 `git show` 核；更早的 53 失败修复（`d2c85a9` 等四包）不在本窗口统计内。
- **关键词分类风险**：修复类提交按 message 关键词（修CI / fix( / Revert / 补修 / 二轮 / 三轮等）初筛，再人工复核；docs-only 提交与重构提交未计入修复类，可能漏掉以「feat」名义提交的返工。
- **证据级别边界**：本报告所有「编译通过 / 测试绿 / 脚本全绿」均沿用备案、流水、修复文档的静态口径；本轮未跑 gradle / kotlinc / 单测，未复核 CI API，不能视为本轮复跑结论。
- **反例检验**：若「测试实现同批交付」被强制执行，在规格要求测试先行锚定的域会与现有口径冲突（8.3 失效条件）；因此该规则必须保留「挂编号跟踪实现缺位」的例外通道，不能写成绝对禁令。

## 12. 认知成本

- **新增概念**：八类聚簇名（编译遮蔽 / 口径错 / 契约漂移 / 贴皮 / 验收放水 / 历史包袱 / 边界缺失 / 测试先行实现缺位）与铁律 65 原七类相比，新增「测试先行实现缺位」一类；接手人需知道该类与「契约漂移」的分界：契约漂移是两侧签名已存在但不一致，测试先行缺位是实现侧零命中。

- **简化建议**：24 份修复文档与 21 份验收 / 复核报告同处 `docs/`，命名前缀已区分（`修复-` / `验收-` / `复核-`），本报告不再新建索引；新规则落条时编号从总纲现行最大序号之后接续（现行已见至铁律 77，见 `docs/机制-总控必读.md:3`）。
