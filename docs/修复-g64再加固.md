## 一、旧版根因（验收实测两条假通路）

- 通路一 漏判（先声明后赋值）：形态 `var src: String? = null` 在 A 行、`src = File(...).readText()` 在 B 行。旧 `extract_readtext_bindings` 只扫 val/var 声明头那一条语句的 RHS；A 行 RHS 是 null，绑定不登记；B 行裸赋值不在声明头正则覆盖范围内，对 src 的整文件 contains 断言新旧两版都 0 命中。验收方在新旧两版上复现本夹具均 PASS（漏判）。
- 通路二 误放行（串内白名单字样）：本绑定 RHS 内部出现 `replace("filterNot", "")` 这类字符串字面量时，旧白名单判断 `any(mark in expr ...)` 是裸子串包含，串内的 `filterNot` 被当成真 filterNot 调用而放行。验收方复现：该夹具旧版 0 命中（误放行）。

## 二、改法（不造兼容层）

- 字符串掩码 `_mask_strings`（`data_scripts/check-test-assert-truth.py:209`）：复用既有 `_scan_string_ranges`（`data_scripts/check-test-assert-truth.py:154`）先扫双引号串、字符字面量、三引号串区间，把区间内字符置空格（换行保留），生成与 code 等长、下标对齐的掩码副本；串内字样不参与任何代码面判定。
- 截面判断 `_slice_has`（`data_scripts/check-test-assert-truth.py:225`）：mark 只在掩码副本对齐截面上子串命中；readText 判定同走掩码面，串内写着 `"readText"` 也不再误登记。
- 跨语句归并 `extract_readtext_bindings`（`data_scripts/check-test-assert-truth.py:413`）：首遍收集声明表 declared（名字 → 声明行号 / 是否 var）；二遍只对 var 名字找裸赋值 `name = ...`（lookbehind 排除标识符拼接，`(?!=)` 排除 `==`，命中点落在字符串区间内跳过），RHS 经 `_rhs_until_boundary`（`data_scripts/check-test-assert-truth.py:290`）按语句收口；RHS 代码面带 readText 且无白名单即并入同一绑定，行号回指最初声明行。val 不进二遍（不可重新赋值）。
- 旧版裸子串白名单判断已随重构移除，不留旧格式兼容层。

## 五、自查反例（改坏推演）

- 反例 1：归并若不限定 var、按名字全文裸匹配，val 声明后出现的同名局部参数 / 别的类成员赋值会被误并入，绑定期望行号也会被带偏。现判据二遍只遍历 declared 表里的 var，val 直接跳过。

- 反例 3：归并 RHS 若不用语句收口状态机、退回首行截断，后续兄弟语句 / helper 体里的 readText 会被卷进截面，派生变量被误登记为全文持有人；现沿用 `_rhs_until_boundary` 括号 / 字符串感知收口。
- 反例 4：通路三 若本单顺手补内联 readText，需引入第二类 File 持有人绑定、helper 返回类型回追与 forEach lambda 参数分析，会推翻现有单绑定模型并在存量上放大 12 处噪音；故登记待裁（见新发现问题 3）。
- 反例 5：断言截面若跟着放宽到绑定声明所在函数体，跨断言幻影命中会回潮；断言匹配仍只在 `_assert_arg_body` 单条实参截面内进行。
