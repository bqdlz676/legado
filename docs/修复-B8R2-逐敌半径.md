## 一、缺陷现状（before，回源实测）

- `CampaignController.kt:543`（改动前）：
  `Intent.FLANK -> pathfinder.flankPath(corps.position, target, corps.type, perceivedEnemies(corps).map { it.position })`
  —— `.map { it.position }` 只取位置，敌军自身 `visionRadiusCells` 被丢弃。
- `Pathfinder.kt`（改动前）：`flankPath` / `flankRoute` 第五参为单一 `visionRadiusCells: Int = radiusFor(type)`；私有 `astar` 形参 `viewRadius: Int`；`watchedBy(enemy, cell, viewRadius)` 用这一个统一半径闸门全部敌军。
- 半径真源：`model/CampaignModels.kt:162` `var visionRadiusCells: Int`；`CampaignController.kt:225` 赋值 `visionRadiusCells = visionRadius(def)`；`perceivedEnemies(observer): List<Corps>` 在 `CampaignController.kt:510`。
- 后果（混编）：高视野敌军（骑兵 6）被按本方兵种半径剪枝时留 2 格暴露环；低视野敌军（民兵 3）可能被按大半径过度绕行。

## 五、二阶 / 三阶影响推演

- **路径长度（二阶）**：逐敌半径后，高视野敌军的剪枝环按 6 格收紧（旧按本方半径可能只留 4 格），低视野敌军环按 3 格放松；侧翼路径整体绕行距离可能变化。`marchAlong` 移动预算 `steps = minOf(budget, route.size - 1)` 口径不变，单回合推进格数不变，抵达回合数可能后移——属「包抄绕侧」预期行为。
- **重载兼容（二阶）**：旧版 `List<Cell>` + 统一半径重载完整保留，既有 12 条测试与 crossing 域唯一生产调用点（改造前）无需改语义；`help/sim` 包是另一套静态 `Pathfinder`（不同包、不同签名），与本类无继承 / 调用关系，未受影响。
- **退化链（三阶）**：加价 A* 与直线折线兜底只消费位置集合与 `watched` 布尔，逐敌条目在 :135 / :153 拆成位置与半径后，退化路径仍非空；新增用例 14 固定该行为。
- **情报一致性（三阶）**：半径仍取自 `Corps.visionRadiusCells`，与情报侧 `CampaignController.kt:477 / :687` 的 `visionRadiusCells` 闸门同源；本单未改情报侧取值。

## 七、交接项（别单，本单未修）

- **R1 半径表双份**：现状仍为 `Pathfinder.radiusFor`（Pathfinder.kt:288-293，骑兵 6 / 精锐 5 / 常规 4 / 民兵 3）与 `CampaignController.visionRadiusFor`（CampaignController.kt:1118）各持一份；当前逐值相等，后续调兵种平衡只改一处会造成「情报看见的半径」与「侧翼躲开的半径」漂移。建议收敛到 model 层单一来源并补等值单测。
