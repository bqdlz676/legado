# 金字塔验收机制（2026-11-26 定稿）

## 一句话

验收不是一道门，是七层塔：下层不绿，上层不许进；每层只解决自己那一层能解决的判断，机检优先，人工兜底。

## 七层（自底向上）

L0 静态事实层（机检，秒级）
判什么：改动是否破坏编译面与结构单源。
判据：`cross-module-guard.py`（删类残留引用 = FAIL、跨编译单元调用点提示、测试字面串陈旧提示）、`check-frankenstein.py`（双轨/兼容层/弃用/半成品）、`debt-ratchet.py`（债务只许减）。
失败回退：改到本地，不提交、不推。

L1 单元行为层（机检，分钟级）
判什么：改坏实现，测试会不会红。
判据：`docs/断言范式.md` 四范式；写单报告必带「自查反例」节；验收单必做「改坏推演」。
失败回退：回写码方补断言，不进验收槽。

L2 结构契约层（机检 + 人工）
判什么：注册表/枚举/入口清单是否单源，有无第二份实现或旁路。
判据：结构锁断言（全集条数、每个非默认分支有独立用例）、全仓 grep 证明"只此一处"、入口清单回证。
失败回退：回 L1 补断言或回写码方拆旁路。

L3 视觉层（机检）
判什么：界面改动有没有破快照基线。
判据：`screenshot` 的 Paparazzi 流水；新增/修改 Composable 形参必须同步调用点（这是历史 CI 红的首要来源）。
失败回退：补基线与调用点，重跑。

L4 构建层（机检，云端）
判什么：整仓能否编译、全部单测能否跑绿。
判据：CI `Verify (unit tests)` 全绿；`Package Debug APK` 在 P0~P3 期本就 skipped，不算失败。
失败回退：最小改动立刻修绿，修复期间停发新功能单。

L5 独立验收层（人工 + 回源）
判什么：这单是否真的实现了它声称实现的东西。
判据：八判据 + 每条 `文件:行` + 真跑命令 + 「不许照抄写码方结论」。
失败回退：判低则换代理重做，禁自评代验收。

L6 规格对照层（人工，逐字）
判什么：实现与规格是否逐字一致（口径、色值、边界、文案）。
判据：锚点卡回源 + 执行层原文切片对照；规格没写的边界由实现方按"不许降级/不许空白态"自裁并留档。
失败回退：回 L5 重判，必要时回写码方改实现。

L7 真机层（当前缺口，如实挂账）
判什么：真机时序、手势、帧率、Compose 重组观感、IME 遮挡。
判据：真机清单逐条过；沙箱没有设备，所以这一层长期是"未验证"，必须写进每份报告的未验证项，不许当成已通过。
处置：出包阶段集中补，或在有设备的环境补。

## 三条硬规则

1. 下层不绿不许进上层。CI 红的时候，全队只修红，不派新功能单。
2. 每层判据必须能回源。L5/L6 的每条结论都要有 `文件:行` 或命令输出；没有回源等于没判。
3. 上层不得重做下层的活。L5 发现"测试空转"应打回 L1，而不是自己在报告里替写码方论证。

## 与"一单一验收"的关系

一对一（一个 W 对应一张 V、必须换代理）是"谁验"的约束；金字塔是"验什么、按什么顺序验"的约束。两者不冲突：V 单按 L0→L6 顺序走，遇失败即停在该层并回退，不越级。

## 现状（每轮由 `pyramid.py` 打印）

L0 有机检（四支脚本）；L1 有范式但靠人执行；L2 部分机检；L3/L4 靠 CI；L5 每单必做；L6 只在高风险单做；L7 缺设备，长期挂账。
