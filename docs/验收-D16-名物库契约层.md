## 三、新发现缺陷 / 风险（静态核查新增，实现报告与选型未登记）

1. **超时边界在契约层缺失（对应判据 5，判低）。** `FallbackState` 与 `CacheStatus` 均无 TIMEOUT 态，`ArtifactLoadStrategy` 无超时参数 / 回调 / 监听；大库按需下载 + 预缓存（09:72）场景下，接线层拿到超时信号后无可回填的契约状态。建议接线单之前在策略接口补超时态或在 LoadStrategy 增 `onTimeout` 回调；本单未补不擅自改码。
2. **`defaultIndex` 被接收后丢弃（对应判据 4/6，判低）。** `ArtifactFallback.ambiguous` 形参 `defaultIndex: Int?`（`ArtifactFallback.kt:67`）在函数体 `:72-83` 构造 `BubbleContent` 时未被读取；冻结契约 `BubbleContent`（`BubbleContractModels.kt:68-78`）也无承载默认下标的字段，`candidates` 仅为 `List<String>`（`:76`）。结果：默认候选下标在气泡内丢失，接线层无法从气泡回读「哪个候选是默认项」。测试 `:107` 传入 `defaultIndex = 0` 但无任何回读断言，掩盖了该问题。收敛路径选型 §3.4、§7 已指方向：逐项 `isDefault` 应由接线层既有 `Candidate` 契约（`BubbleContractModels.kt:115-126`，含 `isDefault` 位）展开；当前 D16 走裸串 candidates，默认下标这一信息链在契约层即已断裂，接线单必须在适配器侧把 `defaultIndex` 翻译成 `Candidate.isDefault`，或回填契约字段。
3. **加载失败（非离线）无独立状态标记。** 除 `CACHE_MISS_OFFLINE` 外，数据源异常、条目损坏、解析失败无 Failure 态；`EntityProvider` KDoc 承诺「绝不抛异常」（`EntityProvider.kt:26-27`），但空实现不经真实源，真实 Provider 的异常→状态映射本层未钉死，存在各实现自行发明失败口径的风险（选型 §3.4 对 B 路线的同类担忧在 A 路线真实实现期仍需守）。
4. **类名碰撞：D16 `PlaceEntry` 与 D3 `help.place.PlaceEntry` 同名。** `help/artifact/store/PlaceStore.kt:9-15` 新声明 `PlaceEntry`；D3 既有 `help/place/PlaceModels.kt:230` 亦为 `PlaceEntry`。两包不冲突（全限定名不同），但 grep / import 极易混读；接线适配层 import 时须显式限定包名，建议后续更名或在条目注释互指。
5. **`EmptyEntityProvider.query` 对既有表类别无 type 映射。** `categoryForType`（`EmptyEntityProvider.kt:34-47`）只覆盖新表 type；person/place/plant/animal/medicine 走 `query` 路径时类别退化为 `Kind.WORD`，只有 `queryByCategory`（`:27-28`）能保留传入类别。真实实现接线时须注意两条入口的类别保真度不一致。
6. **既有表类别兜底 Kind 统一压为 `Kind.WORD`。** PLANT/ANIMAL/MEDICINE 的 `fallbackKind` 均为 `Kind.WORD`（`ArtifactCategory.kt:32/:35/:38`）；冻结 `Kind` 八值（`BubbleContractModels.kt:19-28`）无草木 / 鸟兽 / 药名专用值，当前取值是八值约束下的可行退化为记录项，非编译缺陷。
