## 五、改坏推演

### 5.1 二阶三阶影响

- 二阶：八个屏幕把三布尔并集口径改成显式 `state` 后，同一按钮同时被旧 `enabled`/`loading` 布尔与新 `state` 传入时走并集（`InkButton.kt:93-96`），不会出现新 state 覆盖旧布尔导致的假可点；但未来调用方若只传 `state` 不传 `enabled`，默认 `enabled = true`，DISABLED 仍靠 state 收口，语义自洽。
- 三阶：别名桥一旦提前物理删除而排除域未迁移，`InkCard.kt:98` 与 `BookshelfScreen.kt:815` 会编译断裂；因此 N2 的删除必须排在卡片域/书架域迁移之后，顺序不可反。快照层平行属性（N3）若不随收口删除，后续新增状态档位时两处口径可能各改一边，产生“契约改了、快照没跟上”的静默双源。
- 变体扩面：Divider/Progress 新枚举变体若后续再加，`ComponentTokens` 之外不得回退内联 hex；当前两组件 KDoc 已写明适用条件（`InkDivider.kt:17-34`、`InkProgress.kt:18-29`）。

### 5.2 反例与边界

- 反例一：若别名桥内部保留旧七态映射表或复制系数，即属事实双轨；实测 `compat/ComponentStateCompat.kt:18` 为身份 `= this`，无映射表，反例不成立。
