## 二、判据（逐条可断言）

1. 绿闸：只有 `status=completed 且 conclusion=success` 判 green；`skipped` / `neutral` / `cancelled` / `timed_out` / `action_required` / `stale` / `failure` / `startup_failure` 全部非绿，输出带逐条原因；Package run 闸同口径。
2. 取包二次确认：Package run 存在 → completed+success → artifacts 列表非空 → 有 debug 变体 → 下载 zip 非 0 字节 → 解压恰好 1 个 apk 且过 Manifest/arsc/dex/v1 结构校验；任一不过非 0 退出。
3. 种子：`CI_STATE=unknown` 计入 `UNKNOWN`；`UNKNOWN>0` 必须 `SEED: INCOMPLETE` 并写明「CI 状态不可取，无法确认构建可信」；`green/red/running/none` 不进 UNKNOWN。
4. 种子覆盖面：设计 token（verify + `--selftest`）、静态嫌疑扫描 `--selftest`、取包链 `--selftest`、补偿渠道在册自检四行在岗；无 `--selftest` 的门禁不进种子。
5. 挂死取证：检出终态事件走精确配对；无任何终态关键词判 `WARN_STARTED_ONLY`，建议文案注明「仓内四事件已开，此警告意味日志截断或任务未跑到测试阶段」；WARN 下列表标题不得用「挂死嫌疑」定性词。
6. 补偿：audit 必须带 `{channels, note}`，每个 channel 键存在于 `compensation_channels`；blocking 补偿必须为 `null`；渠道 evidence 指向的仓内路径必须存在；校验器对三类负样本判红。
7. 边界：不改 `app/src/**`、`.github/**`、其它 `check-*.py`；`rule-gate.sh` 仅加开关；不把补偿写成「无」「人工注意」空话。
