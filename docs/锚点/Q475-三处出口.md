## 二、判定口径（不许放宽）

1. 判「接上了」：用户点下去真有下一步且能做到事——空 lambda 不算接上；默认 `{}` 渲出的可点按钮同属假接线。
2. 标签与动作必须同义：写「重试」就只能重试（重新拉取 / 重新校验 / 重新解码），写「返回」就必须是返回；不许靠改标签掩盖接错动作，也不许把重试按钮接到导航动作。
3. 每条都要给「动作 → 点下去发生什么 → 失败时再怎么兜」的完整链条；每种边界必须有迂回方案，不允许空白态或崩溃。
4. 不许为了消掉空态编造无意义动作；本地表单 / 本地菜单无远程事项时不留可点空动作。
5. 新逻辑先接好再删旧；不留旧格式兼容层。

## 三、可测判据（grep 回证，逐条可断言）

1. 三处改前原文行与改后行逐字落报告，禁裸 `:NNN`，全部带文件路径。
2. `onAction = {}` 空 lambda 在三个目标文件（及同目录 VM / 宿主传参文件）的改前 / 改后命中数分列；真动作回调从哪一层传下来（VM 方法行号 → 宿主传参行号 → 屏幕形参行号 → `onAction` 行号）逐条列。
3. 枚举 `FileManageScreen(` / `FilePickerDialog.show` / `DictImageFailure(` 全部调用点，确认新增必填表参数没有漏接的第二调用方。
4. `python3 data_scripts/kotlin-syntax-lint.py <改动文件>` PASS；禁跑 gradle / kotlinc，编译与单测归云端 CI。
5. 域外域（bookshelf、source、config、autoTask、replace）零改动；`git status` 只读核对，禁 git 写。

## 四、兜底边界

- FilePickerDialog / FileManageScreen 的失败态是本机目录读取失败（权限拒绝 / IO 异常 / 根目录不可用），不是网络离线；重试 = 重读当前目录。重读仍失败时：错误文案保留可再试；不可恢复项（根目录为 null）由既有「取消 / 面包屑 / 返回上级」入口兜底，不新造动作。
- DictRichContent 图片失败：重试 = 重置位图与失败标记、自增重试钥匙，强制 Glide 重新解码 / 重新取图；重试仍失败回退占位图（文案 + URL）+ 占位区可点放大原文；查看器内同构补重试。
- 数据：URL 解码失败重试不会成功，属不可恢复边界，落占位 + URL + 可放大原文，不崩溃。
- 本单不碰 B19 两支浮层接缝（`InkBottomSheet` / `InkHalfSheet`），不碰 N2（Timeline 休眠态）、N4（bookshelf 冗余空 lambda）、N5（source 注释占位）等域外遗留。
