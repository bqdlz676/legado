# 锚点卡 · Q-279 出包链脚本化（CI 绿闸 → 取包 → 结构校验）

> 对象：`data_scripts/fetch-apk.py`（新增）；回执报告 `docs/方案-出包链脚本化.md`。承接历史两类事故——「CI 绿但没有包」「报了 APK 实际没校验签名」：旧链 `data_scripts/release.sh` 轮询默认开、变体不判、签名不查、失败面不区分；本卡把整条出包链固化成一条可复现命令。

## 一、事实锚点（逐字，含 文件:行）

- Verify 工作流：`.github/workflows/verify.yml:1` `name: Verify (unit tests)`；影子单测 `.github/workflows/verify-shadow-single.yml` `name: Shadow · single-job full tests`（手动触发，不进绿红判定）。
- 出包工作流：`.github/workflows/package.yml:1` `name: Package Debug APK`。
- 上传产物：`.github/actions/build-apks/action.yml:37` artifact `legado-debug-apk`，path `app/build/outputs/apk/**/debug/*.apk`；`:44` artifact `legado-release-apk`；`if-no-files-found: error`。
- 旧链现状：`data_scripts/release.sh` 轮询 `for i in $(seq 1 40); do … sleep 20; done`；取包 `ls -t dist/*.apk | head -1`；aapt2 缺失时 versionCode 断言跳过；无签名件结构校验。
- 既往人工签名核对：`docs/交付-APK-98ee6d0-静态自检.md` §3 用 `keytool -printcert -jarfile` 人工比对证书指纹（Owner `CN=Luowen, OU=Doubao, O=Luowen …`，SHA256 `B6:2D:…`），脚本层不查签名。
- 新脚本常量：`data_scripts/fetch-apk.py:44` `VERIFY_NAME='Verify'`；`:45` `PACKAGE_NAME='Package Debug APK'`；`:46` `GREEN=('success','neutral','skipped')`；`:47` `DEFAULT_TIMEOUT=300`；`:48` `POLL_INTERVAL=10`。
- 新脚本函数：`:175` `verify_gate()` 绿闸；`:316` `validate_zip()` 解压校验；`:210` `validate_apk()` 单包校验；`:333` `download_artifact()`；`:349` `pick_debug_artifact()`；`:485` `selftest()`。

## 二、判据（逐条可断言）

1. 绿闸前置：第一步只查 Verify run 状态；非绿（`red` / `running` / `none`）输出 `CI=…` 并退出 1，不请求 artifact 端点；Package run 未结束 / 非绿同样不取包。
2. 入口：`--sha`（默认 `git rev-parse HEAD`，短号补全 40 位）/ `--run-id` / `--wait`（默认关）/ `--timeout`（默认 300s）/ `--selftest`。
3. 取包：按 `head_sha` 查 `Package Debug APK` run；artifacts 逐条打印；按名含 `debug` 选变体；下载 `/actions/artifacts/<id>/zip` 到 `dist/<sha前7>/`。
4. 结构校验：恰好 1 个 `*.apk`（0 个 `NO_APK`；多于 1 个 `MULTI_APK` 列名判红）；`AndroidManifest.xml` 存在，有 aapt/aapt2 则解析，缺失降级 zip 结构检查并打印 `MISSING: aapt`；`resources.arsc` 存在；`classes*.dex` ≥1；打印大小与 `sha256`。
5. 签名口径：`META-INF/` 证书（`*.RSA|*.DSA|*.EC`）+ `*.SF` + `*.MF` 三件齐全判 `已签名（v1）`；仅有 `META-INF` 占位或无签名件判 `UNSIGNED` 红；NOTE 写明 v2/v3 在 Signing Block、zip 目录不可见，无 apksigner 不可判定。
6. 失败面：凭据缺失 / 401 / 403 / 404 run 不存在 / artifact 404 过期 / zip 损坏 / 0 apk / 0 字节 apk，各自有明确输出；退出码 0 通过、1 CI 或结构 FAIL、2 基础设施错误、3 超时熔断。
7. 超时熔断：整体 `--timeout` 默认 300s；超时打印停在哪一步，退出码 3，不允许静默挂死。
8. selftest：`/tmp` 四夹具——正常单包 v1 签名（PASS）、双 apk（`MULTI_APK` FAIL）、0 字节 apk（`ZERO_BYTE` FAIL）、`META-INF` 无签名件（`UNSIGNED` FAIL）；末行 `PASS 4/4 …`；夹具自删。
9. 边界：不改 `verify.yml`、既有 `check-*.py`、`app/src/**`；无 git 写；沙箱无 JDK/SDK，不跑 gradlew / kotlinc / apksigner，仅 py_compile 与离线夹具自测。

## 三、边界与取舍

- 本脚本只保证 v1 存在性与 `META-INF` 矛盾态；证书身份是否等于既定 `luowen.jks` 指纹、v2/v3/v4 方案、Manifest 二进制字段，均需 apksigner / aapt2 环境，列入待裁（报告 §五-c）。
- `--wait` 只给人手动盯包；主控自动化路径不带此开关，避免阻塞调度层。
- `release.sh` 本单不删不改；双轨并存期间以 `fetch-apk.py` 输出为准，退役 / 改薄壳归后续单。
- `dist/` 当前未入 `.gitignore`；实跑产物为本地暂存，忽略规则补齐归后续单。

## 四、验收方式

- 静态回证：`python3 -m py_compile data_scripts/fetch-apk.py` RC=0；`python3 data_scripts/fetch-apk.py --selftest` 末行 `PASS 4/4 fetch-apk selftest …` RC=0；`/tmp/fetch-apk-*` 无残留。
- 夹具断言：A 正常包 `overall=True` / `signature=v1-signed`；B `MULTI_APK`；C `ZERO_BYTE`；D `UNSIGNED`。
- 补充边界：外层 zip 无 apk → `NO_APK`；非 zip 字节 → `CORRUPT_ZIP` InfraError；无 aapt 环境 Manifest 行打 `WARN: MISSING: aapt`。
- 云端复验（本单不执行）：下一轮绿跑后实跑脚本，核对 Verify 绿闸放行、debug artifact 下载、结构校验 PASS；若 CI 镜像可加 `apksigner verify` 步骤，再补 v2/v3 与证书指纹比对。
