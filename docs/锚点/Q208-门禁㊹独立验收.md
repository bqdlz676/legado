## 三、可测判据（P1…Pn）与 FAIL 条件

- P1 A 残留：副本工作区出现命中 `POLLUTION_RE` 的未跟踪/改动文件 → 脚本 rc=1 且点名路径；删除后 rc=0。FAIL 条件：应为红却 rc=0，或点名不到文件。
- P2 B 幽灵：RUNNING 行 agent id 对应轨迹文件不存在 → rc=1，点名 Q 号与 agent id。FAIL 条件：幽灵行被 PASS 放行。
- P3 B 僵尸：轨迹存在但 mtime > 10 分钟 → rc=1。FAIL 条件：超龄轨迹仍 PASS。
- P4 C 超时：RUNNING 带起时且距今 > 15 分钟 → rc=1；无起时 → rc=0 仅 INFO。FAIL 条件：超时不红，或无起时被红。
- P5 豁免收口：豁免只对 `git ls-files` 已跟踪夹具生效；新增污染文件进 fixtures 仍须 rc=1。FAIL 条件（D-1）：fixtures 内新坏样本 PASS。
- P6 selftest：`--selftest` 合规样本 rc=0、坏样本 rc=1；夹具目录跑完即删。FAIL 条件：双向任一反向，或 `/tmp/dispatch-selftest-*` 残留。
- P7 watch-ci 真值：无 run rc=3；全绿 rc=0；有红 rc=1；在跑 rc=2；缺凭据 rc=4；已完成红不得被 in_progress 掩盖（D-3）；token 不出现在 stdout/日志。
- P8 复杂度：单文件 < 600 行；头部 docstring 写明为什么与适用条件。FAIL 条件：≥600 行，或无"为什么"注释。
