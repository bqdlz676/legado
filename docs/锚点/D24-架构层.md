## 三、判据（机械可判：可 grep / 可跑单测）

1. 依赖方向：阅读侧、地图侧代码均 import 同一 `core/data` 下 `PlaceStore`/`ChronologyStore`；Store 文件内对阅读引擎/地图引擎渲染层、`Activity`、手势状态的反向 import `grep` 0 命中（切片:14/21/22）。
2. 单例唯一：`grep -rn "PlaceStore(" "ChronologyStore("` 构造点各=1；仓内无第二份 place 地名缓存实例、无第二份年代映射表定义点（切片:21/22）。
3. GPU 抑制与恢复：地图 resumed 路径下阅读页 `onDraw` 空返回符号存在且被调用，无后台阅读面 GL/Canvas 绘制；切回 `onResume` 成对恢复，残留回调 listener=0（切片:23/24）。
4. 体积/内存门禁：内置体积 ≤25MB 且超标明细为出包必备产物；峰值 PSS 按三档判定；`grep -rn "180MB"` 文档/注释/门禁 0 残留（切片:25/27）。

## 四、兜底边界

- 空数据（切片:42）：Store 未加载完成时地图/阅读侧先显示占位空态，不抛空指针；共享实例懒加载，首次访问线程安全。
- 断网/离线（切片:43）：未缓存大资源走兜底空态并提示离线可用范围；核心阅读与已缓存地名/年代可用。
- 低端机/帧率掉线（切片:44）：双引擎并存超 100MB 按三档走「待优化/打回」，不靠减粒子数绕过内存门禁；GPU 竞争不得以降画质替代抑制逻辑。
- 后台返回（切片:45）：回前台 Store 单例不重建；GPU 回调按生命周期重新配对，不重复订阅。
- 体积超限（切片:46）：超标明细未出齐不得出包；豁免项必须逐条指认为按需下载，不得把大资源塞进内置目录规避 25MB。
- 无规格项（F-73）：`core/data` 与 `core/ui` 内部文件划分、Store 懒加载并发原语选型，原文未给，禁自拟，退回 F-73 三段流水线。
