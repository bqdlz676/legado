## 二、参数表

- 复制体积：Float 4 字节/格；32×32 合成场 4096 B ≈ 4.0 KiB；1024×1024 实测 DEM 4,194,304 B = 4.0 MiB；`MAX_PIXELS=4_000_000` 上限 16,000,000 B ≈ 15.3 MiB/份。
- 命中口径：解码前按 sha256 前 16 位（64-bit 前缀）哈希命中；宽高随槽位记录供台账，**不参与查找**（KDoc `:27-29`）。
- 锁：`getOrDecode` / `resetCache` `@Synchronized`；生产者锁内纯解码；密封后返回实例内部状态不可变，并发读无需加锁。
- 路线取舍：采纳路线 A（String 哈希索引 + 读 `slot.key`）；否决路线 B（CacheKey 复合键），因入口解码前无宽高、无法构造复合键。

## 三、结论锚点

- C1 现存消费全只读；类型层密封后热路径标量读零拷贝，仅显式调 `toFloatArray()` 才付一份防御副本；正常装配路径无额外栅格复制。
- C2 Q-252 三行 unresolved 属类型层面确定性错误，字段改读 `victim.value.key`；整文件通读另核 size 口径、台账字段、构造顺序、copy 保字段、计数清零、并发锁，均无其它隐患。
- C3 残余风险：16 位前缀同哈希不同尺寸理论串槽（当前数据规模不现实）；反射可触达私有字段；`HeightRaster.data: IntArray` 同型公共可变未修（交接另派单）。
- C4 沙箱无 JDK，未编译、未跑单测；红绿以云端 clean 编译 + `testAppDebugUnitTest` 为准，不报百分比 / APK。
