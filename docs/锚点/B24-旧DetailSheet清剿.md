# 锚点卡 · B24 旧 DetailSheet 死代码清剿

> 用途：B24 清理单开工依据。出自 `docs/验收-B1-点字半屏Sheet.md` 的 D6。

## 一、事实锚点
- `ui/main/DetailSheet.kt` 等三文件在 B1 落码（69ef748）后零外部引用。
- 阅读域 `DetailSheet` 已零命中（验收报告判据 1 的 grep 回证）。

## 二、判据
1. 删除前必须先出「全仓引用清单」：主源码 + 测试 + 资源（xml/layout/navigation）+ `AndroidManifest.xml` 全部 grep 一遍，逐类给出命中数；任一非零命中即停止，不许删。
2. 只删零引用文件；不许顺手改别的类、不许「重构式删除」。
3. 删除后复跑同一组 grep，证明零命中且无新增断链；并在报告里贴出删除前后的文件清单。
4. 编译风险如实登记：删除文件若被反射/字符串引用（如类名字符串），必须单独 grep 类名字符串。
5. 不改测试来「迁就」删除（若某测试引用待删类，说明该测试本身也已被替代，一并列清）。

## 三、边界
- 只删，不新增功能；不动 B19/B20/B21 已改文件。
- 若发现引用非零，本单转为「只登记不删」，把引用位置交回调度层另立条目。

## 四、验收
独立验收代理核对引用清单与删除前后 grep 输出；CI 唯一编译手段。
