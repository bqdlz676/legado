## 三、结论

1. `seed-check.sh` 与 `种子-机制种子.md` 此前确无独立回执，仅被 Q-275（`docs/锚点/Q275-队列收口.md:31` 登记 DONE）与 Q-286（`docs/锚点/Q286-复核必改.md:10-11` 记 UNKNOWN 计数与新增 need 行）间接提及；本单回执 `docs/修复-机制种子落地.md` 与本卡补齐独立回源。
2. 种子终判口径：`fail=0 且 missing=0 且 unknown=0` 才 `READY`；`MISSING` 显式记账不算通过；`unknown` 单列且同等阻断 READY。当次实跑 `INCOMPLETE（fail=1 missing=0 unknown=0 pass=14）`，阻断级腿有 1 项红，非种子机制自身残缺。
3. 种子覆盖面 = 阻断级门禁 + 13 项关键自测/契约 + 补偿渠道在册自检 + 两布尔；audit 历史噪声、网络态触发对账、队列台账双源一致性、静态嫌疑实跑不在种子常态覆盖面内（判断理由见回执第六节）。
4. 维护棘轮：新门禁无 `--selftest` 不许进种子；删模块必须同步删 `need` 行；种子改动走分桶提交并写明挡掉的错误类型。
