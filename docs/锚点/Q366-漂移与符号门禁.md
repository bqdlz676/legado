## 三、门禁一判据分级

- DEADFILE（FAIL）：锚点指向文件按仓根相对路径或唯一基名解析后仍不存在。
- OUTOFRANGE（FAIL）：文件存在，但行号超出该文件总行数。
- SUSPECT（WARN，不计退出码）：落点行为空白、纯 `}`、纯注释分隔线或 Markdown 分隔线，多半是漂移残骸。
- 白名单 `docs/.line-anchors-allow.txt`：制表符四列「引用文档 / 锚点串 / 理由 / 登记单」，缺理由列即 BADALLOW FAIL。

## 四、门禁二判据分级

- NODEF（FAIL）：自有包 import 进来的名字，仓内索引反查不到任何 fun 或类主构造定义。
- ARITY（FAIL）：同名定义存在，但可核对的顶层/扩展重载无一容纳本次调用实参个数；定义处无 vararg、无默认参、无匹配重载。
- 重载放行：同名多定义时任一重载可容纳（个数相等，或 vararg/默认参兜底）即放行。
- 跳过计数：生成符号 `R.*` / `BuildConfig.*`；外部库 import 前缀；标准库与测试框架白名单；接收者类型未知的名字归未知跳过。

- 门禁二夹具四通路：NODEF 一条必失败；ARITY 一条必失败；两参重载命中放行；一参合法放行。夹具 tempfile 自删，`/tmp` 残留 0。
