## 二、判据（逐条可断言）

1. 特征 a–k 逐条对应挂死机理，机理原文见短名单 §一 特征表；每条命中留 文件:行 + 代码原文（逐字未改写）。
2. 类型感知归类（文件内声明名静态收集）：
   - `AtomicBoolean/Integer/Long/Reference/Int/Double` 接收器的 `.get()` 非阻塞，不计 h，入 §七 附录；
   - 首字母大写接收器判为伴生对象/静态 getter，不计 h，入附录；
   - `CountDownLatch/Semaphore` 接收器裸 `.await()` 记 c（tier1）；
   - `CompletableDeferred` / `async` / `launch` 接收器及 `.result.await()`、常见 Deferred 命名记 d（tier2 降权）；
   - 其余未定型接收器降权 tier2 并备注，交二分复核。
3. 护栏识别：带 `TimeUnit`/数字实参的 `await(...)`、`wait(...)`、`awaitTermination(...)` 不命中；
   `withTimeout`/`withTimeoutOrNull` 同行包裹、或上一行未闭合开门块内的 `await()`/`join()` 视为护栏在位，不计分并入附录。
4. 字面量剔除：字符串/字符字面量区间内的 `while (true)`、`URL(`、`.get()`、`join()` 等不参与匹配；
   import 行、行首 `*`/`//` 注释与行尾注释不参与匹配。
5. d 类按文件级计一次权重，全部 runBlocking 调用点留作聚合证据；文件内检出任一 `withTimeout`/
   `withTimeoutOrNull`/有界 `delay(` 即不记 d 文件级无界。
6. 分桶：`@Ignore` 优先隔离成 ignore 桶；`@Category(...)` 进 category 桶；两桶均不进主短名单与 txt；
   drop 桶仅统计不列嫌疑。
7. 输出：txt 每行一个 FQCN，`#` 注释行可被 `bisect-suspects.py` 的 `read_classes()` 直接跳过；
   实读校验 19 条全部可入二分批。
8. 边界：不新增门禁；不改 `app/src/**`、既有 `check-*.py`、`app/build.gradle`、`verify.yml`；
   无 git 写操作；沙箱无 JDK，不跑 gradle / kotlinc / 单测，仅 `py_compile` 与离线夹具自测。

## 三、边界与取舍

- 静态扫描不做数据流 / 调用图分析：接收器类型只看文件内声明名，跨文件类型不可知时降权标注「未定型」，
  不硬判 tier1；条件永不成立、线程未启动、Rhino native 调用不可中断等运行期挂死覆盖不到。
- runBlocking 护栏为文件级粗判：文件内一处有界不代表每个 runBlocking 都有界；反之局部无界但文件他处
  有 withTimeout 会被低估，两类误差均在短名单备注中留痕。
- okhttp 调用形态不区分 mock 拦截器与真实出站：文件内存在 `Response.Builder()` 时备注「mock 响应待人工确认」；
  localhost 回环标注「非出站网络」。
- 交集仅 4/19 落在主挂死分片：静态法圈出的多为「无护栏写法」而非已证实 culprit；本卡结论是静态名单
  作二分加速器，不单独定罪；若后续交集持续为 0，回退 Q-269 日志取证 + Q-273 二分收敛主线。
