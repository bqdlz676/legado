# 锚点卡 · Q-255 编译风险穷举

> 对象：本轮 `HeightMapRaster` 公开字段 `data: FloatArray` → `private val pixels` + `valueAt(Int)` + `toFloatArray()`、`HeightMapRasterCache` `CacheKey` 口径调整后的全仓静态编译风险审计；报告 `docs/审计-编译风险穷举.md`。本卡对应派单 Q-255：只读穷举五类风险，不改代码、不 push、不编译。

## 一、事实锚点（逐字，含 文件:行）

- 新栅格声明：`terrain/HeightMapDecoder.kt:29` `data class HeightMapRaster(width, height, private val pixels: FloatArray, degraded, source)`；只读面 `at(col,row)`（:49）、`valueAt(index)`（:56）、`toFloatArray()`（:59，防御性 copyOf）。
- 旧栅格声明：`terrain/HeightRaster.kt:15` `data class HeightRaster(width, height, val data: IntArray, degraded)`；`data` 仍是公开 IntArray，与本轮改动无关。
- 缓存结构：`terrain/HeightMapRasterCache.kt:31` `private data class CacheKey(contentHash, width, height)`；:33 `private data class CacheSlot(key, raster, lastUsed)`；:36 `private val rasterCache = LinkedHashMap<String, CacheSlot>()`——索引键 String，CacheKey 只存槽内。
- 唯一装配转换点：`engine/CampaignController.kt:1308` `toHeightRaster(raster: HeightMapRaster): HeightRaster`；:1310 `raster.valueAt(i)`。
- 存疑行：`terrain/HeightMapDecoder.kt:472` `return raster.copy(width = nw, height = nh, pixels = out)`，命名参数 `pixels` 绑定私有构造形参；Kotlin 2.4.20（`gradle/libs.versions.toml`），本环境禁本地编译，待 CI 真值。
- 接口契约：`terrain/RasterDecoder.kt:25` `decode(assetName: String): HeightRaster?`（返回旧栅格，非 HeightMapRaster）。
- 反扫零命中：`modules/book`、`modules/rhino`、`modules/web`、全部 `*.kts` / gradle 脚本、`app/src/androidTest` 对双栅格与缓存键零引用。
- 同名干扰：`AudioCacheKey`（`model/AudioCacheKey.kt:6`）、`fontCacheKey`/`coverBitmapCacheKey`、`ReviewIconCacheKey`（`ChapterProvider.kt:229`）均为无关类型。

## 二、结论锚点

- C1 ① 类：main + test 全部 `HeightMapRaster` 引用点走 `valueAt` / `toFloatArray` / `at` / 公开属性，未发现外部 `.data` 或 `.pixels` 访问；唯一存疑为 :472 的 `copy(pixels = ...)`。
- C2 ② 类：`rasterCache` / `CacheKey` / `CacheSlot` 全部封闭在缓存对象私有域，仓内无外部引用；String 索引键与槽内 CacheKey 分工一致，无类型互串。
- C3 ③ 类：`HeightRaster.data`（IntArray）引用点 9 处（`HeightRaster.kt:19/32/59/62/67/77/86/89`、`CrossingRasterBridge.kt:60/99/100/101/102`）全部标注与本轮无关，禁止误改。
- C4 ④ 类：旧符号 `data`(FloatArray)、`cachedDecode`、`rasterCache` 旧名、`rawData/grayArray/pixelArray` 无外部残留；`lastPathSegment` 三处接收方均为 `android.net.Uri`，与 Q-251 的 java.net.URI 报错判废分开。
- C5 ⑤ 类：栅格域零 `runCatching`；两处 `?.let`（`HeightMapDecoder.kt:227`、`HeightMapRasterCache.kt:66`）类型推断闭合；唯一语法存疑见 C1 :472。
- C6 需改清单仅 R1 一条（:472，待裁，待 CI 复核）；备选返工：类内 `resized(...)` 工厂，或直走公开主构造 `HeightMapRaster(nw, nh, out, degraded = raster.degraded, source = raster.source)`。

- N1 私有构造形参 `copy()` 命名传参可见性未编译验证（待裁，R1）。
- N2 缓存双轨键无「同哈希不同尺寸」相撞用例锁定（已入队，`HeightMapRasterCacheTest.kt` 现 4 用例不覆盖）。
- N3 双栅格值域/类型并行，互转仅 `CampaignController.kt:1308` 一处（已入队，建议类注释互链）。
- N4 缓存键字面撞名四类无关 `*CacheKey`，反扫须按包路径过滤 terrain（已入队）。
- N5 Q-251 URI 误用与本轮栅格改名两类问题判废分开派单。
