## 二、共性根因（机制层面，非道德评价）

1. **回执通道与产物通道解耦**：调度层只解析 assistant 文本，文件系统变更不在回执证据里。10 例全部「返回了一段文字」，其中 6 段文字本身像完成汇报；若调度只看回执文字不 grep 复核，0 改动会被误判为完成。
2. **派单体量触发认知退化**：长篇多段派单（多类清单＋六节报告＋三类处置＋红线）首 turn 即退化为重复句 / 拒答 / 计划倾倒；同一任务、同一文件，仅差指令长度与回执格式的对照实验——`s_0007oNQJnkb`（长派单，空转）vs `s_0007Qc68H0S`（≤60 字机械指令＋三条 grep 自证，成功）——短机械指令成功率显著更高。
3. **回执无强制取证格式**：不要求可回源证据（grep 命中行 / `file:line` / 配平数）时，承诺句、拒答句、编造句都是低成本通过路径；派单里预塞的「现状原文 3 行」只能降低发现成本，**不能替代回执侧取证**（#1 派单已含现状原文仍空转）。
4. **空壳轨迹无闸门熔断**：0 行 / 1 行轨迹、零工具调用的代理未被调度侧识别为未执行，仍走完成流程；空转代理工作记忆已被污染，若复用续跑会把污染带进新单。
5. **三类失败混账**：未执行 / 执行了但无证据 / 交付错形态（计划当成品）被记成同一类「失败」，补救动作各不相同（重派 / 补档 / 重派＋缩派单），混账导致跟进口径糊掉。

## 三、可执行对策

### 派单侧
- **P1 机械改动短句派单**：同一批机械修复，指令 ≤200 字，只给「文件 / 行 / 原文 / 改成什么 / 三条自证」，不附大段背景与日志；长篇派单只用于需要判断的活（见 F-69）。
- **P2 派单前置核验**：派单前调度层自己 grep 一次目标现状，把「现状原文 3 行」写进派单；但明确记录现状原文不等于回执证据（见 F-71）。

### 回执侧
- **R1 零工具调用即判未交付**：禁止以回执文字判完成；轨迹工具计数为 0 一律退回重派（见 F-67）。
- **R2 回证三条硬要求**：写码/改文件类派单，回执必须含 ≥1 条 `grep -n` 命中行、≥1 个 `文件:行`、≥1 个括号配平数；缺一即判未交付并重派（见 F-68）。

### 调度侧
- **S1 空转代理不复用**：空转 / 拒答 / 乱码回执的代理一律不再唤醒续跑；新派同域代理并重申三条自证（见 F-70）。
- **S2 三类分账盘点**：每完成一个大模块，扫一次「零工具调用＋零产物路径」代理，按 ①未执行 ②执行了无证据 ③承诺/拒答句 三类入账，分别走重派 / 补档 / 重派＋缩派单，不许夹在进度里糊过去（见 F-72）。
