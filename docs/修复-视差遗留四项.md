## 一、N5（前置）：单例跨宿主踩踏 → 宿主持牌引用计数

### 1.1 旧口径问题

`GyroBridge` 是 `object` 单例，旧对外接口为 `start(context): Boolean` 与 `stop()`。三个宿主——书架 `InkShelfFragment`、古今地图 `PlaceMapActivity`、战役沙盘 `BattleActivity`——都在 onPause / onDestroy / onHiddenChanged 直接调 `stop()`。任一宿主交还时全局注销监听并清队，会把仍在用桥的另一宿主传感器一并打掉：书架切 Tab 停桥会打断地图正在跟的姿态流，地图 onPause 也会连带拆掉刚回前台的沙盘。

### 1.2 start / stop 时机口径表（散文，不用表格）

书架宿主（`InkShelfFragment`，持牌标识 `"shelf"`）：申领时机为 onResume 且偏好开启且 Fragment 未被 hide；onHiddenChanged(false) 且偏好开启时补申领；交还时机为 onPause、onHiddenChanged(true)、开关被关掉、开关打开时若当前不可见则不申领。地图宿主（`PlaceMapActivity`，标识 `"place-map"`）：onResume 且 WebView 可见（非空数据兜底分支）时申领；onPause、onDestroy、WebView 已 GONE 的 onResume 分支交还。沙盘宿主（`BattleActivity`，标识 `"battle"`）：onResume 申领；onPause、onDestroy 交还。三个宿主语义一致：**可见且在用才上牌，离开可见态 / 销毁即摘牌**；摘牌只摘自己的，不替他人摘。

### 1.3 方案：集合持牌，最后一张牌摘掉才 teardown

- `GyroBridge.kt:53` 新增 `private val holders = HashSet<String>()`。用集合而非单个 Int 计数：三个宿主可交错申领 / 交还，集合能识别「同一宿主重入」（重复 `add` 不重复上牌）与「未上牌先交还」（`remove` 返回 false 不拆桥）；单个计数无法区分身份，重入会误扣他人额度。
- `GyroBridge.kt:85-92` 新入口 `acquire(host: String, context: Context): Boolean`：`holders.add(host)` 记为新牌后才走 `ensureStarted`；已有存活监听时直接复用一路注册，不重复 `registerListener`（双份 50Hz 事件徒增功耗）；返回 `level > 0` 保留旧 `start` 的可用性上报语义。
- `GyroBridge.kt:98-104` 新入口 `release(host: String)`：摘掉自己的牌；仅当集合清空才调 `teardown()`。未上牌宿主调用为幂等空操作，保证 onPause / onDestroy 重复交还不报错。
- `GyroBridge.kt:107-110` 私有 `ensureStarted`：监听与 SensorManager 双非空即复用；否则先 `teardown()` 清残留监听与脏队列（保留旧 `start()` 幂等重入口径），再做三级传感器探测与注册。
- `GyroBridge.kt:172-184` 私有 `teardown()`：即旧 `stop()` 方法体（注销监听、清 FIFO、清兜底缓存、`level=0`），降级为内部重建 / 最后交还路径，不再对外暴露全局停桥。
- 对外 API 变更核对：仓内 `app/**` 与 `modules/**` grep 无第二处 `GyroBridge.start` / `stop` 消费点；测试目录无引用；JS 侧 `assets/map/gyro.js` 只调 JS 接口 `pull()` / `degraded()` / `available()`，不碰原生 `start` / `stop`。`drainLatest()`、`level`、`degraded`、`setDisplayRotation` 签名与语义不变，三宿主之外无需同步改动。未引入任何新依赖。

### 1.4 交错时序静态证明（A 停不影响 B）

持牌集合记为 H，操作语义：`acquire(h)` → H.add(h)，监听存活则复用；`release(h)` → H.remove(h)，H 空才 teardown。

序列一（验收点名的打断场景：地图在用，书架侧交还）：
1. `PlaceMapActivity.onResume` → `acquire("place-map")`，H={map}，注册监听，`level>0`，地图 JS 每帧 `pull()` 取流。
2. 书架 Fragment 切槽 `onHiddenChanged(true)` → `release("shelf")`。旧口径此处全局 `stop()` 会注销地图监听；新口径 `shelf` 本就不在 H 中，`remove` 返回 false，H={map} 非空，**不 teardown**，地图监听与 FIFO 原样保留。
3. 地图后续 `pull()` 仍能 drain 到事件；直到地图 `onPause` / `onDestroy` → `release("place-map")`，H=∅，才真正注销清队。

序列二（双宿主重叠持有，再先后交还）：
1. 书架 `acquire("shelf")` → H={shelf}；地图 `acquire("place-map")` → H={shelf, map}，监听复用不重复注册。
2. 书架 `release("shelf")` → H={map}，监听保留；地图姿态流不断。
3. 地图 `release("place-map")` → H=∅ → teardown。

序列三（地图跳沙盘，旧 Activity 先 pause 后新 Activity resume）：`release("place-map")` 时 H 空 → teardown；随后 `acquire("battle")` 重新注册。这是先拆后装，与旧口径 `stop()` → `start()` 的窗口等价，不存在「B 在用被 A 拆」的交叉；地图已在后台，其姿态流中断属预期前后台行为。

边界兜底：全无传感器时 `ensureStarted` 探测不到任何一路，`level=0` 直接返回；`acquire` 返回 false，持牌仍入账，最后交还时 teardown 无监听可注销，幂等。`holders` 操作用 `synchronized(holders)` 护栏；`queue` 既有 `synchronized(queue)`；`level` 保持 `@Volatile`，JS 线程 `drainLatest` 与主线程申领 / 交还不竞态。

## 三、D2：无传感器 / 关闭态阴影与位移精确归零，不额外分配对象

### 3.1 旧口径问题

`ShelfParallaxState` 的 `shadowOffsetX` / `shadowOffsetY` / `shadowRadiusPx` / `shadowColor` 四个 getter 不受 `active` 守卫：`active = enabled && available && !touchPaused`（`ShelfParallax.kt:176-177`）。关闭开关或无传感器时，残留的 `roll` / `pitch` 仍会算出阴影偏移、放大半径、抬高透明度；`shadowColor` 每帧还新建一个 `Color` 对象，既留残影又造成 GC 抖动。

### 3.2 落码

- `ShelfParallax.kt:184` 预算 `baseRadiusPx`（基础半径 px，构造期一次换算）；`ShelfParallax.kt:185-190` 预算 `baseShadowColor`（基础暖金、基础透明度的缓存实例，构造期一次分配）。
- `ShelfParallax.kt:199` `shadowOffsetX`：active 时 `-roll * shadowShiftPx`，否则精确 `0f`。
- `ShelfParallax.kt:202` `shadowOffsetY`：active 时 `-pitch * shadowShiftPx`，否则精确 `0f`。
- `ShelfParallax.kt:205-210` `shadowRadiusPx`：active 时 `12 + |roll|×6 dp` 换算，否则回 `baseRadiusPx`。
- `ShelfParallax.kt:213-223` `shadowColor`：active 时按 |roll| 提透明度并新建 `Color`（活跃路径维持既有行为），否则直接返回缓存的 `baseShadowColor`，非活跃态不分配对象。
- 位移 `translationX` / `translationY` 旧口径已受 `active` 守卫（`ShelfParallax.kt:193-196`），本次保持不变；阴影四个 getter 对齐到同一口径。

### 3.3 口径说明（手指滑动期间）

`touchPaused` 计入 `active`，故手指拖动期间阴影偏移 / 半径 / 透明度一并回基础态，与位移既有的回中口径一致，不保留上一帧倾斜阴影。这是守卫口径的自然推论，不是砍功能：拖动期间本就暂停跟拍，松手 400ms 后 `resumeFromTouch` 恢复跟踪。

## 四、D3：关闭态轮询降低频，写出功耗推演

### 4.1 旧口径问题

旧 `rememberShelfParallaxState` 轮询协程为 `while(true) { refreshAvailability(); if (enabled) drain; delay(16) }`：开关关掉后仍每 16ms 醒一次（约 62.5Hz 空转），刷一次可用性、空队不 drain，纯扣电。

### 4.2 落码

- `ShelfParallax.kt:67` 新增 `IDLE_POLL_INTERVAL_MS = 500L`（2Hz）。
- `ShelfParallax.kt:240-259` `LaunchedEffect(enabled)` 拆两支：开启态保留 16ms 高频轮询，`refreshAvailability()` + `drainLatest()` + 倾角换算 + 平滑；关闭态只跑 `refreshAvailability()`，500ms 一醒，**不 drain 队列、不构造四元数、不调 `quaternionToTilt` / `smoothTilt`、无 `FloatArray` 分配**。

### 4.3 功耗推演（逐项扣电为零如何成立）

- 传感器侧：关闭开关经 D1 交还持牌，最后持牌者 `teardown()` 调 `unregisterListener`；Android 传感器在本应用无监听者后不再向本桥投递事件，50Hz 事件回调链断开。
- 协程侧：旧口径关闭态每秒约 62.5 次唤醒；新口径每秒 2 次，每次只做一次 `level > 0` 的标量读取，无队列操作、无浮点平滑计算、无对象分配。
- 渲染侧：D2 守卫下非活跃态 getter 回常量缓存，无 `Color` 新建、无重复 dp 换算。
- 边界：保留 2Hz 而非彻底挂起，是为了按钮可用态能回显（设备有无传感器的状态随 `level` 刷新）；若后续确认关闭态无需回显，可再降为状态变更驱动，本单不提前砍这条刷新路径。

## 六、自查反例 / 改坏推演

- 反例一：若引用计数用单个 `Int` 而非身份集合。书架 onResume→onPause→onResume 快速重入时，+1/-1 后计数归零会误拆掉地图正在持有的桥；集合按宿主身份去重，重入 `add` 不增量、未知宿主 `remove` 不扣减他人，规避此错。
- 反例二：若关闭态把轮询彻底取消、不刷 `available`。设备本无传感器时，开关来回切换后按钮置灰态无法回显，用户看不到「陀螺仪不可用」的反馈；保留 2Hz 低频刷新覆盖该边界，不做成空白态。
- 反例三：若非活跃态 `shadowColor` 仍按残留 `roll` 算透明度。上次倾斜到 |roll|≈1 后关掉开关，残影阴影仍偏浓偏虚；现守卫直接回缓存基础色，逐值等于基础态。
- 反例四：若 `ensureStarted` 复用监听时只判 `listener != null`。存在 listener 残留而 SensorManager 已空的脏态会导致注册状态不一致；现双非空（`listener != null && sensorManager != null`）才复用，否则 teardown 重建。
- 反例五：若开关打开时 Fragment 处于隐藏槽也直接申领。不可见宿主白抢传感器，且回到可见路径会重复注册；现按 `resumed && !shelfHidden` 闸门，不可见不申领。
- 反例六：若 D2 守卫把 `touchPaused` 排除在 active 之外（只看 enabled/available）。手指拖动期间阴影会跟残留倾斜偏移，与位移回中口径打架；现沿用既有 `active` 三因子口径，拖动期间阴影位移一并回中。
- 反例七（二阶）：若 `release` 摘牌后不清 FIFO，旧姿态会留在队首被新宿主首帧 drain 到，造成视角跳变。现 teardown 清队口径保留，新宿主注册后首帧空队，JS 端本帧不更新姿态，既有兜底不变。
- 反例八（三阶）：若后续新增第四个宿主却忘了分配独立持牌标识，复用已有字符串会被集合判为重入、互相顶牌。已在 `acquire` KDoc 标注标识取值约定；后续接入方须用唯一 host 串，此条留作代码评审检查项。

## 七、二阶 / 三阶影响推演

- 宿主交错：书架与地图 / 沙盘正常导航路径是「书架点开地图 → 书架 onPause 交还，地图 onResume 申领」；新口径下书架交还不再拆地图的桥，地图姿态流在整个前台期间保持连续。地图跳沙盘走旧 Activity pause → 新 Activity resume 顺序，先拆后装，窗口与旧 `stop`→`start` 等价。
- 队列与首帧：teardown 清空 FIFO；新宿主注册后首帧可能空队，`drainLatest()` 返回 null，JS 端本帧不更新姿态，与既有空队兜底一致。
- 偏好与 Compose 状态：`AppConfig.shelfParallaxEnabled` 读写位置不变；`BookshelfScreen` 的 `parallaxOn` 本地态、`setTouchPaused` / `resumeFromTouch` 手势暂停链路未动；开关切换经 `LaunchedEffect(enabled)` 重启轮询支，状态保留不跳变。
- 渲染消费面：`ShelfBookCard.kt:160-164` / `:204-205` 读位移与阴影 getter，签名未变，无需改卡片层；非活跃态回基础值后卡片静止表现与「无传感器」既有画面一致。
- API 兼容：`level` / `degraded` / `drainLatest()` / `setDisplayRotation` 对外签名与语义不变；JS 三方法 `pull` / `degraded` / `available` 不动；无新依赖、无新线程、无新持久化。
- 历史包袱：旧 `start` / `stop` 全局停桥口径已从生产代码移除，不留旧格式兼容层；仓内无第二处消费点，无需并行保留双入口。
