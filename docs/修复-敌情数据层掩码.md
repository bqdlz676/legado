3. 断言③ 视野精确边界（`B9-R2-3`，`:678`）：同一夹具两个控制器，octile 距 = 4（= 常规兵视野半径）标记观测且下发上报坐标；距 = 5（半径 +1）不观测且 `reportLat` 为 null。反向推演：可见性闸门若写成 `<` 而非 `<=`，贴边 4 格会漏报；若写成 `>=` 或半径表漂移，5 格会误报。闭区间口径与 `CampaignController.kt:482`、`Pathfinder.kt:200`、`IntentResolver` 相邻判定一致。
4. 断言④ 距离项封顶（`B9-R2-4`，`:702`）：直测 internal `distanceTermCells`——常规兵视野 4：目击距离 10 → 半距 5 封顶 4；距离 8 → 半距 4 不触顶；距离 2 → 1；0 → 0；负值钳 0；骑兵视野 6：距离 20 封顶 6。反向推演：生产路径目击距离受视野闸门约束本就 ≤ 视野半径，封顶分支是防御性口径；若未来播种 / 接触记录写入超视野距离而封顶失效，半径距离项会冲破兵种视野，模糊圈失准。
5. 断言⑤ 同格平局（`B9-R2-5`，`:715`）：`TIE_JSON` 两支敌军 b1 / b2 同格 `(12,8)`；`perceivedEnemiesOf("a1")` 中两条目都在、位置相同、不按位置合并；推进一回合裁决不抛，快照保留两支敌军视图且均标记观测。反向推演：若感知集按位置去重，同格两敌会被并成一条，最近目标选取丢失一军；若平局取用依赖不稳定顺序，回合间结果可能翻转。现有 `distinctBy { it.id }`（`CampaignController.kt:613`）按军 id 去重，`minByOrNull` 按列表顺序稳定取用，本断言锁这两条口径。
