## 七、二阶 / 三阶影响推演

### 7.1 等长归名物策略不变前提下，新门禁会不会让原本能出泡的候选消失

- 情形 A：B25 五态兜底壳（空数据 / 离线缓存未命中 / 缺年份 / 消歧失败 / 超时）。适配层正常路径已在 `:49` 过滤，壳本就到不了仲裁器；新门禁只在适配层被改动 / 穿透时兜底拦截。当前 `EmptyEntityProvider` 空数据状态下行为零变化：artifact 仍返 null，word 候选正常胜出。
- 情形 B：真实条目但 `source` 为空串 / 纯空白。按协议（`BubbleModels.kt:92` KDoc「每条数据必须带来源与版本」）此类本属残缺件；旧逻辑会凭 token 长度让它参与仲裁，新逻辑下钻到 word / char / Missing。受影响对象：未来数据装配时漏回填出处标注的名物条目——它们不再出名物泡，改由词槽或兜底承接。这是收紧而非回归；数据组装单须保证真实命中 source 非空。
- 情形 C：真实条目 `source` 恰好等于字面量「未命中」。不可能：`MISSING_SOURCE` 是未命中专用标记（`BubbleContractModels.kt:128-129`），真实出处标注（书名 / 库名 / 收录号）不会取此值。
- 情形 D：`kind` 维度漏网。artifact 槽若漏出 person / place / allusion 类别件，只要 `source` 非空，当前门禁仍放行；这是残留缺口，挂账：待契约层 kind 白名单或 tier 字段接入后在仲裁器内补类别裁决。
- 情形 E：word 侧候选未做同源校验。word 槽当前由 `WordProvider` 经字典内存索引产出，`source` 来自词条条目；若未来 word 侧接入会返壳的 Provider，需对称加固门禁。本单未扩到 word 侧，挂账。
- 三阶影响：门禁拦截后下钻路径与既有 null 下钻完全同构（`artifact == null → return wordHit`），不新增缓存分支、不新增异常路径；`MissingProvider` 兜底仍在链尾，不留空白态。

### 7.2 性能增量

- 门禁成本：每次仲裁一次 null 判断 + 一次 `isNotBlank()` 空白扫描 + 一次 `source != MISSING_SOURCE` 字符串比较；`isNotBlank()` 走字符空白判断、不产生 `trim()` 副本（`SlotArbitrator.kt:71` 注释），无集合分配、无字典查找、无循环。
- 调用频次：一次 `resolve` / `queryToken` 只触发一次仲裁，门禁常数级；不随段落长度、候选数量放大。
- 相对 B35 既有增量（artifact 命中时多一次 word 索引查找，见验收报告 §6.2），本单新增成本可忽略；冷启 ≤300ms / 热路径 ≤80ms 预算口径不变，真实数据落地后随 bench 同口径复测。
