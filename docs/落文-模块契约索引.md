## 0. 三层分离 + 四条硬规则（防腐设计，最高优先级）

### 三层（各自职责不可混用）
1. **导航层（可有损）**：索引/摘要只回答"细节在哪里"——位置 + 状态 + 依赖 + 版本号。摘要丢细节无所谓，因为它**从不被用来干活**。
2. **执行层（无损）**：原文一字不动、只做物理切片；子 AI 拿到的是"读原文第 X 段到第 Y 段"的指针 + 原文本身，逐字照做。解决上下文超限靠"每次只读一小段"，**不靠把大段压成小段**。
3. **验收层（逐字对照）**：总控/验证 AI 对照的是原文全文（不是摘要）。每条规格必须被某个子 AI 的输出完整覆盖，逐条核对，不许"看着差不多"。

### 四条硬规则
1. **锚点强制**：任何摘要条目必须带原文锚点（文件 + 段落号/行号），任何环节一键回源。类比 Git：commit message 可以烂，blob 内容永远无损可查。
2. **三类内容禁止压缩**：规格说明、接口契约、验收标准——永远全量传递、逐字保留（这是"结果与规则"，不是"过程"）。
3. **只压缩过程**：允许摘要的只有"已完结的过程"——旧讨论记录、失败尝试、日志。过程可丢，结论和依据不能丢。
4. **子 AI 禁止自行摘要**：子 AI 的输入输出都走原文切片 + 结构化结果（diff/补丁），不允许"理解后转述"。转述就是丢细节的开始。

### 1.3 派生语义色（S-12 画板六色收口，不新增第 13~15 个基础色）

## 1.5 美化与感官引导（好看 = 硬验收项，不是可选项）
> 本节是「统一规范」的美学延伸：每个 UI / 3D 子 AI 派单时，除功能契约外，还必须按本节把「好看」做对。观感不达标 = 打回重做，与功能 FAIL 同级。

### A. 美学总纲（用户原文，逐字保留，不许改写/降级）
你是落文的设计执行 AI。在实现每一个功能、每一个页面、每一个组件时，自动套用以下美学标准。不要等指令，自己主动提升。

- **气质**：东方美学。绢帛古韵。克制留白。像一个古人设计的现代 App——不是复古贴图，是骨子里的雅。
- **颜色**：纸白、墨色、朱砂、暖金。全站只用这四个色系。暗处偏暖不偏冷。金是沉金不是亮金。禁止 Material Design 色值。禁止纯黑纯白。
- **材质**：纸的纹理、磨砂玻璃的雾感、暖光在绢帛上的渐变——所有表面都有触感。不是扁平设计，是有厚度的平面。
- **动效**：弹簧质感——有弹性但不跳脱。东西出现不是弹出来，是浮上来。东西消失不是闪没，是散开。所有动画用缓动曲线，禁用 linear。
- **空间**：一层一层推进去——阅读页在最后面，气泡浮在阅读页上面，Sheet 浮在气泡上面，毛玻璃遮罩让后面那层还在但不打扰。Z 轴深度感比横向布局更重要。
- **字体**：正文竖排用宋体。数字用等宽。小字无衬线。不混用超过三种字体。
- **组件**：每一个按钮有悬浮态、点击态、禁用态。反馈是朱砂色浸染，不是机械高亮。加载是三个金点依次亮灭，不是转菊花。
- **一句话**：古典不是贴图贴出来的，是把一切拿掉之后剩下的那个字。每一个像素都要好看。

（落地锚点，3D/地图模块对齐六要素）绢帛军图、墨爆粒子、暖金辉光、磨砂毛玻璃、spring 动画、3D 地形隆起。

### B. 配色铁律（四色系 + 12 色 token 语境化）

### F. 「好看」验收（每个 UI / 3D 模块派单必带）
1. 任务书验收标准除功能断言外，必须含一条「观感」检查项：对照 A–E 的六要素/配色/动效/材质，列出本模块落点的美学要求，不能只写「美观」两字了事。
2. 视觉验收单独一轮（对照六要素逐项看，不是「看着差不多」）；观感不达标打回重做，与功能 FAIL 同级。
3. 不降级不砍功能：墨水屏模式 / 低端机降级分支照写，但默认路径必须满血美学。

### G. 落地细则（对总纲的优化补充——不改写 A 原文，把气质落到可执行、可防串味、可验收）
1. 字体（A「不超三种」↔ U9 五枚子集对齐）：三种 = 宋体（正文 Regular + 标题 SemiBold 同一种宋体）+ 无衬线小字（NotoSansSC-Light）+ 等宽族（数字 Inter / 典籍编号 JetBrainsMono）；不是「只能三个字体文件」。
2. 空间（A「一层一层推进去」落地）：固定 zIndex 阅读页(底) → 气泡 → Sheet → 遮罩(顶)；遮罩 bg-overlay `rgba(26,20,16,.45)`，毛玻璃 backdrop-blur 基准 12px，不另造透明度色值。
3. 组件（A 三态补全六态）：默认 / 悬浮（暖金阴影增强）/ 点击（朱砂浸染）/ 禁用 / 加载（三金点 600ms）/ 空数据（EmptyState，不留空白）。
4. 美学禁区（反例清单，防审美漂移）：禁 Material 色值与默认组件、禁纯黑纯白、禁 linear、禁菊花、禁 iOS 式大圆角、禁霓虹/镭射渐变、禁 emoji 当图标、禁系统默认 drop shadow/elevation。
5. 好看不牺牲性能：粒子/辉光/毛玻璃全在红线内（翻页≤16ms、球面 55fps 手机/120fps 桌面、内存峰值≤100MB、首开≤800ms）；低端机降级分支照写、默认满血。内存三档判据见 F-04：≤100MB 过；100–120MB 注「待优化」；>120MB 打回（2026-11-24 订正，取代旧 ≤180MB 红线）。
6. 可 grep 验收判据：UI 域无 `#` hex 硬编码（12 token 定义处除外）、无 `linear` 缓动、曲线命中切片-15 表、字体语义族 ≤3、无 Material 色值/默认组件引用。

### 分页引擎（横排 / 竖排双模式）（已冻结）
- `VerticalLayoutEngine.layout(text, viewWidthPx, viewHeightPx)` / `hitTest(x, y): CharHit?` / `invalidateCache()`（不许改签名）

- **横排模式入口**：分页引擎横排参数（`PageDelegate` 横排模式）为契约允许的既有能力；D20 现代文学只启用横排模式、追加现代文参数（首行缩进 2 字、横排段距、底部横线进度条），**不改引擎核心签名**。
  > 为什么/适用条件：旧标题把"竖排"误当成被保留的引擎本体，易被下游理解成横排需另开新布局；本契约只冻结分页算法与三签名，排版方向以模式参数区分。
