## 四、二阶 / 三阶影响

### 4.1 二阶（本模块内）

- 28 组矩阵把「天候 × 路况」组合锁成精确值契约：未来任一档被改回 >1、或两档数值互换，`assertEquals` 立即报红；旧纯方向断言在「两档同时改小」时会漏网。代价：标定值被固化，规格若重标定需测试与实现同批改。
- 符号注释直接写在两个消费点（速度侧乘法、代价侧倒数）旁，后续重构把 `/weather` 改回 `*weather`、或漏乘 `terrainSpeedFactor` 时，注释与矩阵用例双向拦截。
- 无签名变更：`marchSpeed` / `enterCost` / `weatherModifier` / `terrainFactor` 签名均未动，生产调用点零适配。

### 4.2 三阶（跨模块调用方 / 文件）

- **预算链**：`CampaignController.kt:686 dailyMaxCells`（出口）→ `:688 marchSpeed`；`:442` 回合行动预算 `budget = dailyMaxCells(corps)` 读同一出口；`:191` `MoraleSystem.advance(corps, marchCells, dailyMaxCells)`，疲劳比在 `MoraleSystem.kt:38` 以 `marchCells/dailyMaxCells` 计算。本单未改这三处，速度口径被测试锁稳后，疲劳增长比率的输入随之稳定。

- 无新依赖、无新线程、无持久化结构变更。

## 五、反例与边界（先假设本方案错误）

- **空数据**：`condition = null` / 空串 / 未知串 → `else` 归 1.00；边界用例覆盖 `null` 与 `"drizzle-unknown"`。`trim().lowercase()` 已处理大小写与首尾空格（既有别名用例 `"  OverCast "` 锁定）。
- **零速度**：`fatiguePenalty = 1/(1+0.12·fatigue)` 恒正；`speedBase > 0`；天气因子 0.60–1.00、路况因子 0.40–1.00，`marchSpeed` 不会为 0；预算出口 `dailyMaxCells` `coerceAtLeast(1)` 保底 1 格。极端疲劳 f=100 复算 ≈0.02308，仍为正。
- **极端天气**：最坏 snow 0.60；矩阵断言任一组合 `≤ speedBase` 且 `> 0`，不允许 >1 加速；单调链 `clear≥fog≥wind≥rain>snow` 双向锁定。
- **NaN**：入参是 `String?`，`trim/lowercase` 不产生 NaN；疲劳为有限 `Double`；边界用例 `assertFalse(isNaN())`。未覆盖分支：`condition` 传字符串 `"NaN"` → 归 `else` 1.0（不折减），属可接受兜底。
- **反例自查**：若折减方向应反过来（顺风提速），则与原文 §三 L80「行军速度 = 基础速度 × 路况系数 × 疲劳惩罚」及 B2 判据「恶劣天候必降速」冲突，不成立；地形速度因子取 `terrainFactor` 倒数，与寻路代价方向互补，已由两条单调链分别锁定。
- **涉渡水面**：`terrainSpeedFactor(WATER) = 1/3.0`；非涉渡水面由 `passable` 拦截、不会站上速度预算。涉渡格速度因子未入本矩阵（见未验证项）。
