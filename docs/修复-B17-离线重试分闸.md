## 1. 缺陷与本单结论

- 缺陷原文（`docs/验收-Q53-空态压淡.md` §6.4）：组件库离线重试入口被禁点闸连带短路——`InkEmptyState.kt:61-66` 把 `offline=true` 透传给重试 `InkButton`，按钮随 OFFLINE 一并 `eventsAllowed=false`，`InkInteractionState.kt:75` 抬起不触发 `onAction`；断网时用户看得到「重试」却点不动，错误恢复主链路成死路。
- 本单结论：**分闸，不放宽闸**。容器本体 OFFLINE 禁点的契约语义保持不变；重试按钮作为独立恢复入口，通过显式形参 `standaloneInteractive` 独立于容器闸放行自身点击。不改 `ComponentSystemContract.kt` 的 OFFLINE 枚举值——契约值是全局语义，改它会让所有 OFFLINE 组件都变成可点。
- 设计口径：禁用（`enabled=false`）与加载中仍是硬闸，独立入口不凌驾其上；EMPTY 态语义本单不动。

## 4. 单测清单（`InkEmptyStateRetryGateTest.kt`，纯 JVM）

- `离线重试入口 独立放行点击`：OFFLINE + `standaloneInteractive=true` + enabled + 非 loading → 放行（对应 DoD 1「OFFLINE + 点重试 → action 触发」的闸口判定）。
- `离线容器本体 空白区域 仍不触发点击`：OFFLINE + `standaloneInteractive=false` + enabled → 不放行（对应 DoD 1「OFFLINE + 点容器空白 → 不触发」）。
- `契约离线档事件许可仍为 false 全局语义未改`：契约 `OFFLINE.eventsAllowed == false`、`contentAlpha == 1f` 回归断言。
- `独立入口在真正禁用时仍被拦住`：DISABLED + `enabled=false` + standalone=true → 不放行（禁用硬闸优先）。
- `独立入口在加载中仍被拦住`：LOADING + `loading=true` + standalone=true → 不放行（加载硬闸优先）。
- `空数据档仍按契约放行 语义不变`：EMPTY + standalone=false → 放行（DoD 2：EMPTY 口径不动）。

说明：app 模块 `testImplementation` 仅有 JUnit + Mockito，无 `compose-ui-test-junit4`，故手势回调的 Compose 层触发链路无法在本地纯 JVM 起 `ComposeTestRule`；本单把闸口判定抽成纯函数 `resolveEventsAllowed` 供 JVM 断言，Composable 接线（形参透传链）以 §3.1 grep 回证。
