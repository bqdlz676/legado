## 四、三节

### 二阶三阶影响
- 直接：parse 异常被顶层 catch 兜到 assembleDegraded；装配异常可被测试桩触发。
- 连带：catch 多 null-definition 分支，依赖 `degradedFallback()`；壳层只读 warnings/degraded，契约未变。
- B9 共存：降级态 corps 为空，`seedIntel` 空转、`perceivedEnemies` 空集，与既有空战场口径一致，情报表不被污染。
- 复杂度：新增 1 internal 桩 + 1 internal 工厂，均带注释；无新公开 API。

### 反例与边界
- parse 抛 StackOverflow / 深层递归：catch(Throwable) 兜住，degradedFallback 不二次解析原始 JSON。
- assemble 抛时 definition 已存在：保留原 parser 警告再拼失败文案，不丢历史 warning。
- rivers=null 与 rivers="x"：两条不同文案分别命中；jsonArray 守卫对 JsonNull 返回 null，不进 forEach。
- 桩未复位：测试 finally 置 null；companion 变量跨用例共享，复位是硬约束。空 JSON / 断网：parser 既有 fallback 路径不变。

### 认知成本
- 新增概念：assemblyFault（测试桩）、degradedFallback（空 warnings 中立定义）；命名自解释，注释写明"生产恒 null / 调用方追加原因"。接手者只需知道 load 全链 try 兜底、桩仅供单测，无抽象层叠加。
- 风险点：internal 同包可见，后续同包测试误用桩需靠注释约束。
