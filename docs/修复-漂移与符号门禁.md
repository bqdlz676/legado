## 二、两门禁判据

### 门禁一 锚点行号（g62，audit）

扫描 `docs/**/*.md`，排除原始切片目录、锚点卡目录与原文转储目录。锚点形态含 `path.kt:NN`、`path.md:NN`、`path.kt:NN-MM` 区间；无文件前缀的裸区间按上文最近一次完整锚点归属文件，归属不到上下文则跳过不猜。

- DEADFILE（FAIL）：文件按仓根相对路径或唯一基名解析后仍不存在。
- OUTOFRANGE（FAIL）：文件存在，但行号超出该文件总行数。
- SUSPECT（WARN，不计退出码）：落点行为空白、纯花括号收尾行、纯注释分隔线或 Markdown 分隔线，多半是漂移后的残骸落点，列出来交责任人回修。
- 白名单 `docs/.line-anchors-allow.txt`：制表符四列「引用文档 / 锚点串 / 理由 / 登记单」；理由列缺失即 BADALLOW FAIL，豁免必须写明为什么这条锚点可以不回源。

末行判定格式见 `data_scripts/check-line-anchors.py:256`。

### 门禁二 符号存在配平（g63，blocking）

扫描 `app/src/**` 与 `screenshot/src/**` 的 `.kt`；定义索引覆盖 `.kt` 与 `.java`。位点分顶层函数、扩展函数、类内成员、主构造、Java 符号五类；成员与 Java 符号只做名字存在性参考，不参与参个数配平（静态闸解析不出接收者类型）。

- NODEF（FAIL）：自有包 import 进来的名字，仓内索引反查不到任何 fun 或类主构造定义。
- ARITY（FAIL）：同名定义存在，但可核对的顶层或扩展重载无一容纳本次调用实参个数；定义处无 vararg、无默认参、无匹配重载。
- 重载放行：同名多定义时任一重载可容纳（个数相等，或 vararg、默认参兜底）即放行。
- 跳过并计数：生成符号 `R.*` 与 `BuildConfig.*`；外部库 import 前缀；标准库与测试框架白名单；接收者类型未知的名字归未知跳过，不硬判。

末行判定格式见 `data_scripts/check-symbol-existence.py:553`。事故实例定义在 `app/src/main/java/io/legado/app/ui/config/b3/B3SettingModels.kt:65`，一参扩展 `matchesB3Query`，事故提交 `87c7e0d` 曾被四参调用。

## 六、自查反例

- 反例一：若 SUSPECT 把所有普通注释行都判残骸，一份验收报告会刷出几十条假红，门禁失去可信度。现口径只判空白、纯花括号、纯注释分隔线与 Markdown 分隔线，普通 KDoc 与注释行是合法落点。
- 反例二：若主构造形参也参与参个数配平，data class 调用会被误解析的 ctor 形参错配，刷出上千条假红。现口径主构造只做存在性参考，不进 ARITY 候选。
- 反例三：若跨文件把 private 顶层 fun 也放进全局候选，私有同名符号会错配到别的文件定义上。现口径 private 定义只在本文件可见，跨文件不进候选。
- 反例四：若白名单允许只写锚点不写理由，位置型豁免改名即可蒙过。现口径缺理由列直接 BADALLOW FAIL。
