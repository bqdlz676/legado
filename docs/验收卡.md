> 这张表与 `docs/写码卡.md` 同号对齐：`V-0NN` 只验 `W-0NN`，验收代理只拿自己那一张，从别人的卡上看不到任何东西。

## 卡上字段

1. 所属模块：与配对的 W 卡一致。
2. 只读文件域：与配对 W 卡同一域，但只读，禁任何写入。
3. 判据条数：锚点卡"判据"段条目数；超 4 条会把验收代理逼成"讲过程不讲结论"。
4. 前置卡：永远是它自己的 W 卡。
5. 判据锚点：与 W 卡同一锚点。
6. 配对写码卡：同号 W。
7. 状态：`待验` / `在验` / `过` / `不过` / `缺锚点`。写 `过` 必须填证据（`文件:行号` 或 CI `run id`）。
8. 批次 / 车道 / 失败归因：调度列，初始态全填 `—`；车道可选值只允许 `验证` / `打包`，未定时写 `—`。

## 判废链

判不过只在下方加 `V-0NN-R1`（配 `W-0NN-R1`），原排保留记 `不过`；三次不过退回重拆卡。

## 全卡通用纪律（每张 V 卡判定时必读，不重复写进 36 张卡）

以下四条对所有验收卡生效，卡表不单设列——它们是"所有判定的共同前提"，不是某张卡的专属判据：

1. **F-113 禁人工归因**：判定依据只能是文件逐行 diff（`docs/归因/期望-B-00N.txt` 对照实际产物），不许写"我看过了没问题"。人的印象不可回源，diff 可以。
2. **F-114 dry-run 双批**：归因类判定必须跑 `python3 data_scripts/attribution-dryrun.py --all --check`，单卡批作对照、多卡批作样本；只跑一批等于只证幂等，不证泛化。
3. **F-115 期望文件一次写定**：期望文件落盘后只 diff、不改期望。发现期望与结果不符时先怀疑代码，不许反过来改期望去迁就——那等于自己改考卷。
4. **F-116 轨别**：判定前先看 `check-push-track.py` 的轨别；A 轨（文档）验收通过后才允许 push，B 轨（代码）push 后以 CI 绿红为准，验收卡只补人文判断。
