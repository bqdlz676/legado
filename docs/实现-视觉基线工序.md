- 丢失条目反例实测：基线追加一条指向不存在帧 `screenshot/does-not-exist-frame.png` 的登记 → `FAIL 观感基线被破坏：screenshot/does-not-exist-frame.png 已丢失（冻结屏/资产不存在）`，汇总 `1 项丢失、0 项哈希不一致`，RC=1；基线恢复后复核 PASS。
- 设备档不支持：NEXUS_5 为 Paparazzi 内置档；若 CI layoutlib 不支持该档，迂回口径＝降级到 `DeviceConfig.PIXEL` 并在 `frames-baseline.json` 记录档位变更与原因，帧清单同步改档；禁止跳过对应帧只在报告里写「已生成」。
- 整壳渲染宿主依赖：`MainShell` 含 `BackHandler` 返回拦截、`rememberSaveable` 壳态与 `AnimatedContent` 转场，依赖 Activity 返回栈 owner 与状态注册表；纯 JVM Paparazzi 宿主是否提供这两项未验证。本单只渲染可脱离宿主的 `ShellBottomBar` / `ShellPageSlot` 公开件，整壳帧列入未验证项（见问题一），不冒险在夹具里拉整壳。
- 设置槽页屏宿主依赖：`ShellPageSlot(SETTINGS)` 直挂 `B3SettingScreen`，`rememberB3SettingActions()` 组合期捕获 `appDb` 单例、FileUtils、AppWebDav、`context.getDir(...)`，开关行经 `PreferenceManager.getDefaultSharedPreferences` 读偏好；纯 JVM Paparazzi 宿主无 Application / Room / 偏好实现，composition 即崩。本单不出设置槽页帧（底栏设置 Tab 选中态仍由 `shellBottomBarSettings` 覆盖），设置页本体帧列入未验证项（见问题七）。
- 空数据 / 断网：截图夹具不灌业务数据、不发网络请求；书架 / 发现两槽空态由 `InkEmptyState` EMPTY 档承接，离线 / 加载档位由组件内部按契约解析，夹具只灌态不接管手势。
- 最强反例自否：假设「把尚未存在的 PNG 路径先写进基线也算补齐基线」——否证点：`verify()` 对丢失条目判 FAIL（判据 3），登记幽灵路径只会让门禁 52 变红；故本单基线只登记仓库内真实存在且哈希匹配的源码契约件，不登记未生成帧。
- 并行域反例：`ui/components/**`、`ui/card/**`、`ui/main/shell/**` 为只读生产域；本单按当前工作树签名调用，未改组件 / 卡片 / 壳源码；若在飞签名变化，CI 报签名不匹配时交对应组件批次收口。
- 暗色 / 横屏 / 字体缩放：本单未出对应帧，观感不判通过。

## 认知成本

- 两套帧清单不要混：`screenshot/frames-baseline.json` 是本单提交的**期望帧契约**（静态、在册、被基线哈希冻结）；`frames.json` / `frames.md` 是 CI 上 `frame-manifest.py` 生成的**实测帧产物**（在 build 输出目录，不入库）。接手人先分清前者是期望、后者是实测回填。
- 基线双层：`.visual_baseline.sha256` 本轮登记源码契约层；PNG 帧哈希层留待冻结通过轮。读基线文件时勿把源码条目误读成「帧已冻结验收」。
- 帧名口径：包名点号转下划线 + 类名 + 方法名；清单 `frameName` 字段与 Paparazzi 落盘名一一对应，改测试方法名必须同步改清单条目并重新冻结。
- 简化动作：新夹具各自私有 `Centered` / 布局件，沿用既有四套测试的局部helper惯例，未向 `ScreenshotFixtures.kt` 塞共享抽象；两个新文件分别 96 / 136 行，均低于 600 行棘轮。
