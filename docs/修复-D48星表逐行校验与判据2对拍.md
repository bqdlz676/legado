## 六、自查反例与边界（改坏推演 / 最强反对者视角）

- **为什么不用抽样**：规格 `docs/星空天象层-实施规格-合并定稿.md:316` 原文「内置行数以导入日志校验 = mag≤6.5 全量，不许抽样」；8920 行里越界暗星可能只占个位数，抽样无法保证不漏；逐行解析成本在秒级，没有抽样的性能理由。反例若成立——抽样能代表全表——前提是异常均匀分布，而星等越界/重复主键恰恰是局部簇发，抽样口径不成立。
- **为什么 1° 是合适阈值**：`docs/星空天象层-实施规格-合并定稿.md:312` 冻结口径即「误差 ≤1°」；闭式上中天用例理论误差为 0，1° 容差覆盖透视反演的浮点与坐标还原噪声；若压到 0.01°，反演链路的除法/开方噪声会把正确实现误判红；放到 5° 又失去抓公式符号颠倒的能力。
- **空数据 / 缺字段**：0 行触发行数区间判红；某行缺 `magVt/raDeg/decDeg` 键时计入 `parse_failure` 而非崩溃；`NaN` 与空串分流到非有限 / 解析失败两类，不混计。
- **断网**：脚本只读仓库内 CSV，无网络依赖，断网不影响校验。
- **反对意见：catalog 与 pyramid 两脚本重复造校验**。成立一半：L0 段两套坐标/星等/主键检查确有重叠；但本单域禁改 `data_scripts/astro_check_pyramid.py`，下沉共享模块属重构另单，见交接项 N3。
- **退化边界**：坏样本中 mag=7.0 行若同时坐标越界，两类计数各自落账，一行坏不藏另一类缺陷（沿用 pyramid 闸 `data_scripts/astro_check_pyramid.py:180` 注释口径）。
- **改坏推演**：若投影器时角取成 RA−LST、`sinAlt`/`cosAz` 符号颠倒、或赤纬钳制错位，反演 alt/az 会偏离上闭式期望值超过 1°，`app/src/test/java/io/legado/app/ui/map/globe/astro/contract/SkyContractTest.kt:371` 两条 assertEquals 对应星例变红；若注入入口没接进 `nextFrame`（仍读墙钟 utcMillis），`app/src/test/java/io/legado/app/ui/map/globe/astro/contract/SkyContractTest.kt:445` 的 LST 比对按 0 时刻算出，偏差数百度变红。
