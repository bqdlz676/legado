### 判据 5：语义冲突登记（REMOVED 段 canOpen 口径） —— PASS，建议保留旧语义

任务书原写「REMOVED 段 canOpen=false」；实现保留 B21/B26 旧语义：`canOpen = phase != EXITING`（`SheetExitPhaseGate.kt:90-91`），即 OPEN / REMOVED 放行，仅 EXITING 拒收。报告 §五（:244-247）与 §七.4（:269）已登记该口径分歧。

独立判断：**保留旧语义更正确，建议不改。** 理由：

1. `REMOVED` 语义是「离场动画已收束、子树可摘除、会话已结束」，闸处于空闲可接新会话状态；`canOpen` 回答的是「当前是否允许起新会话」，空闲段必须放行，否则弹窗 / 半屏收束后将永远无法再次打开，只能靠外部重置阶段。
2. 「离场动画播放中不叠新浮层」由 EXITING 段 `canOpen=false` 承担；「在场段不叠第二个节点」由宿主 `tryOpen()`（仅 REMOVED 放行，:56-60）与 B20 在场判重闸承担。三段职责分工清晰，REMOVED 段再置 false 会把「空闲可重开」误判成「永久关闭」。
3. 旧语义有既有断言锁定：`NoteDialogExitGateTest.kt:27/:39/:79/:107`、`ReaderSheetExitGateTest.kt:33/:47/:91/:120`、新增 `SheetExitPhaseGateTest.kt:60/:96/:116` 均断言非 EXITING 段 `canOpen=true`；改成 REMOVED=false 需同步返工五条以上既有断言，属语义变更，报告 §七.4 已列为另单，登记位置正确。

判据 5 PASS；结论为「保留」，不含糊。
