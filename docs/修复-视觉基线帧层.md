## 一、改了什么（问题三问）

### 1. 改了什么

- 基线登记从单层源码形状扩为双层：源码层登记测试套件源码与帧契约清单文本；帧层登记 CI Paparazzi 产出的 golden PNG 帧像素哈希。格式向后兼容，存量 8 行源码登记原样可解析。
- 判据分级：帧哈希不符判 FAIL；帧已登记但 PNG 缺席判 WARN 并逐条点名帧标签与路径，不许静默；源码层既有语义（丢失 FAIL、失配 FAIL、无基线 WARN）保持不动。
- --freeze 双层落盘：PNG 存在时按帧层登记哈希与标签；PNG 本地缺席时只登记源码层，不报错、不写幽灵帧条目。
- selftest 从两向扩到五向，临时目录 tempfile.mkdtemp 造夹具，finally 自删。

### 2. 为什么这么改

- 存量基线 0 条 PNG 帧，只能发现源码与清单文本漂移，锁不住画面像素漂移；上游验收报告 docs/验收-复核-视觉基线工序.md:141 已把该缺口挂账入队。本单把帧层登记面与分级判据先立起来，待 CI 出帧、人眼复核通过后即可直接重冻登帧。
- 帧由 CI artifact 产出（.github/workflows/screenshot.yml:103 上传 screenshot-frames），仓内本地常态无 PNG；新格式必须能接受本地无帧，不能把本地门禁打红，所以帧缺席降级 WARN 而非 FAIL。
- 标签用 frame: 前缀与源码层行同文件混排，解析器按前缀分流两层，不必另开基线文件；标签组/方法名取自 screenshot/frames-baseline.json 的 block/method，清单查不到时回落文件名，哈希复核通路不依赖标签。

- 三模式实跑：正常模式、--freeze（临时基线夹具）、--selftest，各贴真实末行与退出码（见第五节）。

## 二、双层登记格式约定与解析正则

- 源码层行（旧版逐字保留）：`<64位哈希>  <相对路径>`，标准 sha256sum 两行式。
- 帧层行（新增）：`frame:<组>/<方法名>  <64位哈希>  <相对PNG路径>`；组/方法名取自帧契约清单的 block/method；清单缺条目的 PNG 回落 `frame:<PNG文件名去扩展名>`。
- 注释行：`#` 开头；空行跳过。
- 解析正则（与 data_scripts/check-visual-baseline.py:64、:65 实现一致）：
  - 帧层：`^frame:(?P<label>\S+)\s{2}(?P<hash>[0-9a-f]{64})\s{2}(?P<path>\S.*)$`
  - 源码层：`^(?P<hash>[0-9a-f]{64})\s{2}(?P<path>\S.*)$`；双空格切不开时回落空白切分（兼容旧行）。
- 条目结构：load_baseline 返回 dict，含 layer（src/frame）、hash、path、label 四槽；内部消费方只有 verify，无外部脚本解析该基线文件。

## 三、逐分支退出码（逐条陈述）

- 分支 1：基线文件不存在或为空 → WARN，退出码 0（工序未启动，不算 FAIL，既有语义）。
- 分支 2：源码条目文件丢失 → FAIL 点名路径，退出码 1（既有语义）。
- 分支 3：源码条目哈希不一致 → FAIL 点名前后 12 位，退出码 1（既有语义）。
- 分支 4：帧层 PNG 存在且哈希一致 → 计入匹配，不单独出声。
- 分支 5：帧层 PNG 存在但哈希与登记不符 → FAIL 点名帧标签与路径、前后 12 位，退出码 1。
- 分支 6：帧层已登记但 PNG 本地缺席 → WARN 点名帧标签与路径，退出码 0；同次复核另有 FAIL 项时退出码仍为 1，WARN 行照常列出。
- 分支 7：无任何 FAIL、仅帧缺席 WARN → 退出码 0。
- 分支 8：源码层 + 帧层全匹配 → PASS，退出码 0；无帧条目时保留旧版 PASS 文案口径。

## 六、二阶三阶影响（含反作用推演）

- 一阶（直接效果）：门禁 52 现在认识帧层；帧像素漂移在有 golden 帧登记后可被哈希抓到；本地无帧常态不被打红。
- 二阶（相邻环节）：CI 出帧并经人眼复核通过后，需用 --freeze 登记帧目录与清单产物哈希；清单回填 width/height/sha256/bytes 后必须重新冻结，否则基线仍指旧清单。帧标签依赖帧契约清单，清单增删帧条目后重冻即可对齐。
- 三阶（流程节奏与维护成本）：后续加组件态或主槽固定链路＝补测试方法 → 清单补条目 → 重冻；不新增平行脚本、不另造帧目录惯例。
- 反作用（必须直面的风险）：帧层一旦锁死，每次视觉改动（含刻意的美化调整）都会让帧哈希失配而 FAIL，倒逼每轮都要重新 freeze。这可能诱发两类随手 freeze 绕过：一是未过人眼复核就本地重冻，把漂移帧当成新 golden 写进基线，门禁退化为自证；二是把帧缺席 WARN 误读成可以长期不补帧，帧层空挂。缓解口径：freeze 只允许在人眼复核通过轮执行（规格 docs/工序-观感打磨.md 观感冻结节）；帧缺席 WARN 必须在 CI 出帧批次闭环；后续批次可评估给 --freeze 加轮次备注留痕与复核人锚点，本单未做该加固，列入第九节待裁。
- 四阶（防伪造）：登记面只含仓库内真实存在文件；幽灵 PNG 路径在缺席通路 WARN 点名；脚本不存在改判据永远绿的通路。反向风险：源码层 + 帧层全绿也不等于观感通过，冻结轮之前人眼/像素复核缺位时不得拿门禁 PASS 充当观感结论。
