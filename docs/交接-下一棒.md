## 五、坑（已验证）

- 公开仓：Actions 分钟免费；"两个 GitHub 账号两台 CI"纯属自找麻烦（并发不是瓶颈、镜像双烧、状态分叉）。
- 沙箱 2 核 3G 9.6G、JDK11、无 Android SDK、无依赖缓存 → 不能本地编译，只能静态机检 + CI。
- 连续快推会被 `cancel-in-progress` 取消（`16bc12b` 的 Verify 就是 cancelled）。
- 并发上限 5 个 subagent，第 6 个直接报 limit；满槽时调度层自己动手而不是空转。
- 多代理并行读 git 会产生 0 字节 `.git/index.lock`；确认无 git 进程并等它消失再重试。
- `git add docs/` 会带走别人在飞改动；`git status --porcelain` 中文名要 `-c core.quotepath=false`；`git checkout HEAD -- file` 在锁存在时失败。
- Bash 里 `cmd &` 起的后台进程随调用被杀，后台跑用 run_in_background。
- `acceptance-evidence.py` 全仓模式很慢（扫所有 kt），验收时用 `--paths` 或小 `--rev` 样本。
- `docs/` 里曾混进测试夹具导致回执机检 FAIL，夹具只许放 `data_scripts/fixtures/`。

## 六、口径（不许改）

进度只报 HEAD commit 与 CI 绿红两个布尔；不报百分比、不报 APK。写→验收→push→CI→CI 后再验收，两道都过才算完成。写码与验收代理一次性用完即弃，禁自评代验收。改动后先 grep 回证再报完成。CI 红时停发新功能单，全队先修红。豁免必须打印、不许静默；基线只许手动下调，脚本不许自动抬。
