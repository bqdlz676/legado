# 修复-雷达路径锚假失联（W-436：反引号路径被当成符号，890 条假红 → 629）

> 一句话：漂移雷达把报告里 `` 仓内某路径 + 行号 `` 这种**路径锚**截成 `app` 当符号候选，目标行自然没有 `app`，于是判 MISSING「符号全文件失联」。这类假红累计 261 条，把「失联只增不减」的棘轮长期顶在红线上，诱使后来人去改历史报告洗红。

## 一、缺陷现场（先取数）

## 二、根因（第一性原理：候选符号怎么来的）

`idents_of()` 用 `IDENT_RE = [\`*]{1,2}([A-Za-z_][\w.]*)[\`*]{1,2}` 取反引号内容，字符类只含 `\w.`、**不含 `/`**。于是：

- 报告写 `` `app/src/main/java/io/legado/app/help/chrono/Chronology.kt` + 行 521 ``，正则只吃到 `app`（到第一个 `/` 截断），`app` 长度 3、不在 STOP，成为候选符号；
- `check_anchor()` 在第 519–521 行窗口里找 `app` → 没有 → 转全文件找 → Chronology.kt 里也没有独立的 `app` 词元 → 判 `MISSING 符号全文件失联`。

同源污染还有 `hint` 提取：`re.search(r'\`([A-Za-z_][\w.]*)\`', line)` 对同一串也只吃 `app`，把 hint 也定成 `app`，等于给假候选再加一票。

实测这两处的直接代价：`docs/修复-g67语料断言闸.md:61/:84`、`docs/修复-g67语料断言闸.md:84` 三条锚点，指向的 `Chronology.kt:521` 与 `InkBubbleRouteResolverTest.kt:63` 都真实存在、符号也命中，却被判失联。

## 三、方案与被拒方案

采纳：**反引号内容先整段取出，再判断是否为路径锚**（含 `/` 或 `:` 或代码扩展名一律不入候选），符号从剩余反引号里切词；`hint` 同样跳过路径串。

- 为什么先取整段：`IDENT_RE` 的截断发生在字符类里，任何「事后检查 group(0)」的写法都看不到被截掉的那半截，只能在更外层先把整段内容拿到。
- 为什么不直接改 `IDENT_RE` 的字符类（把 `/` 加进去）：那会让 `group(1)` 直接拿到整条路径，`split('.')[-1]` 得到 `kt`，仍然错，且动摇 DRIFT 判定的既有口径。

被拒方案：

1. **改历史报告洗红**（给 261 条加「已废」）：违反红线（历史报告语义只许加「已作废→以 X 为准」），且治的是症状——判据错却让证据背锅。
2. **上调 drift-baseline.json 到 890**：直接撞「债务棘轮不许上调基线」。
3. **把 MISSING 降级成 SUSPECT 只提示**：静默降级，禁。
