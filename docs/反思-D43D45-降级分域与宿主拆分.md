# 反思复盘 D43/D45（2026-11-28）

本单两条缺陷的根因复盘与可复用规则。每条含：机制、根因、反例、沉淀规则或自动化建议。

## 1. 聚合标量掩盖了子域独立性（D43）

- **机制**：离线档位把「地球仪态」与「星空天象」两套种类混在一个集合里算三档，一个标量 `degradation` 同时服务两个渲染 pass。
- **根因**：早期素材表只有一套兜底链，分 pass 是后加的；档位口径没跟着拆，沿用了单集合归纳。
- **反例**：星空三项未就位时，地球九项就位被聚合成 `CACHED_MIX`，地球纹理精度被错误压低；反向亦然。
- **沉淀规则**：凡一个标量被两个以上语义独立的渲染域消费，标量必须按域拆分（`x` / `skyX`），归纳函数接域参数；聚合视图只读自检，不参与档位决策。可自动化：lint 扫「档位枚举字段被两个 renderer 读取但只有一个装配点」给警告。

## 2. 壳文件随功能堆叠越过父基线（D45）

- **机制**：回放控制台五组件与地球 pass 几何都写在 `GlobeScreenHost` 单文件，组件没有自己的归属文件。
- **根因**：首次搭壳时把 Composable 都放在宿主文件最省事；后续每加一个 pass / 组件就继续追加，没有行数基线倒逼下沉。
- **反例**：630 行壳内混着手势编排、战役 chips、时间轴、路线几何、光针标签，改一个按钮要在长文件里找上下文。
- **沉淀规则**：宿主壳只保留状态提升、帧节拍、手势与挂载点；纯展示组件与独立绘制 pass 必须有归属文件；行数机检断言（≤基线口径）随拆分一并落地，不靠人记。

## 3. 拆分搬迁最易漏 import / 漏包（本单自查抓到一处）

- **机制**：组件下沉到新文件后，父包符号（`GlobeSpecSurface`）未随迁 import，文本层合法、编译期才红。
- **根因**：搬迁靠复制粘贴，符号出处没有逐类核对；机检 S8 对扩展接收者前缀的同名函数收集不到，存在假 PASS 缝隙。
- **反例**：`EarthGlobePass` 初版缺 `GlobeSpecSurface` import；若不在提交前人工对账包名，CI 编译才暴露。
- **沉淀规则**：拆分后必须做两步——①新文件每个大写符号对 import / 同包 / 标准库三类出处逐一过；②旧文件 HEAD 与新文件逐段 diff（去缩进）证明行为等价。扩展接收者函数在本仓机检下改显式入参，避免 S8 假绿。

## 4. 旧口径删除前先 sweep 零引用（A3 落地）

- **机制**：`realTextureCount()` / `fallbackCount()` 在主代码零消费方，属于旧聚合口径遗留。
- **根因**：上一轮分域改造只加了新路径，旧计数方法没同批清理，留成并行口径。
- **反例**：后续维护者可能误调旧计数方法，绕过新分域口径。
- **沉淀规则**：改口径同批 sweep 旧入口；零引用即删，不保留「也许以后用得上」的兼容层；同名方法跨类时（`TextureCache.realTextureCount`）单独登记归属，不混删。

## 5. 测试断言必须能指到具体红行

- **机制**：六条分域断言每条标注「改坏会红在哪一行 / 哪个断言」，空集、互换、完备性边界都有对应用例。
- **根因**：旧测试只断言聚合档位一个值，分域回归时测不出串档。
- **反例**：若用例只写「地球就位是混合以上」这类宽松断言，域过滤写反也可能绿过。
- **沉淀规则**：分域 / 分支类改动的单测，正反两侧各落一条；断言值取枚举精确值，不取区间；纯归纳逻辑（`levelFor`）抽成可单测纯函数，空集边界单独一条。
