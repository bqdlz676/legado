# 反思 · Crossing 引擎 B9 情报模糊半径

1. **做了什么**：在 `CampaignController.kt` 收口决策 / 展示双路情报模糊化——决策层感知集剔除无记录敌军、不回退真值；视图层未观测敌军主坐标走上次已知位置、盲区 NaN 占位 + 文案出口、路线清空；交战接触互刷情报并记时间戳；半径改为侦察 / 距离 / 时间三因子（`recordRadius`）；补 9 条单测。基线 main 工作区，未编译。

2. **踩的坑 / 教训**：
   - 上一轮 B9 骨架只模糊了"上报坐标 reportLat/Lng"，主坐标 `lat/lng` 和 `route` 仍带真值，壳层画棋子 / 路线直接读这两个字段——情报雾必须在控制器出口一次性把所有对外通道（主坐标、上报坐标、路线）都收口，漏一条就等于没做。
   - 情报表兜底最容易写成 `?: enemy.latLng` 图省事，这正是原始泄漏点；缺条时宁可让决策层"未知"（剔除感知集），也不能回读真值。
   - 测试夹具坐标要先按投影格距换算，同格 / 相邻 / 视野外三档要分开；接触战退却会让报告位与最终真值差一格，断言别强等值。

3. **我可能判断错的地方**：
   - 盲区用 `Double.NaN` 占主坐标是 model 字段非 null 约束下的折中；壳层若不门控，NaN 经投影 toInt 钳到边缘格可能画一个空棋子。最终是否该在 model 加 `blind: Boolean` 字段，需总控 / 验收定。
   - 距离项取 `seenDist/2` 是经验系数，没有战役数据校准；实战中距离与方位误差的关系可能非线性。
   - 9 条新单测均未本地执行，合成高程场的通视 / 行军方向可能让某条时序与预期不符，需 CI 结果复核。

4. **遗留未决项**：壳层按情报雾门控渲染（他人域）；`CorpsView` 半径 / 盲区文案字段扩 model（待批准）；出局敌军旧报告清扫；`fuzzyRadiusCells` 纯时间口径与 `recordRadius` 双口径待合并；B8R1 视野半径双表收敛。
