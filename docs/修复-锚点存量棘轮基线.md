## 一、缺陷现场（先取数，不凭印象）

- 门禁 62 的检测器 `data_scripts/check-line-anchors.py` 一上线就扫出全仓存量：`LINE-ANCHORS: FAIL（扫描 781 份，锚点 37078 条，DEADFILE 1576 / OUTOFRANGE 2624 / SUSPECT 4368）`，涉及 327 份历史报告。
- `bash data_scripts/rule-gate.sh` 默认全量模式把 audit 项的 FAIL 也算进 `GATE: FAIL`，于是 STEP 0 每轮都以 62 一项恒红开局。实测 `rule-gate.sh` 末行原文：`✗ 62锚点行号｜ OUTOFRANGE docs/CI核验-InkBubbleRouteResolverTest修红.md:60 ...`。
- 该门禁自己的接线段注释写着「全量 docs 存量漂移走 audit 补偿，不挡 push」，而 `data_scripts/gate-levels.json` 也把 g62 定为 `audit` —— **口径写着"不挡"，机器却在挡**，这是本单要修的第一性矛盾。

## 二、根因

1. 62 的判据面是全仓历史报告（781 份 / 37078 条锚点），而锚点漂移的成因是「源码与测试被后续单子改过」，属历史欠账，不是本轮缺陷。
2. 修历史欠账的唯一直接办法是逐份回改 327 份报告的 `文件:行`，但红线「不许改历史报告语义（只许加"已作废→以 X 为准"标记）」禁止这么做；结果是「判据正确 + 存量不可修 = 门禁恒红」，信噪比归零。
3. 只比总数也不行：新增一条 + 修掉一条会互相抵消，等于给漂移开后门。

## 三、方案与被拒方案

- 采用：**存量键棘轮基线**。键 = `引用文档|级别|目标文件|书写锚点`（`data_scripts/check-line-anchors.py:252`）。冻结当轮全部存量键（3837 条，少于 1576+2624=4200，因为同一 `(文档,级别,目标,书写锚点)` 组合去重），此后任何**新键**一律判红、退出码 1；存量键只留计数，不逐条打印以免淹没真信号。
- 被拒方案 A：批量回改 327 份历史报告的行号。拒绝理由：违反「不许改历史报告语义」红线，且改完下一轮源码再动又漂，是永久性打地鼠。
- 被拒方案 B：在白名单 `docs/.line-anchors-allow.txt` 里逐条登记 3837 行豁免。拒绝理由：白名单语义是「这条锚点不需要回源」的理由制豁免，逐条登记等于把全部存量判成"合法不回源"，且文件体积与维护成本都比基线高一个量级。
- 被拒方案 C：把 62 降级成 SUSPECT（只提示不判红）。拒绝理由：这就是"静默降级"，红线明令不许；棘轮保留了对新增漂移的阻断力，降级则全部放弃。
- 被拒方案 D：键里带报告自身行号。拒绝理由：报告正文增删一行会让行号整体平移，存量全判成新增，棘轮立刻变噪声源。

## 五、自查反例（改坏验证：冻结不得洗掉新漂移，证明它会抓而不是只报"已修"）

自测内造的棘轮通路（`data_scripts/check-line-anchors.py:415` 起）分四步，全部在 tempfile 夹具内跑生产 `main()`，跑完自删：

1. 无基线时夹具报告里的死锚点（`app/Gone.kt` 第 7 行那条）→ rc=1（新键必须红）。
2. `--baseline-update` → rc=0，写入 1 条键。
3. 同一死锚点复跑 → rc=0（存量放行）。
4. 报告里再加一条新的死锚点（另一个不存在的 `app/Gone2.kt` 第 9 行）→ rc=1，输出点名 `NEW` 行，键形态为「引用文档｜DEADFILE｜目标文件｜书写锚点」。

第 4 步就是必失败样本：冻结**没有**把新漂移一起洗掉。实跑末行逐字：
```

[selftest] 夹具已自删，双向自测通过。
```

## 七、未验证项（显式）

1. 棘轮对"目标文件被删除"的形态：DEADFILE 键只要目标文件还在索引里就不再命中，文件真被删时键仍在、条目会继续判存量；这种"存量里藏着已经彻底失效的锚点"不会被单独挖出来，需要靠后续 `--baseline-update` 收紧时人工看。
2. 基线键不含报告自身行号，代价是：同一份报告里**同一目标文件 + 同一书写锚点**在第 12 行与第 300 行各出现一次时只算一个键，若前者被删后者新增，棘轮不报。这是数量级的取舍（3837 键 vs 4200+ 键），记录在此备查。
3. 本单未在真实 push 链路上验证 pre-push 与 CI 侧的调用路径，只验证本地 `rule-gate.sh` 全量模式末行。
