> **合并版历史稿（降级留档）**：本文件把 W/V 卡放在一张表里，已于 2026-11-25 按"写码卡与验收卡分开"拆出 `docs/写码卡.md` 与 `docs/验收卡.md`。现行唯一权威是那两份，本文件只留作历史对照，不再更新。

## 这套东西就五句

一、开工前把项目切成一张张卡，一张卡一个活；卡先写好、定死，后面按卡派活。

二、每张卡写七件事：哪个模块、只能改哪些文件、大概写多少行、要先等哪张卡做完、验收看哪个锚点文件、它的验收卡是哪张、现在什么状态。

三、写码卡叫 W，验收卡叫 V，两张卡挨着放，一对一，永远不拆。一个 W 只有一张 V，别人不许验。

四、同时最多 5 个活在跑：3 个写、2 个验。写完一张立刻叫它的验收卡开工，同时开下一张写码卡，所以永远不会有"全部写完才验收"。

五、验收不过，配对不动，只在下面加一对 `-R1` 重做卡；同一张卡三次不过，说明卡切错了，回去重切。

## 卡上七项（列说明）

1. **所属模块**：模块 ID + 名字。
2. **文件域（独占/只读）**：只有这张卡能写这些文件或目录，越界即冲突（父子目录也算重叠）。V 卡一律只读。
3. **行数预算**：写码卡 100–350 行；V 卡填判据条数（2–4 条）。
4. **前置卡**：必须先落成的 W 号，无则 `—`。V 卡的前置永远是它自己的 W。
5. **判据锚点**：指向 `docs/锚点/` 下真实存在的卡片路径；不存在则此卡不可冻结，状态记 `缺锚点`。
6. **配对卡**：这一排的对方 ID。
7. **状态**：写码卡 `待取` / `在写` / `已交活` / `过` / `不过` / `缺锚点` / `待拆卡`；验收卡 `待验` / `在验` / `过` / `不过` / `缺锚点`。

## 判废链

`W-017` 判不过 → 原排保留、状态记 `不过`，下面加一行 `W-017-R1` 与一行 `V-017-R1`。重做链一路带 `-R2`、`-R3`；三次不过不许再起 R4，退回切分层重拆这张卡。

## 取卡纪律

- 只取"前置卡已 `过`"且状态 `待取` 的卡；5 槽里 3 写 2 验。
- 写码卡交活必须带 commit 短号；V 卡只认自己配对 W 的 commit。
- 卡冻结后只许加行（判废链、拆卡后代），不许改已冻结卡的内容。
