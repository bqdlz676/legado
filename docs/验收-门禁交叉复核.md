### 样本 a：「新发现问题」每条只有「待裁」两字 —— 被放过（漏洞）

- 夹具 `/tmp/q256/a.md`：`## 新发现问题` 下两条，正文分别只有 `1. 待裁`、`2. 待裁`。
- 实测命令：`python3 data_scripts/check-problem-finding.py /tmp/q256/a.md`
- 实测末行：`PROBLEM-FINDING: PASS（1 份报告均带新发现问题与处置状态）`，rc=0。
- 对照夹具 `/tmp/q256/a_neg.md`：两条目无任何状态词，同命令末行 `PROBLEM-FINDING: FAIL`，`问题无处置状态（已修/已入队/判废/待裁/已闭环）`，rc=1。

## 三、空集豁免审计（49 号 9 条逐条）

基线实测：`python3 data_scripts/check-vacuous-pass.py` → `VACUOUS-PASS: PASS（未发现未豁免的空集假绿结构；9 处已按哈希锚定登记豁免）`；`--selftest` 4/4 PASS。逐条回源码核对结论如下。

1. `check-onboarding.py:184` `files`（哈希 eb1ece3c6b08）——**理由成立**。`:183 files = changed_reports()`，来自 `git status` 本轮改动报告；空集 = 本轮无报告改动，diff 型真实状态。`:178-182` 的 `--emit`/`--audit` 分支不走此空集。
2. `check-report-fields.py:97` `paths`（53fabe213b5e）——**基本成立，理由描述不完整**。`:96 paths = sys.argv[1:] or changed_reports()`，空集同时覆盖「CLI 漏传参数且工作区干净」与「本轮无报告改动」两种；豁免理由只写了 changed_reports 一路。CLI 显式传空等价无对象，不构成假绿，但理由应补注 CLI 入参路径。
3. `check-dependency-symbols.py:104` `files`（cc556ab09ea1）——**理由成立**。`:98-100` 索引文件缺失已 `return 1` 单独兜底；`:104` 空集只是本轮无 kt 改动，不掩盖索引故障。
4. `check-commit-trailer.py:74` `commits`（9f15f2bd9a75）——**部分成立，有两处残留**。区间型空集 = 无待推提交，方向正确；但 `collect()`（`:31-48`）对 `git log` 失败的返回码未检查，git 异常时 `out` 为空同样落到 `:74` 空集分支，且判词是 `PASS（无未推提交）` 而非 WARN/INFO。脚本整体是 WARN 型、退出码恒 0（`:99`），不阻断 push，假绿风险低；建议空集判词降 INFO，并对 git 不可用补 `return 1`。
5. `check-push-track.py:71` `shas`（4760bf4009dc）——**理由成立**。`:30-36` `git()` 失败 `raise RuntimeError`，不会静默落到空集；空 shas 只在 rev-list 真无提交时发生，打印「干净」与空区间一致。
6. `check-commit-split.py:83` `commits`（040b63a248fc）——**理由成立**。`:75-77` `git log` 不可用已 `return 1` 兜底；空 commits 仅零提交仓库可达，CI 必有历史提交。
7. `check-commit-provenance.py:120` `commits`（1508651e032a）——**理由成立**。`:117-119` git log 不可用 `return 1`；`:121` 空区间打印 `INFO` 非 PASS，未把空集说成合规。
8. `check-anchor-integrity.py:29` `anchors`（5e5944523212）——**理由成立**。`:30` 打印 `WARN` 即 `return 0`，未表述合规；无处置锚点由下游时间窗守卫兜底。
9. `check-visual-baseline.py:88` `entries`（fca05d5ddc35）——**理由成立**。`:89` WARN 明示工序未冻结不算 FAIL；冻结侧 `freeze()` `:131-133` 未收集到文件 `return 1`，空文件不会被当成冻结通过。

审计小结：9 条中 7 条理由成立；#2 理由描述漏 CLI 入参路径（不影响判定）；#4 缺 git 异常兜底且空集判词分级偏绿，是 9 条里最值得收紧的一条。

## 七、自查反例（改坏推演）

- 反例 1：若把 a 样本判成红，等于要求每条目都显式贴状态词，历史报告里「问题 + 句末括号状态」的写法会被批量误杀；故改造方向是逐条点名而非整节加严，§五 已按此设计。
- 反例 2：若给 53 号把孤立 job 直接判红，有意的并行入口 job（无 needs 即触发起点）会被误杀；故可达性结论只列 WARN，并行起点留注释豁免口。
- 反例 3：若 evidence 递归 glob 后不做同名消歧，两个同名 `Utils.kt` 会互相顶替回源；故要求行号落入候选文件长度内才算命中，多候选按行号消歧。
- 反例 4：若把已删文件锚点全量豁免，真幻影（活报告里写错路径）也会被放过；故豁免限定「同句留档词 + 文件确不存在」双条件，不靠前缀文件名。
