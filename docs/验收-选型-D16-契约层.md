## 3. 逐维对照（七维，逐维给结论，禁「差不多」）

### 3.1 边界清晰度（是否与 D1/D2/D3 职责重叠）

- **A：清晰，胜。** 包路径即边界：D16 全部契约集中在 `help/artifact/**`；既有表（person/person_alias/place/place_name/plant/animal/medicine）在 `ArtifactSchema.EXISTING_TABLES` 只列名，注释标明归原模块；`ArtifactCategory.PERSON/PLACE` 条目注释写明「走 D2/D3 原 Provider 路径，本层不双轨」。边界有两道固定：包路径 + 代码注释，接线期可 grep 回证。残留风险：枚举把人物/地名也收进 17 类清单，「类别清点清单」与「Provider 生效域」是两层概念，需靠注释与后续接线单守住，不能让适配层对 person/place 二次出气泡。
- **B：边界模糊，负。** 5 张新表中 artifact（人造物）、architecture（建筑）、astronomy（天文）、food（饮食）、landscape（山川风物）在 D1（char/word 字典）、D2（人物档案/图谱）、D3（地名两表）内均无对应职责域；硬拆入三包等于把名物库职责渗透进三个已 v1 完成的模块，三包各自的单一职责被破坏。共享门面又反向要求三包依赖同一套 EntityProvider 抽象，形成双向耦合，边界不再可由包路径判定。
- 契约硬约束：索引:153 与问题清单 D16⑥ 逐字要求「EntityProvider 不重构 D1/D2/D3，旧三类仍走原有 Provider 路径、不双轨，内部可复用其接口但代码结构不合并」。B 的核心动作（拆表入三包、代码结构合并）直接违背该 FROZEN 段；A 与该约束逐字相容。

### 3.2 对既有 Provider 的破坏面

- **A：破坏面 ≈ 0，胜。** 现状骨架对 `help/bubble/` 只读取冻结协议类型（`BubbleContent`/`Kind`/`Action`/`MISSING_SOURCE`），未 import、未改写 `help/dict`、`help/person`、`help/place`、`help/bubble` 任何实现类；既有六 Provider（Char/Allusion/Person/Place/Date/Word）注册链与 `BubbleResolverImpl` 七槽构造器不动。
- **B：破坏面大，负。** 需在 D1/D2/D3 既有包内扩表、插入 3 个新 Provider，并把共享门面接进 resolver 注册链；D2 人物包刚经历关系包整包拆除、D3 地名包已完成 v1，此时拆入新表与新 Provider 会引入回归面。另存在口径冲突：既有 `BubbleProvider.query(token, anchor): BubbleContent?` 约定「查不到返回 null，落到下一优先级」，而 D16 契约要求「绝不返回 null、返回结构完整气泡」（09:15 + 锚点卡 §四）；把 D16 空态语义塞进既有 Provider 链，必须二次改写既有兜底口径，破坏面从数据层扩散到气泡协议层。

### 3.3 17 类与 5 表 schema 的可扩展性

- **A：单点闭环，胜。** 索引:218 冻结口径「加新类别只加数据表、不改 Provider/UI」；A 路线下新增类别＝在枚举加条目 + 在 `ArtifactSchema` 加表/type，改动封闭在 `help/artifact/` 包内，schema 表名与 type 清单集中可 grep（现状 5 张新表、type 顺序照抄 09:19-24）。
- **B：口径碎片化，负。** 表分散到三个既有包，后续加一类要跨三包判断归属、协调三处 schema 定义；「只加数据表」的单点闭环被打破，新类别评审成本随包数线性增长。
- **C 在此维的否决理由补强**：剔除人物/地名后枚举清点不再是 17 项，锚点卡 §三判据 1（grep 清点 17 项、wire 逐字一致）无法机械通过；且人物/地名仍是 09:11 十七类原文成员，剔除属擅改原文，与「类别名不改写、不增删」注释约束冲突。
- 两份候选共同的待补项（不构成选型翻转）：artifact 的 vehicle/seal/jade/armor、architecture 的 palace/bridge/tomb/academy 在 17 类中无一一对应条目，现状 `categoryForType` 返回 null 走通用兜底；后续若拆类再补映射（实现报告 §七已登记）。

### 3.4 四边界可落地性（空值 / 断网 / 缺年份 / 同名消歧）

- **A：四态在接口层均有落点，胜。** `FallbackState` 四态（NO_DATA / CACHE_MISS_OFFLINE / YEAR_MISSING / AMBIGUOUS）+ `CacheStatus` 三态（HIT / MISS / OFFLINE_CACHE_MISS）齐备；空数据走 `notFound` 产出字段齐全气泡；断网以缓存态标记、本层不自动联网；缺年份时 anchor 透传、不过滤不猜年代；同名消歧失败走 `ambiguous` 出 candidates + defaultIndex，候选为空退化为空壳。四边界均可在纯 JVM 单测中断言。
- **B：边界口径分散，负。** 四态兜底若拆入三包各自 Provider，极易各自发明回退口径（既有 Provider 习惯返回 null，与 D16 完整气泡口径不同）；断网缓存状态、年代锚不过滤、候选列表默认下标这些口径要在三处重复实现，一致性失去单点守卫。
- 边界遗留（A 路线接线期必须守）：`ambiguous` 的逐项 isDefault 须由接线层既有 `Candidate` 契约携带，不在冻结 `BubbleContent` 上扩字段；anchor 年份消费归后续真实实现，空实现只占位透传（实现报告 §八已登记）。

### 3.5 单测可测性

- **A：纯 JVM 可直测，胜。** 现状骨架零 android/Compose import；`EmptyEntityProvider` 可直接实例化，12 条断言覆盖 17 类计数、wire 逐字、五表 type 逐字、type 合法性、空回退字段、17 类全覆盖、同名多候选、未知 type、landscape 不落 artifact、断网标记、缺年份不过滤、分域接口分立。后续加类别只需在同一测试文件补遍历断言。
- **B：测试耦合既有链，负。** 既有人物/地名 Provider 依赖 `ContextAnchor`/`BubbleEnv`/资产资源，拆入后名物测试要么带 Android 环境、要么 mock 整条 resolver 链；边界四态断言分散到三包测试文件，跨文件清点成本高。

### 3.6 后续接 UI 与 `BubbleResolver` 七槽的装配成本

- **七槽现状**：`BubbleResolverImpl` 构造器七槽 date/allusion/person/place/word/char/missing，优先级链冻结（纪年→典故→人名→地名→多字词→单字→Missing），槽位不可增删。
- **A：适配点集中一处，胜（相对）。** 须如实指出：`EntityProvider.query(name, type, anchor)` 签名与既有 `BubbleProvider.query(token, anchor)` 不同（多 type 维度、返回非 null 气泡），接线期需要一个 D16 侧适配器把 EntityProvider 包成 `BubbleProvider` 挂入多字词/名物槽；该适配器只存在于 D16 文件域，不改 resolver 构造器与既有六 Provider。UI 侧：卡片 07 名物索引卡（`CategoryCard.kt`）、卡片 08 名物条目卡（`EntityRowCard.kt`）已按类别名落地，图标 `ic_cat_sword/horse/daoist/instrument/vessel/food/animal/plant/person/place/allusion` 等已按类别出齐；A 枚举 wire 与卡片/图标命名可单点映射，D21 发现页名物标签（索引:200，N-010）按 wire 取卡片与图标即可。
- **B：表面「Provider 直接进槽」，实际装配更贵，负。** 要改既有 Provider 注册与 resolver 构造链才能塞新 Provider；三包内类别归属跨包，UI 取数与图标/卡片映射要跨三包 join；适配器与注册链两处都动，装配面比 A 大。
- 动作契约：名物详情走冻结 `OpenArtifact(artifactId, type)`，名寺气泡地图按钮复用 `OpenMap`，两级跳转（问题清单 D16⑤）；两候选都不改 Action 五子类，此维持平。

### 3.7 维护成本（新人认知成本）

- **A：认知路径短，胜。** 新人进 `help/artifact/` 即见全部 D16 契约：枚举 → schema → 统一接口 → 兜底 → 加载策略 → 两个分域 Store；与索引:200 文件域登记「help/artifact/（新建）」一致。D1/D2/D3 各看各的，不互相渗透。
- **B：认知成本高，负。** 新人查「名剑/名寺/星宿」须先判断被塞进哪个既有包；三包被名物库渗透后，模块表（索引 §3）的文件域独占约定失效，接手者需跨三包拼出名物库全貌；历史包袱风险高——本仓已有旧 `help.relation/` 整包拆除、旧扁平 NameResolver 收口的教训，跨包合并类重构正是同类返工的高发形态。

### 3.8 七维小结

- 边界清晰度：A 胜，B 负。
- 既有 Provider 破坏面：A 胜（≈0），B 负（改动冻结注册链 + 兜底口径）。
- schema 可扩展性：A 胜（单点闭环），B 负（跨三包碎片化）。
- 四边界可落地性：A 胜（四态单点守卫），B 负（口径三处重复）。
- 单测可测性：A 胜（纯 JVM 直测），B 负（耦合既有链）。
- UI / 七槽装配成本：A 胜（一处适配器），B 负（改注册链 + 跨包 join）。
- 维护与认知成本：A 胜（单包可览），B 负（跨包拼全貌）。
