- 回执四件痕：旧指纹、新指纹、归因、HEAD；缺一件视为基线引用不完整。

### 2. 失配判定

- 八条冻结面 diff 或 status 出现名单外路径行、b3 任一签名行哈希或整文件哈希变化、26 文件清单文件数或逐件行数变化、目录指纹变化，均记为基线失配。
- read 面只对 read/ink 在飞名单以外的路径行判越界；名单内文件先核对归属在飞单（本单名单见第二节 4）。
- b3 目录内经批准的合法扩面改动（B5-03 起各单白名单内动作），不属于对本基线的破坏，但须在对应单回执内单列说明并触发该单自身的基线更新登记。

### 3. 失配处置（谁重冻、留什么痕、越界怎么回滚）

- 谁重冻：失配先由当单执行代理在回执内如实点名失配条目（路径、旧指纹、新指纹、归因），禁止自行改基线哈希掩盖；重冻只能由调度层指定的基线维护登记单执行，该单不改业务代码。
- 归因分流：失配源于冻结区被越界改动的，先回滚越界改动、恢复到基线状态，再谈重冻；失配源于已批准的合法维护改动（含规格变更经任务书复核）的，才按新状态重冻。
- 越界回滚：越界改动按文件粒度回滚到 HEAD 基线状态（git 层面由总控统一执行 revert 或 checkout，子代理不做 git 写操作）；回滚前先备份越界件 diff 留痕，回滚后重跑双通道与目录指纹比对，确认回到基线值。
- 重冻留痕：重冻单独成单或单独一笔提交，记录失配条目清单、旧指纹、新指纹、归因、重冻命令、重冻后 HEAD；报告内新增「基线重冻留痕」节，锚点卡同步更新指纹；重冻后机检复跑。
- 验收口径：验收代理按本基线旧快照比对签名与指纹；签名变化无对应冻结豁免单或重冻留痕的，判 FAIL，不接受口头说明。

## 七、二阶三阶影响（含反作用推演）

- 一阶：B5-02 ~ B5-22 开工前都有同一组静态可比对象；冻结面越界、b3 签名漂移、26 旧清单内容漂移可由 diff、status 与哈希在 L1 静态层抓到。
- 二阶连带：基线指纹把只读目录整体锁住，后续单若需要在 ui/components 或 ui/card 内新增组件，属新增文件而非改既有文件，目录指纹会变；这类新增须在回执内单列说明并走重冻流程，不能悄悄挂进只读目录。
- 三阶后果：基线一旦被随手重冻覆盖，门禁会退化为自证；故第六节把重冻权限收归调度层指定登记单，并要求旧指纹、新指纹、归因、HEAD 四件留痕。

- 反作用：目录指纹粒度是整目录，单文件改动与整目录增删在指纹层面都表现为目录指纹变化；回执比对时须再下钻到逐件哈希与逐件行数定位具体条目，不能只凭目录指纹判责。

- 反例一：只锁 b3 各 fun 声明行，漏掉数据类与顶层 val/const；越界方改形参或改常量值绕开声明行比对。否证：第四节逐文件登记 sealed interface、data class、顶层 val、const val 与私有扩展，逐行留哈希；形参名、类型、可空性、默认值、顺序任一变化都能由整文件哈希与行哈希比对定位。
