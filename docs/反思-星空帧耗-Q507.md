## 2. 踩的坑 / 教训（下任避开）

- 共享索引串单是真实高发事故：提交必须独立索引 `GIT_INDEX_FILE=/tmp/idx_<用途>_$$ git read-tree HEAD`，只 add 显式路径，提交后立刻 `git show --stat` 核对；别用 `git add -A`。
- **独立索引文件名禁跨 shell 用 `$$` 拼**：本单第二轮第一次提交，暂存调用与提交调用分属两个 Bash 进程，`$$`（PID）不同，提交时 `GIT_INDEX_FILE` 指向一个不存在的空索引，提交树只剩 3 个暂存文件、其余 5080 个文件全记成删除（本地坏提交 `8de21f2`，未推送）。修复：`git reset --mixed origin/main` 保工作树，改用固定文件名 `/tmp/idx_q507_fix`，`read-tree → add → 校验清单 → commit → show stat` 全部放进同一条 shell 命令一次跑完。下任：独立索引要么固定文件名，要么整条链路单 shell 完成。
- 红 run 的 stdout 数值不会自动留仓：这次 run `46119559068` 的中位 / P99 原文没存下来，匿名 API 又 403，报告只能如实写「未回捞」，不能估数。下次修红单应在开工先把失败 run 的 artifact 快照文件名（数值编码在文件名里）或日志存档到 `artifacts/`。
- 沙箱禁编译：所有「应该能过」都不算数，编译面只能等 CI；静态门禁（lint / 孤儿 / 符号存在性）先跑一遍拦低级错。
