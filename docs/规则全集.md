# 第一部分　旧链（E01~E13）

> 旧链以「派单」为中心：调度层先登记立项，再切单派给写码代理，收单后派独立验收代理，按节拍攒批 push，CI 编译后复验；状态散落在台账、队列、登记册、多本台账里。

## E01 输入：用户口令与规格原文

- **这一环解决什么**：防执行代理凭记忆转述规格、自行编造或摘要。实证：BookCard / TopicCard 两张返工，根因是执行代理把分享卡三背景 lerp `0.35/0.12/0.10` 记岔（见 R6 前置设计费）。
- **这一环的规则**：
  - C1 用户原文规格逐字保留、不蒸馏不改写；子 AI 只读小段原文照做，靠索引+完整覆盖核对。
  - C2 规格超上下文时分段读、记结论继续读，不许跳读。
  - C8 指令前后冲突时，以后面（最新）指令与实际（工程现实/史实）为准。
  - C9 上下文抢救只做逐字抽取，禁止转述。
  - C10 状态判断以仓库事实为准。
  - F-11 地图入口=六主+二附+专题联动，统一 PlaceMapActivity 单壳三模式不跳页（规格事实样例，其余规格事实见 F-06~F-20）。
- **机械门禁**：无独立前置门禁；保真后果由 E02 的 ⑪/㉒ 在流入环节兜底。

## E02 规格流入与完整性

- **这一环解决什么**：用户持续贴新规格，漏登一片则后续写码/验收无锚点可回源。实证：旧 `spec-check.sh` 不反向校验切片↔登记册，切片 21~25 漏登长期未被发现（㉒ 注释原文）。
- **这一环的规则**：
  - F-88 规格流入与完整性持续巡检：四向双向对齐；新规格走六步入库流水线；禁跳过登记直接派写码单。
  - E13 规格登记 + 持续完整性闭环（立项规则唯一权威见 `docs/立项规则.md`）。
- **机械门禁**：㉒ `check-spec-flow.py`（切片↔登记册 / 登记册↔清单 / 登记册↔索引 / 登记册↔派单踪迹四向双向对齐）；⑪ `spec-check.sh`（规格完整性）。

## E03 立项与登记

- **这一环解决什么**：立项术语、两类规格、状态机、粒度、完整性判据必须单一权威，防止两处各写一套、一处漂移让子 AI 误读（E13 原文）。
- **这一环的规则**：
  - 规格登记册：立项数据唯一权威（唯一编号 + 立项缺陷号 + 状态 + 完成定义/验收证据）。
  - 立项规则：术语定义、两类规格（功能/治理）、状态机、每轮动作、立项粒度、完整性判据唯一权威。
  - E13 每一项规格登记唯一编号 + 立项缺陷号 + 状态 + 完成定义/验收证据；用户每轮新增/修改要求当轮登记立项。
  - F-83 拍板指针：T1~T12 口径以拍板记录为唯一权威，入口径冻结由收口轮执行。
- **机械门禁**：⑪ `spec-check.sh`（每轮结束前 + commit 前机械检查）。

## E04 前置设计费：锚点卡

- **这一环解决什么**：用小钱买断返工。一张锚点卡 ≈ 轻代理 5~10 分钟，一次返工 ≈ 写码+验收+CI 复位 30~60 分钟加重读上下文（R6 原文）。
- **这一环的规则**：
  - F-85 前置设计费（锚点卡）：写码单前先出锚点卡三件套；无锚点卡不许开工；验收逐字对照锚点卡；返工率 <5% 可降级参数表版；承认拉长单包是已知成本。
  - R6 锚点卡三件套：①逐字原文引文（带 `文件:行`，从切片原文复制，禁改写）；②参数表（数值/单位/来源 token 逐项列）；③可测判据（P1…Pn + FAIL 条件）。
  - ⑲ 无锚点卡不许开工：写码回执带锚点卡路径 + 逐字抄录参数段；锚点卡由设计/查证代理产出，写码代理不许自写。
  - F-73 / F-74 无规格功能走三段流水线；候选规格本身即锚点，不重复付费。
  - 台账-前置设计费：返工记一行（缺陷号 / 根因类 / 返工实际耗时 / 前置设计预估耗时 / 是否本可避免），用数据定投入强度。
- **机械门禁**：⑲ `check-anchor-card.py --strict`（只校验本次改动的写码/验收报告，历史留档不追改）。

  - D2 写码/验收代理一次性用完即弃，禁止唤醒复用；产物可继承、代理不可继承。
  - D6 跨模块问题交接，不漏交不甩锅。
  - D7 同文件多缺陷必须串行，不同文件可并行。

  - E12 派单分型 + 完成定义 + 止损：执行型给切片照做+预算+DoD；探索型额外给探索边界+止损点+阶段汇报锚点；每单必带可判定 DoD 与止损动作。

  - 派单队列：调度层唯一排队事实源。
  - ⑱ 队列与满槽：队列在册；PENDING 不超时丢单；不空槽空转；有积压不空转。
  - F-79 派单台账是并发唯一事实源：派单当轮登记，状态列严格写"在飞"才能被统计。
  - F-80 台账新鲜度门禁：HEAD 比台账新 >60min FAIL；在飞超硬上限 FAIL；无当日行 WARN。
  - ⑯ 台账新鲜度。
- **机械门禁**：⑤ 台账一行一缺陷号（python 数去重后缺陷号）；⑱ `check-dispatch-queue.py`；⑯ `check-dispatch-ledger.py`。

## E06 并发与限流

- **这一环解决什么**：限流主因是单位时间工具请求数爆掉，不是稳定 CPU 高。实证：中位子代理 49 次调用，失控代理 6894 次（4857 Bash + 539 Edit + 512 Write）；本机 2 vCPU / 3.9G 无 swap（E9/E10 原文）。
- **这一环的规则**：
  - E3 代码槽永不空（满编 5 槽：4 写 + 1 独立验收），写完即送审。
  - E9 并发自适应与限流防护：在飞硬上限 5 = 4 写码 + 1 验收（查）；`load1 ≥ 1.5` 饱和降到 2（下限 2 永不突破）；只并发文件域互不重叠的任务；触发限流标准动作停发→终止在飞→清孤儿进程/查盘→低频恢复→重建基线。
  - E10 子代理请求预算：写/修 ≤40 次、验收 ≤60 次，超即判失控 kill；独立工具调用必须一条消息内并行发，禁串行单发；回报只一次 ≤4KB。
  - E10b F=5 内吞吐四杠杆：同域串行多件 / 零发现成本派单 / wait 不 poll / 长任务异步+短任务填缝。
  - E11 请求率补齐五杠杆：派单零发现成本 / 脚本合并 / 外置重活 / 请求整形（错峰、阻塞等待、退避）/ 实测留边际（压到实测阈值 60~70%）。
  - F-82 并发分档表在册：档1 5=4写1查 / 档2 6=4写2查 / 档3 8=5写3查；档位唯一事实源=并发档位.md。
  - 并发档位：三档配比与升降档条件唯一事实源。
  - ⑨ 并发上限；F=5 硬顶。
- **机械门禁**：⑨ `queue_stats.py` + 并发档位.md + `/proc/loadavg`；⑰ 档位表在册（口径冻结三档串 + 档位文件存在且含"当前档位："行）。
