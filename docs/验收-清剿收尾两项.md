## 新发现缺陷 / 观察项

1. 【轻微·测试切片锚点脆弱】两条契约测试按方法名文本切片（`clearInvalidCache()` → `clearComicCache`；`importData(...)` → `private suspend fun dispatch`）。后续若重命名这些私有方法、调整方法顺序，切片边界会静默扩大或缩小，断言可能落空或误命中；且 `private suspend fun dispatch` 是 `dispatchFile`（`FileAssociationViewModel.kt:140`）的前缀串，当前因 `dispatchFile` 位于 `importData` 之前被 `substringAfter` 排除，一旦方法顺序调换即可能切错。建议后续契约测试改用花括号配平或行号区间之外的更稳锚点；本单不扩大改动面。

2. 【轻微·语种未对齐】新键 `import_bookshelf_default_group` 仅补默认英文与简中；`values-es-rES`、`values-ja-rJP`、`values-pt-rBR`、`values-vi`、`values-zh-rHK`、`values-zh-rTW` 未补译，走资源回退到默认英文；其中 `zh-rHK` / `zh-rTW` 用户会看到英文而非繁中。仓内 `LocaleResourceConsistencyTest` 不校验字符串键对齐，不构成 CI 红；属既有惯例，自述未验证项 4 已登记。若产品要求全语种对齐，需另立翻译单。

3. 【轻微·断言误报面】`ImportBookshelfGroupContractTest.kt:25` `assertFalse(importData.contains(", 0)"))` 按片段文本匹配；若未来 `importData` 切片内出现其他形参为字面量 `0` 的合法调用，该断言会误报。当前切片内无此类调用，风险仅在未来扩分支时显现。

4. 【观察·老设备残留未迁移】升级前旧版本可能在私有 `filesDir` 留有 `books.json` 分享临时文件；删行后该残留不再随缓存清理摘除。本验收复核：全仓零读取方、备份不打包、不参与书架数据库与分组统计，文件位于应用私有目录、用户不可见、单个 JSON 体积有限。自述「不做一次性 migration，后续如需统一清污在独立启动迁移中处理」的判定成立；真机上残留是否实际存在、体积多少未实证（见未验证项 2）。
