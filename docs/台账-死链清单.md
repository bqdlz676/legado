# 台账-死链清单（公开成员生产零调用 / 假绿）

为什么立这份台账（2026-11-28 实测）：`data_scripts/check-orphan-members.py` 扫 `astro/` 与 `host/Sky*.kt` 得到 108 个公开成员，其中 **28 个在 `app/src/main` 生产代码零调用**，12 个还被单测真实调用——单测全绿、CI 三绿、功能一行不生效。这正是 Q-497/Q-498 两单的自陈缺口在同一根因上第二次发作：单测只证明「函数能算对」，证明不了「生产有人调它」。g68 只扫顶层入口，抓不到类成员函数，所以需要本台账 + 成员级机检兜住。

口径：生产引用 = `app/src/main/**/*.kt` 里出现 `符号(`（排除定义文件自身）；测试引用 = `app/src/test/**/*.kt` 同口径。**生产 0 / 测试 >0 标「假绿」**——这类最危险，因为任何靠「单测绿 + CI 绿」判断功能已完成的读数都会把它读成通过。

## 归类（为什么死、该接到哪）

1. **图层未挂载**（`AsterismLayer.loadGroups/groupByCode/membersOfCode/codeOfStar`、`ConstellationLayer.loadLines/loadLabels/allSegments/allLabels/constellationOfStar/starsOfConstellation`、`FieldAllocationLayer.entriesForRegion/regionForCodes`）：渲染器从头到尾没调加载，索引在内存里建好了却没人建，于是判据 3 正向（点星→星官→分野州域脉冲）与星官连线绘制全不生效。归属 Q-503。
2. **触发链未接入输入**（`SkyInputHandler.evaluatePyramidDemand`）：Q-497 交付的 >6.5 触 L1、>9.0 先 L1 后 L2 判定挂在成员函数上，`/` 生产侧没有任何输入路径调用它，金字塔永远不会被真的触发。归属 Q-503。
3. **拾取双轨**（`StarPicker.pick/hitRadiusPx`）：拾取测试走 picker，生产走的却是渲染器自己的命中测试，两套口径并存（g22 缝合怪的静默版）。归属 Q-503 统一到 picker。
4. **日月明暗四件**（`Sun.worldNormal/dayFactor/nightBrightness/terminatorSide`）：只有 `dayFactor/nightBrightness/terminatorSide` 被单测调，生产渲染器没读明暗，判据（日月明暗过渡）实为纸面。归属 Q-503。
5. **入口换算与数据面**（`SkyParams.skyBlendFromDiameter`、`StarCatalog.constellationAt/pyramidConstellationAt`、`StarStore.byAsterism/byRegion/isPyramidIndex/pyramidSlot`、`SkyNameIndex.codes`、`StarStoreProvider.hasAttempted`）：都是为上层准备好的查询面，上层还没接。归属 Q-503（`StarStore` 内的三条随 Q-502 收工后一并接，避免与其改同一文件冲突）。

- 新增公开成员当轮必须有生产调用方；只被单测调用即视为未完成，不得在报告里写「已交付」。
- 本清单只许缩短，不许加行；Q-503 接线后逐条划掉并在提交信息点名。
- 白名单 `data_scripts/orphan-members-allow.txt` 四列制表符（`相对路径::符号名` / 理由 / 单号），无理由不许入。
- 机检命令：`python3 data_scripts/check-orphan-members.py --list`；门禁 g76（audit 起步，Q-503 落库后转 blocking）。
