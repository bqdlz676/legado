### 2.1 新增数组取值守卫 `jsonArray`（370-375）

```kotlin
/**
 * 数组取值守卫：字段缺失 / JsonNull / 非数组（对象、字符串、数字、布尔）一律返回 null，不抛。
 * 适用条件：Gson `JsonObject.getAsJsonArray(name)` 在字段存在但类型错位时直接抛
 * `IllegalStateException`，会穿透到 UI 层；本守卫把类型错位统一降级为空表，由调用方记 warning。
 */
private fun jsonArray(obj: JsonObject, key: String): JsonArray? {
    val el = obj.get(key) ?: return null
    if (el.isJsonNull || !el.isJsonArray) return null
    return el.asJsonArray
}
```

### 2.2 新增布尔取值守卫 `boolPrimitive`（381-389）

```kotlin
/**
 * 布尔取值守卫：字段缺失 / 非布尔 primitive / 解析异常回落 [default]，不抛。
 * 适用条件：`asBoolean` 对非布尔字符串 / 数字会抛；procedural 等开关被素材写错类型时按默认值走，
 * 避免一条开关错位把整块地形拖进外层兜底分支。
 */
private fun boolPrimitive(obj: JsonObject, key: String, default: Boolean): Boolean {
    val el = obj.get(key) ?: return default
    if (!el.isJsonPrimitive) return default
    return try {
        el.asBoolean
    } catch (t: Throwable) {
        default
    }
}
```

### 5.3 反例与边界（先假设本单方案错误）

- **反例 1：`getAsJsonArray` 会不会在类型错位时返回 null 而非抛？** 核对 Gson 2.14 公开源码语义：字段存在且 `!isJsonArray()` 时抛 `IllegalStateException`；字段缺失（key 不存在）才返回 null。旧代码 `?: return emptyList()` 只兜得住缺失，兜不住错位——这正是本单穿透点成立的依据。若未来换 Gson 大版本行为变化，`jsonArray` 的 `!el.isJsonArray` 守卫仍成立，不受影响。
- **反例 2：字符串 `"NaN"` / `"Infinity"` 会不会被 `getAsNumber` 抛掉？** Gson 数字解析走 `Double.parseDouble`，后者接受 `"NaN"` / `"Infinity"` / `"-Infinity"`，返回非有限值；由 `guardedPoint` 的 `isFinite` 过滤，不靠异常路径。若素材写成数字字面量 `NaN`，JSON 解析阶段就非法，由顶层 `JsonParser.parseString` catch 兜底。
- **反例 3：合法战役会不会被误降级？** 最小合法用例（第四节第 5 条）锁定 `degraded=false`、warnings 空；只要素材字段类型与 schema 一致，守卫不介入。
- **边界 1：点数组长度 >2**（如 `[lng, lat, extra]`）只取前两位，多余位忽略；规格点列口径是 `[lng, lat]`，多余位视为素材冗余。
- **边界 2：坐标越出 0..1 / 经纬度越界** 本守卫不钳制；越界判定与投影钳制属 `terrain/GeoProjection` / `TerrainMap` 口径，不在 B4 独占范围。
- **边界 3：`heightMap` 字段** 仍是字符串留存，无 PNG→栅格解码通路（B13，`docs/问题清单.md:61`），本单不展开。
