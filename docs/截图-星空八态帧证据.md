## 五、观感判定要点（逐态）

通用基线（§八 美学口径，逐帧核对）：

- 夜空底为暖墨压暗，禁纯黑；星点走 4 档 atlas 光晕，不允许逐帧圆斑；暖金辉光不得压过星点本体。
- 参考线：经纬网 0.8px 灰 0.12；天赤道 1.0px 石青 0.30；黄道 1.0px brandGold 0.30——基准线不得亮过星点。
- 星名 / 星官名为 14sp 竖排；相邻竖排不得重叠、不得压到星点。

逐态：

- **态 1 默认**：星点密度随星等连续变化，无整层星点突现；背景网格 / 赤道 / 黄道层级清晰但不抢主体。
- **态 2 悬停**：被定点星直径约为邻星 1.3×；其余星点直径不变；帧内无残留的放大环或亮斑。
- **态 3 按下**：被定点星 1.6× 并带 1200ms 呼吸幅度；静态帧只覆盖「过门后呼吸段」，60ms 预压段时序见 §六。
- **态 4 加载**：顶部一条 1px brandGold 金线（本帧为 0.5 半幅代理值）；画面内无菊花 / 转圈进度控件；已有星与线框不消失。
- **态 5 禁用**：星等上限封顶 6.5；银河带、尘粒、流星均关闭；星点与星座 / 星官线框仍在，属「减层」不是「消失」。
- **态 6 空**：300 颗种子散点铺满天区；底部居中一行「星表未载，当前为示意星空」；画面不空白、不崩。
- **态 8 离线**：未缓存天区密度底图更疏（低层级 14px 步长、0.10 alpha）；经纬线框与亮星完整，不出现空白洞。

## 六、反例边界与不可自动化缺口

1. **态 7 错误态：当前不可自动化，不出伪造帧。** 公开星表构造入口只有 `StarCatalog.fromAssets(AssetManager?)`；含异常计数（`importAnomalies > 0`）的目录只能经 `internal parseRows` 构造，跨 Gradle 模块不可见；测试侧没有公开入口能喂出一份异常目录给 `StarStore`。所需缺口入口（二选一，属生产接线单域，本单不代改）：
   - 在 `StarCatalog` 暴露测试友好的行级工厂（如 `fromRows(rows)`，口径同现有 `parseRows`）；或
   - 在 `StarStoreProvider` 增加测试钩子，允许注入指定异常计数目录。
   - 在此之前，错误态只登记分支位置（`SkyCanvasRenderer.kt:73-74,131-133`），不画「看起来像错误态」的假帧。
2. **态 2 的 120ms 回弹时序：静态帧截不到。** 规格要求 1.3× / 120ms 回弹；代码侧无 120ms 悬停计时器（验收:135 已记）。本单帧只能证明 `hoverId` 放大分支被真实走到；抬手回弹是否无残留，需手势序列 + 可控时钟的 instrumented / 真机环境补帧。
3. **态 4 的真实 0..1 进度源：随金字塔下载接线单缺。** 本帧进度为 `PENDING_DOWNLOAD → 0.5` 半幅代理值（另有 `notifyLocalChartRequested()` 的 0.2 占位），不能充当真实下载进度帧；真实进度源落地后需复测本态。
4. **真机手势不在 JVM 截图域**：捏合缩放、长按拖拽、点选星官等交互序列，Paparazzi 静态帧不覆盖；对应判据另走真机 / instrumented 链路。
5. **assets 可解析性以 CI 为准**：测试经 `StarStoreProvider.get(paparazzi.context.assets)` 取内置表；若 Paparazzi 运行时未挂上 `:app` 资产目录，门面会收敛为占位目录，相关帧退化为种子散点（与态 6 同源）。出帧后须逐帧核对：态 1/2/3/5/8 是否画出真实目录星点；若全退化为散点，缺口记为「测试运行时缺 `:app` assets 目录」，修复方向是测试侧 File → 目录的公开工厂（同 §六.1），不在生产代码塞兼容层。

## 七、二阶 / 三阶影响

- **CI 时长**：背景离屏位图与 4 档 atlas 在首帧一次性烘焙，后续帧复用缓存；本单 7 帧叠加在既有 42 帧基线上，增量约一成七量级；单帧纯 layoutlib 渲染、不触网。截图 workflow 与主 build 物理拆分（独立 concurrency group，不 gate 主 run），不会拖垮主链路。
- **入库膨胀**：PNG 不进 Git——CI 启动前清空旧 golden（`screenshot.yml:83-84`），帧仅作为临时 artifact 上传；本单源码只有两个 `.kt`，不新增资源 / 资产文件。
- **状态面跨用例共享**：`SkyCanvasRenderer` 是 object，状态面（`hoverId` / `pressId` / `offline` / `loadingProgress` 等）跨用例保留；夹具在每态出帧前 `resetRendererState()` 复位，防止上一态的选中星或离线标志泄漏到下一帧。atlas / 背景位图属帧间缓存，刻意不重置以省重复烘焙。
- **二阶（后续追加用例）**：`StarStoreProvider` 进程内单例缓存；态 6 直接传 `store=null` 绕过门面，不污染缓存。后续若在同一 JVM 补星空用例，复用同一复位夹具即可，不需要再碰渲染器内部。
- **三阶（生命周期与泄漏面）**：测试侧 `SkyRenderView` 由 Paparazzi 管理挂载 / 销毁，夹具不持有 Activity / Context 长引用；渲染器只读快照与 store，不反向持有视图。
