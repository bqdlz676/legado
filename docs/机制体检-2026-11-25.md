# 机制体检：冲突与可优化项（2026-11-25）

> 为什么写这份：用户问「机制中哪些有冲突，哪些可以优化」。这份是机械体检结果，不是感想——每条都带可回源的证据（门禁输出行 / 脚本行号 / 文档行号）。
> 判据：冲突＝两条规则同时满足会互相否决，或两处守卫给出互斥结论；优化＝机制本身有冗余、盲区、可被洗白或维护成本过高。

## 一、冲突（8 条）

C1 **计数口径三源打架（最严重）**：同一次 `rule-gate.sh` 输出里出现三个互斥的"在飞"数字。
- ⑨/⑥ 从 `docs/派单台账.md` 抓含「在飞」的行 → 在飞 4；
- ⑱ `check-dispatch-queue.py` 结构化解析 `docs/派单队列.md` 状态列 → PENDING 0 / RUNNING 0；
- ㉙/㉚ `check-queue-running.py` 用**行内子串**匹配 `PENDING`/`RUNNING`/`在飞` → PENDING 7 / RUNNING 6。
后果：⑨ 的「未超上限」可能建立在错数上；㉚ 会把备注文字里的词当状态。三个数没有一个可信。

C2 **F-109 攒批一次 push vs 既有铁律「代码槽永不空、验收未过也先 push 云端只做区分标记」**：一个要求等 CI 终态再推，一个要求不等、先推保槽。两条都写在册，执行时必然二选一。

C3 **F-108 每条在飞须独立验收代理 vs 框架硬顶并发 5**：一单要占 2 槽（写码 + 验收），实际并行度降到 2.5；写码全占满时验收单派不出去，反之亦然。

C4 **⑦级别自报 vs 现实**：门禁报「16 个 docs 含『验收通过』」，而独立验收刚判 6 单里 5 单不过。因为没有任何守卫规定"验收通过"字样只能由验收代理写，自报因此不可信。

C5 **门禁 ① 待提交态必红 vs 多子代理并发写工作区**：有子代理在飞时工作区必然有未提交改动 → 与 F-109「除 ① 外全绿才 push」叠加，等于「有子代理在飞就推不了」，只能永远等全静默。

C6 **⑩ 本地构建能力 与 ㉝ 本地禁止编译 守同一件事**：⑩ 查"能力缺失"（无 JDK21/SDK），㉝ 查"痕迹"（daemon/日志）。两处判据、两处维护，改一处容易漏另一处。

C7 **㉝ 处置锚点可被洗白**：`docs/台账-本地编译违规.md` 里 `处置锚点 epoch=<秒>` 一改就把之前所有违规痕迹失效；脚本不校验"推进锚点的人是否同时登记了违规处置条目"，等于给了自己一个免检开关。

C8 **⑪ 规格登记滞后**：⑪ 报「已验收 2 / 已立项 51」，而 §3.8 显示 14 张切片契约层已全部落地并接线 → 状态字段滞后，门禁按旧数放行，等于放水。

## 二、优化（11 条，按收益排序）

O1 **计数单源**：抽 `data_scripts/queue_stats.py` 一个解析器，⑨⑥⑱㉙㉚ 全部调它；行内子串匹配全部废弃（㉚ 的 `'在飞'` 子串已实证会误判）。收益：一次修掉 C1 全部三个数。
O2 **门禁分级**：把不可机械判定的项（① 未提交的**性质**、⑦ 级别自报、⑤ 的一半判断）降为 WARN/提示，只有机械可判项一票否决。E-04 就是"不可执行规则上线"的产物，分级能从根上防止再长这种东西。
O3 **推送前守卫**：新增 `check-push-window.py`——若有 `in_progress` 的 CI run 则拒绝 push（K-20 待机制化项）。收益：把"我看一眼再推"变成"脚本不放行"。
O4 **锚点双写防洗白**：推进 epoch 必须同时在该台账增一条处置记录（违规代理 id + 处置动作 + 时间），gate 校验「锚点时间 == 最后一条处置记录时间」，不等即 FAIL。收益：修掉 C7 的免检开关。
O5 **并发分槽**：写码槽 3 + 验收槽 2，⑨ 按槽分别计数，不再共用 5。收益：修掉 C3 的互锁。
O6 **「验收通过」字样加守卫**：docs 内出现该字样的文件，必须在 `docs/派单队列.md` 有验收代理 id 且回执带「PASS + 判据行」，否则 FAIL。收益：把 ⑦ 从人工转机械，修掉 C4。
O7 **事故同因复发自动开规则**：`check-incident-register.py` 增一条——同一根因标签出现 ≥2 次而「已机制化」字段仍空 → FAIL。收益：不让同一个坑付第三次成本（用户第 10 条项目规则的原意）。
O8 **门禁变化摘要**：`rule-gate.sh` 输出与上一次快照 diff，新增红项标 `NEW`。收益：34 项肉眼扫一遍的成本降到只看新增。
O9 **㉜ 扩面**：从「契约层 17 个文件」扩到全 app 源码 + 历史白名单。理由：接线之后，混算高发区恰恰是渲染文件（K-16 就出在 `GlobeSphere.kt:86` 的渲染侧）。
O10 **门禁合并瘦身**：⑩+㉝、⑤+⑥、⑬+⑳、㉓+㉔ 四对同域合并，34 项降到 ~28 项。收益：降低每次全跑的心智成本，同域判据只维护一处（顺带修 C6）。
O11 **docs 前缀收敛**：现在 `落文-`/`口径冻结-`/`台账-` 三套前缀语义交叉（60+ 文件）。建议固定六类前缀（立项/验收/事故/锚点/台账/归因）+ 一个 `docs/INDEX.md` 单入口。收益：新接手的工程师（用户第 8 条规则）第一眼就能分类。
