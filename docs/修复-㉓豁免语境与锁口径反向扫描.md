## 三、改动 2：check-lock-rule.py 锁口径反向扫描

### 3.1 判据（窄，防假红）

- 旧模式（`data_scripts/check-lock-rule.py:34-37`）：
  - `禁删锁` 短语；
  - `禁删index.lock` 正则 `禁[^。\n]{0,16}rm[^。\n]{0,20}index\.lock`，容忍反引号与空格夹在 rm 与路径之间。
- 新标记（`:38`）：同句含「僵尸锁可删」即视为新口径，不报。
- 文件名白名单（`:41-45`、`:47-58` `_whitelisted`）：复盘- / 形成史 / 分析- / 验收- / 修复- / 锚点 / 交接- / 流水 / 自检 / 审计 / 留档 / 备案 / 索引 / 诊断- / 规则冲突清单。以「-」结尾的词按**文件名前缀**匹配——事故-停工事故复盘件文件名中段含「复盘-」子串，按子串会被提前豁免、绕过基线，故改前缀匹配；修复/验收报告是证据件，旧串仅作回溯引用。
- 棘轮基线（`:70-74` `load_baseline`、`:77-91` `ratchet_expansion`）：`lock-rule-baseline.json` 条目 `相对路径:行内容 sha256 前 12 位`；当前基线必须 ⊆ origin/main 或 HEAD~1 基线，扩张即 FAIL；新基线首提交无参照时跳过比照。哈希锚内容不锚行号：行号漂移不误伤，行被改写哈希失效、须重审后再入基线。
- 围栏豁免（`:116-120`）：``` 块内逐字转写/夹具区不扫，围栏按行配对，未闭合保持到文件尾。
