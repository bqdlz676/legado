# 虚拟运行自检协议（F6 门禁）

> 用户口径：**虚拟运行自检是需要的**；**整个 App 做完之后虚拟运行自检是需要的**。
> 本机无 Android SDK、无运行时、禁一切 gradle/kotlinc。所以"虚拟运行"不是装 APK 点一遍，而是：
> **在没有运行时的前提下，把"用户会走的那条路"逐环检查到可举证的粒度**，并把"查不到"如实记为缺口，不假装通过。

---

## 1. 为什么必须有这层（先自我否证，铁律 61）

反对者的最强论点：静态 grep 是假阳性温床 —— 符号在场不等于被调用，被调用不等于行为正确。
这个反对意见成立，所以本协议**不承诺**"grep 全过 = 功能可用"，而是把它压缩到它能诚实承担的那部分：

| 能证明 | 不能证明 |
|---|---|
| 关键路径每一环的**组件/符号存在**，且落在正确目录（不是别的模块同名物） | 逻辑分支真的走对（如 ROUT 判定、快照恢复） |
| 组件**确实被调用**（调用计数 ≥ 阈值，排除"写了没接"） | 视觉呈现、动画、手感、性能 |
| 数据资产可解析、字段无 NaN/负坐标、action 标签与枚举对齐 | 编译是否通过（那是 L2 云端的事） |
| 同一出口函数被两条入口（手势 + 返回键）共用，未分叉 | 真机/模拟器上的崩溃与 ANR |

所以它承担的是**"接线层"**，不是"行为层"。行为层靠单测（L2）与 L3 整仓验收。三层不重叠、不替代。

## 2. 两层脚本

### 2.1 数据级 `data_scripts/selfcheck-data.py`
模拟"App 启动后读资产"这条路：① 70 个 assets JSON 全量解析；② `Enums.kt` 认得的事件标签 vs JSON 里出现的 `action` 比对；③ NaN/Infinity/负坐标；④ 重排版三件套字节数与块标记自洽；⑤ 词典/默认数据 JSON。
判据：**0 项失败**。当前基线 6 过 / 8 败（8 种 action 无执行分支，已立 B15）。

### 2.2 接线级 `data_scripts/selfcheck-path.sh`
8 条关键路径 × 每环"真实符号 + 限定目录"（v2 起强制限定目录，避免跨模块同名假阳性——v1 曾靠全仓 grep 跑出 22/22，实际 4 条是假阳性：进书数据命中 `ReadBookActivity`、退书返回命中别的模块 `AudioPlayActivity`）。路径清单：

| 路径 | 环节 |
|---|---|
| 进书 | 入口→分发→数据→渲染→兜底 |
| 竖排排版 | 引擎 layout→调用≥2→缓存失效 |
| 点字命中 | 几何命中→分发 |
| 气泡解析 | 契约 resolve→调用≥2→渲染 |
| 查人 | 数据→接线 |
| 纪年 | 锚定→干支 |
| 半屏 | 组件→调用≥3→模型 |
| 退书 | 手势→返回键 |

判据：**0 环缺**。当前基线 21/22，唯一缺口「退书·返回」（已立 B16）。

## 3. 使用节奏

- **每轮收尾**（任一包提交前）：两个脚本都跑，输出原文贴进该包报告末尾。
- **整个 App 交付前**（F6 门禁）：两脚本 0 FAIL + L2 CI 全绿 + L3 整仓验收；缺一不许报"完成"。
- 新写模块必须**同时**把该路径写进 `selfcheck-path.sh`（脚本即"接线契约"的可执行形式），否则新模块没有自检覆盖。
- 脚本模式串只许写**已 grep 核实的真实符号**。新增模式前先 `grep -rn '<符号>' <目录>` 确认存在，否则等于自造断言。

## 4. 已踩的坑（写进协议防复发）

1. **全仓 grep = 假阳性**：`BackHandler` 在别的模块 Activity 里存在，全仓扫会误判"退书返回已接"。→ 每环必须限定目录。
2. **类名前缀误命中**：`class ReadBook` 会命中 `class ReadBookActivity`；`object ReadBook` 才是真身（`model/ReadBook.kt:146`）。→ 用完整声明形态匹配。
3. **枚举扫描口径**：第一版只抓 `"x" ->` 模式产生 6 条假阳性；修为扫 `Enums.kt` 全部引号字面量。
4. **脚本自身也要被审**：v1→v2 的收紧本身就是一次"自检失败"，说明"自检通过"必须先能解释"它凭什么通过"。
